## 一、这次唯一总目标

本次不是重做岗位实习，也不是继续把功能堆在原学生全生命周期 SaaS 里。

唯一目标是：

```text
现有岗位实习业务域无损抽离
→ 最小公共底座
→ 去就业/平台强耦合
→ 建全新 Standalone 数据库基线
→ 五端独立运行
→ 按益阳 88 项采购需求补齐
→ G01～G20 真链路验收
```

最终形成一套可独立部署、独立销售、独立升级、独立验收的：

**《跃科岗位实习管理平台》**

要求它不依赖教务、学工、迎新、毕设等其他业务模块也能完整运行。

- academic_affairs
- student_affairs
- graduation
- orientation

- Student360

### 就业衔接

岗位实习只能通过：

`EmploymentGateway`

访问就业衔接。

不得在 Standalone 核心域重新直接 import：

- `app.modules.employment.*`
- `app.models.employment.EmpStudent`

### 学生生命周期

归档完成等生命周期事件只能通过：

`LifecycleGateway`

发布。

不得重新直接依赖：

`app.modules.platform.document_lifecycle.*`

## 六、数据库原则

Standalone 必须拥有独立安装链。

禁止：

- 直接复制原 SaaS 54 份 Internship 历史 Alembic migration 当新系统安装链；
- 依赖教务 / 学工 / 毕设 migration 才能升级；
- 猜 migration 编号。

Standalone 新链：

```text
0001_internship_standalone_baseline
0002+
```

`0001` 必须能在空 MySQL 中一次性建立当前 Standalone 所需全部基础表。

原 SaaS → Standalone 的历史数据迁移另做 Migration Bridge：

- 保留主键关系
- 保留历史时间
- 保留审核记录
- 保留文件关联
- 保留文件哈希
- 提供迁移前后数量对账和孤儿检查
