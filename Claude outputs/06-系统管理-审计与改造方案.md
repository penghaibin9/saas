# 文档 6：系统管理中心——审计与改造方案（2026-10-24）

> 依据代码：分支 `claude/retire-r2`（3941470f8）的 `frontend/src/modules/system/`、`backend/app/modules/system_admin/`、`backend/app/core/permissions.py`、平台后台目录 `platformManagementCatalog.js`。
> 本文是施工依据。用户已授权按成熟 SaaS 管理后台的通行做法直接定方案；第五节的决策可直接改。
> 与文档 2 的关系：岗位菜单契约（R1）、学校管理员收权（决策 28）由文档 2 负责；本文只管“系统管理中心”自身的菜单、页面合并和迁出，施工排在文档 2 的 R0、R1 之后。

## 一、结论

系统管理中心做复杂了。原因不是单个功能写得多细，而是**把三类使用者的东西放进了同一个菜单**：

1. 学校信息中心管理员日常要用的（账号、导入、组织、岗位、配置、日志）；
2. 你自己或实施人员在开局阶段用的（开局向导、预设方案、已安装配置、变更升级、上线验收、老系统迁移）；
3. 系统运维才看得懂的（文件存储治理、完整性异常、批处理任务、流程运行治理、消息治理、主数据质量、审计证据完整性）。

| 指标 | 现在 | 目标 |
|---|---|---|
| 菜单项（`systemManagementCatalog.js`） | 60（8 个分组 + 52 个入口） | 10 + 开局期临时入口 1 |
| 路由页面（`system.routes.js`） | 43 | 约 14（含分页签） |
| 前端页面与组件 | 53 个 .vue，约 1.29 万行 | 预估删除或迁出约四成（以 S2、S4 实际为准） |
| 后端接口（`system_admin`） | 218 个，其中 183 个在一个 3774 行的 `system_bundle.py` | 数量基本不减，按域拆文件，部分改为平台权限 |
| 角色入口 | 同一件事最多 7 个入口（角色与权限） | 每件事 1 个入口 |

成熟 SaaS（钉钉、飞书、企业微信的企业管理后台，Workday 的租户管理）的通行做法是：**租户管理员只管“自己学校的人、组织、权限、配置、审计”；开通、模板、版本、运维、跨租户治理都在厂商自己的平台后台。** 你的平台后台（`platformManagementCatalog.js`）其实已经有初始化模板、自动开通、租户数据迁移、平台角色模板、全局字典、版本灰度、接口密钥、同步任务、跨租户审计等入口，学校侧的一批页面与它重复。

**三员分立**：教育行业等保 2.0 测评常要求系统管理员、安全管理员、审计管理员分开。菜单按上表分三组，大学校可以分给三个人，小学校给同一个人。审计管理员只能看日志，系统管理员和安全管理员都不能删改日志。

## 四、技术方案

1. **菜单**：系统管理菜单并入文档 2 R1 的岗位菜单契约（`shared/contracts/role-menus/system.json`）；`systemManagementCatalog.js` 删除，或只作为页面登记表。不再用 `?tab=` / `?surface=` 冒充菜单项：一个菜单项对应一个路由，分页签在页面内部切换。
2. **角色**：
   - `SYS_ADMIN` 改名为“系统管理员”，负责账号、组织、配置、流程、对接。
   - 新增 `SECURITY_ADMIN`“安全管理员”，负责岗位分配、临时授权、安全策略。
   - `SECURITY_AUDITOR` 改名为“审计管理员”，只看日志。
   - `SCHOOL_ADMIN`“学校主管理员”等于以上三者的合集（给小学校用），按文档 2 决策 28 不含业务权限。
   - 新增 `IMPLEMENTER`“实施人员”，只拥有开局空间权限，由平台开通、有到期时间，操作单独留痕。
   - 以上权限变化都必须走角色模板发布流程（见文档 2 第 0.1 节）。
3. **开局空间**：学校新增状态字段“实施中 / 已上线”，或复用租户生命周期已有状态；开局菜单只在“实施中”且账号为实施人员或学校主管理员时出现。上线检查通过后状态改为“已上线”，菜单消失，接口同时拒绝。
4. **迁平台后台**：迁出的页面先**从学校菜单和学校角色权限里移除**，接口改挂平台权限（`platform.*`）；平台后台对应入口已存在的（初始化模板、版本灰度、接口密钥、同步任务、跨租户审计、用量容量）直接对接，没有的（文件存储治理、完整性异常、数据治理）在平台“运行保障 / 数据治理”下新增，按学校筛选。
5. **学年学期归教务**：系统管理不再提供写入口；没有购买教务模块的学校，由教务中心的最小学期设置页承接（属文档 2 R6 教学运行岗）。
6. **后端拆文件**：`system_bundle.py` 按域拆为 accounts、org、iam、config、workflow、audit、integration 七个路由文件，接口路径不变，只搬家。
7. **删除旧路由**：迁出或合并后的旧路由按文档 3 的口径直接删除，不留跳转，访问落到 404。删除前列清单确认。
8. **文案**：新菜单与页面文案遵守文档 1 第三节（无技术词、无内部编号、状态中文）。

## 七、施工前要核实的点

1. “合规与业务表单”（`SystemBusinessFormsView`）的真实用途：如果是业务模块的表单配置，应归各业务中心，而不是放在学校设置。
2. “统一消息、待办与通知治理”中，哪些是学校要配的（渠道、模板），哪些是投递排查（归平台）。
3. 实施人员现在实际用哪个账号进学校开局，开局数据有没有在学校侧审计里留痕。
4. 平台后台已有入口（初始化模板、版本灰度、接口密钥、同步任务）与学校侧被迁页面调用的是否同一套接口；不是同一套的，以平台侧为准，学校侧接口按文档 3 流程退役。
5. 以上判定基于路由、菜单和文件规模，未逐页打开核对交互；S2 动手前按“页面 → 接口 → 服务 → 数据库”追一遍。
