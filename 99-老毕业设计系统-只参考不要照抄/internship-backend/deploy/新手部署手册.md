# 新手部署手册（傻瓜版）

> 面向：第一次部署、非专业运维的人。照着抄命令即可。
> 进阶/学校信息中心请看同目录的详版《[部署运维手册](../docs/部署运维手册.md)》。

这套系统 = **后端服务（Node.js）+ 数据库（MySQL）+ 网页前端（PC 管理端 / 手机 H5）**。
部署就是把这三样在一台服务器上跑起来，让别人能用浏览器访问。

下面给两条路，**新手优先选「方式 A：Docker」**，最省心。

---

## 方式 A：Docker 一键部署（推荐）

适合：一台干净的 Linux 服务器（Ubuntu/CentOS 均可）。Docker 会自动把数据库、后端、网页全装好。

### 第 1 步：装 Docker（只需一次）
```bash
curl -fsSL https://get.docker.com | sh
```

### 第 2 步：拿到代码并进入目录
```bash
git clone <你的仓库地址>
cd 毕业设计/internship-backend
```

### 第 3 步：配置密码（**最重要的一步**）
```bash
cp .env.example .env
```
然后用编辑器打开 `.env`，**必须改这两个**：
- `DB_PASSWORD=` 改成一个你自己的强密码（数据库密码）
- `JWT_SECRET=` 改成一长串随机字符（≥32 位，用来加密登录令牌）

> 生成随机串的偷懒办法（任选其一）：
> ```bash
> openssl rand -hex 32
> ```

### 第 4 步：一键启动
```bash
docker compose -f deploy/docker-compose.yml up -d --build
```
等几分钟（第一次要下载镜像）。

### 第 5 步：初始化数据库（只需一次）
```bash
docker compose -f deploy/docker-compose.yml exec app npm run setup
```
看到「✅ 安装完成」就成了。

### 第 6 步：访问
浏览器打开 `http://服务器IP/`，用 **admin / 123456** 登录，**马上改密码**。

## 方式 B：传统安装（不用 Docker）

适合：已有一台装了 MySQL 的 Windows/Linux 机器，或不方便用 Docker。

### 第 1 步：装好两个软件
- **Node.js**（≥18 版本）：https://nodejs.org 下载安装
- **MySQL**（5.7 或 8.0）：装好后记住 root 密码

### 第 2 步：进入后端目录，装依赖
```bash
cd internship-backend
npm ci --omit=dev
```

### 第 3 步：配置 .env
```bash
cp .env.example .env
```
打开 `.env`，把数据库信息填对：
```
DB_HOST=localhost
DB_USER=root
DB_PASSWORD=你的MySQL密码
DB_NAME=internship_management
JWT_SECRET=改成一长串随机字符
```

### 第 4 步：一键初始化（建库 + 建表 + 建管理员）
```bash
npm run setup
```
> 这条命令是非破坏性的，可重复执行，不会清空已有数据。

### 第 5 步：启动服务
```bash
npm start
```
浏览器打开 `http://服务器IP:3000/admin`，用 **admin / 123456** 登录后改密码。

> **想让它后台常驻、关机自启？** 用 PM2：
> ```bash
> npm i -g pm2
> pm2 start deploy/ecosystem.config.js
> pm2 save && pm2 startup
> ```
> Windows 上也可以直接双击 `重启服务.bat`。

## 每天自动备份（强烈建议）

数据无价。配置每天凌晨 2 点自动备份，保留 30 天：

**Linux（crontab）：**
```bash
crontab -e
# 加一行（路径换成你的实际路径）：
0 2 * * * /path/to/internship-backend/deploy/backup.sh
```
备份文件在 `deploy/backup/` 下。**记得定期把备份复制到另一台机器/硬盘**，别和数据库放一起。

**Windows：** 用「任务计划程序」每天运行一次 `mysqldump`，或手动定期导出。

## 升级到新版本

```bash
# 1. 先备份！
deploy/backup.sh
# 2. 拉新代码
git pull
# 3. Docker 方式：
docker compose -f deploy/docker-compose.yml up -d --build
docker compose -f deploy/docker-compose.yml exec app npm run setup   # 补新表
# 3. 传统方式：
npm ci --omit=dev && npm run setup && pm2 restart all
```
> `npm run setup` 只会补缺的新表，不动老数据，可放心重复执行。

## 常见报错排查表

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `数据库连接失败` / `ECONNREFUSED` | MySQL 没启动，或 .env 密码错 | 确认 MySQL 在跑；核对 `.env` 的 DB_PASSWORD |
| `Access denied for user` | 数据库账号/密码不对 | 改对 `.env` 里的 DB_USER / DB_PASSWORD |
| `Unknown database` | 还没建库 | 跑一次 `npm run setup` |
| 打开网页是空白 / 502 | 后端没起来 | Docker：`docker compose ... logs app`；传统：看 `npm start` 报错 |
| 登录提示「请求过于频繁」 | 触发了登录限流 | 等 1 分钟再试，这是防爆破的正常保护 |
| 端口 3000 被占用 | 别的程序占了端口 | 改 `.env` 的 `PORT=`，或关掉占用程序 |
| 打卡总是「不在范围内」 | 企业坐标/打卡半径没设对 | 在「企业管理」里设好经纬度和打卡半径 |

查看后端日志：
- Docker：`docker compose -f deploy/docker-compose.yml logs -f app`
- 传统/PM2：`pm2 logs`

## 上线前安全检查单

- [ ] `.env` 里 `JWT_SECRET` 是长随机串，`NODE_ENV=production`
- [ ] 数据库 root 用强密码，且 MySQL **只允许内网访问**（不要暴露到公网）
- [ ] 配好 HTTPS 证书（学校统一证书或 certbot），80 跳 443
- [ ] 配好每日自动备份，且备份异机存放
- [ ] 初始 admin 密码已改；演示账号/演示数据已清理
- [ ] （如用小程序）微信后台把 request 合法域名配成正式 HTTPS 域名
