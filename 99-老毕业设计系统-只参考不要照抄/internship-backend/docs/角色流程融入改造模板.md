# 角色流程融入改造模板

> 本文档为「商业化能力 → 角色流程内嵌」的标准改造模板，适用于后续新模块接入或给其他学校复制实施。

---

## 一、改造目标

| 改造前 | 改造后 |
|--------|--------|
| 侧边栏独立「商业化能力」分组 | 功能归入岗位实习 / 安全合规 / 系统管理 |
| 管理员手动找模块 | Dashboard / 工作台 **待办驱动** |
| 教师分散在多个菜单批阅 | **待批阅中心** 统一聚合 |
| 学生不知道下一步 | 首页 **流程状态条 + alerts** |

---

## 二、架构约定

### 2.1 统一待办 API

**接口：** `GET /api/workbench`

**各角色返回：**

| 角色 | `pending` 字段 | `alerts[]` |
|------|----------------|------------|
| 学生(4) | unsignedAgreements, asgChange, insuranceWarn, leaves | 协议/换岗/保险/打卡提醒 |
| 教师(3) | applications, internLogs, asgChanges, complaints, agreements… | 链至 reviewhub / riskcomplaint |
| 管理员(1/2) | entAudit, posAudit, complaintsPending, filingPending… | 链至 entpos / filinghub 等 |

**流程文案：** `flowLabels` 来自 `t_workflow_config`，管理员可在「审批流程」修改步骤名称，待办标题自动同步。

### 2.2 菜单映射（PC）

| 原模块 | 新归属 | 路由 key |
|--------|--------|----------|
| 企业入驻 + 岗位审核 + 实习单位 | 单位与岗位 | `entpos` |
| 风险预警 + 投诉 | 风险与投诉 | `riskcomplaint` |
| 保险预警 | 保险管理 | `insurancehub` |
| 备案 + 质量报告 | 备案与报告 | `filinghub` |
| 换岗/终止 | 岗位实习（流程节点） | `asgchange` |
| 审计 | 安全合规 | `auditlog` |
| 流程/CAS/通道 | 系统管理 | `workflow` / `syscfg` |

**兼容：** 旧 key（`entaudit`、`filing` 等）通过 `navigate` 别名自动跳转新页。

## 三、页面清单

### PC（`frontend/index.html`）

| 页面 | 说明 |
|------|------|
| `dashboard` | 管理员待办 + workbench.alerts |
| `workbench` | 教师/学生流程卡片 + 状态条 |
| `reviewhub` | 教师：申请/周报/换岗/协议/请假/成果/报告 |
| `entpos` | Tab：合作单位 / 入驻审核 / 岗位审核 / 已上架 |
| `riskcomplaint` | Tab：风险预警 / 投诉处理 |
| `insurancehub` | 到期 + 未投保扫描 |
| `filinghub` | 备案向导三步 + 质量报告 Tab |

### H5（`frontend/m/index.html`）

- 学生首页：`workbench.alerts` 黄条
- 教师首页：待办扩展 + `review` 聚合换岗/协议
- Tab 角标：`workbench.pending.total`

### 小程序

- `pages/home`：flowAlerts、unsignedAgreements、asgChangeActive
- `pages/review`：asgChanges、pendingAgreements
- TabBar 角标：`pending.total`

## 四、新增模块接入 checklist

复制以下步骤即可把新商业化功能融入流程：

1. **数据层** — 在 `workbenchModel` 增加 `count` 查询与 `buildAlerts` 规则  
2. **流程配置** — 在 `workflowConfigModel.DEFAULT_STEPS` 增加 module_key + INSERT IGNORE  
3. **菜单** — 归入业务分组，不要新建「商业化」分组  
4. **PC 页** — 合并到相关 Tab 页或待批阅中心  
5. **移动端** — 首页 alerts + 教师 review 一节  
6. **演示路径** — 更新 `help` 页迎检步骤  

---

## 五、迎检演示路径（一条线）

```
企业入驻(entpos) → 岗位上架(entpos) → 实习分配 → 学生打卡
→ 周报批阅(reviewhub) → 风险/投诉(riskcomplaint) → 保险(insurancehub)
→ 换岗/终止(asgchange) → 备案向导(filinghub) → 数据大屏(/screen)
```

- [ ] 教师待批阅含换岗、协议、投诉计数  
- [ ] 学生工作台/首页有协议、保险、换岗状态条  
- [ ] 备案页有三步向导  
- [ ] 修改 workflow 步骤名后，待办标题随之变化
