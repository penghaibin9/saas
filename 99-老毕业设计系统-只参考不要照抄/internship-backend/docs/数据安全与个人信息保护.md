# 数据安全与个人信息保护说明（PIPL 合规）

> 适用对象：拟采购本平台的院校信息中心 / 数据安全审查。
> 法规依据：《个人信息保护法》(PIPL)、《数据安全法》、《网络安全法》、《职业学校学生实习管理规定》(教职成〔2021〕4 号)。
> 本文档说明平台收集的个人信息范围、用途、安全措施与用户权利；其中部分为**实施方需配合落实的组织措施**（已标注）。

---

## 1. 个人信息收集清单（数据最小化）

| 数据项 | 涉及主体 | 用途 | 是否必需 |
| --- | --- | --- | --- |
| 姓名、学号/工号 | 学生、教师 | 身份识别、考核归档 | 是 |
| 手机号、邮箱 | 学生、教师、企业导师 | 通知触达、紧急联系 | 否（可留空） |
| 所属学院/专业/班级 | 学生 | 分院数据隔离、统计 | 是 |
| 打卡定位（经纬度/地址） | 学生 | 实习考勤真实性核验 | 是（仅打卡时） |
| 打卡/巡访照片 | 学生、教师 | 过程留痕 | 否 |
| 家长知情同意书 | 学生家长（监护人） | 未成年/在校生实习合规 | 是（按规定） |
| 紧急联系人 | 学生 | 安全应急 | 否 |
| 企业评价、成绩 | 学生 | 考核 | 是 |

> 原则：未在上表中列明的个人信息一律不收集；新增字段须先评估必要性。

## 2. 敏感与未成年人信息

- 学生多为未成年人或在校生，**家长知情同意书**作为实习前置条件留存（`t_parent_consent`），落实监护人告知同意。
- 定位、照片属敏感信息，仅在打卡/巡访等明确场景采集，不做后台持续追踪。
- 平台提供**脱敏工具**（`utils/desensitize.js`），用于非权威展示场景对手机号/学号/姓名等掩码，降低泄露面。

## 3. 技术安全措施（平台已内置）

- **传输安全**：全站 HTTPS（由部署侧 Nginx 终止，见部署手册）。
- **认证**：JWT 鉴权，生产环境强制 ≥32 位密钥，弱密钥拒绝启动。
- **口令**：bcrypt 加盐哈希存储，初始密码强制首登修改，强口令校验（字母+数字≥6 位）。
- **越权防护**：基于角色（院校/分院/教师/学生/企业导师）的数据范围隔离；分院按 `college_id` 隔离，企业导师仅限本企业数据，学生仅限本人。
- **审计留痕**：所有写操作经审计中间件记录责任链（`t_audit_log`，只增不可改）；**敏感数据导出（学信网数据/实习手册/毕设档案）单独记录导出人、时间、数量**。
- **上传安全**：文件类型白名单 + 加密随机文件名，避免按序枚举他人材料。
- **基础响应头**：`X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy` 等。
- **限流**：登录等接口限流，识别真实客户端 IP。

## 4. 数据存储与生命周期

- 数据存于学校自有/自管 MySQL（支持本地化/私有化部署，数据不出校）。
- 逻辑删除（`is_deleted`）保证可追溯；物理清理按学校档案保管期限执行。
- 备份：每日数据库备份 + 文件备份，保留期与恢复演练见《部署运维手册》。
- 保管期限建议：实习/毕设过程数据随学籍档案保管，毕业后按校档案规定留存或销毁。

## 5. 数据主体权利

- 查询/更正：用户可在个人中心查看并更正本人手机号、邮箱、紧急联系人等。
- 删除/注销：由学校管理员按学籍管理流程处理（含逻辑删除与到期清理）。
- 知情同意：家长知情同意书在线签署留存，作为实习开展前置条件。

## 6. 第三方与委托处理

- 短信、微信订阅消息、查重/AIGC 检测均为**可选对接**；未配置时自动降级（站内信 / 明确标注"演示数据"），不向第三方传输个人信息。
- 一旦对接第三方，需与服务商签订数据处理协议(DPA)，明确处理范围与安全责任（**实施方落实**）。

## 7. 实施方需落实的组织措施（清单）

- [ ] 完成系统等级保护定级与备案（建议二级及以上）。
- [ ] 制定本校《学生个人信息处理规则》并向师生/家长公示。
- [ ] 数据库账号最小权限、运维操作留痕。
- [ ] 明确数据保管期限与销毁流程，指定数据安全责任人。
- [ ] 与已对接的第三方服务签订数据处理协议(DPA)。
- [ ] 定期（建议每学期）导出审计日志抽查，核对敏感导出记录。

---

> 说明：本平台在技术层面提供了上述安全与合规能力，但合规是"技术 + 管理"的整体工程，第 7 节组织措施需由采购学校与实施方共同落实后方可视为完整合规。
