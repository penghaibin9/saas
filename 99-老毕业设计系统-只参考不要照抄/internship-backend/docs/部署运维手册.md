# 部署与运维手册（学校生产环境）

面向学校信息中心 / 实施人员。覆盖安装、配置、数据初始化、上线、备份、监控、升级与安全清单。

---

## 1. 环境要求

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| 操作系统 | Linux（CentOS 7+/Ubuntu 20.04+）或 Windows Server | 生产建议 Linux |
| Node.js | ≥ 18 LTS | 使用了内置 `fetch`、`node --test` |
| MySQL | 5.7+ / 8.0 | 字符集 `utf8mb4` |
| Nginx | 任意稳定版 | 反向代理 + HTTPS |
| mysqldump | 随 MySQL 客户端 | 备份脚本依赖，需在 PATH 中 |

---

## 2. 安装

```bash
git clone <仓库地址> && cd internship-backend
npm ci --omit=dev          # 仅装运行依赖
cp .env.example .env       # 若无示例，参照第 3 节手工创建
```

---

## 3. 环境变量（`.env`）

```ini
# —— 数据库 ——
DB_HOST=127.0.0.1
DB_USER=internship
DB_PASSWORD=<强口令>
DB_NAME=internship_management

# —— 服务 ——
PORT=3000
NODE_ENV=production

# —— 鉴权（必填，生产环境强制 ≥32 位，否则拒绝启动）——
JWT_SECRET=<openssl rand -hex 32 生成>
JWT_EXPIRES_IN=7d

# —— 跨域：允许的前端来源，逗号分隔 ——
CORS_ORIGIN=https://intern.your-school.edu.cn

# —— 微信小程序（用于登录/订阅消息，可选）——
WX_MP_APPID=
WX_MP_SECRET=
WX_TEMPLATE_NOTIFY=

# —— 短信（可选，未配置时降级为站内信）——
SMS_PROVIDER=
SMS_ACCESS_KEY=
SMS_ACCESS_SECRET=
SMS_SIGN_NAME=
SMS_TEMPLATE_CODE=

# —— 查重/AIGC 第三方服务（可选，未配置时为"演示数据"并明确标注）——
PLAGIARISM_API_URL=
PLAGIARISM_API_KEY=
PLAGIARISM_TIMEOUT=20000

# —— 保险到期预警提前天数（可选）——
INSURANCE_WARN_DAYS=15

# —— 批量导入默认初始密码（可选）——
IMPORT_DEFAULT_PASSWORD=Abc12345
```

> ⚠️ 生产环境 `JWT_SECRET` 必须 ≥ 32 位随机串，否则服务会拒绝启动（见 `middlewares/auth.js`）。

## 4. 数据库初始化

```bash
mysql -u root -p -e "CREATE DATABASE internship_management DEFAULT CHARSET utf8mb4;"
npm run migrate:all      # 建全部表（幂等，可重复执行）
npm run seed             # 创建首个院校管理员账号
```

> 启动时还会自动兜底建表/补列（审计、流程配置、benchmark 等），即使漏跑某个迁移也能自愈。

### 导入师生名册（上线入职关键步骤）

```bash
npm run import:users -- ./名册.xlsx --password=Abc12345 --dry   # 先 DRY-RUN 预览
npm run import:users -- ./名册.xlsx --password=Abc12345          # 正式导入
```
Excel 列：`用户名 | 姓名 | 角色 | 学号工号 | 手机号 | 邮箱 | 学院 | 专业 | 班级`
（学院/专业/班级按名称解析，库中须先存在；已存在用户名自动跳过；全部强制首登改密。）

## 5. 启动与守护

推荐 PM2：

```bash
npm i -g pm2
pm2 start app.js --name intern-api -i 2      # 2 实例（按 CPU 调整）
pm2 save && pm2 startup                       # 开机自启
pm2 logs intern-api                           # 看日志
```

systemd 方式见附录或由实施人员按惯例配置。

## 6. Nginx 反向代理（含 HTTPS）

```nginx
server {
  listen 443 ssl;
  server_name intern.your-school.edu.cn;
  ssl_certificate     /etc/nginx/cert/fullchain.pem;
  ssl_certificate_key /etc/nginx/cert/privkey.pem;
  client_max_body_size 20m;            # 与后端上传上限匹配

  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}
```
后端已 `app.set('trust proxy', 1)`，限流可正确识别真实 IP。

## 7. 备份与恢复

```bash
npm run backup:db        # 输出到 backups/，使用 mysqldump --single-transaction
```
定时备份（crontab，每日 2:00，保留近 30 天）：
```cron
0 2 * * * cd /opt/internship-backend && /usr/bin/npm run backup:db >> /var/log/intern-backup.log 2>&1
0 3 * * * find /opt/internship-backend/backups -name '*.sql' -mtime +30 -delete
```
恢复：
```bash
mysql -u root -p internship_management < backups/xxxx.sql
```
> 上传文件目录 `uploads/` 需一并纳入文件级备份（rsync/对象存储）。

## 8. 监控与日志

- 进程/重启：`pm2 status`、`pm2 monit`。
- 健康检查：`GET /api/health`（可接入 Nginx/Uptime 探活）。
- 应用日志：PM2 日志或重定向到文件，建议接入 logrotate。
- 审计日志：系统内置 `t_audit_log`，记录关键操作；管理端可查询。

## 9. 升级流程

```bash
npm run backup:db                 # 1. 先备份
git pull                          # 2. 拉取新版本
npm ci --omit=dev                 # 3. 装依赖
npm run migrate:all               # 4. 迁移（幂等）
pm2 reload intern-api             # 5. 平滑重启（零停机）
npm run smoke                     # 6. 冒烟自检
```
