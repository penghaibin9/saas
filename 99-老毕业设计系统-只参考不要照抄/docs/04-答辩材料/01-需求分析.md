# 需求分析

> 毕业设计及岗位实习管理平台 · 需求分析说明书

## 1. 项目背景

高职院校的"岗位实习"与"毕业设计"是人才培养的关键环节，长期依赖纸质表格、微信群、Excel 汇总管理，存在以下痛点：

- **过程不可见**：学生是否在岗、是否按时打卡、日志是否提交，教师无法实时掌握。
- **流程割裂**：实习计划、岗位申请、三方协议、签到、日志、巡访、成绩各自为政，数据不打通。
- **安全有隐患**：学生脱岗、企业不规范、保险缺失等风险无预警手段。
- **合规压力大**：教育主管部门要求实习数据上报省平台，纸质材料难以归档审计。
- **毕设管理散**：选题、任务书、指导记录、查重、答辩、成绩缺乏统一系统。

本平台以"**实习 + 毕设双主线、全周期数字化**"为目标，对标市面主流职业院校实习管理系统（工学云、正方实习、蘑菇丁等），实现从计划下达到成绩归档的全流程线上闭环，并满足私有化部署交付的商用要求。

## 2. 项目目标

| 目标 | 说明 |
| --- | --- |
| 全周期覆盖 | 实习准备期→进行期→监控预警→收尾，毕设选题→答辩→成绩全流程 |
| 多端协同 | PC 管理端 + 移动端 H5 + 微信小程序，师/生/企/管各取所需 |
| 过程可监管 | GPS 打卡、日志周月报、巡访、风险预警、催办，过程留痕 |
| 数据可上报 | 学信网格式导出、省平台对接、档案归档 |
| 安全合规 | RBAC 权限、操作审计、数据脱敏、电子协议 |
| 可交付可售 | 私有化一键部署、备份、运维手册，满足学校采购 |

## 3. 用户角色与权限

系统采用基于角色的访问控制（RBAC），共 5 类角色：

| 角色编码 | 角色 | 权限范围 | 典型场景 |
| --- | --- | --- | --- |
| 1 | 院校管理员 | 全校数据、系统配置、用户管理 | 下达实习计划、审核、统计上报、归档 |
| 2 | 分院管理员 | 本学院数据 | 学院级审核、统计 |
| 3 | 指导教师 | 所带学生 | 审批申请/请假、批阅日志、巡访、毕设指导、评分 |
| 4 | 学生 | 个人数据 | 申请岗位、签到、写日志、提交报告、选题、答辩 |
| 5 | 企业（导师） | 本企业岗位/实习生 | 发布岗位、确认录用、企业评价 |

## 4. 功能需求

### 4.1 岗位实习子系统

**准备期**
- 实习计划下达（院校管理员制定计划，设定打卡/周报/月报次数要求）
- 企业入驻审核、岗位发布与审核
- 学生岗位浏览、申请，教师审核 → 院校审核 → 登记录用
- 三方协议在线签署（学生/教师/学校三方会签）
- 家长知情书提交与审核
- 免实习/其他去向登记

**进行期**
- GPS 定位打卡（地理围栏校验，支持上/下班班次、补卡）
- 实习周报 / 月报提交与教师批阅
- 请假申请与审批
- 换岗 / 终止实习申请与审批
- 指导教师巡访记录（实地/线上/电话）

**监控预警**
- 风险预警（脱岗、缺报监测）
- 催办中心（一键提醒未打卡/未交报告学生）
- 保险预警（未投保/即将到期）

**收尾**
- 实习报告提交与评阅
- 实习鉴定表（企业鉴定）
- 实习考评（多维权重核算总成绩并发布）
- 就业去向填报与统计

### 4.2 毕业设计子系统

- 任务节点管理（选题、开题、中期、答辩等里程碑）
- 选题管理（课题库、双向选题轮次与匹配）
- 任务书下达与学生确认
- 指导记录
- 互查布置与互评
- 成果提交与查重
- 答辩管理（答辩分组、委员会、评分）
- 毕设成绩录入与发布

### 4.3 数据与系统服务

- 数据分析与可视化大屏（迎检）
- 省厅数据对接、学信网格式导出
- 档案归档
- 投诉 / 安全上报处理
- 用户管理、基础数据（学院/专业/班级）
- 操作审计日志
- 企业评价、企业满意度
- 通知 / 公告

## 5. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 支持早八集中打卡场景（PM2 集群 / 连接池），接口响应 < 500ms |
| 安全 | JWT 认证、bcrypt 加密、参数化查询防注入、RBAC、操作审计、首登强制改密、登录限流 |
| 兼容 | 主流浏览器；移动端 H5 自适应；微信小程序 |
| 可用 | 健康检查、Docker 健康探针、异常不阻断启动 |
| 可维护 | MVC 分层、统一响应格式、迁移脚本幂等 |
| 可部署 | 私有化一键安装、每日备份、运维手册 |
| 数据合规 | 数据脱敏、可导出、可归档、可封存移交 |
