## 4. UI 实走测试（无头浏览器）

为保证"可演示、不出错"，使用 Playwright 驱动真实前端，分三层实走：

- **页面级**（脚本 7、8）：四角色登录后逐个点遍每个菜单，捕获 JS 异常 / console 报错 / 4xx-5xx 接口失败。结果：PC 92 页 + 移动 28 功能，**0 异常**。
- **交互级**（脚本 9）：在每页点开"新增/编辑/查看/详情/筛选/审核"等交互（只点开不提交，不污染数据），验证弹窗与详情接口。结果：155 次交互 **0 缺陷**。
- **内容质量**（脚本 10）：扫描渲染文本中是否出现 `undefined` / `[object Object]` / `NaN` / 裸 `null`。结果：**0 处**。

## 5. 缺陷修复记录

测试过程遵循"边跑边修"，发现并修复的代表性缺陷：

| 缺陷 | 发现方式 | 根因 | 修复 |
| --- | --- | --- | --- |
| 实习鉴定 / 任务书「详情」404 | 交互级实走 | 后端缺 `GET /:id` 详情接口 | 新增详情接口（model+controller+route） |
| 教师「新增巡访/指导/任务书」403 | 交互级实走 | 前端调管理员专属 `/admin/users` 取学生 | 新增 `/benchmark/student-options`，前端按角色取数 |
| 登录框硬编码演示账号 admin/123456 | 体验审计 | 不利于正式交付（专业度/安全） | 清除默认值，改为通用占位 |
| E2E 打卡环节地理围栏外 | E2E | 演示坐标与企业坐标不匹配 | 修正演示坐标落入围栏，闭环 25/25 |

修复后均已回归验证通过（见第 2 节脚本 9 由"15 缺陷 → 0 缺陷"）。

## 6. 性能与安全验证（要点）

- **权限隔离**：冒烟测试含"学生越权访问 `/province` 被拦截"用例，通过。
- **首登强制改密 / 登录限流**：E2E 与冒烟中验证生效。
- **地理围栏**：打卡超范围（4074m > 200m）被正确拒绝，证明 GPS 校验有效。
- **审计**：所有写操作经 `auditMiddleware` 落库。
