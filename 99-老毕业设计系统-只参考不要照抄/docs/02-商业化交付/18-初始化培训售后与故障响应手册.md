# 初始化、培训、售后与故障响应手册

## 一、初始化交付

### 正式学校环境

1. 创建全新生产数据库，不从演示库复制。
2. 配置 HTTPS、数据库强密码、JWT、AppID/AppSecret 和备份目录。
3. 设置不少于 12 位的 `INITIAL_ADMIN_PASSWORD` 后执行迁移和管理员初始化。
4. 管理员首登改密，再导入学院、专业、班级、教师、学生、企业和岗位。
5. 执行 `npm run readiness`，所有项目通过后才能签署上线确认。

### 演示环境

执行 `npm run seed:demo && npm run audit:demo`。演示环境使用合成数据并保留 `demo_` 账号；不得混入真实学生数据。

## 二、数据导入顺序

学院 → 专业 → 班级 → 教师 → 学生 → 企业 → 岗位 → 实习计划 → 指导关系/实习分配。每次导入先用 5 条数据试导，确认编码和字段后再全量导入；保留原始文件和导入结果。

## 三、培训安排

| 场次 | 对象 | 时长 | 必讲内容 | 通过标准 |
| --- | --- | --- | --- | --- |
| 1 | 系统管理员/信息中心 | 2小时 | 初始化、权限、备份、日志、升级 | 能独立建账号、恢复测试库 |
| 2 | 院校/分院管理员 | 2小时 | 基础数据、计划、分配、监测、导出 | 完成一条业务闭环 |
| 3 | 指导教师 | 1小时 | 学生、批阅、请假、巡访、风险 | 完成一次批阅和巡访 |
| 4 | 学生/企业导师 | 45分钟 | 登录、打卡、周报、申请、评价 | 手机完成核心操作 |

培训材料包括系统说明书、角色速查卡、录屏、签到表和问题记录。培训后收集考试/操作结果和待改进项。

## 四、售后受理

受理渠道必须在项目启动前填写：服务电话 `[ ]`、邮箱 `[ ]`、工单/群 `[ ]`、值班负责人 `[ ]`。工单至少记录学校、联系人、时间、环境、现象、截图、影响人数、处理过程和关闭确认。

## 五、事件分级

| 等级 | 示例 | 首次响应 | 恢复目标 | 升级 |
| --- | --- | --- | --- | --- |
| P1 | 全站不可用、疑似泄露、数据大面积错误 | 15分钟 | 4小时内临时恢复 | 立即通知项目负责人和学校 |
| P2 | 打卡/登录/批阅等核心功能受阻 | 30分钟 | 8小时内恢复或绕行 | 1小时未恢复升级 |
| P3 | 个别账号、一般缺陷 | 4工作小时 | 2工作日 | 超期升级 |
| P4 | 咨询、优化建议 | 1工作日 | 排期答复 | 周报汇总 |

## 六、P1 处置步骤

确认影响 → 建立事件群和时间线 → 禁止无关变更 → 保存日志/快照 → 隔离攻击或故障组件 → 切换/回滚/恢复 → 验证登录、打卡、上传、下载 → 通知恢复 → 24小时内复盘。涉及个人信息时按法律和学校制度决定通知与报告。

## 七、例行巡检

- 每日：服务、磁盘、数据库、证书到期、备份结果。
- 每周：错误日志、慢请求、失败登录、附件容量。
- 每月：权限复核、补丁、恢复演练抽查、SLA 报告。
- 关键期：开学集中导入、集中打卡、毕业归档前专项检查。
