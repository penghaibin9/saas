# AI 与合规增强功能说明（商业化第三波）

> 本波次面向"卖给职业院校"的真实落地需求，补齐三档功能：**AI 智能能力**、**合规/业务硬缺口**、**触达与体验**。
> 全部遵循系统既有规范：分层（model + 迁移 + controller + 路由）、统一鉴权、参数化 SQL、操作审计、专用限流，并对外部依赖采用"**配置即真用、未配置即演示（明确 isDemo）**"的可插拔范式，私有化无外网环境同样可运行。
>
> 交付状态：35/35 单元测试通过；11 个新接口对真实数据库端到端冒烟通过。

## 一、第一档：AI 智能能力（DeepSeek 驱动）

### 设计

- 模型：**DeepSeek**（OpenAI 兼容接口），服务层 [`utils/ai.js`](../../internship-backend/utils/ai.js)，原生 `fetch` 零依赖。
- 未配置 `DEEPSEEK_API_KEY` 时自动降级为**确定性启发式**结果，并标记 `isDemo:true`，**绝不伪装成模型输出**（与 `utils/plagiarism.js` 一致）。
- AI 接口统一挂登录守卫 + **AI 专用限流**（每客户端 1 分钟 20 次，控成本防滥用），并在 controller 内做资源归属/角色校验防越权。

### 环境变量

```bash
DEEPSEEK_API_KEY=sk-xxx          # 缺省即演示模式
DEEPSEEK_MODEL=deepseek-chat     # 深度推理可用 deepseek-reasoner
DEEPSEEK_BASE_URL=https://api.deepseek.com   # 可指向自建网关
AI_TIMEOUT_MS=60000
```

### 接口（前缀 `/api/ai`，均需登录）

| 方法 | 路径 | 能力 | 权限 |
|---|---|---|---|
| GET | `/ai/status` | AI 服务状态（live/demo） | 任意登录 |
| POST | `/ai/score-log/:id` | 实习周报/月报**智能质检**（评分+维度+改进建议） | 本人/指导教师/院校管理员 |
| POST | `/ai/review-report/:id` | 实习报告 **AI 辅助评阅**（评语初稿，教师确认后采纳） | 指导教师（本人指导） |
| POST | `/ai/analyze-risk` | 文本**风险研判**（脱岗/安全/权益/心理信号），可传 `text` 或 `log_id` | 教师/管理员 |
| POST | `/ai/assistant` | 政策/流程**智能问答助手** | 任意登录 |
| POST | `/ai/match-positions` | **岗位智能匹配推荐**（按学生技能排序） | 学生本人 |

> 答辩讲解点：风险研判正好补强系统既有的安全监管卖点——把规则触发升级为对日志文本的弱信号识别。

## 二、第二档：合规/业务硬缺口

### 2.1 实习报酬台账（合规刚需）

依据教育部《职业学校学生实习管理规定》——实习报酬原则上**不低于相同岗位试用期工资的 80%**，且应有发放记录。

- 表：`t_stipend`（[`models/stipendModel.js`](../../internship-backend/models/stipendModel.js)）
- **自动合规判定**：`amount ≥ base_salary_ref × 80%`；无参考工资返回 `null`（待核，不武断判违规）。
- 统计含**发放进度 + 合规率**。

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| GET | `/stipends` | 台账列表（学生看本人，分院看本院） | 登录 |
| GET | `/stipends/stats?period=YYYY-MM` | 发放进度 + 合规率 | 教师/管理员 |
| POST | `/stipends` | 登记发放 | 教师/管理员 |
| PUT | `/stipends/:id` | 更新 | 教师/管理员 |
| DELETE | `/stipends/:id` | 删除 | 管理员 |

### 2.2 数据报送中心（省级/国家平台对接预留）

与既有 `filing`（逐生备案/回执）**互补**：此处把在册实习学生汇聚成**标准字段映射**的报送数据集。

- [`models/reportingModel.js`](../../internship-backend/models/reportingModel.js)：`fieldMap()` 标准列定义 + `fetchRecords()`（学生 + 最新有效分配 + 单位 + 计划起止）。
- 推送上报采用网关预留：配置 `REPORTING_PUSH_URL` 即真实推送，未配置返回演示态预览。

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| GET | `/reporting/config` | 字段映射 + 上报通道状态 | 管理员 |
| GET | `/reporting/preview` | 报送数据预览（总数 + 样例） | 院校/分院管理员 |
| GET | `/reporting/export` | 导出**标准报送包**（xlsx，含审计） | 院校/分院管理员 |
| POST | `/reporting/push` | 推送上报（网关，含审计） | 院校管理员 |

```bash
REPORTING_PUSH_URL=https://gov-gateway/api/report   # 缺省即演示
REPORTING_PUSH_KEY=xxx
```

### 2.3 家长在线签署（监护人电子签）

补 benchmark 既有"家长知情书文件上传"之外的**家长本人在线确认**。学校发起 → 生成安全令牌 → 家长凭链接在线签署，留存签署人/关系/姓名/IP/时间等**可追溯电子签记录**。

- 表：`t_guardian_consent`（[`models/guardianModel.js`](../../internship-backend/models/guardianModel.js)），令牌 192 位随机。
- 家长端页面：[`web/m/guardian.html`](../../web/m/guardian.html)（`?token=` 打开，无需登录）。

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| POST | `/guardians` | 发起签署（返回 token + signPath） | 教师/管理员 |
| GET | `/guardians` | 列表（角色范围） | 登录 |
| GET | `/guardians/:id` | 详情 | 归属校验 |
| DELETE | `/guardians/:id` | 删除 | 管理员 |
| GET | `/public/guardian/:token` | **家长免登录**查看 | 公开（令牌） |
| POST | `/public/guardian/:token` | **家长免登录**签署/拒签 | 公开（令牌，限流） |

## 三、第三档：触达与体验

### 3.1 Email 触达渠道

仿 `sms.js` 的 [`utils/email.js`](../../internship-backend/utils/email.js)，懒加载 `nodemailer`（可选依赖，未装则降级日志），并接入统一 `notify()`：`notify(uid, title, content, type, { email:true })`。系统配置开关 `notify_email_enabled=1` 生效。

```bash
EMAIL_HOST=smtp.exmail.qq.com
EMAIL_PORT=465
EMAIL_USER=xxx@xx.com
EMAIL_PASS=授权码
```

### 3.2 移动端 PWA + 弱网离线打卡

- [`web/m/manifest.webmanifest`](../../web/m/manifest.webmanifest)：可"添加到主屏"，独立窗口运行。
- [`web/m/sw.js`](../../web/m/sw.js)：应用壳缓存（离线可打开）；打卡 `POST /api/checkins` 断网时**写入 IndexedDB 队列并返回 202**，联网后（`sync` 事件或恢复在线）**自动重放上报**。
- 注册脚本已最小侵入注入 `web/m/index.html`，并广播离线计数事件 `checkin-queue`。
- 适用车间/工地等弱网场景，是实习打卡的真实痛点。

> 注意：Service Worker 生产环境需 HTTPS（或 localhost）。

### 3.3 报表中心

[`controllers/reportCenterController.js`](../../internship-backend/controllers/reportCenterController.js) 提供跨模块**真实聚合**总览 + 报表目录（统一入口，复用各模块导出，不造假数据）。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/report-center/overview` | 学生数/在册实习数/报酬合规率/家长签署率/AI 状态 |
| GET | `/report-center/catalog` | 可下载报表目录及入口 |

## 四、部署 / 升级

```bash
cd internship-backend
npm run migrate:up          # 幂等迁移（已含本波次 t_stipend / t_guardian_consent）
# 或单独：npm run migrate:wave-ai
npm install                 # 可选：拉取 nodemailer（邮件渠道）
# 按需在 .env 配置 DEEPSEEK_API_KEY / EMAIL_* / REPORTING_PUSH_URL
npm start
```

启动时 `app.js` 会幂等 `ensureTable` 两张新表，无需手动建表。**未配置任何外部密钥也能完整运行**（AI/报送/邮件均演示降级）。

## 五、安全与合规要点（卖给学校关注项）

- 全部新接口在 `guard`（登录 + 强制改密）之后；家长签署走独立公开令牌通道并**限流**。
- SQL 全参数化；`stipendModel.update` 用字段白名单防批量赋值提权。
- 导出/上报写入**操作审计**（谁、何时、导出多少条 PII）。
- AI 与上报均"未配置即演示且 `isDemo` 标记"，不伪造权威数据。
- 多租户感知：所有 model 经 `config/db` 代理，SaaS 模式自动落到各校独立库。
