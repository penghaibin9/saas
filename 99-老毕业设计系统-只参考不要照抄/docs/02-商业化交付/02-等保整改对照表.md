# 等级保护 2.0 整改对照表（建议定级：二级）

高校非核心业务系统通常定二级（S2A2）。流程：定级备案（属地网安）→ 差距整改 → 测评机构测评（二级测评费约 3-5 万，每两年一次）。

| 控制域 | 等保要求 | 当前状态 | 整改动作 |
|---|---|---|---|
| 身份鉴别 | 口令复杂度、定期更换、登录失败处理 | 已有：强制改密（数字+字母≥6位）、登录限流 | 补：连续失败锁定 15 分钟；口令 90 天到期提醒 |
| 访问控制 | 最小权限、角色分离 | 已有：五角色 RBAC、接口级 requireRole | 补：管理员操作二次确认已部分实现，保持 |
| 安全审计 | 留存≥6个月、防篡改 | 已有：审计日志模块 | 补：日志定期归档到独立存储；备份脚本已提供 |
| 通信保密 | 传输加密 | 部分：nginx 配置已备 | 必做：全站 HTTPS，小程序域名强制 https |
| 数据安全 | 备份恢复、个人信息保护 | 已有：每日备份脚本、身份证号脱敏显示 | 补：备份异机存放；数据库账号与 root 分离 |
| 入侵防范 | 最小化服务、漏洞修补 | Docker 镜像非 root 运行 | 补：定期 npm audit；服务器仅开 80/443/22 |
| 安全管理 | 制度、人员、应急 | 缺 | 用《03-SLA》《05-数据移交SOP》作为制度附件，补应急预案一页 |

> 投标话术：未测评前可承诺"系统按等保二级标准建设，中标后 X 个月内完成定级备案与测评"。
