> 对标国内主流实习管理产品（工学云、蘑菇丁、正方实习、新锦成就业等），补齐「规模化/可靠性、防作弊、合规」三类商用门槛能力。
> 延续既有「配置即真用、未配置即演示/降级」可插拔范式，私有化单机零外部依赖也能跑。
>

## 一、规模化 / 可靠性（解决「上集群就出事」）

### 1.1 定时任务集群安全（分布式锁）
**问题**：原 `setInterval` 定时任务在 PM2 cluster / 多实例下**每个进程都会跑一遍**保险扫描与发通知 → 学生收到重复短信。
**改法**：新增 [`utils/lock.js`](../../internship-backend/utils/lock.js) 基于数据库行 + TTL 的分布式锁；[`utils/scheduler.js`](../../internship-backend/utils/scheduler.js) 的每日扫描经 `withLock('insurance_scan', 23h)`，**多实例下同一天只有一个实例真正执行**，其余跳过；持锁实例崩溃后锁到期自动释放，别的实例接管。
- 表：`t_scheduler_lock`（启动/迁移自动建）。

### 1.2 上传走对象存储抽象（多实例共享）
**问题**：附件存本地 `uploads/`，**多实例/容器互相看不到**文件。
**改法**：新增 [`utils/storage.js`](../../internship-backend/utils/storage.js) 存储抽象层（`local` 默认 / 阿里云 `oss` / AWS `s3`，SDK 懒加载）；`createUploader` 透明接入，17 处上传站点统一改用 `keyToUrl()` 取访问 URL。
- `STORAGE_DRIVER=local`（默认）行为不变，私有化单机够用；
- `STORAGE_DRIVER=oss|s3` 自动落对象存储、URL 指向 bucket。

```bash
STORAGE_DRIVER=oss
OSS_REGION= OSS_BUCKET= OSS_ACCESS_KEY_ID= OSS_ACCESS_KEY_SECRET= OSS_PUBLIC_BASE=
# 或 S3：STORAGE_DRIVER=s3 + S3_REGION/S3_BUCKET/S3_ACCESS_KEY_ID/S3_SECRET_ACCESS_KEY/S3_PUBLIC_BASE[/S3_ENDPOINT]
```
> 远端模式下，鉴权下载（report 附件）走公网 URL；如需私有签名 URL 可后续在 storage 层扩展。

### 1.3 错误告警
[`utils/logger.js`](../../internship-backend/utils/logger.js) 的 `error` 级日志在 `ALERT_ON_ERROR=1` 且配置了群机器人时，推送到企业微信/钉钉群（全局 60s 节流，防错误风暴刷屏）。`unhandledRejection/uncaughtException` 已接结构化日志，与告警联动。

## 二、防作弊打卡（对标工学云/蘑菇丁的命门）

**问题**：原打卡仅校验 GPS 是否在围栏内，**易被虚拟定位绕过**（学生在宿舍打卡）。
**改法**：新增 [`utils/checkinRisk.js`](../../internship-backend/utils/checkinRisk.js) 反作弊评估（纯逻辑、可单测），打卡时综合判定并**留痕、高风险标记待教师复核**：

| 检测 | 规则 | 处置 |
|---|---|---|
| 模拟定位 | 客户端上报 `is_mock` | 高风险（+70） |
| 精度异常 | `accuracy > 1000m`（IP/基站粗定位伪装） | 中风险（+30） |
| 位移突变 | 与上次打卡推算时速 > 250km/h（不可能通勤） | 高风险（+60） |

- `t_checkin` 增补列：`accuracy / is_mock / device_id / risk_level / risk_reason`（启动/迁移幂等增补）。
- 高风险打卡照常记录但 `within_range=0` 并提示「已标记待教师核实」，签到返回 `risk` 字段。
- 客户端只需在打卡请求体附带 `accuracy / is_mock / device_id`。
> 进一步的「人脸活体核身」属第三方 SDK（微信人脸核身/腾讯云慧眼），可在此评估之上做可插拔适配，本波先落地**定位反作弊**这一最常被绕过的环节。

## 三、信创 / 等保合规

### 3.1 国密 SM3 口令哈希（可选）
- 新增 [`utils/gmcrypt.js`](../../internship-backend/utils/gmcrypt.js)（SM3 加盐）+ [`utils/password.js`](../../internship-backend/utils/password.js) 可插拔适配层；全部口令哈希/校验改走适配层。
- `PASSWORD_ALGO=bcrypt`（默认）/ `sm3`（信创合规，需可选依赖 `sm-crypto`，未装自动回退 bcrypt）。
- **校验时按哈希前缀自动识别**（`$sm3$`→SM3，`$2`→bcrypt），新旧哈希共存、平滑迁移。

### 3.2 限流多实例共享（已具备）
登录限流配 `REDIS_URL` 即多实例共享配额（见 [`utils/rateLimit.js`](../../internship-backend/utils/rateLimit.js)），避免暴力破解阈值被进程数放大。

### 3.3 信创落地路线（属基础设施/采购，非纯代码）
| 项 | 现状 | 落地建议 |
|---|---|---|
| 数据库国产化（达梦/人大金仓） | MySQL（mysql2） | 抽象 SQL 方言层 / 用兼容 MySQL 协议的国产库；本系统 SQL 多为标准语法，迁移面可控 |
| 国密传输（SM2/SM4） | HTTPS(TLS) | 网关层启用国密 TLS（国密 SSL 证书 + 支持 SM 的反代/负载） |
| 国产 OS（麒麟/统信） | Node 跨平台 | Node 在麒麟可运行，部署脚本适配 |
| 等保三级 | 已具审计/RBAC/限流/日志 | 按等保对照表补齐（见 docs/02 既有等保整改对照表） |

## 四、部署 / 升级

```bash
cd internship-backend
npm run migrate:up        # 幂等（含 t_scheduler_lock、打卡反作弊列）
npm install               # 可选依赖：ioredis/nodemailer/ali-oss/@aws-sdk/client-s3/sm-crypto
npm start
```

按需在 `.env` 开启：`STORAGE_DRIVER`、`REDIS_URL`、`ALERT_ON_ERROR`+群机器人、`PASSWORD_ALGO=sm3`。**全不配也能完整运行**（本地存储 + 内存限流 + bcrypt + 无告警）。
