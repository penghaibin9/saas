# 销售演示与采购验收执行手册

## 一、产品定位

本系统面向高职院校，统一管理岗位实习与毕业设计。销售时只承诺系统内已经形成闭环、可以现场验收的能力；需要校方账号、接口文档或第三方授权的集成不纳入默认交付承诺。

省级平台模块已从产品导航、公开演示、流程演练和后端产品路由中下架，不作为销售功能展示。

## 二、演示前检查（提前 30 分钟）

1. 双击根目录 `销售演示启动.bat`，确认交付自检全部通过。
2. 分别打开 `/demo`、`/admin`、`/screen`，按 `Ctrl+F5` 刷新。
3. 使用院校管理员、指导教师、学生三个身份各登录一次。
4. 确认大屏无真实姓名、手机号、身份证号等个人信息。
5. 拔掉外网后再次打开管理端核心页面，确认样式和登录页不依赖公共 CDN。
6. 准备一份脱敏 Excel 导入样例和一份归档导出结果。

## 三、10 分钟成交演示动线

| 时间 | 演示内容 | 要回答的采购问题 |
|---|---|---|
| 0:00-1:00 | 产品概览与双业务切换 | 一套系统是否覆盖实习和毕业设计 |
| 1:00-2:30 | 管理员工作台与待办中心 | 管理人员每天先处理什么 |
| 2:30-4:00 | 过程监管、定位打卡、缺报监测 | 如何发现未到岗、未打卡、未交材料 |
| 4:00-5:30 | 风险预警、保险预警、审计日志 | 风险是否闭环，责任是否可追溯 |
| 5:30-7:00 | 教师身份：申请、周报、请假、报告批阅 | 教师是否能批量、快捷处理任务 |
| 7:00-8:30 | 毕设选题、任务书、指导、成果、答辩、成绩 | 毕设过程材料是否完整留痕 |
| 8:30-9:30 | 档案自动生成、核验、归档 | 验收时能否交出学生完整档案 |
| 9:30-10:00 | 大屏、部署方式、备份恢复材料 | 是否能私有化部署并长期运维 |

## 四、验收证据映射

| 验收主题 | 页面证据 | 技术证据 |
|---|---|---|
| 组织和账号 | 用户管理、基础数据 | RBAC、数据范围、首登改密测试 |
| 实习过程 | 过程监管、周报月报、请假、巡访 | 接口鉴权、状态流转测试 |
| 风险闭环 | 风险预警、缺报监测、保险预警 | 打卡反作弊、预警规则测试 |
| 毕设过程 | 选题、任务书、指导、成果、答辩、成绩 | 权限边界、流程引擎测试 |
| 档案交付 | 档案归档、数据分析 | 导出、访问控制、备份恢复 SOP |
| 安全审计 | 权限管理、审计日志 | 104+ 自动测试、敏感信息脱敏测试 |
| 部署运维 | 无需业务页面演示 | Docker、Nginx、PM2、监控与备份文档 |

## 五、现场表述边界

- 可以承诺：私有化部署、校内业务闭环、五角色协同、审计留痕、归档导出、配置化流程。
- 需条件确认后承诺：统一身份认证、微信正式登录、短信、对象存储、学校数据中心对接。
- 不展示、不承诺：省级平台直连、未经正式凭证验证的第三方回执。
- AI 未配置密钥时必须称为“演示模式”，不得表述为已经接入正式智能服务。

## 六、成交前必须取得的信息

学校名称与组织结构、在校生规模、预计并发量、部署网络环境、数据库与操作系统要求、统一身份认证方式、现有数据模板、校内审批流程、验收清单、售后响应要求。未取得这些信息前，不应承诺固定上线日期。
