## 3. 真实业务结果与边界

- **让谁完成什么**：宿管建"月度卫生/安全/违禁/夜不归宿"检查任务，按房逐条录结果；异常自动生成宿舍异常单+ DORM 来源风险；夜不归宿记录学生名单。
- **进入条件**：`studentAffairs.dorm.inspection.manage`(建任务)/`inspection:input`(录入)，宿管限本楼。
- **退出条件**：任务 DONE，记录落库，异常/风险生成。
- **上游**：房源(房间)、在住学生。**下游/回写**：`t_cs_dorm_exception`、`t_affairs_risk_record`(共享)、成长时间线(严重异常)。**跨模块**：风险回写(见 §16 总包对齐)。
- **本卡完成**：任务/记录列表、关闭任务、同房幂等、夜不归宿名单落 `student_ids_json` 并绑真实学生、异常/风险绑真实 student_id、scope+权限、（评估）多评分项。
- **明确不做**：文明寝室评比（backlog）；移动查寝真机（backlog）。
- **仅学校可决定**：检查评分是否需卫生/安全分项打分（影响是否补评分列）；异常等级阈值。

## 6. 主流程、异常流程与状态机

见二级总包 §7.2。要点：
- 建任务即 RUNNING（service L395 强制，忽略 model 默认 DRAFT）——保留，DRAFT 态暂不使用。
- 录入 ABNORMAL：须 detail≥5(L421)；生 `CsDormException(status=PENDING_HANDLE)` + `AffairsRiskRecord(source=DORM,source_ref_id=rec.id,risk_level=MEDIUM,status=NEW)`。
- **缺陷 D-05**：`cs_student_id=0`/`student_id=0` 占位——须改为按 room_id→在住学生（卫生类挂房间无单一学生时可挂空但风险须可定位到房/楼；夜不归宿类须按 absentStudents 名单**逐生一条**异常+风险绑真实 student_id）。
- **缺口**：同任务同房可重复录入（无幂等）——须补 `uk(tenant_id,task_id,room_id)` 或应用层查重→409。
- 夜不归宿名单：`student_ids_json` 须写入并驱动逐学生异常/风险。

安全：Excel 导入公式注入转义；越栋(scope)；照片不投影非授权角色。

**审计分流**：建检查任务/录结果/关闭任务/生成异常与风险等业务动作 → `t_affairs_audit_trail`（`AffairsAuditTrail`，事件 TASK_CREATE/NORMAL/ABNORMAL/TASK_CLOSE）；查看或下载检查照片、查看夜不归宿名单完整联系方式(`sensitiveView`) → `t_security_audit_log`（敏感查看，脱敏+水印+原因）；检查结果 Excel 导入 → **双写**（`t_affairs_audit_trail` 记导入发起+结果 + `t_security_audit_log` 记导入文件/操作人）；越权拒绝 → `t_security_audit_log`。
**SEC-4（真实缺陷·未实现）**：现状——`submit_check_record` 生成的 `CsDormException(cs_student_id=0)` 与 `AffairsRiskRecord(student_id=0)` 用硬编码占位（`affairs_dorm_service.py` L425-436），**未绑真实学生**，致非全校角色按 scope 恒不可见、风险无法进 360/责任人。本卡 §6/§12「名单绑真实学生」与总包 D-05/D-06 已给出"卫生类挂房/楼定位、夜不归宿按 `absentStudents` 名单逐生异常+风险绑真实 `student_id`"的**设计**；属编码阶段待实现，本轮未落地。
**SEC-5（真实缺陷·未实现）**：本卡 `/dorm/check-tasks*` 现仅 `require_staff`，**无 `studentAffairs.dorm.inspection.manage`/`view` 强校验、无 `DORM_BUILDING` scope、越栋录入不返 403**；§7/§9 权限矩阵为设计，属编码阶段待实现，本轮未落地。
