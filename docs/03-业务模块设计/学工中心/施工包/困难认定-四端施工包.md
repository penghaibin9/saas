## 二、真实流转

| 前置 / 当前状态 | 责任人与动作 | 下一状态 / 四端结果 |
|---|---|---|
| 已发布认定批次 | 本人申请；教师按范围代受理 | CLASS_REVIEW，生成真实责任人任务和待办 |
| CLASS_REVIEW → COUNSELOR_REVIEW → COLLEGE_REVIEW → SCHOOL_REVIEW | 各节点具体经办人，通过 / 退回 / 驳回 | 逐节点通过，最后进入 PUBLICITY；班级评议不等于办结 |
| 评审退回 | 学生按原意见补正、保存、重提 | DRAFT → CLASS_REVIEW，沿用同一申请，更新版本 |
| 评审驳回 | 经办人填写至少5字原因 | REJECTED，结束流程；不能重复建同批申请撞唯一约束 |
| 公示中 | 学生提交异议，授权教师复核 | 异议未结阻断确认；成立驳回，不成立维持；仍须满足公示期满 |
| 公示到期且无未结异议 | 授权教师确认 / 既有扫描服务 | APPROVED，困难库、成长事件、消息与待办同步 |
| 已认定 | 发起动态调整，具体责任人审批 | ADJUST_REVIEW → APPROVED；保留原结果历史 |
| 并发 / 越权 / 无责任人 | 后端拒绝，不改流程真值 | 页面保留输入并提示刷新核对；不可自动换版本重试写入 |

### 本节实施与补充核验

- 实际文件中心会把等待扫描文件同时标为 `status=QUARANTINED / scanStatus=PENDING`。两学生端先区分 PENDING/RUNNING 与 ERROR，再判定风险隔离；不能把所有 QUARANTINED 都提示感染。readyForBusiness 严格等于 true 才允许提交，后端门禁保持。
- 两学生端提交中同时禁用文件选择、说明输入和其他提交按钮；手机选择回调也检查忙碌状态，避免异步选文件覆盖在途内容。学生PC导航守卫在提交中阻止离开，成功后以实际未提交文件/说明判断，其他材料的编辑继续受保护；确认切换申请后清除旧上下文暂存。
- 隔离UI运行启用 FILE_SCAN_REQUIRED，仅测试运行配置，不改变正式部署设置。普通 ZIP 被现有上传策略拒绝，未放宽策略；改用合法合成 DOCX 验证扫描等待，两次检查后只读数据库仍只有一份文件（文件3，QUARANTINED/PENDING）。随后通过页面另选已允许的测试PDF完成材料提交；未将待扫描DOCX直接改成安全可用，也未声称验证了扫描工作进程。
- 学生PC提交后编辑圆点消失，点击返回原申请直接进入申请2详情，无未保存误报。教师PC验收后，学生PC已完成筛选与学生手机H5显示同一版本及审核意见。
