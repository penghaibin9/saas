## 5. 业务目标、角色与完整闭环

- **解决的真实问题**：把"学生住哪张床、能否调宿、寝室查得如何、有无夜不归宿、住宿率多少"变为可核查、可导出、可上报、可追责的账，并让夜不归宿/严重检查异常自动进入**风险中枢**（`t_affairs_risk_record`）。
- **购买/管理部门**：学生公寓（宿舍）管理中心 / 学工处。当前代码未标明具体部门，标记**部分未知**，不编造。
- **使用角色**：宿管老师（DORM_BUILDING）、辅导员/班主任（CLASS/ADVISOR）、学院学工负责人（COLLEGE）、学工处管理员（SCHOOL）、学生（SELF）；心理老师**不在本模块**（宿管不得看心理明细）。
- **发起/处理/审核/查看/归档责任**：房源—宿管维护（本楼）；入住/退宿—宿管/辅导员执行，学生可自选（开关放开时）；调宿—学生/辅导员发起→辅导员初审→宿管终审→系统执行；检查—宿管建任务并逐房录入；异常—宿管登记→辅导员认领处置→严重升级转风险；统计—学院/学工处查看导出；档案归档在 `sa-archive-stats`（不在本模块）。
- **主流程**：楼→房→床建模（一键铺满）→ 入住（回写 `t_cs_dorm_record`）→ 调宿审批换床 → 查寝录结果 → 异常/夜不归宿登记 → 严重项转风险 → 住宿率/异常/查寝统计上报。
- **异常/撤回/退回/重复/超时/关闭/重开**：床位占用/性别 409；在途调宿再发 409；调宿驳回(REJECTED)/退回(RETURNED)/撤销(CANCELLED)；检查同任务同房重复 409；异常认领超时提醒/升级 ESCALATED；夜不归宿阈值自动升级（阈值待定 D-12）。
- **与其他模块的输入输出**：
  - 输入：学生主档 `StudentProfile`（性别、班级）；`t_cs_service_student`（cs_student_id 映射）。
  - 输出/回写：`t_cs_dorm_record`（我的宿舍读链路，被移动端/学生端读）；`t_affairs_risk_record`（**共享表**，被 sa-risk 承接处置，见 §16）；`t_cs_dorm_exception`（异常台账）。

### 10.2 继承硬规则（务必落到每卡）

- **两层授权**：第一层未授权 STUDENT_AFFAIRS→菜单不显示+接口 403 `module not granted`（§12.1）；已授权但角色无 `studentAffairs.dorm.*`→有菜单无按钮/403+越权审计（§12.2）。
- **六要素合取**（§8A.1）：角色+模块授权+权限点+数据范围+业务关系+敏感权限，**后端最终裁定**；前端隐藏≠授权。
- **数据范围**：宿管 `DORM_BUILDING`=`t_teacher_student_scope` 中该教师负责楼栋集合；可见学生=在住床位属该楼栋集合（`t_affairs_dorm_bed.building_id`/`t_cs_dorm_record` 反查）。**前端不传 scope，后端从激活角色解析**。
- **宿管红线**（§7.3 L266）：宿管**不得**看学生学业/心理/困难明细；本模块任何页面**不得**投影这些字段。
- **敏感统一控制**（§10.1）：联系方式/夜不归宿名单/检查照片/调宿病情说明默认脱敏；查看完整值需 `sensitiveView` 授权+原因(≥5字)+二次确认+水印+审计；导出走 `t_export_task`（用途≥5字），心理明细列默认锁死剔除（本模块不含心理，天然满足）。
- **拒绝码**：401/403（`NO_PERMISSION` 无权 / `NO_DATA_SCOPE` 越栋）/404（越范围表现为不存在）/409（`DATA_CONFLICT`/`APPROVAL_VERSION_CONFLICT`）/422（`VALIDATION_ERROR`）。

### 10.3 需新增/复用的 key 与 scope

- **权限码（按 13A §12 授权矩阵唯一权威，非新造）**：本模块动作统一用 `studentAffairs.dorm.view`、`studentAffairs.dorm.resource.manage`、`studentAffairs.dorm.allocation.manage`、`studentAffairs.dorm.transfer.create`、`studentAffairs.dorm.transfer.approve`、`studentAffairs.dorm.inspection.manage`、`studentAffairs.dorm.exception.handle`、`studentAffairs.dorm.import`、`studentAffairs.dorm.export`；跨域动作用 `studentAffairs.config.manage`（自选开关，属处级配置域）、`studentAffairs.stats.view`（宿舍统计，属统计域）；菜单 `menu:studentAffairs:dorm`。按 §12 收敛、**不新设独立码**：transfer/inspection/exception 的只读一律 `studentAffairs.dorm.view`，检查录入(旧 inspection:input)并入 `studentAffairs.dorm.inspection.manage`，异常升级(旧 exception:escalate)并入 `studentAffairs.dorm.exception.handle`，学生自选(旧 selfselect，学生本人移动端写、受 config 开关+本人范围约束)复用 `studentAffairs.dorm.view`。
- **命名归一（已裁定，非待确认项）**：旧稿一度以 affairs 前缀命名 dorm 码，属**已清理的错误口径**（本包已全量归一，不保留为别名/兼容码）；权限码唯一权威 = 13A §12，本模块一律 `studentAffairs.dorm.*`。前端 `AppPermissionButton`/路由 meta 已用 `studentAffairs.dorm.view` 等，与后端应校验码同源；前端隐藏≠授权，后端须按同一 `studentAffairs.dorm.*` 码逐动作强校验（现状=未校验，见 §10.4 与 §16.3 SEC-5）。
