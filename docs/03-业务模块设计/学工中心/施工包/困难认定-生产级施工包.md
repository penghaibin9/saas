### 2.3 从公开政策口径可作 `project_rule` 的设计约束（据 CAND-1/2/4 搜索摘要，标未逐页核验）

- 认定档次：可设 **2-3 档**（特殊困难 / 困难 / 一般困难）——对应代码 `LEVELS = {SPECIAL/DIFFICULT/GENERAL}`（`affairs_aid_service.py` l20）。
- 认定方式：家访、个别访谈、大数据分析、信函索证、**量化评估**、**民主评议**综合，避免单一材料定级。
- 民主评议：**各班认定评议小组**依申请表/证明材料/日常消费行为评议确定各档资格。
- 公示：经院系认定工作组审核后**公示不少于 5 个工作日**，接受监督。→ 对应 `publicity_days default=5`（`affairs_aid.py` l28）。
- 重点关注群体：建档立卡、农村低保、特困供养、孤残、烈士子女、突发事件家庭。→ 对应 `special_flags_json`/`difficulty_factors`。

> 以上为公开政策**通用口径**，作为本包设计的合规基线；**未逐页核验原文**，施工前应由甲方/资助中心据本校现行文件确认档次数、公示天数、评议小组构成。

## 5. 业务目标、角色与完整闭环

- **解决的真实问题**：面向职校家庭经济困难学生的「申请—民主评议—四级审核—公示（含异议）—认定入库—动态调整—年度复核」全流程闭环，产出**困难学生库 + 困难等级**，作为奖助勤贷补、绿色通道、临时补助的**唯一上游数据源**。家庭经济属强敏感个人信息，全程可追溯、可审计、可上报。
- **购买/管理部门**：学校学生资助管理中心 / 学工处（未知具体采购主体的不臆造）。
- **使用角色**（据权限总控 §7.3 + 代码 `_SENSITIVE_ROLES`）：
  - 学工处管理员（`STUDENT_AFFAIRS_ADMIN`）/ 校管理员（`SCHOOL_ADMIN`）：全校，建批次、终审核定、管全库、公示、导出、看家庭经济明文。
  - 资助老师（`FUNDING_TEACHER`）：全校/本院资助，审核、名单、金额台账、看家庭经济明文（数据范围内）。
  - 学院学工负责人：本学院，复审、本院名单（默认脱敏）。
  - 辅导员（`COUNSELOR`，`scope_type=CLASS/ADVISOR`）：本班，组织班级评议、初审、动态调整发起；**默认脱敏**，reveal 无权（`_SENSITIVE_ROLES` 不含 COUNSELOR，测试 A5 验 403）。
  - 学生本人：移动端提交家庭经济+材料、看进度/结果、提异议（`GET /affairs/aid/my` 已建）。
  - 心理老师 / 宿管：**不可见**困难认定。
- **发起/处理/审核/查看/归档责任**：学生（移动端）或辅导员代受理发起 → 班评/初审/复审/终审逐级处理 → 公示 → APPROVED 入库 → 学年可 ADJUST/年度复核 → 归档（ARCHIVED 枚举已定义，转移未实现，见 §7）。
- **主流程**：`建批次(OPEN) → 受理申请(直达 CLASS_REVIEW) → 四级评审 → SCHOOL_REVIEW 终审核定等级 → PUBLICITY → 期满/确认 APPROVED（写 level_history + 进 360 + 通知）→ 困难库可查`。
- **异常/撤回/退回/重复/超时/关闭/重开**：批次未 OPEN/已截止受理→409；同批次重复(非终态)→409；退回(RETURN，reason≥5)→DRAFT→resubmit 回班评；驳回(REJECT，reason≥5)→REJECTED 终态；公示期满 scan 幂等；REJECTED 后 adjust→409。
- **与其他模块输入输出**：产出困难库供 **sa-aid 助学金资格校验**（`affairs_funding_service.py` l174-176 调 `is_in_difficult_library`）、**学生画像 360**（`affairs_profile_service.py` l57 显示当前等级）、绿通/临补（文档意向，暂无代码调用方）。详见 §跨模块依赖（§16）。

## 7. 状态机与业务规则

**申请单状态枚举（代码 `L_AID` l28-32；真相列 `AidApply.status`）**：

（`NOT_STARTED` 为批次前置态，非申请单状态；`SUBMITTED` 枚举定义但代码 `apply()` 直达 `CLASS_REVIEW`，实际未落 DRAFT/SUBMITTED 起始态。）

## 10. 本模块权限总控理解与实例化

已完整读取 `docs/03-业务模块设计/系统管理中心/00-系统管理中心-权限角色模块授权与权责边界设计.md`（§5 四层裁定 l70；§6.2 角色类型；§7.3 学工角色模板 l264-268；§8 数据范围 l345-403；§8A 业务关系六要素 l470；§10 敏感控制 l516-529；§12/§15/§17 前端隐藏≠授权 l600）。

**继承的硬规则**：
- **两层授权**：平台→学校租户模块授权（第一层）；学校→角色授权（第二层）。未授权困难认定菜单不显示；已授权无权限点→有菜单无按钮/403。
- **四层裁定**（§5 l70）：当前激活角色 → 权限点（能不能）→ 数据范围（看多少）→ 敏感权限（能不能看明文）→ 审批节点（能不能审）。**前端隐藏不等于授权**，后端独立校验。
- **六要素合取**（§8A l470）：模块授权 + 角色权限 + 数据范围 + 业务关系 + 按钮权限 + 敏感字段权限。
- **数据范围枚举**（§8）：ALL / COLLEGE / CLASS / ADVISOR / SELF；困难认定当前代码只用「班级(ADVISOR/CLASS via `_allowed_class_ids`) / ALL」两档，**须补 COLLEGE 学院档**。
- **敏感统一控制**（§10 l516-529）：家庭经济默认脱敏；完整值需 sensitiveView + 原因 + 二次确认 + 水印（操作人+时间+租户）+ 审计；导出困难数据强控（脱敏/部分禁止），导出必审计+水印。

**审计双轨（按动作性质分流，非二选一）**：两张表各司其职，同一敏感业务动作允许**双写**——
- **业务留痕 → `t_affairs_audit_trail`**（模型 `AffairsAuditTrail`，`_audit` l53，biz_type=AID，含 operator/role/before/after）：建批次、受理申请、各级评审(REVIEW_STEP/RETURNED/REJECTED/TO_PUBLICITY)、公示确认(APPROVED)、动态调整(ADJUST_*)、异议登记/核查(OBJECTION_*) 等业务流转。
- **安全敏感 → `t_security_audit_log`**（模型 `SecurityAuditLog`，`audit_insert`，含 ip/ua/traceId 由底座注入）：家庭经济**完整值查看**（`SENSITIVE_VIEW` reveal，DENY/SUCCESS 均落）、**导出/下载**、越权拒绝。
- **双写场景**：导出困难库/认定名单 = 业务动作（`t_affairs_audit_trail` 记「导出发起」）+ 敏感动作（`t_security_audit_log` 记「敏感导出」，含水印+原因+二次确认）；`reveal` 家庭经济亦为敏感读，只落 `t_security_audit_log`（业务侧不额外留痕）。
- **红线**：**不写 `t_security_audit_log` 的家庭经济明文读取路径不得存在**。

**安全检查**：reveal 越权返回 403 且**先落 DENY 审计再抛异常**（l545-547，防"越权不留痕"）；列表/详情 SQL 均带 `tenant_id==_tid()` + `is_deleted`（防跨租户/枚举）；家庭经济密文列 `select` 序列化时 `_apply_row` 只调 `_mask_family`（l203），明文仅经 reveal 出。

**真实安全阻断项登记（现状=缺陷 / 本轮=仅登记设计 / 状态=待编码修复，未实现——不得写成已修复）**：
