## 3. 真实业务结果与边界

- **让谁完成什么**：学工处/资助/学院查看困难认定统计：困难生总数、各等级分布、覆盖率、办理进度（各状态分布）、年度复核完成率，并可按学院/班级下钻；供决策与上级报送。
- **进入条件**：`studentAffairs.aid.view`。**退出条件**：无（只读看板）。
- **上游**：认定申请/审核/困难库数据。**下游**：报送、决策。
- **本卡必须完成**（代码阶段）：新增 `GET /aid/stats` 聚合端点（scope 过滤+脱敏下钻）+ 统计看板页。
- **明确不做**：跨模块联合统计（与奖助/风险的交叉分析后置）；实时大屏（后置）。
- **仅学校可决定**：覆盖率分母口径（全校在校生/资助适龄）、统计维度、是否含历史学年。

## 6. 主流程、异常流程与状态机

统计为**只读聚合**，无状态机。边界：
- scope 过滤：按当前角色数据范围聚合（辅导员=本班、院=本院、处=全校），复用 `_allowed_class_ids`。
- 空数据：无批次/无申请时返回 0 值，前端 empty 态。
- 一致性：统计数与「困难学生库」列表、下钻明细对账 0 差异（同 status==APPROVED 口径）。
- 覆盖率分母为 0（无在校生）时避免除零。

## 10. 敏感数据、安全与审计

- 统计聚合本身为计数（低敏），但**下钻明细必须脱敏**（无家庭经济，姓名掩码）。
- 覆盖率等比例值不泄露个体。
- 安全：聚合 SQL 带 tenant_id + scope；下钻复用 `difficult_students`（已 scope 过滤）；导出走 excel 底座 sanitizer + 水印。
- 审计落点：统计聚合**只读无写**（不留痕，不涉 `t_security_audit_log`）；**统计导出** = 业务动作（`t_affairs_audit_trail` 记「导出发起」）+ 敏感动作（`t_security_audit_log` 记「脱敏导出」+水印+原因，双写），导出任务落 `t_export_task`。
- **SEC-5（真实缺陷·未实现）**：现状——`GET /aid/stats` 端点**整体 missing**（`student_affairs.py` grep 无命中），无鉴权可言；本轮——§9 已给出 `studentAffairs.aid.view`/`studentAffairs.aid.export` 权限码设计；状态——**编码阶段待实现（须从零建端点+权限点），本轮未落地**。
