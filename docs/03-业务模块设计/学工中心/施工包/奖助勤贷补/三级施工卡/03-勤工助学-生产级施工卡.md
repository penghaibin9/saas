## 3. 真实业务结果与边界

- **让谁完成什么**：用工部门管理员发布勤工岗位（时段/名额/时薪）；学生报名；部门筛选初选；辅导员确认；资助中心审批→上岗（ON_POST）；每月录考核工时→生成补贴 result；离岗 TERMINATED。
- **进入条件**：岗位在招 + 学生困难等级达门槛（可配）+ 无时间冲突。**退出**：TERMINATED / REJECTED / CANCELLED。
- **上游输入**：困难库等级（只读）；（backlog）13B 课表冲突。**下游**：补贴发放 result（卡 07，result_type=WORK_STUDY_MONTH）、360。
- **本卡必须完成（恢复代码时）**：新建岗位表+月考核表；解除 WORK_STUDY 的 V1 硬拦；岗位/报名/筛选/上岗/月考核端点与页面。
- **明确不做**：课表冲突校验（backlog，依赖 13B）；银行代发补贴（只做台账）。
- **仅学校可决定**：勤工时薪、月工时上限、困难等级准入门槛、补贴发放方式（银行/现金）。

## 6. 主流程、异常流程与状态机（勤工专属）

在总包 §7 基础上扩展：报名→（部门筛选）COUNSELOR_REVIEW→SCHOOL_REVIEW（资助中心审批，跳过 COLLEGE_REVIEW）→GRANTED→**ON_POST**→月考核（留痕）→**TERMINATED**。异常：岗位满/下架→409；无时段交集→422；门槛不达→409；ON_POST 前录考核→409；非 WORK_STUDY 调 on-post→409；同岗同批重复→409。
