## 3. 真实业务结果与边界

- **让谁完成什么**：辅导员→学院→学校三级评审拟资助名单；资助/学工处发布脱敏公示名单（快照）；公示期内登记异议→回 SCHOOL_REVIEW 复核；期满（定时/手动）→GRANTED。
- **进入条件**：批次评审完成有拟资助名单。**退出**：全部 GRANTED（或异议驳回）。
- **上游输入**：评审通过的 application（PUBLICITY 态）。**下游**：GRANTED→发放台账（卡 07）、360。
- **本卡必须完成（恢复代码时）**：新建公示快照表；发布公示端点（生成脱敏 list_snapshot）；异议登记端点（→回 SCHOOL_REVIEW）；公示专页（脱敏名单展示）。
- **明确不做**：对外公网公示（仅校内系统内）；异议自动裁决（人工复核）。
- **仅学校可决定**：公示层级（校/院/班）；公示天数 N（现默认 5，`publicity_days` model l109）；异议处理时限。

## 6. 主流程、异常流程与状态机

评审：COUNSELOR_REVIEW→COLLEGE_REVIEW→SCHOOL_REVIEW→PUBLICITY（review l376-388）。公示：发布快照（新）→期内异议登记→回 SCHOOL_REVIEW 复核（新）→重新评审→再 PUBLICITY；期满（scan l431 / confirm l450）→GRANTED。异常：非 FUND_NODES 评审→APPROVAL_VERSION_CONFLICT l372；reason<5→VALIDATION_ERROR l396；非 PUBLICITY 确认→409 l454；异议对非 PUBLICITY→409。
