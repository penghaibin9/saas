## 5. 业务目标、角色与完整闭环

- **解决的真实问题**：把"学生违纪→立案→告知申辩→逐级审批→处分生效→决定书送达→考察期→解除/申诉"的法定程序全过程线上化、留痕化、可核查，并向奖助/评优/毕业资格/风险画像输出权威处分结论。
- **购买/管理部门**：学工处（校级）+ 各二级学院学工办。
- **使用角色**：辅导员/班主任（登记、送达、代发起解除、跟进）、学院学工负责人（初审）、学工处管理员（复核/终审/撤销/台账/归档）、校级审批人（严重处分终审）、学生本人（移动端查本人处分、满期申请解除、签收）、奖助/毕业/风险模块（只读"有无未解除处分"结论）。
- **责任链**：登记=辅导员/学院；初审=学院；复核/终审=学工处；严重终审=校级；送达回执=辅导员；解除审批=辅→院→处；申诉受理=申诉委员会(线下 V1)。
- **主流程**：见 §7 状态机（已实现 11 态）。
- **异常/撤回/退回/超时/重开**：登记态可撤销(CANCELLED)；审批 REJECT/RETURN；RETURNED 可补充重提；EFFECTIVE 改→409；未生效发起解除→409；未满考察期→409(待建校验)；解除节点停留超时→催办无自动通过。
- **跨模块输入输出**：EFFECTIVE→投影 `t_cs_discipline`(ACTIVE)→奖助/评优冻结、进 360 事件 `DISCIPLINE_EFFECTIVE`、生成风险记录(可选)；REMOVED→投影 record_status=REVOKED→奖助/评优恢复、360 事件 `DISCIPLINE_REMOVED`。

## 7. 状态机与业务规则（处分主流程 + 解除子流程，已实现 11 态）

| REGISTERED | submit / cancel | 辅导员/学院(范围内) | disc_type∈枚举, reason≥5字 | COLLEGE_REVIEW / CANCELLED | 直接审批 | version 递增 | SUBMIT / CANCELLED |

**EFFECTIVE 事务内联动**（service `_make_effective` L209-225，已实现，同一事务）：写投影 `t_cs_discipline`(record_status=ACTIVE, source_case_id=case.id) → `x.cs_discipline_id` 回链 → `x.effective_at`/status=EFFECTIVE → `StudentStageEvent`(to_stage=`DISCIPLINE_EFFECTIVE`) → `UnifiedMessage`(处分决定送达) → 完成待办 → audit EFFECTIVE。

## 10. 本模块权限总控理解与实例化

已完整核对 `00-系统管理中心-权限角色模块授权与权责边界设计.md` 与 `13A-学工中心状态机与权限矩阵.md` §12。硬规则落地：

- **§12 权威权限码口径**（13A §12 L506-511，唯一权威）：discipline 二级仅 6 个权威码 —— `studentAffairs.discipline.view` / `.create` / `.approve`（含 reject/return，同一审批码，节点由数据范围区分）/ `.remove.create` / `.remove.approve` / `.export`。全文页面/按钮/API/§9矩阵/seed/测试**同一动作同一码**。口径纠正：①校级审批用 `.approve` 节点，**无独立 `.schoolApprove` 码**；②登记撤销归登记人 `.create`，**无独立 `.cancel` 码**；③处分统计用**共享** `studentAffairs.stats.view`，**非** `discipline.stats.view`；④送达 `.deliver`、申诉 `.appeal.*`、撤销已生效 `.revoke` 为 **§12 授权矩阵待扩展码**（对应送达/申诉/撤销为待建功能，编码前须先补入 §12 矩阵，本轮仅登记）。模块内旧式 affairs 冒号权限码残留 = 0（已全部统一为 `studentAffairs.*`）。
- **两层授权**（§4.2/L470）：平台→学校模块授权(第一层)；学校→角色授权(第二层)。当前端点仅 `require_staff`——**第二层细粒度 permission key 未落地，属真实缺口**(D-08，见 §16 SEC-5)。
- **六要素合取**（§8A/L470）：激活角色+模块授权+权限key+数据范围+业务关系+资源状态，后端裁定。当前已做数据范围(`_scope_or_403`)+资源状态(状态机)；缺 permission key + 敏感字段。
- **数据范围**（§8/L567/L637 `t_teacher_student_scope`）：`_allowed_class_ids` 返回 None(全校 admin)或 class_id 集合；测试 D7 证辅导员跨班 403 `NO_DATA_SCOPE`。
- **敏感控制与审计分流**（§10/L512/L516）：**查看处分详情 = 敏感**；导出处分数据 = 强控。审计口径（各司其职，非二选一）：
  - **业务流转**（登记/提交/审核/退回/解除/生效/撤销等状态动作）→ `t_affairs_audit_trail`（现码已实现，`_audit` L46-51）；
  - **敏感动作**（处分明细=事实/证据/文书的查看、导出、回证下载、明文查看）→ `t_security_audit_log`（operator/ip/ua/traceId/原因/前后值/水印）；
  - **双写**：处分明细**查看**与台账**导出**同时留两条 —— 业务动作留痕写 `t_affairs_audit_trail`，敏感留痕写 `t_security_audit_log`。
  - **现状（真实缺陷·待编码对齐，未实现）**：当前 `_row` 全量返回明细、无脱敏，且**敏感查看/导出仅写 `t_affairs_audit_trail`，未写 `t_security_audit_log`**——本轮把设计口径纠正为「敏感→`t_security_audit_log` 双写」，属**编码阶段待落地项，本轮未实现**（见 §16 SEC 登记）。
- **处分审批链**（L550）：辅导员(登记)→学院(审批)→学工处(终审)，代码一致。
- **终态保护**（L145）：已生效处分平台方不可改；EFFECTIVE→409（test D4）。
- **角色红线**：团委(L269)/专业课教师(L443)/班主任(L454)/企业导师(L462)**不得看处分明细**；资助老师仅"有无未解除处分"结论。

### 双表投影对账兼容口径（核心，务必贯彻各卡）

- **`t_affairs_discipline_case`** = 流程主表(11 态，走完整正当程序)；**`t_cs_discipline`** = 结论投影台账(旧"在校服务"表，奖助/毕业/画像的消费源)。
- **两条写入路径**：
  - **新路径**(`affairs_discipline_service._make_effective` L209)：多级审批通过后插投影行，`source_case_id=case.id`、status=EFFECTIVE、record_status=ACTIVE；解除时 `record_status→REVOKED`（**status 字段不动，仍 EFFECTIVE**）。
  - **旧路径**(`campus_service_service.create_discipline` L456)：直接插行，`source_case_id=NULL`、status=EFFECTIVE、record_status=ACTIVE，**无审批**；`void_discipline`→record_status=VOIDED+is_deleted；`update_discipline`可置 status=REVOKED。
- **对账口径**(`projection_reconcile` L413)：`count(case status=EFFECTIVE)` == `count(投影 where source_case_id 非空 AND record_status=ACTIVE)`；**旧路径手工行(source_case_id=NULL)不计入对账**，对账只保新路径不变式。
- **record_status 三值语义**：`ACTIVE`(生效未解除) / `REVOKED`(新路径解除) / `VOIDED`(旧路径作废)；`list_disciplines` 与台账仅过滤 ACTIVE，故 REVOKED 与 VOIDED 均从台账消失。
- **消费方判定**"有无未解除处分"必须读 **`record_status==ACTIVE`**（不是 `status`），奖助/毕业/画像零改动(§2.4 硬约束)。
