## 3. 真实业务结果与边界

- 让**团委老师**审批建社/年审、管社团档案；让**社长/学生干部(被授权)**管成员纳新、发起社团活动(挂 org_id)。
- 进入条件：有 `studentAffairs.club.*`。退出：社团 DISSOLVED。
- 上游：学生主档、指导老师、`t_file_object`(章程)。下游：社团活动复用活动底座(01)；任职进 06 干部履历。
- 本卡完成：`t_affairs_club`+`t_affairs_club_member`+`t_affairs_club_annual_review` + 建社/审批/纳新/年审/换届。
- 不做：社团活动通用流程(01 复用)；干部履历聚合(06)。
- 学校决定：**社团归口(团委/学工处)、社团分类、年审周期与材料、换届备案要求**。

## 6. 主流程、异常流程与状态机

社团：`APPLYING→ACTIVE→ANNUAL_REVIEW→ACTIVE/SUSPENDED→DISSOLVED`；成员：`APPLYING→ACTIVE→QUIT`。
- 主流程：建社申请(章程/指导老师/发起人)→团委审批→ACTIVE→纳新(入社申请→社长审)→年审→换届备案。
- 异常：重复社团名→409;非 ACTIVE 纳新→409;越权审批→403;年审逾期→SUSPENDED(可配)。

检查：社长越权看他社/敏感、跨租户、附件校验。

**权限码归口（§A）**：本卡 `studentAffairs.club.view / create / review / member.manage / annual-review / export` 属 13A §12 **未列**的活动二课细分域，登记为「§12 授权矩阵待扩展（活动二课细分）」，施工前须由权限总控/§12 正式扩展补入再种 RBAC。社长为学生干部被授权协助角色（§7.3 L339，最小授权，仅本社）。菜单键 `menu:studentAffairs:activities` 为 navPlan 命名，非动作码。

**审计表分流（§B）**：业务动作 CLUB_*（建社）/ CLUB_REVIEW（建社·年审审批）/ CLUB_MEMBER_*（纳新/管理）/ CLUB_ANNUAL_REVIEW → `t_affairs_audit_trail`；社长越权看他社/越权拒绝 → `t_security_audit_log`；**社团成员导出 = 双写**：`t_affairs_audit_trail` 记导出发起 + `t_security_audit_log` 记敏感导出 + 水印 + 原因≥5字（文件走 `t_export_task`）。

**SEC-5（真实缺陷·未实现·三段式）**：现状本域后端端点仅 `Depends(require_staff)`（`backend/app/core/security.py` L97-103），**无 `studentAffairs.club.*` 细粒度强校验**，尤其社长仅 `require_staff` 无法约束"仅本社"；§2 grep 实证本卡端点整体 `missing`。本卡 §7/§9 已给应校验权限码（**设计**），属**编码阶段待实现项，本轮未落地**，不得记为已实现端点；施工时社长动作须绑本社数据范围 + 六要素强校验，**严禁停留在 `require_staff`**。
