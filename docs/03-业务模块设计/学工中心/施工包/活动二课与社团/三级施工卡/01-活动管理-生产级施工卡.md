## 3. 真实业务结果与边界

- 让**团委老师/学院学工/辅导员**完成：建活动→编辑→发布→（报名截止/取消）→归档，作为报名签到与二课积分的上游。
- 进入条件：有 `studentAffairs.activity.create` 且在数据范围。退出条件：活动 CONFIRMED/ARCHIVED。
- 上游输入：学生主档/班级/学院（scope）、附件 `t_file_object`。下游输出：02 报名签到、03 二课积分（confirm 生成）、`t_student_stage_event`（进360）。
- 本卡完成：活动主表 CRUD + 发布/取消/归档状态机 + 列表/详情页 + 名单入口（名单细节在 02 卡）。
- 明确不做：报名/签到写入（02 卡）、积分生成明细（03 卡）。
- 仅学校决定：活动类型枚举、审批层级（是否院级活动需处审）、FINISHED 自动确认天数。

## 6. 主流程、异常流程与状态机

见总包 §7.1。本卡覆盖 DRAFT→PUBLISHED→ENROLL_CLOSED→ONGOING→FINISHED→CONFIRMED→ARCHIVED 及 CANCELLED；报名签到子状态在 02 卡。
- 重复提交：`request_id` 幂等；重复发布→幂等跳过。
- 撤销：CONFIRMED 后改名单→撤销确认（仅发布方上级 + reason≥5 + 删 credit + 审计）。
- 超时：到 enroll_deadline/start_at/end_at 系统任务自动流转；FINISHED≥N 天未确认提醒。
- 异常恢复：发布失败回 DRAFT；乐观锁冲突 409 提示刷新。
