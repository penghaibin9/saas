## 3. 真实业务结果与边界

- 让**团委/学工/领导**看活动参与率、二课积分分布、志愿时长、社团数、党团发展进度概览，并下钻到学院/班级/年级明细。
- 进入条件：有 `studentAffairs.stats.view`。退出：无。
- 上游：`t_affairs_activity/signup/credit/volunteer_record/club/org/league_dev`(聚合)。下游：领导驾驶舱可引用;导出台账。
- 本卡完成：概览 + 下钻 + 导出，**首页-明细对账 0 差异**。
- 不做：明细业务(01-07);综测公式(backlog)。
- 学校决定：统计口径(参与率分母)、展示维度组合。

**权限码归口（§A）**：本卡统计查看/导出用 13A §12 **已列权威码** `studentAffairs.stats.view` / `studentAffairs.stats.export`（原草稿 `activity:stats:view/export` 已收敛入既有 stats 码，不新增独立 activity.stats 码）。菜单键 `menu:studentAffairs:activities` 为 navPlan 命名，非动作码。

**审计表分流（§B）**：统计为只读聚合，无业务写动作；**统计台账导出 = 双写**：`t_affairs_audit_trail` 记导出发起 + `t_security_audit_log` 记敏感导出 + 水印 + 原因≥5字（文件走 `t_export_task`，脱敏、党团只计数不投影明细）；越权拒绝 → `t_security_audit_log`。

**SEC-5（真实缺陷·未实现·三段式）**：现状本域后端端点仅 `Depends(require_staff)`（`backend/app/core/security.py` L97-103），**无 `studentAffairs.stats.view/export` 细粒度强校验**，且统计须按 scope 收敛防跨范围/跨租户泄露；§2 grep 实证本卡端点整体 `missing`。本卡 §7/§9 已给应校验权限码（**设计**），属**编码阶段待实现项，本轮未落地**，不得记为已实现端点；施工时聚合查询须后端 scope 强收敛 + 六要素校验，**严禁停留在 `require_staff`**。
