## 5. 业务目标、角色与完整闭环

- **解决的真实问题**：把学校奖学金 / 助学金 / 勤工助学 / 助学贷款 / 学费减免 / 临时困难补助的"项目立项—批次开放—学生申请—资格审查—逐级评审—公示异议—发放台账—金额汇总上报"从 Excel 满天飞收敛为一站式闭环，金额/银行/家庭经济按角色脱敏，导出带水印审计。
- **购买/管理部门**：学校学生资助管理中心（学工处下设），角色 = 资助老师（权限总控 l267）。
- **使用角色**：学生（申请，本轮 backlog 走移动端）、辅导员（本班初审/核实困难/核对回执）、用工部门管理员（勤工发岗/筛选/月考核）、学院学工负责人（学院评审/差额排序/复审）、资助老师（全程运营/审批/名单/金额台账/导出）、学工处管理员（终审/公示/统计/导出）、校院领导（脱敏看板下钻）。
- **发起/处理/审核/查看/归档责任**：发起=学生或管理端受理（资助老师）；处理审核=辅导员→学院→学校三级；公示/发放/统计=资助老师+学工处；归档=批次收编 ARCHIVED。
- **主流程**：建项目→建/发布批次(OPEN)→受理申请(资格硬校验)→COUNSELOR_REVIEW→COLLEGE_REVIEW→SCHOOL_REVIEW→PUBLICITY→（期满/确认）GRANTED→写发放台账+进 360→批次 ARCHIVED。
- **异常/撤回/退回/重复/超时/关闭/重开**：资格校验失败→409 拦截不入库；同批次在途重复→409；REJECT/RETURN 需原因≥5 字；RETURNED 学生修改后重交；PUBLICITY 期满定时扫描自动 GRANTED；异议登记回 SCHOOL_REVIEW 复核（新）；终态写操作→409。
- **与其他模块的输入输出**：
  - **输入（只读引用，不重建）**：困难认定 sa-difficulty 的困难库（`is_in_difficult_library` 读 `t_affairs_aid_apply` APPROVED 的 final_level，`affairs_aid_service.py` l582-589）；违纪处分（`t_cs_discipline` record_status=ACTIVE，via `t_cs_service_student`）；教务成绩（`t_academic_grade` pass_status=FAIL）；学籍（`t_student_profile.student_status`）。
  - **输出**：GRANTED 写 `StudentStageEvent to_stage=FUNDING_GRANTED`（进成长时间线 360）；写 `UnifiedTodo`(FUNDING_APPROVAL)/`UnifiedMessage`/`AffairsAuditTrail`(FUNDING)。

## 10. 本模块权限总控理解与实例化

**继承硬规则**（权限总控）：四层裁定"权限点→数据范围→敏感权限→审批节点"（l70）；前端隐藏≠授权（l70）；敏感明细（完整手机号/身份证/家庭经济/心理/处分）需敏感字段权限（l38/l401）；敏感操作二次确认+填原因+水印（l163）；数据范围变更审计（l379）；平台方不能删改学校审计（l163）。
