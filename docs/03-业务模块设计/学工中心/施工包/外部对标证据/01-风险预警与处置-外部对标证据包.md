## 0. 结论先行

本轮已取得可打开、可核验的高校实际运行材料、采购材料、企业公开披露和国家制度原文。可以解除原施工包中“完全没有可核验外部来源”的阻断，但不能把所有厂商宣传都当成已验证产品能力。

已被外部实践反复验证的产品主链是：

`多源数据发现异常 → 风险分级/聚合 → 按角色与业务关系派给责任人 → 限时处理 → 过程留痕 → 跟进/关闭/必要时升级 → 汇总分析和源头治理`

关键判断：

1. 成熟系统不是只有一个“预警数字大屏”，必须能落到具体学生、具体来源、具体责任人和具体处置结果。
2. 风险来源至少覆盖学业、消费/资助、晚归未归、请销假、宿舍、就业及人工/学生诉求；心理明细属于更高敏感域，不得因进入风险中心而自动放开。
3. 预警必须进入人工核实和处置闭环，系统不得自动作出心理诊断、处分决定或其他对学生权益有重大影响的结论。
4. 责任分派、限时处理、升级、关闭和复盘，比“复杂算法评分”更应优先实现。
5. 学校可配置阈值，但阈值、规则版本、来源和命中原因必须可解释、可追溯。

## 2. 三套高校真实运行方案

### 2.1 山东大学：数字赋能辅导员工作平台

**来源**：CERNET《中国教育网络》，作者为山东大学项目人员李腾、马忠亮、马明月、何泽鲲。

- 原文：[提高学工服务，数字化赋能高校辅导员](https://www.edu.cn/xxh/xy/xytp/202308/t20230801_2455314.shtml)
- 证据等级：B（教育行业权威媒体 + 高校项目人员署名）
- 查阅日期：2026-07-12

**已核验事实**：

1. 平台从学生花名册、智慧学工、学生预警、学业预警、学生就业等方面建设数据指标。
2. 风险/预警信息覆盖消费、学业、就业、晚归未归等维度。
3. 数据来自一卡通、门禁、教务等系统，经数据仓库、数据湖、治理和服务开放平台提供给应用层。
4. 平台使用权限管理、访问控制和审计监控；支持企业微信和PC统一门户。
5. 辅导员操作会留痕，可用于工作评价；系统强调及时发现问题并提供有针对性的帮助。

**可转化设计输入**：

- 风险看板需要多来源聚合、来源分布、等级分布、时间趋势和按数据范围下钻。
- 风险学生页需要显示“为什么被预警”，至少展示来源、命中规则、发生时间、最新状态和责任人。
- 数据来源必须记录同步时间、规则版本和原始业务记录引用，避免只保存一个不可解释的总分。
- PC端之外，应通过统一消息/待办向责任人主动推送，而不是要求辅导员每天自己刷新大屏。

**不可推断边界**：

- 原文没有公开山东大学预警工单的完整状态枚举、超时时限、关闭条件和数据库字段。
- 原文没有证明其自动进行心理诊断或自动处分；本项目不得增加此类推断。

### 2.2 西安邮电大学：“我在校园”学工管理平台

**来源**：西安邮电大学学生工作部官网。

- 原文：[学生工作部举办“我在校园”新功能上线培训会](https://52xy.xiyou.edu.cn/info/1031/4483.htm)
- 证据等级：A（高校官网真实运行通知）
- 查阅日期：2026-07-12

**已核验事实**：

1. 学校自2018年起使用“我在校园”学工管理平台，具备连续使用事实。
2. 已实现签到、请假、离留校登记、通知公告、问卷调查等业务。
3. 新增学生数据报送、政工管理和宿舍卫生检查；学生每日在校数据可电子化报送、统计并进行异常预警。
4. 宿舍检查采用层级化检查记录；政工管理可形成辅导员工作画像。

**可转化设计输入**：

- 请假、离留校、签到、宿舍检查不能成为彼此孤立的页面，应能按标准来源契约写入风险中心。
- 自动预警任务需要区分“数据未报”“数据异常”“确有风险”，避免把数据质量问题直接当学生风险。
- 来源系统补录或纠错后，风险记录要能重算/解除，并保留纠错轨迹。

**不可推断边界**：

- 原文没有公开“我在校园”的处置状态机和权限模型。
- 不能仅凭该来源声称平台具备升级、接管、复开等动作。

### 2.3 西南财经大学：“学工e家”应用平台

**来源**：西南财经大学学生工作部官网。

- 原文：[关于“学工e家”应用平台上线的通知](https://xgb.swufe.edu.cn/info/1171/4771.htm)
- 证据等级：A（高校官网正式上线通知）
- 查阅日期：2026-07-12

**已核验事实**：

1. 学生可提交建言、投诉、求助或感谢，业务覆盖资助、日常管理、心理健康咨询、校园安全等多个领域。
2. 平台实行归口办理和分级负责，事项按类别直达业务单位并落实具体责任人。
3. 实行首问负责制；非本单位职责的事项仍需协调，不允许简单丢回。
4. 实行限时办结；短期无法解决时必须反馈阶段进展。
5. 建立风险警示报告制度：发现突发事件可能或风险时，立即向有关单位和学校预警，并要求快速处置、及时化解。
6. 对高频、共性问题进行重点领域治理和源头治理；学生可在线评价处理结果。

**可转化设计输入**：

- 风险工单必须有责任单位、责任人、接单时间、处理时限、阶段反馈、办结结论。
- 需要“转办但不甩锅”的责任机制：转办前原责任人仍负责，接收确认后才转移责任。
- 风险升级不是简单改等级，必须产生接收单位/人员、原因、时间和审计记录。
- 看板除风险数量外，应统计超时率、办结率、复开率、来源高频问题和责任单位处理情况。

**不可推断边界**：

- 原文描述的是学生诉求与风险报告闭环，不等于所有自动数据预警均使用完全相同流程。
- 学生在线评价适用于学生主动提交事项；心理危机等特殊风险不应机械要求学生评价。

### 2.4 补充实践：中国石油大学（华东）智慧学工

**来源**：中国石油大学（华东）党委学生工作部官网。

- 原文：[党委学生工作部（武装部）联合信息化建设处召开智慧学工系统建设研讨会](https://csun.upc.edu.cn/2024/0509/c14757a430784/page.htm)
- 证据等级：A
- 查阅日期：2026-07-12

**已核验事实**：

- 学校已建设学生基础数据库、一体化办公平台和学生管理预警系统。
- 建设方向强调“连接、感知、协同、决策”，并要求梳理和改造业务流程、加强跨部门协同。

**设计意义**：风险中心应成为跨模块协同枢纽，不应重复建设请假、宿舍、学业等来源业务。

## 4. 国家制度与合规依据

### 4.1 监测预警、咨询服务和干预处置必须形成体系

- 教育部等十七部门《全面加强和改进新时代学生心理健康工作专项行动计划（2023—2025年）》明确提出形成“健康教育、监测预警、咨询服务、干预处置”四位一体体系，并强调健全预防和监测机制、主动干预：
  [教育部正式文件](https://www.moe.gov.cn/srcsite/A17/moe_943/moe_946/202305/t20230511_1059219.html)
- 证据等级：A

**施工约束**：风险模块不能只做预警展示；必须能连接咨询/谈话、人工处置、后续跟进和必要转介。

### 4.2 心理风险要专业干预，不能由算法自动定性

- 《高等学校学生心理健康教育指导纲要》要求构建教育教学、实践活动、咨询服务、预防干预“四位一体”格局，重视心理问题及时疏导和危机预防干预，强调分类服务、家校合力和危机转介：
  [教育部正式文件](https://hudong.moe.gov.cn/srcsite/A12/moe_1407/s3020/201807/t20180713_342992.html)
- 证据等级：A

**施工约束**：系统只提供“需关注/待专业研判”及来源摘要；心理诊断、危机等级最终确认和转介决定必须由具备授权的专业人员完成。

### 4.3 风险数据中包含多类敏感个人信息

- 国家网信办2026年个人信息保护政策法规问答明确：医疗健康、金融账户、连续精准定位轨迹等属于敏感个人信息，教育经历、消费记录、收入状况、位置、用户画像等属于个人信息：
  [国家网信办个人信息保护政策法规问答](https://www.cac.gov.cn/2026-01/09/c_1769688003183197.htm)
- 《中华人民共和国个人信息保护法》规定了敏感个人信息处理、告知和个人信息保护影响评估等要求：
  [中国人大网法律原文](https://www.npc.gov.cn/WZWSREL25wYy9jMi9jMzA4MzQvMjAyMTA4L3QyMDIxMDgyMF8zMTMwODguaHRtbD9yZWY9aW1i)
- 《中华人民共和国数据安全法》要求建立数据分类分级保护和风险监测、处置机制：
  [工业和信息化主管部门转载法律原文](https://sdca.miit.gov.cn/zwgk/fgbz/art/2026/art_ce88eeb3d3744672a54923061c125885.html)
- 证据等级：A

**施工约束**：

1. 看板默认只显示必要摘要，不显示心理原文、精确轨迹、完整消费流水和家庭经济明细。
2. 心理/医疗、精确轨迹、完整家庭经济等字段实行单独权限、逐生业务关系、查看原因和安全审计。
3. 规则计算尽量使用派生指标，避免把无关原始明细复制到风险表。
4. 导出默认脱敏、水印、用途必填并记录导出审计。

## 6. 可直接进入施工卡的设计结论

以下为基于外部证据和本项目权限底座形成的 `design_inference`，不是声称某一家产品逐字段完全一致。

### 6.1 风险看板

必须具备：

1. 总风险数、今日新增、待分派、处理中、待跟进、已超时、已升级、已关闭。
2. 按风险等级、来源域、学院/班级、责任单位、处理状态、时间进行筛选。
3. 来源趋势、等级分布、超时率、关闭率、复开率、高频问题分布。
4. 所有统计按当前激活角色与数据范围计算；禁止前端拿全量后自行过滤。
5. 点击数字必须带同一筛选条件进入风险学生/风险记录列表，不能落到无条件全量页。
6. 明确数据更新时间、扫描批次和失败来源；数据未同步不能显示为“零风险”。

### 6.2 风险学生

必须具备：

1. 学生维度聚合视图，但保留每条独立风险记录，禁止把不同来源覆盖成一个不可追溯总分。
2. 展示风险等级、来源摘要、命中规则、首次/最近发生时间、责任人、当前状态、最后处置时间。
3. 相同来源记录按 `(tenant_id, source, source_ref_id)` 去重；跨来源可聚合但不能物理合并原始记录。
4. 心理来源默认只显示“需关注”，完整内容需要心理专项权限 + `PSY_STUDENT` 关系 + 查看原因 + `SENSITIVE_VIEW` 审计。
5. 支持从学生页进入处置时间线、谈心记录摘要和后续跟进，不直接复制心理/家庭经济原文。

### 6.3 风险处置

建议状态机：

`NEW → ASSIGNED → PROCESSING → WAIT_FOLLOWUP → CLOSED`

辅助状态/动作：

- `ESCALATED`：升级后仍需明确接收责任人，不得只改变等级。
- `TRANSFERRED` 作为动作轨迹而非永久终态；接收确认后回到 `ASSIGNED/PROCESSING`。
- `REOPENED` 作为动作轨迹，记录原关闭结论和复开原因，状态回到 `PROCESSING`。
- 危急事件允许 `TAKEOVER`，但必须记录接管人、接管原因、原责任人和通知对象。

每次处置必须记录：

- 动作、前后状态、责任单位/责任人；
- 处置摘要、后续计划、下次跟进时间；
- 规则版本、来源引用；
- 操作人、激活角色、数据范围、时间、trace_id；
- 是否发送消息/待办及发送结果。

关闭条件：

- 至少存在一条有效处置记录；
- 填写关闭结论和依据；
- 存在后续跟进的，必须完成或明确转交；
- 心理危机等专业事项由授权专业人员确认，不允许普通管理员单独关闭。

## 7. 明确禁止写入产品的伪需求

1. 不得根据消费少、上网时长、晚归等单一指标自动判定学生“贫困”“心理异常”或“违纪”。
2. 不得向普通辅导员、学院管理员或学工处默认开放心理原始记录。
3. 不得长期保存与处置无关的精确位置轨迹到风险记录表。
4. 不得用一个不可解释的AI总分替代来源、规则和人工核实。
5. 不得把“已推送消息”视为“已处置”；必须有接收、处理和结果。
6. 不得因规则重跑产生重复风险单；必须具备来源幂等键和扫描批次。
7. 不得让平台运营方跨租户查看学校风险明细；运维协助另走授权、时效和审计流程。
