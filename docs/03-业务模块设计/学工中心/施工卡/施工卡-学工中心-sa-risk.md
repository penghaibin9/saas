## 1. 模块定位与真实学校业务价值

### 1.1 真实学校谁在用、解决什么

| 角色 | 真实使用场景 | 本模块解决的痛点 |
|---|---|---|
| 辅导员（最高频） | 每天在工作台看「我的风险学生」，逐个处置：联系学生/家长、转谈话、记录、升级或关闭 | 过去风险散在请假逾期表、宿舍夜不归宿表、学业预警表、心理关注表里，辅导员要跨多个系统/表格自己拼；本模块把七类来源汇成一个「风险中枢」，一处看全、一处处置 |
| 学院学工负责人 | 看本院风险分布、督办长期未处置、接管被升级的高危风险 | 学院层缺乏统一的风险台账与督办抓手 |
| 学工处管理员 | 全校风险看板、按学院/等级/来源统计、批次归档 | 校级要「可核查、可上报的账」，而非流程碎片 |
| 心理老师 | 处置心理来源风险（强权限、明细隔离） | 心理数据必须与普通风险分级，普通教师只见「需关注」 |
| 宿管老师 | 处置宿舍来源风险（夜不归宿反复/安全隐患升级） | 宿舍异常到风险的自动升级闭环 |

### 1.2 商业价值一句话（供投标响应引用）

「多来源风险自动汇聚 + 责任到人 + 处置留痕 + 超期升级 + 心理数据强隔离」的学工风险中枢，把辅导员从「跨表找风险」变成「一屏处置风险」，并为学院/学校提供可上报的风险台账与督办视图。依据：《13A-学工中心-商业化对标审计与补丁建议（第一轮）.md》第五步 module 10「风险预警」（L156）、精华原则 12（L97）。

## 2. 三家成熟系统对标表（按 CLAUDE.md §0.0 十点）

### ① 对标对象 A：正方（成熟学工/一体化教务学工产品线）
- 核心流程：风险/预警从各业务（请假、学业、宿舍、心理）汇聚 → 责任人处置 → 关闭归档。**具体流程细节需人工确认（未联网核验）**。
- 角色：校级、院级、辅导员分层看板。**需人工确认**。
- 字段：风险来源、等级、责任人、处置记录。**需人工确认**。
- 亮点：与教务学业预警同源打通。**需人工确认**。
- 缺点：模块耦合重、实施定制成本高（行业普遍反馈，**需人工确认**）。

### ② 对标对象 B：强智（成熟高校信息化产品线）
- 核心流程：预警指标库 → 触发 → 分派 → 跟踪。**需人工确认（未联网核验）**。
- 角色：分级预警责任体系。**需人工确认**。
- 字段：预警级别、指标、处理状态。**需人工确认**。
- 亮点：预警规则可配置。**需人工确认**。
- 缺点：学工与教务预警口径易割裂。**需人工确认**。

### ③ 对标对象 C：青果（成熟学工/教务产品线）
- 核心流程：学工事务与预警联动。**需人工确认（未联网核验）**。
- 角色：辅导员为中心的工作台。**需人工确认**。
- 字段：学生画像 + 风险标签。**需人工确认**。
- 亮点：辅导员工作台聚合。**需人工确认**。
- 缺点：移动端处置能力参差。**需人工确认**。

### ④ 三家共同具备的核心功能（仓库审计文档已提炼为通用精华，可直接采信）

### 4.3 责任人分派规则（已实现，本卡照用）
来源：状态机 §6（L274）、按钮矩阵 09-3（L669）、表单 §3.11（L314）。
- 学业来源 → 辅导员；心理来源 → 心理老师 + 辅导员；宿舍来源 → 宿管 + 辅导员；实习来源 → 指导教师 + 辅导员。

### 4.4 超期升级（已实现，本卡照用）
来源：状态机 §6.2（L294–301）。

| 触发 | 条件 | 动作 |
|---|---|---|
| 分派超时 | NEW 停留 ≥4h | 自动分派→ASSIGNED；RISK_ALERT→责任人 |
| 处置超时 | ASSIGNED ≥48h 无首条处置 | DEADLINE_REMINDER→责任人；≥72h 自动→ESCALATED + RISK_ALERT→学院学工 |
| 跟进超时 | FOLLOWING ≥14 天无跟进 | DEADLINE_REMINDER→责任人 |
| 自动重开 | CLOSED 后 30 天内同学生同来源再次命中规则 | 自动→REOPENED（非新建），保留历史链 |

### 4.5 非法转移防护（已实现，本卡照用）
来源：状态机 §6.1（L287–292）、表单 §3.11（L318/L329）。
- NEW/ASSIGNED 无任何处置记录直接关闭 → **409**（至少一条处置记录）；
- 非责任人处置/转办后原责任人写操作 → **403 NO_DATA_SCOPE**（可读历史）；
- 来源=学业预警的记录引用既有 `t_acad_warning`（不复制），双向状态同步，重复建单 → **409**；
- 同一风险单 5 秒内相同内容处置记录去重 → **409001**；升级动作同一单进行中仅一次（表单 §3.11 L329）。

### 4.6 风险来源枚举（**存在口径冲突，需人工确认**）
- **数据表（权威库结构）** `t_affairs_risk_record.source` = `LEAVE_OVERDUE / ACADEMIC_WARNING / DORM / MENTAL / DISCIPLINE / INTERNSHIP / GRADUATION_DESIGN / EMPLOYMENT / FAMILY / MANUAL`（**10 类**）（数据表 §3.6，L141）。
- **状态机**引言列举：心理关注/学业预警/请假异常/宿舍异常/处分/长期未登录/实习异常/就业异常/家庭困难/人工标记/家校反馈（**11 类**，多「长期未登录」「家校反馈」）（状态机 §6 L269）。
- **本任务下发**表述为「**七类来源**」。
- 【需人工确认】三处来源数量不一致（10 / 11 / 7）。施工前须由甲方确认**权威来源清单**；建议以数据表 `source` 枚举（10 类）为库级权威，状态机多出的「家校反馈/长期未登录」若保留需补进枚举，任务「七类」若指「PC 首期只做的七类」需明确是哪七类。**不得由开发自行取舍**。

7. NEW/ASSIGNED 无处置记录直接关闭 → **409001**；
