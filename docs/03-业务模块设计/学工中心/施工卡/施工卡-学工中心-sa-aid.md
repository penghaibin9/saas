## 1. 模块定位与真实学校业务价值

### 1.1 真实学校谁在用、解决什么

| 角色 | 真实工作场景 | 本模块为其解决的问题 |
|---|---|---|
| 资助老师 / 学工处资助中心 | 每学年建国家奖/励志奖/校奖/助学金/勤工/贷款批次，组织评审、公示、发放、报表上报 | 项目库 + 批次 + 评审 + 公示 + 发放台账 + 金额汇总一站式，替代 Excel 满天飞 |
| 辅导员 | 初审本班奖助申请、核实困难情况、代提推荐名单、核对贷款回执 | 待办直达、本班获助一览、初审即办，减少线下收表 |
| 学院学工负责人 | 学院评审会差额排序、复审奖学金名单 | 学院评审页强制差额排序、名单对账 |
| 用工部门管理员 | 发布勤工岗位、筛选初选名单、每月录考核工时 | 岗位发布 + 部门筛选 + 月度考核补贴流水 |
| 学生本人 | 申请奖助、报名勤工岗、登记助学贷款、查资助进度、看本人受助档案 | 移动端「资助」聚合页，申请到进度到结果全程可视 |
| 校/院领导 | 看奖助覆盖率、资助金额汇总、困难生受助率 | 统计看板下钻名单（脱敏），支撑上报与决策 |

> 依据：`总册 §3.7 ①角色四问`（L410）、`⑧数据范围`（L434）、`⑮入口`（L448）；权限总控 `资助老师` 行（`00-系统管理中心-权限角色模块授权与权责边界设计.md` L267）。

### 1.2 一句话投标响应功能描述（商业化口径，精华原则 15）

> 奖助勤贷补以「统一资助项目抽象」承载**奖学金、助学金、勤工助学、助学贷款**四大主链及**学费减免 / 临时补助 / 绿色通道**三类项目开关，覆盖项目库→批次→资格校验→申请→三级评审→公示→发放台账→金额汇总统计的完整闭环，金额与银行信息加密脱敏、导出带水印审计，学生端移动申请、辅导员本班初审、学院差额评审、资助中心复核发放全角色协同。困难库、成绩、处分三校验器保证资格真实，绿色通道与数字迎新缓交数据打通。

依据：`总册 §3.7 ⑯模块关系`（L449）、`⑰V1必做/P2P3`（L450）。

## 2. 三家成熟系统对标表（CLAUDE.md §0.0 十点结构）

> **对标对象**：正方（ZFsoft 学工/资助）、强智（QZDATA 学工/资助）、青果（QGSOFT 学工/资助）——三家均为经大量高校采购、部署、验收的成熟校园系统。
> **口径声明**：以下 A/B/C 三家的「核心流程/角色/字段/亮点/缺点」，凡与仓库审计 15 条精华原则一致处，标注来源；凡属产品级细节（具体字段名、界面、内部实现）**本卡未联网核实，标「需人工确认（需联网或招标文件/操作手册核实）」**，不冒充已完成外部对标。严禁抄袭其界面、代码、数据库、商标。

### 2.1 对标对象 A：正方 学工/资助

- **核心流程**：项目立项→名额下达学院→学生网上申请→辅导员初审→学院评审→学校审定→公示→发放名单导出上报。**（流程主干与本模块一致；具体节点命名需人工确认）**
- **角色**：学生、辅导员、学院管理员、学工处/资助中心管理员、（勤工）用工部门。
- **关键字段**：项目类型、批次学年、名额、资格条件、申请理由、绩点引用、困难等级引用、发放金额、公示名单。**（字段清单为行业通用推断，精确字段需人工确认）**
- **亮点**：与教务成绩、学籍数据同源打通（绩点/学籍直读），名额分配到学院精细化，报表上报模板丰富。
- **缺点**：勤工月度考核、贷款毕业还款提醒等长尾环节较弱；移动端体验偏后置（依版本）。

### 2.2 对标对象 B：强智 学工/资助

- **核心流程**：资助项目库配置→批次开放→学生申请（含困难认定前置）→多级审核→公示异议→结果归档→金额台账。**（主干一致；节点细节需人工确认）**
- **角色**：同 A，另含评审专家/评委打分角色（量化评审）。
- **关键字段**：项目类型、准入困难等级、量化评分项、公示区间、发放批次。**（需人工确认）**
- **亮点**：量化评审打分成熟（评分表 + 差额排序），困难库与助学金强绑定，参数化程度高（各校阈值可配）。
- **缺点**：量化评审对小校偏重；银行代发对接依地方政策，标准化程度受限。

### 2.3 对标对象 C：青果 学工/资助

- **核心流程**：项目/批次→申请→审核→公示→发放；勤工岗位发布→报名→录用→考核。**（主干一致；细节需人工确认）**
- **角色**：同 A，勤工场景强化用工部门角色。
- **关键字段**：岗位工时/时薪/名额、月度考核工时、补贴发放、贷款回执。**（需人工确认）**
- **亮点**：勤工助学岗位→报名→上岗→月度考核→补贴链条完整；台账导出规整。
- **缺点**：奖学金量化评审相对轻；跨年度贷款滚动台账依实施配置。

> 以上三家的产品级流程/字段判断来自：仓库审计对标声明（`审计 L6` 明确对标正方/强智/青果的「产品精华与业务成熟度」）+ 行业通用认知；**未逐项联网核实，均标需人工确认**。

### 2.4 三家共同具备的核心功能（默认即本项目必须具备的基础能力）

1. 资助**项目库 + 批次**双层配置（项目定类型/条件，批次定学年/窗口/名额）。
2. **学生网上申请 + 资格前置校验**（成绩/困难/学籍/处分）。
3. **多级审核链**（辅导员初审→学院评审→学校审定）+ 退回/驳回。
4. **公示 + 异议处理**（脱敏公示、期满确认）。
5. **发放/获助名单台账**（可导出上报）。
6. **金额汇总统计**（覆盖率、金额、困难生受助率）。
7. **勤工岗位 + 月度考核补贴**链条。
8. **助学贷款登记 + 回执核对 + 年度滚动台账**。
9. **敏感数据脱敏**（金额区间化、银行/身份证脱敏、公示不出家庭明细）。
10. **导出水印 + 审计**。

### 4.2 通用状态转移（含责任人 / 审批 / 通知 / 审计 / 进 360）

## 12. 验收标准（页面级用例）

|---|---|
| 进入 | 8 页均可从菜单/待办/下钻进入；planned 页进公共占位页不白屏 |
| 旧路由兼容 | 旧资助入口 redirect 到 `/admin/student-affairs/funding`，刷新不 404（`CLAUDE.md §9.1`） |

| 资格校验 | 有未解除处分/非困难库/绩点不达标/同批次重复 → 422001/409001 携明细，不允许提交 |
| 脱敏 | 银行卡后 4 位、电话掩码、金额按档位；公示不出家庭明细 |
| 审计 | 审批/公示/发放/导出/查看完整银行号全部写审计，可追溯到人 |
| 三态 | 列表 loading / empty / error / no-permission / network-error 全覆盖（`CLAUDE.md §17`） |
| 导出 | 带水印 + 用途必填 + t_export_task 留痕；金额导出二次确认 |
| 无假按钮 | 无 mock 成功；发放 result 真实写库；无假数据页（`CLAUDE.md §38.9`） |
| 台账对账 | 统计（07-12）金额汇总与 result 台账下钻名单 0 差异（精华原则 9） |
| 状态机 | 各终态 ARCHIVED 只读，写操作→409；节点级退回可回 COUNSELOR_REVIEW |
