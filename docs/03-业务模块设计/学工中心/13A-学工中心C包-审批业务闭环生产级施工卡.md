# 13A 学工中心 C 包-审批业务闭环生产级施工卡

> C 包承接 B 包形成的画像、权限、数据范围和待办基础，重点补齐资助、处分、谈话、家校等闭环。本文档是施工卡，不是实现记录。

## 1. C 包范围

| 模块 | 优先级 | 目标 | 建议提交 |
|---|---|---|---|
| 困难认定 | P0 | 形成批次、申请、评议、公示、复核、归档闭环 | `feat(student-affairs): add aid identification workflow` |
| 奖助勤贷补 | P0 | 项目、名额、申请、评审、公示、发放台账闭环 | `feat(student-affairs): add funding workflow` |
| 违纪处分 | P0 | 登记、调查、告知、处分、申诉、解除、归档闭环 | `feat(student-affairs): add discipline workflow` |
| 谈心谈话 | P1 | 谈话计划、记录、跟进、风险联动 | `feat(student-affairs): add talks and followups` |
| 家校联系 | P1 | 联系、回执、后续跟进与风险联动 | `feat(student-affairs): add home-school contact loop` |

| 状态机 | draft/submitted/class_review/college_review/public_notice/objection_review/confirmed/rejected/archived |

## 7. C 包统一验收

所有 C 包页面必须具备：流程状态可解释、审批动作有权限、有数据范围、附件可预览、导出需确认、敏感信息默认脱敏、审计可追踪、空态/错误态/加载态完整。不得用前端隐藏替代后端权限，不得把未接流程引擎的页面标为闭环完成。
