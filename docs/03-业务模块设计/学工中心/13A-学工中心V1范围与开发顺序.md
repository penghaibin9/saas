## 1. 功能分档清单（V1 必做 / P2 / P3）

判档原则：
- V1 = 需求 §10 学工 V1 名单 + 支撑闭环所必需的底座（契约/范围/规则/360 沉淀）。
- P2 = 有业务价值但不阻塞主闭环、或依赖现场确认项（需求 §9）未回答的。
- P3 = 复杂算法/深度集成/家长端等，需 V1 数据沉淀后才有意义的。

| 功能 | 档位 | 理由 | 依赖 |
|---|---|---|---|
| 学工首页（三角色视图） | V1 | 模块门面，聚合既有六域即可先出 | stats_service 扩展、dashboard preset |
| 辅导员工作台 | V1 | 最高频入口，闭环的枢纽 | scope 机制、t_unified_todo、六域计数 |
| 学生信息与画像（360 学工视角） | V1 | "进入 360"是每个业务的验收项 | StageEvent、teacher student/{id} 聚合扩展 |
| 班级管理（档案/学生/班干部/画像） | V1 | 辅导员范围与画像的载体 | t_class 绑定关系 |
| 请假/销假/续假全闭环 | V1 | 核心示范流程，需求点名【核心】 | t_cs_leave 扩展方案、Workflow、规则中心 |
| 困难认定（批次/申请/多级评审/公示/困难库） | V1 | 奖助的前置数据源 | Workflow、敏感矩阵、公示规则 |

| 短信通知 | P2 | 需求 §9 待确认；已有 sms provider 骨架可后接 | notification 服务 |
| 宿舍房源/入住/调宿/检查（基础） | V1 | 需求 V1 名单"宿舍基础"；异常进风险 | 迎新分宿初始化、t_cs_dorm_* |
| 智能排宿 | P2 | 需求 §10 明示后置；V1 人工分配+校验 | 房源台账 |
| 夜不归宿/公寓纪律/文明寝室评比 | P2 | 检查基础先行，评比后置 | 宿舍检查 |
| 学生活动/志愿/第二课堂 | P2 | 需求 §10 后置（复杂积分 P2/P3） | 360、积分规则 |
| 社团/学生组织/党团建设 | P2/P3 | 需求 §10 明示 | 活动 |

| 学工材料归档 | V1（基础） | V1 名单含归档；范围=已闭环业务的档案包 | 各业务终态、export 水印管线 |
| 学工统计分析 | V1（随各业务） | 指标随业务上线逐卡点亮 | stats_service 扩展 |
| 移动端学工服务（学生请假全流程等） | V1 | 需求 §11：请假移动端全流程、长假回 PC | miniapp 请求层 |
| 家长端 | P3 | 需求 §10 明示 | 家校联系 |
| 行为大数据预警 | P3 | 需求 §10 明示 | 风险数据沉淀 |

**V1 边界一句话**：首页 + 工作台 + 班级 + 请假闭环 + 困难认定 + 奖/助学金基础 + 处分与解除 + 风险预警 + 谈话 + 家校基础 + 宿舍基础 + 归档基础 + 统计随行 + 小程序入口。

## 2. 开发阶段 13A-P1 … P9

通用约束（每阶段适用）：
- 所有新端点遵循统一响应体与错误码；教师写操作走范围校验；学生写操作 student_id 取自 token。
- 每阶段交付自带 pytest（新增用例）且**现有全量 pytest 必须保持绿**；demo-school 只读锁与 sandbox 重置不受影响。
- 每阶段结束更新契约文档偏差记录（若与 P1 冻结契约有出入必须显式记录并评审）。

### 13A-P1 契约冻结
- **目标**：冻结 13A 全部 API 契约、表结构、状态机、workflow_code/node_code、权限点、消息类型、统计口径、导出 domain、规则键。产出契约文档一份，后续阶段只实现不设计。
- **涉及页面**：无（纯契约）。页面树与路由表（/admin/student-affairs/* 全量清单）作为契约一部分冻结。
- **涉及接口**：定义不实现——student-affairs/dashboard、counselor/workbench|students|todos|risk-students、leave 族、aid 族、funding 族、discipline 族、risk 族、talk 族、dorm 族、archive 族、classes 族、students/{id}/profile|timeline、mobile/affairs/* 学生族。
- **涉及状态机**：请假 14 态、困难认定 12 态、处分 11 态、风险 8 态、调宿、归档——全部冻结含转移表（谁在什么状态可做什么、退回回到哪）。
- **涉及权限点**：`studentAffairs.*` 全量命名表冻结（每业务 view/create/approve/handle/export/config）。
- **涉及测试**：契约评审 checklist（与速查 §1-§11 逐条对齐）；无自动化测试。
- **不允许做什么**：不写实现代码；不新建数据库对象；不修改既有六域契约；不引入速查中未列的响应结构。
- **验收标准**：契约文档覆盖率 100%（每页面 41 项规格引用、每接口出入参、每状态机转移表）；与融合设计 8 条红线无冲突；评审通过并打冻结标记。

### 13A-P2 首页与工作台
- **目标**：学工首页三角色视图 + 辅导员工作台可用，先聚合既有六域数据（13A 自有业务卡置灰/为 0），验证 scope 与 preset 机制后再上业务。
- **涉及页面**：
  - /admin/student-affairs（首页，三角色差异视图：学工处/学院学工/辅导员）。
  - /admin/student-affairs/workbench（工作台 13 模块卡）。
  - 班级管理页面组骨架（列表/详情/学生/画像）。
  - 学生快速搜索、学生 360 入口（跳既有 teacher student/{id} 聚合）。
- **涉及接口**：
  - GET student-affairs/dashboard（summaryCards/todoList/riskStudents/workflowPending/classOverview/warningTrends/recentActivities 七区块）。
  - GET counselor/workbench、counselor/students、counselor/todos、counselor/risk-students（此阶段 risk 读实习域 t_risk_record + 学业 t_acad_warning）。
  - GET classes、classes/{id}、classes/{id}/students。
  - stats_service.get_affairs_stats(scope) 骨架（与 dashboard 共用查询构造）。
- **涉及状态机**：无新状态机。
- **涉及权限点**：studentAffairs.counselor.dashboard.view / student.view / todo.handle / risk.handle；studentAffairs.home.view（三角色 preset）。
- **涉及测试**：三角色 dashboard 返回结构与 scope 差异（学工处全校/学院/辅导员班级）；辅导员越权访问他班学生列表 403；demo-school 可读。
- **不允许做什么**：不做 13A 业务写操作；不建 t_affairs_* 业务表（仅可建 dashboard 无关的 0 张表）；不改 stats 既有四端点行为。
- **验收标准**：三角色登录见差异化首页；辅导员工作台 13 个模块卡全部渲染（未上线业务显示空态）；每卡下钻路由可达；scope 用例全过。

### 13A-P3 请假销假闭环【核心示范】
- **目标**：请假/审批/销假/续假/逾期全链路上线，作为 13A 流程范式（后续业务照此模式复制：状态机 + workflow 建流 + todo 联动 + 360 沉淀 + 统计点亮的标准五件套）。
- **涉及页面**：
  - PC：请假列表 / 请假详情 / 新增请假(代录) / 请假审批 / 销假确认 / 续假申请 / 请假统计 / 规则配置（读写平台规则中心）。
  - 小程序学生：leave-apply / leave-list / leave-detail / leave-cancel / leave-extension。
  - 教师移动端：审批卡（复用移动审批包装，payload 加请假摘要）。
- **涉及接口**：
  - POST /student-affairs/leave；GET leave/my、leave/pending、leave/{id}。
  - POST leave/{id}/approve | reject | cancel-leave | extension。
  - mobile/affairs/leave* 学生族；逾期扫描任务（幂等）。
  - 兼容层：既有 campus-service 请假读端点代理新表。
- **涉及状态机**：请假 14 态全量 + 旧 t_cs_leave 三态映射（PENDING_REVIEW→COUNSELOR_REVIEW / APPROVED / RETURNED）；workflow AFFAIRS_LEAVE / _LONG / _MAJOR / _EXTENSION / _CANCEL。
- **涉及权限点**：studentAffairs.leave.view / create / approve / cancelConfirm / export / config。
- **涉及测试**：状态机全转移用例；重复提交 409；跨学生 403/404；天数阈值分流（规则中心改值生效）；逾期→OVERDUE→风险记录→辅导员待办；旧数据迁移脚本 dry-run 校验；t_cs_leave 兼容期读端点回归。
- **不允许做什么**：不动 t_cs_leave 表结构；不删旧 API（兼容期）；不自建审批表/消息表；不做家长短信（仅预留 parent_notify 规则位）。
- **验收标准**：小程序提交→辅导员移动审批→销假→CLOSED→学生 360 出时间线记录→首页"在假/逾期"卡数字变化，全链路演示通过；409/403 用例过；现有 campus-service 相关 pytest 不红。

### 13A-P4 困难认定与奖助基础
- **目标**：困难认定批次全流程 + 困难学生库 + 奖学金/助学金申请评审公示；家庭经济敏感管线落地（本阶段是敏感数据处理的范式阶段）。
- **涉及页面**：
  - PC 认定：批次管理 / 申请列表(脱敏) / 申请详情 / 评审 / 公示 / 困难学生库。
  - PC 奖助：项目 / 批次 / 申请列表 / 评审 / 公示 / 结果。
  - 小程序学生：aid-apply / aid-detail（12 态进度条）/ funding-apply。
- **涉及接口**：
  - aid/batches、aid/apply、aid/{id}/review、aid/difficult-students、家庭经济"查看完整"专用端点（原因必填+审计）。
  - funding/projects | batches | applications | {id}/review | publicity | results。
  - 公示到期定时流转任务（幂等）；导出 domain=affairs_aid_list / affairs_funding_result。
- **涉及状态机**：认定 12 态（含 PUBLICITY 定时流转，公示天数走规则中心）；奖助申请状态机；workflow AFFAIRS_AID_IDENTIFY / _ADJUST / SCHOLARSHIP / GRANT。
- **涉及权限点**：studentAffairs.aid.view/apply/review/viewSensitive/export；studentAffairs.funding.*。
- **涉及测试**：家庭经济默认脱敏+看完整需原因+审计落表；奖学金校验（学籍异常/未解除处分/成绩不达标/同批次重复→422/409）；助学金读困难库前置校验；公示到期自动流转；导出带水印且非授权角色列剔除。
- **不允许做什么**：不做勤工/贷款/减免/临时补助/绿色通道（P2）；不做"系统智能推荐名单"算法（V1 只做规则校验）；不在列表接口回家庭经济数字。
- **验收标准**：一个批次从创建到 ARCHIVED 全程可走；困难库供助学金引用；敏感四用例（脱敏/审计/水印/越权）全过；360 出认定与获奖记录。

### 13A-P5 处分与风险预警
- **目标**：处分登记→生效→解除全流程 + 风险预警中枢（多来源接入/分派/处置/升级/关闭），并完成与 t_cs_discipline 投影、与既有各域风险来源的联动。
- **涉及页面**：
  - PC 处分：登记 / 列表 / 详情 / 审批 / 解除申请 / 解除审批。
  - PC 风险：列表 / 详情 / 处置 /（详情页动作）转办 / 升级 / 关闭 / 重开。
  - 工作台风险卡与首页"风险学生"卡点亮（下钻至学生 360）。
  - 教师移动端：risk-handle 处置页。
- **涉及接口**：
  - discipline/cases 族 + {id}/remove-apply；EFFECTIVE/REMOVED 的 t_cs_discipline 投影同步（事务内）。
  - risk/records 族 + {id}/assign | handle | transfer | escalate | close | reopen。
  - 五来源接入读取（t_cs_leave affairs_status=OVERDUE / t_acad_warning / t_cs_dorm_exception / 实习域 / t_cs_mental_record 引用）；超时自动升级扫描（幂等）。
- **涉及状态机**：处分 11 态、风险 8 态；workflow AFFAIRS_DISCIPLINE / _REMOVE。
- **涉及权限点**：studentAffairs.discipline.view/register/review/remove/export；studentAffairs.risk.view/handle/escalate/close。
- **涉及测试**：处分 EFFECTIVE 同步 t_cs_discipline 投影行（学生端数量接口回归）；REMOVED 后毕业审核读最新状态（供 13B 接口预留）；风险五来源（请假逾期/学业预警/宿舍异常/实习异常/心理）各建一条并按责任规则分派；心理来源明细对普通教师隐藏；升级/重开转移合法性。
- **不允许做什么**：不改 t_cs_discipline / t_acad_warning / 实习域表结构；不做行为大数据自动预警（P3）；处分不联动德育积分（P2）。

```
P1 契约冻结
 ├──→ P2 首页与工作台（只依赖 P1 + 既有六域）

P9 测试验收（依赖全部）
```

**并行建议**（两条开发线）：
- A 线（流程线）：P3 → P5 → P6，专注状态机+workflow 范式。
- B 线（数据线）：P2 → P4 → P7，专注聚合/批次/台账。

**并行泳道示意（时间从左至右，非等宽）**：

```
后端A(流程线)：P1━━┓        ┏━P3请假━━━━┓ ┏━P5处分风险━━┓ ┏━P6谈话360━┓
```

| 就业未填报→待办 | P2 计数卡 / 后续待办生成 | employment 既有表 | 无阻塞 |
| stats/dashboard 扩展 | P2 起逐卡点亮 | 既有 stats 四端点不动 | 13B 教务指标独立接入，互不阻塞 |

结论：13A 全部九阶段不依赖 13B 任何交付，可独立排期先行；13B 仅在毕业资格预审阶段消费 13A P5 的处分状态契约。
