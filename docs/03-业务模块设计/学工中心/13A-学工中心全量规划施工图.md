# 13A 学工中心全量规划施工图

> 本文为任务包 A 的主施工地图。它只冻结“要建什么、接哪里、欠什么、先后顺序是什么”，不代表页面、接口、数据库或小程序已经施工完成。

## 0. 状态口径

| 状态 | 含义 | navPlan 等价 | 可否在正式菜单中直接当完成项 |
|---|---|---|---|
| `implemented` | 真实前后端 + MySQL + 权限范围 + 审计 + 测试 + 验收通过 | implemented | 是 |
| `partial` | 有部分能力（后端/旧页/外链/mock），未形成生产闭环 | partial | 否，须标待补 |
| `planned` | 仅设计文档，无真实闭环 | planned / hidden | 否 |
| `external-link` | 主能力在外部模块，学工只做入口/摘要/跳转 | external-link | 否，须标明外链 |
| `merged` | 多三级入口合并为同页 Tab/面板（如画像各摘要区块） | merged | 视父页验收而定 |
| 已承接（历史口径） | 同 `partial` 或 `external-link`，已有系统可串联 | partial | 否 |
| 部分完成（历史口径） | 同 `partial` | partial | 否 |
| 外链/过渡（历史口径） | 同 `external-link` | external-link | 否 |
| 待施工（历史口径） | 同 `planned` | planned | 否 |

硬规则：

1. **数字迎新**全部三级入口默认 `external-link` + `partial`，禁止全量标 `implemented`；日期/Excel/导出/水印/审计归 **D 包专项**。
2. **在校服务**默认 `external-link` + `partial`，学工只做承接摘要，不得标学工已完成。
3. **学生主档**在画像中 `merged` 承接，学工不重复造学生中心。

## 3. 现有系统串联结论

| 现有系统/目录 | 承接模块 | 结论 |
|---|---|---|
| `frontend/src/views/admin/student`、`frontend/src/modules/student` | 学生画像 | 已有学生中心能力，学工中心只收编入口和摘要，不复制学生主档 |
| `frontend/src/views/admin/orientation`、`frontend/src/modules/orientation` | 数字迎新 | 已有独立迎新系统，学工中心只做入口/摘要/跳转 |
| `backend/app/api/v1/student_affairs.py` 和 `backend/app/services/affairs_*.py` | 请假、奖助、处分、风险、谈话、宿舍、归档等 | 后端已有一批学工能力，PC 页面和公共底座接入仍是主要缺口 |
| `miniapp/src/pages/student/affairs`、`miniapp/src/pages/teacher/affairs` | 学生端/教师端学工入口 | 已有移动端痕迹，需要按 B/C/D 分包接真实状态 |
| `frontend/src/components/common/date` | 日期时间底座 | 公共底座存在，数字迎新尚未全量迁移 |
| `frontend/src/components/common/excel` | Excel 导入导出底座 | 公共底座存在，数字迎新和学工台账需逐页接入 |
| `frontend/src/components/common/AppExportConfirm.vue`、`AppAuditTrail.vue`、`AppPermissionButton.vue` | 导出确认、审计、权限按钮 | 公共底座存在，所有学工导出/审批/敏感操作必须接入 |
