## 第二部分：核心流程验收用例

用例格式：**前置 / 步骤 / 预期（状态变化 + 通知 + 360 + 统计）**。
公共前置：租户 sandbox-school（或测试租户）；学生 S1（student2，辅导员 T1 班级内）、学生 S2（T1 范围外）；辅导员 T1（teacher2）、学院学工 C1、学工处 A1。

### 流程 1：请假全链路（L1-L8）

**L1 学生提交普通请假**
- 前置：S1 无进行中请假；规则 college_threshold_days=3。
- 步骤：S1 小程序提交 2 天病假（原因 20 字、附材料）。
- 预期：t_cs_leave 新增/更新 1 行（affairs_status SUBMITTED→COUNSELOR_REVIEW）；生成 workflow 实例(AFFAIRS_LEAVE)与 T1 的 task；T1 收 t_unified_todo(WORKFLOW_TODO) 与消息；S1 端显示"待辅导员审批"；360 暂无记录；首页"请假待审"+1。

**L2 重复提交仅一条 + 409**
- 前置：L1 提交成功后单据非终态。
- 步骤：S1 对同一时间段再次点提交（或连点/弱网重试重放）。
- 预期：第二次返回 409001（IDEMPOTENCY_CONFLICT），文案"存在时间重叠的进行中请假"；库中仍仅 1 条；无新 workflow/todo/消息；提交锁期间按钮不可点。

**L3 辅导员审批通过**
- 前置：L1 单据处于 COUNSELOR_REVIEW。
- 步骤：T1 在教师移动端审批通过。
- 预期：单据 APPROVED；task=APPROVED 且 acted_at 落值；T1 待办置 DONE；S1 收 WORKFLOW_RESULT 消息；写 StageEvent(source_module='student-affairs')，S1 的 360 时间线出现"请假获批"；首页"在假人数"+1、"请假待审"-1；审计有 approve 记录。

**L4 并发/重复审批 409**
- 前置：L3 已通过。
- 步骤：T1（或另一有权者）对同一 task 再次审批。
- 预期：409001 APPROVAL_VERSION_CONFLICT，提示"已被处理"；单据状态不变；无重复通知。

**L5 跨学生访问 403/404**
- 前置：S2 有一条请假单 X。
- 步骤：① S1 用自己 token GET /mobile/affairs/leave/{X}；② T1（S2 不在其 scope）PC/移动查看 X 或审批 X。
- 预期：① 404001（本人数据不存在语义）或 403，绝不返回 X 内容；② 403001/403002 且 t_security_audit_log 记录越权尝试；均无状态变化。

**L6 销假闭环**
- 前置：L3 的请假已到返校期内。
- 步骤：S1 点销假并上传返校证明→T1 确认。
- 预期：状态 APPROVED→WAIT_CANCEL_LEAVE→CLOSED；cancel_record 落实际返校时间；S1 收 STATUS_CHANGED；360 出"销假完成"；统计"在假人数"-1；单据进入可归档集合。

**L7 逾期未销 → 风险**
- 前置：一条 APPROVED 请假 end_time 已过且超宽限，未销假。
- 步骤：触发逾期扫描（两次）。
- 预期：状态→OVERDUE（仅第一次生效）；生成 1 条 t_affairs_risk_record(source=LEAVE_OVERDUE)（第二次扫描不重复）；T1 收 RISK_ALERT 待办；请假详情红色风险标识；统计"逾期未销"+1；风险闭环后（见 R 组）请假可 CLOSED。

**L8 退回修改重提**
- 前置：一条 COUNSELOR_REVIEW 单据。
- 步骤：T1 退回（填原因）→ S1 修改后重提。
- 预期：状态→RETURNED，S1 收 RETURNED_NOTICE 含原因；S1 端单据可编辑；重提后回 COUNSELOR_REVIEW 并生成新 task；退回历史保留可查；统计待审数先减后增。

### 流程 2：困难认定（A1-A5）

**A1 批次内提交申请**
- 前置：A1(学工处) 已建认定批次且开放；S1 未申请。
- 步骤：S1 小程序提交认定申请（家庭经济信息+材料）。
- 预期：apply 落表、家庭经济落隔离表；状态 SUBMITTED→CLASS_REVIEW（评议开启时）；评议人/T1 收待办；批次统计申请数+1。

**A2 重复提交仅一条 + 409**
- 步骤：S1 同批次再次提交。
- 预期：409001；库中仅 1 条；无新待办。

**A3 三级评审至公示通过**
- 步骤：班级评议→T1 初审→C1 复审→A1 终审→进入 PUBLICITY；到公示期满（publicity_days）。
- 预期：逐级状态推进且每级 task/todo 闭合；PUBLICITY 期满自动→APPROVED；等级写 level_history、进困难学生库；S1 收 PUBLISHED_NOTICE；360 出"困难认定通过（等级）"；统计"困难学生数"+1；公示名单接口全脱敏。

**A4 跨学生访问 403/404 + 敏感审计**
- 步骤：① S1 访问 S2 的认定详情；② 无 viewSensitive 权限的教师读家庭经济明细；③ T1 通过"查看完整"端点填原因读取。
- 预期：① 403/404；② 403001 且明细字段不出现在任何响应；③ 返回完整值且 t_security_audit_log 落 VIEW_SENSITIVE 记录（含原因）。

**A5 驳回与调整**
- 步骤：C1 复审驳回→S1 收通知；另对已 APPROVED 学生发起等级调整（AFFAIRS_AID_ADJUST）通过。
- 预期：驳回→REJECTED + RETURNED_NOTICE；调整通过后 level_history 新增一行且困难库等级更新、旧等级保留历史；统计按新等级重分布。

### 流程 3：奖学金申请（S1-S5）

**S1 合格学生申请**
- 前置：奖学金批次开放；S1 无未解除处分、成绩达标。
- 步骤：S1 提交申请。
- 预期：application 落表→COUNSELOR_REVIEW；T1 收待办；批次统计+1。

**S2 校验拦截（不能申请四连）**
- 步骤：分别以 学籍异常学生/有未解除处分学生/成绩不达标学生/材料缺失 提交。
- 预期：全部 422001（材料缺失逐字段提示）或业务拦截文案明确各原因；不产生半提交数据。

**S3 同批次重复申请 409**
- 步骤：S1 重复提交同批次。
- 预期：409001，仅一条记录。

**S4 评审公示确认全链**
- 步骤：T1 初审→C1 学院评审→A1 学校复核→公示→期满确认。
- 预期：状态逐级推进；确认后写结果表 + StageEvent，360 出"获奖记录"；S1 收 PUBLISHED_NOTICE；统计"奖助覆盖率"分子+1；结果导出带水印且登记 t_export_task。

**S5 跨学生访问 403/404**
- 步骤：S1 访问 S2 的申请详情；范围外教师审批该申请。
- 预期：403/404；审批越权 403 + 审计；状态不变。

### 流程 4：处分登记与解除（D1-D5）

**D1 登记并生效**
- 步骤：T1/C1 登记 S1 处分（警告级，附材料）→C1 初审→A1 复核通过→送达。
- 预期：case REGISTERED→…→EFFECTIVE；同事务写 t_cs_discipline 投影行（学生端数量接口 +1，明细仍不外泄）；S1 收送达 STATUS_CHANGED；360 出处分记录（按权限可见）；统计"处分数"+1；奖学金校验即刻拦截该生。

**D2 重复登记幂等**
- 步骤：同一事由（同 case 幂等键）重复提交登记。
- 预期：409001，仅一条 case；投影行不重复。

**D3 严重处分升学校审批**
- 前置：规则 school_review_levels=记过及以上。
- 步骤：登记记过处分并逐级审。
- 预期：node 序列多出 SCHOOL_REVIEW；少一级不能 EFFECTIVE；非法直改状态被拒（409/422）。

**D4 解除全链**
- 前置：D1 处分 EFFECTIVE 且满最短间隔（规则 remove_min_months，可临时调 0 测试）。
- 步骤：解除申请（表现材料）→T1→C1→A1 终审通过。
- 预期：REMOVE_REVIEW→REMOVED；投影行 record_status 更新（学生端"生效中数量"-1）；360 保留处分历史并新增"解除"事件；奖学金校验放行；统计"解除数"+1。

**D5 跨学生/越权 403/404**
- 步骤：S1 尝试读自己处分明细接口以外的 S2 处分；无权教师读处分文书。
- 预期：403/404；审计落表；学生端仅数量语义不变。

### 流程 5：风险预警处置（R1-R5）

**R1 多来源生成与分派**
- 步骤：分别触发 请假逾期(L7)/学业预警转风险/宿舍异常/实习异常引用/心理关注 五来源。
- 预期：五条 risk_record 各带 source 与 source_ref_id；按责任规则分派（NEW→ASSIGNED）；责任人收 RISK_ALERT 待办；首页/工作台风险数+5，风险学生卡可点进 360。

**R2 同源去重 409/幂等**
- 步骤：同一 source_ref 再次触发生成。
- 预期：不新增记录（幂等跳过或 409001）；总数不变。

**R3 处置到关闭**
- 步骤：T1 填处置记录→（可选转谈话）→关闭（填 close_record）。
- 预期：PROCESSING→CLOSED；close_record 落表；关联请假单可闭环；S1 相关提醒终止；360 出"风险关闭"摘要（不含心理明细）；统计风险数-1；重开（reopen）后回 REOPENED 并重新计数。

**R4 升级与超时自动升级**
- 步骤：① T1 手动 escalate；② 造一条超 auto_escalate_days 未处置记录跑扫描。
- 预期：ESCALATED，上级 C1 收待办；自动升级幂等（重复扫描不重复通知）；处置责任转移记录在 transfer 表。

**R5 越权访问 403 + 心理隔离**
- 步骤：范围外教师读风险详情；普通教师读心理来源风险明细；S1 读任何风险接口。
- 预期：范围外 403+审计；心理来源对普通教师仅"需关注"布尔、明细 403；学生无风险端点权限（403/404）；导出默认不含心理明细列。

### 流程 6：谈心谈话（T1-T5）

**T1 计划→记录→完成**
- 步骤：T1 建谈话计划（选 S1、主题学业）→按约完成→填记录。
- 预期：计划→完成；写 StageEvent，360 时间线出"谈话（主题）"摘要；统计"谈话完成率"分子+1；工作台"待谈话"-1。

**T2 重复提交同一记录 409**
- 步骤：保存记录时连点/重放。
- 预期：仅一条记录，重复 409001。

**T3 转风险/转家校联动**
- 步骤：谈话结果标记"需跟进"→转风险（或转家校联系）。
- 预期：生成关联 risk_record（记 talk_id 来源）或家校联系任务；责任人收待办；谈话记录与风险互链可跳。

**T4 跨学生 403/404**
- 步骤：T1 对 scope 外学生 S2 建谈话/读 S2 谈话记录。
- 预期：403+审计；S1 学生端不可见教师谈话原文（仅在其 360 中按策略展示摘要或不展示）。

**T5 心理类谈话权限**
- 步骤：普通教师读心理类型谈话记录；心理老师（PSY_STUDENT scope）读取。
- 预期：普通教师 403 或仅"存在心理谈话"标记；心理老师可读且审计落表。

### 流程 7：调宿（M1-M5）

**M1 正常调宿全链**
- 前置：S1 有当前床位；目标床位空闲。
- 步骤：S1 小程序发起调宿（原因）→T1 审→宿管审→通过。
- 预期：transfer 单逐级推进→APPROVED；事务内原床释放、新床占用、t_cs_dorm_record 回写；S1 收 STATUS_CHANGED，"我的宿舍"显示新床位；360 出"调宿"事件；宿舍统计入住分布更新。

**M2 重复申请 409**
- 步骤：S1 存在进行中调宿单再次发起。
- 预期：409001，仅一条。

**M3 目标床位冲突**
- 步骤：审批期间目标床位被他人占用后继续审批通过。
- 预期：终审校验拦截 409001（床位已占用），单据退回或改选；无半更新（原床未释放）。

**M4 跨学生 403/404**
- 步骤：S1 查询/取消 S2 的调宿单；范围外宿管审非本楼栋调宿。
- 预期：403/404；宿管 DORM_BUILDING scope 生效并审计。

**M5 检查异常联动**
- 步骤：宿管建检查任务→记录 S1 房间严重违纪异常。
- 预期：t_cs_dorm_exception 落表；生成 source=DORM_EXCEPTION 风险并分派 T1；统计"宿舍异常"+1；整改闭环后异常关闭。

### 流程 8：学工归档（V1-V4）

**V1 建批次生成档案包**
- 前置：S1 有已终态请假/认定/谈话记录。
- 步骤：A1 建归档批次（学年范围）→按学生生成档案包。
- 预期：package 按学生生成，收录终态业务快照；缺件学生进补缺清单并给 T1 待办（ARCHIVE_NOTICE 前置提醒）。

**V2 重复建包幂等 409**
- 步骤：同批次同学生重复生成。
- 预期：409001 或幂等跳过，仅一份包。

**V3 审核确认与水印归档**
- 步骤：T1 补缺→C1 完整性审→A1 确认→生成水印归档包下载。
- 预期：批次→已归档；打包走 export 管线（首行水印、sha256、t_export_task 登记、下载审计）；相关业务单置 ARCHIVED 只读（编辑/审批按钮消失，写接口 409/422）；统计"归档率"更新；360 出"归档"事件。

**V4 越权与只读校验 403/404**
- 步骤：C1 访问非本学院归档包；任何角色修改 ARCHIVED 业务单；S1 访问归档管理接口。
- 预期：范围外 403；ARCHIVED 写操作全部拒绝且无副作用；学生 403/404；越权均审计。

### 用例执行说明与测试数据准备

**执行环境**：独立测试租户（禁用 demo-school 执行写用例，禁依赖 sandbox 隔夜数据——每晚 0 点重置）。自动化用例落 backend/tests（与既有 pytest 同框架），小程序交互项以手测清单+录屏归档。

**基础数据准备清单**：
- 组织：1 学院 / 2 专业 / 2 班级（t_class 绑定 T1 为其中一班辅导员）。
- 人员：S1（T1 班内）、S2（另班，T1 范围外）、T1（CLASS scope）、C1（COLLEGE scope）、A1（ADMIN_TENANT）、宿管 W1（DORM_BUILDING scope）、心理教师 P1（PSY_STUDENT scope 含 S1）。
- 规则：affairs.leave.* / aid.publicity_days / discipline.* 以测试友好值初始化（如公示 0 天档位供快测 + 正常档位供流转测）。
- 业务底数：开放中的认定批次与奖学金批次各 1；空闲床位 ≥2；t_acad_warning 一条 PENDING_HANDLE 供转风险。

**通用断言约定**（每条用例默认附加）：
- 响应体结构 `{code,bizCode,message,data,traceId,timestamp}`；业务失败绝不 500。
- 写操作后：t_workflow_task / t_unified_todo / t_unified_message 增量与用例预期一一对应，无多发。
- 越权尝试必落 t_security_audit_log；敏感读取必有 VIEW_SENSITIVE 记录。
- 统计断言统一走 dashboard/stats 端点前后对比（不直查库凑数）。

### 通用负向用例组（G1-G8，覆盖全部 13A 写端点抽样）

**G1 未登录 401**：无 token 调任意 13A 端点 → 401001，无副作用。
**G2 学生调 PC 端点 403**：S1 token 调 /api/v1/student-affairs/*（require_staff）→ 403001。
**G3 demo 租户写 403**：demo-school 账号执行任一 13A 写操作 → 403 + "请前往沙箱体验"引导文案；读操作正常。
**G4 跨租户隔离**：租户 A 教师以合法角色访问租户 B 的 13A 资源 id → 404001（租户内不存在语义），绝不泄漏存在性。
**G5 校验 422**：必填缺失/枚举非法/长度越界（如请假原因 9 字、材料 11MB）→ 422001 逐字段错误，不产生半提交数据。
**G6 乐观锁 409**：两会话并发处理同一 workflow task → 一成功一 409001 APPROVAL_VERSION_CONFLICT。
**G7 导出限流与登记**：同用户 1 分钟内第 6 次导出 → 429001；成功导出均有 t_export_task 行（用途≥5 字校验）。
**G8 归档只读**：对 ARCHIVED 单据的全部写端点抽样 → 拒绝且无状态/通知/统计副作用。

## 第三部分：回归红线（P9 一票否决项）
