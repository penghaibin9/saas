## 1. 施工顺序冻结

```mermaid
flowchart LR
  A["A 施工地图 + 底座欠账冻结"]
  B["B 学工主链路 PC + 小程序闭环"]
  C["C 奖助处分沟通闭环"]
  D["D 商业化补强 + 数字迎新底座补齐"]
  A --> B
  B --> C
  C --> D
  A -.冻结数字迎新欠账.-> D
```

1. A 只做文档冻结，不做页面、接口、数据库、小程序开发。
2. B 优先处理能让学工中心“可点、可办、可追踪”的高频主链路。
3. C 处理审批、公示、材料、台账压力大的学生事务链路。
4. D 处理商业化增强、统计归档和数字迎新公共底座欠账，避免在 B/C 中反复返工。

## 3. 数字迎新专项冻结

数字迎新不在学工中心内重新开发，只允许以入口、摘要、跳转、数据引用的方式接入。后续真正补强归入 D 包。

| 欠账项 | 当前结论 | 归属任务包 | 处理规则 |
|---|---|---|---|
| 外链/局部完成 | 数字迎新已有独立路由和页面，但学工中心应视为外部系统承接 + 局部完成 | D | 学工中心只放入口和摘要，不复制迎新页面 |
| 新生主链路 Excel | 后端和前端已有新生台账导入导出能力，但只覆盖主链路 | D | 保留现有能力，补齐其他台账导出前不得标成全量完成 |
| 进度/异常/批量提醒 | 页面存在，但完整进度、异常闭环、批量提醒仍需按底座复核 | D | 统一列入迎新补强清单 |
| 日期时间底座 | 公共日期组件已存在，但迎新页仍有局部本地格式化和原始时间字段 | D | 统一迁移到公共日期组件后才能关闭欠账 |
| 导出确认/审计/水印 | 公共导出确认、审计、Excel 组件已存在，迎新未完全公共化 | D | 所有导出按钮必须走确认、权限、审计、水印和脱敏 |
| 公共组件准入 | 迎新仍有模块内 ImportDialog/ExportDialog/AuditTrailPanel/BatchActionBar 等局部组件 | D | 逐页确认是否替换为公共组件或保留有明确理由 |

## 4. 下一步进入 B 的条件

A 完成后，可以进入 B。原因是：二级/三级地图、现有系统承接、数字迎新欠账、四包顺序已经冻结；B 不需要再讨论全量边界，只按地图施工最高频主链路。
