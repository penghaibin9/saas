## 1. 全局约定（各页共用，页内只写差异）

### 1.1 五态全局约定

| 状态 | 统一展示与行为 |
|---|---|
| loading | 骨架屏（列表=表格骨架、详情=分组卡片骨架、统计=图表占位）；超过 10 秒展示「加载较慢，仍在请求」提示，不白屏 |
| empty | 业务化空文案 + 引导按钮（如「暂无请假记录」+「代学生录入」）；筛选后为空提示「当前筛选无结果，试试清除筛选」 |
| error | 展示统一响应中的 message + traceId（可复制），提供「重试」按钮；连续失败不重复弹 toast |
| noPermission | 403001（无权限点）/403002（无数据范围）分别提示「您没有访问该功能的权限」/「该数据不在您的管理范围内」，页面渲染 noPermission 态而非白屏，后端落审计 record()（越权访问必审计），404001 渲染 notFound 态 |
| readonly | 只读态三来源：① demo-school 租户只读锁（写按钮保留但点击提示「演示环境只读，请前往沙箱环境操作」，后端 403 兜底）；② 到期租户只读中间件；③ 业务只读（ARCHIVED/CLOSED 等终态）。只读态下写按钮统一置灰或替换为提示 |

### 1.2 业务态全局约定

| 业务态 | 统一展示 |
|---|---|
| 审批中（*_REVIEW 等中间态） | 页面顶部状态条（当前状态+当前节点+当前处理人）+ 审批进度时间轴（已过节点/当前节点/后续节点，含处理人、时间、意见）+ 表单区整体只读；仅当前节点人见审批操作区 |
| 已归档（ARCHIVED） | 全页只读 + 可导出（走导出管线：用途必填≥5 字、脱敏列、首行水印、t_export_task 留痕、下载审计）+ 页面水印（当前登录人姓名+工号+时间） |

### 1.3 按钮动作矩阵统一格式

每页按钮统一按七列输出：**按钮 / 出现条件(角色+状态) / 动作 / API / 成功变化 / 失败提示 / 是否审计**。约定：
1. 「出现条件」= 角色（处/院/辅/班/心/宿/资，缩写同页面树文档 §3）+ 数据范围命中 + 业务状态三重判定；不满足则按钮不渲染（而非置灰），demo-school 只读锁例外（见 §1.1）。
2. 「成功变化」必须写明：状态变更、待办/消息（t_unified_todo / t_unified_message）联动、列表/计数刷新、是否写 t_student_stage_event（进 360）。
3. 「是否审计」：写操作与敏感读取（看完整隐私、导出、下载）一律 record() 落 t_security_audit_log；普通读取不审计。

### 1.4 API 前缀与失败提示映射

- PC 业务接口统一前缀 `/api/v1/student-affairs/*`；审批操作复用 Workflow：`/api/v1/approvals/tasks/{taskId}/approve|reject|transfer`（13A 各业务 = 新 workflow_code + node_code，任务实例落 t_workflow_instance / t_workflow_task）；「退回修改」为业务动作，走 `/api/v1/student-affairs/{biz}/{id}/return`（业务态置 RETURNED、终止当前 Workflow 节点、通知发起人 RETURNED_NOTICE）。
- 失败提示必须与错误码一一对应，全模块统一文案模式：

| 错误码 | 统一失败提示 |
|---|---|
| 401001 | 登录已失效，跳 /login（沿用全站强制登录） |
| 403001 | 「您没有该操作权限」，按钮侧提示，落审计 |
| 403002 | 「该数据不在您的管理范围内」（如学生 B 的辅导员访问学生 A 单据），落审计 |
| 404001 | 「数据不存在或已被删除」，渲染 notFound 态 |
| 409001 | 重复提交→「已存在进行中的同类申请，请勿重复提交」；APPROVAL_VERSION_CONFLICT→「该任务已被处理」弹窗+自动刷新；床位等资源冲突→「目标资源已被占用，请重新选择」 |
| 422001 | 校验失败逐字段提示（后端返回字段级错误数组，前端定位到具体表单项标红），不弹全局 toast |

### 1.5 13A 新增 workflow_code 一览（节点即各业务状态机审批段）

| workflow_code | 业务 | 节点序列（node_code） |

## 2. 请假管理（05，核心 8 页全）

#### 8. 状态机呈现

#### 9. 权限规则
看:各角色按范围;新增:宿管房源/检查、学院活动、学工处归档批次;审批:辅导员调宿/活动审核;排宿:dorm.allocation;归档:archive.manage;导入:检查/活动导入;导出:各 export;打印:归档/荣誉;查看敏感:学生号码脱敏;查看审计:学工处/学院;下载归档包:archive.export+用途+审计。

#### 10. 接口绑定
`GET/POST /dormitory/*`、`POST /dormitory/transfer/:id/approve`、`POST /dormitory/inspections/records`、`POST /risk`(source=DORM)、`GET/POST /activity/*`、`GET/POST /archive/batches`、`GET /stats/*`。需补 API：`/dormitory/allocation/suggest`(排宿接口位)、`/dormitory/civilized`、`/dormitory/discipline`、`/clubs/*`、`/organizations/*`、`/party-league/*`,**需人工确认**(排宿无算法)。每接口写入参/出参核心/错误码(409床位占用/名额,422用途)/前端处理。

#### 11. 前端状态
loading=表格/工作台骨架;empty=空床/无活动/无归档;error=traceId+重试;no permission=403;network error=重试;conflict=床位占用409/名额满409/归档冻结409;validation error=422(检查项/活动名额/用途);submit success=刷新;submit failed=错误码;offline draft=检查录入/活动报名草稿(移动端);duplicate=提交锁+幂等;sensitive data hidden=学生号码脱敏;audit reason required=归档下载填用途。

#### 12. 人性化设计
学生少跑——移动端我的宿舍/调宿/活动报名+进度;宿管少录——检查移动端录入;默认带出床位/活动信息;宿舍异常自动转风险防漏;归档缺失自动催办;活动名额并发防超发;**智能排宿无算法也能人工跑通、有算法只出草稿由老师确认**;统计一键下钻到明细。

#### 13. 导入导出与打印
导入：宿舍检查/活动名单(模板列,行级校验);导出：宿舍/活动/归档/统计台账(脱敏,水印,下载审计);打印：归档材料/荣誉证。

#### 14. 审计日志
