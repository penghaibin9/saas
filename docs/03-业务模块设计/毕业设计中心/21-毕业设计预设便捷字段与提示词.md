> 来源：本仓库 PC 管理平台（`web/管理平台.html`）、移动 H5（`web/m/index.html`）、微信小程序（`miniprogram/`）。

## 5. 任务节点「提交清单」提示（H5，按节点名称匹配）

当节点名称包含下列关键词时，展示对应 checklist：

### 5.1 开题报告

- 研究背景与意义（300字以上）
- 国内外研究现状综述
- 研究目标与主要内容
- 研究方法与技术路线
- 研究计划与进度安排
- 预期成果
- 指导教师签字确认

### 5.2 文献综述

- 参考文献不少于15篇（含3篇英文）
- 按主题分类整理综述
- 总结现有研究的不足
- 阐明本研究的切入点
- 字数不少于3000字

### 5.3 中期检查

- 已完成工作进度说明
- 遇到的问题与解决方案
- 后续工作计划
- 相关阶段性成果展示

### 5.4 论文初稿

- 摘要（中英文）
- 论文结构完整（引言/正文/结论/参考文献）
- 图表规范清晰
- 引用格式统一（APA/GB/MLA等）
- 字数符合专业要求

### 5.5 论文定稿

- 按意见修改完毕
- 查重率符合要求（一般≤30%）
- 导师审核通过
- 装订版和电子版均已准备

### 5.6 答辩准备

- 制作PPT（建议20-30页）
- 演讲时间控制在15分钟内
- 系统/作品可正常演示
- 准备常见问题解答

## 6. 填写模板芯片（申报 / 任务书 / 指导）

### 6.1 课题描述

- 本课题研究×××问题，拟采用×××方法，设计并实现×××系统/方案，以解决实际工程问题。
- 本课题面向×××行业，通过对×××技术的研究与应用，开发×××功能的×××系统。

### 6.2 课题对学生要求

- 要求有一定编程基础，掌握Java/Python/JavaScript之一
- 要求熟悉数据库原理，有Web开发基础
- 无特殊要求，有学习热情即可

### 6.3 选题轮次说明

- 学生可按志愿顺序选题，系统按时间先到先得分配；如第一志愿已满，自动匹配第二志愿。
- 本轮选题采用双选制：学生提交志愿 → 教师确认 → 系统确认分配。

### 6.4 任务书 · 目标

- 设计并实现一个功能完整的×××系统，满足实际业务需求。
- 研究×××关键技术，提出改进方案并通过实验验证。
- 调研×××领域现状，设计并开发×××原型系统。

### 6.5 任务书 · 主要任务

- 1. 完成需求分析与系统设计；2. 完成数据库设计与后端开发；3. 完成前端界面开发；4. 编写论文并通过答辩。
- 1. 调研相关技术；2. 完成系统方案设计；3. 编码实现并测试；4. 撰写学位论文。

### 6.6 任务书 · 具体要求

- 严格按学校规范撰写论文，字数不少于8000字；每周汇报进展；按时参加中期检查和答辩。
- 完成系统功能设计并测试，提交完整源代码及文档；论文格式符合规范。

### 6.7 任务书 · 进度安排

- 第1-2周：调研选题，完成开题报告；第3-8周：完成系统设计与开发；第9-12周：测试优化；第13-15周：撰写论文；第16周：答辩。

### 6.8 指导记录内容

- 检查开题报告初稿，指导文献综述方向，要求细化研究方法。
- 审阅论文初稿，就结构框架、研究方法和写作规范提出修改意见。
- 检查系统功能实现进度，针对存在的技术问题给出解决方向。
- 中期检查，汇报进展，提出下阶段重点和完成时间节点。
- 就答辩PPT制作和答辩技巧进行辅导，模拟答辩环节。

### 6.9 指导 · 下次结果 / 待办

- 按意见修改后下次提交修改稿
- 下次前完成数据库设计并测试
- 下次提交中期报告初稿

### 6.10 成果提交备注（学生侧）

- 初稿，待审阅
- 已按上次意见修改，请重新审阅
- 终稿，已通过指导教师审查

## 7. 答辩与成绩相关芯片

### 7.1 答辩评语

- 选题有实际意义，完成度高
- 回答问题思路清晰
- 论文结构完整，工作量饱满
- 部分问题回答不够深入

### 7.2 答辩组名称快选

- 答辩第1组 / 答辩第2组 / 答辩第3组 / 补答辩组 / 优秀论文答辩组  
（可拼「{届}届」前缀）

### 7.3 答辩安排备注

- 学生需提前10分钟到场签到，准备答辩PPT（含论文概述，不超过15分钟）。
- 线上视频答辩，学生需确认设备正常，开始前5分钟进入会议室等待。

### 7.4 指导成绩快捷分（录入）

| 等级 | 建议分值 |
|------|----------|
| 优秀 | 92 |
| 良好 | 83 |
| 中等 | 75 |
| 及格 | 65 |

### 7.5 成绩筛选档位

- 优秀（≥90）
- 良好（80-89）
- （可扩展中等/及格/不及格）

## 8. 驳回快捷理由（毕设）

### 8.1 选题确认驳回（H5 / 教师或管理员）

- 题目范围过大，请缩小研究范围
- 题目已有学生选定，请更换题目
- 研究方向与本专业培养目标不符
- 题目缺乏研究价值或创新性，请与教师协商重选
- 与企业合作课题相关，需先获得企业授权

### 8.2 成果审查驳回

**小程序：**
- 材料不完整，请补充
- 内容质量不达标，需修改
- 格式不符合要求
- 与选题方向不符

**PC：**
- 材料不完整，请补充
- 内容质量不达标，需修改
- 格式不符合学校规范
- 与选题方向不符

**H5：**
- 格式不规范，请按学院要求修改
- 重复率超标，需降重后重新提交
- 内容不完整，请补充相关章节
- 与选题方向不符，请重新确认

### 8.3 互查 / 质量检查驳回

**PC：**
- 格式不符合毕业设计课程标准
- 内容深度不足，需修改
- 疑似抄袭，建议复核查重

**H5：**（同类场景 `sheetReject('驳回质量检查', …)`，以学院制度为准可对齐上列）

## 9. 中期检查结论（建议 SaaS 新增独立字段）

本仓库导航文案含「指导与中期检查」，建议移植时拆出独立结论，不要只写在指导文本里：

| 结论 | 说明 |
|------|------|
| 通过 | 进入下一阶段成果/定稿 |
| 限期整改 | 带整改期限与跟踪 |
| 不通过 | 重大调整或延期 |

整改跟踪状态建议：`正常 / 待整改 / 整改中 / 已复核`

## 10. 移植建议（毕业设计中心）

1. **配置维度：** `module=gd` · `scene=课题描述|任务书目标|成果驳回|答辩评语|节点清单` · `texts[]`
2. **节点清单：** 按「节点名称关键词」匹配 checklist，便于学校改节点名仍能命中
3. **查重阈值：** 默认文案「一般≤30%」建议做成学校配置项，不要写死
4. **权重与等级：** 指导/评阅/答辩权重与等级区间做成可配置
5. **与岗位实习分离：** 入口分组、流程条、状态机独立，避免学生首页混排
6. **芯片交互：** 同实习模块——点击填入、可多选拼接、支持自定义
