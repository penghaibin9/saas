# 毕业设计中心生产级升级总控方案

> 工作分支：`codex/graduation-production`  
> 目标：将现有“功能较完整、可演示”的毕业设计中心，升级为可在学校真实运行、可审计、可运维、可回归、可灰度发布的生产级产品。

## 一、最终验收口径

生产级不以页面数量或构建成功为准，须同时满足：

1. 真实性：生产包不得展示 Mock 业务数据，断网、超时和后端故障必须显式告知。
2. 安全性：每个读写接口都通过身份、权限码、组织范围、业务归属四层校验。
3. 一致性：选题、分配、评阅、成绩发布、归档等关键写入支持幂等、并发冲突检测和事务回滚。
4. 闭环性：管理端、教师小程序、学生小程序使用同一状态机和同一数据源。
5. 可追溯性：关键操作记录操作人、租户、原值、新值、理由、请求号和时间。
6. 可恢复性：批处理可查进度、可下载失败明细、可重试；关键数据有备份恢复演练证据。
7. 可验证性：单测、API 集成、跨端 E2E、权限、租户、并发、性能和微信真机测试全部通过。

## 二、产品闭环范围

主链路冻结为：

`毕设批次 → 学生名单 → 题目库 → 选题轮次/调剂 → 导师分配 → 任务书 → 开题 → 指导记录 → 中期检查 → 成果提交 → 查重 → 教师评阅 → 答辩排程/评分 → 成绩审核发布 → 申诉更正 → 材料归档 → 毕业资格供数`

跨端职责：

- PC 管理端：规则、批次、全局调度、异常处置、发布、归档和统计。
- 教师小程序：本人待办、学生指导、开题/中期/成果批阅、评阅与答辩任务。
- 学生小程序：选题、材料提交、整改、查看安排/成绩、发起申诉。

## 三、分阶段实施

### P0：生产真实性与权限闸门

- 区分 `demo` / `test` / `production` 构建，生产包编译期移除 Mock 分支和 Mock 数据。
- 小程序断网显示缓存时间与“非实时数据”标识，严禁回退演示数据。
- 建立 `graduation.*` 权限码清单，路由统一声明权限，服务层再验证数据归属。
- 建立租户、学院、专业、导师本人、学生本人的数据范围策略。
- 敏感操作增加二次确认、理由、审计日志和安全告警。

完成定义：生产包 Mock 扫描为 0；未登录、无权限、越组织、跨租户、越业务归属用例全部通过。

### P1：状态机、幂等与并发一致性

- 冻结学生项目、题目、轮次、材料、评阅、答辩、成绩、归档状态机。
- 所有写接口验证前置状态，非法跳转统一返回 `409` 和可读冲突原因。
- 对选题确认、匹配、导师分配、答辩分组、成绩发布、归档增加幂等键。
- 关键表增加版本号/乐观锁和数据库唯一约束，批处理改为可追踪任务。
- 建立失败补偿和对账任务，禁止“部分成功但前端显示全部成功”。

完成定义：重复点击、请求重放、双管理员冲突和事务中断测试全部通过。

### P2：微信小程序真机生产化

- 配置正式 AppID、合法域名、隐私声明、版本号和环境配置。
- 打通微信登录、校内身份绑定、Token 刷新、账号停用和解绑。
- 补齐文件选择、分片上传、断点续传、进度、取消、预览、重试和权限过期处理。
- 进行真机弱网、切后台、锁屏、重启、低存储和多机型测试。
- 接入订阅消息，消息直达对应待办，并保留站内消息兜底。

完成定义：真实微信环境下学生和教师主链路通过，不依赖 H5 专用 API。

### P3：材料、查重、评阅与归档增强

- 文件服务执行白名单、大小限制、文件头检测、病毒扫描、私有存储和限时下载。
- 材料保留版本、提交人、时间、摘要、校验和，支持历史版本比对。
- 查重结果关联原始报告、供应商任务号、校验标识和复查记录。
- 评阅实现回避规则、匿名模式、评分表版本和异常分差复核。
- 归档前运行材料完整性校验，归档包生成清单、校验和和缺失报告。

完成定义：文件越权、恶意文件、版本篡改和归档缺失测试全部通过。

### P4：可观测、性能与交付闸门

- 建立结构化日志、请求链路 ID、业务指标、错误率、慢接口和任务积压告警。
- 设定容量基线：至少覆盖万名学生、千名教师、十万份材料索引的现实数据规模。
- 优化统计查询、批量匹配、导入导出和归档生成，避免大事务阻塞在线请求。
- CI 强制执行后端单测/API、PC 组件/E2E、小程序单测/契约、Mock 扫描、依赖和密钥扫描。
- 建立数据库迁移回滚验证、备份恢复演练、灰度发布和应急回退手册。

完成定义：所有闸门在干净环境可重复通过，监控、告警、备份和回滚完成演练。

## 四、必须建立的测试矩阵

| 测试层 | 必验内容 |
|---|---|
| 后端单测 | 状态机、评分公式、回避规则、归档完整性 |
| API 集成 | 成功、参数错误、无权、越权、冲突、重放、事务回滚 |
| 租户/范围 | 跨校、跨学院、跨专业、跨导师、跨学生记录 |
| PC E2E | 批次到归档的管理端全链路和异常处置 |
| 小程序 E2E | 学生提交、教师批阅、学生收到结果的跨端闭环 |
| 文件安全 | 伪扩展名、超大文件、恶意文件、越权下载、URL 过期 |
| 并发性能 | 选题抢占、重复发布、批量匹配、万人列表、导入导出 |
| 微信真机 | 登录、续期、上传、预览、订阅消息、弱网、切后台 |

## 五、生产上线一票否决项

任一项未通过即不得上线：

- 生产包仍可进入 Mock 数据分支。
- 存在未绑定权限码的敏感写接口。
- 跨租户或跨导师记录访问未被拦截。
- 成绩发布、归档或匹配可被重复执行。
- 小程序未在真实 AppID 和真机上通过主链路。
- 材料上传缺少类型、大小、内容与访问权限校验。
- 没有可重复执行的自动化回归报告。
- 备份恢复、数据迁移回滚或发布回退未经演练。

## 六、推荐施工顺序

1. 先做 P0 生产真实性和权限，解决“不能上线”的根问题。
2. 再做 P1 状态机和并发，解决“上线后会出错数据”的问题。
3. 随后做 P2 微信真机，形成真实学生/教师入口。
4. 再完成 P3 材料与归档，确保教学证据可信。
5. 最后以 P4 性能、监控、灰度和恢复演练关闭生产验收。

不在上述闸门完成前继续堆叠低价值页面或报表。
