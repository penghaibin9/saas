## 一、最重要的冲突裁决

原文档提出独立`execution_plan`域，产品逻辑成立，但**不能立即成为教学任务的新前置条件**。

当前正式链路是：

```text
AaProgram + AaProgramBinding
→ academic_affairs_task_service.generate_batch()
→ AaTeachingTaskBatch/AaTeachingTask
```

`navPlan.js`中的“教学计划”也被明确设计为对培养方案、教学任务、归档的收编入口。普通模型若直接新建执行计划并强制任务从它生成，会造成：

- 两套“应开课程”；
- 两套调整入口；
- 旧任务批次无法解释；
- 页面和API大量断链。

V2采用三阶段：

1. `REUSE`：补强方案校验和编辑页面；
2. `EXTEND`：建立“开课差异读模型”，不落第二主表；
3. `MIGRATE`：真实学校验证确有学期计划微调需求后，再建立执行计划并双写。

## 二、当前代码事实

| 位置 | 当前能力 | 页面/产品问题 |
|---|---|---|
| `AaProgram/AaProgramCourse/AaProgramBinding` | 方案、课程明细、专业年级/班级绑定 | 课程快照字段少；方案完整性主要看总学分 |
| `academic_affairs_program_service.submit_program()` | 检查总学分已设置、课程学分合计达标 | 不检查模块、学期、重复课、实践、停用课程、先修顺序 |
| `AaProgramListView.vue` | 列表+内联新建 | 缺覆盖度、版本和异常结论 |
| `AaProgramEditorView.vue` | 国家标准、学分条、课程表、审核与绑定 | 课程只有4列；缺实时校验、结构树、影响分析 |
| `AaProgramConsoleView.vue` | 十类Tab、多个Drawer | 控制台过载；与编辑器功能重叠 |
| `AaTaskBatchListView.vue` | 直接按方案生成任务 | 生成前没有差异预览和来源快照 |

## 五、方案校验器的开发优先级

### 第一轮必须做

- 总学分；
- 课程重复；
- 课程必须关联有效`course_id`；
- 停用课程；
- 开课学期合法；
- 模块不能为空；
- 模块学分目标达成；
- 实践学分/周数；
- 同专业年级ACTIVE绑定唯一。

### 第二轮

- 先修顺序；
- 学时与学分换算；
- 每学期负荷；
- 国家标准差异；
- 毕业要求与课程映射。

校验器独立文件：

`backend/app/modules/academic_affairs/services/academic_affairs_program_validator.py`

`submit_program()`只调用校验器，不继续堆if。

## 七、教学计划的安全产品落地

### 阶段A：开课准备读模型（当前推荐）

新增页面：

```text
/admin/academic-affairs/teaching-plan/opening
AaOpeningPlanView.vue
```

它不建新主表，只聚合：

- 当前学期；
- 有效方案绑定；
- 应开课程；
- 已生成教学任务；
- 差异：漏开、重复、学时不一致、班级缺失。

接口：

```http
GET /teaching-plan/opening?termId=
GET /teaching-plan/opening/differences?termId=&collegeId=
```

页面：

```text
应开课程 326 / 已生成任务 301 / 漏开18 / 重复3 / 学时异常4
[查看漏开] [重新校验] [进入教学任务]
```

### 阶段B：任务批次保存来源快照

EXTEND `AaTeachingTaskBatch`：

- `source_program_snapshot_hash`
- `source_binding_count`
- `generation_rule_version`
- `difference_summary_json`

不改变现有生成入口。

### 阶段C：条件性执行计划域

只有真实学校出现以下需求才进入：

- 学期计划需要学院申报、教务审核；
- 方案课程经常提前/延后；
- 临时不开课/替代课必须独立审批；
- 同一方案不同班级执行差异大。

此时才创建执行计划，并让旧任务批次进入双写迁移。

## 八、版本影响页

新增独立页面，不使用Drawer：

```text

```

显示：

- 旧/新版本课程差异；

- 已生成教学任务；
- 已修读学生；
- 新增补修/免修风险；
- 建议生效范围。

影响分析只读，最终迁移必须二次确认并记录审计。

## AI施工共同约束

1. 开工前必须同时读取：本专题文档、`academic-affairs.routes.js`、对应Vue页面、对应API文件、后端model/service/router/test。

3. 一轮只改一个页面主任务或一条业务闭环，不允许一次重写整个教务中心。
4. 旧路由保留redirect/alias；旧接口保持兼容；旧数据采用新增列/表、回填、双读、双写、切换的安全顺序。
5. 复杂业务使用独立页面。抽屉只允许：少量字段的新建、快速确认、简单原因填写；名单、编排、规则、审核详情、影响分析不得放抽屉。
6. 页面首屏必须回答：当前阶段、是否正常、阻断数量、责任人、截止时间、下一动作。
7. 后端必须覆盖：租户隔离、数据范围、权限、状态机、幂等、并发、审计、通知、归档写保护。
8. 测试只跑本轮相关文件及必要构建，不无理由跑全仓数据库测试。
9. 禁止 `git add -A`；禁止自动commit/push；完成后只提交修改清单、测试证据和剩余风险。
