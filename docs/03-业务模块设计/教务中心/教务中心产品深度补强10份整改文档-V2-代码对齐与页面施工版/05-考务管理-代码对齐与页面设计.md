## 一、最高风险冲突

原文档建议新增`AaExamCandidate`，但现有`AaExamRoomStudent`已经包含：

- `exam_course_id`
- `student_id`
- 学号/姓名快照
- 座位号
- 准考证号
- 到考/缺考/违纪状态
- 同考试课程学生唯一约束

直接再建“考生表”会形成两套名单。V2裁决：

### 方案1（推荐当前）

扩展`AaExamRoomStudent`：

- `teaching_class_id`（待教学班域稳定）
- `roster_version`
- `eligibility_status`
- `eligibility_reason_code`
- `source_type`

未分考场前可使用`exam_room_id`可空的迁移设计，需先验证现有nullable约束和服务逻辑。

### 方案2

若现有考生必须依附考场，才新建“考试资格预名单”表，但它只负责发布前资格，安排后必须投影到`AaExamRoomStudent`，不得长期双主表。

## 二、现有页面问题

`AaExamConsoleView.vue`把批次、圈课、时间、考场、巡考、异常集中在一个左右布局页面，并大量使用Drawer。问题：

- 考场编排空间不足；
- 无独立课程核对和漏排队列；
- 圈课按单个教学任务操作；
- 发布门禁不够显著；
- 考生名单与资格不透明。

## 三、页面架构

### 页面A：考试批次总览

路由保留`/exam`，组件重构为：

```text
当前期末考试：课程186 / 待学院确认12 / 未排8 / 监考缺口6 / 冲突2
状态：编排中（被阻断）
[进入批次] [处理漏排]
```

列表显示每批次阶段、课程数、安排率、考生数、异常和下一动作。

### 页面B：考试批次工作台

新增：

```text
/exam/:batchId
AaExamBatchDetailView.vue
```

顶部阶段：

```text
课程生成 → 学院确认 → 时间编排 → 考场座位 → 监考巡考 → 发布 → 考后处理
```

首屏显示每阶段的完成数和阻断数。

### 页面C：考试课程核对

```text
/exam/:batchId/courses
```

- 自动生成预览；
- 应考、考查排除、手工补充；
- 无教学班名单；
- 无教师；
- 学院确认/退回；
- 批量操作。

不再逐门打开Drawer圈课。

### 页面D：考场编排

```text
/exam/:batchId/arrangement
```

三栏：

- 左：待排课程/漏排原因；
- 中：日期×时段；
- 右：教室容量、考生数、监考、冲突。

### 页面E：考生与座位

```text
/exam/:batchId/courses/:courseId/candidates
```

显示资格、来源教学班、考场、座位、准考证、缓考、异常。名单数百人时必须分页和导出，不使用Drawer。

### 页面F：发布门禁

```text
/exam/:batchId/publish
```

门禁：

- 课程确认率100%；
- 应排课程全部安排或有豁免；
- 资格名单完整；
- 座位完整；
- 监考满足；
- 学生/教师/教室冲突为0；
- 通知接收人可解析。

## 四、自动圈课

现有按`teachingTaskId`单项添加保留为特批入口。新增预览：

```http
POST /exam-batches/{id}/courses/generate-preview
POST /exam-batches/{id}/courses/generate
```

输入使用：

- 当前学期已就绪教学任务；
- 课程`exam_mode`；
- 教学班名单；
- 已存在考试课程。

返回应新增、已存在、排除、异常，不直接静默生成。

## 五、考试资格

至少规则：

- 学籍有效；
- 在正式教学班名单；
- 非免修；
- 缓考状态；
- 学校明确的考勤资格规则；
- 违纪限制（如制度有要求）；
- 不使用无来源的欠费数据阻断。

每个不具备资格的学生显示中文原因和证据。

## 六、移动端

学生“考试/缓考”页不能只突出申请，首屏应显示：

- 最近考试；
- 日期、时间、地点、座位；
- 准考要求；
- 变更提醒；
- 缓考入口和状态。

教师端显示：

- 我的监考；
- 待确认；
- 巡考；
- 考场异常登记。

## AI施工共同约束

1. 开工前必须同时读取：本专题文档、`academic-affairs.routes.js`、对应Vue页面、对应API文件、后端model/service/router/test。
2. 先输出“事实核对表”，明确哪些能力已经存在；**不得因为文档写了“新增”就重复建表、重复建service或重复建页面。**
3. 一轮只改一个页面主任务或一条业务闭环，不允许一次重写整个教务中心。
4. 旧路由保留redirect/alias；旧接口保持兼容；旧数据采用新增列/表、回填、双读、双写、切换的安全顺序。
5. 复杂业务使用独立页面。抽屉只允许：少量字段的新建、快速确认、简单原因填写；名单、编排、规则、审核详情、影响分析不得放抽屉。
6. 页面首屏必须回答：当前阶段、是否正常、阻断数量、责任人、截止时间、下一动作。
7. 后端必须覆盖：租户隔离、数据范围、权限、状态机、幂等、并发、审计、通知、归档写保护。
8. 测试只跑本轮相关文件及必要构建，不无理由跑全仓数据库测试。
9. 禁止 `git add -A`；禁止自动commit/push；完成后只提交修改清单、测试证据和剩余风险。
