## 一、重新审计后的直接结论

**原10份文档与现有代码的产品方向冲突不大，但“直接照文档建表、换模型、改页面”的施工冲突中等偏大。**

问题不在于原文档判断错，而在于原文档从“当前实现”直接跳到了“目标架构”，缺少兼容层。普通模型可能会发生四类误施工：

1. 看到“新增教学执行计划”，就平行建立第二套开课事实，绕开现有 `AaTeachingTaskBatch`；
2. 看到“独立教学班”，就删除或替换 `AaTeachingTask.teaching_class_*`，破坏排课、选课、考务、成绩现有链路；
3. 看到“考试候选人表”，就重复建设现有 `AaExamRoomStudent`；
4. 看到“统一规则/待办/资源日历”，就重复建设 `rule_json`、`AffairsAuditTrail`、`UnifiedTodo`、预约/维修/占用现有事实。

因此本V2将每项建议改成四种施工标签：

| 标签 | 含义 | AI行为 |
|---|---|---|
| `REUSE` | 现有能力已经存在 | 只优化页面/契约/测试，不新建平行实现 |
| `EXTEND` | 现有能力可增量补强 | 优先加字段、读模型、校验器或兼容API |
| `MIGRATE` | 目标模型正确，但会碰核心链路 | 必须双读/双写和回填，禁止一步替换 |
| `LATER` | 依赖真实规模或学校制度 | 只登记，不在当前轮次开发 |

## 二、代码漂移情况

原10份文档提交后，当前HEAD只对教务中心的组织/专业分流服务有少量改动，主体路由、模型和核心页面没有大面积变化。因此：

- **文件路径冲突较小**；

- **真正风险来自设计建议重复现有事实，而不是代码已经完全变了。**

## 四、现有页面的真实结构问题

### 4.1 教务看板是“超长统计页”

`AaDashboardView.vue` 当前按指标卡、当前学期、模块状态、成绩、考试、异动、预警、毕业、待办、今日课程等连续向下堆叠。数据丰富，但用户必须滚动寻找结论。目标应改为：

```text
当前学期 + 当前业务阶段
→ 总体是否可继续
→ 3~8个最高优先级阻断
→ 本人待办
→ 今日运行
→ 其余统计折叠/下钻
```

### 4.2 多个控制台把“菜单复杂度”转成“Tab复杂度”

以下页面都存在大量Tab或一个页面承载多个业务阶段：

- `AaProgramConsoleView.vue`
- `AaSchedulingConsoleView.vue`
- `AaSelectionConsoleView.vue`
- `AaExamConsoleView.vue`
- `AaTextbookConsoleView.vue`
- `AaEvaluationConsoleView.vue`
- `AaQualityDashboardView.vue`
- `AaGraduationAuditConsoleView.vue`

V2不要求全部拆页，而是按规则拆：

- 总览、筛选、只读统计可留在控制台；
- 名单、编排、规则制定、批次详情、审核详情、影响分析必须独立页面；
- 一个页面只保留一个主任务。

### 4.3 移动端是“图标目录”，不是任务首页

学生端教务首页当前展示19个图标；教师端展示11个图标。功能入口够多，但缺“今天要做什么、逾期什么、会影响什么”。V2改为：

```text
今日 / 本周
我的待办
风险与结果更新
常用服务
全部服务
```

## 五、事实源优先级

普通模型施工前必须使用下表，避免制造第二真相：

| 业务事实 | 当前正式事实源 | 禁止平行建设 |
|---|---|---|
| 学期 | `AaTerm` | 不另建第二个学期主表 |
| 校历 | `AaCalendarEvent` + `AaClassTimeBand` | 不复制整套校历事件 |
| 培养方案 | `AaProgram/AaProgramCourse/AaProgramBinding` | 执行计划不能绕过方案版本和绑定 |
| 开课任务 | `AaTeachingTaskBatch/AaTeachingTask` | 新计划域不能直接替换现有批次 |
| 教学班（当前） | `AaTeachingTask.teaching_class_*` + 合班快照 | 新教学班表必须兼容投影 |
| 课表 | `AaScheduleBatch/AaScheduleItem/AaSchedulePublish` | 不新建平行当前课表 |
| 选课 | `AaSelectionBatch/Course/Round/Record` | 候补与抽签必须边界清晰 |
| 考生/座位 | `AaExamRoomStudent` | 不直接再建同语义考生表 |
| 成绩 | `AaGradeTask/AaGradeRecord` + `AcademicGrade`投影 | 动态组件不能绕开发布投影 |
| 学籍 | `StudentProfile` + `change_student_status()` | 不新建学生主档或直接改状态 |
| 预警 | `AcademicWarning/Intervention` + `UnifiedTodo` | 不复制预警/待办表 |
| 毕业审核 | `AaGraduationAuditResult.item_results_json` | 新item表先双写，JSON保留摘要 |
| 审计 | `AffairsAuditTrail`，考务另有`AaExamAuditTrail` | 新日志表须有明确必要性 |
| 统一待办 | `UnifiedTodo` | 不新建第二套教师/学生任务中心 |

## 六、新增表准入门禁

任何AI建议建新表前，必须回答五个问题：

1. 现有表是否已经表达了同一业务事实？
2. 扩展字段、子表或读模型是否足够？
3. 新表与旧表谁是唯一写入源？
4. 历史数据如何回填、对账、回滚？
5. 哪个版本、哪个页面、哪个API开始切换？

答不出时禁止迁移。

## 七、页面设计的统一骨架

### 7.1 列表/批次首页

```text
[页面标题] [当前学期] [角色/数据范围]
[业务结论条：正常/有风险/被阻断 + 原因]
[进度：阶段1—阶段2—阶段3—阶段4]
[待处理异常卡：数量、责任人、截止时间、去处理]
[筛选栏]
[业务表格]
```

### 7.2 业务详情/工作台

```text
[对象名称 + 状态 + 版本 + 关键主按钮]
[左侧步骤/分类导航] [中间主业务区] [右侧校验/影响/历史]
[底部固定操作栏：保存草稿 / 校验 / 提交]
```

右侧栏不是抽屉，是页面内稳定区域；移动端改为折叠卡。

### 7.3 审批页

```text
申请事实
规则校验
影响分析
附件/证据
历史时间线
审批意见
同意 / 退回 / 驳回
```

审批动作必须显示“动作后会发生什么”。

## 九、首个推荐施工任务

**先做培养方案编辑器与校验，不先建执行计划或教学班新表。**

原因：

- 它是教学任务、排课、毕业审核的上游；
- 当前后端提交只校验总学分，页面也只展示学分差额；
- 可以在不破坏现有表和接口的情况下获得显著产品提升；
- 普通模型边界清晰，失败成本低。


## AI施工共同约束

1. 开工前必须同时读取：本专题文档、`academic-affairs.routes.js`、对应Vue页面、对应API文件、后端model/service/router/test。
2. 先输出“事实核对表”，明确哪些能力已经存在；**不得因为文档写了“新增”就重复建表、重复建service或重复建页面。**
3. 一轮只改一个页面主任务或一条业务闭环，不允许一次重写整个教务中心。
4. 旧路由保留redirect/alias；旧接口保持兼容；旧数据采用新增列/表、回填、双读、双写、切换的安全顺序。
5. 复杂业务使用独立页面。抽屉只允许：少量字段的新建、快速确认、简单原因填写；名单、编排、规则、审核详情、影响分析不得放抽屉。
6. 页面首屏必须回答：当前阶段、是否正常、阻断数量、责任人、截止时间、下一动作。
7. 后端必须覆盖：租户隔离、数据范围、权限、状态机、幂等、并发、审计、通知、归档写保护。
8. 测试只跑本轮相关文件及必要构建，不无理由跑全仓数据库测试。
9. 禁止 `git add -A`；禁止自动commit/push；完成后只提交修改清单、测试证据和剩余风险。
