## 一、结论

当前学生教务首页有19个入口，教师教务首页有11个入口。功能覆盖很强，但当前页面仍是“应用图标目录”。

V2不删入口，而是建立两层：

```text
第一层：今日、待办、风险、进度
第二层：全部教务服务
```

统一任务继续复用`UnifiedTodo`和现有移动聚合API，不新建第二套任务表。

## 五、统一任务DTO

复用`UnifiedTodo`，移动聚合层转换为：

```json
{
  "taskId": "AA_GRADE_ENTRY:123",
  "taskType": "GRADE_ENTRY",
  "title": "《数据结构》成绩待录入",
  "stageLabel": "已录45/52",
  "priority": "HIGH",
  "dueAt": "2026-12-28T18:00:00",
  "overdue": false,
  "route": "/pages/teacher/academic-affairs/grade-entry?taskId=123",
  "sourceModule": "成绩管理",
  "nextAction": "继续录入"
}
```

不同模块负责创建/完成自己的todo；移动端只聚合，不修改业务状态。

## 六、移动页面状态标准

每个页面必须有：

- 首次加载骨架；
- 下拉刷新；
- 无数据；
- 无权限；
- 业务不可办理；
- 网络错误重试；
- 提交中防重复；
- 成功结果页；
- 状态时间线；
- 归档只读。

错误文案必须告诉用户如何解决，不能只显示接口message或英文状态。

## 七、帮助中心

每个高频任务绑定`helpTopic`：

```javascript
meta: {
  helpTopic: 'AA.PROGRAM.SUBMIT',
  taskType: 'PROGRAM_REVIEW',
  businessOwner: '教务处'
}
```

任务卡包括：

- 什么时候做；
- 前置条件；
- 准备材料；
- 操作步骤；
- 完成标志；
- 常见错误；
- 对后续影响。

```text

完成报告：
- 修改文件；
```

## 十、无开发人员陪同验收

每个页面必须由未参与开发的人完成：

- 找到任务；
- 理解当前状态；
- 完成操作；
- 处理一次失败；
- 找到结果；
- 返回继续工作。

记录：用时、点击数、求助次数、错误次数、无法理解的词。

### 页面验收硬指标

- 10秒内找到本人待办；
- 首屏知道是否正常；
- 高频任务3次页面跳转内进入操作区；
- 失败有解决建议；
- 英文状态码暴露为0；
- 核心表单无多层Drawer；
- 页面刷新不丢上下文；
- 旧链接不404；
- 越权进入业务页为0。

## 十一、真实学校试点顺序

```text
基础数据迁移
→ 培养方案
→ 教学任务
→ 排课与课表
→ 教师确认
→ 学生选课
→ 考务
→ 成绩
→ 学籍异动
→ 毕业预审
→ 学期归档
```

至少完整跑一个学期。静态代码审计、pytest和演示数据均不能替代真实学期运行。

## AI施工共同约束

1. 开工前必须同时读取：本专题文档、`academic-affairs.routes.js`、对应Vue页面、对应API文件、后端model/service/router/test。
2. 先输出“事实核对表”，明确哪些能力已经存在；**不得因为文档写了“新增”就重复建表、重复建service或重复建页面。**
3. 一轮只改一个页面主任务或一条业务闭环，不允许一次重写整个教务中心。
4. 旧路由保留redirect/alias；旧接口保持兼容；旧数据采用新增列/表、回填、双读、双写、切换的安全顺序。
5. 复杂业务使用独立页面。抽屉只允许：少量字段的新建、快速确认、简单原因填写；名单、编排、规则、审核详情、影响分析不得放抽屉。
6. 页面首屏必须回答：当前阶段、是否正常、阻断数量、责任人、截止时间、下一动作。
7. 后端必须覆盖：租户隔离、数据范围、权限、状态机、幂等、并发、审计、通知、归档写保护。
8. 测试只跑本轮相关文件及必要构建，不无理由跑全仓数据库测试。
9. 禁止 `git add -A`；禁止自动commit/push；完成后只提交修改清单、测试证据和剩余风险。
