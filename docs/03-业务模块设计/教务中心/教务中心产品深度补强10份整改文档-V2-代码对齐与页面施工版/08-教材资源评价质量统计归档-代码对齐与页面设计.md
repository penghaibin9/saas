## 二、页面01：教材管理

`AaTextbookConsoleView.vue`当前7个Tab和多个Drawer。目标拆分：

### 教材总览

```text
本学期应选教材课程326
已提交选用301 / 待教师指定25 / 待学院审18 / 待教务备案7
征订缺口12 / 到货不足8 / 发放异常5
```

### 独立详情

- `/textbooks/selections/:id`：选用详情与审核；
- `/textbooks/orders/:id`：征订、到货、差异；
- `/textbooks/distributions/:id`：发放签收；
- `/textbooks/fees`：费用登记台账。

大量到货/发放名单不放Drawer。

### 财务边界

页面文案改为：

- 应登记金额；
- 已登记收取；
- 减免登记；
- 财务同步状态。

无财务接口时显示“教务登记口径，非学校财务结算结果”。

## 五、页面04：教学质量

`AaQualityDashboardView.vue`当前把看板、四类记录、整改、归档和多个Drawer集中在一页。

### 目标结构

- `/quality`：质量总览；
- `/quality/records`：问题记录；
- `/quality/records/:id`：详情；
- `/quality/rectifications`：整改队列；
- `/quality/rectifications/:id`：整改详情；
- `/quality/archive`：质量档案。

详情页包含：事实、证据、认定、责任人、期限、进展、复核和历史。创建表单字段较多，使用独立页或页面内编辑，不用长Drawer。

同时修正`academic_affairs_quality_service.py`头部过期注释，防止普通模型误以为能力仍planned。

## 六、页面05：教务统计

`AaStatsOverviewView.vue`继续作为总览，但每个指标必须显示：

## 七、页面06：教务归档（最高优先级）

当前`AaArchiveConsoleView.vue`直接显示“记录数/有数据/缺失”，并允许缺失时强制归档。需要改成语义门禁。

### 首屏

```text
2026秋学期归档
总体：不可归档（4项阻断）
方案完整 29/32
教学任务就绪 301/326
课表：已发布，但漏排3
成绩：待发布任务8
毕业：不适用
[处理阻断]
```

### 每个域返回

```json
{
  "domain": "GRADE",
  "result": "BLOCKED",
  "ruleCode": "GRADE_TASK_UNPUBLISHED",
  "summary": "8个成绩任务尚未发布",
  "recordCount": 326,
  "blockingCount": 8,
  "route": "/admin/academic-affairs/grade-publish?filter=pending",
  "evidence": []
}
```

### 强制归档

只有`SCHOOL_ADMIN`，必须：

- 看到全部阻断；
- 填写原因；
- 二次确认短语；
- 记录审批/审计；
- 生成风险清单；
- 不得把“强制”变为普通按钮。

## 八、语义规则第一批

先覆盖四域：

- PROGRAM：所有在读专业年级有有效方案且校验通过；
- TEACHING_TASK：应开无漏项、教师确认完成；
- SCHEDULE：已发布、HARD冲突0、漏排均有豁免；
- GRADE：应录任务全部发布或正式豁免、在途更正/复查0。

后续再扩九域，不一次完成。

## AI施工共同约束

1. 开工前必须同时读取：本专题文档、`academic-affairs.routes.js`、对应Vue页面、对应API文件、后端model/service/router/test。
2. 先输出“事实核对表”，明确哪些能力已经存在；**不得因为文档写了“新增”就重复建表、重复建service或重复建页面。**
3. 一轮只改一个页面主任务或一条业务闭环，不允许一次重写整个教务中心。
4. 旧路由保留redirect/alias；旧接口保持兼容；旧数据采用新增列/表、回填、双读、双写、切换的安全顺序。
5. 复杂业务使用独立页面。抽屉只允许：少量字段的新建、快速确认、简单原因填写；名单、编排、规则、审核详情、影响分析不得放抽屉。
6. 页面首屏必须回答：当前阶段、是否正常、阻断数量、责任人、截止时间、下一动作。
7. 后端必须覆盖：租户隔离、数据范围、权限、状态机、幂等、并发、审计、通知、归档写保护。
8. 测试只跑本轮相关文件及必要构建，不无理由跑全仓数据库测试。
9. 禁止 `git add -A`；禁止自动commit/push；完成后只提交修改清单、测试证据和剩余风险。
