## 四、页面01：教务看板重构

```text
页面ID：AA-DASHBOARD
现有路由：/admin/academic-affairs
现有组件：AaDashboardView.vue
主要角色：教务处、学院教务、校领导
页面唯一主任务：判断当前教学阶段是否正常，并处理最高优先级异常
```

### 首屏布局

```text
┌ 当前学期：2026-2027-1  当前阶段：开学准备  总体：被阻断 ┐
│ 4项阻断 / 12项预警 / 37项本人待办 / 最近截止 8月25日 │
└──────────────────────────────────────────────┘
┌ 最高优先级阻断（最多8条） ─────────┐ ┌ 阶段进度 ────────┐
│ 2专业无有效方案  责任：学院教务  去处理 │ │ 校历 ✓ 方案 ! 任务 ! │
│ 7任务未分教师    责任：学院教务  去处理 │ │ 排课 · 课表 · 发布 · │
└──────────────────────────┘ └────────────────┘
┌ 我的待办 ──────────────────────────────────────┐
└──────────────────────────────────────────────┘
┌ 今日教学运行 ┐ 其余统计折叠到“运行数据”区域
```

### 复用与新增

- REUSE：`getDashboard()`、`getDashboardReminders()`；
- EXTEND：前端先用现有提醒计算简易结论；
- 后续可新增 `GET /dashboard/readiness?termId=`，但不要求新表；
- 删除“LIVE/建设中”面向学校用户的模块卡，施工状态只在开发环境显示。

### 修改文件

- `AaDashboardView.vue`
- `academic-affairs.api.js`
- `academic_affairs_dashboard_service.py`
- 对应dashboard测试

### 验收

- 进入页面不滚动即可知道总体状态；
- 任一阻断都有责任角色、数量、最晚时间和真实路由；
- 没有当前学期时只显示一个明确主动作；
- 学院角色只看到本院问题。

## 五、页面02：学期详情与业务时间轴

当前路由缺独立学期详情页，建议新增：

```text
/admin/academic-affairs/terms/:termId
AaTermDetailView.vue
```

### 页面区域

1. 基本信息：学年、学期号、起止日期、教学周、考试周、状态；
2. 业务时间轴：注册、任务确认、排课、选课、考试、成绩、归档；
3. 校历状态：事件数、是否发布、最近变更；
4. 下游准备度：方案覆盖、任务生成、课表发布；
5. 状态历史：发布、冻结、解冻、归档。

### 冲突规避

业务时间轴首期从各模块现有字段读取：

- 注册：`AaRegistrationBatch.window_*`；
- 选课：selection batch/round时间；
- 考试：exam batch周次；
- 其他无窗口时显示“未配置”，不另造中央事实。

只有学校明确要求“一处配置全业务窗口”时，才进入统一窗口表设计。

## 六、页面03：校历发布与影响预览

### 现有问题

`AaCalendarView.vue`能够维护事件，但成熟页面应区分：

- 草稿编辑；
- 发布前校验；
- 发布后变更；
- 变更影响。

### 目标页面

```text
顶部：当前学期 / 校历状态 / 版本号 / 发布按钮
左侧：月历或周历
右侧固定区：校验结果
- 教学周数量
- 重叠事件
- 补课日缺原日期
- 对课表影响X条
- 对考试影响X场
底部：保存草稿 / 影响预览 / 发布
```

### 接口

REUSE：现有事件CRUD与publish。  
EXTEND：

```http
POST /terms/{termId}/calendar/impact-preview
GET  /terms/{termId}/calendar/validation
```

影响预览只读，不直接改课表。

## AI施工共同约束

1. 开工前必须同时读取：本专题文档、`academic-affairs.routes.js`、对应Vue页面、对应API文件、后端model/service/router/test。
2. 先输出“事实核对表”，明确哪些能力已经存在；**不得因为文档写了“新增”就重复建表、重复建service或重复建页面。**
3. 一轮只改一个页面主任务或一条业务闭环，不允许一次重写整个教务中心。
4. 旧路由保留redirect/alias；旧接口保持兼容；旧数据采用新增列/表、回填、双读、双写、切换的安全顺序。
5. 复杂业务使用独立页面。抽屉只允许：少量字段的新建、快速确认、简单原因填写；名单、编排、规则、审核详情、影响分析不得放抽屉。
6. 页面首屏必须回答：当前阶段、是否正常、阻断数量、责任人、截止时间、下一动作。
7. 后端必须覆盖：租户隔离、数据范围、权限、状态机、幂等、并发、审计、通知、归档写保护。
8. 测试只跑本轮相关文件及必要构建，不无理由跑全仓数据库测试。
9. 禁止 `git add -A`；禁止自动commit/push；完成后只提交修改清单、测试证据和剩余风险。
