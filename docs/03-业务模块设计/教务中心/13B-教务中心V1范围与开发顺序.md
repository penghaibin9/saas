## 1. V1 / P2 / P3 三档清单

### 1.0 分档原则

1. V1 只做"教学运行的读侧闭环 + 学籍写侧闭环 + 毕业预审"，即需求 §10 教务 V1 清单的忠实落地；一切排课算法、成绩录入审核发布、考务全流程、选课引擎后置。
2. V1 的每个写操作都必须走四件套：Workflow 审批 + 统一待办消息 + 学生 360（StageEvent/域记录）+ 审计。宁可少做一个功能，不允许做一个"裸 CRUD"。
3. 依赖既有数据即可成型的读侧功能（成绩查看、预警扫描）优先进 V1，因为交付见效快且零迁移风险。
4. 所有"需要学校现场确认"的规则（需求 §9）不阻塞分档：一律做成平台规则中心键 + 默认值（融合设计 §7），确认后改配置不改代码。
5. P2 = 依赖 V1 数据基座、闭环写侧重、工作量大的功能；P3 = 独立域或需外部对接/现场确认的功能。

### 1.2 V1 明确不做清单（防蔓延）

- 不做任何排课自动算法（含"简单贪心"也不做——V1 课表以导入/手工维护为准）。
- 不做成绩写端点（教务中心侧），t_acad_grade 保持既有写入口不动。
- 不做选课，学生课表按行政班归属推导。
- 不做调停课流转（仅冻结 workflow_code），课表发布前允许撤回重排，发布后 V1 只能走"作废批次重发"运维通道并留审计。
- 不做学生 PC 门户，不做家长端。
- 不做教材/教室借用/评教/等级考试/上报。

## 2. 开发阶段 13B-P1 … P8

通用约定：
- 页面均在 `/admin/academic-affairs/*`（PC，require_staff）或 `pages/student/academic/*`（小程序）。
- 接口均为 **13B 新建** `/api/v1/academic-affairs/*` 或 `/api/v1/mobile/academic-affairs/*`、`/api/v1/mobile/teacher/academic-affairs/*`；**复用既有学业过程** `/api/v1/academic/grades|warnings|students` 与 `/api/v1/mobile/academic/my/*`（成绩/预警）；不覆盖既有端点。
- 权限点前缀 `academicAffairs.`；数据范围一律经 getAcademicScope（融合设计 §0.5）。
- 每阶段交付物包含：代码 + 新增 pytest + 页面自测清单 + 演示种子增量 + 文档勘误。

### 13B-P1 契约冻结（不出功能，只出契约）

**目标**
- 冻结全部对外契约，后续阶段只实现不再议。产出七份清单：
  1. 新表 DDL 草案（融合设计附表 12 组表，含索引/唯一键/公共字段核对）；
  2. API 契约稿（OpenAPI 草案：路径/入参/响应示例/错误码矩阵）；
  3. 与既有 `/api/v1/academic` 端点冲突盘点表（逐路径列：既有/新增/决议）；
  4. workflow_code/node_code 14 项冻结表（融合设计 §2.2）+ 各流程 on_approved 回调职责；
  5. 权限点全集与角色默认矩阵；
  6. 规则中心 10 键与默认值（融合设计 §7）、导出 domain 4 项；
  7. stats 11 指标口径卡（口径/来源/频率/范围/下钻）。

**页面**：无。

**接口**：无实现；OpenAPI 草案评审通过即锁。

**状态机**：冻结 6 个——学年学期（DRAFT/PUBLISHED/FROZEN/ARCHIVED）、学籍异动单、注册、培养方案、课程、教学任务批次、毕业审核（后两阶段引用，不再改枚举字面）。

**权限点**：命名规范定稿 `academicAffairs.<biz>.<action>`，action 收敛为 view/create/edit/review/final/publish/import/export/config/execute 十种。

**测试**：契约评审 checklist——每 API 对照统一响应体/错误码；每写操作对照四件套；每敏感字段对照脱敏矩阵；每列表对照 scope。

**不允许做什么**：写任何业务代码；改现有表；预占融合设计附表之外的表名；与 13A-P1 议定的公共契约（消息类型、scope_type 扩展）单方面变更。

**验收标准**
1. 七份清单齐备且与事实速查逐条对照无冲突；
2. t_acad_*/t_aa_* 职责划分表（融合设计 §5.1）三方签认；
3. 203 条 pytest 基线清单+耗时记录在案；
4. 既有 /api/v1/academic 端点与 /mobile/academic/my 响应结构快照建档（供回归红线比对）。

### 13B-P2 学年学期 · 校历 · 学籍

**目标**：时间轴基座上线；学籍写侧闭环（入学/学年注册 + 四类异动）全链路可用；单一写入口 change_student_status 成为全平台事实标准。

**页面**
- 学年学期：列表页 / 新增编辑页 / 发布确认页；
- 校历：编辑页（教学周/考试周/节假日/调休，周历组件）；作息节次配置页；
- 学籍：名册列表页（筛选+脱敏列+导入入口）/ 学生学籍详情页（状态+异动历史+360 入口）；
- 注册：注册批次页 / 待注册名单页（预检结果列）/ 注册确认页；
- 异动：异动列表页 / 异动发起页（按类型动态表单+材料）/ 异动详情页 / 异动审批页（复用统一审批组件）/ 异动统计页；
- 导入：学籍导入页（domain=academic-roster，模板下载/dry-run/确认）。

**接口**
- `GET/POST /academic-affairs/terms`、`POST /academic-affairs/terms/{id}/publish`（幂等）、`GET/PUT /academic-affairs/terms/{id}/calendar`、`GET/PUT /academic-affairs/time-slots`；
- `GET /academic-affairs/roster`（scope+脱敏）、`GET /academic-affairs/roster/{studentId}`；
- `GET/POST /academic-affairs/registrations/batches`、`GET /academic-affairs/registrations/pending`、`POST /academic-affairs/registrations/confirm`；
- `GET/POST /academic-affairs/status-changes`、`GET /academic-affairs/status-changes/{id}`、审批经 `/api/v1/approvals/*`（零新端点）；
- `POST /api/v1/import/domain/academic-roster/validate|confirm`（管线注册）。

**状态机**
- 学期：DRAFT→PUBLISHED→FROZEN→ARCHIVED；
- 异动单：DRAFT→SUBMITTED→（节点流转）→APPROVED→EFFECTIVE / REJECTED / RETURNED→（修改后重走 SUBMITTED）/ CANCELLED；
- 注册：PENDING_REGISTER→REGISTERED / UNREGISTERED（逾期批处理标记）。

**权限点**：term.view/edit/publish；roster.view/import；registration.view/execute；statusChange.view/create/review/final/export。

**测试**：状态机非法迁移 422 表驱动；异动四类型全链路（通过/驳回/退回）；重复发起与审批版本冲突 409；跨租户 404 / 非 scope 403 / demo 只读 403；导入 dry-run 行级错误断言；基线全绿。

**不允许做什么**：任何代码直接 UPDATE student_status（必须经单一入口，Code Review 红线）；写 current_stage；实现排课/成绩任何逻辑；给学生 PC 入口；发明新消息类型。

**验收标准**
1. 学期发布后教务首页与校历组件即时生效；
2. 一名种子学生完整走通"迎新完成→注册→在籍"与"休学→复学"，主档/StageEvent/待办/消息/统计五处均正确；
3. 学籍导入 500 行样例 dry-run 报错可复现、确认后整批事务；
4. 新增 pytest ≥25 条，基线 203 条全绿。

### 13B-P3 专业 · 培养方案 · 课程库

**目标**：教学依据层上线——课程库两级审核可用、培养方案编制→两审→发布→绑定年级全链路、组织三表字段补齐。

**页面**
- 学院/专业/班级管理页（新字段维护：学制/班级编号/编制人数/应毕业年份）；
- 课程库：列表页 / 新增编辑页 / 详情页 / 审核页；
- 培养方案：方案列表页 / 编制页（课程模块树 + 学分汇总条 + 校验错误面板）/ 审批页 / 发布与版本页 / 绑定年级页；
- 导入：课程导入页、方案导入页。

**接口**
- `PUT /academic-affairs/orgs/colleges/{id}|majors/{id}|classes/{id}`（扩展字段维护）；
- `GET/POST /academic-affairs/courses`、`POST /academic-affairs/courses/{id}/submit`、审批经 approvals；
- `GET/POST /academic-affairs/programs`、`PUT /academic-affairs/programs/{id}/courses`、`POST /academic-affairs/programs/{id}/submit|publish|bind`；
- import domain=academic-course / academic-program。

**状态机**
- 课程：DRAFT→COLLEGE_REVIEW→ACADEMIC_REVIEW→ENABLED（RETURNED 回 DRAFT；DISABLED 运维态）；
- 方案：DRAFT→COLLEGE_REVIEW→ACADEMIC_REVIEW→PUBLISHED→ENABLED（FROZEN/DISABLED 运维态；发布后修改强制新版本）。

**权限点**：org.edit；course.view/create/review/publish；program.view/edit/review/publish/bind。

**测试**：方案校验器表驱动（课程重复/学分不足/学期非法/引用未启用课程/毕业要求不一致→422 字段级明细）；发布后修改→新版本且旧绑定不变；两级审批 409/退回重提；越权（A 学院负责人操作 B 学院 403）；导入用例；回归。

**不允许做什么**：方案发布后原地改内容；课程绕过审核直接 ENABLED；方案内联自造课程（必须引用课程库）；删除组织三表既有字段或改其语义。

**验收标准**
1. 一个专业完成"建 10 门课程→审→启用→编方案→两审→发布→绑定 2026 级"全链路；
2. 学分汇总与毕业要求一致性校验实时生效（编制页可见差额）；
3. 历史年级绑定旧版本，新版本仅可绑新年级；
4. 新增 pytest ≥20 条，基线全绿。

### 13B-P4 教学任务 · 课表查看

**目标**：从已发布方案生成学期教学任务并完成"分配→确认→审核"；课表项可手工维护/导入，冲突检测生效；班级/教师/学生三视图查看并可发布。

**页面**
- 教学任务：批次页 / 应开课程核对页 / 教师分配页（工作量提示）/ 教师确认页（教师 PC 视图）/ 提交审核页；
- 课表：课表项维护页（周历网格+冲突红标）/ 课表导入页 / 班级课表页 / 教师课表页 / 学生课表代查页 / 课表发布页 / 课表导出（水印）。

**接口**
- `GET/POST /academic-affairs/teaching-tasks/batches`、`POST /academic-affairs/teaching-tasks/batches/{id}/generate`（幂等）、`POST /academic-affairs/teaching-tasks/{id}/assign|confirm`、`POST /academic-affairs/teaching-tasks/batches/{id}/submit`、审批经 approvals；
- `GET/POST/PUT/DELETE /academic-affairs/schedule/items`、`GET /academic-affairs/schedule/class/{classId}|teacher/{teacherId}|student/{studentId}`、`POST /academic-affairs/schedule/batches/{id}/publish`；
- import domain=academic-schedule；export domain=academic-schedule。

**状态机**
- 任务批次：DRAFT→COLLEGE_CONFIRMED→TEACHER_CONFIRMED→SUBMITTED→APPROVED（可排课）；
- 课表批次：DRAFT→PRE_PUBLISHED→PUBLISHED（发布前可撤回，发布后 V1 不提供改动流程）。

**权限点**：teachingTask.view/execute(generate)/edit(assign)/review；schedule.view/edit/import/publish/export。

**测试**：generate 幂等；冲突检测表驱动（教师/班级/教室 × 手工/导入六组合）；无教师提交 422；容量/工作量 warning 非阻断；发布通知（教师+学生）落 t_unified_message 断言；越权 403；回归。

**不允许做什么**：自动排课；调停课流转；发布后静默改课表项；学生视图走前端拼接（必须服务端按归属推导）。

**验收标准**
1. 一门课完成"方案→任务→分配→确认→审核→排入课表→发布"，三视图数据一致；
2. 冲突项在手工与导入两通道均被拒且提示冲突对方；

### 13B-P5 成绩查看 · 学业预警

**目标**：成绩读侧上线（与既有 t_acad_grade 同源，零写入）；学业预警规则引擎接入平台规则中心并复用既有处置链路。

**页面**

**接口**

- 明确：**不新增任何成绩写端点**；预警生成调用既有创建逻辑，处置沿用既有 close/escalate/assign/remind 端点。

**状态机**：无新增（预警沿用 t_acad_warning 既有 PENDING_HANDLE/PROCESSING/ESCALATED/CLOSED）。

**权限点**：gradeView.view/export；warningRule.config；warningScan.execute。

**测试**：扫描幂等（student+source+term 唯一）；阈值改配置立即生效；成绩可见性矩阵三角色断言；预警生成后待办/消息双落点；导出留痕与限流；既有 warnings 端点响应快照比对；回归。

**不允许做什么**：新建预警表；写 t_acad_grade；改既有 warnings/grades 端点；扫描绕过既有创建逻辑直插表。

**验收标准**
1. 造数"两门挂科"→扫描→中级预警→辅导员移动端处置→关闭，全链路含 360 可见；

3. t_acad_warning 新增 source_code/rule_code 迁移后基线全绿；
4. 新增 pytest ≥18 条。

### 13B-P6 毕业资格预审

**目标**：批次化系统预审（七项供数契约、三态判定）+ 异常清单推待办 + 学院/教务两级复核出三名单（毕业/结业/延毕，预审结论）。

**页面**：审核批次页 / 应审学生圈定页 / 预审执行与结果页（逐项三态矩阵）/ 异常清单页（按类型分组+推待办）/ 学院初审页 / 教务终审页 / 三名单页（含导出）。

**接口**：`GET/POST /academic-affairs/graduation-audit/batches`、`POST …/{id}/generate|precheck`（均幂等）、`GET …/{id}/results|abnormal`、审批经 approvals、export domain=academic-graduation。

**状态机**：WAIT_PRECHECK→SYSTEM_PASSED / SYSTEM_ABNORMAL→COLLEGE_REVIEW→ACADEMIC_REVIEW→GRADUATED / COMPLETED / DELAYED / REJECTED→ARCHIVED。

**权限点**：graduationAudit.view/execute(generate+precheck)/review/final/export。

**测试**：七项供数造数矩阵（每项 PASS/FAIL/UNKNOWN）；批次重跑幂等；异常待办责任人路由断言（实习→指导教师/毕设→导师/处分→辅导员/欠费→学院教务员）；终审经单一入口写 student_status；30 人批次 <60s；越权/只读；回归。

**不允许做什么**：要求六域改表供数；预审直接改各域数据；发证书文书；就业未填报默认卡审（默认提醒，规则开关控制）；把 UNKNOWN 判成 FAIL。

**验收标准**
1. 全通过/供数异常/供数缺失/处分联动四类学生各至少 1 例走通；
2. 一名学生补齐实习归档后重审转 PASS（重跑幂等）；
3. 名单导出水印+留痕；
4. 新增 pytest ≥18 条。

### 13B-P7 小程序教务入口

**不允许做什么**：改 /mobile/academic/my 响应结构；学生端出现教师功能；绕过 mobile 前缀直调 PC 端点；本地缓存敏感字段。

## 3. 依赖图

```
P1 契约冻结
 ├─→ P2 学年学期/校历/作息 ──┬─→ P4 教学任务/课表 ──→ P5 成绩查看/预警 ──→ P6 毕业预审
 │    学籍/注册/异动 ────────┤        ↑                      ↑                ↑
 └─→ P3 课程库 → 培养方案 ───┘        │                      │                │
                                     校历/作息            t_acad_grade      P2 学籍 + P3 方案
                                                          (既有,零依赖)      + 六域供数(既有)
P7 小程序入口 ←—— P2(学籍/异动) + P4(课表) + P5(成绩) + P6(进度) 的读侧接口
P8 测试验收 ←—— 全部
```

- **关键路径**：P1→P2→P3→P4→P6（毕业预审依赖方案学分要求与任务/课表提供的学期上下文）。
- **可并行**：P5 与 P4 可大部并行（成绩读侧只依赖既有 t_acad_grade；预警只依赖规则中心 + P2 注册状态）；P7 可在 P5 完成后启动，与 P6 并行推进，仅 graduation-progress 页最后接线。
- **提前量**：P2 期间前端可并行搭 /admin/academic-affairs 路由骨架与菜单（F1-1 产物）；测试可并行写表驱动用例框架。
