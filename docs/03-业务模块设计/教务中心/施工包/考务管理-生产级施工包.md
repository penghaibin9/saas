## 5. 业务目标、角色与完整闭环

- **解决的真实问题**：期末考试从"排考场→排监考→发布→考后登记→缓考"目前完全线下（Excel+纸质），本模块提供教务处/学院教务在线编排、冲突检测、准考证/门贴打印、考后异常登记与缓考四级审批的闭环。
- **购买/管理部门**：教务处（考务管理是教务处标准职能科室，参照 S1 上海交通大学"教务处教学运行管理办公室"设置）。
- **使用角色**：教务处（全权）、学院教务/教学秘书（本学院编排+确认）、任课教师/监考教师（本人监考场次只读+登记）、辅导员（缓考首级审批，本人所带班级学生）、学生（本人查询+缓考申请）。
- **发起、处理、审核、查看、归档责任**：教务处发起批次并终审发布；学院教务确认课程清单、执行考场/监考编排；监考教师登记考场异常；辅导员/任课教师/学院/教务处四级审批缓考；教务处归档批次。
- **主流程**：建批次(DRAFT) → 圈定考试课程(从教学任务带出) → 学院确认(COURSE_CONFIRMED) → 排考试时间/考场/座位/监考/巡考(ARRANGED) → 发布(PUBLISHED，通知考生+监考教师) → 考试进行/考后登记异常(FINISHED) → 归档(ARCHIVED)。
- **异常、撤回、退回、重复提交、超时、关闭、重开流程**：DRAFT 可删除；COURSE_CONFIRMED 阶段学院可"退回"课程条目（REMOVED，教务处补课程）；发布后如需变更走"作废重排"运维通道（参照 `AaScheduleBatch.void_reissue` 先例，留审计）；缓考任一节点可"退回"补材料（RETURNED，回 SUBMITTED 重提，旧任务留痕，新任务生成）或"驳回"（REJECTED，终态）；重复缓考申请同一 `exam_course`+`student` 若存在未终态记录 → 409；考试已开始后提交缓考 → 422 转人工通道（人工=教务处线下受理再补录）。
- **与其他模块的输入输出关系**：上游读 `t_aa_teaching_task`（教学任务，课程/班级/教师来源）、`t_aa_term`（学期/考试周）、`t_class`（行政班学生名单，V1 无选课）；依赖（暂未就绪，见 §16）教学资源模块的教室字典、排课管理模块的课表数据（避免考试时段与常规排课时段的教室双重占用，V1 降级为仅本批次内部考场冲突检测，跨模块教室时段联合校验列 backlog）；下游：缺考写 `RISK_ALERT` 类通知给辅导员（消费方=13A 学工中心风险预警，接口位不实现联动细节，仅落地一条通知/待办）；违纪登记留下"处分线索"引用位供学工处分模块消费（仅存 `discipline_case_ref` 字段位，不建跨域表，不实现联动逻辑）；成绩管理模块（R1，已实现）后续可读缺考标记作为 `ABSENT_EXAM` 预警来源（`t_acad_warning.source_code`，已在 §4.5 加列冻结，本卡不改动该表，仅在服务层为将来对接留字段位）。
