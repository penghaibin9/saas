## 3. 至少三套成熟系统逐家核验

### 系统 A · 强智教务管理系统（湖南强智科技发展有限公司）

1. 模块能力证据ID：`RES-VEN-01-CAP`（C 级，厂商官网自述）
2. 高校采用证据ID：`RES-VEN-01-ADOPT`（A 级，厦门软件职业技术学院，2024-10-31 正式启用，真实高职院校）
3. 已核验事实：厂商提供"教室实时状态发布"能力、"教室借用在线申请与审批"、"教室借用率"统计分析；真实高职院校已整体切换该产品并上线课表/成绩等模块。
4. 不可推断边界：厦门软件职业技术学院的启用通知未提及教室子模块，不能证明该校教室字典/教室资源功能被实际使用；"教室实时状态"未说明状态枚举具体取值（是否为"可用/占用/维修/停用"等）。
5. 可转化的设计输入：教室应有"状态"字段且需要能被排课等下游模块实时读取（本卡 `usable_status` 字段设计的佐证之一，主依据仍为项目手册与既有 `t_aa_schedule_item.classroom_text` 冲突检测现状）。

### 系统 B · 正方教务管理系统（正方软件股份有限公司）

1. 模块能力证据ID + 高校采用证据ID：`RES-VEN-02-CAP-ADOPT`（A 级，能力与采用合一，证据强度本包最高）
2. 已核验事实：华南师范大学官方学生手册原文出现"教室类别""座位数""校区"三个可检索字段，及"空教室查询→预约→审核"的借用流程；证明真实高职/本科教务系统的教室数据确实包含"类别（对应本卡 classroomType）""容量（座位数，对应本卡 capacity）"两个核心维度。
3. 不可推断边界：手册为学生预约视角文档，不能证明教务管理员侧维护教室字典时的具体字段命名和状态枚举；"校区"维度本项目本轮不采纳（明确不做：多校区跨区约束，见手册原文）。
4. 可转化的设计输入：`classroomType`（教室类别）与 `capacity`（座位数/容量）确认为真实产品的核心教室属性，本卡采纳为必填字段（designSource 仍以项目手册原文"教室字典(楼栋/教室/容量/类型/可用状态)"为第一优先，本证据作双重印证）。

### 系统 C · 超星教务系统 / 超星智慧教务（超星集团）

1. 模块能力证据ID：`RES-VEN-03-CAP`（B 级，厂商正式赛题需求规格，非泛泛宣传）
2. 高校采用证据ID：`RES-VEN-03-ADOPT`（A 级，常州工业职业技术学院，2022-06-21，真实高职院校）
3. 已核验事实：厂商需求规格明确"教学楼、教室、教学班"为排课数据要素，教室资源含"不同类型、容量和设备配置"，并有"班级人数须小于教室容量"的硬约束描述；真实高职院校已上线该厂商教务系统学生端。
4. 不可推断边界：常州工业职业技术学院的通知未提及教室查询功能，不能证明该校教室资源模块被实际使用；赛题为厂商命题非独立评测，不采信任何效果类数字。
5. 可转化的设计输入：**"班级人数须小于教室容量"** 直接对应下册 R4 指令验收点"教室容量小于班级人数 warning 不阻断"，是本卡与排课模块共享设计契约中"容量校验"能力的核心外部佐证。
