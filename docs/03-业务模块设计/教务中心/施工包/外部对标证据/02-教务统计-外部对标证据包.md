## 3. 至少三套成熟系统逐家核验

### 系统 A · 强智教务管理系统 / 质量管理信息平台（湖南强智科技发展有限公司）

1. 模块能力证据ID：`AASTAT-VEN-01-CAP`（B 级，厂商官网公开产品功能条目，已实际打开两页原文）
2. 高校采用证据ID：`AASTAT-VEN-01-ADOPT`（C 级，仅 logo 图片弱信号）
3. 已核验事实：产品明确具备"评估体系自定义指标+设定预警""统计分析及报告可视化图表化""数据看板""质量预警业务功能"等条目，功能定位与本模块（多维筛选汇总卡+预警统计）方向一致。
4. 不可推断边界：不得把"logo 出现在案例展示区"当作"该校已启用统计/预警子模块"的证据；不得推断具体指标口径与钻取深度；不得引用同中心姊妹证据包 `SCHED-VEN-01-ADOPT`（西北工业大学"翱翔教务"）作为本模块（统计）的专属 ADOPT 证据——该证据针对的是排课模块工作流程原文，未涉及统计/看板内容，仅可作"该厂商在真实高校长期驻场、公司资质可信"的弱旁证，不计入本模块 ADOPT 门禁。
5. 可转化的设计输入：多维筛选（学院/专业/学年学期）+ 预警阈值配置+可视化图表 的产品方向已获真实厂商官网证据支撑（作为行业惯例佐证，不单独作为字段级决策依据；本模块具体指标口径仍以 `project_rule`——即项目自有 §4 指标接入清单——为第一优先级来源）。

### 系统 B · 正方教务管理系统（正方软件股份有限公司）

1. 模块能力证据ID：`AASTAT-VEN-02-CAP` = **FAIL**（PDF 手册内容两次尝试均未能解析出统计相关章节文本）
2. 高校采用证据ID：`AASTAT-VEN-02-ADOPT`（A 级，福州外语外贸学院教学发展中心真实发布、持续维护 2020→2022 两版操作手册，证明该校长期真实使用正方教务系统）
3. 已核验事实：仅能确认"该校真实长期使用正方教务系统"这一采用事实，不能确认其统计模块的具体功能与口径。
4. 不可推断边界：不得把"该校使用正方系统"扩大解释为"正方系统的统计报表功能已被验证具备某些具体能力"——两者是独立维度，本证据只覆盖 ADOPT，不覆盖 CAP。
5. 可转化的设计输入：无法从本证据直接转化字段级设计；仅作为"正方是中国高校广泛使用的主流教务系统之一，本项目对标正方具有现实意义"的背景合理性支撑。

### 系统 C · 超星学习通/泛雅综合教学管理平台（超星集团）

1. 模块能力证据ID / 高校采用证据ID：`AASTAT-VEN-03-CAP` / `AASTAT-VEN-03-ADOPT`（合并为一条，A 级，九江学院教务处 2025-03-11 正式通知，真实高校 + 真实功能描述同时具备）
2. 已核验事实：九江学院教务处官方通知确认该校已开通超星"AI学情分析""图谱化课程报告""知识图谱细粒度数据采集与反馈，实现精准化、个性化诊断"等能力，证明真实高校教务处认可并向师生正式发布这类学情/教学数据分析能力。
3. 不可推断边界：该通知描述的是"学情分析"（偏向课堂学习行为大数据），与本模块聚焦的"11 项教务运行结果性指标（注册/异动/课表/成绩/预警/毕业等）汇总统计"并非同一产品模块，不得把"AI学情分析"直接等同于"教务统计总览"；不能证明该校是否使用超星做学籍/课表/毕业资格类统计。
4. 可转化的设计输入：仅作为"真实高校教务处认可数据驱动的教学过程分析能力、愿意为此发正式通知"这一行业趋势的佐证（design_inference 级）；不作为本模块具体指标口径的来源。

## 7. 禁止推断清单

- 不得把 `AASTAT-VEN-01-ADOPT`（logo 图片墙）当作"这些学校已启用强智统计/预警子模块"的证据——仅证明客户关系存在。
- 不得把姊妹证据包 `SCHED-VEN-01-ADOPT`（西北工业大学排课工作流程原文）挪用为本模块的 ADOPT 证据——该证据未涉及统计/看板内容。
- 不得把 `AASTAT-POL-02`（未核实条款号的政策摘要）当作已逐条核验的 A 级法规原文引用，只能作 `design_inference` 参考。
- 不得推断三家产品统计模块的具体算法、准确率、客户满意度等宣传数字（本次未采信任何效果类宣传数据）。

- 不得把九江学院超星通知中的"AI学情分析/知识图谱"能力，扩大解释为"超星已具备与本项目 11 项指标完全一致的教务统计报表"。

**总体判定**：`PARTIAL`。三套系统均已实际联网核验，但没有一套系统同时具备 A 级"当前模块能力"与 A 级"高校真实采用"两类证据（强智：能力 B / 采用 C；正方：能力 FAIL / 采用 A；超星：能力+采用合一 A 但主题偏离）。按 CLAUDE.md §5.1"若本地证据包部分通过，只能使用其中已通过的证据，缺失项继续标 PARTIAL/FAIL，不得整包冒充通过"处理——本二级施工包外部证据门禁项在 §17 设计就绪门禁中如实标注为 `PARTIAL`，不改写为 PASS。

本模块绝大部分正式指标设计（11 项指标精确口径）designSource 优先取 `project_rule`（本项目已冻结的《13B-教务中心与现有系统融合设计.md》§4 指标接入清单，2026-07-11 定稿）与 `existing_code`（各业务域真实表结构，见二级施工包 §1 代码审计），外部证据仅作辅助验证与行业合理性背景，不构成对既有冻结口径的推翻依据。是否接受"以 `project_rule`+`existing_code` 为主、外部证据为辅"的方式推进 `design_ready`，还是要求后续针对"正方统计模块 CAP"与"强智 ADOPT"专项补充核验后再放行，列为二级施工包 §16 用户决定项。
