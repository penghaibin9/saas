## 3. 真实业务结果与边界

- 学院教务确认"本学院哪些教学任务需要参加本批次考试"，是批次从 DRAFT 推进到 COURSE_CONFIRMED 的必要环节。
- 进入条件：批次已"圈定课程"（生成 PENDING_CONFIRM 清单）；退出条件：全部课程非 PENDING_CONFIRM。
- 上游：`t_aa_teaching_task`（课程/班级/教师/预计人数）。下游：04号卡（考场安排）、03号卡（考试时间设置）均以 `exam_course_id` 为锚点。
- 本卡必须完成：批量生成（幂等）、逐条/批量确认、移除（学院退回）、按学院范围列表过滤。
- 明确不做：手工新增考试课程（V1 全部从教学任务带出，若某课程需要考试但教学任务未生成，需先在教学任务模块补录，不在本卡开口子）；选课名单（LOCKED 切换位仅留字段，不实现）。
- 仅学校能决定：某教学任务是否必须参加统一考试（`exam_mode='EXAM'` vs `'CHECK'` 考查免考——`t_aa_course.exam_mode` 已有该字段，生成逻辑默认只圈定 `exam_mode='EXAM'` 的课程，`CHECK` 类课程默认不生成，此为技术事实非业务政策，已按代码可查明处理，不列入用户决定项）。

## 6. 主流程、异常流程与状态机

`PENDING_CONFIRM → CONFIRMED`（学院确认）/`PENDING_CONFIRM → REMOVED`（学院退回）。非法操作：CONFIRMED/REMOVED 后再次确认/移除 → 409 `ILLEGAL_STATE`；批次非DRAFT时调用生成接口 → 409。并发：批量确认逐条独立提交，单条失败不影响其余（部分成功响应体列出失败项）。
