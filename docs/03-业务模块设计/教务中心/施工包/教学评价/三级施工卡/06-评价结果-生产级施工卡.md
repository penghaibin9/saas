## 3. 真实业务结果与边界

- **该三级模块让哪类学校用户完成什么工作**：批次关闭后，系统按教师+课程维度聚合学生评教均分与参评率，按规则中心阈值分级（优秀/良好/合格/待整改），教务处审核后发布，教师查看本人结果，教务处/学院查看全量/本学院结果用于教学质量管理。
- **进入条件与退出条件**：进入——批次状态CLOSED；退出——批次归档（结果随批次一起进入只读态）。
- **上游输入、下游输出和跨模块回写**：输入——`t_aa_evaluation_response`（学生评教均分主计算源，自评/同行/督导作为并列展示）、`t_aa_evaluation_task`（参评率=SUBMITTED/总任务数）；输出——供"评价申诉"三级模块作为申诉对象、本卡内嵌整改跟踪子流程（FAIL档触发）、"评价统计"三级模块的聚合数据源。
- **本卡必须完成**：结果生成（关闭后自动触发，教务处也可手动重算未发布结果）、分级计算（按规则中心阈值）、结果发布（批量/单条）、结果详情（含学生均分+自评/同行/督导并列展示，不加权合成为单一分数）；**整改跟踪子流程**：FAIL档结果自动生成整改任务（PENDING）→教师提交整改计划（SUBMITTED）→学院确认（COLLEGE_CONFIRMED）→关闭（CLOSED）。
- **明确不做及理由**：不做加权合成公式（R9范围明确排除）；不做跨批次历史趋势对比图（backlog，属"评价统计"卡的延伸能力，本卡只做单批次结果）；整改跟踪不做逾期自动升级报送（如自动报告院长），仅做逾期提醒展示，升级规则待用户确认（见下）。
- **仅学校能够决定的业务政策**：分级阈值具体分数线（本卡默认：均分≥90优秀/≥80良好/≥60合格/<60待整改，`ai_proposal`，需学校确认或调整默认值）；参评率过低（如<50%）时结果是否仍可发布（本卡默认允许发布但在结果详情标注"参评率偏低，结果仅供参考"，`ai_proposal`）。
