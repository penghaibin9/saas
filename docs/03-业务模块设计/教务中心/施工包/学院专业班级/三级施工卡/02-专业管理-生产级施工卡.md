## 3. 真实业务结果与边界

- **该三级模块让哪类学校用户完成什么工作**：学院教务员/教学秘书维护本学院专业的学制、培养层次、招生状态；教务处管理员维护全校专业并做跨学院一致性审查；专业负责人只读查看本专业信息用于参与培养方案编制（不在本卡内编辑，编辑走培养方案模块）。
- **进入/退出条件**：进入需 `org.view`；停招（退出招生态）需前置核对本专业是否仍有在读年级（存在则允许停招但需二次确认"仅停止新生招生、不影响在读学生"，与"停用"语义区分——见 §6）。
- **上游输入、下游输出**：上游=学院管理（`college_id` 外键，学院停用会级联阻断本专业新建/编辑，见组织结构同步卡）；下游=培养方案（`aa-training` 按 `majorId` 筛选并读 `education_years` 计算毕业年限——融合设计 §1.4"培养方案与毕业年限计算"）、行政班管理（`class.major_id`）、毕业资格审核（专业负责人视角）。
- **本卡必须完成**：专业列表（含班级数/学生数只读列）、新建、编辑（含加列字段）、停招/复招。
- **明确不做及理由**：不做专业删除（专业一旦有历史班级/学生引用不可物理删除，只能停招）；不做跨学院迁移专业（专业转学院属重大组织调整，超出本轮范围，需学校书面决定后走后续迭代）。
- **仅学校能够决定的业务政策**：`training_level`（培养层次）字典值范围（如"高职专科/五年一贯制/中职"等，需学校提供本校实际使用的层次口径，本卡不编造字典值，编码阶段以可编辑字典表或简单字符串字段实现，默认给出常见候选但允许学校自定义）。

## 5. 字段、按钮与校验

### 5.1 字段

| 字段 | 类型 | 必填/默认 | 来源/字典 | 前端校验 | 后端校验 | 敏感级 | 入库/API映射 |
|---|---|---|---|---|---|---|---|
| majorName | string | 必填 | 用户输入 | 长度1-200 | 非空 | 不敏感 | `major_name` |
| code | string | 选填 | 用户输入 | ≤50 | 应用层建议同院唯一（不加DB唯一约束） | 不敏感 | `code` |
| collegeId | ref | 必填 | 学院列表 | 必选且ACTIVE | 必须存在且ACTIVE，学院教务员固定本院 | 不敏感 | `college_id` |
| educationYears（新增） | int | 选填，默认3 | 用户输入 | 1-6 | 同左，默认3 | 不敏感 | `education_years` |
| trainingLevel（新增） | string | 选填 | 学校自定义字典（编码阶段先给候选值，允许自定义） | ≤50 | 长度校验 | 不敏感 | `training_level` |
| enrollStatus（新增） | enum | 默认 ENROLLING | 系统 | 只读展示，通过停招/复招按钮变更 | 状态机 | 不敏感 | `enroll_status`∈{ENROLLING,SUSPENDED} |
| status | enum | 默认 ACTIVE | 系统 | 只读 | 状态机 | 不敏感 | `status`∈{ACTIVE,DISABLED} |

**`enrollStatus` 与 `status` 的语义区分（避免混淆）**：`enrollStatus=SUSPENDED` = 暂停招收新生（历史班级/在读学生不受影响，专业实体保留 ACTIVE）；`status=DISABLED` = 专业整体停用归档（要求已无任何在读学生，比 `enrollStatus` 更严格的终态）。
