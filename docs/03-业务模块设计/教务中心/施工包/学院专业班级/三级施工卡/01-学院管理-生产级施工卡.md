## 3. 真实业务结果与边界

- **该三级模块让哪类学校用户完成什么工作**：教务处管理员维护全校学院清单（简称、排序、启停状态）；学院教务员只读查看本学院信息（本卡不授予学院侧编辑"学院"实体本身的权限——学院是全校统一编号的顶层组织单元，参照权限总控 §5.1"学校平台管理员配置组织结构"与 §7.4"教务处管理员=全校教务"的权责设计，编辑权收拢在教务处层，避免多学院各自改名造成全校口径不一致）。
- **进入条件与退出条件**：进入需 `module.academicAffairs.enabled` 已授权；退出/停用需组织结构同步核对通过（无在读专业/班级/学生）。
- **上游输入、下游输出和跨模块回写**：上游=开校向导批量建院（`school_onboarding_service.py`）；下游=专业管理（`college_id` 外键）、学工班级画像（`affairs_class_service.py` 只读 `college_name`）、教学任务批次（`AaTeachingTaskBatch.college_id`）、统计看板。本卡不回写任何其他模块数据。
- **本卡必须完成**：学院列表（含专业数/班级数/学生数只读统计列）、编辑扩展字段（简称/排序）、停用/启用（含前置核对）。
- **明确不做及理由**：不做学院新建/删除（学院新建属开校初始化范畴，日常新增学院是低频重大变更，暂由平台运维协助或后续迭代评估，避免教务处随意新增造成组织混乱——按 CLAUDE.md §10"关键业务方向存在两种会显著改变产品的选择"预留，本轮只做维护不做新建/删除）；不做拖拽排序（用户已排除组织结构树拖拽调整）。
- **仅学校能够决定的业务政策**：学院编号（`code`）规则、简称显示规范——由学校提供，不由 AI 编造默认值（新增学院本轮不做，此项实际不适用于本卡范围，留待未来"学院新建"功能评估时确认）。

2. 点击任一学院"编辑"，修改简称并保存，列表立即刷新显示新简称。
3. 找一个下面还有在读专业的学院点击"停用"，系统应弹出提示"该学院下仍有 N 个在用专业，无法停用"并列出清单，不能强行停用成功。
4. 用学院教务员账号登录，只能看到自己学院1条数据，且看不到"编辑"/"停用"按钮（或点击后被拒绝）。
