## 5. 业务目标、角色与完整闭环

- **解决的真实问题**：学校组织架构（学院/专业/年级/行政班/班级学生）是教务、学工、实习、毕设、迎新等全平台模块共同依赖的基础主数据；目前只能在"开校初始化向导"批量建一次，日常无法维护学制、班级编号、编制人数、应毕业年份等培养管理必需字段，也没有教务侧的组织变更审计与教学秘书协助分工。
- **购买/管理部门**：教务处（组织基础数据权威归口部门）；日常协同部门为各学院教务办公室。
- **使用角色**：教务处管理员（全校）、学院教务员（本学院）、教学秘书（本学院协助/代录，不终审）、专业负责人（本专业只读参与）；学工侧辅导员/班主任、实习/毕设等模块仅为只读消费方（不在本模块内操作）。
- **发起、处理、审核、查看、归档责任**：学院教务员/教学秘书发起扩展字段维护与班级新建申请；教务处管理员对跨学院影响的动作（学院停用、专业停用、班级归档）做确认；专业负责人查看本专业组织信息参与培养方案编制；系统对班级停用/归档做前置引用核对。
- **主流程**：学院管理员建学院 → 学院教务员/教务处维护专业（含加列字段）→ 建年级/行政班（含班级编号/学制推导的应毕业年份/编制人数）→ 绑定辅导员/班主任/教学秘书 → 学生入班（读学籍模块）→ 教学班按学期动态生成（只读聚合，不在本模块编辑）→ 毕业年份到期后批量核销/归档。
- **异常、撤回、退回、重复提交、超时、关闭、重开流程**：编辑冲突走乐观锁（`version`）409；停用/归档前必须通过"组织结构同步"引用核对（存在在读学生/未结课教学任务时拒绝并给出清单）；误停用可由教务处管理员重新启用（`status` 回退，全程审计）。
- **与其他模块的输入输出关系**：向学工中心（班级画像/辅导员考评只读）、教务学籍/注册/异动/培养方案/教学任务/毕业资格审核、迎新（分班）、实习/毕设（学生组织归属只读）等全部下游模块提供权威组织数据；本模块只读消费学生主档统计人数，不改写 `t_student_profile`。

## 7. 状态机与业务规则

本二级模块无跨三级模块的单一大状态机，采用**每个实体各自的轻量状态**（多为 ACTIVE/DISABLED 二态或三态），详细状态机见各三级卡 §6。此处登记跨实体的公共规则：

| 当前状态 | 允许动作 | 操作角色 | 前置条件 | 下一状态 | 非法操作 | 并发/幂等 | 审计事件 |
|---|---|---|---|---|---|---|---|
| ACTIVE（学院/专业/班级） | 停用 | 教务处管理员(全校)/学院教务员(本学院，仅班级) | 组织结构同步核对通过（无在读学生/未结课教学任务） | DISABLED（班级为 GRADUATED/DISBANDED） | 存在在读学生/未结课教学任务时停用 → 422 + 核对清单 | 乐观锁 `version`，冲突 409 | `AA_ORG.*_DISABLE` |
| DISABLED | 启用 | 教务处管理员 | 无 | ACTIVE | 无 | 乐观锁 | `AA_ORG.*_ENABLE` |
| 任意 | 编辑扩展字段 | 教务处管理员(全校)/学院教务员(本学院) | 数据范围内 | 不变 | 跨学院编辑 → 403 NO_DATA_SCOPE(403002) | 乐观锁 | `AA_ORG.*_UPDATE` |

## 8. 数据模型与迁移

| 表/字段/索引 | 新增/复用 | 业务含义 | 租户隔离 | 关联主数据 | 敏感级别 | 唯一/并发约束 | 迁移与回滚 |
|---|---|---|---|---|---|---|---|
| `t_college` | 复用（加列） | 学院 | `tenant_id`（`TenantMixin`已有） | — | 不敏感 | `(tenant_id, code)` 建议唯一（现状未加约束，本轮补充应用层校验，暂不加 DB 唯一索引避免存量脏数据迁移失败） | `alembic` 新版本：`ALTER TABLE t_college ADD COLUMN short_name VARCHAR(100) NULL, ADD COLUMN sort_order INT NULL DEFAULT 0` |
| `t_major` | 复用（加列） | 专业 | `tenant_id` | `college_id → t_college.id` | 不敏感 | 无 | `ADD COLUMN education_years TINYINT NULL DEFAULT 3, ADD COLUMN training_level VARCHAR(50) NULL, ADD COLUMN enroll_status VARCHAR(20) NULL DEFAULT 'ENROLLING'` |

| `t_aa_major_direction`（新表，D-09） | 新增 | 专业方向（试点默认关闭） | `tenant_id` | `major_id → t_major.id` | 不敏感 | `(tenant_id, major_id, code)` 唯一 | 新表迁移，回滚=`DROP TABLE`（无历史数据） |
| `t_aa_class_adjustment`（新表，班级调整） | 新增 | 批量班级调整申请单 | `tenant_id` | `from_class_ids(JSON)/to_class_id → t_class.id` | 不敏感 | 无唯一约束（可多次发起） | 新表迁移 |

**回滚策略**：加列迁移一律 `nullable`，降级仅需 `DROP COLUMN`（无数据丢失风险，因新字段无下游写依赖）；新表迁移降级为 `DROP TABLE`（`t_aa_major_direction`/`t_aa_class_adjustment` 均为本轮新建，无历史数据）。

## P6. 教学计划收编决议（拍板记录）

**背景**：`aa-teaching-plan`（教学计划）与"培养方案绑定年级"（`aa-training` → 已实现 `POST /academic-affairs/programs/{programId}/bind`，真实签名 `BindGradeBody{gradeYear, classId}`，见 `backend/app/modules/academic_affairs/routers/academic_affairs.py:241-248`）、"教学任务生成/批次"（`aa-teaching-tasks` → 已实现 `/admin/academic-affairs/teaching-tasks`，真实页面 `AaTaskBatchListView.vue`/`AaTaskDetailView.vue`）功能重叠——方案绑定年级即年级教学计划的实质内容（某年级用哪个培养方案版本），教学任务批次即学期开课计划的实质内容（某学期开哪些课、分给哪些教师/教学班）。

**拍板**：`navPlan.js` 中 `aa-teaching-plan` 模块叶子不新建表、不新建端点、不新建独立页面；后续（非本次任务范围）由教务中心统一收口时，将其 10 个 `P()` 占位子项改造为指向已有页面的 `I()` 链接（"年级教学计划/专业教学计划/学期教学计划"类指向 `/admin/academic-affairs/programs/:id`；"课程开设计划/教学任务生成"类指向 `/admin/academic-affairs/teaching-tasks`），或在教务中心整体施工时直接归并/移除该二级模块条目，具体收口方式由教务中心二级模块统一收口任务决定。

**理由**：避免重复造轮子；两条已实现链路已覆盖"教学计划"的实质业务功能（年级用哪个方案、学期开哪些课）。

**范围声明**：`aa-teaching-plan` 本身不属于"学院专业班级"二级模块，本节仅按用户任务要求在本施工包内正式记录该决议存档，具体 navPlan 改造由教务中心后续统一收口任务执行，不在本次"学院专业班级"施工范围内交付。

**若学校后续明确要求独立"实践教学计划"能力**：本轮不做，需另立项、重新走 A 模式外部对标与施工包门禁。

`designSource=user_decision`（P6 拍板）+ `existing_code`（两条链路真实签名已核验）。
