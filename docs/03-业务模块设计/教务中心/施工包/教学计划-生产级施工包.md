## 5. 业务目标、角色与完整闭环

- **解决的真实问题**：培养方案（`AaProgram`）规定"某专业需修哪些课程/学分要求"，教学任务（`AaTeachingTask`）是"某教学班由某教师实开"，二者之间缺一个显式的、可审核发布的"**应开**"层——即"某年级某专业在某学期应开哪些课程、周学时几何、由哪个学院开"。本模块补齐该层，使教学任务生成有权威的、经审核发布的计划依据，而非每次直接从培养方案临时推导。
- **购买/管理部门**：教务处（计划建/审/发/变/归全权）；学院教务（本院计划编制、核对、建议）。
- **使用角色**：教务处管理员（`ACADEMIC_ADMIN`/`SCHOOL_ADMIN`，TENANT_ALL）、学院教务员（`COLLEGE_ADMIN`，COLLEGE）、专业负责人（业务关系，本专业计划编制/确认，非独立权限角色）、普通教务教师（`ACADEMIC_TEACHER`，按范围只读）。
- **发起、处理、审核、查看、归档责任**：教务处/学院教务员编制计划（DRAFT）→提交→学院初审（COLLEGE_REVIEW）→教务处终审（ACADEMIC_REVIEW）→发布（PUBLISHED，供教学任务消费）→学期中如需调整走计划变更（CHANGING→审批→新版本 PUBLISHED）→学期结束归档（ARCHIVED）。
- **主流程**：选定学年学期（`AaTerm` PUBLISHED）+ 培养方案（`AaProgram` ENABLED）+ 年级/专业 → 系统按方案 `AaProgramCourse` 预填该学期应开课程草案 → 编制人调整（增删课/改周学时/标实践/指定开课学院）→ 提交两级审核 → 发布 → 教学任务生成消费（切换位就绪后）→ 执行进度跟踪（应开 vs 实开）→ 归档。
- **异常、撤回、退回、重复提交、超时、关闭、重开流程**：审核驳回→RETURNED（原因≥5字）→修改重提；已 PUBLISHED 计划禁止直接改，须走计划变更生成新版本（旧版本 SUPERSEDED）；重复提交由头表 `status` 幂等拦截（非 DRAFT/RETURNED 提交→409）；无课程明细的计划提交→422。
- **与其他模块的输入输出关系**：**输入** `AaProgram`/`AaProgramCourse`（派生课程草案）、`AaProgramBinding`（年级绑定）、`AaCourse`（课程字段快照）、`AaTerm`（学期）；**输出** PUBLISHED 计划的 `plan_course` 清单，供 `AaTeachingTaskBatch.generate` 作为"应开课程"来源（D-09 切换位，V1 不切）；执行进度读 `AaTeachingTask` 实开数据。**重叠边界（P6 所指）**：`AaProgramBinding` 承载"年级绑定哪个方案版本"，本模块"年级教学计划"叶子**只读消费**该绑定（不重复建绑定关系，仅按绑定聚合展示）；`AaTeachingTaskBatch` 承载"实开批次"，本模块"学期教学计划/课程开设计划"叶子产出"应开清单"，二者是应开/实开两侧，通过 `course_id`+`term` 关联，不互相覆写。

| `t_aa_teaching_plan_change`（变更） | 新增 | 计划变更单（append-only，4 态） | `tenant_id` | `plan_id`→头表 | 无敏感字段 | 无唯一约束（append-only） | 随头表同一 revision |

**头表 `t_aa_teaching_plan` 字段（PKMixin/TenantMixin/CommonMixin 约定，对齐 `AaProgram`/`AaTeachingTaskBatch` 命名）**：
- `plan_name` String(200) NOT NULL —— 计划名（如"2026级软件技术专业2026-2027-1学期教学计划"）
- `program_id` BigInteger NOT NULL index —— → `t_aa_program`（派生来源方案）
- `program_version` Integer —— 方案版本快照（防方案改版污染历史计划，对齐 `AaProgram.version`）
- `major_id` BigInteger index —— 专业
- `grade_year` String(20) index —— 适用年级（对齐 `AaProgram.grade_year`/`AaProgramBinding.grade_year`）
- `term_id` BigInteger index —— → `t_aa_term`
- `plan_type` String(20) default "MAJOR" —— MAJOR/PRACTICE（区分普通专业计划与实践专项计划，供 U-03 弹性；默认 MAJOR）
- `total_credits_snapshot` Numeric(6,1) —— 计划总学分（明细汇总冗余，供列表快速展示）
- `version` Integer NOT NULL default 1；`prev_version_id` BigInteger —— 版本链（对齐 `AaProgram`）
- `status` String(50) NOT NULL default "DRAFT" index —— DRAFT/SUBMITTED/COLLEGE_REVIEW/ACADEMIC_REVIEW/RETURNED/PUBLISHED/CHANGING/ARCHIVED
- `college_reviewed_at/college_reviewer_id/academic_reviewed_at/academic_reviewer_id` —— 两级审核留痕（对齐 `AaGradeTask` 同名字段范式）
- `return_reason` String(500)；`publish_at` DateTime；`archived_at` DateTime；`archived_by` BigInteger
- `workflow_instance_id` BigInteger index —— 审批流实例（对齐既有）

**明细表 `t_aa_teaching_plan_course` 字段**：
- `plan_id` BigInteger NOT NULL index；`course_id` BigInteger NOT NULL index → `t_aa_course`
- `course_code/course_name` 快照（对齐 `AaTeachingTask.course_code/course_name` 快照做法）
- `open_term_no` Integer —— 第几学期开课（对齐 `AaProgramCourse.open_term_no`）
- `nature_snapshot` String(50) —— 必修/选修/限选快照（自 `AaCourse.nature`）
- `credit_snapshot` Numeric(4,1) —— 学分快照（自 `AaCourse.credit`）
- `weekly_hours` Integer；`total_hours` Integer —— 周学时/计划总学时（对齐 `AaTeachingTask`）
- `offering_college_id` BigInteger index —— 开课学院（数据范围过滤依据，自 `AaCourse.owner_college_id` 预填可改）
- `is_practice` Boolean default false；`practice_weeks` Integer —— 集中实践标志+周数（D-04）
- `exam_mode_snapshot` String(20) —— 考核方式快照（自 `AaCourse.exam_mode`）
- `remark` String(500)
- `status` String(50) NOT NULL default "PLANNED" index —— PLANNED/CHANGED/CANCELLED
- `change_id` BigInteger index —— → `t_aa_teaching_plan_change`（变更期回链，对齐 `AaScheduleItem.change_id` 范式）

**变更表 `t_aa_teaching_plan_change` 字段**：
- `plan_id` BigInteger NOT NULL index；`change_type` String(50) —— ADD_COURSE/REMOVE_COURSE/MODIFY_HOURS/MOVE_TERM
- `before_json` String(2000)；`after_json` String(2000) —— 变更前后快照
- `reason` String(500) NOT NULL —— 变更原因（≥5字）
- `applicant_id` BigInteger；`reviewer_id` BigInteger；`reviewed_at` DateTime
- `status` String(50) NOT NULL default "SUBMITTED" index —— SUBMITTED/APPROVED/REJECTED/APPLIED
- `workflow_instance_id` BigInteger index

**索引建议**：头表补 `(tenant_id, grade_year, term_id)`（年级/学期视图高频）+ `(tenant_id, status)`；明细表补 `(tenant_id, plan_id, status)` + `(tenant_id, offering_college_id)`（学院范围过滤）+ `(tenant_id, course_id, open_term_no)`（执行进度连 `AaTeachingTask` 用）。

**迁移策略**：新 Alembic revision（编号在教务中心并行包合并阶段由总控统一排序，防冲突）；三表同一 revision 建表；`downgrade` 三表 drop（新业务表无存量数据，执行前自动导出快照，遵循 §5.4 通用回滚规则）。

**继承的硬规则**：①模块授权→角色权限→数据范围→业务关系→按钮权限六要素合取（权限总控 §8A.1）；②前端隐藏不等于授权，后端独立校验；③两级审核角色分离（学院初审 vs 教务终审），越级终审后端拦截；④角色切换后菜单/数据范围重载。
**需要新增/复用的 permission key**：新增 `academicAffairs.teachingPlan.view/manage/review/publish/change/archive`；复用 `ACADEMIC_ADMIN`/`ACADEMIC_TEACHER`/`COLLEGE_ADMIN` 的 `academicAffairs.*` 通配（`permissions.py:48,50,51`），新增细粒度 key 无需改角色映射即自动生效，仅需在系统管理中心权限点注册表登记供未来自定义角色裁剪。
**需要甲方/学校确认的边界（业务政策，非技术问题）**：①两级审核是否都必须（部分学校仅教务处一级审核）→ U-05；②专业负责人是否作为独立数据范围主体（当前无专业负责人关系表）→ U-04；③实践教学计划是否需独立台账/独立审批线 → U-03。技术事实（表是否存在、scope 机制、通配覆盖）均已自查清楚，不推给用户。
