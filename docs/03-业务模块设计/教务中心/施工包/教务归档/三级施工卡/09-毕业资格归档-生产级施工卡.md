## 3. 真实业务结果与边界

- 使用角色/工作内容：教务处管理员核对本学期（若为毕业学期）的毕业资格预审批次是否全部完成终审（每个学生的逐生结果达到终态 `GRADUATED/COMPLETED/INCOMPLETE`），并且本卡的"迎新档案供数接入"改造让 ARCHIVE 项从永久 UNKNOWN 变为基于真实数据的 PASS/FAIL/UNKNOWN 三态判定。
- 进入/退出条件：同前述卡；若本学期不是任何年级的毕业学期（无对应批次），本域直接判为OK（无需归档）。
- 上游输入：`t_aa_graduation_audit_batch`/`t_aa_graduation_audit_result`（只读取数）+ **本卡新增写入**：批次终审完成后推进 `status` 到 `ARCHIVED`（这是本卡对既有毕业预审service的唯一实质性改动）；`t_orientation_material`（只读，供ARCHIVE项判定）。
- 下游输出：`AaArchiveItem(category='GRADUATION')`；ARCHIVE项判定结果实时体现在毕业预审七项供数结果中（不需要等归档批次才生效——即改造后 `academic_affairs_graduation_service.py:108` 那一行代码本身就变成真实判定，任何时候跑预审都用得到，不依赖教务归档模块是否已建）。
- 本卡必须完成：①毕业批次是否已ARCHIVED（或全部逐生终审完成可推进ARCHIVED）的检查；②`_check_archive` 真实判定函数替换现有UNKNOWN占位行。
- 明确不做：不在归档页发起毕业终审动作（终审走既有毕业资格审核模块）；不对接学籍档案馆纸质件核验。
- 仅学校能够决定的业务政策：ARCHIVE项判定阈值（见§16 U-02）。

## 6. 主流程、异常流程与状态机

本卡不持有独立归档状态机；但涉及对既有 `AaGraduationAuditBatch` 状态的**增量补齐**：

| 当前状态 | 动作 | 角色 | 前置条件 | 下一状态 | 非法操作/错误码 | 并发/幂等 | 通知/待办 | 审计 |
|---|---|---|---|---|---|---|---|---|
| PRECHECKED | 本卡新增：检测全部逐生结果为终态后自动推进 | 系统（教务归档检查触发，非用户手动点击） | 全部 `AaGraduationAuditResult.status` 属于 `{GRADUATED,COMPLETED,INCOMPLETE}` | ARCHIVED | 仍有非终态记录 → 不推进，计入本域缺项 | 幂等（重复检查不重复推进，已ARCHIVED直接跳过） | 无 | `AA_GRAD_AUDIT/BATCH_ARCHIVE_AUTO` |

**ARCHIVE项判定函数改造**（替换 `academic_affairs_graduation_service.py:108`）：

```
def _check_archive(db, s):
    from app.models import OrientationStudent, OrientationMaterial
    ori = db.scalars(select(OrientationStudent).where(
        OrientationStudent.tenant_id == _tid(), OrientationStudent.student_id == s.id,
        OrientationStudent.is_deleted.is_(False))).first()
    if not ori:
        return {"item": "ARCHIVE", "result": "UNKNOWN", "owner": "COUNSELOR",
                "evidence": "无迎新档案记录（非本系统线上迎新入学或数据未关联）"}
    mat = db.scalars(select(OrientationMaterial).where(
        OrientationMaterial.tenant_id == _tid(), OrientationMaterial.ori_student_id == ori.id,
        OrientationMaterial.material_type == "ARCHIVE", OrientationMaterial.is_deleted.is_(False)
        ).order_by(OrientationMaterial.id.desc())).first()
    if not mat:
        return {"item": "ARCHIVE", "result": "FAIL", "owner": "COUNSELOR", "evidence": "迎新纸质档案材料未提交"}
    # 判定阈值见 §16 U-02，此处按"APPROVED 才算 PASS"的默认口径实现，待用户确认后可能改为 UPLOADED 也算
    ok = mat.status == "APPROVED"
    return {"item": "ARCHIVE", "result": "PASS" if ok else "FAIL", "owner": "COUNSELOR",
            "evidence": f"迎新档案材料状态={mat.status}"}
```

（伪代码用于说明设计意图，实际实现需在施工时对齐既有代码风格与 `_check_domain_exists` 等函数的错误处理模式。）

## 9. 权限总控逐动作实例化

同二级总包§10模式；`_check_archive` 判定读取的 `t_orientation_material` 属迎新中心数据，本卡为**跨中心只读引用**，不新增迎新中心相关权限码，遵循教务中心文档关联索引"跨模块依赖只读边界"惯例（对照"学生主档只读"的既有先例）。

## 10. 敏感数据、安全与审计

`missingList` 含学生姓名学号（中敏），规则同其他域；`_check_archive` 内部读取迎新档案材料状态字段本身不含身份证等敏感原文（只读取 `status` 字段），不产生额外敏感面。

## 11. Excel、附件、通知、待办、统计和归档

Excel导出：需要。附件：不需要（材料本身归属迎新模块管理）。通知/待办：需要（未终审学生名单催办）。统计：需要（终审率）。打印/归档：并入统一确认单，同时是《毕业名单》正式打印物料的数据源。
