## 3. 真实业务结果与边界

- 使用角色/工作内容：教务处管理员/学院教务员核对本学期教学任务批次是否已全部确认到 `APPROVED` 终态，任务层面是否存在教师拒绝(`REJECTED_BY_TEACHER`)未处理的记录。
- 进入/退出条件：同前述卡。
- 上游输入：`t_aa_teaching_task_batch`/`t_aa_teaching_task`（只读，写操作走既有"教学任务"三级模块）。
- 下游输出：`AaArchiveItem(category='TEACHING_TASK')`。
- 本卡必须完成：批次状态非APPROVED判为缺项；任务状态为 `REJECTED_BY_TEACHER` 判为缺项（未重新分配）。
- 明确不做：不在归档页重新分配教师。
- 仅学校能够决定的业务政策：无。

## 6. 主流程、异常流程与状态机

本卡不持有独立状态机；R4合并升级为8态链后，本规则的"终态"定义（当前仅 `APPROVED`）需要回来复核是否需要纳入新增终态值，登记为 backlog（见二级总包§16），不阻断本次设计。
