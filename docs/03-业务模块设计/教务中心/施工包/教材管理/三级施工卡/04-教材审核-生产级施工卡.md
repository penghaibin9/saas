## 3. 真实业务结果与边界

- **该三级模块让哪类学校用户完成什么工作**：学院教务员/专业负责人对本院教材负责人提交的选用做初审，教材管理员（代表教务处）做终审，终审通过后经公示期备案，教材选用才能进入征订环节。
- **进入条件与退出条件**：进入条件=存在`t_aa_textbook_selection.status=SUBMITTED`的记录；退出条件=批次PUBLISHED（联动选用APPROVED，可被卡03征订消费）或批次被任一级RETURNED（联动选用RETURNED，回到卡02重新编辑）。
- **上游输入、下游输出和跨模块回写**：上游=卡02教材选用(SUBMITTED状态)；下游=卡02(状态回写APPROVED/RETURNED)、卡03教材征订(消费PUBLISHED批次对应的APPROVED选用)。
- **本卡必须完成**：生成审核批次(勾选待审选用)、学院初审(通过/退回)、教务终审(通过/退回)、公示期展示、备案(PUBLISHED)。
- **明确不做及理由**：不做真正的"教材选用委员会"多人投票/会议纪要系统（S1制度层要求是线下治理机制，系统只承接"发起-审核-备案"的数字化留痕，不做投票器/会议系统，超出R9范围）。
- **仅学校能够决定的业务政策**：公示时长是否固定3日还是可配置（C1证据显示的是该校自定的3日惯例，非全国统一标准，需学校确认是否采用3日默认值或自定义）。

**非技术验收步骤**：学院教务员登录 → 教材管理 → 教材审核 → 看到本院待审批次 → 查看批次内选用清单 → 点"通过"（二次确认），批次进入公示；教务处管理员在公示期满后登录同菜单 → 看到该批次"教务终审"按钮已可点（公示未满时按钮灰显+提示"公示中，剩余N天"） → 点"通过" → 公示期满后点"备案" → 批次状态变为"已备案"，对应教材选用变为"已通过"，可在教材征订环节看到。
