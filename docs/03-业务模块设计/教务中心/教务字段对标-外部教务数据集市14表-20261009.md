# 教务字段对标：外部教务数据集市 14+11 张表 vs 本系统教务中心（2026-10-09，已补全“教学管理”分类 21 张）

> 性质：**规划与记录文档**。本轮没有改任何代码、迁移和数据库。
> 来源：用户提供的某职业院校数据集市截图（部门“教务处”，供给库 UDW，共 14 张数据表）+ 全部字段清单（字母代码 + 中文名）。
> **更新（同日）**：按分类视图“教学管理数据集”共 21 张 = 教务处 10 张（已在第三节）+ 网络安全与信息技术中心 11 张（见第三B节）。文件名里的“14表”是首版遗留。
> 对照对象：`backend/app/models/` 下 `academic_affairs*.py`、`org.py`（t_college / t_major / t_class）、`national_standard.py`。
> 用途：后续改造「教务中心」时，决定补哪些字段、不补哪些字段、哪些要先问业务。

## 一、先说结论

1. 对方这 14 张表是学校**数据中台里的“教务基础数据”**，覆盖：基础资源（校区/教室/专业/班级）→ 培养方案 → 开课排课 → 选课 → 考务。**不含成绩、学籍异动、考勤、评教、教材征订**——这些不能用它当蓝本，本系统已做的部分比它更完整。
2. 本系统对应表结构大部分已有，**真正缺的主要是 5 类**：校区主表、课程/培养方案的学时与考核方式细分、教学班的开课说明与教学特征、教室的管理部门与总座位数、教学成果获奖（整块没有）。
3. 对方所有字段都是**国标式代码**（`KSFSDM` 这类 + 代码表）。本系统用英文枚举。建议**保持英文枚举不动**，将来若要和学校现有教务系统对接，再单独加“代码映射表”，不要把对方代码直接写进业务字段。
4. 对方每张表都有 `TSTAMP` 时间戳（共 14 个），本系统已有 `created_at/updated_at`，**全部不需要**，后文不再逐表列。

## 二、数据关系主线（对方）与本系统对应

```
校区(XQH) ─ 教学楼/教室(JXLH+JSH)
学院/单位(DWH) ─ 专业(ZYDM) ─ 专业方向(ZYFXH) ─ 班级(BJDM)
培养计划(JHBH) ─ 教学计划课程(JHBH+KCBH+学期) ─ 课程(KCH)
排课(PKBH，也是“选课课号”=教学班) ─ 任课教师 ─ 课表(上课时间/教室/周次)
选课(学号+教学班) ─ 学生课表
考试安排(KSBH) ─ 考场/监考/巡考/参考名单
```

| 对方 | 本系统 |
|---|---|
| 校区 | 无主表，仅各表有预留字符串 `campus_code` |
| 学院/专业/班级 | `t_college` / `t_major` / `t_class`，另有 `t_aa_major_direction` |
| 课程 | `t_aa_course`（版本链） |
| 培养计划 / 教学计划课程 | `t_aa_program` / `t_aa_program_course` |
| 排课（教学班） | `t_aa_teaching_task` + `t_aa_teaching_class`（+教师、名单版本、成员） |
| 课表 | `t_aa_schedule_item`（星期+节次+周次，结构化） |
| 选课 | `t_aa_selection_batch/round/course/record` |
| 考试安排 | `t_aa_exam_batch/course/room/room_student/invigilator/patrol` |
| 教室 / 教学楼 | `t_aa_classroom` / `t_aa_teaching_building` |
| 教学成果获奖 | **无** |

图例：✅已有　◐部分有/要调整　➕建议新增　⛔不需要　❓需你拍板（见第四节）

## 三B、后补：网络安全与信息技术中心提供的 11 张表（教学管理分类，ODS 库）

按分类“教学管理数据集”共 21 张 = 教务处 10 张（上文）+ 网络中心 11 张。网络中心这批更像从**教务系统原生库**同步，**字段带中文字典说明**，对我们定枚举很有用。11 张的字段数与截图核对一致。

### 字典参考（来自对方字段注释，可直接作为我们枚举的参考）
- 课程性质：公共基础课、专业基础课、专业课、专业方向课、公共选修课　→ 我们 `category`（公共基础/学科基础/专业核心/专业选修/集中实践）
- 课程属性：必修、限选、任选、公选　→ 我们 `nature`
- 课程类别：理论课（不含实践）、理论课（含实践）、实验(践)课　→ **我们缺**
