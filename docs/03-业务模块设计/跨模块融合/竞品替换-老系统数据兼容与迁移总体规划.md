## 一、背景与目标

`designSource=user_decision`（用户提出竞争策略方向）+ `ai_proposal`（拆解方式）

学校已经在用别家的学工/教务系统（常见：正方、青果、金智、强智或自建）。要抢下这类客户，换系统的最大阻力不是功能，而是三件事：

1. **历史数据搬不过来**：学籍、异动、成绩、处分、资助、住宿等历史记录是学校的"账本"，丢了无法向上级和学生交代；
2. **切换期风险**：开学、评奖、毕业审核等节点不能停摆；
3. **对账责任**：换系统后数字对不上，学校经办人要担责。

因此本规划的目标是把"换系统"做成对学校**低风险、可验收、有留痕**的动作：

- 历史数据经我方标准通道迁入，逐类对账清单全绿并留 SQL 执行记录；
- 每家竞品一套《迁移工具包》，实施周期和工作量可承诺、可报价；
- 迁移能力本身成为销售武器（"你的旧数据我们 N 天迁完，逐条对账"）。

## 三、总体策略：三条兼容通道，分层承诺

`designSource=project_rule`（通道划分沿用 13A-13B 裁定）

### 通道 1：Excel 半自动迁移（V1 唯一通道，销售主打）

```
老系统自带导出（xls/csv） → 按《映射对照表》转官方模板 → validate(dry-run) → 错误清零 → confirm → 逐类对账
```

- 不依赖竞品配合、不需要对方开数据库权限，**任何有"导出 Excel"功能的老系统都能迁**——这是对学校最容易解释、对我们风险最低的方案；
- 行级错误回执 + 整批事务回滚 + 批次留痕 + 对账清单，天然形成"可验收"的实施交付物；
- 身份匹配铁律：**一律以学号为身份键**，姓名仅作复核列；先迁组织三表与学生主档，再迁业务历史（依赖顺序见上位设计 §五）。

### 通道 2：并行共存期同步（P2，文件交换/中间库）

学校换系统常有一学期并行期（老系统跑毕业班、新系统跑新生）。此阶段按对接设计的**暂存区铁律**：外部数据必须先进 `t_integration_staging`，经校验和身份匹配后才进业务表，禁止直写。V1 不承诺此通道，销售侧只作为"有规划"表述。

### 通道 3：API 对接与开放接口（P3）

面向学校已有一卡通、迎新、财务等周边系统的长期共存，走 `t_external_system` + app_key/secret 验签轨。属集成开放中心范畴，不进本规划的近期承诺。

## 四、分期路线图

`designSource=ai_proposal`（分期切法待用户确认优先级）

### 第一期 P1「换系统可开学」——最小可抢单能力

目标：一所用竞品的学校，签约后 **2–4 周内**完成"组织+人+学籍+时间坐标"迁移，新学期直接在我方系统开学。

| 事项 | 内容 | 依托 |
|---|---|---|
| 1 | `DOMAINS` 注册项扩展为配置对象（管线不动，只加配置模块） | 上位设计 §1.2 |
| 2 | 注册教务时间坐标域：B1 学年学期 / B2 校历 / B3 作息 | 21 域清单 |
| 3 | 注册学籍域：B4 学籍名册初始化 / B5 异动历史 | 同上 |
| 4 | 注册高价值历史域：B10 历史成绩（落 `t_acad_grade` 唯一权威表） | 同上 |
| 5 | 每域官方 xlsx 模板 + 模板版本号 + 双表头兼容 | 上位设计 §1.3 |
| 6 | 逐域对账 SQL 落成脚本（可重复执行、输出差异清单） | 各域"对账清单" |

验收口径：在 sandbox 租户用一份仿真竞品导出数据完成 0→14 步依赖顺序中 [0][1][2][7][12] 的全链路，逐域对账全绿，历史数据零待办零工作流。

### 第二期 P2「历史完整」——学工+教务全量历史

- 注册其余 15 个域（学工 A1–A10、教务 B6–B9、B11），按依赖顺序图分批；
- 重复策略三档（ERROR/SKIP/OVERWRITE）与 `dupPolicy` 参数落地，OVERWRITE 强制审计；
- 前端在系统管理挂"历史数据迁移"工作台：选域→下模板→传文件→看错误→确认→看对账。

### 第三期 P3「共存与生态」

- `t_integration_staging` 暂存区 + 同步任务/错误表落地（Alembic 迁移）；
- 主数据权属矩阵生效（谁是权威源、同步方向、可否回写）；
- 开放 API 验签轨，按客户实际需求驱动，不预先全量开发。

## 五、商业配套：把迁移能力做成抢单武器

`designSource=ai_proposal`

每家目标竞品一套**《迁移工具包》**（放 `docs/07-部署运维交付与商业化/templates/migration/<厂商>/`，P1 期随施工产出）：

1. 字段映射对照表模板（竞品导出列 → 我方模板列，逐校填一份并归档）;
2. 数据清洗检查单（编码/日期/前导零/班级名/合并单元格等 10 类坑的处置步骤）;
3. 实施 SOP（导出→转换→dry-run→清错→confirm→对账 的角色分工与时间表）;
4. 对账验收单（逐域 SQL + 学校经办人签认位）;
5. 工作量与报价参考（按学生规模 × 迁移域数估算）。

销售话术锚点：**"旧系统只要能导出 Excel，历史数据我们就能迁；每一类数据交付对账清单，数字对不上不算完"**。四件套归档（原始导出、映射表、错误清单、confirm 回执）同时是我们的免责与验收证据。

`designSource=project_rule`（CLAUDE.md §5.1、§3.0）
