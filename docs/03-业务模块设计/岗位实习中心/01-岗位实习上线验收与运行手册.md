# 岗位实习上线验收与运行手册

本手册只覆盖当前仓库的岗位实习模块；学校政策、监管接口和微信主体资质仍须由学校确认后才能启用。

## 上线前门禁

1. 执行 `cd backend && alembic upgrade head`，确认唯一 head 为 `0050_internship_trusted_checkin`。
2. 设置生产环境：`APP_ENV=prod`、`DEBUG=false`、强 JWT 密钥、显式 CORS 白名单、`DB_ENABLED=true`；禁止启用 mock-login。
3. 小程序生产构建必须提供真实 `VITE_API_BASE_URL`，并在微信公众平台配置 HTTPS 合法域名。生产包强制禁用 mock，不能使用本地演示账号。
4. 导入每个岗位的经纬度和围栏半径；没有围栏的真实坐标打卡只会得到 `RECORDED`，不会被误标为正常。
5. 为每个在岗学生绑定有效指导教师用户。历史姓名关系可展示，但新建和调整必须走用户关系接口。

## 日常运行

- 请假逾期扫描由后端每六小时按活动租户执行；开关 `INTERNSHIP_OVERDUE_AUTO_SCAN` 默认为 `true`。扫描可重复执行，单个请假周期只生成一张未关闭的 `INT-R06` 风险单。
- 打卡写入使用服务端时间、每日唯一约束和 `idempotencyKey`。网络重试必须复用同一个键；设备风险只产生“待核实”异常，不能直接定性学生违规。
- 学生异常申诉必须有说明和已鉴权的文件；指导教师通过“合理”处理时申诉状态变为 `ACCEPTED`，其他处理变为 `REJECTED`，全过程保留审计。
- 申请、销假、规则版本和成绩配置均有审计记录。发现异常时先保全审计和附件，不直接改库修正状态。

## 合规边界

- 围栏、定位和设备标记仅用于风险提示与人工核验；不得以此自动处分、自动否定成绩或持续后台定位。
- 未经学校确认，不启用夜班、未成年人特殊岗位、跨省备案/监管报送、企业外部身份登录等政策功能；本系统不伪造“已上报”状态。
- 企业真实评价须使用已验证企业联系人或一次性、短时、绑定业务对象的令牌；教师代录必须标明来源，不能计入企业真实评价。

## 事故与回滚

1. 暂停发布和批量写入，保留请求 traceId、审计轨迹和附件元数据。
2. 对迁移异常，先备份数据库并使用 Alembic 的前一版本回退；不得手工删除业务记录。
3. 恢复后先跑岗位实习专项测试、PC 构建和小程序生产构建，再开放写入口。
