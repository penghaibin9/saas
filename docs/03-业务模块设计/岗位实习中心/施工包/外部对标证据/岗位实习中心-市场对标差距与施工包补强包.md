## 三、补强设计要点(逐 GAP 落包)

### GAP-01 监管红线合规引擎 `designSource=external_evidence(POL-03/04/05)`

新增**合规规则编码 REG-R 系列**(与 INT-R 风险系列并列,区别:INT-R 是过程风险,REG-R 是违规红线,等级默认 CRITICAL,触发即阻断或强制留痕上报):

| 编码 | 规则 | 触发点 | 动作 | 例外通道 |
|---|---|---|---|---|
| REG-R01 | 学生年龄<16周岁 | 名单导入/资格认定/分配 | **硬阻断**,不可豁免(童工红线) | 无 |
| REG-R02 | 学生<18周岁且无监护人知情同意书附件 | 上岗核验 | 阻断放行 | 补传后放行 |
| REG-R03 | 一年级学生进入岗位实习 | 资格认定 | 阻断 | 无 |
| REG-R04 | 岗位行业命中娱乐场所类(酒吧/夜总会/歌厅/洗浴/游戏厅/网吧) | 企业资质审核/岗位发布 | 阻断发布 | 无 |
| REG-R05 | 岗位专业大类与学生专业大类不一致 | 匹配/分配 | 警告+管理员强确认留痕 | 管理员书面理由 |
| REG-R06 | 协议报酬字段<同岗位工资80%口径 或 支付周期>1月 | 协议发起/三方确认 | 警告+留痕 | 学校政策确认(user_decision) |
| REG-R07 | 排班含夜班/法定节假日且批次未登记"特殊专业备案号" | 批次规则/打卡时段配置 | 阻断配置 | 批次登记主管部门备案号后放行 |
| REG-R08 | 疑似中介代理(同一企业联系人手机号横跨异常多企业等启发式) | 企业审核 | 风险单人工核 | — |

落地:规则清单存 `批次与规则` 新三级卡《合规红线规则》;执行点分散在既有 API 的服务层校验;全部触发写审计+可在风险处置台账筛 REG-R 前缀。**卖点提示:对手平台是"过程记录工具",合规引擎能把产品定位拉高到"校方免责证据链",这是招投标差异化项。**

### GAP-02 安全教育 `designSource=external_evidence(POL-01)+ai_proposal(形式)`

实习学生二级包新增三级卡《岗前安全教育》:教育材料下发(文档/视频)→学生确认阅读+答题(可选)→留痕(时间/时长/得分);上岗核验增加"安全教育完成"检查项(与 REG 系列同级门禁)。材料管理复用公共附件底座。

### GAP-03 实习报酬登记 `designSource=external_evidence(POL-04)`

协议实体增列:`salary_amount / salary_basis(同岗位80%|最低档|其他) / pay_cycle_days`;学生端月度可选登记"实际到手报酬"(user_decision:是否启用);REG-R06 消费该字段。**注意:报酬数据属敏感字段,按权限总控做脱敏+明文授权+审计。**

### GAP-04 省级备案与监管报送 `designSource=external_evidence(POL-02/05)+existing_code(导出底座)`

归档统计二级包新增三级卡《监管报送》:① 实习记录增加 `is_cross_province` 派生标记(企业地址省份≠学校省份);② 跨省实习须登记备案状态(未备案→REG 级预警);③ 月度《实习管理工作月报》《跨省实习统计表》Excel 一键导出(口径参照 GXY-UNI-01);④ 省级平台 API 对接留扩展位,V1 以标准 Excel 报送为主(各省平台接口不一,做接口是过度承诺)。

### GAP-05 打卡防作弊 `designSource=external_evidence(GXY-THREAT-01/XXY-CAP-01)+ai_proposal(具体机制)`

打卡与请假包补强,分三层:
1. **采集层**(小程序):`is_mock`(系统模拟定位标志)、`accuracy`、`device_id`(设备指纹)、可选拍照;原骨架冻结项保留——仅点击时采集、超范围可说明不直接定性。
2. **规则层**(后端):同一 device_id 多学生复用→风险;定位精度长期异常→风险;打卡时间规律性过强(秒级同刻)→疑似脚本;is_mock 命中→INT-R08。
3. **抽查层**(新增):**随机点名签到**——教师/系统在工作时段随机下发点名,学生 N 分钟内需完成定位(可选拍照)响应;这是对"定时脚本打卡"的针对性杀招,因为脚本无法预测随机时刻。此为对手平台被攻破后的差异化能力,建议做为可配置批次规则(频次/响应时限)。

### GAP-06 报告查重 `designSource=ai_proposal(阈值 user_decision)`

周报与任务包补强:提交时计算 ① 与本人历史报告相似度 ② 与同批次他人报告相似度(SimHash/MinHash 级即可,V1 不上大模型);超阈值标记"疑似复制"进教师批阅视图,不自动判罚。AI 代写检测不做硬判定(误伤率高),仅做"高风险提示"(user_decision:是否启用)。

### GAP-07 免实习/豁免 `designSource=external_evidence(GXY-CAP-01/GXY-UNI-01)`

实习学生包新增三级卡《免实习申请》:类型(参军入伍/升学/健康/其他)+材料+两级审批;通过后学生状态标记 EXEMPTED(状态机新增终态,与 TERMINATED 语义区分);成绩按学校政策记分(泉州样例:参军记 60 分,做成批次可配置项);统计口径中免实习单列。

### GAP-08 成绩四等次 `designSource=external_evidence(POL-03 第28/29条)`

评价与成绩包补强:五项分加权总分之上增加**四等次映射配置**(优/良/合格/不合格分数段,批次规则可配);成绩发布后回写学生学业档案接口位;`不合格` 联动:① 触发 INT-R17;② 向毕业资格模块(07)输出阻断标记。总分制与等次制并存,等次为对外法定口径。

### GAP-09 未成年人门禁 `designSource=external_evidence(POL-03 第14/15条)`

即 REG-R01/R02/R03 的实施——单列强调因为它是**唯一涉刑事责任**的红线(童工)。学生主档出生日期为必填校验源;知情同意书为附件类型枚举新增项,上岗核验清单硬依赖。

### GAP-10 企业端轻量门户 `designSource=external_evidence(GXY-CAP-01)+ai_proposal(H5 方案)`

不建企业 App。参照工学云"扫码"路径:评价与成绩包的企业评价三级卡补强为——系统对每个待评学生生成带签名 token 的 H5 评价链接/二维码→企业导师微信打开→免注册完成分项评价→留痕(openid/手机号验证码二选一,user_decision)。巡访/异常联系同理可复用该轻量通道。矩阵 #22 的"外部身份授权"以此为 V1 形态,完整企业门户后置。

### GAP-11 实习手册导出 `designSource=external_evidence(XYB-CAP-01)`

归档包补强:按学生一键导出《岗位实习手册》PDF/Word(封面+计划+协议摘要+考勤统计+周报精选+评价+成绩+鉴定),模板可配学校抬头;这是院系检查/评估时的高频刚需,校友邦已验证。

### GAP-12 指导频次口径 `designSource=external_evidence(GXY-UNI-01)`

批次 guidance 规则补样例口径:指导记录周一次、总次数≥N(泉州=24)、巡访须附照片;INT-R11 阈值直接读该规则,不另设死值。
