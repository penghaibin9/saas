## 2. TO-BE 目标设计

### 2.1 使用者

| 角色 | 用途 |
|---|---|
| 实习管理部门 | **唯一**可点「扫描超期」；全校实习范围处置（CONTACT/TO_RISK/CLOSE）与代销假 |
| 学校管理员 | 同实习部门（全校）；可 scan |
| 指导教师 | 本人指导学生：CONTACT 留痕、代销假；**不可** scan；TO_RISK/CLOSE 是否开放：**本卡定为指导教师 ALLOW CONTACT + 代销假；TO_RISK/CLOSE 仅院系及以上** |
| 院系负责人 | 本院系：CONTACT/TO_RISK/CLOSE/代销假；不可 scan |
| 学生 | 看到 OVERDUE 状态；走 08 申请销假；不可处置 |
| 企业导师 | DENY 全部 overdue 写操作与 scan |
| 平台运营 | DENY 校内明细写与 scan |
| 审计 | READ 超期台账与审计 |

### 2.2 场景

1. 定时任务或实习部门手动触发 `scan-overdue`：把「已通过且预期归岗日已过且未推送」标为 OVERDUE。  
2. 指导教师电话联系学生，点 CONTACT 留痕（状态仍 OVERDUE）。  
3. 持续失联：院系/部门 TO_RISK → 生成实习风险单，状态仍 OVERDUE（或保持 OVERDUE 并写 overdue_risk_id）。  
4. 已确认安全但无需走销假证明：CLOSE → CLOSED（终态）。  
5. 学生补办销假：08 RETURN_APPLY → WAIT_RETURN → CONFIRM → CLOSED。  
6. 教师代销假：08 RETURN_PROXY → WAIT_RETURN → CONFIRM。

### 2.3 前置

- `expected_return_date` 已有值（APPROVE 时写入；历史回填）。  
- scan：操作者角色∈{实习管理部门, 学校管理员} + `internship.leave.overdue.scan`。  
- handle：数据范围内 + 对应 handleType 权限。  
- 租户模块实习已启用。

### 2.4 正常流程

```
APPROVED ∧ expected_return_date < today ∧ overdue_pushed_at IS NULL
  →(scan-overdue) OVERDUE
  写 overdue_at=now, overdue_pushed_at=now；audit OVERDUE_SCAN；version++

OVERDUE →(overdue-handle CONTACT) OVERDUE
  写 overdue_handle_*；audit OVERDUE_CONTACT

OVERDUE →(overdue-handle TO_RISK) OVERDUE
  创建 RiskRecord(risk_code=INT-LEAVE-OVERDUE, internship_id=..., title含学号姓名超期未归)；
  overdue_risk_id=新风险id；audit OVERDUE_TO_RISK；幂等：已有 overdue_risk_id 则不重复建单

OVERDUE →(overdue-handle CLOSE) CLOSED
  audit OVERDUE_CLOSE；不强制裁剪 LEAVE（与销假确认不同：CLOSE 表示处置关闭；
  **本卡规则**：CLOSE 时同样执行「未来日 LEAVE soft-delete；已过去日保留」，actual_return_date 默认=今天，可请求体覆盖）
```

### 2.5 拒绝/异常

| 情况 | 错误码 |
|---|---|
| 非 APPROVED 被误 handle | DATA_CONFLICT |
| 教师调 scan | NO_PERMISSION |
| 企业导师 TO_RISK | NO_PERMISSION |
| handleType 非法 | VALIDATION_ERROR |
| CLOSE 无 note（本卡要求 CLOSE note≥5字） | VALIDATION_ERROR |
| 跨租户 | NOT_FOUND |
| WAIT_RETURN 被 scan | 跳过（不改状态） |
| 重复 scan 同单 | 幂等跳过（count 不加） |

### 2.6 跨模块联动

| 联动 | 说明 |
|---|---|
| → 08 销假 | OVERDUE 可 return-apply / return-proxy |
| → 风险处置 | TO_RISK 进 `t_risk_record`；离岗异常面板可后续按 risk_code 筛选（不在本卡改 exceptions） |
| → 打卡 | CLOSE/销假确认均裁剪未来 LEAVE |
| ✕ 学工 | 零联动 |

### 2.7 完成结果

- PC：`/admin/internship/leaves?panel=overdue` 列表 status=OVERDUE；扫描+处置+代销假可用。  
- nav 超期未归不再指向 exceptions。  
- 测试 `test_internship_leave_overdue.py` 全绿。  
- 与 08 交叉用例双方测试文件均覆盖。

## 5. API 契约

### 5.1 POST `/api/v1/internship/leaves/scan-overdue` — **new**

| 项 | 内容 |
|---|---|
| 方法 | POST |

### 5.2 POST `/api/v1/internship/leaves/{id}/overdue-handle` — **new**

| 项 | 内容 |
|---|---|
| permission key | 按 handleType：`internship.leave.overdue.contact` / `internship.leave.overdue.to_risk` / `internship.leave.overdue.close` |
| 数据范围 | `_rec_in_scope` |

## 6. 数据库和迁移

与 08 卡 §6 **完全一致**的字段清单（此处展开便于单卡编码，不省略）：

| 列名 | 类型 | 本卡用途 |
|---|---|---|
| expected_return_date | VARCHAR(10) | scan 比较基准 |
| actual_return_date | VARCHAR(10) | CLOSE/销假写入 |
| return_proof_file_id / return_note / return_applied_at / return_applied_by_name / return_proxy_flag / return_proxy_by_name / return_confirm_at / return_confirm_by_name / return_reject_reason | 见 08 | 交叉销假 |
| overdue_at | DATETIME | 首次超期 |
| overdue_pushed_at | DATETIME | scan 幂等 |
| overdue_handle_type | VARCHAR(20) | CONTACT/TO_RISK/CLOSE |
| overdue_handle_note | VARCHAR(500) | 处置说明 |
| overdue_handle_at | DATETIME | 处置时间 |
| overdue_handle_by_name | VARCHAR(50) | 处置人 |
| overdue_risk_id | BIGINT | 风险单 id |

迁移策略：

1. 与 08 **共用** `00xx_internship_leave_return_overdue.py`。  
2. upgrade：加列 + 回填 `expected_return_date=end_date` WHERE status='APPROVED'。  
3. downgrade：drop 新列。  
4. **不**新建学工同名表。  
5. `tenant_id` 过滤所有查询；`version` 乐观锁。  
6. RiskRecord 使用既有表，不改表结构（仅插入行）。

索引（可选增强）：`(tenant_id, status, expected_return_date)` 加速 scan——若加索引入同一迁移，命名 `ix_t_internship_leave_scan`。
