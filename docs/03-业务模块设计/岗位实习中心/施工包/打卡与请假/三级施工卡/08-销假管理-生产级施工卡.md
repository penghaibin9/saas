## 1. AS-IS 真实实现

### 1.1 结论（必须先读）

**实习域销假能力完全缺失。** navPlan 为「销假管理」挂了假入口；后端 `InternshipLeave` 仅四态；`internship_leave_service` 无 return/overdue 符号。学工销假仅作**隔离对照**，**禁止复用、禁止调用、禁止共享表与状态枚举**。

## 2. TO-BE 目标设计

### 2.1 使用者

| 角色 | 本卡用途 |
|---|---|
| 学生（移动端） | 请假已通过或已超期后，提交销假申请（实际归岗日、说明、证明附件） |
| 指导教师 | 对本指导学生：确认销假、退回销假、代销假 |
| 院系负责人 | 本院系范围：确认/退回/代销假 |
| 实习管理部门 | 全校实习范围：确认/退回/代销假；与超期处置协同 |
| 学校管理员 | 全校范围同上（管理兜底） |
| 企业导师 | **DENY** 销假写操作与待销假队列（仅可看本企业关联学生只读列表若已有 leave.view；本卡写动作一律 DENY） |
| 平台运营 | **DENY** 校内销假明细写操作 |
| 审计人员 | 只读查看销假留痕与附件元数据 |

### 2.2 业务场景

1. 学生请假审批通过（`APPROVED`），按计划结束日 `end_date` 回填 `expected_return_date`；学生返岗前/当日在小程序点「申请销假」。
2. 指导教师在 PC「销假管理」面板（`?panel=return`）看到 `WAIT_RETURN` 队列，核对证明后确认或退回。
3. 学生无法操作时，指导教师/院系/实习部门代销假（proxy）→ 直接进入 `WAIT_RETURN`（或配置为代销假后仍须确认：本卡定为 **代销假进入 WAIT_RETURN，仍须确认销假**，与学生自申同队列）。
4. 已超期（`OVERDUE`，由 09 卡扫描产生）仍可申请销假或被代销假，确认后 `CLOSED`。

### 2.3 前置条件

- 租户已启用 `module.internship.enabled`。
- 存在有效 `InternshipRecord`，请假单 `tenant_id` 匹配。
- 销假申请：当前状态 ∈ `{APPROVED, OVERDUE}`；申请人=请假学生本人。
- 确认/退回/代销假：操作者数据范围内且具备对应 permission key；乐观锁 `version` 匹配。
- 模块授权与菜单 `in-attendance-leave` 对当前角色可见（写操作另验 button key）。

### 2.4 正常流程

```
APPROVED 或 OVERDUE
  →(学生 return-apply | 教师/部门 return-proxy) WAIT_RETURN
  →(教师/院系/部门 return-confirm CONFIRM) CLOSED
副作用：
  - 写 return_* 字段；version++
  - InternshipAuditTrail：RETURN_APPLY / RETURN_PROXY / RETURN_CONFIRM
  - 对 t_internship_checkin：result=LEAVE 且 checkin_date > actual_return_date 的行 soft-delete（is_deleted=1）；checkin_date ≤ actual_return_date 的 LEAVE 行保留
  - 若来自 OVERDUE：清除未关闭的超期待办语义（本卡在 leave 行写 overdue_closed_by_return=true 语义字段可用 overdue_handle_type 置空并记 audit）；不调用学工 todo
```

### 2.5 拒绝/退回流程

```
WAIT_RETURN →(return-confirm action=REJECT，原因≥5字) 
  → 若 expected_return_date < 今天：OVERDUE
  → 否则：APPROVED
副作用：清空本次 return_proof_file_id/return_note 申请态或标记 return_reject_reason；允许再次申请销假；审计 RETURN_REJECT
```

### 2.6 异常流程

| 异常 | 处理 | 错误码 |
|---|---|---|
| 状态非 APPROVED/OVERDUE 却申请销假 | 拒绝 | `DATA_CONFLICT` |
| 非本人申请 | 拒绝 | `NO_PERMISSION` |
| 证明附件 file_id 无效 | 拒绝 | `VALIDATION_ERROR` |
| actualReturnDate 早于 start_date 或晚于今天+1（允许当日） | 拒绝 | `VALIDATION_ERROR` |
| 并发双确认 | 第二请求失败 | `DATA_CONFLICT` |
| 跨租户 id | 404 语义 | `FORBIDDEN_CROSS_TENANT` 或 `NOT_FOUND`（统一对外 `NOT_FOUND`，审计记跨租户试探） |
| 企业导师调确认接口 | 拒绝 | `NO_PERMISSION` |
| 重复 WAIT_RETURN 再申请 | 拒绝 | `DATA_CONFLICT` |

### 2.7 跨模块联动

| 方向 | 联动 | 落点 |
|---|---|---|
| 上游 | 07 请假审批 APPROVE | `_write_leave_checkins` 已写 LEAVE；本卡确认时裁剪未来 LEAVE |
| 上游 | 09 超期未归 | OVERDUE 可进入销假；确认 CLOSED 后离开超期池 |
| 下游 | 打卡台账 | 未来日不再显示请假；过去日保留请假留痕 |
| 下游 | 风险（可选） | 本卡确认不自动关风险单；若 09 已 TO_RISK，由风险模块人工关闭（本卡 audit 记 leaveId） |
| 禁止 | 学工 360/家校/CsLeave | 零写入 |

### 2.8 完成结果

- PC `/admin/internship/leaves?panel=return` 可筛 `WAIT_RETURN` 并完成确认/退回/代销假。
- 移动端请假详情可「申请销假」。
- DB：`t_internship_leave` 新字段有值；状态可达 `CLOSED`。
- 自动化测试 `test_internship_leave_return.py` 覆盖正反向/越权/并发/LEAVE soft-delete。
- nav 销假管理深链改为 `'/admin/internship/leaves?panel=return'`（修改 navPlan 该行，不改其它中心）。

## 4. 状态机表

实习请假状态全集（本卡+09+既有）：

`PENDING | APPROVED | REJECTED | WITHDRAWN | WAIT_RETURN | OVERDUE | CLOSED`

### 4.1 本卡转移表

| 当前 | 动作 | 操作者 | 前置 | 下一 | 副作用 | 失败码 |
|---|---|---|---|---|---|---|
| APPROVED | RETURN_APPLY | 学生本人 | 无进行中 WAIT_RETURN；证明有效 | WAIT_RETURN | 写 actual_return_date/return_*；audit RETURN_APPLY | VALIDATION_ERROR / DATA_CONFLICT / NO_PERMISSION / NOT_FOUND |
| OVERDUE | RETURN_APPLY | 学生本人 | 同上 | WAIT_RETURN | 同上 | 同上 |
| APPROVED | RETURN_PROXY | 指导教师/院系/实习部门/学校管理员 | 数据范围+proxy 权 | WAIT_RETURN | return_proxy_flag=true；audit RETURN_PROXY | NO_PERMISSION / DATA_CONFLICT / VALIDATION_ERROR |
| OVERDUE | RETURN_PROXY | 同上 | 同上 | WAIT_RETURN | 同上 | 同上 |
| WAIT_RETURN | RETURN_CONFIRM | 指导教师/院系/实习部门/学校管理员 | version 匹配；confirm 权 | CLOSED | 裁剪未来 LEAVE；audit RETURN_CONFIRM | DATA_CONFLICT / NO_PERMISSION |
| WAIT_RETURN | RETURN_REJECT | 同上 | reject 权；reason≥5 | APPROVED 或 OVERDUE | 按 expected_return_date 与今天比较；audit RETURN_REJECT | VALIDATION_ERROR / DATA_CONFLICT |
| PENDING | RETURN_* | 任意 | — | — | 禁止 | DATA_CONFLICT |
| REJECTED/WITHDRAWN/CLOSED | RETURN_* | 任意 | — | — | 禁止 | DATA_CONFLICT |
| WAIT_RETURN | RETURN_APPLY | 学生 | — | — | 禁止重复 | DATA_CONFLICT |

### 4.2 与 09 交叉（编码必须实现）

| 场景 | 规则 |
|---|---|
| OVERDUE 学生销假 | 允许 RETURN_APPLY → WAIT_RETURN |
| WAIT_RETURN 期间扫描超期 | **不得**把 WAIT_RETURN 改成 OVERDUE（scan 仅命中 APPROVED） |
| CLOSED 后扫描 | 跳过 |
| OVERDUE 处置 CLOSE（09） | 可直接 CLOSED 且不经 WAIT_RETURN；与本卡确认等价终态，但 audit action 不同（`OVERDUE_CLOSE` vs `RETURN_CONFIRM`） |

### 4.3 APPROVE 时写 expected_return_date（modify review）

`review(APPROVE)` 成功时：`expected_return_date = end_date`（YYYY-MM-DD）。历史 APPROVED 行由迁移回填 `expected_return_date=end_date`。

## 5. API 契约

统一前缀：管理端 `/api/v1/internship`；移动端 `/api/v1/mobile/internship`。

### 5.1 GET `/api/v1/internship/leaves` — **modify**

| 项 | 内容 |
|---|---|
| 方法 | GET |
| permission key | `internship.leave.view` |
| 数据范围 | `_current_scope` / `_rec_in_scope`（与现 list_leaves 一致） |
| Query | `page,pageSize,status,keyword`；**新增支持** status=`WAIT_RETURN`/`OVERDUE`/`CLOSED` |

| 幂等 | 是（读） |
| 审计 | 不写（列表） |
| 变更类型 | **modify** |

item 增补示例字段：

```json
{
  "id": "1001",
```

## 7. 权限实例化矩阵

图例：ALLOW=允许；DENY=明确拒绝；READ=只读。

| 业务动作 | permission key | 学生 | 企业导师 | 指导教师 | 院系负责人 | 实习管理部门 | 学校管理员 | 平台运营 | 审计人员 |
|---|---|---|---|---|---|---|---|---|---|
| 菜单可见销假面板 | `internship.leave.view` | DENY(PC) | READ* | ALLOW | ALLOW | ALLOW | ALLOW | DENY | READ |
| 移动申请销假 | （本人会话） | ALLOW | DENY | DENY | DENY | DENY | DENY | DENY | DENY |
| 确认销假 | `internship.leave.return.confirm` | DENY | DENY | ALLOW(owner) | ALLOW(本院系) | ALLOW(全校实习) | ALLOW | DENY | DENY |
| 退回销假 | `internship.leave.return.reject` | DENY | DENY | ALLOW(owner) | ALLOW(本院系) | ALLOW | ALLOW | DENY | DENY |
| 代销假 | `internship.leave.return.proxy` | DENY | DENY | ALLOW(owner) | ALLOW(本院系) | ALLOW | ALLOW | DENY | DENY |
| 导出含销假 | `internship.leave.export` | DENY | DENY | ALLOW | ALLOW | ALLOW | ALLOW | DENY | READ |
| 查看明文附件 | 文件中心授权 + leave.view | 本人 | DENY | ALLOW | ALLOW | ALLOW | ALLOW | DENY | READ+水印 |

\*企业导师：若已有 leave.view 且数据范围=本企业关联学生，仅 READ 列表/详情；**所有 return.* 写 key = DENY**。  
越权统一：`NO_PERMISSION`；跨租户：`NOT_FOUND`（内部记 `FORBIDDEN_CROSS_TENANT`）。

种子/权限配置：在系统权限初始化中登记上述 new keys，绑定到指导教师/院系/实习部门/学校管理员角色模板；企业导师与学生模板不授 return.*。
