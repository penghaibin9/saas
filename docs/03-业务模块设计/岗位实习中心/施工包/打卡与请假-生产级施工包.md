## 1. 模块目标、业务价值和边界

### 1.1 解决的真实问题

把岗位实习期间「每日打卡 → 缺卡/异常发现 → 补卡审批 → 请假覆盖考勤 → 销假闭环 → 超期未归处置」做成可留痕、可审批、可统计、可审计、可下钻的全过程考勤闭环，支撑《职业学校学生实习管理规定》信息化全过程管理与安全监管要求（INTERNSHIP-POL-01）。

### 1.2 业务价值

| 价值点 | 说明 | designSource |
|---|---|---|
| 过程可视 | 指导教师/院系/实习部门按数据范围看到打卡、请假、异常 | external_evidence（XYB-CAP-01 签到；XXY-CAP-01 签到/请假变更；CX-ADOPT-01 考勤） |
| 缺卡可处置 | 日终扫描缺卡、连续未打卡面板、异常处理转风险 | project_rule + existing_code |
| 请假不误判缺卡 | 审批通过后按区间幂等写 `result=LEAVE` 打卡留痕 | existing_code（`internship_leave_service._write_leave_checkins`） |
| 销假/超期闭环 | APPROVED→WAIT_RETURN→CLOSED；超期 OVERDUE 可联系/转风险/关闭 | industry_rule(POL) + project_rule + ai_proposal（厂商菜单证据不能直接证明销假/超期未归） |
| 与学工请假隔离 | 实习域表/状态/服务独立，避免跨中心状态污染 | project_rule |

### 1.3 边界（必须遵守）

| 边界 | 纳入 | 不纳入 |
|---|---|---|
| 数据表 | `t_internship_checkin`、`t_attendance_exception`、`t_internship_makeup`、`t_internship_leave`、`t_internship_audit_trail` | `t_cs_leave`、学工销假子表、新建销假子表 |
| 服务 | `internship_leave_service`、`internship_makeup_service`、`internship_service`（checkin/exception） | `affairs_leave_service` |
| 风险 | 异常/超期处置可创建风险单（INT-R06 类），不改请假终态以外的业务主档 | 不重建风险处置二级模块状态机 |
| 成绩 | 打卡率可被成绩权重读取（只读聚合） | 本模块不核算/发布成绩 |
| 企业导师 | 本企业关联学生只读打卡/请假摘要 | 默认 DENY 销假确认与超期处置 |
| 平台运营 | 模块授权与租户配置 | DENY 学生考勤明细 |

### 1.4 购买/管理部门

学校实习管理部门（教务处实践教学科/就业处实习办等，具体处室由学校组织架构决定，不编造校名）。使用侧主力为指导教师、院系负责人、学生（小程序）。

### 4.3 证据缺口与设计来源声明（销假 / 超期未归）

共享库**不能直接证明**厂商「销假管理」「超期未归」独立菜单或状态名。这两项正式设计来源为：

- `industry_rule`：INTERNSHIP-POL-01 全过程管理与安全闭环义务；  
- `project_rule`：生产级安全闭环（请假结束必须销假确认，超期必须可处置）；  
- `ai_proposal`：本项目独立销假/超期设计（状态 WAIT_RETURN/CLOSED/OVERDUE），**对标学工能力思路但表与状态隔离**，不调用 `affairs_leave_service`、不写 `t_cs_leave`、不使用 `WAIT_CANCEL_LEAVE`。

不得把上述三项写成「三家厂商均有销假菜单」。

## 8. 完整业务主流程

### 8.1 打卡主链

1. 学生小程序对 ACTIVE/ONBOARD 实习记录发起每日打卡 → `POST /mobile/internship/checkin` → 写 `t_internship_checkin`（一天一次，唯一约束兜底）。  
2. PC 指导教师/管理部门按范围 `GET /internship/checkins` 查看；可 `POST /checkins/export`。  

### 8.2 缺卡与连续未打卡

1. 日终或手动 `POST /internship/exceptions/scan-missing`：对 ACTIVE 实习记录，若当日无 checkin 且无 APPROVED/WAIT_RETURN/OVERDUE 覆盖的 LEAVE 日 → 创建或更新 `AttendanceException` type=MISSING，计算 `streak_days`。  
2. `streak_days >= checkin.streakThreshold`（默认 3）进入「连续未打卡」面板（`GET /exceptions?type=MISSING&minStreak=N`）。  
3. 教师/部门 `handle` 或 `batch-handle`：REASONABLE / ABNORMAL / TO_RISK（意见≥5 字；TO_RISK 创建风险单）。  

### 8.3 补卡

1. 学生对缺卡日 `POST /mobile/internship/makeup` → PENDING。  
2. 可 `withdraw` → WITHDRAWN。  
3. 指导教师 `approve` → 补写打卡；`reject` → REJECTED（原因≥5 字）。  
4. PC `panel=makeup-apply` 只读查看申请台账；审批在 makeups tab。  

### 8.4 请假 → 销假 → 关闭

1. 学生 `POST /mobile/internship/leave` → PENDING（可附 file_id）。  
2. 指导教师/院系/实习部门 `POST /leaves/{id}/review` APPROVE → APPROVED，并 `_write_leave_checkins` 按区间幂等写 result=LEAVE；REJECT → REJECTED。  
3. 学生可在 PENDING `withdraw` → WITHDRAWN。  
4. 学生 `POST /mobile/internship/leave/{id}/return-apply` 或教师 `POST /leaves/{id}/return-proxy` → WAIT_RETURN（写 actual_return_date/proof 等）。  
5. 教师/院系/部门 `POST /leaves/{id}/return-confirm` action=CONFIRM → CLOSED；未来日 LEAVE soft-delete，已过去日保留。  

### 8.5 超期未归

1. `POST /internship/leaves/scan-overdue`：APPROVED 且 today>end_date → OVERDUE（写 overdue_at）。  
2. OVERDUE 可 return-apply/proxy → WAIT_RETURN；或 overdue-handle：CLOSE→CLOSED；TO_RISK→保持 OVERDUE 并建风险单；CONTACT→保持 OVERDUE 仅留痕。

## 10. 跨三级模块状态机

### 10.1 补卡状态机（KEEP）

| 当前 | 动作 | 操作者 | 下一状态 | 副作用 |
|---|---|---|---|---|
| （无） | apply | 学生本人 | PENDING | 写 makeup |
| PENDING | withdraw | 学生本人 | WITHDRAWN | 无 |
| PENDING | approve | 指导教师（owner） | APPROVED | 补写 checkin |
| PENDING | reject | 指导教师 | REJECTED | 写原因 |

### 10.2 异常状态机（STRENGTHEN）

| 当前 | 动作 | 操作者 | 下一状态 | 副作用 |
|---|---|---|---|---|
| （无） | scan_missing | 系统/实习部门 | PENDING_HANDLE | 创建/更新 MISSING，算 streak_days |
| PENDING_HANDLE | handle / batch-handle | 教师/院系/部门 | COMPLETED | REASONABLE/ABNORMAL/TO_RISK；TO_RISK 建风险单 |

### 10.3 请假状态机（扩展，实习域独立）

| 当前 | 动作 | 操作者 | 下一状态 | 副作用 |
|---|---|---|---|---|
| （无） | apply | 学生本人 | PENDING | 写 leave |
| PENDING | approve | 指导教师/院系/实习部门 | APPROVED | 按区间幂等写 checkin result=LEAVE |
| PENDING | reject | 同上 | REJECTED | 无 |
| PENDING | withdraw | 学生本人 | WITHDRAWN | 无 |
| APPROVED | return_apply | 学生本人 | WAIT_RETURN | 写 actual_return_date/proof/return_requested_* |
| APPROVED | return_proxy | 指导教师/院系 | WAIT_RETURN | 代销申请 |
| WAIT_RETURN | return_confirm | 指导教师/院系/实习部门 | CLOSED | 未来日 LEAVE soft-delete；已过去日保留 |
| WAIT_RETURN | return_reject | 同上 | APPROVED；若已过 end_date 则 OVERDUE | 退回证明；写 return_confirm_action=REJECT |
| APPROVED | scan_overdue | 系统/实习部门 | OVERDUE | today&gt;end_date 且未 CLOSED/WAIT_RETURN |
| WAIT_RETURN | scan_overdue | 系统 | **保持 WAIT_RETURN** | 不转 OVERDUE |
| OVERDUE | return_apply / return_proxy | 学生/教师 | WAIT_RETURN | — |
| OVERDUE | overdue_handle CLOSE | 指导教师/实习部门 | CLOSED | — |
| OVERDUE | overdue_handle TO_RISK | 同上 | OVERDUE 保持 | 创建风险单 INT-R06 类，不改请假态 |
| OVERDUE | overdue_handle CONTACT | 同上 | OVERDUE 保持 | 仅留痕 |

终态：REJECTED、WITHDRAWN、CLOSED。OVERDUE 为可再进入销假的异常态，非终态。

### 10.4 打卡 result 与请假联动

- APPROVE 请假：区间内无打卡则插入 `result=LEAVE`；已有打卡则跳过（幂等）。  
- CONFIRM 销假：`checkin_date > actual_return_date`（未来日）的 LEAVE 行 `is_deleted=1`；`checkin_date <= actual_return_date` 保留。

### 14.3 status 列取值（施工后）

`PENDING` / `APPROVED` / `REJECTED` / `WITHDRAWN` / `WAIT_RETURN` / `CLOSED` / `OVERDUE`。

### 14.4 checkin.result

业务写入值：`RECORDED` / `NORMAL` / `OUT_OF_RANGE` / `NO_LOCATION` / `LEAVE`。model comment 与迁移注释同步包含 LEAVE。

## 25. 非技术验收

1. 学生小程序能打卡；教师 PC 能看到该生打卡记录。  
2. 故意缺卡后，管理员触发缺卡扫描，异常列表出现缺卡；连续≥3 天出现在连续未打卡视图。  
3. 学生补卡 → 教师通过 → 打卡台账出现补录。  
4. 学生请假 → 教师通过 → 请假日显示请假而非缺卡。  
5. 学生申请销假 → 教师确认 → 请假单已销假；未到日期可再打卡。  
6. 将结束日改到过去（测试环境）触发超期扫描 → 超期未归列表可见 → 教师可「已联系/转风险/关闭」。  
7. 企业导师账号（若有）不能点销假确认。  
8. 导出均为 Excel，能打开且人数与列表一致。  
9. 学工「请假销假」菜单与实习请假数据互不影响。
