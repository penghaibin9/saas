## 先审计：证据与结论

1. **工作入口：正文缺失。** 实际打开原稿的岗位实习中心，今日工作台正文是“此区域保留原业务页面内容”的占位卡，无批次、待办或办理动作。底部默认快捷项仍是学工事项。截图：`artifacts/internship-ui-audit/01-reference-workbench.jpg`。
2. **批次准备：只能切换菜单。** 点击批次与学生→批次管理后，标签与高亮正确，正文仍为空白示例。当前流程无法由此创建批次、核对名单、审查资格。截图：`artifacts/internship-ui-audit/02-reference-batches.jpg`。
3. **落岗路径被分散。** 原稿与 `frontend/src/config/navPlan.js` 实际代码均有 11 个二级模块。选岗匹配、申请协议、保险核验和上岗合规分属不同模块，用户需要自己拼接上岗前置条件。新菜单应按办理任务组织，状态和审批动作仍由原页面承载。
4. **过程与变更的归属不顺。** 考勤、报告、巡访是持续监管的并行任务；调岗退岗当前置于选岗匹配，应与在岗风险、异常处置衔接。不是把所有学生强制经过风险阶段。
5. **现有 Vue 工作台跳转不准确。** `InternshipDashboardView.vue` 中“查看全部工作队列”指向 `/admin/internship/risk-disposal`，只覆盖风险；`workflowStages`、`openWorkItem` 和部分风险跳转未统一合入当前 `batchId`。
6. **菜单和权限口径存在差异。** 示例：批次菜单使用 `internship.batch.view`，批次列表路由要求 `internship.batch.manage`；保险菜单要求 verify、路由要求 view；部分查看页面菜单使用写权限。这会让只读角色找不到页面，或点击可见入口后被路由拒绝。菜单整理必须核对真实后端权限，不得以隐藏菜单代替后端校验。
7. **无障碍与视口。** 原稿菜单具备完整可访问名称和当前页状态；两字窄栏对新用户辨识不足，应保留完整名称展开。窄屏必须仍能访问二、三级菜单。现有原稿截图不构成读屏、键盘或 WCAG 全面合规证明。

## 核心流程与已实施菜单

业务主线：批次与名单准备 → 企业岗位准备 → 申请、匹配、导师与协议 → 上岗条件核验 → 考勤、报告、指导 → 评价与成绩 → 材料归档与就业衔接。
风险和调岗退岗属于持续监管的旁路，处理后返回在岗流程，不能当作每个学生都必须完成的线性步骤。

| 二级工作区 | 三级入口 | 业务目的 |
|---|---|---|
| 今日工作 | 待办与进度 | 先看本人可处理对象，再进入所属业务队列 |
| 批次与学生 | 批次管理、学生名单、资格认定 | 确定周期、人员范围及参与资格 |
| 企业与岗位 | 企业库、岗位库、招聘与邀请、企业准入 | 准备合格企业与可用岗位 |
| 申请与落岗 | 申请审核、岗位匹配、导师分配、三方协议、保险核验、上岗核验、分配记录 | 将上岗前置条件放在同一工作区 |
| 实习过程 | 考勤记录、异常核验、请假与返岗、计划任务、报告批阅、指导巡访、指导计划 | 持续记录并处理实习过程 |
| 风险与变更 | 风险预警、风险处置、调岗退岗、事故与应急 | 处理旁路问题并回到主流程 |
| 评价与成绩 | 企业评价、学生与教师评价、综合成绩、成绩申诉 | 完成多方评价、核算和异议处理 |
| 归档与分析 | 材料归档、实习统计、就业衔接 | 核对结项事实、保存材料、衔接就业 |

保留已有业务路径、状态参数、旧地址、接口和动作权限。菜单短名称只用于窄栏，完整名称用于展开、搜索、标题和辅助技术。批次切换不跨用上一批次的对象详情。

## 已实施的前端改动

- 在独立 worktree 内，将截图对应的横向一级菜单、独立二/三级栏、页签、浮动快捷栏、可展开日期日历接到现有 Vue 实习模块。样式限定在岗位实习布局，继续复用实际业务页面和接口。
- 菜单从 11 个工作区整理为 8 个，保留 33 个日常入口及原有 100 条能力路径；隐藏详情和旧参数链接仍可访问。二/三级菜单按真实权限投影，参数变化不影响所属菜单的高亮。
- 今日工作先给出办理流程和对象待办，支持风险、考勤、报告筛选；“查看全部”进入对应业务队列。操作日志改为实习分配日志；新增批次进入新建页。
- 页签与快捷入口携带当前批次。切换批次时清除旧对象、分页和队列参数；详情回到对应列表。打开某个批次的详情时，工作批次同步为该对象的批次。
- 快捷栏按身份上下文保存常用页面，刷新后保留；只展示当前仍被授权的入口。页签不保存表单数据，关闭当前页继续经过现有未保存保护。
- 批次列表和详情采用后端已有的查看权限；编辑、结束、归档、作废、冻结名单继续要求管理权限，导出单独要求导出权限。补齐了列表和详情原本缺少的只读按钮状态。
