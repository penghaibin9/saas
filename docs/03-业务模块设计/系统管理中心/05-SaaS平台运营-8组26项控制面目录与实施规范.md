# SaaS 平台运营：8 组 26 项控制面目录与实施规范

## 1. 平台定位

平台运营端是 SaaS **控制面**，负责跨学校的租户、产品授权、交付、运行、安全和客户成功。它不是学校业务后台的放大版：平台人员默认不进入学校学生、成绩、心理、资助等业务数据。

学校后台负责本校组织、账号、角色和业务配置；平台后台负责学校是否存在、购买什么、何时开通、是否健康、是否续费以及平台如何安全服务该学校。

## 2. 8 组 26 项三级能力

| 组别 | 三级能力 |
|---|---|
| 平台总控 | 1. 平台经营总览；2. 租户生命周期看板；3. 告警与事件中心 |
| 租户生命周期 | 4. 租户学校；5. 试用与线索；6. 开通、停用与归档；7. 学校联系人与平台主管理员 |
| 产品、合同与授权 | 8. 产品与增值能力；9. 套餐与价格版本；10. 合同、订单与续费；11. 租户授权、配额与到期策略 |
| 自动交付 | 12. 初始化模板；13. 自动开通任务；14. 学校上线检查与验收 |
| 全局标准与发布 | 15. 平台角色模板；16. 全局字典与规则；17. 版本发布与灰度开关 |
| 客户成功与支持 | 18. 工单与服务请求；19. 受控远程协助；20. 租户健康度与客户沟通 |
| 集成与运行保障 | 21. 平台级接口与连接；22. API、密钥与 Webhook；23. 同步任务、资源与服务健康 |
| 安全与合规 | 24. 平台人员与职责权限；25. 跨租户审计日志；26. 安全策略与数据留存 |

## 3. 自动交付唯一链路

`合同/订单确认 → 租户授权生效 → 自动创建租户 → 套用初始化模板 → 创建首位学校管理员 → 学校导入师生并分配角色 → 上线检查 → 验收 → 日常健康监控与续费提醒`

禁止平台人员用数据库、手工菜单配置或临时超级权限跳过该链路。

## 4. 平台与学校的权责边界

| 事项 | 平台运营端 | 学校系统管理端 |
|---|---|---|
| 创建/停用租户 | 是 | 否 |
| 套餐、价格、合同、订单 | 是 | 只读查看已购授权 |
| 授予模块与配额 | 是 | 仅调整授权范围内业务开关 |
| 菜单、角色模板、全局权限点 | 发布与版本治理 | 启用模板、分配和裁剪本校角色 |
| 师生账号和组织数据 | 不直接维护 | 本校维护 |
| 学校业务数据 | 默认不可见 | 本校业务处理 |
| 排障协助 | 必须学校授权、限时、只读优先、审计 | 可授权、随时撤销、可审计 |

## 5. 平台角色分权

- 平台负责人：套餐、价格、授权策略和高风险审批；
- 交付运营：租户开通、初始化、上线检查，不可看学校敏感业务；
- 客户成功：健康度、续费提醒、工单和客户沟通，不可改套餐价格；
- 技术运维：服务健康、集成、同步和密钥轮换，远程协助必须受控；
- 安全审计：只读查看跨租户审计和异常，不处理业务。

任何单一平台角色都不应同时拥有“修改套餐/授权”和“删除或篡改审计”的能力。

## 6. 关键安全规则

1. 平台角色不可见学校业务模块；学校角色不可见平台控制面。
2. 平台远程协助必须记录学校、用途、授权人、开始/结束时间、范围、操作和结果，到期自动回收。
3. 密钥只可轮换、一次性下发，页面不回显明文；所有调用和投递可审计。
4. 租户到期的默认策略为提醒 → 受限只读 → 停用/归档，历史数据留存与导出规则由合同和留存策略决定。
5. 发布采用内部演示租户 → 试点租户 → 灰度租户 → 全量的顺序，并支持按租户回滚。

## 7. 实施优先级

### P0：先实现低人力交付闭环

租户、套餐、订单、功能授权、初始化模板、自动开通任务、上线检查、到期提醒和基础审计。

### P1：减少人工支持

租户健康度、工单、受控远程协助、客户公告、同步失败中心和告警事件。

### P2：规模化运营

灰度发布、版本回滚、密钥轮换、资源/备份可观测、数据留存与退出归档。
