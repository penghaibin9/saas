# 师生账号唯一导入入口与业务导入边界

## 冻结结论

批量创建登录账号的唯一入口为：`系统管理 → 导入老师和学生`。

该入口只接受系统下载的标准 `.xlsx` 模板，不提供 CSV、旧版 `.xls` 或宏文件导入，
避免编码、分隔符、前导零和宏安全问题形成额外实施维护成本。

- 学生导入：创建学生主档、学生登录账号并绑定 `STUDENT`。
- 教师导入：创建教师登录账号，并从 SaaS 预设角色中选择一个或多个角色。
- 新学校开局向导不接收师生数据；开通完成后由学校管理员进入本菜单导入。
- 重复导入不重复创建账号，只补齐缺失角色和数据范围关系。
- 新建账号的初始密码只写入本次自动下载的受控 Excel 回执，不写审计日志；首次登录强制修改。
- 预检批次绑定当前学校和操作者，30 分钟过期；有任一错误时不能进入确认步骤。

当前隔离开发阶段按约定不改数据库：预检批次暂存应用内存，服务重启后需重新上传。
待教务中心释放 MySQL 联调窗口后，再将批次元数据持久化到导入批次表，以支持多实例部署和断点追踪。

## 业务中心边界

毕业设计、岗位实习、教务、学工等业务中心导入只允许建立业务名单或业务关系：

1. 根据租户内学号/工号匹配既有账号和主档。
2. 匹配不到时返回明确错误，并提示先到系统管理导入。
3. 禁止业务导入创建 `User`、签发初始密码或隐式分配系统角色。
4. 禁止未知 `roleCode` 自动创建为系统角色。

这一边界保证身份主数据只有一个来源，避免同一学生出现多个账号、不同业务中心密码不一致、
角色被拼写错误后永久残留等高维护问题。
