## 1. 冻结目标

建设平台级“职业教育国家标准知识库”，做到：

1. 教育部职业教育国家教学标准体系目录全量登记；
2. 官方原始 PDF/HTML 可校验归档；
3. 原文全文、页、章节、条款、表格结构化入库；
4. 支持中文全文检索和专业、层次、类别、版本等组合筛选；
5. 搜索结果能定位到原始文件具体页码/章节；
6. 能比较新旧版本和替代关系；
7. 能从标准条款生成专业实施包，但平台推荐与官方原文严格分层；
8. 学校可以查看、收藏、引用到本校方案并保留引用快照；
9. 标准更新后能判断影响哪些专业包、学校和年级；
10. 在合法授权范围内决定原文全文的展示、下载、复制和导出能力。

知识库不是简单的 PDF 下载站，而是本系统所有专业预设、课程推荐、实践要求和毕业要求的可追溯事实底座。

## 2. 全量范围

以教育部[职业教育国家教学标准体系专题](https://www.moe.gov.cn/s78/A07/zcs_ztzl/2017_zt06/)为首批权威目录，覆盖：

| 标准域 | 全量入库内容 | 与系统的关系 |
|---|---|---|
| 职业教育专业目录 | 历版目录、层次、专业大类、专业类、专业名称、代码、增补/撤销/更名 | 学校专业主数据根目录 |
| 职业教育专业简介 | 中职、高职专科、职业本科全部公开专业简介 | 专业包职业面向、能力和课程方向输入 |
| 专业教学标准 | 2025 年修（制）订的 758 项及后续新增、旧版有效标准 | 专业实施包核心依据 |
| 中职公共基础课程标准 | 思想政治、语文、历史、数学、英语、信息技术、体育与健康、艺术及相关专业物理化学等 | 公共基础课包 |
| 中职大类专业基础课程教学大纲 | 按大类发布的专业基础课程要求 | 中职专业基础课包 |
| 岗位实习标准 | 职业学校专业（类）岗位实习标准 | 实习计划、岗位、内容、考核和安全预设 |
| 实训教学条件标准 | 专业仪器设备装备规范、实训教学条件建设标准 | 实训室和设备能力要求 |
| 学位门类对应表等配套文件 | 与职业本科专业治理直接相关的官方配套表 | 职业本科配置与校验 |
| 后续增补和调整文件 | 专业目录增补、标准修订、废止和替代通知 | 增量更新和影响分析 |

2025 年新标准为 758 项，覆盖当时 1434 个专业中的 52.9%，因此“专业目录记录数”和“专业教学标准文件数”不是一一相等。系统必须允许：一个标准适用多个专业、一个专业存在多版标准、某专业当前只有简介尚无 2025 新标准。[教育部758项新版标准发布说明](https://www.moe.gov.cn/jyb_xwfb/gzdt_gzdt/s5987/202502/t20250211_1178746.html)

## 3. 版权、来源和展示边界

### 3.1 已核验事实

- 教育部官网公开提供上述目录、网页和 PDF，并明确它们是职业教育国家教学标准体系内容。
- 教育部[网站声明](https://www.moe.gov.cn/jyb_sy/s3634/201005/t20100504_87292.html)写明，媒体、互联网网站和商业机构不得对网站内容进行商业性的原版原式转载，也不得歪曲、篡改。
- 《中华人民共和国著作权法》第五条规定，法律法规、国家机关的决议、决定、命令及其他具有立法、行政、司法性质的文件不适用著作权法。[中国人大网现行著作权法](https://www.npc.gov.cn/c2/c30834/202011/t20201119_308796.html)

### 3.2 产品处理结论

本项目是商业 SaaS，不能仅凭“官网可下载”就默认取得商业镜像全文的权利；同时也不能自行断言所有专业教学标准都当然属于著作权法第五条所称文件。因此采用“数据全量准备、展示按权利状态开放”的双层策略：

- 标准目录、专业代码、官方来源、版本、结构化事实和检索字段全量入库；
- 官方原始文件可以在受控存储中归档，用于校验、解析、内部审核和溯源；
- 全文解析结果可以入库并建立索引，但学校端全文展示、复制、下载和批量导出必须受 `rights_status` 控制；
- 未取得明确授权或合规结论前，学校端优先展示结构化结果、必要摘要、页码定位和教育部原文链接；
- 取得教育部或权利方书面许可，或经正式法律审查确认可开放后，再切换为完整全文展示；
- 无论是否开放全文，都必须注明发布机关、标题、版本、来源 URL、查阅日期，并禁止篡改原文。

这不是放弃全量入库，而是把“数据库已经准备好”和“商业产品可否原版展示”解耦，避免后期因授权问题重建数据模型。

### 3.3 权利状态

| 状态 | 含义 | 学校端能力 |
|---|---|---|
| `PENDING_REVIEW` | 已采集，尚未完成来源/版权复核 | 不公开 |
| `OFFICIAL_LINK_ONLY` | 官方公开但暂不开放商业全文镜像 | 可搜元数据、结构化条款和摘要，跳转官方原文 |
| `AUTHORIZED_FULLTEXT` | 已取得书面授权或正式法律审查通过 | 可全文阅读和站内搜索 |
| `AUTHORIZED_DOWNLOAD` | 额外允许原文件下载 | 可阅读、搜索、下载 |
| `RESTRICTED_INTERNAL` | 仅平台标准审核人员内部使用 | 学校端不可见 |
| `WITHDRAWN` | 来源撤回、内容失效或权利要求下架 | 仅保留审计和历史引用快照 |

`rights_status` 与标准的业务有效状态分离。一个标准可能业务上仍有效，但只能链接官方原文；也可能版权可展示，但业务上已被新标准替代。

## 4. 数据存储分层

```text
对象存储/文件中心
  └─ 官方 PDF、HTML 快照、附件、文件哈希

MySQL 权威数据库
  ├─ 文档/版本/来源/权利状态
  ├─ 页/章节/条款/表格/脚注
  ├─ 专业/岗位/任务/能力/课程领域/要求
  ├─ 引用/替代/适用关系
  └─ 导入任务/复核/审计/引用快照

检索索引
  ├─ 首期：MySQL InnoDB FULLTEXT + ngram 中文分词
  └─ 后期：数据量或搜索体验需要时增加独立搜索服务，MySQL 仍为权威源
```

原始二进制文件不建议直接塞入 MySQL 大字段；复用现有文件中心保存文件，数据库保存 `file_id、sha256、mime_type、size、source_url`。全文、段落和结构化条款保存在 MySQL，便于关系、版本、审计和检索。

MySQL 官方提供适用于中日韩文字的 `ngram` 全文解析器，可在 InnoDB 上建立中文全文索引，因此首期不必为了搜索单独部署 Elasticsearch/OpenSearch。[MySQL 8.4 ngram 全文解析器](https://dev.mysql.com/doc/refman/8.4/en/fulltext-search-ngram.html)

## 5. 核心数据模型

以下为设计表名，正式施工前必须通过数据库冻结总册和 Alembic 命名复核。

### 5.1 文档与版本

#### `t_platform_standard_document`

- `standard_code`：平台稳定编码；
- `standard_type`：目录/简介/专业教学/公共课程/实习/实训条件/配套文件；
- `title`；
- `issuer`；
- `document_no`；
- `publish_date`；
- `effective_date`；
- `business_status`：草稿/现行/被替代/废止；
- `rights_status`；
- `official_url`；
- `source_domain`；
- `current_version_id`；
- `applicable_level`；
- `applicable_scope_json`；
- `reviewed_by/reviewed_at`。

#### `t_platform_standard_version`

- 文档 ID、版本号、目录版本；
- 原始文件 `file_id`；
- MIME、大小、SHA-256；
- 抓取时间、最后校验时间、HTTP 元信息；
- 解析器版本、解析状态和质量分；
- 全文字符数、页数、表格数；
- 替代前版本 ID；
- 版本说明。

### 5.2 全文结构

#### `t_platform_standard_page`

- 版本 ID、页码；
- 页文本、OCR 文本、页图 `file_id`；
- 文本层/OCR 来源；
- 解析置信度；
- 页眉页脚清理标记。

#### `t_platform_standard_section`

- 版本 ID；
- 父章节 ID；
- 章节编号、标题、层级、排序；
- 起止页；
- 章节全文；
- 标准 11 要素类别。

#### `t_platform_standard_clause`

- 章节 ID、条款编号、页码、排序；
- 原文；
- 结构化摘要；
- 条款类型；
- 强制程度：原文明确/基本要求/推荐/学校自主；
- 解析方式：规则/人工/AI 辅助；
- 人工复核状态；
- 原文坐标或段落定位。

#### `t_platform_standard_table` 与 `t_platform_standard_table_cell`

保存表格标题、页码、行列、合并单元格和原文单元格，避免岗位—任务—课程领域等关键表格在纯文本中丢失结构。

### 5.3 专业实体和关系

- `t_platform_standard_major`：历版国家专业；
- `t_platform_standard_major_alias`：更名、旧代码、常用简称；
- `t_platform_standard_occupation`：职业类别与岗位；
- `t_platform_standard_task`：典型工作任务；
- `t_platform_standard_competency`：知识、能力、素质；
- `t_platform_standard_curriculum_field`：课程涉及主要领域；
- `t_platform_standard_requirement`：师资、条件、质量、毕业、学时、实践等要求；
- `t_platform_standard_relation`：标准化保存专业—岗位—任务—能力—课程—要求关系；
- `t_platform_standard_citation`：任一结构化实体回链文档、章节、条款和页码。

### 5.4 导入、复核和使用

- `t_platform_standard_ingest_job`：全量/增量导入任务、来源、状态、统计和错误；
- `t_platform_standard_ingest_error`：文件、页、条款级错误；
- `t_platform_standard_review_task`：来源、结构和权利复核；
- `t_platform_standard_search_log`：匿名化搜索词、零结果和性能，不记录学校敏感业务数据；
- `t_platform_standard_bookmark`：学校用户收藏；
- `t_platform_standard_usage`：标准被专业包、课程、方案引用的关系；
- `t_platform_standard_quote_snapshot`：学校发布方案时保存引用原文和版本快照，防止来源后来变化。

## 6. 全量入库流水线

```text
官方目录发现
→ URL 白名单校验
→ 下载 HTML/PDF
→ 文件哈希去重
→ 病毒/类型/大小检查
→ 文件中心归档
→ 文本层抽取
→ 无文本页 OCR
→ 页眉页脚和乱码清理
→ 章节/条款/表格识别
→ 专业代码与 11 要素映射
→ 中文全文索引
→ 自动完整性校验
→ 人工抽检/重点复核
→ 权利状态判定
→ 发布搜索
→ 生成专业包候选
```

### 6.1 采集规则

- 只允许 `moe.gov.cn`、`hudong.moe.gov.cn` 等已审核教育部官方域名进入首批自动采集白名单；
- 发现外部协作单位文件时先登记来源，不自动认定为教育部标准；
- 限速、失败重试、断点续传，不高频冲击政府网站；
- 每次采集保存来源 URL、时间、响应头、文件哈希和父目录位置；
- 相同哈希不重复存文件，但允许多个官方 URL 引用同一文件；
- 官方目录删除或链接失效时不自动物理删除历史版本，进入复核。

### 6.2 解析规则

- 优先读取 PDF 自带文本层；只对无文本或严重乱码页 OCR；
- 保留页码、章节号、表格结构和原文顺序；
- 原文层永不被 AI 改写；
- AI 只允许生成结构化候选和摘要，必须保存模型/提示词版本和复核状态；
- 数值、比例、学时、学分、年限、专业代码必须通过规则二次校验；
- 解析失败不阻断其他文件，但该文件不能发布为可搜索全文；
- 低置信度条款进入人工复核队列。

### 6.3 发布门禁

单份文档发布前必须满足：

- 官方来源已验证；
- 文件哈希和页数登记；
- 标题、类型、层次、专业代码和版本完整；
- 全文页覆盖率达到 100%，或缺失页有明确说明；
- 章节顺序和 11 要素结构校验通过；
- 关键表格抽检通过；
- 权利状态已填写；
- 搜索结果能回到页码和原文；
- 原文与结构化摘要视觉上明确区分。

## 7. 搜索产品设计

### 7.1 搜索范围

用户可搜索：

- 专业名称、专业代码、旧名称和别名；
- 标准标题、文号、发布机关；
- 职业、岗位和典型工作任务；
- 能力、知识、素质要求；
- 课程领域和教学内容；
- 实训设备、场地和师资要求；
- 学时、实践、质量保障和毕业要求；
- 岗位实习内容和安全要求；
- 标准原文全文（受权利状态控制）。

### 7.2 筛选项

- 办学层次：中职/高职专科/职业本科；
- 标准类型；
- 专业大类、专业类、专业；
- 专业代码；
- 发布年份和版本；
- 业务状态：现行/被替代/废止；
- 是否有 2025 新标准；
- 是否可全文阅读；
- 11 要素类别；
- 预设包成熟度 L0—L5。

### 7.3 搜索结果卡

每条结果显示：

- 专业/标准名称与代码；
- 办学层次和所属大类；
- 文档类型、版本、发布日期、业务状态；
- 命中章节、页码和合规长度的摘要；
- “官方原文”“查看结构化标准”“对比版本”“用于专业包”“收藏”入口；
- 来源和权利状态提示。

不得把平台推荐课程混在原文命中结果中。页面分为：

1. `官方原文/结构化事实`；
2. `平台标准映射`；
3. `学校采用情况`。

### 7.4 详情页

- 左侧目录树：11 要素和原文章节；
- 中间正文：按页/条款显示，支持命中高亮；
- 右侧证据栏：来源、版本、页码、哈希、替代关系和权利说明；
- 关系视图：岗位 → 任务 → 能力 → 课程领域；
- 版本对比：增加、删除、修改，精确到条款；
- “生成专业包候选”仅平台模板角色可用；
- 学校用户可以引用到方案草稿，但不能直接改官方原文。

## 8. API 设计草案

平台管理端：

- `GET /api/v1/platform/standards`：标准检索；
- `GET /api/v1/platform/standards/{id}`：标准详情；
- `GET /api/v1/platform/standards/{id}/content`：全文/章节，执行权利控制；
- `GET /api/v1/platform/standards/{id}/versions`：版本链；
- `GET /api/v1/platform/standards/{id}/diff`：版本差异；
- `POST /api/v1/platform/standards/ingest-jobs`：创建采集任务；
- `GET /api/v1/platform/standards/ingest-jobs/{id}`：导入报告；
- `POST /api/v1/platform/standards/{id}/review`：来源/结构/权利复核；
- `POST /api/v1/platform/standards/{id}/publish`：发布；
- `POST /api/v1/platform/standards/{id}/create-preset-draft`：生成模板候选。

学校端：

- `GET /api/v1/standards/search`：学校可见范围检索；
- `GET /api/v1/standards/{id}`：结构化详情；
- `GET /api/v1/standards/{id}/content`：按权利状态返回全文、摘要或官方链接；
- `POST /api/v1/standards/{id}/bookmarks`：收藏；
- `POST /api/v1/standards/clauses/{id}/cite`：引用到培养方案草稿并生成快照。

所有接口返回 `source、version、businessStatus、rightsStatus、officialUrl、locator`。全文接口不得仅靠前端隐藏，后端必须裁定权利状态和角色。

## 9. 权限与审计

| 操作 | 平台标准管理员 | 平台审核员 | 平台运营 | 学校教务 | 教师/学生 |
|---|---:|---:|---:|---:|---:|
| 搜索已发布标准 | 是 | 是 | 是 | 是 | 按产品授权 |
| 查看受限全文 | 按内部授权 | 是 | 否 | 否 | 否 |
| 创建采集任务 | 是 | 否 | 否 | 否 | 否 |
| 修改结构化候选 | 是 | 退回 | 否 | 否 | 否 |
| 发布/撤回 | 否 | 是 | 否 | 否 | 否 |
| 修改权利状态 | 否 | 专门授权 | 否 | 否 | 否 |
| 生成模板草稿 | 是 | 是 | 否 | 否 | 否 |
| 引用到本校方案 | 否 | 否 | 否 | 本校范围 | 否 |

## 11. 验收指标

### 11.1 覆盖和准确性

- 官方专题目录发现覆盖率 100%；
- 已发现文件来源 URL、哈希和版本登记率 100%；
- 可解析文件页面覆盖率 100%；
- 2025 新标准 758 项清册对账无未知缺口；
- 专业代码与层次自动匹配后人工抽检；
- 11 要素章节映射完整率 100%，不适用/缺失必须有状态；
- 表格行列抽检无错位；
- 原文引用能准确定位到页码/章节。

### 11.2 搜索

- 专业名称、代码、岗位、课程领域、毕业要求可检索；
- 支持简繁常见变体、旧专业名和别名；
- 筛选条件组合正确；
- 现行标准优先，被替代标准明确标识；
- 零结果有建议，不把无命中伪造成 AI 答案；
- 常用检索性能在数据量基准测试后确定正式 SLA，未压测前不预先承诺毫秒数。

### 11.3 权利和安全

- `OFFICIAL_LINK_ONLY` 不能通过任何接口取得完整镜像全文；
- `AUTHORIZED_FULLTEXT` 才能返回完整正文；
- 原文件下载另受 `AUTHORIZED_DOWNLOAD` 控制；
- 批量导出有权限、用途原因、水印和审计；
- 学校只能看到平台发布内容和本校收藏/引用，不能读取其他学校引用记录；
- 撤回内容从搜索结果下架但历史方案引用快照保留。

### 11.4 业务贯通

- 标准条款可以生成专业包候选；
- 专业包课程能回链课程领域和原文条款；
- 学校方案发布后保存标准版本快照；
- 新标准出现时能列出受影响模板、学校、专业和年级；
- 标准更新不自动覆盖在读年级。
