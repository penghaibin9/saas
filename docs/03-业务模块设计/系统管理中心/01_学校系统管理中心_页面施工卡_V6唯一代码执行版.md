# 0. V6使用方式

本文件不允许一次全部交给AI施工。正确单位是：

```text
一张卡
一个分支
一个Draft PR
一个迁移所有者
一份精确文件白名单
一套定向测试
一次独立复审
```

单卡在完整执行V6闸门后，工程目标成功率为85%～92%；这不是保证值。

AI开始编码前必须先输出：

1. 当前分支、HEAD、工作区和Alembic heads；
2. 本卡现有router/service/model/schema/page/api/test；
3. 旧接口所有消费者；
4. 复用、修改、新增、退役清单；
5. 精确允许文件和禁止文件；
6. 依赖PR、迁移所有者和公共文件锁；
7. 测试与回滚计划。

事实不清楚时只输出差异报告，不得猜测施工。

# 3. 公共底座边界

| 底座 | 唯一控制面 | 负责 | 模块边界 |
|---|---|---|---|
| 账号 | 系统管理 | 稳定主体、登录状态、身份绑定 | 业务模块只引用userId/studentId/staffId |
| 组织 | 系统管理 | 组织版本、任职和有效期 | 业务模块只引用组织和业务关系 |
| 权限 | 角色权限专项 | 角色、权限包、范围、流程、安全激活 | 业务模块只声明动作和resolver |
| 消息 | 系统管理公共通信 | 事件、模板、渠道、投递 | 模块只发布eventCode |
| 待办 | 系统管理公共任务 | 责任人、期限、状态、跳转和完成证据 | 模块提供业务完成证据 |
| 文件 | 公共文件中心（已合并main） | 安全、版本、绑定、任务、归档 | 模块提供材料规则和范围resolver |
| 主数据 | 系统管理治理+业务owner | 数据域、来源、质量、责任 | 业务模块维护本域权威数据 |
| 集成 | 系统管理+平台服务目录 | 连接、凭证、映射和运行 | 模块提供adapter |

DDL执行规则：

- 逻辑引用是否建立数据库外键，必须根据当前仓库既有约定决定并写理由；
- JSON字段必须有Pydantic/schema验证，不能成为无结构垃圾桶；
- 所有更新使用`version = version + 1 WHERE version = expectedVersion`；
- 大表索引必须用真实查询`EXPLAIN`验证；
- downgrade不得静默丢失已激活安全或配置数据。
