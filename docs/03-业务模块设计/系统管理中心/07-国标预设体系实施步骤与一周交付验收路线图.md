> 文档状态：`implementation_baseline_v1`（实施基线，未执行项不得标记已完成）

> 产品设计依据：[06-国标驱动学校预设体系产品与数据设计总册.md](./06-国标驱动学校预设体系产品与数据设计总册.md)

## 1. 两条实施路线

### 1.1 标准路线：5 个工作日

这是正式交付承诺的默认路线，给学校留出专业负责人确认、数据修正、权限验证和签字验收时间。

### 1.2 快速路线：2 个工作日

只有同时满足下列条件才进入快速路线：

- 学校办学层次、专业和年级清单已确认；
- 学院、部门、班级、教师、学生 XLSX 已按模板准备；
- 所选专业已有 `L4 可运行级` 专业实施包；
- 学校接受一键标准版，不要求现场重构培养方案；
- 学校管理员、教务负责人、专业负责人能连续参与确认；
- 无旧系统复杂历史数据迁移和第三方接口阻断。

任一条件不满足，自动切回 5 日标准路线，不把赶工风险转嫁给学校。

## 2. 产品研发总路线

本路线是“先把预设能力做进系统”的开发顺序，不等同于单所学校的一周交付。

| 阶段 | 建设目标 | 核心产物 | 完成门禁 |
|---|---|---|---|
| P0 基线冻结 | 锁定国标来源、系统边界和现有代码映射 | 本两份文档、来源登记表、现状缺口表 | 来源可打开；设计与现有教务主链无冲突 |
| P1 国家标准库 | 全量建立目录、原始文件、全文、页面、章节、条款、表格、版本、权利状态和替代关系 | 标准库表/API/平台页面/导入与中文检索工具 | 官方来源、哈希、版本、条款定位均可追溯；全文展示服从权利状态 |
| P2 预设模板引擎 | 建立包、条目、依赖、参数、版本、发布 | 黄金配置环境、模板编审发布 | 不含租户业务数据；发布前双人或分权审核 |
| P3 专业实施包模型 | 打通岗位、任务、能力、课程、实践、毕业要求 | 专业包编辑器和标准覆盖矩阵 | 专业标准 11 要素全覆盖 |
| P4 租户安装引擎 | dry-run、差异、幂等、事务、映射和回滚 | 安装批次、安装报告、对象来源链 | 重复安装零副作用；硬错误整批回滚 |
| P5 一键实施向导 | 支持标准/引导/自定义三模式 | 平台端实施任务、学校端步骤向导 | 学校不懂配置也能按默认方案走完 |
| P6 教务主链贯通 | 专业包生成学校课程、方案、计划和任务 | `major → course → program → task` | 每个运行对象可追溯模板和标准 |
| P7 权限与验收 | 岗位关系、权限、审计、就绪度和验收报告 | 阻断/警告检查、签字快照 | 跨租户、越权、历史覆盖测试通过 |
| P8 首批专业包 | 建设 3—6 个 L4 专业包并试点 | 可售专业包和演示学校 | 每包有官方标准、完整映射、真实试点证据 |
| P9 模板升级运营 | 标准监测、差异评估、租户升级建议 | 升级中心、过期提醒、覆盖率看板 | 不静默改在读年级和生产数据 |

### 2.1 P0：当前文档阶段的收口项

- [x] 确定国家标准优先级；
- [x] 确定第三方系统只作流程参考；
- [x] 确定标准实施周期为 5 个工作日，2 天为快速通道；
- [x] 确定学校配置不全时可以直接采用平台预设；
- [x] 确定标准库、预设库和租户运行库分离；
- [x] 确定复用现有专业、课程、培养方案、实践和教学任务数据；
- [ ] 实施前建立专属生产级施工包和全部三级施工卡；
- [ ] 实施前核对 MySQL 表名、迁移基线、API 和页面现状；
- [ ] 实施前完成不少于三套成熟系统的有效外部证据门禁；
- [ ] 实施前冻结首批专业包清单。

### 2.2 P1：国家标准库施工步骤

1. 建标准文档主档和附件/链接登记；
2. 导入 2021 专业目录和 2022 专业简介索引；
3. 登记 2025 专业教学标准及后续增补；
4. 登记公共基础课程、岗位实习、实训条件标准；
5. 建文档版本、适用范围、替代和失效关系；
6. 建标准条款人工拆解工作台；
7. 建来源复核、发布、退回和停用状态机；
8. 建官方 URL 可达性、文件哈希、重复文档检查；
9. 建标准更新影响分析；
10. 建标准覆盖率看板；
11. 建 PDF/HTML 文件归档、文本层抽取、OCR、页/章节/条款/表格结构化；
12. 建 MySQL 中文全文索引和组合筛选；
13. 建权利状态和全文/摘要/官方链接三种学校端展示策略；
14. 按 [08-职业教育国家标准全量入库与检索实施方案.md](./08-职业教育国家标准全量入库与检索实施方案.md) 分批导入 758 项新版标准及其他标准域。

验收：任一结构化字段都能回到官方文档及条款定位；平台建议与原文事实有明显标签区分。

### 2.3 P2：模板引擎施工步骤

1. 建模板包、模板条目、依赖和参数模型；
2. 建平台黄金模板环境，禁止保存真实学校数据；
3. 建模板草稿、校验、审核、发布、停用和替代状态；
4. 建主/次/修订版本；
5. 建模板复制和专业方向扩展机制；
6. 建参数的锁定级别：平台锁定、学校必选、学校可改、只读推荐；
7. 建模板发布前完整性检查；
8. 建模板变更差异和受影响租户统计；
9. 建模板导出/导入包，但不携带租户业务数据；
10. 建模板回归测试样例。

### 2.4 P3：专业实施包施工步骤

每个专业按同一套流水线建设：

1. 绑定专业目录代码和办学层次；
2. 绑定专业简介和专业教学标准原文；
3. 拆解标准 11 要素；
4. 结构化职业面向、岗位和典型任务；
5. 建能力与素质图谱；
6. 拆解公共基础、专业基础、专业核心、拓展、实践和实习课程领域；
7. 从课程领域生成推荐课程，不把推荐名称冒充国标原文；
8. 建课程前置、后续、替代和能力映射；
9. 建实践项目、岗位实习和安全要求；
10. 建师资、场地和设备条件；
11. 建质量保障和毕业要求；
12. 建推荐学期、学分学时区间和培养方案骨架；
13. 运行标准覆盖校验；
14. 由另一角色复核来源和映射；
15. 发布为 `L2 推荐级`；
16. 安装到测试学校并贯通教学任务后升为 `L4 可运行级`。

### 2.5 P4：租户安装引擎施工步骤

安装顺序冻结为：

```text
租户与模块授权
→ 学校基础参数
→ 学年学期/节次
→ 组织/专业
→ 角色/流程/安全
→ 公共基础课
→ 专业实施包
→ 课程库草稿
→ 培养方案草稿
→ 实践/毕业要求
→ 方案绑定
→ 学期教学任务草稿
→ 就绪度检查
```

每一步必须支持：预检、对象匹配、冲突说明、原子事务、幂等键、审计、结果导出和失败重试。

### 2.6 P5：一键实施向导步骤

向导只让学校处理确实需要选择的内容：

1. 选择采用模式；
2. 确认学校和办学层次；
3. 选择专业、年级和专业方向；
4. 选择学期校历和作息模板；
5. 下载、预检并导入组织师生数据；
6. 指定关键岗位人员；
7. 预览课程、培养方案和教学运行产物；
8. 查看默认值与学校差异；
9. 学校负责人确认并应用；
10. 运行上线检查并生成验收报告。

向导允许“稍后细化”，但不得跳过租户安全、专业标准来源、培养方案责任确认和上线阻断项。

## 3. 单所学校一周实施 SOP

### 3.1 开通前准备（D-3 至 D0）

平台准备：

- 创建实施任务但不提前写正式业务数据；
- 确认合同套餐、模块、租户代码、学校名称和首位校管；
- 根据学校专业清单匹配可用专业包和缺口；
- 生成学校需要准备的 XLSX 清单；
- 建立实施问题台账和联系人；
- 对不具备 L4 包的专业明确标记“本周不能一键生成完整教务方案”。

学校准备：

- 确认学校管理员、教务负责人和专业负责人；
- 提供学院/部门、专业、年级班级、教师和学生数据；
- 提供现行培养方案或书面确认采用平台标准版；
- 提供校历、作息、校区和关键审批人员；
- 确认上线范围和日期。

### 3.2 第 1 日：开户与选择

上午：

- 平台创建租户、套餐、模块授权和首位学校管理员；
- 系统初始化角色、安全策略、字典和实施任务；
- 学校管理员首次登录、改密和确认学校信息。

下午：

- 选择一键标准版、引导选择版或学校自定义版；
- 选择办学层次、学制、专业、年级和方向；
- 系统推荐公共基础课包和专业实施包；
- 生成《将要安装内容预览》《国标来源清单》《需学校决定项清单》；
- 学校确认采用范围。

当日门禁：租户、模块、校管、采用模式、专业包匹配全部明确。

### 3.3 第 2 日：组织、账号与业务关系

上午：

- 导入学院、部门、专业、年级和班级；
- 预检编码、重复、层级、专业代码和跨租户关系；
- 修复错误后正式导入。

下午：

- 通过唯一账号入口导入教师和学生；
- 分配学校管理员、教务、学院、专业负责人、辅导员和教师岗位；
- 建立教师组织归属、辅导员班级和专业负责人关系；
- 运行账号、角色、数据范围和弱密码检查。

当日门禁：师生账号可登录；无孤儿班级、孤儿账号和越界关系。

### 3.4 第 3 日：专业、课程与培养方案

一键标准版：

- 系统安装国标派生专业包；
- 自动生成课程库草稿、培养方案草稿、实践环节和毕业要求；
- 专业负责人集中查看“国标明确项、平台推荐项、学校待定项”；
- 学校一次性确认或只修改少量内容。

引导/自定义版：

- 导入或映射学校现有课程；
- 比较学校方案与标准模板；
- 处理缺失课程领域、学时学分、实践和毕业要求差异；
- 形成学校正式版本草稿。

当日门禁：每个启用专业均有标准来源、专业负责人和完整方案草稿；11 要素无未解释缺口。

### 3.5 第 4 日：教学运行、流程和权限

上午：

- 发布或启用经确认的培养方案；
- 绑定专业、年级和班级；
- 生成当学期应开课程、教学任务批次和教学班；
- 分配任课教师、周学时、起止周和场地类型；
- 运行漏课、缺师、缺场地和排课前置检查。

下午：

- 确认课程、方案、教学任务、成绩、实习等审批流程；
- 用学校管理员、教务、专业负责人、专业课教师、辅导员、学生账号做角色验收；
- 验证菜单、按钮、数据范围、敏感字段、审批回避、审计和导出水印；
- 验证模块未授权时 API 和页面均拒绝。

当日门禁：教务主链可运行；课程教师只看本人教学任务；专业负责人只看本专业；跨租户访问被拒绝。

### 3.6 第 5 日：试运行、修正与验收

上午：

- 模拟教师查看任务、学生查看培养方案、教务查看计划；
- 抽查一个专业从国标条款到课程、方案、任务的追溯链；
- 运行全部上线阻断和警告检查；
- 只修配置与数据问题，不临时绕过安全和标准规则。

下午：

- 复跑检查并冻结配置快照；
- 生成《模板采用清单》《学校修改差异》《数据导入报告》《权限验收报告》《上线就绪度报告》；
- 双方确认正式启用范围、遗留警告和处理计划；
- 学校负责人执行上线确认；
- 进入上线后一周观察期。

当日门禁：零阻断项；警告项有负责人和期限；验收材料可归档。

## 4. 2 天快速实施 SOP

### 第 1 日

- 上午完成租户、模块、校管、标准方案选择和 dry-run；
- 下午完成组织、师生、班级、岗位和关系导入；
- 当晚系统生成专业、课程和培养方案草稿并运行校验。

### 第 2 日

- 上午由教务和专业负责人确认方案，生成教学任务；
- 下午完成角色抽测、上线检查、差异确认和验收。

快速路线不省略任何阻断校验，只压缩等待时间和自定义范围。

## 5. 学校只需决定的最小事项

一键标准版将学校决策压缩为以下 15 项：

1. 办学层次；
2. 基本学制；
3. 学年学期结构；
4. 校历起止和教学周；
5. 作息节次；
6. 当前专业和年级；
7. 是否启用专业方向；
8. 是否采用平台标准专业包；
9. 是否采用平台推荐学分学时；
10. 当前学期开课范围；
11. 学校管理员；
12. 教务负责人；
13. 各专业负责人；
14. 默认审批链是否采用；
15. 正式上线日期。

其他可推导项由系统自动生成；其他可后置项进入上线后优化清单。

## 6. 默认方案的确认与责任机制

学校直接采用平台预设时，系统必须形成一份不可抵赖的采用记录：

- 学校名称和租户；
- 采用模式；
- 采用的标准与模板版本；
- 适用专业、年级和班级；
- 平台默认的课程、学分、学时、实践和毕业要求；
- 学校修改项；
- 仍为警告的条件缺口；
- 确认人、角色、时间和意见；
- 生成对象与来源快照；
- 后续变更必须走新版本。

建议确认声明：

> 本校已核对该方案引用的国家标准、平台推荐项和本校待定项，同意将确认后的配置作为本校对应专业和年级的实施草案/正式方案；后续变更按学校制度审批并保留版本。

“草案”还是“正式方案”由学校在确认时选择。没有正式发布授权时，系统只能生成草稿，不能替学校自动发布。

## 7. 开发施工包拆分建议

后续进入代码施工时，不把整个预设体系塞进一个超大二级模块。按依赖拆成以下施工包，每包再建立独立三级施工卡：

| 序号 | 二级施工包 | 三级能力建议 |
|---|---|---|
| 1 | 国家标准库 | 标准文档、专业目录、专业简介、教学标准、条款拆解、版本替代、来源复核、覆盖率 |
| 2 | 预设模板中心 | 模板包、条目、参数、依赖、复制、审核发布、版本比较、停用替代、导入导出 |
| 3 | 专业实施包 | 岗位、任务、能力、课程领域、推荐课程、实践、师资、条件、质量、毕业要求 |
| 4 | 学校实施向导 | 采用模式、学校信息、专业选择、数据导入、人员指定、预览、差异、确认、应用、进度 |
| 5 | 模板安装与升级 | dry-run、冲突匹配、安装、回滚、对象映射、差异、升级建议、历史保护 |
| 6 | 上线就绪与验收 | 租户、账号、组织、权限、专业、课程、方案、任务、安全检查及报告归档 |

依赖顺序：`1 → 2 → 3 → 4/5 → 6`。教务中心不是重建对象，而是施工包 3、4、5 的运行落点。

## 8. 每阶段必须执行的测试

### 8.1 标准和模板测试

- 官方来源缺失、URL 失效、哈希变化；
- 同一专业多标准版本；
- 旧标准被替代；
- 国标字段与平台建议标签混淆；
- 专业标准 11 要素缺项；
- 模板依赖循环；
- 未发布模板被安装；
- 不同办学层次模板错配。

### 8.2 安装测试

- 空学校首次安装；
- 已有部分组织和课程时安装；
- 重复安装同版本；
- 安装过程中硬错误回滚；
- 同专业不同年级安装不同版本；
- 学校修改后升级模板；
- 模板停用但历史对象仍可查看；
- 两租户同时安装且数据完全隔离。

### 8.3 教务贯通测试

- 专业包生成课程库草稿；
- 课程生成培养方案；
- 方案绑定年级班级；
- 方案生成学期教学任务；
- 实践课程进入实训/实习链；
- 成绩和毕业审核读取正确方案版本；
- 转专业学生的方案重绑和历史学分处理；
- 已发布方案不能被模板升级覆盖。

### 8.4 权限安全测试

- 平台角色不能默认查看学校敏感业务明细；
- 学校管理员不能发布专业培养方案；
- 专业负责人不能跨专业；
- 课程教师只访问本人教学任务和学生；
- 编制人不能绕过审批发布；
- 未授权模块前后端均拒绝；
- 跨租户读取、写入、导出全部拒绝并审计；
- 默认方案确认、升级和回滚均有审计记录。

## 10. 单人团队的施工优先级

### 第一阶段：先做可演示、可试点闭环

1. 国家标准文档与专业目录；
2. 预设包和版本；
3. dry-run 安装；
4. 一键标准版向导；
5. 与现有专业、课程、培养方案、教学任务贯通；
6. 上线检查；
7. 3 个完整专业包。

### 第二阶段：降低长期维护成本

1. 标准差异和升级建议；
2. 专业包复制和方向扩展；
3. 学校现有方案导入与自动映射；
4. 师资/场地条件缺口分析；
5. 交付材料自动生成；
6. 扩展到 6—12 个专业包。

### 第三阶段：形成商业壁垒

1. 多地区地方标准加层；
2. 行业企业任务与课程映射；
3. 专业设置与招生预警；
4. 专业标准覆盖率和实施质量看板；
5. 匿名化沉淀可复用实施经验，严禁汇聚学校敏感数据；
6. 标准变化的租户影响评估和一键升级建议。

6. 然后按依赖进入预设模板中心和专业实施包。
