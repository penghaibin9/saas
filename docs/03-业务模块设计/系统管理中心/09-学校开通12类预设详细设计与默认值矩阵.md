## 1. 产品结论

### 1.1 可以实现的交付承诺

采用“一键标准版”的学校，原则上只需完成两件事：

1. 提供真实教师和学生基础数据；
2. 对系统自动推导的组织、专业、关键岗位、校历、培养方案和默认政策进行集中确认。

其余租户、模块、角色、权限、组织骨架、流程、字典、安全、菜单、通知、国标专业课程包和上线检查，在学校开户期间由平台自动安装。

准确的产品表述是：

> 学校无需从零搭建系统，只需导入真实师生数据并确认本校差异，即可在一个自然周内形成可运行的学校管理和教学底座；资料齐全且采用标准方案时可缩短到 2 个工作日。

### 1.2 学校仍需提供的最小信息

不能由平台猜测的内容压缩为一张《学校开通确认表》：

- 学校法定名称、简称和办学层次；
- 当前招生专业、年级和班级；
- 首位学校管理员；
- 教务负责人、学工负责人和各专业负责人；
- 当前学年学期、开学日期和正式上线日期；
- 是否直接采用平台标准方案；
- 学校已有制度与平台默认值冲突时采用哪个值。

学院、专业、年级、班级名称允许直接从师生导入数据中自动发现，不要求学校先到系统逐项创建，但正式落库前必须预览确认。

## 2. 预设的统一产品模型

“预设”不是写死数据，而是一个可安装的版本化配置包。每个预设项必须标记以下四种控制级别之一：

| 控制级别 | 含义 | 示例 |
|---|---|---|
| `PLATFORM_LOCKED` | 平台安全或合规红线，学校不能关闭 | 租户隔离、审计不可删除、业务导入不得隐式建号 |
| `STANDARD_BASELINE` | 来自国家标准的底线，学校可加严但不能无说明降低 | 专业代码、课程领域、实习和毕业基本要求 |
| `SCHOOL_CONFIRM` | 平台给推荐值，首次启用前学校必须确认 | 审批层级、学分学时、校历、成绩规则 |
| `SCHOOL_EDITABLE` | 学校可随时在边界内调整 | 展示名称、通知文案、快捷入口排序 |

每个预设包统一具备：

- 包编码、类型、适用版本和适用办学层次；
- 模板版本、标准来源和发布状态；
- 前置依赖和安装顺序；
- 默认值、可选值、锁定级别和学校决定项；
- dry-run 预检、冲突、差异和影响说明；
- 幂等安装、事务回滚和对象映射；
- 安装人、确认人、时间和快照；
- 升级、停用、替代和历史版本保护；
- 对应上线检查规则。

## 3. 12 类预设总览

| 编号 | 预设域 | 自动解决的问题 | 学校最少动作 |
|---:|---|---|---|
| 1 | 学校开通预设 | 版本、模块、容量、租户、初始化步骤和验收范围 | 选择版本并确认学校信息 |
| 2 | 角色与权限预设 | 谁能做什么、看谁、看多敏感 | 指定关键岗位人员 |
| 3 | 组织结构预设 | 学校组织树和负责人关系 | 确认自动发现的真实组织名称 |
| 4 | 师生导入预设 | 账号、身份、字段、重复、密码和错误处理 | 上传标准 XLSX 并处理错误行 |
| 5 | 业务关系预设 | 用户如何获得真实业务数据范围 | 确认辅导员、任课、导师等关系 |
| 6 | 流程预设 | 业务怎样提交、审批、退回、超时和归档 | 确认审批层级和责任人 |
| 7 | 字典与编号预设 | 全校统一代码、状态和业务编号 | 确认学号工号等本校规则 |
| 8 | 安全与审计预设 | 登录、敏感数据、导出、高风险操作和追溯 | 确认加严项，不能关闭平台红线 |
| 9 | 菜单与工作台预设 | 各角色登录后看到什么、先做什么 | 可选调整名称和排序 |
| 10 | 消息与通知预设 | 谁在何时通过什么渠道收到什么 | 确认渠道和对外文案 |
| 11 | 上线检查预设 | 自动判断学校是否真的能上线 | 处理阻断项并确认验收 |
| 12 | 模块业务预设 | 迎新、学工、教务、实习、毕设、就业直接获得运行规则 | 选择启用模块并确认学校政策 |

## 4. 预设一：学校开通预设

### 4.1 版本模板

| 版本 | 默认定位 | 默认模块原则 | 数据与容量原则 | 初始化方式 | 验收重点 |
|---|---|---|---|---|---|
| 高职标准版 | 高职专科/职业本科正式学校 | 全生命周期基础模块；教务、实习、毕设按合同开通 | 正式生产容量，按合同和安全上限 | 一周标准实施，支持国标专业包 | 学分制/学年制、培养方案、教学任务、实习毕设毕业贯通 |
| 中职标准版 | 中等职业学校正式学校 | 学工、教务、实习为重点；按合同启用其他模块 | 正式生产容量 | 一周标准实施，使用中职公共基础和专业标准 | 学制、公共基础课、实训实习、班主任/辅导员关系 |
| 试点快速版 | POC 或首校小范围试运行 | 只开合同试点模块，不伪造业务数据 | 限定真实学生、教师、文件和调用容量；到期策略明确 | 2—5 日，真实数据、小范围班级 | 功能闭环、安全、转正式零迁移、试点范围清楚 |
| 演示版 | 售前演示和培训 | 预置完整展示模块 | 仅虚构数据；只读演示或每日可重置沙箱 | 种子数据初始化 | 与真实租户隔离、弱密码仅演示、重置可追溯 |
| 私有化版 | 学校独立部署 | 与合同一致，不另建业务分支 | 容量由部署资源决定 | 安装包+环境检查+初始化+联调 | 数据库、对象存储、域名证书、备份恢复、监控和升级 |

职业本科可以在高职标准版基础上叠加职业本科办学层次包，不单独复制一套业务代码。

### 4.2 自动生成

- 租户、租户代码和状态；
- 套餐、模块授权和有效期；
- 容量策略：账号、文件、导出、API、短信等；
- 学校品牌默认值；
- 首位学校管理员待交付任务；
- 基础角色、安全、字典和流程包安装任务；
- 专业和国标包匹配任务；
- 初始化阶段、负责人、截止日期和验收清单；
- 试点转正式、演示重置或私有化交付策略。

### 4.3 学校确认

- 学校名称、代码、办学层次和校区；
- 版本类型和已购模块；
- 真实使用范围和上线日期；
- 首位管理员；
- 试点是否转正式、历史数据是否迁移、第三方接口是否接入。

### 4.4 不允许自动决定

- 未购买模块不能因模板存在而启用；
- 试点真实租户不能灌演示数据；
- 私有化版不能默认降低安全、审计和备份标准；
- 到期、停用和容量超限策略必须符合合同，不能由代码随意变化。

### 4.5 验收

版本、套餐、模块、容量、租户状态、校管交付、初始化任务、上线范围和验收项完全一致；关闭模块时页面与 API 同时拒绝。

## 5. 预设二：角色与权限预设

### 5.1 角色包组成

每个角色模板不是一个名称，而是：

```text
角色
+ 默认菜单
+ 页面/按钮/API权限
+ 数据范围上限
+ 真实业务关系解析规则
+ 敏感字段权限
+ 审批节点资格
+ 工作台和统计口径
+ 导入导出权限
+ 审计规则
```

### 5.2 首批角色目录

| 类别 | 预设角色 | 默认数据范围 |
|---|---|---|
| 学校治理 | 学校系统管理员、身份管理员、组织管理员、安全审计员、学校领导 | 系统配置面；领导以脱敏汇总为主 |
| 学工 | 学工管理员、学院学工负责人、辅导员/班主任、资助老师、宿管、心理老师 | 全校/学院/所带班级/楼栋/专项授权对象 |
| 教务 | 教务管理员、学院教务员、专业负责人、教研室主任、课程负责人、专业课教师、公共课教师、实训指导教师 | 全校/学院/专业/教研室/课程/本人教学任务 |
| 毕设 | 毕设管理员、专业负责人、毕设导师、评阅教师、答辩秘书、答辩专家 | 管理范围或本人被分配任务 |
| 实习就业 | 实习管理员、学院实习负责人、实习指导教师、就业老师、企业导师 | 管理范围或本人指导学生 |
| 学生和外部 | 学生、企业联系人等 | 仅本人或协议授权对象 |

### 5.3 自动绑定规则

- 首位校管自动绑定学校系统管理员；
- 教师导入的岗位只生成候选角色，敏感角色需确认；
- 辅导员由辅导员—班级关系获得学生范围；
- 任课教师由教学任务获得教学班学生范围；
- 专业负责人由专业负责人关系获得本专业范围；
- 毕设和实习导师分别由真实指导关系获得学生范围；
- 一个用户可有多个角色，但会话只激活一个角色；切换后菜单、权限、范围、待办和统计同步变化。

### 5.4 权限红线

- 学校系统管理员不天然拥有所有学生敏感明细；
- 安全审计员只读，不能修改被审计配置；
- 身份管理员可以维护账号，不自动拥有业务数据查看权；
- 组织管理员可以维护组织，不自动拥有成绩、资助、心理等明细；
- 教师不能审核自己提交的成绩或业务申请；
- 专业负责人不等于全校教务管理员；
- 前端隐藏不是权限，后端必须完成最终裁定；
- 学校自定义角色不得突破来源模板和操作者自身权限上限。

### 5.5 小学校兼任

学校人员少时允许一人多岗，但必须：

- 分角色切换使用；
- 高风险动作保留二次确认和审计；
- 自提自审场景强制回避或由上级角色复核；
- 无法分离审计员时记录风险确认，审计日志仍不可删除。

### 5.6 验收

对每个角色执行正向、反向、跨范围、跨租户、敏感字段和状态限制测试；权限解释器能说明“为什么能看/为什么不能看”。

## 6. 预设三：组织结构预设

### 6.1 统一组织模型

```text
学校
├─ 校区（可选）
├─ 行政部门
├─ 教学单位/学院/系部
│  ├─ 教研室（可选）
│  └─ 专业
│     ├─ 专业方向（可选）
│     └─ 年级
│        └─ 行政班
└─ 实训基地/宿舍楼等业务组织
```

行政组织、教学组织和业务管理范围分开建模；不能因为同一个人属于某部门就自动获得该部门所有业务权限。

### 6.2 自动发现和匹配

师生导入预检时，系统从以下字段提取去重值：

- 教师：部门、学院/系部、教研室、岗位；
- 学生：学院/系部、国家专业代码、专业名称、年级、班级；
- 负责人：组织名称、负责人身份、有效期。

生成《待确认组织树》，按以下顺序匹配：

1. 国家专业代码精确匹配；
2. 学校组织编码精确匹配；
3. 标准名称和别名匹配；
4. 名称近似只给候选，不自动合并；
5. 同名跨学院、代码冲突或层级循环必须人工处理。

确认后按“组织 → 专业 → 年级 → 班级 → 师生”顺序原子落库。

### 6.3 历史保护

- 组织、专业、班级采用停用/撤销，不物理删除历史业务关系；
- 改名保留别名和变更记录；
- 专业更名、代码调整要与国标版本建立映射；
- 学生历史归属和当时负责人保存快照；
- 组织变更触发数据范围重算，但不改历史审计责任人。

### 6.4 学校确认

- 真实组织名称和层级；
- 哪些单位是行政部门、教学单位或两者兼具；
- 专业所属教学单位；
- 负责人和生效时间；
- 同名、别名和历史组织处理。

### 6.5 验收

无孤儿组织、无循环、无跨租户父子关系、专业代码层次正确、班级均归属专业和年级、负责人关系有效。

## 7. 预设四：师生导入预设

### 7.1 唯一建号入口

批量创建教师和学生账号只能通过“系统管理 → 导入老师和学生”，正式格式只接受平台标准 XLSX。迎新、教务、学工、实习、毕设、就业的名单导入只能关联已有账号，禁止隐式建号。

### 7.2 标准工作簿

建议一个开户工作簿包含：

- `教师`：工号、姓名、手机号、证件标识、部门、学院、教研室、岗位、关键负责人标识；
- `学生`：学号、姓名、证件标识、专业代码/名称、年级、班级、培养层次；
- `关系补充`：辅导员、班主任、专业负责人等首批关系；
- `填写说明`：字段、示例、枚举、隐私说明和模板版本。

仍由唯一身份导入入口统一解析，不形成多个建号入口。

### 7.3 字段映射

- 支持学校列名映射到平台标准字段；
- 映射方案按学校和模板版本保存；
- 必填、类型、长度、格式、文件内重复、库内重复和业务规则分层校验；
- 专业、组织、年级、班级先匹配候选，不直接凭文本写业务外键；
- 证件号、手机号等敏感字段在预检报告中脱敏。

### 7.4 重复处理

| 场景 | 默认策略 |
|---|---|
| 同一文件工号/学号重复 | 阻断并定位全部重复行 |
| 本租户已存在同工号/学号 | 更新候选或跳过，禁止再建账号 |
| 同一自然人同时教师/管理人员 | 一个账号，多身份/多角色 |
| 跨租户相同工号/学号 | 允许，必须按租户隔离 |
| 手机号已被本租户其他人占用 | 阻断人工处理 |
| 姓名相同但唯一标识不同 | 不自动合并 |
| 离职教师或历史学生重新导入 | 恢复/新业务关系，不覆盖历史记录 |

### 7.5 初始密码

正式学校推荐：

- 随机一次性初始密码或激活链接；
- 首次登录强制改密；
- 初始凭证短期失效；
- 禁止整校统一使用 `123456`；
- 凭证交付不写入明文导出文件；
- 演示版弱密码只存在于隔离演示租户并明确标识。

### 7.6 错误回执

- dry-run 不写库；
- 返回总行数、可导入、警告、错误和将新建组织数量；
- 下载只含错误行的 XLSX，附错误字段、原因和修复建议；
- 修正后重复上传，成功行不会重复创建；
- confirm 一个事务，硬错误整批回滚；
- 导入任务、操作者、文件哈希、结果和错误回执全审计。

### 7.7 验收

账号唯一、租户正确、组织专业班级匹配、初始凭证安全、角色绑定符合规则、错误回执可复现、重复导入幂等。

## 8. 预设五：业务关系预设

### 8.1 标准关系类型

| 关系 | 来源 | 产生的数据范围 | 生命周期 |
|---|---|---|---|
| 辅导员/班主任—班级 | 组织确认或导入 | 所带班级学生 | 任职有效期 |
| 任课教师—教学班 | 教学任务 | 本人教学班和学生 | 学期/任务有效期 |
| 课程负责人—课程 | 课程库 | 本课程建设数据 | 任命有效期 |
| 专业负责人—专业 | 组织关系 | 本专业方案、计划和预审 | 任命有效期 |
| 毕设导师—学生 | 毕设分配 | 本人指导学生 | 毕设批次 |
| 评阅/答辩人员—任务 | 评阅/答辩分配 | 被分配材料 | 任务有效期 |
| 实习指导教师—学生 | 实习分配 | 本人指导学生 | 实习批次 |
| 企业导师—实习学生 | 企业协议和分配 | 协议内必要信息 | 协议有效期 |
| 宿管—楼栋 | 宿舍管理分配 | 指定楼栋和入住学生必要信息 | 任职有效期 |
| 审批人—流程实例 | 当前流程节点 | 当前单据必要信息 | 节点完成即失效 |

### 8.2 统一字段

- 关系类型、主体用户、对象类型和对象 ID；
- 来源模块、来源业务 ID；
- 生效/失效时间；
- 关系状态；
- 创建方式：导入/业务生成/人工确认；
- 数据范围策略；
- 敏感字段上限；
- 历史责任快照。

### 8.3 规则

- 角色只回答“能做什么”，业务关系决定“能对谁做”；
- 关系以真实 ID 为准，禁止长期按姓名、班名文本匹配；
- 关系变化立即影响后续访问，但历史审批和操作保留当时快照；
- 业务关系不能自动抬高功能权限；
- 无来源关系不能为了“让页面有数据”随意创建；
- 多角色会话按当前激活角色解析关系，不无条件并集所有角色范围。

### 8.4 验收

每种关系至少验证建立、变更、失效、历史追溯、跨范围拒绝和跨租户拒绝。

## 9. 预设六：流程预设

### 9.1 流程模板组成

- 流程编码和版本；
- 发起角色与适用范围；
- 节点、责任角色和候选人解析规则；
- 条件分支、会签/或签、退回、撤回、转办、加签；
- 时限、催办、升级和超时处理；
- 自提自审回避；
- 附件、意见、必填原因和表单校验；
- 通知事件；
- 终态业务影响、归档和审计；
- 缺少审批人时的异常队列。

### 9.2 首批流程模板

| 业务 | 推荐默认链 | 关键可配置项 |
|---|---|---|
| 学生请假 | 学生 → 辅导员 → 长假学院/学工 | 天数分级、家长告知、销假/续假 |
| 困难认定/资助 | 学生 → 班级/学院审核 → 学工终审/公示 | 批次、等级、敏感字段、回避和公示范围 |
| 违纪处分 | 登记 → 学院 → 学工/学校终审 → 生效/解除 | 处分等级、法定程序、申诉和解除 |
| 课程新增/变更 | 课程负责人 → 学院 → 教务发布 | 哪些字段改动必须新版本 |
| 培养方案 | 专业负责人 → 学院 → 教务发布 | 适用年级、学分学时、实践和毕业要求 |
| 成绩更正 | 任课教师 → 学院 → 教务 | 更正窗口、材料、回避和发布通知 |
| 调停课 | 任课教师 → 学院/教务 → 冲突校验 → 发布 | 类型、提前时间、补课、通知范围 |
| 实习申请/变更 | 学生/教师 → 学院 → 实习管理 | 企业审核、安全、协议和家长知情 |
| 毕设题目/开题/成果 | 导师/学生 → 专业/学院 → 对应任务 | 轮次、评阅、答辩、重复率和材料 |

### 9.3 学校未细分时

默认采用最短合规链：业务责任人编制、上一级组织审核、校级业务部门发布。无学院层的学校允许折叠学院节点，但系统必须检查自提自审和终审责任。

### 9.4 不允许自动决定

审批层级、时限、处分和资助政策、成绩更正规则、家长通知门槛等属于学校政策。模板可推荐，但首次启用前必须集中确认并生成政策采用快照。

### 9.5 验收

正常、退回、撤回、超时、缺审批人、重复提交、自提自审、并发审批、终态回写、通知和审计全部有用例。

## 10. 预设七：字典与编号预设

### 10.1 字典分层

| 层级 | 示例 | 修改边界 |
|---|---|---|
| 国家/平台锁定字典 | 专业代码、系统状态、审计事件、权限代码 | 学校不可修改编码含义 |
| 平台标准、学校可扩展 | 学生类别、困难等级、处分类型、实习类型 | 可新增显示项，不得改变历史编码含义 |
| 学校自定义字典 | 校区简称、本校特色类型 | 学校维护，仍需审计和停用机制 |

首批字典包括学籍、学生类别、政治面貌、困难等级、资助、请假、处分、宿舍、课程、考核、成绩、预警、实习、毕设、就业、审批、消息和导入任务状态。

### 10.2 编号规则

- 学号、工号；
- 学院、专业、班级、课程、教学班；
- 请假、资助、处分、实习、毕设、审批等业务单号；
- 批次、导入、导出、归档和审计追踪号。

编号模板支持：学校代码、年份、学院、专业、流水号、重置周期、位数和示例预览。

### 10.3 规则

- 编码一经业务引用不得修改含义或重复分配；
- 名称可改，稳定编码不变；
- 流水号必须数据库并发安全；
- 编号规则变更只影响新数据；
- 手工编号要校验唯一并审计；
- 国标专业代码不得由学校自造替代。

### 10.4 验收

枚举兼容旧数据；编号在高并发下不重复；规则变更前后历史可追溯；停用字典不影响历史显示。

## 11. 预设八：安全与审计预设

### 11.1 默认安全策略

- 首次登录强制改密；
- 密码长度、复杂度、历史密码和有效期；
- 连续失败锁定、验证码和解锁；
- 会话空闲与最长有效期；
- 高风险角色可选 MFA；
- 登录设备、异地和异常行为提醒；
- Token、角色切换和权限版本失效；
- 平台支持人员必须经学校临时授权；
- 试点、演示和正式环境明确区分。

### 11.2 敏感数据策略

- 身份证、手机号、家庭经济、心理、处分、成绩等分级；
- 列表最小返回和默认脱敏；
- 查看明文需独立权限、用途原因和审计；
- 导出按角色、范围、字段和用途控制；
- 导出文件水印包含学校、用户、时间和追踪号；
- 下载链接短期有效；
- 批量和高风险操作二次确认。

### 11.3 审计策略

- 登录、改密、锁定、角色切换；
- 账号、组织、角色、权限和业务关系变更；
- 模板安装、升级、回滚和学校确认；
- 敏感明文查看、导出、批量操作；
- 审批、状态变化、终态回写；
- 标准采集、发布和权利状态变化；
- 接口密钥、Webhook、同步和失败重试；
- 审计日志不可由被审计人删除或改写。

### 11.4 私有化附加项

- 域名和 TLS；
- 数据库账号和密钥托管；
- 对象存储权限；
- 备份、恢复和灾难演练；
- 日志留存和磁盘告警；
- 离线授权和升级包验签；
- 第三方接口网络白名单。

### 11.5 验收

弱密码、暴力登录、会话过期、权限回收、明文查看、导出、跨租户、支持授权和审计防篡改测试通过。

## 12. 预设九：菜单与工作台预设

### 12.1 菜单生成公式

```text
最终菜单
= 租户已购模块
∩ 当前角色菜单权限
∩ 当前角色操作权限
∩ 学校业务开关
∩ 页面真实可用状态
```

不能购买了模块却因前端漏菜单无法进入，也不能只有菜单而后端无接口权限。

### 12.2 工作台组成

每个角色预设：

- 首页标题和角色身份提示；
- 今日待办、逾期和催办；
- 高频快捷入口；
- 本角色范围内统计卡；
- 风险和异常提醒；
- 最近处理记录；
- 帮助、导入状态和系统通知；
- 空数据、加载和异常三态。

### 12.3 典型角色

- 学校管理员：开户进度、账号异常、角色缺口、安全告警、接口失败；
- 教务管理员：校历、方案、任务、排课、成绩、考试和毕业待办；
- 学工管理员：请假、风险、资助、处分、宿舍和学院排行；
- 辅导员：所带班级待办、学生风险和家校事项；
- 任课教师：今日课程、教学任务、成绩录入、考试和调停课；
- 专业负责人：本专业标准、方案、课程、师资和条件缺口；
- 毕设/实习导师：本人指导学生、逾期材料和待审；
- 学生：本人课表、待办、申请、实习、毕设和毕业进度。

### 12.4 统计口径

- 卡片与明细使用同一后端口径；
- 显示统计周期、范围和更新时间；
- 角色切换后统计范围同步重算；
- 汇总不得泄露无权限明细；
- 空数据不伪造示例数；演示数据只能在演示租户。

### 12.5 验收

不同角色、模块开关、角色切换、无权限、空数据和异常场景均正确；所有卡片可下钻并与列表对账。

## 13. 预设十：消息与通知预设

### 13.1 通知模板组成

- 模板编码、业务事件和版本；
- 接收人解析规则；
- 站内信/微信/短信/邮件等渠道；
- 标题、正文、变量和跳转链接；
- 发送时机、延迟、合并、静默时段；
- 重试、降级、回执和失败队列；
- 敏感内容限制；
- 学校可修改字段和平台锁定字段。

### 13.2 首批事件

- 账号创建、激活、密码和安全告警；
- 导入预检完成、正式导入完成和失败；
- 待办产生、即将超时、已经超时、升级催办；
- 审核通过、退回、拒绝、撤回和转办；
- 培养方案、课表、成绩和考试发布；
- 请假、资助、处分、预警和家校提醒；
- 实习签到异常、周报逾期、协议和变更；
- 毕设任务、开题、评阅、答辩和逾期；
- 租户、模块、证书、接口密钥和服务到期。

### 13.3 规则

- 学校可以改显示文案和渠道，不能删除必要的安全告警；
- 模板变量必须白名单，缺变量不能发送残缺文案；
- 敏感信息不直接写进短信或锁屏可见通知；
- 同一事件幂等，防止重复轰炸；
- 批量通知限速并提供退订/偏好边界；
- 发送失败进入失败中心，不用假成功；
- 消息跳转仍需目标页面权限校验。

### 13.4 验收

变量、接收范围、重复、失败重试、静默时段、敏感内容、跳转权限、回执和审计全部通过。

## 14. 预设十一：上线检查预设

### 14.1 检查阶段

```text
租户开通
→ 基础配置
→ 组织师生
→ 角色关系
→ 专业教学
→ 安全接口
→ 场景抽测
→ 验收归档
```

### 14.2 检查域

| 检查域 | 阻断示例 | 警告示例 |
|---|---|---|
| 租户和模块 | 租户停用、套餐不一致、核心模块未授权 | 模块临近到期 |
| 管理员和账号 | 无首位校管、正式租户弱密码、账号跨租户 | 少量未激活账号 |
| 组织和师生 | 孤儿班级、学生无专业年级、重复唯一标识 | 负责人暂缺 |
| 角色和关系 | 关键角色无人、数据范围为空或越界 | 一人兼任过多高风险角色 |
| 流程 | 启用流程找不到审批人、自提自审 | 时限仍使用平台默认值 |
| 字典和编号 | 必填字典缺失、编号会重复 | 学校未自定义显示名 |
| 国标和专业 | 专业代码/层次不符、标准来源缺失 | 采用旧标准待升级 |
| 课程和方案 | 11 要素缺口、学时不平、方案无确认 | 使用平台推荐学分学时 |
| 教学运行 | 任务无课程/班级/学期、关键课程漏开 | 部分教师待分配 |
| 安全审计 | 租户隔离、审计、水印、脱敏未生效 | 可选 MFA 未开启 |
| 接口通知 | 必需接口不可用、消息无失败通道 | 非关键渠道未配置 |
| 数据真实性 | 正式租户存在演示种子数据 | 培训数据带 TEST 前缀待清理 |

### 14.3 验收机制

- 阻断项必须归零；
- 警告项必须有责任人、原因和完成期限；
- 检查项返回证据，不只返回红绿状态；
- 支持重跑、历史比较和按负责人分派；
- 验收时冻结租户配置、模板版本、师生统计、权限和检查结果快照；
- 生成学校可读的验收报告；
- 上线后一周继续监测登录、导入、权限、流程和接口异常。

### 14.4 验收

使用真实角色账号抽测“管理员建配置、教师看任务、辅导员看班级、学生看本人、越权账号被拒绝”主线；不以页面能打开代替业务可用。

## 15. 预设十二：模块业务预设

业务包只初始化规则、模板、目录、批次骨架和检查项，不伪造学校真实业务单据。正式租户不生成假请假、假成绩、假实习或假就业数据。

### 15.1 数字迎新包

- 迎新批次和时间窗；
- 报到流程、资格核验和任务清单；
- 信息采集字段、材料类型和审核规则；
- 绿色通道、未报到和异常处理；
- 学院/班级/宿舍等分配规则占位；
- 学生通知和现场工作台；
- 迎新完成后回写学生生命周期事件。

学校确认：批次时间、现场环节、材料、绿色通道政策和责任部门。

### 15.2 学工包

- 学生主档扩展、班级与辅导员；
- 请假销假续假；
- 困难认定、资助和公示；
- 奖惩、处分和解除；
- 宿舍、调宿、检查和异常；
- 心理关注最小必要权限；
- 风险预警、处置、谈话和家校联系；
- 统计、台账、通知和归档。

学校确认：审批层级、困难等级、处分制度、家长通知和敏感数据责任人。

### 15.3 教务与国标专业教学包

这是专业课程预设的正式落点，至少包括：

#### 国标基础

- 全量国家标准知识库搜索；
- 中职/高职专科/职业本科专业目录；
- 专业简介和专业教学标准；
- 公共基础课程、岗位实习和实训条件标准；
- 标准版本、替代、来源和引用快照。

#### 学校专业和课程

- 学校专业、方向和负责人；
- 职业面向、岗位、典型任务和能力图谱；
- 公共基础、专业基础、专业核心、拓展、选修、实践、实习和毕业项目课程包；
- 课程名称建议、性质、学分学时区间、理论/实践比例、考核方式；
- 前置、后续、替代、互斥和可合并关系；
- 师资、实训室和设备能力要求。

#### 培养与运行

- 人才培养方案骨架和版本；
- 专业年级/班级绑定；
- 实践环节和毕业要求；
- 学年学期、校历、节次和教学周；
- 学期教学计划/开课计划；
- 教学任务、教学班、任课教师和场地需求；
- 排课、选课、考务、成绩、预警和毕业审核默认规则；
- 教材、教学资源、评价、质量和归档模板。

学校配置不完整时可直接采用平台国标派生标准方案；学校必须确认具体课程名称、学分学时、学期、校历和正式发布范围。

### 15.4 岗位实习包

- 实习批次、类型和适用专业；
- 企业准入、岗位、协议和保险材料；
- 学生申请、分配、变更和退出；
- 学校教师和企业导师关系；
- 签到、周报、巡访、异常、安全和应急；
- 实习考核、成绩、归档和毕业条件联动；
- 对应国家岗位实习标准和专业教学标准引用。

学校确认：实习组织方式、企业审批、安全制度、签到规则、考核和异常上报链。

### 15.5 毕业设计包

- 毕设批次、适用专业和学生范围；
- 题目来源、题目审核和双选/分配；
- 导师、学生、评阅和答辩关系；
- 任务书、开题、中期、成果、查重、评阅和答辩节点；
- 材料模板、时限、逾期提醒和归档；
- 成绩、异常和毕业资格联动。

学校确认：是否启用、流程节点、材料、查重规则、评分结构和答辩制度。

### 15.6 就业包

- 就业批次和毕业生范围；
- 去向分类和证明材料；
- 就业、升学、参军、创业、待就业等状态；
- 企业、岗位、招聘和就业指导；
- 去向审核、变更、核验和统计；
- 敏感字段、数据上报和毕业后跟踪边界。

学校确认：去向口径、审核责任、证明材料、上报接口和跟踪期限。

### 15.7 跨模块联动

| 上游事件 | 下游动作 |
|---|---|
| 迎新完成 | 建立正式学生身份、班级关系和生命周期事件 |
| 辅导员/班级变化 | 重算学工数据范围和待办 |
| 培养方案发布 | 生成学期应开课程、毕业要求和学生方案视图 |
| 教学任务发布 | 生成任课关系、课表/成绩/考试前置数据 |
| 成绩发布 | 触发学业预警和毕业资格取数 |
| 请假与考试冲突 | 提示缓考等教务处理，不直接替学校决定 |
| 实习完成 | 回写实践完成和毕业审核证据 |
| 毕设终态 | 回写毕业资格审核证据 |
| 学籍毕业 | 进入就业批次和毕业后服务范围 |

### 15.8 验收

每个已购模块必须有：默认规则、角色、流程、字典、菜单、通知、导入导出、统计、审计、异常处理和上线检查；未购模块不初始化业务入口。正式租户零伪造业务数据。

## 16. 开户期间的自动执行顺序

```text
合同/订单确认
→ 选择学校开通版本
→ 创建租户、套餐和模块授权
→ 安装安全、字典和编号包
→ 安装角色、菜单、工作台和通知包
→ 创建首位学校管理员
→ 学校上传师生开户工作簿
→ 自动发现组织、专业、年级、班级和岗位
→ 学校集中确认组织树和关键负责人
→ 创建组织、账号、角色和业务关系
→ 安装已购模块业务包
→ 匹配国标并生成专业课程/培养方案草稿
→ 学校确认少量政策和正式发布范围
→ 生成学期教学任务等运行骨架
→ 执行上线检查
→ 验收并冻结配置快照
```

如果学校直接采用标准版，绝大部分步骤由系统后台完成；学校面对的是“确认清单”，不是数百项设置页面。

## 17. 默认值决策矩阵

| 情况 | 系统行为 | 是否阻断上线 |
|---|---|---:|
| 学校没有预先建组织 | 从师生表自动发现并生成待确认树 | 否，确认后继续 |
| 学校没有细分角色 | 安装平台内置岗位包并按关系自动绑定 | 否 |
| 学校没有流程制度电子版 | 使用推荐流程，学校集中确认 | 未确认则阻断对应流程启用 |
| 学校没有完整培养方案电子版 | 使用国标派生专业方案草稿 | 未经专业/教务确认不得正式发布 |
| 学校没有课程编码 | 按平台建议规则生成候选编码 | 学校确认后继续 |
| 学校没有通知文案 | 使用平台默认文案 | 否，安全必需消息不可关闭 |
| 学校没有接口 | 以平台内置能力运行，接口检查标不适用 | 否，除非合同要求该接口 |
| 学校没有实训条件明细 | 按国标生成条件缺口清单 | 可警告上线，但学校需给替代计划；硬性安全条件除外 |
| 学校关键岗位无人 | 允许合规兼任或指定代理 | 无人且流程无法解析时阻断 |
| 学校要求降低安全红线 | 拒绝安装该差异 | 是 |

## 18. 12 类预设的依赖关系

```text
学校开通
├─ 安全与审计
├─ 字典与编号
├─ 角色与权限
│  ├─ 菜单与工作台
│  └─ 流程
├─ 组织结构
│  ├─ 师生导入
│  └─ 业务关系
├─ 消息与通知
└─ 模块业务
   ├─ 国标/专业/课程/培养方案
   └─ 各模块运行规则
        ↓
     上线检查与验收
```

安装器必须按依赖排序，不允许先建教学任务再建专业、课程、班级和学期。

## 19. 商业卖点表达

推荐销售表达：

> 传统学校系统需要逐校配置角色、流程、字典、专业、课程和菜单。本平台内置 12 类职业院校预设，专业教学部分可追溯到教育部国家标准。学校导入真实师生数据后，系统自动识别组织和岗位，生成角色、流程、专业课程、培养方案和教学运行骨架；学校只确认本校差异，一周内即可进入使用。

可演示的证据：

1. 选择“高职标准版/中职标准版”；
2. 勾选专业和已购模块；
3. 上传一份师生工作簿；
4. 自动生成组织树和关系预览；
5. 展示国标专业来源和专业课程包；
6. 预览即将生成的课程、方案、角色和流程；
7. 一键应用并显示进度；
8. 切换不同角色展示菜单和数据范围；
9. 运行上线检查并生成验收报告。

禁止宣传“完全不需要学校确认”。真正的卖点是把复杂实施压缩为少量、清晰、有来源的确认，而不是替学校虚构制度和教学方案。

## 21. 后续施工顺序

12 类预设不是一次写死，应按以下顺序落地：

1. 国家标准库与全文检索；
2. 通用预设包、版本、依赖和安装引擎；
3. 学校开通版本与实施任务；
4. 组织自动发现和师生唯一导入；
5. 角色权限、业务关系和工作台；
6. 字典编号、安全、流程和通知；
7. 教务国标专业实施包；
8. 迎新、学工、实习、毕设、就业开局包；
9. 上线检查与验收报告；
10. 试点学校完整演练和模板迭代。

进入代码施工前，每个二级模块仍需按项目规范建立外部证据、生产级施工包和全部三级施工卡。本文件负责冻结 12 类预设的完整产品范围，防止以后漏项或换会话重新规划。
