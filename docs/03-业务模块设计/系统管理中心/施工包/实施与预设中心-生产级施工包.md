## 2. 业务目标和边界

学校完成开户后，通常只需准备教师、学生和必要的真实组织名称；系统根据学校类型、已购模块和问答答案生成开局方案，从导入数据推断组织和业务关系，学校确认预览后一次应用，并用上线检查封板。数据准备完整时可走 2 天快速线，正常交付采用 5—7 天。

平台运营负责创建租户、套餐和全局模板；学校实施管理员负责本校实施项目；学校管理员负责受控配置；身份/组织/教务/学工等责任人确认各自政策；审计员只读全过程。学校系统管理员不因此获得学生敏感业务明文。

预设覆盖 12 类：学校开通、角色权限、组织结构、师生导入、业务关系、流程、字典编号、安全审计、菜单工作台、消息通知、上线检查、模块业务。模块业务必须包含迎新、学工、教务、实习、毕设、就业及专业课程/培养方案标准入口。

## 4. 状态机与规则

`DRAFT → CONFIGURING → PREVIEW_READY → APPLYING → APPLIED → VERIFYING → READY_FOR_ACCEPTANCE → ACCEPTED`。

| 当前状态 | 动作/下一状态 | 约束 |
|---|---|---|
| DRAFT/CONFIGURING | 保存问答、方案、匹配；生成预览→PREVIEW_READY | 每次写入带 `version`，旧版本冲突返回 `DATA_CONFLICT` |
| PREVIEW_READY | 应用→APPLYING→APPLIED | 必须无阻断项，提交 `idempotencyKey`、`reason`、`confirmText` |
| APPLIED/VERIFYING | 自动检查→READY_FOR_ACCEPTANCE 或保持 VERIFYING | 检查来源为真实表/API，不以用户勾选代替 |
| READY_FOR_ACCEPTANCE | 验收→ACCEPTED | 所有 BLOCKER 通过，学校管理员确认责任与时间 |
| APPLIED~ACCEPTED | 发起变更→新草稿版本 | 不直接覆盖已安装快照；回滚也是一个新变更并留痕 |

应用失败记录 `APPLY_FAILED` 和失败步骤，可从幂等检查点重试；已验收项目不反向改状态，后续变更生成新版本。

## 5. 数据模型

| 表 | 作用 | 关键约束 |
|---|---|---|
| `t_system_implementation_project` | 每校当前/历史实施项目 | `tenant_id + project_no` 唯一；status/version；profile_code；owner_id；时间戳 |
| `t_system_implementation_section` | 12 类配置答案与预览片段 | `tenant_id + project_id + section_code` 唯一；JSON 内容仅存配置，不存密码/身份证明文 |
| `t_system_preset_installation` | 已安装方案快照/变更记录 | `tenant_id + installation_no` 唯一；source_version、snapshot_hash、status、parent_id |
| `t_system_implementation_check` | 自动/人工验收项 | `tenant_id + project_id + check_code` 唯一；severity/result/evidence/confirmed_by |

复用组织、用户、角色、权限、流程、课程和培养方案表。所有查询必须带 `tenant_id`；写入使用乐观锁；快照 JSON 只包含 ID、编码、来源版本和非敏感配置。

## 7. 权限总控实例化

权限链：租户模块授权 → 当前激活角色 → menu/API/button → SCHOOL 范围 → 实施项目归属 → 敏感边界 → 状态限制 → 审计。

| 角色 | 能力 | 禁止边界 |
|---|---|---|
| 平台运营管理员 | 建租户、下发全局模板；跨校操作必须显式目标租户 | 不查看学校学生敏感业务数据 |
| 学校实施管理员/学校管理员 | 配置本校项目、预览、应用；验收由学校管理员执行 | 不改套餐/平台模板；不因系统角色获得敏感业务明文 |
| 身份/组织/教务/学工管理员 | 仅确认本责任域配置段和检查项 | 不能应用整校方案或越域授权 |
| 审计员 | 查看版本、差异、事件和检查证据 | 只读，不能确认代签 |

高危动作 `apply/change/rollback/accept` 必须二次确认、填写原因，记录 actor/activeRole/tenant/project/before/after/result/traceId。前端隐藏不是授权；后端逐接口门禁。

## 8. 安全、Excel、通知、统计与归档

- Excel：师生导入继续复用标准 XLSX 入口；匹配回执可导出，公式注入转义、文件大小/MIME/列头校验、脱敏水印和审计。
- 附件：首轮不要求；政策确认材料后置到对象存储，禁止塞 JSON/base64。
- 通知/待办：阻断项、责任人待确认、应用完成/失败、验收到期需要；外部渠道未配置时保留站内待办。
- 统计：只统计实施进度、失败项、未匹配数量和版本，不统计敏感学生业务明细。
- 归档：验收后冻结快照、检查证据和操作链；不允许物理删除。
- 移动端：不需要，本模块为后台配置；配置结果通过既有 PC/移动端角色上下文生效。

## 9. 自动化测试和甲方验收
