# 数据导入与智能匹配生产级施工卡

## 0. 身份与现状

`systemAdmin.implementation.mapping` / `sys-implementation-mapping` / `/admin/system/implementation/data-mapping`；基线 `codex/mock@9957a5f`；状态 `implemented_partial`。统一师生导入、确定性组织/岗位候选、人工确认、组织与角色安装、原批次重检工作台已经接通；课程教学班和其他业务关系候选仍待后续阶段。

## 1. 业务结果与页面

学校上传标准教师/学生 XLSX，先 dry-run；系统从学院、专业、年级、班级、岗位、课程/教学班字段生成候选组织树和关系映射。唯一匹配自动建议，重复名称、缺父级、同编码异名和一人多岗位进入冲突队列；学校逐项合并、创建、忽略或改映射后再次校验。页面为导入批次区 + 可编辑树预览 + 冲突队列 + 统计/回执。

## 2. 字段、动作和规则

| 动作 | 校验 | API/权限 | 结果/审计 |
|---|---|---|---|
| 下载模板/上传校验 | xlsx；MIME/大小/列头/公式注入；不接受 CSV 账号开户 | 复用 identity import；`.mapping.manage` | 生成 batchNo，不落业务表 |
| 发现候选 | 只读取本批次和本租户现有 org/role | POST `/projects/{id}/mapping/discover` | `IMPLEMENTATION_MAPPING_DISCOVERED` |
| 确认映射 | action=`MATCH/CREATE/IGNORE`；MATCH 目标必须来自候选；缺父级禁止新建 | PUT `/mapping/decisions` | 决定写入 12 类中的 `identity_import` 配置段 |
| 安装并再校验 | 所有候选和教师角色已确认；batchNo+fileHash 未变化 | POST `/mapping/apply` | 同事务安装组织/内置角色，原批次自动重检 |
| 正式导入 | 重检 0 错误后，复用唯一身份导入确认接口 | POST `/system/identity-import/confirm-batch` | 原子创建账号并下载一次性凭据回执 |

自动匹配不是 AI 黑箱：首轮使用编码精确、规范化名称、父级路径和岗位字典规则；置信度仅作提示，低置信必须人工确认。教师—教学班必须来自真实教学任务；导师—学生、辅导员—班级等写既有关系表或受控配置，不能仅靠角色名猜测。

## 3. 权限、安全与数据

身份管理员处理账号字段，组织管理员处理组织树，教务管理员处理课程/教学任务，实施管理员可查看汇总但不可查看无权限的敏感明文。导入预览默认脱敏证件/手机/邮箱；下载错误回执加学校、操作者、时间水印并审计。临时文件按既有上传保留策略清理；快照不存初始密码。

候选/决定写入十二类中的 `identity_import` section；批次真实数据继续由现有导入底座管理。重复请求用项目状态、batchNo 和 fileHash 幂等；跨租户 batch 返回不存在。当前批次为进程内 30 分钟短时存储，多实例共享存储列为后续生产增强项。

## 4. 测试、施工与验收

测试：精确匹配、同名歧义、缺父级、跨校目标 ID、恶意公式、错误 MIME、重复文件、低置信未确认、普通管理员越权明文、正式导入不绕过 apply。施工：发现规则服务→API→树/冲突页→接既有导入器→回执/权限测试。回滚删除未应用候选 section 版本；已导入数据走安装回滚/业务停用，不物理删账号。

验收：只给教师和学生模板也能推断大部分组织树；所有不确定项清楚列出而非静默猜；确认后组织名称可后期修改且不破坏 ID 关系。
