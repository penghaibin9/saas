# 首次开局向导生产级施工卡

## 0. 身份与现状

`systemAdmin.implementation.wizard` / `sys-implementation-wizard` / `/admin/system/implementation/wizard`；状态 `implemented_partial`。12 类问答配置、保存恢复、预览、应用和运行预设编辑已接通；更细的条件跳题和责任人问答仍按学校配置逐步扩展。

## 1. 业务结果与页面

通过少量业务问答确定学校层次、已购模块、组织层级、身份来源、角色责任人、流程政策、安全策略和专业课程标准范围。不是固定长表：回答“无二级学院”后跳过学院负责人；未开通毕设则不问毕设导师。左侧步骤/完成度，中部一题或一组相关题，右侧实时显示将产生的组织/角色/流程变化；支持保存退出、返回修改和刷新恢复。

## 2. 字段与动作

| 字段/动作 | 后端校验 | API/权限 | 结果/审计 |
|---|---|---|---|
| schoolLevel | `HIGHER_VOCATIONAL/SECONDARY_VOCATIONAL/PILOT/DEMO/PRIVATE` | PUT section `school_opening`；`.configure` | 决定推荐 profile，不直接安装 |
| enabledModules | 必须是租户已授权模块子集 | PUT section `module_business` | 越权模块 `PRECONDITION_FAILED` |
| orgMode/levels | `college-major-grade-class` 等受控枚举 | PUT `organization` | 生成组织识别规则 |
| responsibilityAnswers | 引用本租户有效教师账号/岗位；可暂空但形成阻断项 | PUT role/workflow sections | 不写入业务审批人前先预览 |
| security/process policy | 推荐值可接受或改写；学校政策项必须确认 | PUT 对应 section | 保存 before/after |
| 生成预览 | 12 类必答问题完整且租户授权一致 | POST `/preview`；`.preview` | 状态 CONFIGURING→PREVIEW_READY |

每次 PUT 携带 projectVersion 和 answerRevision；重复同一 `idempotencyKey` 返回原结果。XSS 过滤、字符串长度、枚举和引用完整性由后端校验。

## 3. 状态、权限与安全

DRAFT 首答后进 CONFIGURING；可反复保存；PREVIEW_READY 修改答案会使旧预览失效并回 CONFIGURING；APPLYING 期间拒绝修改；ACCEPTED 只能查看并通过变更中心复制。学校实施管理员可答全局题；组织/身份/教务/学工管理员只可改责任域 section；审计员只读。问答不得采集师生身份证、初始密码或个人手机号。

## 4. 数据和辅助能力

答案写 `t_system_implementation_section`，`section_code + project_id + tenant_id` 唯一；JSON schema 版本化，保留 `source=USER/RECOMMENDED/INFERRED`。无需 Excel和附件；需要保存退出待办、未答统计和预览归档。

## 5. 测试、施工与验收

测试：分支跳题；越权模块；责任域越权；旧版本冲突；PREVIEW_READY 修改使预览失效；APPLYING 禁改；跨租户引用拒绝；重复保存幂等；脚本内容不回显。施工：schema/题库→section service/API→wizard state store→问答页→权限/刷新测试→build。回滚只停用入口，保留答案供恢复。

验收：高职标准版能在 10—20 个关键回答内形成 12 类预览；无学院学校不会被强迫创建学院；后退修改后推荐和预览同步变化；刷新不丢答案。
