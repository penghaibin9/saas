# 实施总览生产级施工卡

## 0. 身份与现状

`systemAdmin.implementation.overview` / `sys-implementation-overview` / `/admin/system/implementation/overview`；状态 `implemented_partial`。实施项目、方案、12 类配置进度、安装状态和验收入口已接入；责任人/阻塞明细仍以检查结果证据为准，后续继续细化。

## 1. 业务结果与页面

学校管理员进入即可知道“做到哪、卡在哪里、谁处理、下一步去哪里”。页面使用 `AppPageShell + AppSectionCard + AppProgressBar + AppStatusTag + AppOperationResult`：顶部项目/方案/状态/负责人；中部 12 类进度；右侧阻塞与责任人；底部最近版本和审计。loading/empty/error/no-permission 均为真实状态；空态只提供有 `create` 权限的“创建实施项目”。PC 管理页，不建移动端。

## 2. 字段、动作、状态

| 字段/动作 | 校验与状态 | API/权限 | 审计 |
|---|---|---|---|
| projectName/profileCode/ownerId/targetDate | 名称1—100字；方案必须来自目录；日期不得早于今天 | POST `/projects`；`.create` | `IMPLEMENTATION_PROJECT_CREATED` |
| 查看/继续实施 | 项目归本租户；按状态跳 wizard/presets/mapping/acceptance | GET `/projects/current`；`.view` | 查看不记敏感审计 |
| 修改负责人/目标日 | 非 ACCEPTED；带 version | PATCH `/projects/{id}`；`.update` | before/after |
| 重新计算进度 | 读取 12 配置段和检查结果，不允许前端伪算 | POST `/projects/{id}/progress/refresh`；`.check.run` | `PROGRESS_REFRESHED` |

状态只展示总包状态机；ACCEPTED 后不可改项目基本信息，后续走变更。

## 3. 数据/API/权限

使用 `t_system_implementation_project`；进度由 section/check 聚合，禁止缓存学生明细。列表和详情均 `tenant_id` 过滤；学校实施管理员/学校管理员可写，责任域管理员和审计员只读，学生/普通教师 403。重复创建活动项目返回 `DATA_CONFLICT`；并发更新返回 `VERSION_CONFLICT`；跨租户 ID 返回 `DATA_NOT_FOUND`。

## 4. 安全和辅助能力

不展示密码、身份证、手机号；负责人只返回账号 ID、姓名和岗位。无需 Excel/附件/打印；需要站内待办、进度统计和验收后快照归档。所有错误不泄露其他租户是否存在项目。

## 5. 测试、施工与回滚

测试：T-NORMAL 创建并聚合；T-EMPTY 空态；T-PERM 普通教师403；T-TENANT 跨校不泄露；T-CONFLICT 单校双活动项目冲突；T-VERSION 旧版本冲突；T-ACCEPTED 禁止修改。施工顺序：model/migration→service/router→api client→view/route/menu→pytest/node test/build。回滚保留旧 `/system/overview`，新菜单可关闭；数据库已有数据时不 drop，应用层停止入口。

验收：首次进入看到创建入口；建项目后 12 类均为“待配置”且下一步正确；刷新后仍一致；无权限账号看不到菜单且直链被拒绝。
