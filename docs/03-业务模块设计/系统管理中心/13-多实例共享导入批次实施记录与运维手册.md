# 多实例共享导入批次实施记录与运维手册

> 基线日期：2026-07-18  
> 迁移版本：`0107_shared_identity_batch`、`0108_shared_import_batches`、`0109_implementation_permissions`  
> 状态：已完成

## 1. 解决的问题

原身份导入、学生主档导入、21 域历史数据迁移和旧导入契约把 Dry-Run 后的有效行放在 Python 进程字典中。请求换到另一台 API、进程重启或滚动发布时，确认操作会得到“批次不存在”。本阶段已移除后端全部此类进程内导入批次。

## 2. 真实共享表

| 表 | 范围 | 保存内容 |
|---|---|---|
| `t_identity_import_batch` | 师生账号、组织/角色匹配、六类业务关系接续 | 预检载荷、错误、关系候选、文件哈希、操作者、状态和租约 |
| `t_shared_import_batch` | 学生主档、21 域历史迁移、旧契约兼容入口 | 命名空间、有效行、错误、请求幂等键、状态和租约 |
| `t_student_import_batch` | 原有业务台账 | 总行数、成功/失败数、最终状态；继续用于页面列表与审计 |

初始密码不写数据库；只在首次成功确认的响应中生成一次 XLSX 回执。重复确认只返回不含密码的公共结果。

## 3. 状态机与并发规则

`DRY_RUN_PASSED/VALIDATED → CONFIRMING → SUCCESS/IDENTITY_CONFIRMED`。

- 确认时使用数据库行锁和随机租约令牌；同一批次同一时刻仅一个实例可执行。
- 5 分钟内的活跃租约阻止另一实例重复写入；进程异常退出后，过期租约可被安全接管。
- 业务写入失败会回滚整批事务并释放租约，允许排障后重试。
- 同一租户、命名空间和 `requestId` 形成幂等边界；相同请求号指向不同批次时拒绝。
- 所有查询至少同时限定租户、命名空间和批次号；身份开户批次还绑定上传操作者。
- 预检批次默认有效 24 小时，已确认且仍需安装业务关系的身份批次保留 7 天。

## 4. 数据格式兼容

历史迁移的校验结果可能包含日期、时间和 Decimal。共享层使用带类型标记的 JSON 编解码，跨实例读取后恢复原 Python 类型，避免学期、校历等真实主表写入时发生类型漂移。

## 5. 隐私与清理

运行：

```powershell
python scripts/cleanup_shared_import_batches.py
python scripts/cleanup_shared_import_batches.py --apply --purge-after-days 30
```

第一条只报告数量；第二条将到期载荷中的师生行、错误、关系和公共结果清空，并物理删除已超过保留期的批次。生产环境应每天调度一次；脚本幂等，可在多台调度节点重复触发。

## 7. 部署要求

所有 API 实例必须连接同一业务数据库，并完成 `0109` 迁移后再接流量。数据库不可用时导入预检失败关闭，不允许退回单机内存模式。负载均衡无需会话粘滞；下一阶段真实服务器部署将把迁移、健康检查和定时清理纳入发布流程。
- 最新迁移口径：在原有 0107/0108/0109 基础上，已追加 `0110_change_impact_analysis` 与 `0111_immutable_acceptance_summary`；所有实例接流量前以 `alembic upgrade head` 和 `/health/ready` 的当前/期望一致为准。
