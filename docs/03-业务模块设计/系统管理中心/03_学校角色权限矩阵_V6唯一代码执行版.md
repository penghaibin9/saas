# 0. 最终权限决策

```text
租户有效
AND 平台已授权
AND 学校已启用
AND 当前激活角色
AND 权限包/原子动作
AND NOT 显式DENY
AND 组织/行级范围
AND 业务身份
AND 流程动作策略
AND 业务状态机
AND 敏感数据策略
AND 有效日期
= ALLOW
```

硬规则：

- 无法确定即DENY；
- 多角色不默认并集；
- 菜单可见不等于后端可访问；
- 批处理不默认SYSTEM全权；
- 平台角色与学校角色不得混用；
- 前端不得复制最终权限算法；
- 关键ALLOW和所有DENY必须可生成decisionTraceId。

# 4. 9个权限治理施工包

这些施工包不创建新路由，映射到01文档的canonical page。

## RBAC-01｜交付角色、权限包与学校自定义角色

- 正式页面：`SYS-06 /admin/system/roles`
- 交付角色`DELIVERED`不可直接修改；
- 学校角色`CUSTOM`必须从模板复制并记录sourceTemplate/sourceVersion；
- 默认配置权限包，原子权限仅高级视图；
- 学校角色的最终权限必须是平台交付上限的子集；
- 模板升级只展示diff，不自动注入高风险权限；
- `*`和模块级通配进入退役队列。

必须测试：
1. 越过模板上限的保存返回403；
2. 模板升级不改变已激活学校角色；
3. 旧RolePermission兼容读一致；
4. 无owner权限不能进入交付包。

## RBAC-02｜成员、业务身份与有效期

- 正式页面：`SYS-07 /admin/system/role-assignments`
- 固定角色成员必须有来源、理由、effectiveAt、expiresAt；
- 任课、导师、评阅、答辩、实习指导使用自动业务身份；
- 停用、离职、任务转交立即覆盖未来有效期；
- 高权角色按季度复核，普通角色半年，业务身份按学期/批次；
- 到期回收采用定时任务和读取时校验双保险。

必须测试：
1. 到期后两实例均失效；
2. 任务转交不保留旧身份；
3. 当前激活角色隔离；
4. 手工应急业务身份自动到期。

## RBAC-03｜组织安全树、继承与显式DENY

- 正式页面：`SYS-08 /admin/system/data-scopes`
- 顺序：DENY > 敏感专项 > 业务关系 > 直接ALLOW > 继承ALLOW > 默认拒绝；
- 支持未来生效组织树；
- 支持ALLOW_SELF、ALLOW_CHILDREN、ALLOW_SELECTED、DENY_NODE、DENY_DOMAIN；
- 数据范围引用统计必须来自结构化`t_data_scope_rule`/scope policy；
- Role.remark只作为迁移来源，不再作为权威。

必须测试：
1. 父级ALLOW被子节点DENY覆盖；
2. 未来组织树激活前不改变权限；
3. 页面模拟和真实API同决策；
4. 跨租户targetId不可引用。

## RBAC-04｜业务流程动作安全

- 正式页面：`SYS-14 /admin/system/workflows`
- 功能域权限与流程动作权限分开；
- 动作至少覆盖发起、查看、编辑、提交、审批、退回、撤回、取消、转交、代办、人工推进、撤销结果；
- 节点参与者引用角色/业务身份resolver，不引用具体姓名；
- 在途实例版本策略只能是SNAPSHOT、DYNAMIC、MIGRATE；
- 导师不能默认最终评阅自己的学生，答辩秘书没有专家评分权。

必须测试：
1. 有菜单权限无审批动作时拒绝；
2. 职责分离冲突后端拒绝；
3. 在途实例按版本策略执行；
4. 人工推进必须理由和审计。

## RBAC-05｜安全变更、复核、激活与回滚

- 正式页面：`SYS-09 /admin/system/security-changes`
- 状态：DRAFT→PENDING_REVIEW→APPROVED→SCHEDULED→ACTIVATED/REJECTED/ROLLED_BACK；
- 草稿、批准、排期不改变真实权限；
- 激活生成securityRevision/securityTimestamp；
- 激活事务与outbox失效事件必须可恢复；
- 一人阶段允许加强型自复核：MFA、确认文本、最短延迟、影响预览、不可关闭审计。

必须测试：
1. 激活失败不产生半生效；
2. 并发激活只有一个成功；
3. Redis和两实例同步失效；
4. 回滚恢复前一快照并生成新revision。

## RBAC-06｜访问解释与拒绝诊断

- 正式页面：`SYS-10 /admin/system/access-governance`
- 查询输入：userId、activeRole、client、action、objectType/objectId、atTime；
- 输出：最终ALLOW/DENY、命中角色、权限包、原子权限、组织路径、DENY、业务身份、流程策略、敏感策略、有效期和revision；
- 真实403返回decisionTraceId；
- 无权查看对象时隐藏对象敏感信息，避免成为枚举器；
- 解释必须来自PolicyDecision核心，不允许前端重算。

必须测试：
1. 真实403可复现；
2. 关键ALLOW解释与实际一致；
3. 无权解释目标时不泄露存在性；
4. 旧revision解释清楚标记历史。

## RBAC-07｜批处理和系统任务授权

- 正式页面：`SYS-16 /admin/system/jobs`
- 每个任务必须携带tenantId、jobType、initiator、delegatedSubject、permissionRevision、scopeSnapshot或systemTaskPolicy、purpose、idempotencyKey；
- 只允许USER_DELEGATED、SERVICE_POLICY、TENANT_SYSTEM_TASK三类；
- TENANT_SYSTEM_TASK只能执行注册动作和明确范围；
- 文件/导入/导出/归档任务复用已合并main的公共文件与数据交换底座；
- 任务重试不得扩大原始数据范围。

必须测试：
1. 跨租户jobId返回404；
2. 旧权限revision按策略拒绝或重算；
3. 重试幂等；
4. 导出不越过提交者数据范围。

## RBAC-08｜权限复核、职责分离与紧急访问

- 正式页面：`SYS-10 /admin/system/access-governance`
- 页签：定期复核、职责分离、异常权限、紧急访问、安全历史；
- 高权季度复核，普通半年，业务身份按期；
- 紧急访问必须MFA、事件/工单、短时、范围限制、全程横幅和自动到期；
- 默认无人永久持有break-glass；
- 复核结果必须是保留、调整、回收或例外，不允许只打勾无后续。

必须测试：
1. 紧急会话到期后即时失效；
2. 职责冲突在后端强制；
3. 复核回收产生安全变更；
4. 平台管理员不能用学校紧急角色。

## RBAC-09｜文件与数据交换权限包

### 9.1 为什么必须新增

公共文件底座合并后，当前仍存在两个权限过宽问题：

```text
systemAdmin.file.manage
systemAdmin.user.import
```

前者同时被用于治理页面、扫描重试，并在公共文件授权中被识别为文件管理员；后者同时承载任务查看、确认、下载和撤销。成熟控制面必须将“治理元数据”“业务内容访问”“高危执行”拆开。

### 9.2 文件权限包

| 权限包 | 原子权限 | 允许 | 明确不允许 |
|---|---|---|---|
| FILE_GOVERNANCE_VIEW | `systemAdmin.fileGovernance.view` | 看容量、状态、异常数量 | 看文件内容 |
| FILE_QUOTA_ADMIN | `.quota.manage` | 配置学校/模块配额 | 扩大平台商业上限 |
| FILE_RETENTION_ADMIN | `.retention.manage` | 配置保留策略 | 立即删除文件 |
| FILE_CLEANUP_EXECUTOR | `.cleanup.execute` | 执行已绑定预演 | 跳过引用/法律保留 |
| FILE_LEGAL_HOLD_ADMIN | `.legalHold.manage` | 设置/解除保留 | 默认预览原文 |
| FILE_SCAN_OPERATOR | `.scan.retry` | 查看扫描健康、重试失败扫描 | 下载感染文件 |
| FILE_CONTENT_ACCESS | 业务模块权限+binding+resolver | 按业务关系预览/下载 | 因系统治理身份全盘访问 |

迁移完成后，`systemAdmin.file.manage`只作为旧兼容别名，并在一个发布周期内告警；不能继续作为内容访问依据。

### 9.3 数据交换权限包

| 权限包 | 原子权限 | 范围 |
|---|---|---|
| DATA_EXCHANGE_VIEW_OWN | `systemAdmin.dataExchange.viewOwn` | 本人创建任务 |
| DATA_EXCHANGE_VIEW_TENANT | `.viewTenant` | 本校全部任务 |
| DATA_EXCHANGE_CONFIRM | `.confirm` | 确认被授权类型 |
| DATA_EXCHANGE_DOWNLOAD | `.download` | 下载授权回执 |
| DATA_EXCHANGE_REVOKE | `.revoke` | 撤销导出 |
| DATA_EXCHANGE_RETRY | `.retry` | 重试失败任务 |

权限仍要叠加moduleCode、import/export type、数据范围和敏感等级。能看任务不代表能下载凭据回执。

### 9.4 文件访问解释链

访问解释器必须增加：

```text
tenant一致
→ FileObject有效
→ scanStatus可用
→ FileBinding有效
→ action权限
→ 业务resolver
→ 数据范围/业务身份
→ sensitivity策略
→ legal hold/归档状态
→ allowedActions
```

治理角色的决策示例：

```text
ALLOW governance metadata
DENY file preview
reason = GOVERNANCE_ROLE_HAS_NO_CONTENT_RELATION
```

### 9.5 服务任务权限

file worker、scan worker、cleanup worker和Import/Export worker必须使用注册的ServicePolicy：

- 明确jobType；
- 明确tenant；
- 明确允许读取的字段与字节；
- 不使用普通人的长期token；
- 不具有跨租户通配；
- 任务证据带policyVersion和traceId。

### 9.6 迁移步骤

```text
登记当前systemAdmin.file.manage消费者
→ 新权限码和权限包
→ 页面/接口双权限兼容
→ file_access_service移除治理权限=内容管理员
→ 数据交换动作拆分
→ 角色模板升级差异
→ 权限激活
→ 访问解释与回归
→ 旧别名告警
→ 一个发布周期后退役
```

### 9.7 必测用例

- **RBAC09-T01**：文件治理员可看容量但不能预览普通材料
- **RBAC09-T02**：心理材料即使是治理员也不能枚举
- **RBAC09-T03**：扫描操作员能重试但不能下载感染文件
- **RBAC09-T04**：任务查看员不能确认或下载凭据
- **RBAC09-T05**：数据交换管理员可看本校任务但不能跨租户
- **RBAC09-T06**：worker只能处理注册jobType和tenant

# 6. 迁移与兼容顺序

```text

→ 权限包映射
→ DELIVERED模板版本
→ 学校角色来源
→ 成员有效期
→ 范围结构化与DENY
→ 安全草稿双写
→ 激活读切换
→ 访问解释对账
→ 批处理授权
```
