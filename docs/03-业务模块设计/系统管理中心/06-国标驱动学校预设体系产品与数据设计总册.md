## 1. 已冻结的产品决策

| 决策 | 冻结结论 | designSource |
|---|---|---|
| 标准依据 | 专业、课程、实践、毕业要求首先依据教育部现行国家教学标准；地方和学校制度只做有来源的加层，不得覆盖国标底线 | `user_decision + external_evidence` |
| 国标全量入库 | 职业教育国家教学标准体系的目录、文件、全文、条款和结构化关系按全量知识库设计，供检索和预设生成；全文对学校开放受权利状态控制 | `user_decision + external_evidence` |
| 实施周期 | 对外按“一个自然周内完成标准实施”设计；资料齐全的标准学校允许走 2 天快速开通 | `user_decision` |
| 学校不会配置 | 提供“一键标准版”，学校不必先完成细致的岗位、课程和流程设计，也能直接采用平台预设开通 | `user_decision` |
| 学校责任 | 平台可以生成推荐方案，但正式培养方案、课程名称、学时学分和发布范围必须由学校确认并留下责任记录 | `external_evidence + project_rule` |
| 成熟系统参考 | 正方、强智等成熟教务系统公开材料用于验证业务链路和交付形态，不作为国家标准或课程内容权威来源 | `user_decision + project_rule` |
| 已发布数据保护 | 已绑定在读年级、已生成教学任务或已进入学期运行的数据不被模板升级静默覆盖 | `project_rule + existing_code` |

本体系的产品目标不是“替学校随便编一张课表”，而是：

> 把国家标准转化为可追溯、可选择、可确认、可执行、可升级的学校实施包，使配置能力弱的职业院校也能在一周内获得可运行的组织、权限、专业、培养方案、课程和教学任务底座。

## 2. 国家标准事实源与效力顺序

### 2.1 首批权威来源登记

| 证据 ID | 权威来源 | 能直接约束本系统的内容 | 不能直接证明的内容 |
|---|---|---|---|
| `MOE-CATALOG-2021` | [教育部《职业教育专业目录（2021年）》](https://www.moe.gov.cn/jyb_xwfb/gzdt_gzdt/s5987/202103/t20210322_521664.html) | 中职、高职专科、职业本科三级专业分类、专业名称和代码；发布时 19 大类、97 专业类、1349 专业 | 不能直接给出每校最终课程名称、学分和学期安排 |
| `MOE-PROFILE-2022` | [教育部新版职业教育专业简介](https://www.moe.gov.cn/jyb_xxgk/s5743/s5744/A07/202209/t20220907_659058.html)及[专业简介索引](https://www.moe.gov.cn/s78/A07/zcs_ztzl/2017_zt06/17zt06_bznr/bznr_zdzyxxzyml/) | 全部专业的职业面向、培养目标、主要专业能力和主要课程方向，是专业包推荐层的重要输入 | 不能替代更新后的专业教学标准，也不能替学校发布培养方案 |
| `MOE-STANDARD-2025` | [教育部758项新版职业教育专业教学标准](https://www.moe.gov.cn/jyb_xwfb/gzdt_gzdt/s5987/202502/t20250211_1178746.html)及[国家教学标准专栏](https://www.moe.gov.cn/s78/A07/zcs_ztzl/2017_zt06/) | 专业名称代码、入学要求、学制、职业面向、目标规格、课程与学时、师资、条件、质量保障、毕业要求等 11 类要素 | 标准为学校自主设置课程留有空间，不能据此声称全国统一使用同一课程表 |
| `MOE-PUBLIC-2020` | [教育部中职公共基础课程标准说明](https://www.moe.gov.cn/jyb_xwfb/s271/202001/t20200120_416130.html)及[公共基础课程标准索引](https://hudong.moe.gov.cn/s78/A07/zcs_ztzl/2017_zt06/17zt06_bznr/bznr_zzggkdg/) | 中职公共基础必修课程范围、课程目标、内容及学业质量要求；公共基础课总量约束 | 不能直接套用于高职专科和职业本科全部课程政策 |
| `MOE-INTERNSHIP-2021` | [八部门《职业学校学生实习管理规定（2021年修订）》](https://www.moe.gov.cn/jyb_xwfb/gzdt_gzdt/s5987/202201/t20220121_595541.html)及国家岗位实习标准 | 实习是教学环节；学校、实习单位、学生责任和全过程管理红线 | 不能替代每个专业的具体岗位实习内容标准 |
| `MOE-CONDITION` | [职业教育国家教学标准体系](https://www.moe.gov.cn/s78/A07/zcs_ztzl/2017_zt06/)中的实训教学条件建设标准 | 专业教学所需实训场所、设备和条件要求 | 不能证明学校已经具备对应场地设备 |
| `MOE-REFORM-2026` | [教育部2026年职业教育教学关键要素改革意见](https://www.moe.gov.cn/srcsite/A07/zcs_zhgg/202602/t20260212_1428773.html) | 专业、课程、教材、教师、实习实训标准协同；产业和真实工作场景进入课程；标准动态调整方向 | 不能作为某个专业的具体课程清单 |

查阅日期统一登记为 `2026-07-18`。后续每个专业包仍必须绑定具体专业教学标准原文，不允许只引用上表的新闻稿或索引页。

### 2.2 标准效力顺序

出现冲突时按以下顺序裁定：

1. 现行法律、行政法规和教育行政部门强制性规定；
2. 教育部现行职业教育专业目录；
3. 当前专业对应的国家专业教学标准；
4. 公共基础课程、岗位实习、实训条件等国家专项标准；
5. 省级教育行政部门有明确来源的实施要求；
6. 学校正式发布的人才培养方案和管理制度；
7. 平台依据上述标准形成的推荐预设；
8. 成熟系统公开做法和平台 AI 建议。

第 7、8 层不得冒充国标。系统页面必须显示每项内容的 `来源层级、来源文件、版本、定位、生成方式`。

### 2.3 标准更新规则

- 只从教育部或有权机关官方页面登记国家标准；禁止从培训文章、公众号转载或竞品页面导入为国家标准。
- 标准原文登记 URL、发布日期、适用范围、版本、文件摘要、原文文件哈希和替代关系。
- 新标准发布后，旧标准标记 `SUPERSEDED`，不物理删除；已执行年级继续保留历史依据。
- 新标准先进入“待评估”，由平台生成差异报告，审核后才能发布新版预设包。
- 标准更新不得直接修改租户业务数据；只生成升级建议和影响清单。

### 2.4 全量入库和检索

国标不只保存链接：目录、原始文件、全文、页面、章节、条款、表格和结构化关系全部进入平台知识库，并支持学校按专业、代码、岗位、能力、课程领域、实训条件和毕业要求搜索。详细数据模型、采集解析、中文全文检索及版权展示门禁见：[08-职业教育国家标准全量入库与检索实施方案.md](./08-职业教育国家标准全量入库与检索实施方案.md)。

教育部网站声明禁止商业机构对网站内容进行商业性的原版原式转载，因此“全量入库”和“商业产品完整展示”分开控制：数据库按全量能力建设，学校端根据权利状态显示全文、摘要或官方原文链接。

## 3. 产品定位与销售表达

正式卖点定义为：

> 国标可追溯的职业院校快速实施平台。系统将专业教学标准转化为专业、课程、培养方案、实践环节、毕业要求、岗位角色和教学任务预设；学校可一键采用，也可按本校特色调整，全程保留来源、差异、审批和历史版本。

可以对外证明的能力：

- 每个专业包能追溯到教育部目录、专业简介和专业教学标准；
- 每门推荐专业课能说明对应职业面向、典型任务、能力要求和标准条款；
- 专业包安装后可继续生成培养方案、学期开课计划和教学任务，不只是展示课程名单；
- 学校不会配置时可采用平台标准方案，会配置时可保留本校特色；
- 标准升级不会破坏在读年级和已发布教学数据；
- 一周实施过程具有预检、差异、审批、上线检查和验收报告。

禁止对外宣称：

- “教育部认证软件”或“教育部指定系统”；
- “平台课程表就是国家统一课程表”；
- 未实际登记标准原文时声称某专业已完成国标适配；
- 只生成了模拟数据却声称学校已正式上线。

## 4. 总体架构：标准库、预设库、租户运行库三库分离

```text
国家标准库（平台全局、只读来源）
  ├─ 专业目录/简介/教学标准
  ├─ 公共基础课程标准
  ├─ 岗位实习标准
  └─ 实训条件标准
            ↓ 规则化映射 + 人工复核
预设模板库（平台全局、版本化黄金配置）
  ├─ 办学层次包
  ├─ 学校基础包
  ├─ 专业群包
  ├─ 专业实施包
  ├─ 角色/流程/安全包
  └─ 上线验收包
            ↓ dry-run + 学校选择/授权 + 原子安装
学校租户运行库（学校正式业务数据）
  ├─ 组织/账号/岗位/角色
  ├─ 专业/课程库
  ├─ 培养方案/实践环节/毕业要求
  ├─ 学期教学计划/教学任务/排课
  └─ 实习/成绩/毕业审核/审计
```

三库分离是硬边界：

- 国家标准库不保存学校业务数据；
- 预设库只保存可复用配置和参数，不保存某校师生明细；
- 租户运行库保存安装后的独立副本和来源快照；
- 学校修改本校副本不会反向污染平台黄金模板；
- 模板升级通过差异包进入租户，禁止直接跨租户批量更新。

## 6. 三种学校采用模式

### 6.1 一键标准版（默认推荐）

适合尚未细分岗位、流程、专业方向或没有完整电子化培养方案的学校。

学校仅需确认：

1. 办学层次和基本学制；
2. 当前招生专业和年级；
3. 学年学期和上课节次；
4. 首位学校管理员、教务负责人、专业负责人；
5. 是否授权采用平台推荐的标准专业实施包；
6. 正式启用日期。

系统自动采用默认值并生成组织、角色、流程、专业、课程、培养方案和教学任务草稿。默认值必须满足国标底线；涉及学校政策但学校未细分的内容，使用“安全保守默认值”，同时进入《采用默认配置清单》。学校负责人一次性确认后方可发布。

### 6.2 引导选择版

适合已经有部分制度和培养方案的学校。学校在向导中选择专业方向、课程组合、实践安排、审批层级和业务开关，系统实时展示与标准模板的差异和风险。

### 6.3 学校自定义版

适合制度成熟的学校。在不低于国标和平台安全红线的前提下，允许学校：

- 调整具体课程名称、开设学期、学分和学时；
- 增加地方、行业、企业和学校特色课程；
- 调整审批人和组织分工；
- 配置专业方向、选修模块和毕业条件加项。

删除国标要求领域、降低底线或放宽安全权限时必须触发阻断或高风险审批，不能静默保存。

## 7. 专业实施包的数据结构

每个专业实施包必须完整覆盖专业教学标准的 11 类要素，不得只做课程清单。

| 国标要素 | 平台结构化对象 | 最低字段 |
|---|---|---|
| 概述 | 专业包说明 | 适用范围、来源、版本、说明 |
| 专业名称与代码 | 国家专业主档 | 层次、大类、专业类、名称、代码 |
| 入学基本要求 | 招生适用条件 | 学历/对象、学校确认项 |
| 基本修业年限 | 学制规则 | 基本学制、弹性边界、学期数 |
| 职业面向 | 职业与岗位组 | 职业类别、岗位、行业、证书参考 |
| 培养目标 | 目标条目 | 知识、能力、素质总体目标 |
| 培养规格 | 能力图谱 | 通用能力、专业能力、职业素养、典型任务 |
| 课程设置及学时安排 | 课程领域与方案模板 | 模块、性质、建议课程、学期、学分/学时区间、实践比例 |
| 师资队伍 | 师资要求 | 数量/结构建议、教师能力、企业经历、负责人要求 |
| 教学条件 | 条件要求 | 场地、设备、信息化、校企合作、实训条件 |
| 质量保障与毕业要求 | 质量/毕业条目 | 诊改、评价、学分、课程、实践、实习、毕业条件 |

### 7.1 岗位—任务—能力—课程追溯链

```text
国标条款
  → 职业面向
  → 典型岗位
  → 典型工作任务
  → 能力/素质要求
  → 课程领域
  → 平台推荐课程
  → 学校正式课程
  → 培养方案课程
  → 教学任务/实训项目
  → 考核证据/毕业审核
```

每一条推荐专业课至少记录：

- 推荐课程名称和课程领域；
- 对应专业代码与办学层次；
- 对应标准条款、原文定位和标准版本；
- 对应岗位、任务、能力；
- 课程模块和必修/选修建议；
- 建议学期、学分、总学时及理论/实践区间；
- 前置、后续、替代和可合并课程；
- 考试/考查/项目考核建议；
- 实训场地与设备能力标签；
- 教师能力标签；
- 是否国标明确、国标领域映射、地方要求、学校特色或平台建议。

其中课程名称、具体学时学分和开设学期如果不是国标原文明确值，必须标记 `RECOMMENDED`，不得标记 `NATIONAL_MANDATORY`。

### 7.2 课程分类统一枚举

为兼容现有 `t_aa_course`，首期统一为：

- `PUBLIC_BASIC`：公共基础；
- `PROFESSIONAL_BASIC`：专业基础；
- `PROFESSIONAL_CORE`：专业核心；
- `PROFESSIONAL_EXTENSION`：专业拓展；
- `PUBLIC_ELECTIVE`：公共选修；
- `PRACTICE`：集中实践；
- `INTERNSHIP`：岗位实习；
- `GRADUATION_PROJECT`：毕业设计/毕业项目。

现有代码中的 `DISCIPLINE_BASIC / MAJOR_CORE / MAJOR_ELECTIVE` 需要在实施阶段建立兼容映射，不能直接改枚举导致旧数据失效。

### 7.3 专业方向

国家专业与学校专业方向分离：

- 国家专业代码只存在一份；
- 学校可以在同一国家专业下建立多个方向；
- 方向包只能新增或替换拓展模块，不能把国家专业改成另一个专业；
- 学生绑定“国家专业 + 学校方向 + 年级培养方案版本”；
- 专业方向停用不影响历史学生和历史方案。

## 8. 模板组合、依赖和版本

### 8.1 组合公式

```text
学校最终配置
= 平台安全基础包
+ 办学层次包
+ 学校运行基础包
+ 公共基础课包
+ N 个专业实施包
+ 可选专业方向包
+ 学校差异层
```

### 8.2 版本规则

模板版本采用 `主版本.次版本.修订版本`：

- 主版本：标准依据或数据结构发生不兼容变化；
- 次版本：新增专业能力、课程推荐、校验规则；
- 修订版本：错别字、链接、展示或不影响业务的修订。

每个安装动作保存：模板版本、标准版本、参数快照、安装人、确认人、安装时间、生成对象清单、差异和校验报告。

### 8.3 安装状态机

```text
DRAFT
→ VALIDATED
→ READY_TO_APPLY
→ APPLYING
→ APPLIED
→ SCHOOL_CONFIRMING
→ PUBLISHED
→ SUPERSEDED
```

异常状态：`VALIDATION_FAILED / APPLY_FAILED / ROLLED_BACK / UPGRADE_BLOCKED`。

### 8.4 安装硬规则

- 所有安装先 `dry-run`，展示新增、更新、跳过、冲突、阻断数量；
- 一个安装批次必须原子执行，硬错误时整批回滚；
- 重复执行同模板同版本必须幂等；
- 模板依赖按拓扑顺序执行；
- 已发布培养方案不原地覆盖；
- 已存在学校对象时优先映射、复制或跳过，不按名称盲目覆盖；
- 所有跨租户操作必须逐租户授权、逐租户留痕；
- 模板升级先比较，不默认应用。

## 12. 一键标准版默认策略

学校没有细分配置时，平台使用以下默认原则：

- 角色采用内置岗位包，不让学校逐项勾权限；
- 数据范围优先从学院、专业、班级、教学任务、辅导员、导师和实习指导关系自动推导；
- 审批采用最短合规链，例如“专业负责人编制 → 学院审核 → 教务发布”；学校无学院层时可折叠，但编制与发布原则上不由同一人完成；
- 专业课程采用国标课程领域映射的推荐课程名，不伪造国标原文名称；
- 不确定的学分、学时和学期采用推荐区间或平台默认值，并在发布前集中列为待确认项；
- 岗位实习、实训安全、敏感数据、跨租户隔离和审计红线不能由默认模式关闭；
- 不启用学校未购买模块；不因模板存在而越过套餐授权；
- 学校确认时生成《平台标准方案采用声明》和完整配置快照。

默认模式的目的不是取消学校治理，而是把几十页零散配置压缩为一次有证据的集中确认。

## 13. 上线就绪度检查

### 13.1 阻断项

- 租户、套餐、模块授权或首位学校管理员未完成；
- 专业代码不存在、办学层次不匹配或标准来源缺失；
- 已选专业没有对应有效专业教学标准或未明确“标准待补”；
- 课程学时分项不等于总学时；
- 培养方案存在重复课程、非法学期或未启用课程；
- 国标明确要求的课程领域、实践环节或毕业要求被遗漏；
- 培养方案没有专业负责人/教务确认；
- 教师、学生、班级存在跨租户或孤儿关系；
- 关键角色无人员、人员无有效数据范围；
- 敏感权限、审批回避、审计或导出水印未生效；
- 教学任务生成后存在课程、班级或学期断链；
- 生产租户仍使用演示弱密码、模拟数据或测试通知通道。

### 13.2 警告项

- 推荐课程名称被学校修改但能力映射仍未确认；
- 实训条件存在缺口但学校已有替代实施计划；
- 专业负责人或课程负责人未完全分配；
- 教学任务尚未分配全部教师；
- 地方标准、学校制度尚未数字化登记；
- 学校采用平台默认学分学时，没有提交本校正式制度附件。

### 13.3 就绪度评分

评分仅用于进度展示，不能抵消阻断项：

- 租户与安全 15%；
- 组织、师生与关系 20%；
- 专业与国标追溯 20%；
- 课程与培养方案 20%；
- 教学运行 15%；
- 权限、审计和验收 10%。

有任一阻断项时不得标记“正式上线”，即使分数达到 100。

## 14. 首发专业包策略

你是单人团队，首期不追求覆盖全部专业。采用“引擎先行、真实客户优先、一个包完整胜过十个空壳”的策略：

1. 先完成标准库和预设引擎；
2. 以系统现有演示专业和首批意向学校专业交集确定首发包；
3. 每个专业包必须完成 11 要素、岗位能力课程链、实践、师资、条件和毕业要求后才标记可售；
4. 没有官方原文和条款定位的专业包只能标记 `DRAFT/NOT_SELLABLE`；
5. 首发建议优先评估软件技术、计算机应用技术、电子商务、新能源汽车技术等已有明确官方标准且易形成演示闭环的专业；
6. 第二批再扩展会计、机电、护理、旅游、幼儿保育等，以真实客户需求排序。

专业包完成度分级：

- `L0 目录级`：只有专业代码和名称；
- `L1 标准级`：已登记专业简介和专业教学标准；
- `L2 推荐级`：完成岗位—能力—课程—实践结构化映射；
- `L3 可实施级`：可生成课程库和培养方案草稿；
- `L4 可运行级`：可继续生成教学任务并通过上线检查；
- `L5 已验证级`：已在真实试点学校完成验收且有版本记录。

只有 `L4` 及以上可以宣传为“一键专业实施包”。

## 16. 明确不做和后置范围

首期不做：

- 自动抓取互联网内容后未经审核直接发布标准；
- 用 AI 自动决定学校正式学分、学时和毕业要求；
- 一次性手工建设全部 1349 个专业的完整包；
- 复制第三方系统代码、数据库结构、受保护文案或完整教材内容；
- 模板跨学校共享真实师生数据；
- 标准升级自动覆盖正在执行的培养方案和教学任务；
- 以“就绪度分数”替代学校正式验收。

教学资源预设只保存元数据、目标、任务、标准来源和合法资源链接；教材正文、课件和题库通过学校有权使用的文件或资源平台另行接入。
