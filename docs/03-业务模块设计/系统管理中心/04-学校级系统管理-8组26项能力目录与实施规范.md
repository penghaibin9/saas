# 学校级系统管理：8 组 26 项能力目录与实施规范

## 1. 定位与边界

本目录服务于学校租户管理员。目标是让一所学校在完成组织确认、导入教师和学生、分配预设角色后即可运行，不依赖实施人员逐页配置。

平台运营侧能力不得下放：租户创建/冻结、套餐、模块销售授权、全局菜单和权限点目录、跨校运维、平台级密钥和全局参数。

学校管理员可查看本校已开通模块及到期信息，但不能修改套餐或开通未授权模块。

## 3. 关键业务规则

### 3.1 唯一建号入口

只有「导入老师和学生」可批量创建账号，且仅接收 XLSX。教务、学工、毕业设计、岗位实习中的名单导入只允许关联已有账号，禁止隐式建号。

### 3.2 统一权限目录

每一个三级能力必须登记：菜单码、页面权限码、操作权限码、适用数据范围、敏感等级、后端接口。前端导航、角色授权树、路由元数据及后端鉴权均消费此目录，不再各自维护。

### 3.3 六要素权限判定

后端对每次请求至少判断：租户与模块授权、当前激活角色、菜单权限、操作权限、数据范围、真实业务关系；敏感字段还需要单独授权。前端隐藏菜单不是安全边界。

### 3.4 数据范围与业务关系

数据范围决定组织上限，例如本院、本班、授课班、指导学生；业务关系决定具体对象，例如辅导员带班、教学任务、毕设导师分配、实习指导分配、企业协议和审批节点。两者不能互相替代。

### 3.5 流程与角色不重复维护

流程只引用统一角色和权限目录。审批任务归工作台；流程配置只负责模板、节点规则和异常处理。不得在工作流中再建立一套角色或权限点。

### 3.6 审计不可篡改

账号、角色、权限、数据范围、流程、接口、导入导出和敏感查看均要记录操作人、时间、对象、原因、变更前后值和结果。学校管理员及平台人员均不可删除学校审计日志。

## 4. 角色模板初始化

每个学校初始化时至少预置：学校管理员、身份管理员、组织管理员、权限管理员、流程管理员、审计人员、学院管理员、辅导员、班主任、任课教师、毕设导师、实习指导老师、企业导师、学生。

学校可以复制模板建立自定义角色，但权限集不得超过创建者权限和学校模块授权；临时授权必须有到期时间并自动回收。

## 5. 实施顺序

第一阶段：组织主数据、唯一师生导入、预设角色、角色成员、菜单/动作/范围授权、基础审计、初始化检查。

第二阶段：登录安全、临时授权、流程模板与运行监控、编号规则、字典和扩展字段。

第三阶段：第三方接口、同步失败中心、凭证轮换、告警和高级安全策略。

- 建立 `systemManagementCatalog.js` 作为学校级 8 组 26 项菜单与权限动作目录；
- `navPlan.js` 从该目录生成系统管理侧栏；
- 角色权限树从同一目录生成，避免手写缩减树；
- 已有成熟页面复用到对应三级入口；暂无后端服务的能力使用治理承载页，明确学校边界、权限动作与接入约束，不伪造数据或写接口；
- 已接入只读角色目录接口：`GET /api/v1/system/roles`。接口按当前学校租户隔离，支持关键词、角色类型和状态筛选，并返回真实成员数；不跨租户读取。
- 角色模板初始化与师生 XLSX 导入均已使用真实库事务。角色的创建、权限配置、临时授权等写能力仍须与后端鉴权和审计一并接通后再开放，不能以页面 Mock 冒充已生效配置。
