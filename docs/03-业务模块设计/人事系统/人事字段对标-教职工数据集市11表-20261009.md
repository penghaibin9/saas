# 人事字段对标：外部教职工数据集市 23 张表 vs 本系统（2026-10-09，已更新为全量）

> 性质：**规划与记录**，未改代码/迁移/数据库。
> 来源：用户提供的某职业院校数据集市（部门“组织人事部、党校”）。按分类视图，“教职工管理数据集”21 张 + “教职工数据集”（归默认分类）+ “单位基本信息”（归学校概况）= **23 张**。
> **23 张字段已全部提供**（首次只给了 11 张，后补全 12 张：岗位代码表、离退休、离职、工资变动子类、工资结构、编制异动、党政职务、惩处、奖励、学历学位、政治面貌、工作简历，见第四B节）。文件名里的“11表”是首版遗留，内容已是 23 表。
> 配套设计：`docs/人事系统.png`（高校人事管理系统黄金流程泳道图，HR01–HR18）。该图明确：**HR03 人员事实核心、HR02 岗位编制事实核心、HR18 统计归档（不反向篡改业务事实）**。

## 一、先说结论

1. **本系统目前没有“教职工主档”。** 老师只散落在三处：`t_user`（登录名、姓名、手机）、`t_gd_mentor`（毕设导师：工号、职称、学院、研究方向，只为毕设服务）、`t_staff_assignment`（组织任职关系）。人事系统是**从零新建**，不是补字段。
2. 对方 11 张表里，**真正的主档只有两张**：教职工基本信息（66 字段）和教职工数据集（64 字段）。经核对，**数据集 = 基本信息去掉 `JZGLXM`（教职工类型码·教务用）和 `GWDM`（岗位代码）**，是同一份数据的两个交换版本，**只建一套主档**，不要照搬成两张表。
3. 对方的“基本信息”是一张 66 列的宽表，把**自然人信息、任职信息、岗位职务职称现状、联系方式、档案**混在一起。我们按泳道图拆成：人员（自然人）→ 教职工（任职）→ 岗位/职务/职称履历 → 联系方式，且**岗位、职务、职称现状不在主档重复存，由履历“当前有效记录”派生**（泳道图要求 effective-dated 历史保留）。
4. **敏感个人信息很多**（身份证号、健康状况、血型、信仰宗教、政治面貌、婚姻、籍贯、港澳台侨外）。按项目底线必须加密/脱敏/最小返回，其中**宗教信仰、健康状况建议不采集或仅限人事专员可见**（见 ❓H2）。
5. 其余 21 张是履历/异动/退休离职/薪酬/奖惩类子表，和泳道图模块对应（见第二、四、四B节），可分期做；**薪酬类 2 张建议一期不做**（❓H6）。
6. 对方没有的：合同、考勤、考核、培训、家庭成员。泳道图里有这些环节，需要我们自己设计，不能靠对标。
