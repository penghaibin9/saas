## 1. 阶段 0 结论

1. 当前分支开始施工前与 `main` 完全一致：ahead 0、behind 0。
2. V6 共冻结 **37 个施工单元**：21 张 SYS 卡、15 张 PLAT 卡、1 张 RBAC-09 专项卡。
3. 明确属于“已有真实底座、只做生产增强”的卡：`SYS-18`、`SYS-19`、`PLAT-07`。
4. 其余卡多数已有共用 API、旧页面或旧服务可复用，但 V6 专属 service/model/page/test 尚未建立，统一标记为“部分覆盖”或“规划型”，不得宣称完成。
5. `systemAdmin.file.manage` 当前同时影响文件治理动作与文件内容管理员判断；`systemAdmin.user.import` 当前仍承载多项数据交换动作。结论：`RBAC-09` 是 `SYS-19` 的硬前置。
6. 数据交换后端已支持 `Idempotency-Key`，但学校端前端确认接口当前只发送 `expectedVersion`；任务汇总仍按当前页计算，页面仍使用 `window.confirm/window.prompt`。
7. 当前静态 Alembic 顶部 revision 文件为 `0154_file_storage_quota_reservation`，其 `down_revision` 为 `0153_file_storage_governance`。PR #25 的最终验收记录证明当时 `alembic heads` 为单一 head，MySQL 8 空库可升级到 0154。后续任何迁移卡开工前仍必须在最新分支重新运行 `alembic heads`，不得根据本报告写死 0155。
8. V6 机器索引与 canonical Markdown 存在路由/依赖漂移；本阶段以 canonical Markdown 为权威校正机器索引。

## 6. SYS-18 旧消费者清单

### 学校端直接消费者

- `SystemDataExchangeView.vue`：任务列表、确认、下载、撤销；当前汇总由当前页 rows 计算，并使用 `window.confirm/window.prompt`。
- `SystemStudentImportView.vue`：`validateIdentity → getImport → confirmImport`。
- `SystemTeacherImportView.vue`：同上。
- `SystemMigrationView.vue`：迁移预检后调用统一确认。
- `ImportDialog.vue`：承接 validate/import DTO，不能恢复前端 rows 权威。
- `dataExchange.api.js`：第一施工点；确认请求需增加 `Idempotency-Key`，并新增 summary/errors/cancel/retry/visibility。
- `systemManagementCatalog.js`：权限动作需要从 `user.import` 拆为 dataExchange 原子动作。

### 教务及公共底座消费者

- `AaRosterImportExportView.vue` 与 `academic-file-exchange.api.js`：教务自有任务视图和 adapter；SYS-18 不得破坏其路由与任务生命周期。
- `academic_file_exchange_router.py`、`academic_file_exchange_service.py`：生产 ImportJob/ExportJob，继续通过 adapter 复用。
- `data_exchange_confirm_service.py`：统一确认权威，属于 PR #25 保护路径；SYS-18 只调用，不重写。
- `identity_import_scan_orchestrator.py`：扫描后解析；扫描失败/未完成禁止确认。
- `data_exchange_cleanup_service.py`：过期与清理兼容。
- `migration.py`：老系统迁移 adapter 兼容入口。

### 旧权限风险

- `data_exchange.py` 的确认、列表、详情、下载、撤销仍广泛依赖 `systemAdmin.user.import`、`systemAdmin.migration.view`、`systemAdmin.audit.sensitive.view`。
- `file_governance.py` 的 overview/quota/retention/cleanup/legal-hold 全部依赖 `systemAdmin.file.manage`。
- `file_access_service.py` 把 `systemAdmin.file.manage` 视为文件管理员，默认 resolver 可因此允许内容访问。

冻结裁决：先完成 SYS-18 的显式 visibility 与新动作双权限兼容，再完成 RBAC-09 迁移，RBAC-09 通过后才能施工 SYS-19 的治理权限收口。
