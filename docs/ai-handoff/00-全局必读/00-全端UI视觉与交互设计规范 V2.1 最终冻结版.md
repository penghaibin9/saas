本版本在 V2.1 修订版基础上继续采纳最后一轮评审意见，并完成最终冻结。

本次最终采纳结果如下：

| 问题 | 采纳结论 | 处理方式 |
|---|---|---|
| UI 规范混入 AI 操作手册 | 部分采纳 | 不新增独立文档，避免新手记不住；主文档主体只保留 UI 规范，AI 提示词移入“附录”，不作为视觉规范主体 |

## 2.1 总体气质

- 现代教育 SaaS
- 专业可信
- 清爽克制
- 信息清晰
- 流程可见
- 数据有力
- 操作低成本
- 演示有卖相

关键词：

- 教育蓝
- 温和白
- 高级灰
- 轻卡片
- 强状态
- 清晰流程
- 有层次

6. 移动端搬 PC：手机里放密集表格。
7. PC 端搬手机：电脑端大量大卡片，信息密度过低。

# 三、全局视觉系统

## 3.1 主色系统

| Token | 色值 | 使用场景 |
|---|---|---|
| Primary-50 | #EFF6FF | 浅背景、选中背景 |
| Primary-100 | #DBEAFE | 标签背景 |
| Primary-500 | #3B82F6 | 次级强调 |
| Primary-600 | #2563EB | 主按钮、当前菜单 |
| Primary-700 | #1D4ED8 | Hover、强强调 |

## 3.2 状态语义色

状态语义色只表达业务状态，不表达数据趋势。

| 语义 | 颜色 | 示例 |
|---|---|---|
| 已完成 / 已通过 | Success | 开题已通过、实习评价完成 |
| 处理中 / 审核中 | Primary | 材料审核中、流程办理中 |
| 待处理 / 即将超时 | Warning | 周报待批阅、就业材料待核验 |
| 异常 / 逾期 / 驳回 | Danger | 打卡异常、材料驳回、预警逾期 |
| 草稿 / 未开始 | Gray | 未提交、草稿、未激活 |
| 已归档 / 只读 | Info | 已归档、模块到期只读 |

## 3.3 数据趋势色

趋势色与状态色必须分离。

趋势色不得由前端根据数字正负自行推断。指标数据必须明确返回趋势方向和趋势质量。

### 3.3.1 AppMetricCard 指标数据接口

指标卡数据必须包含：

```ts
export interface MetricCardData {
  id: string
  title: string
  value: number | string
  unit?: string
  description?: string
  trendType?: 'up' | 'down' | 'flat'
  trendQuality?: 'good' | 'bad' | 'neutral'
  trendLabel?: string
  drillable?: boolean
  drillTarget?: string
  updatedAt?: string
}
```

### 3.3.2 强制规则

- `trendType` 表示数学方向：up / down / flat。
- `trendQuality` 表示业务好坏：good / bad / neutral。
- 前端颜色只看 `trendQuality`，不能自己猜。
- 后端或 Mock 层必须返回 `trendQuality`。
- 没有 `trendQuality` 时，前端默认使用 neutral，不得擅自用红绿。

### 3.3.3 示例

| 指标 | trendType | trendQuality | 显示颜色 |
|---|---|---|---|
| 就业率 +5% | up | good | Success |
| 风险学生数 +3 | up | bad | Danger |
| 未提交人数 -8 | down | good | Success |
| 总学生数 +12 | up | neutral | Gray |
| 周报提交率 -4% | down | bad | Danger |

# 四、字体与间距

## 4.1 字体族

PC 和 Web 推荐：

```css
font-family: system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", Arial, sans-serif;
```

数字指标推荐：

```css
font-variant-numeric: tabular-nums;
font-feature-settings: "tnum";
```

原则：

- 中文清晰优先。
- 数字指标等宽对齐。
- 不强依赖 Inter，避免 Windows 中文混排失衡。
- Mac、Windows、移动端视觉尽量一致。

## 4.2 字号

| 场景 | PC 字号 | 移动端字号 |
|---|---:|---:|
| 页面大标题 | 20px / 22px | 18px / 20px |
| 卡片标题 | 16px | 16px |
| 正文 | 14px | 14px / 15px |
| 辅助文字 | 12px / 13px | 12px / 13px |
| 表格正文 | 13px / 14px | 不建议复杂表格 |
| 指标数字 | 24px / 28px / 32px | 22px / 26px |

## 4.3 间距

统一使用 4px 栅格：

- 4px
- 8px
- 12px
- 16px
- 20px
- 24px
- 32px
- 40px
- 48px

PC 推荐：

- 页面外边距：24px
- 卡片内边距：20px / 24px
- 区块之间：20px / 24px
- 表单项间距：16px

移动端推荐：

- 页面外边距：12px / 16px
- 卡片间距：12px
- 卡片内边距：14px / 16px

## 4.4 移动端安全区

所有移动端底部固定操作必须使用 safe-area。


# 五、09B 学生 PC 门户规范

## 5.1 三层结构

09B 学生 PC 门户固定为三层：

1. **StudentPortalLayout：学生门户壳**  
   负责顶部导航、身份、消息、待办、左侧轻菜单、内容容器。

2. **StudentDashboard：学生仪表盘首页**  
   负责当前阶段、待办、风险、最近消息、模块进度、常用入口。

3. **Module Execution Pages：业务模块执行页**  
   包括毕业设计、岗位实习、就业填报、材料上传等具体操作页面。

## 5.2 路由硬性约束

学生 PC 所有业务模块执行页，必须渲染在 `StudentPortalLayout` 的 `<router-view>` 内。

禁止：

- `/student/graduation-design` 脱离学生门户壳独立成全屏页面。
- 进入毕业设计后左侧轻菜单消失。
- 学生业务页复用 09A 管理端布局。
- 学生端出现后台系统管理菜单。

推荐路由结构：

```ts
{
  path: '/student',
  component: StudentPortalLayout,
  children: [
    { path: '', component: StudentDashboard },
    { path: 'todos', component: StudentTodos },
    { path: 'materials', component: StudentMaterials },
    { path: 'graduation-design', component: StudentGraduationDesignHome },
    { path: 'internship', component: StudentInternshipHome },
    { path: 'employment', component: StudentEmploymentHome },
    { path: 'profile', component: StudentProfile }
  ]
}
```

## 5.3 学生 PC 左侧轻菜单

允许菜单：

- 首页
- 我的待办
- 我的消息
- 我的材料
- 我的档案
- 毕业设计
- 岗位实习
- 毕业就业
- 个人中心

禁止菜单：

- 系统管理
- 数据配置
- 审计日志
- 批量导出
- 权限管理
- 管理端菜单树

## 5.4 学生 PC 视觉要求

- 不像后台管理端。
- 背景使用 Gray-50。
- 主卡片使用白色。
- 少表格，多卡片、步骤条、时间线、任务列表。
- 当前阶段突出。
- 下一步操作突出。
- 被退回、逾期、风险必须醒目。
- 只显示本人数据。

# 六、09C 企业导师 PC 轻门户规范

## 6.1 企业导师 PC 的定位

企业导师 PC 不属于学校管理后台，不应使用 09A 的复杂管理布局。

企业导师 PC 是轻门户，面向企业联系人和企业导师，主要处理：

- 我的实习生
- 周报查看
- 请假确认
- 企业评价
- 录用意向
- 异常反馈

## 6.2 布局复用规则

企业导师 PC 门户必须复用学生 PC 门户壳结构。

推荐实现：

- 抽象 `BasePortalLayout`
- `StudentPortalLayout` 基于 `BasePortalLayout`
- `EnterprisePortalLayout` 基于 `BasePortalLayout`

或者：

- 直接复用 `StudentPortalLayout` 的结构
- 通过 props / slots 替换菜单、标题、用户信息、权限提示

禁止：

- 复制一份几乎一样的 `StudentPortalLayout.vue` 改名。
- 企业导师端使用 09A AdminLayout。
- 企业导师端看到学校内部菜单。

## 6.3 企业导师 PC 推荐路由

```ts
{
  path: '/enterprise',
  component: EnterprisePortalLayout,
  children: [
    { path: '', component: EnterpriseDashboard },
    { path: 'students', component: EnterpriseStudents },
    { path: 'weekly-reports', component: EnterpriseWeeklyReports },
    { path: 'evaluations', component: EnterpriseEvaluations },
    { path: 'employment-intentions', component: EnterpriseEmploymentIntentions },
    { path: 'profile', component: EnterpriseProfile }

}
```

## 6.4 企业导师权限提示

企业导师页面必须明确提示：

- 仅展示企业授权学生。
- 不展示学生家庭信息。

# 九、数据驾驶舱规范

## 9.1 定位

数据驾驶舱不是炫技大屏，而是领导能看懂、能下钻、能发现问题的管理驾驶舱。

必须做到：

- 指标清楚。
- 口径清楚。
- 趋势清楚。
- 风险清楚。
- 可下钻。
- 有更新时间。
- 有处理入口。

## 9.2 指标来源

驾驶舱指标不能硬编码。

在 Mock 阶段，也必须由底层 Mock 数据聚合生成。

推荐聚合函数：

```ts
aggregatePracticeTeachingMetrics(students, gdTasks, internships, checkins, reports)
aggregateGraduationDesignMetrics(students, gdTasks, submissions, reviews)
aggregateInternshipMetrics(students, internships, checkins, reports, risks)
aggregateEmploymentMetrics(students, employments, materials)
```

要求：

- 改一个学生状态，看板指标自动变化。
- 改一条周报记录，周报提交率自动变化。
- 改一条打卡记录，打卡异常数自动变化。
- 指标卡的 `trendQuality` 必须由聚合层或服务层返回。

禁止：

- 在驾驶舱页面直接写死 92.6%。
- 每个 Store 各自维护孤立 JSON，导致指标无法联动。
- 前端页面自己临时计算颜色和趋势。

# 十一、退回 / 驳回交互规范

## 11.1 为什么要单独规范

退回和驳回是毕业设计、岗位实习、就业材料核验里最常见、最影响体验的流程。

如果退回原因不清楚，学生不知道怎么改。  
如果老师退回操作太随意，流程容易失控。  
所以必须统一。

## 11.2 教师操作侧

教师点击“退回”或“驳回”时，必须触发 `AppConfirmDialog`。

弹窗必须包含：

- 操作标题：确认退回 / 确认驳回
- 操作影响说明
- 必填 textarea：退回原因 / 驳回原因
- 可选附件
- 是否通知学生
- 主按钮：确认退回 / 确认驳回
- 次按钮：取消

规则：

- 退回原因必填。
- 驳回原因必填。
- 原因少于 5 个字不允许提交。
- 高风险驳回需要二次确认。
- 退回后必须生成学生待办和消息。

## 11.3 学生 PC 接收侧

学生进入模块执行页时，如果当前材料被退回，页面顶部必须显示不可关闭的 `AppInlineAlert`。

显示内容：

- 状态：已退回
- 退回人
- 退回时间
- 退回原因
- 修改要求
- 重新提交按钮

规则：

- 该提示不可关闭。
- 直到学生重新提交后才消失。
- 被退回材料区域必须高亮。
- 历史退回记录可查看。

## 11.4 学生移动端接收侧

学生小程序待办卡片必须显示：

- 红色或警告气泡：已退回
- 模块来源：毕业设计 / 岗位实习 / 就业材料
- 退回原因摘要
- 按钮：查看原因 / 去修改

点击后首屏必须显示老师意见，不允许让学生自己找。

## 11.5 驳回与退回的区别

| 类型 | 含义 | 学生是否可重新提交 | 颜色 |
|---|---|---|---|
| 退回 | 材料需修改补充 | 可以 | Warning |
| 驳回 | 当前申请不通过 | 通常不可以，需重新发起 | Danger |

# 十二、全局异常状态规范

## 12.1 AppGlobalState

所有 PC 页面必须使用 AppGlobalState 或同等封装处理页面状态。

支持状态：

- loading
- empty
- error
- forbidden
- offline
- readonly
- noLicense

## 12.2 状态显示

| 状态 | 显示内容 | 操作 |
|---|---|---|
| loading | 骨架屏或加载动画 | 不显示空白页面 |
| empty | 空状态图标、说明、引导按钮 | 去创建 / 去导入 / 返回 |
| error | 错误说明、错误码、重试按钮 | 重试 / 查看详情 |
| forbidden | 无权限说明 | 返回首页 / 联系管理员 |
| offline | 网络异常 | 重试 |
| readonly | 当前模块只读 | 查看历史 / 联系管理员 |
| noLicense | 模块未开通 | 返回 / 联系学校管理员 |

# 十三、全局反馈通知规范

## 13.1 反馈类型

系统反馈分为：

- Toast 轻提示
- Message 顶部消息
- InlineAlert 行内提示
- ConfirmDialog 确认弹窗
- ResultPage 结果页
- ErrorDetail 错误详情

## 13.2 成功反馈

成功反馈使用轻提示：

- 位置：页面顶部或右上角。
- 时长：3 秒自动消失。
- 颜色：Success。
- 文案简短。

示例：

- 已提交，等待导师批阅。
- 已保存草稿。
- 就业材料已提交核验。
- 周报已退回学生修改。

## 13.3 错误反馈

错误反馈必须包含：

- 失败原因
- 可执行建议
- 重试按钮或联系入口

禁止只显示“操作失败”。

示例：

- 上传失败：文件超过 50MB，请压缩后重新上传。
- 提交失败：当前节点已截止，请联系指导老师。
- 无权限：当前身份无法查看该学生材料。
- 模块到期：当前模块已到期，只能查看历史数据。

## 13.4 二次确认

以下操作必须二次确认：

- 删除
- 发布
- 驳回
- 退回
- 归档
- 导出敏感数据
- 人工放行
- 成绩发布
- 模块停用

按钮必须写清楚动作，不允许只写“确定”。
