## 二、测试范围

本轮测试文档覆盖两个被测对象，均为 **mock 版**：

| 被测对象 | 目录 | 技术栈 | 数据来源 | 当前状态 |
|---|---|---|---|---|
| PC 管理端 | `frontend/` | Vue3（无 UI 框架，UI-P1.5 工程壳） | `frontend/src/mocks/{模块}/*.mock.js` + `db.js`（演示剧本，基准日 `TODAY=2026-07-02`，当前实习周 `CURRENT_WEEK=4`） | UI 母版对接中，模块齐全，mock 数据 |
| miniapp（学生端 + 教师端） | `miniapp/` | uni-app + Vue3 | `miniapp/src/mock/`（`user.js`、`student/*`、`teacher/*`） | 纯 mock，可运行/可构建/可演示，`ENV.useMock=true`，`apiBaseUrl` 为空，`mockLatency=260ms` |
| 后端 | `backend/` | PostgreSQL + Python FastAPI + SQLAlchemy + Alembic（技术栈已拍板） | 无 | 仅有 config/middlewares/utils，真实接口**尚未接入**，本轮测试不覆盖真实后端联调，仅在用例中标注"后端接入后验证" |

不在本轮范围内：真实数据库联调测试、真实文件服务联调测试、真实短信/邮件网关测试、压力测试/性能基准测试的真实数值（仅在总览中列出后续需做的性能测试项）、跨浏览器真实兼容性测试执行记录（仅在回归清单中列出检查项）。

## 三、测试环境与启动方式

### 3.1 miniapp（学生端 + 教师端）

```bash
cd miniapp
npm install        # 首次执行
npm run dev:h5      # 启动 H5 开发态
```

- 访问地址：`http://localhost:5188/`
- 构建检查：
  ```bash
  npm run build:h5         # H5 构建
  npm run build:mp-weixin  # 微信小程序构建
  ```
- mock 配置：`ENV.useMock=true`，`apiBaseUrl` 为空，`mockLatency=260ms`（模拟网络延迟，用于观察加载态）。
- 账号：学生 **林可欣**（学号 2024010612）；教师 **张明远**（工号 T20190087，可切换 6 类教师身份）。

### 3.2 PC 管理端（`frontend/`）

PC 前端启动方式以 `frontend/` 工程内实际 `package.json` 脚本为准（参见 `frontend/package.json`）。当前工程内已确认的脚本：

```bash
cd frontend
npm install     # 首次执行
npm run dev     # 启动开发态（Vite，默认端口 5173，具体以终端输出为准）
npm run build   # 构建产物（用于 08-回归测试清单.md 的 build 检查）
```

若终端实际输出端口与本文不一致，以终端输出的真实地址为准；本文不改写 `frontend/vite.config.js`。

### 3.3 后端（当前不启动）

`backend/` 当前不提供可运行的业务接口服务，本轮所有测试均在 mock 数据基础上执行，不需要、也无法启动真实后端联调环境。

## 五、缺陷回填

- 测试执行中发现的缺陷，登记到 **[质量与风险台账.md](./质量与风险台账.md)** 或 **`docs/施工记录/历史欠账.md`**，不在本目录散落新建记录文件。
- 登记时建议附带：对应测试编号（如 `PC-STU-004`）、复现步骤、期望结果与实际结果的差异、截图或控制台报错（如有）。
- 本目录内的清单文件只负责"测什么、怎么测、期望是什么"，不负责"缺陷本身的跟踪与修复状态"。

## 六、与其他文档的关系

- 权限点、角色、数据范围的**权威口径**以共享事实底稿与 `docs/rbac/`（RBAC 权限与数据范围矩阵，由另一 agent 生成）为准；本文档中的权限/数据范围用例引用该口径，不重新定义。
- 接口路径、请求/响应结构的**权威口径**以 `docs/api/00-API契约冻结总册.md` 及分域文档为准；本文档中涉及接口的用例只引用，不重写契约。
- 安全基线（会话、脱敏、上传、导出、审计）的**权威口径**以 `docs/security/00-等保三级安全基线总册.md` 为准。
- 后端接入顺序与联调任务分工参见 `docs/backend-integration/`（由另一 agent 生成），本文档中标注"后端接入后验证"的用例在后端联调阶段应回到本清单逐条执行。
