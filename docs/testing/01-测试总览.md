## 一、测试目标

在后端真实接口接入之前，验证当前 mock 版 PC 管理端 + miniapp：

1. **功能完整性**：底稿列出的模块、页面、角色、按钮均可在 UI 上正常触发，交互链路（看板→列表→详情→写操作→提示）闭环。
2. **权限与数据范围口径正确**：前端已实现的权限判断（`permission.context.js`）与数据范围过滤在 mock 层面表现符合底稿定义的角色-权限-范围绑定关系。
3. **异常与边界处理到位**：空态、加载态、错误态、无权限态、会话超时态均有对应 UI，不出现白屏/控制台报错/无提示卡死。
4. **可回归、可交付**：构建（build）通过、路由刷新不 404、跨模块导航不断链，具备向客户演示或转手后端联调的基础质量。

不属于本轮目标：真实数据的准确性、真实并发/压力表现、真实数据库读写正确性——这些均依赖后端接入，本文档中相应用例标注"（后端接入后验证）"。

### 2.2 测试类型

- **功能测试**：核对功能是否按预期工作（列表、详情、表单提交、状态流转）。
- **权限测试**：核对菜单/按钮/页面/数据是否按角色-权限点正确显隐与拦截。
- **数据范围测试**：核对同一功能在不同数据范围角色下看到的数据集合是否符合范围定义。
- **异常测试**：核对空数据、网络错误、无权限、会话失效等非正常路径的表现。
- **回归测试**：核对新变更未破坏既有基础质量（构建、路由、跨模块导航）。
- **兼容性测试**：核对不同屏宽/分辨率下是否出现横向滚动条等布局问题（本轮为人工检查项，见 08）。
- **安全测试**：核对脱敏、审计、会话超时、上传白名单等安全基线在 UI 层的落地（详细安全测试深化见 07 与 09，权威基线见 `docs/security/00-等保三级安全基线总册.md`）。

### 2.3 mock 可测 vs 需后端 —— 判定原则

判定一条用例"mock 阶段可测"还是"需后端"，按以下原则区分：

| 判定为 mock 阶段可测 | 判定为需后端（标注"后端接入后验证"） |
|---|---|
| 数据来自 `frontend/src/mocks/**/*.mock.js`、`miniapp/src/mock/**/*.js`，前端能自行渲染 | 依赖真实数据库中的实际记录（如"新建的学生真实写入 PostgreSQL 后再查询"） |
| 权限判断逻辑在前端 `permission.context.js` / `security/guards/*` 中已实现，可用 mock 角色数据触发 | 依赖服务端返回的 `traceId`、`X-Request-Id` 真实链路追踪 |
| 错误态可通过 mock 层预留的 `forceError` / `MOCK_ERROR` 机制人为触发 | 依赖真实网络异常、真实服务端 500、真实并发冲突（`APPROVAL_VERSION_CONFLICT`） |
| 表单校验（如退回原因≥5字）在前端 JS 中已实现 | 服务端二次校验（如 `REJECT_REASON_REQUIRED` 由后端返回） |
| 导入模板下载、前端字段校验 | 真实文件解析、真实导入落库、真实错误行回填 |
| 导出按钮触发、导出行数前端限制提示 | 真实文件生成、真实文件服务、导出审计落库查询 |
| 会话 30 分钟超时倒计时 UI、超时前 5 分钟预警 UI | 真实会话失效判定（服务端 session store） |

本文档体系中的每一条标注"（后端接入后验证）"的用例，其"是否通过"列在当前阶段应填 **N/A**，不计入本轮通过率统计；待后端接入并联调后，应重新执行并转为 ☑/✗。

## 四、通过标准

### 4.1 用例级通过标准

单条用例判定为"通过"（☑）需同时满足：

1. 操作步骤按用例执行，无需绕过异常报错才能完成；
2. 实际结果与预期结果一致（允许合理的 mock 占位文案差异，但状态、数据集合、拦截行为必须一致）；
3. 控制台（浏览器开发者工具 Console）无未捕获的 JS 报错（Vue 警告可记录但不计入不通过，除非直接导致渲染异常）；
4. 不出现白屏、页面卡死、无限加载。

### 4.2 模块级通过标准（用于验收）

| 判定 | 标准 |
|---|---|
| 模块通过 | 该模块 P0 用例 100% 通过，P1 用例 ≥ 90% 通过，无阻断性缺陷（白屏/无法进入页面/build 失败） |
| 模块有条件通过 | P0 100% 通过，P1 通过率 70%~90%，缺陷已登记 `docs/qa/` 且有明确修复计划 |
| 模块不通过 | 存在 P0 用例不通过，或 build 失败，或存在权限拦截失效（越权可见/可操作） |

### 4.3 整体上线前置标准

见 `09-上线前验收清单.md`；当前阶段（后端未接入）不具备"整体上线"条件，本总览与验收清单均以"mock 版可交付演示/可转后端联调"为现阶段目标，而非"生产可上线"。
