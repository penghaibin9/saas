# ADR-001：帮助中心运行时内容真值

- 状态：Accepted
- 日期：2026-08-06
- 决策范围：管理 PC 帮助中心及其治理文档

## 背景

仓库已有 `frontend/src/config/helpContent.js`、`frontend/src/config/help/`、`frontend/public/help/` 和 `/admin/help`。PR #48 又建立了 `docs/help` Markdown 目录。如果两边都被定义为正式内容源，同一业务会出现重复维护和版本漂移。

## 决策

当前阶段采用“运行时内容即代码 + 文档治理证据”的模式：

- 运行时结构化帮助真值：`frontend/src/config/helpContent.js` 与 `frontend/src/config/help/`；
- 运行时可视化资产：`frontend/public/help/`；
- 产品入口：`/admin/help`；
- 治理、审计、写作规范、覆盖矩阵和发布证据：`docs/help/`；
- `docs/help` 中的操作草稿不能自动视为已发布，除非同步进入运行时真值并通过校验。

## 理由

1. 兼容当前顶部搜索、路由映射和页面深链；
2. 避免一次高风险大迁移；
3. 允许先把查找体验和质量控制做好；
4. 为后续生成式 Markdown 单一源保留迁移路径。

## 后果

正面：

- 当前 PR 可小范围、可验证地提升产品；
- 运行时不会同时读取两套正文；
- 现有任务卡和可视化资产能够继续复用。

负面：

- 内容编辑仍需要代码 PR；
- 自由文本角色和非统一字段仍需渐进治理；
- Markdown 草稿与运行时条目之间仍需人工同步，直到未来引入生成管线。

## 被否决的替代方案

### 立即改成 Markdown / MDX 唯一源

本次不采用。原因不是方向错误，而是当前没有成熟的解析、生成、路由绑定、版本迁移和多端回归管线；在帮助内容仍快速变化时直接迁移会扩大风险。

### 立即引入外部 CMS

本次不采用。当前团队规模和商业阶段尚不足以抵消 CMS 带来的权限、发布、租户隔离、搜索同步和运维复杂度。

## 重新评估触发条件

满足以下任意两项时重新评估 Markdown 生成管线或 CMS：

- 运行时帮助条目超过 300；
- 每月内容变更 PR 超过 20 个；
- 有专职产品/售后人员需要直接编辑；
- 学生 PC 与两个小程序要求复用同一内容；
- 已有稳定的文章反馈和搜索分析数据；
- 多所正式学校要求按版本或租户发布不同说明。
