# 帮助图片资产迁移与维护规则

本目录用于管理帮助文章所需的截图、标注图和原始素材。现有图片先清点、归属和脱敏，再决定保留、裁剪、重拍或归档；在新文章完成验证前不得批量删除旧图片。

## 1. 目标目录

```text
assets/
├── desktop/
│   ├── system/
│   ├── student/
│   ├── academic-affairs/
│   ├── student-affairs/
│   ├── internship/
│   └── graduation/
├── mobile/
│   ├── teacher/
│   └── student/
└── source/
    └── 原始截图或可编辑源文件（不直接发布）
```

仓库只保留帮助中心确实使用的必要图片。较大的可编辑源文件应评估仓库体积和访问权限，不得包含真实生产隐私。

## 2. 资产清点表

迁移旧图片时建立清单：

| asset_id | 原路径 | 归属文章 ID | 端 | 状态 | 隐私风险 | 负责人 | 备注 |
|---|---|---|---|---|---|---|---|
| 示例 | 待填写 | student.import | PC | retake | 待检查 | 学生主档 | 页面版本待核验 |

状态只能使用：

- `keep`：页面和步骤仍一致，无隐私，可继续使用；
- `crop`：主体有效，需要裁剪、压缩或重新标注；
- `retake`：页面已变化、模糊、尺寸不合格或含真实隐私；
- `archive`：已被新图替代，仅保留历史记录。

## 3. 命名规则

```text
<platform>/<module>/<task>-step-<两位序号>.webp
```

示例：

```text
desktop/student/import-step-01.webp
desktop/system/permission-role-step-02.webp
mobile/teacher/internship-review-step-03.webp
mobile/student/profile-scan-step-01.webp
```

禁止：

```text
图片1.png
最终版2.png
截图20260806.png
新建文件夹/未标题.png
```

## 4. 截图要求

- 使用固定测试学校、测试教师和测试学生；
- 一张图只说明一个步骤；
- 只截取必要区域，避免无关浏览器标签、桌面和聊天信息；
- 数字标注原则上不超过 5 个；
- PC 与移动端分别截图，不把两个端拼成难以阅读的大图；
- 保持统一浏览器缩放、窗口宽度和移动端设备尺寸；
- 发布图优先使用 WebP，在保证文字清晰的前提下压缩；
- 图片下方写解释，图片上不堆放大段文字；
- 每张图片提供准确替代文字。

## 5. 隐私与安全检查

发布前必须确认图片中没有：

- 真实姓名、学号、手机号、身份证号；
- 家庭住址、监护人、健康、心理、资助或处分信息；
- 企业联系人、电话、协议编号；
- 登录密码、验证码、访问令牌、密钥；
- 内部域名、服务器 IP、数据库信息；
- 可继续访问的二维码或邀请链接；
- 浏览器自动填充、收藏夹、聊天通知等无关内容。

遮挡必须不可逆。不要只在可编辑图层上盖色块后导出可恢复的源文件。

## 6. 原图处理

- 原图不直接在文章中引用；
- 原图和发布图分开；
- 原图含真实生产数据时不得上传仓库，应重新使用测试数据拍摄；
- 页面更新后先替换发布图，再将旧图标记为 `archive`；
- 确认没有文章引用后再删除旧发布图；
- 不通过在旧图旁补充大段文字来解释已经变化的页面。

## 7. 文章引用示例

```markdown
![学生导入页面中的模板下载入口](../../assets/desktop/student/import-step-01.webp)
```

替代文字应说明图片表达的动作或结果，不能只写“截图”“页面图片”。

## 8. 本批次处理方式

本批次只建立图片治理规则，不移动或删除仓库中的既有图片。下一批次应：

1. 搜索并列出全部旧帮助图片；
2. 为每张图片登记原路径和归属文章；
3. 检查当前页面一致性和隐私；
4. 按 `keep/crop/retake/archive` 分类；
5. 优先为五篇 P0 文章补齐关键截图；
6. 完成引用验证后再处理重复和废弃图片。
