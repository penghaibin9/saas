# 为什么看不到菜单、按钮或学生数据

## 这篇帮助能解决什么

按固定顺序判断问题来自当前学校和业务上下文、账号状态、角色权限、操作权限、数据范围、业务状态还是基础数据，避免直接给老师添加过大权限。

## 适用角色与端

- 普通用户：可完成前半部分自查。
- 学校管理员：可检查账号、角色、权限、数据范围和业务关系。
- 适用端：教师／管理 PC、教师小程序。

## 先判断属于哪一种现象

| 现象 | 优先检查 |
|---|---|
| 整个一级或二级菜单都没有 | 模块是否开通、账号角色、菜单权限 |
| 页面能打开，但新增、审核、导出按钮没有 | 操作权限、业务状态、只读角色 |
| 有页面和按钮，但列表为空 | 学校、学期、批次、筛选、数据范围、业务关系 |
| 能看到学生但无法处理 | 操作权限、当前状态、前置材料、是否本人待办 |
| PC 有数据，小程序没有 | 登录账号、端能力、接口数据范围、批次和同步状态 |
| 其他同角色老师正常，只有一个人异常 | 账号状态、单独授权、组织或指导关系 |

## 普通用户自查

### 步骤 1：确认登录的是正确账号和学校

检查页面显示的姓名、学校和当前身份。退出后重新登录，避免使用他人账号或历史测试账号。

### 步骤 2：确认当前学期、批次和组织

很多页面只显示当前学期、当前批次或选中组织的数据。检查页面顶部和筛选条件，并清除不必要筛选。

### 步骤 3：确认业务是否已经开始

未创建批次、未发布任务、未分配学生或流程尚未到当前角色时，页面可能正常为空或按钮不可用。

### 步骤 4：刷新登录状态

保存手头内容后刷新页面；登录时间过长时重新登录。小程序可退出后重新进入，不要连续重复提交。

### 步骤 5：向管理员提供完整现象

不要只说“没权限”。至少提供：

- 使用端：PC、教师小程序或学生小程序；
- 页面或任务名称；
- 缺少的是菜单、按钮还是数据；
- 当前学校、学期或批次；
- 期望看到哪个班级或学生；
- 问题发生时间；
- 脱敏截图。

## 学校管理员排查顺序

### 第 1 层：学校与账号状态

确认账号属于正确学校，未停用、未锁定、未过期，人员身份没有被错误解绑或重复创建。

### 第 2 层：模块和菜单权限

确认学校已经开通对应模块，用户角色包含页面访问权限。不要把“模块未开通”误判为个人账号问题。

### 第 3 层：按钮或操作权限

页面访问权限不等于新增、编辑、审核、发布、导入、导出权限。确认角色拥有完成任务所需的最小操作权限。

### 第 4 层：数据范围

确认用户的数据范围是全校、部门、专业、班级、本人、指导学生或其他业务关系，并确认目标学生确实落入该范围。

典型问题：

- 辅导员没有关联负责班级；
- 指导教师没有建立指导关系；
- 部门管理员的学生属于另一个院系；
- 教师角色有菜单权限，但数据范围为空；
- 学生转班后当前关系或历史筛选未更新。

### 第 5 层：业务状态和待办归属

确认当前记录是否处于该用户可操作的状态，以及待办是否属于本人。已归档、已正式发布、已撤销或已由其他人处理的记录可能只能查看。

### 第 6 层：学期、批次和基础数据

检查当前学年学期、业务批次、班级、课程、教学班、指导关系等前置数据是否存在并启用。

### 第 7 层：筛选、缓存和跨端差异

清除筛选，重新登录，再比较 PC 与小程序。若 PC 正常、小程序异常，记录相同账号、相同批次和相同数据的对比结果后再提交售后。

## 处理原则

### 不要直接授予超级管理员

临时给全校最高权限虽然可能让页面出现，但会掩盖真实配置问题，并带来越权查看、误操作和敏感信息泄露风险。

正确做法：

1. 明确用户职责；
2. 找出缺少的菜单、操作或数据范围；
3. 只增加完成职责所需的最小授权；
4. 重新登录验证；
5. 记录变更原因、操作人和时间。

### 不要把前端隐藏当成安全控制

菜单或按钮隐藏只能改善界面，后端仍必须校验权限、租户和数据范围。发现“手工输入地址仍能越权访问”时，应立即按安全问题处理。

## 常见问题

### 同一个角色，为什么其他老师有数据而我没有

角色相同不代表数据范围和业务关系相同。重点检查部门、班级、任课、指导或审批分工。

### 管理员给了权限，为什么还没生效

确认修改的是当前学校中的正确账号和正确角色；保存后重新登录。若角色存在缓存或有效期，也应按系统实际机制核验。

### 为什么按钮昨天能点，今天不能点

业务状态、截止时间、正式发布、归档、待办归属或批次状态可能已经变化。先看当前记录状态和操作日志。

### 为什么列表数量和同事不同

比较双方学校、角色、数据范围、组织关系、学期、批次和筛选条件。不要只比较页面总数。

### 哪些情况需要平台售后处理

学校管理员已经核验账号、角色、权限、数据范围、业务状态和基础数据，问题仍可稳定复现；或者出现跨学校数据、无权限地址可访问、错误暴露敏感信息等安全风险时，应立即提交平台处理。

## 权限与数据范围

- 权限配置遵循最小权限原则；
- 菜单、操作和数据范围分别检查；
- 学校管理员只管理本校授权；
- 平台运营人员不得无依据查看或修改学校业务数据；
- 关键授权变更必须保留审计记录；
- 涉及敏感学生信息时，排障截图必须脱敏。
