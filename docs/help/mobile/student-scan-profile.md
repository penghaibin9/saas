# 如何使用手机扫码采集学生资料

## 这篇帮助能解决什么

当学校已启用学生资料扫码采集能力时，由学校发起采集任务，学生使用手机填写或补充资料，学校在 PC 端复核后再进入正式学生主档。

> 本文只适用于当前部署版本已经启用扫码采集的学校。未启用时请使用单个新增或 Excel 批量导入，不要通过公开表单代替正式功能。

## 适用角色与端

- 学校管理员或学籍管理员：在 PC 端发起、查看和复核采集任务。
- 学生：在学生小程序或学校指定移动入口扫码填报。

## 操作前准备

1. 学校已经建立院系、专业、年级和班级；
2. 扫码采集功能已经启用并完成正式域名、小程序和权限配置；
3. 管理员明确本次采集对象、字段范围、截止时间和复核责任人；
4. 已确认二维码是否限定学校、批次、班级、有效期或使用次数；
5. 已准备隐私告知和学生填报说明；
6. 不在公开网络、公开群或无关人员可访问的位置长期发布二维码。

## 推荐流程

```text
学校创建采集任务
-> 选择采集范围和字段
-> 生成有限期二维码
-> 学生扫码并确认身份
-> 学生填写、校验并提交
-> 学校查看待复核记录
-> 管理员处理重复和异常
-> 审核通过后进入或更新学生主档
-> 关闭任务并归档结果
```

## 学校管理员操作

### 步骤 1：创建采集任务

在学生资料采集相关页面创建任务，明确任务名称、适用学校或班级、开始时间、截止时间和负责人。

**正确结果：** 任务处于可识别的草稿或待发布状态，尚未向学生开放。

### 步骤 2：选择采集字段

只选择本次业务确实需要的字段。姓名、学号、证件号、手机号、家庭信息等敏感字段应符合学校制度和授权范围。

**正确结果：** 学生端不会要求填写与本次建档无关的多余信息。

### 步骤 3：设置范围和安全限制

按系统实际能力设置班级、批次、有效期、身份校验或使用限制。

**正确结果：** 非目标学生、过期二维码或不属于本校的账号无法提交到本次任务。

### 步骤 4：生成并发布二维码

正式发布前先用固定测试学生账号扫描一次，检查学校名称、任务说明、字段、隐私提示和提交结果。

**正确结果：** 测试学生进入正确学校的正确任务，不会跳转到陌生页面或其他学校数据。

### 步骤 5：监控提交进度

查看应填人数、已提交、未提交、待复核、已通过、已退回和异常数量。对未提交学生使用学校认可的通知渠道提醒。

**正确结果：** 各状态数量清楚，能够定位未提交和异常记录。

### 步骤 6：复核学生资料

重点核对：

- 是否与已有学生重复；
- 学号、姓名和证件信息是否一致；
- 学生是否属于目标班级；
- 联系信息格式是否正确；
- 是否缺少必填材料；
- 是否存在明显冒用或错误提交。

**正确结果：** 合格记录通过，需修改记录退回并说明原因，重复或异常记录进入人工处理。

### 步骤 7：确认进入正式主档

只有页面明确显示“审核通过会新增或更新正式学生主档”时才执行。提交前确认新增、更新、跳过和冲突处理规则。

**正确结果：** 正式主档中学生只出现一次，组织、状态和账号关系正确，处理过程可追溯。

### 步骤 8：关闭任务

采集结束后关闭或过期二维码，导出必要台账并按学校要求保存或销毁临时数据。

**正确结果：** 旧二维码不能继续产生未授权提交，任务结果和异常处理有记录。

## 学生操作

### 步骤 1：确认二维码来源

只扫描学校正式通知中的二维码。页面应显示正确学校和任务名称。

### 步骤 2：完成身份确认

按学校要求登录或填写校验信息。发现学校、班级或个人信息不一致时停止提交并联系老师。

### 步骤 3：填写真实资料

按提示填写，涉及证件号、手机号、家庭信息时确认当前网络和周围环境安全。不要把二维码、验证码或个人资料转发给他人代填。

### 步骤 4：提交前复核

重点检查姓名、学号、班级、证件信息和联系方式。阅读隐私说明后再提交。

### 步骤 5：查看结果

记录提交成功提示。若被退回，查看原因后修改并重新提交；不要重复建立多份记录。

## 完成后的正确结果

- 学生只提交到正确学校和正确采集任务；
- 学校能够看到进度并复核；
- 资料未经复核不会无条件污染正式主档；
- 重复、冒用和错班记录能够被拦截或人工处理；
- 任务结束后二维码失效；
- 个人信息采集、查看和导出均受权限控制。

## 常见问题与排查

### 扫码后显示任务不存在或已过期

确认二维码是否来自本次任务、任务是否发布、是否超过有效期，以及学生是否属于目标范围。不要使用旧截图中的二维码。

### 扫码后显示的学校不对

立即停止填写和提交，保留脱敏截图并联系学校管理员。管理员应检查二维码来源、租户绑定和任务范围。

### 提示已经提交

先查看是否允许修改或重新提交。可能是本人已提交，也可能是学号、证件号或账号被重复使用。不要更换虚假信息绕过校验。

### 学生提交后，正式学生列表里没有

扫码提交可能仍处于待复核、已退回或冲突状态。管理员应检查任务状态、审核结果和正式入库规则。

### 手机无法打开或一直加载

检查网络、小程序版本、登录状态和任务有效期。不要连续重复提交；可换稳定网络重新进入，仍异常时提供发生时间和脱敏截图。

### 可以把二维码长期贴在公开位置吗

不建议。二维码应限定范围和有效期，任务结束后关闭。涉及学生敏感信息时必须避免无关人员访问和恶意提交。

## 权限与数据安全

- 创建、发布、复核和正式入库权限应分开控制；
- 学生只能填写本人被授权采集的资料；
- 管理员只查看职责所需范围；
- 二维码、链接和验证码不得用于跨学校或跨任务复用；
- 采集页面应明确学校主体、用途和隐私说明；
- 导出的未审核资料与正式花名册同样属于敏感数据；
- 异常排障截图必须遮盖二维码内容和个人信息。
