## 第三阶段收口（2026-08-07）

本阶段已按真实系统页面和后端契约核验并接入 **20 张新增高频任务卡**：

- 系统管理 7 张：教职工账号与角色、角色权限与数据范围、组织结构初始化、学生 Excel 导入、导入错误与回执、访问权限排查、账号异常排查；
- 开局与通用基础 4 张：学校首次开局、教师/管理人员登录与忘记密码、登录安全策略、学年学期创建与发布；
- 学生主档与数据 3 张：单学生补录与重复学号、学生主档查询筛选、安全导出与下载；
- 微信小程序 6 张：学生实习打卡、学生实习周报、学生毕设选题/换题、教师移动待办、教师实习过程办理、教师毕设选题审核。

新增内容进入运行时帮助模型，并在应用启动时注册到既有共享帮助数组；不另建第二套 Markdown 正文。小程序卡登记真实 `mobilePath` 与入口文案，但**不登记 PC route**，避免管理 PC 帮助中心生成点击后 404 的“前往办理页面”。

### 本轮确认的关键真实规则

1. **学号永久唯一**：同一学校内学号对有效和逻辑作废主档都保持唯一；有效同号拒绝重复建档，已作废同号只能通过独立高风险恢复动作复用原 studentId，不能新建第二份档案。
2. **恢复主档不恢复账号**：恢复保留成绩、实习、毕设、审批、消息等原历史关联，但登录账号是否启用、是否改密仍由账号管理单独处理。
3. **学生查询先受数据范围约束**：关键词和学院/班级/年级/状态/风险等筛选只能缩小当前有权数据，不能扩大可见范围；敏感字段按权限脱敏。
4. **正式学生导出以后端当前数据范围为边界**：真实 xlsx 固定安全字段、手机号脱敏、首行水印、用途与任务审计，下载再次校验租户、权限和任务归属。
5. **学生实习打卡不是持续定位**：只在确认打卡时采集一次位置；无定位/超范围只形成待核验异常，不自动认定作弊。
6. **教师移动办理不能用离线数据假装成功**：周报批阅和打卡异常处理遇离线兜底记录会拒绝提交；并发 409 后刷新服务器真值。
7. **教师“快速处理”不是绕过审批**：移动待办里的“快速处理”仍进入真实业务办理页，不在列表里直接完成业务。

### 旧帮助真值纠正

本阶段不只新增卡，也对历史运行时帮助做了后端状态机级复核。为避免大面积改写历史大文件，新增 `verifiedHelpOverrides.js` 作为带测试的临时权威修正层；同 id 直接覆盖运行时对象，不产生重复条目。

**岗位实习成绩**已纠正：

- 真实成绩组成是 **打卡、周报、月报总结、企业评价、学校评价** 五项，不是旧卡中的“企业评价 + 学生自评 + 指导老师评价 + 过程分”；
- 五项权重必须严格合计 100；
- 企业评价分只读取已审核企业评价，不能在成绩核算处手填覆盖；
- 完整链路为待核算 → 待复核 → 已发布；复核可退回重算；已发布成绩可由学校管理员填写原因撤回后重新核算、复核、再发布；归档后不能直接重算。

**毕业设计成绩与申诉**已纠正：

- 综合成绩真实来源是 **导师分 + 已完成评阅分 + 当前轮次已确认答辩分**，默认权重 40% / 30% / 30%，批次可配置；
- 评阅分和答辩分来自权威业务记录，客户端不能用传值覆盖；
- 成绩必须先核算 → 复核 → 发布，发布前再次核验源成绩快照；如果复核后权威来源变化，必须重新核算；
- 已发布成绩可按权限填写原因撤回，学生阶段从已完成回到答辩阶段，再重新核算 → 复核 → 发布；
- 学生只能对已发布成绩发起申诉，理由不少于 5 字，同一学生同时只能有一条待复核申诉；
- 申诉受理不会直接改成学生要求的分数，而是把原成绩撤回为 WITHDRAWN，触发风险重扫与消息通知后进入重新核算；驳回理由不少于 5 字且原成绩不变。

以上纠正均已加入 Node 回归测试，避免旧错误口径再次进入顶部搜索、本页帮助或帮助中心。

### 小程序帮助入口现状

当前 `miniapp/src/pages.json` 有学生/教师真实业务页，也有“实习求助”业务页，但没有 `pages/common/help` 这类统一自助帮助中心页面。此次先把高频移动任务纳入统一运行时帮助真值，供顶部搜索、PC 帮助中心、售后培训与后续移动入口复用。

在设计移动端统一入口前，不复制一份独立小程序帮助正文，避免形成 PC 一套、小程序一套且后续互相漂移。移动入口需要后续选择能复用同一内容源的实现方式，并单独做微信环境、登录态、返回路径与窄屏验收。

### 已发现但不能靠帮助文档掩盖的运行时差异

`StudentListView` 和数据导出页目前展示“导出所选 / 导出范围 / 导出字段”等交互，但真实适配器调用 `/export/students` 时只提交 `purpose`，没有提交所选学生 ID、当前筛选条件或字段列表；后端实际仍按当前 `student_directory_scope` 生成固定列 xlsx。

因此当前帮助明确以**真实后端安全边界**为准，不把“导出所选”写成正式子集隔离能力。此项属于产品参数闭环欠账，后续应选择：

- 补真实后端筛选/所选 ID/字段白名单参数，并保持数据范围二次求交；或
- 在闭环前收敛/禁用会让用户误以为已精确导出的前端入口。

当前真实产品中，教师/管理 PC 的“忘记密码”仍是联系本校管理员重置，也未把不存在的自助短信找回写成已交付能力。

当前仍不得宣称完成的项目：真实角色端到端验收、正式脱敏截图、学生端/统一认证登录差异、独立年级主数据口径、小程序统一帮助入口、跨模块统一导出，以及逐业务错误码与异常状态机。
