# 学校首次开通后应该先配置什么

## 这篇帮助能解决什么

按照正确顺序完成学校基础配置，避免先导入学生、先开业务批次或先分配任务后，才发现组织、学期、账号和权限不完整。

## 适用角色与端

- 适用角色：平台运营人员、学校管理员。
- 适用端：学校管理 PC。

## 操作前准备

开始前应准备：

1. 学校正式名称、简称和基础联系信息；
2. 学校组织结构，包括院系、专业、年级和班级；
3. 当前学年、学期和校历安排；
4. 首批管理员和业务负责人的姓名、账号及职责；
5. 学生基础数据来源和导入责任人；
6. 首批准备启用的业务模块和试点范围。

不要直接使用真实生产数据试错。首次配置应先使用固定测试账号和少量测试数据完成验证。

## 推荐配置顺序

### 步骤 1：确认学校主体和超级管理员

核对学校名称、学校标识、租户状态、管理员账号和联系方式，确认管理员能够正常登录。

**正确结果：** 管理员登录后看到本校名称，账号处于可用状态，不会进入其他学校的数据空间。

### 步骤 2：建立学年、学期和必要校历

先建立当前及即将使用的学年、学期，再配置业务中需要引用的日期范围。

**正确结果：** 后续培养方案、教学任务、实习批次、毕业设计批次等能够选择正确学期或时间范围。

### 步骤 3：建立组织结构

按学校真实结构建立院系、专业、年级和班级，并检查上下级关系、名称和编码。

推荐顺序：

```text
学校 -> 院系 -> 专业 -> 年级 -> 班级
```

**正确结果：** 新建学生和教师数据时能够选择正确组织，列表筛选和数据范围能够正常工作。

### 步骤 4：创建教师账号和角色

先创建少量核心人员账号，再按职责分配角色。不要为了省事给所有老师全校管理员权限。

至少应区分：

- 学校管理员；
- 教务管理人员；
- 学工管理人员；
- 辅导员或班主任；
- 任课教师；
- 实习指导教师；
- 毕业设计指导教师。

**正确结果：** 不同角色登录后只看到职责范围内的菜单、按钮和数据。

### 步骤 5：配置数据范围和业务关系

角色决定“能做什么”，数据范围决定“能对哪些数据做”。根据学校制度配置全校、部门、专业、班级、本人或指导关系等范围。

**正确结果：** 辅导员只看到负责班级，指导教师只看到指导学生，学校管理员可以按授权范围管理全校数据。

### 步骤 6：建立或导入学生主档

先用 2—5 名测试学生验证字段、组织归属、账号生成和重复校验，再导入正式花名册。

正式导入前：

- 从系统下载最新模板；
- 确保院系、专业、年级和班级已经存在；
- 清理重复学号、身份证号和手机号；
- 先预校验，再确认导入；
- 保存错误行和导入结果。

**正确结果：** 学生能够在正确班级查询到，账号、状态和组织归属符合学校要求。

### 步骤 7：配置首批业务模块

只配置学校本次确实要使用的模块。每个模块先确认：

- 负责人；
- 适用学期或批次；
- 参与角色；
- 审核流程；
- 必填材料；
- 正式发布或归档规则。

不要同时大规模启用所有模块。建议先选择一个班级走通完整流程。

### 步骤 8：完成试点验收

使用管理员、业务老师、指导教师和学生等真实角色测试：

1. 登录与菜单；
2. 列表数据范围；
3. 新建、提交、审核、退回、重新提交；
4. 消息和待办；
5. 导入、导出和错误处理；
6. PC 与小程序的数据一致性；
7. 正式发布或归档后的限制。

**正确结果：** 一个试点班级可以从业务开始走到结束，所有角色都知道自己的入口和下一步。

## 配置完成检查表

| 检查项 | 正确结果 | 主要负责人 |
|---|---|---|
| 学校主体 | 名称、标识和租户状态正确 | 平台运营／学校管理员 |
| 学年学期 | 当前业务可选择正确学期 | 学校管理员 |
| 组织结构 | 院系、专业、年级、班级关系正确 | 学校管理员 |
| 教师账号 | 核心人员可登录 | 学校管理员 |
| 角色权限 | 不同角色只看到职责内功能 | 学校管理员 |
| 数据范围 | 老师只看到授权学生和班级 | 学校管理员 |
| 学生主档 | 测试学生和正式学生归属正确 | 学籍管理员 |
| 业务试点 | 一个班级走通完整流程 | 对应业务负责人 |
| 移动端 | 目标角色可登录并完成高频事项 | 业务负责人 |
| 售后联系人 | 学校内部和平台侧联系人明确 | 双方负责人 |

## 常见问题与排查

### 为什么新增学生时没有班级可选

先检查院系、专业、年级和班级是否已经建立，班级是否属于正确学校和当前组织。

### 为什么老师登录后什么都看不到

依次检查账号状态、角色、菜单权限、数据范围和业务关系。参见[为什么看不到菜单、按钮或学生数据](../modules/system/data-permission.md)。

### 为什么业务页面没有当前学期或批次

检查当前学年学期是否已建立并启用，业务批次是否已创建，日期范围是否有效。

### 是否可以一次导入全校数据后再检查

不建议。应先使用少量测试数据验证字段、组织映射、重复规则和账号生成，再分批导入正式数据。

## 权限与数据范围

- 平台运营人员只处理租户开通和授权范围内的平台事项，不应替学校长期维护日常业务数据。
- 学校管理员负责本校账号、角色、组织和数据范围。
- 业务管理员只获得完成职责所需的最小权限。
- 学生个人敏感数据不得通过群聊、公开链接或未授权文件传递。
