# 跃科 SaaS 帮助中心内容库

本目录存放面向学校用户的操作帮助，不用于替代开发文档、接口文档或部署文档。

## 建设目标

帮助内容围绕用户要完成的事情组织，而不是照抄系统菜单。老师、管理员和学生应当能够通过“我是谁”“我要做什么”“遇到了什么问题”快速找到答案。

帮助中心统一采用四类内容：

1. **快速操作卡**：解决一件高频事项，控制在 3—8 个主要步骤。
2. **完整业务流程**：说明角色分工、状态流转、退回修改和正式归档。
3. **常见问题**：回答简短、明确、可直接处理的问题。
4. **故障排查**：按固定顺序定位账号、权限、数据范围、业务状态和基础数据问题。

## 发布状态说明

首批文章统一标记为 `draft`。原因是文章的业务步骤已经建立，但正式发布前仍须在目标部署版本中逐项核验菜单名称、按钮名称、权限点和截图。

不得为了让文章显得完整而猜测入口。未核验的路径必须写成“常见入口（以当前部署版本为准）”，并在发布检查表中留下待确认项。

## 维护规则

- 每篇文章必须具有唯一 `id`、适用角色、适用端、模块、关键词、负责人、状态和复核日期。
- 功能 PR 必须判断是否影响已有帮助、是否需要新增文章、是否需要重新截图。
- 图片只能使用固定测试学校和测试账号，必须遮盖姓名、手机号、身份证号、住址、企业联系人等个人信息。
- 原有图片在完成文章归属和替换验证前不得批量删除。
- 每次正式发布前检查文章中的菜单、按钮、状态名称和相关链接。
- 页面级帮助后续通过稳定的 `helpId` 关联文章，不直接依赖页面标题。

## 建议的用户查找路径

```text
按角色：学校管理员 / 教务人员 / 学工人员 / 辅导员 / 指导教师 / 学生
按任务：新增学生 / 导入学生 / 审核申请 / 处理退回 / 导出台账
按业务：系统管理 / 学生主档 / 教务 / 学工 / 岗位实习 / 毕业设计
按问题：无法登录 / 看不到菜单 / 看不到数据 / 无法提交 / 导入失败
```

## 本批次边界

本批次先建设内容架构、规范和五篇 P0 高频文章，不修改现有业务流程，不删除旧帮助内容和图片，也不把未经核验的文档直接标记为正式发布。
