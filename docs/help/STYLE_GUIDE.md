# 帮助文章写作与截图规范

## 1. 写作原则

- 围绕用户要完成的任务写，不照抄菜单结构。
- 使用普通老师能理解的语言，首次出现的专业词必须解释。
- 每个步骤只包含一个主要动作，并说明完成后的可见结果。
- 不写“点击这里”“按正常流程操作”“配置正确即可”等无法执行的表述。
- 未经真实页面核验的菜单和按钮不得写成确定事实。
- PC、教师小程序、学生小程序的步骤分开写，不在同一组步骤中混用。

## 2. 标题规则

优先使用以下句式：

- `如何……`：例如“如何批量导入学生”；
- `为什么……`：例如“为什么看不到学生数据”；
- `无法……怎么办`：例如“Excel 无法导入怎么办”；
- `从……到……的完整流程`：用于跨角色业务流程。

避免使用“功能介绍、模块说明、操作指引汇总”等缺少任务目标的标题。

## 3. 必填元数据

每篇文章必须包含 YAML Front Matter：

```yaml
---
id: student.import
title: 如何批量导入学生
roles:
  - 学校管理员
  - 学籍管理员
platforms:
  - PC
module: 学生主档
keywords:
  - 导入学生
  - 学生花名册
  - Excel 导入
owner: 学生主档
status: draft
reviewedAt: 2026-08-06
---
```

要求：

- `id` 全局唯一，发布后原则上不修改；
- `roles` 只写真正能够执行或查看该事项的角色；
- `platforms` 使用 `PC`、`教师小程序`、`学生小程序`；
- `owner` 是内容责任域，不写个人手机号等信息；
- `status` 只能使用 `draft/reviewed/published/stale/archived`；
- `reviewedAt` 是最后一次业务与页面核验日期，不是文件修改日期。

## 4. 正文章节顺序

所有操作文章按以下顺序编写：

1. 这篇帮助能解决什么；
2. 适用角色与端；
3. 操作前准备；
4. 常见入口；
5. 操作步骤；
6. 完成后的正确结果；
7. 常见问题与排查；
8. 权限与数据范围；
9. 相关帮助；
10. 发布前核验。

流程文章可以增加“角色分工”“状态流转”“退回后如何处理”“正式数据能否修改”。

## 5. 操作步骤规则

推荐格式：

```markdown
### 步骤 1：下载最新模板

在导入页面下载当前版本模板，不要继续使用历史群聊或本地保存的旧模板。

**正确结果：** 浏览器下载一个带有字段说明的 Excel 文件。
```

每一步应回答：

- 在哪里做；
- 做什么；
- 需要注意什么；
- 做完看到什么。

步骤超过 10 个时，应拆分为多篇任务卡或增加完整流程总览。

## 6. 菜单和按钮核验

正式发布前必须用目标角色登录目标部署版本，逐项核验菜单、按钮和状态名称。

未完成核验时统一写法：

> 常见入口（以当前部署版本为准）：进入学生主档相关页面，找到新增或导入入口。

禁止凭代码文件名、旧截图或记忆推断正式入口。

## 7. 故障排查顺序

所有故障文章优先按以下顺序排查：

```text
当前学校、学期或批次
-> 账号状态
-> 角色与菜单权限
-> 按钮或操作权限
-> 数据范围
-> 业务状态
-> 前置基础数据
-> 网络与登录状态
-> 学校管理员
-> 平台售后
```

每个问题尽量写明“现象、原因、处理方式、需要谁处理”。

## 8. 图片规范

### 8.1 一图一事

- 一张图只解释一个步骤或一个结果。
- 只截取必要区域，避免整屏无关内容。
- 数字标注原则上不超过 5 个。
- 文字解释写在图片下方，不在图上堆大段文字。

### 8.2 隐私与测试数据

必须使用固定测试学校、测试教师和测试学生。截图前检查并遮盖：

- 姓名、手机号、身份证号、学号等可识别信息；
- 家庭地址、监护人信息、健康和心理信息；
- 企业联系人、电话、协议编号；
- 访问令牌、密钥、内部域名和真实服务器信息。

马赛克或遮挡必须不可逆，不能只在可编辑图层上覆盖。

### 8.3 目录与命名

```text
assets/
├── desktop/
│   └── <module>/<task>-step-01.webp
├── mobile/
│   ├── teacher/<task>-step-01.webp
│   └── student/<task>-step-01.webp
└── source/
    └── 原始图（不直接发布）
```

禁止使用：`图片1.png`、`最终版2.png`、`截图20260806.png`。

建议命名：

```text
desktop/student/import-step-01.webp
mobile/student/profile-scan-step-02.webp
```

### 8.4 替代文字

每张发布图片必须提供能说明用途的替代文字，例如：

```markdown
![学生导入页面中的“下载模板”按钮](../../assets/desktop/student/import-step-01.webp)
```

## 9. 用词与状态

- 使用系统正式名称，不在同一篇文章中混用多个叫法。
- 明确区分“保存草稿、提交审核、审核通过、正式发布、归档”。
- 涉及不可逆或影响正式数据的操作，必须增加醒目警告。
- 涉及批量操作，说明影响范围、失败处理和审计记录。
- 不承诺系统当前没有实现的自动通知、回滚或跨端同步能力。

## 10. 发布前检查表

- [ ] 文章 ID 唯一且已登记到 `catalog.yml`
- [ ] 标题能直接表达任务或问题
- [ ] 适用角色与端准确
- [ ] 前置条件完整
- [ ] 菜单、按钮和状态已用目标角色核验
- [ ] 每个步骤有正确结果
- [ ] 权限与数据范围说明完整
- [ ] 异常排查可执行
- [ ] 图片与当前版本一致
- [ ] 图片无个人隐私和内部敏感信息
- [ ] 相关链接有效
- [ ] 负责人和复核日期已更新
- [ ] 状态已由 `draft` 调整为正确阶段
