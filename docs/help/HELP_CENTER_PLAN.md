# 帮助中心建设方案

## 1. 建设目标

跃科 SaaS 已覆盖平台运营、学校管理、教师、学生及移动端场景。帮助中心必须从“页面说明集合”升级为可独立完成业务的自助服务体系，重点解决：

- 用户不知道从哪里开始；
- 用户找到功能但不了解完整流程；
- 用户遇到无权限、无数据、状态不符或导入失败时无法自行排查；
- 系统升级后旧图片和旧路径持续失效；
- 售后培训反复讲解同一批高频问题。

核心结构为：**角色导航 + 高频任务 + 完整流程 + 异常排查 + 页面内帮助**。

帮助首页应同时提供“我是哪个角色”和“我要完成什么事情”两条主路径。

## 3. 分阶段建设

### P0：可开通、可培训、可排障

优先完成：

1. 学校首次开通后应该先配置什么；
2. 首次登录、密码和账号问题；
3. 创建组织、专业、年级、班级和学期；
4. 创建教师账号、分配角色和数据范围；
5. 新增与批量导入学生；
6. 看不到菜单、按钮或学生数据的排查；
7. 教务、学工、实习、毕设四条业务主流程；
8. 教师小程序和学生小程序高频操作；
9. 导入、导出、消息和待办异常。

### P1：各模块高频任务卡

按真实使用频率补齐审核、退回、补材料、批量办理、风险处置、成绩发布、材料归档和台账导出等文章。

### P2：制度差异与低频配置

补充复杂学校制度、多角色交接、历史数据处理、特殊批次、配置项解释和版本更新说明。

## 4. 文章模型

每篇文章至少包含：

- 唯一文章 ID；
- 标题、关键词和同义词；
- 适用角色、适用端、所属模块；
- 能解决的问题；
- 操作前准备；
- 常见入口；
- 操作步骤；
- 完成后的正确结果；
- 常见问题和排查；
- 权限与数据范围；
- 相关帮助；
- 内容负责人、状态、复核日期。

文章标题使用用户语言：

- “如何新增一名学生”，不写“学生主档功能说明”；
- “为什么看不到某个菜单”，不写“权限中心介绍”；
- “教师如何批阅实习周报”，不写“实习周报模块”。

## 5. 页面内帮助

独立帮助中心之外，后续在产品内逐步接入：

1. **页面级帮助**：页面右上角提供“本页帮助”“操作流程”“常见问题”。
2. **字段级帮助**：对学期、正式发布、数据范围等高风险字段显示简短解释。
3. **错误级帮助**：错误信息说明原因、下一步和对应文章，例如“无法提交：尚未上传三方协议”。

页面与文章通过稳定 `helpId` 绑定，例如：

```text
学生新增页面 -> student.create
学生导入页面 -> student.import
权限排查入口 -> system.permission.troubleshooting
```

路由和页面名称变化时，`helpId` 不随意变更。

## 6. 搜索能力

搜索应覆盖标题、正文、角色、模块、关键词和常用说法。例如“新增学生、添加学生、学生建档、录入学生、导入花名册”能够命中对应文章。

后续应统计：

- 搜索词；
- 无结果搜索词；
- 搜索后打开的文章；
- 用户是否认为文章有用；
- 高频无结果词对应的内容待办。

不得在搜索分析中保存学生或教师的个人隐私内容。

## 7. 图片资产治理

旧图片先登记再处理，状态统一为：

- `keep`：页面一致且无隐私，可继续使用；
- `crop`：内容有效但需要裁剪和重新标注；
- `retake`：页面已变化、分辨率不足或包含真实隐私；
- `archive`：已经被新图替代，仅保留历史记录。

原图与发布用压缩图分开保存。PC、教师小程序、学生小程序分目录管理。一张图只说明一个步骤，数字标注原则上不超过 5 个。

## 8. 内容生命周期

```text
草稿 draft -> 已复核 reviewed -> 已发布 published -> 待更新 stale -> 已归档 archived
```

文章正式发布前必须由熟悉对应业务的人员核对：

- 当前菜单和按钮名称；
- 前置条件和权限；
- 状态流转；
- 图片是否与当前版本一致；
- 是否泄露个人信息；
- 相关链接是否有效。

## 9. PR 与发布联动

每个功能 PR 必须回答：

- 是否影响现有帮助文章；
- 是否需要新增文章；
- 是否需要重新截图；
- 是否修改页面级 `helpId`；
- 是否已经检查页面内帮助链接。

文档变更应与功能变更一同评审，但不得因为文档尚未准备好而把错误操作路径写进正式文章。

## 10. 验收标准

帮助中心进入正式交付至少满足：

1. 20 个最高频任务有完整文章；
2. 学校管理员、教务老师、学工老师、辅导员、指导教师和学生均有角色入口；
3. 重要操作分别说明 PC 和对应小程序；
4. 高频任务可在 3 次点击内找到；
5. 每篇文章都有前置条件、成功结果、权限说明和异常排查；
6. 图片无真实学生、教师和企业联系人隐私；
7. 没有失效图片、失效链接和重复文章 ID；
8. 页面改动时能够定位受影响文章；
9. 用户可以评价文章是否有用；
10. 无结果搜索词能够形成内容补充清单。

## 11. 本批次交付边界

本批次建立帮助内容底座、目录、模板、图片规范和五篇 P0 文章。由于尚未逐页进行真实角色点击核验，首批文章保持 `draft`，不把推测的菜单路径当成正式事实。后续再结合实际页面和固定测试账号补截图、校路径、改为 `reviewed/published`。
