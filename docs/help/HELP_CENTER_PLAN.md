# 帮助中心建设方案

## 1. 前提

仓库已经存在可运行的管理 PC 帮助中心、大量任务卡、流程图、顶部搜索和可视化 HTML。目标不是重新做一套文档，而是：

1. 让老师按角色、任务和问题快速找到已有内容；
2. 统一运行时真值，避免 `docs/help` 与前端内容双轨漂移；
3. 用真实业务证据补齐前置条件、正确结果、权限、异常和不可逆影响；
4. 将帮助内容纳入功能 PR、测试和发布流程；
5. 分阶段接入学生 PC、教师小程序和学生小程序。

核心结构：**角色导航 + 高频任务 + 完整流程 + 异常排查 + 页面内帮助**。

## 2. 目标架构

```text
功能代码 / 状态机 / 权限 / 路由
          ↓ 事实核验
frontend/src/config/help*        运行时结构化帮助真值
frontend/public/help/*           可视化业务图
          ↓ 渲染、搜索、深链
/admin/help                      管理 PC 帮助中心
          ↑ 治理、审计、证据
docs/help/*                      规范、覆盖矩阵、草稿、验收记录
```

当前不立即迁移到 Markdown 单一源或外部 CMS，理由见 ADR-001。

## 3. P0：先消除生产误导风险

1. 单一真值与自动校验；
2. 权限、数据范围和状态排障；
3. 账号、组织初始化、导入错误和统一导出；
4. 教务、学工、实习、毕设的前置条件、退回、正式发布和归档影响；
5. 帮助首页、搜索、角色、分类和无结果恢复；
6. 真实角色与资产复核。

验收以 [覆盖矩阵](COVERAGE_MATRIX.md) 和 [完成定义](maintenance/definition-of-done.md) 为准。

## 4. P1：多端高频闭环

- 教师小程序：待办、审批、批阅、风险处置、消息；
- 学生小程序：申请、进度、退回修改、补材料、消息；
- 学生 PC：材料、进度、成绩、申诉和归档；
- 页面级帮助和错误级帮助；
- 统一导入导出：模板、预校验、错误行、审计台账和异步结果。

## 5. P2：规模化运营

- 搜索无结果词统计；
- 文章是否有用反馈；
- 按版本和租户发布；
- 负责人看板与过期提醒；
- 评估 Markdown 生成管线或 CMS；
- 从同一源生成产品帮助和培训材料。

## 6. 内容质量模型

正式条目应包含：ID、标题、关键词、角色、端、模块、入口、前置条件、步骤、正确结果、权限/数据范围、异常排查、不可逆影响、相关入口、负责人、状态、版本、复核日期和证据。

旧条目缺字段时渐进兼容，不因元数据不完整而误隐藏内容。

## 7. 查找体验

帮助首页同时支持按角色、任务、业务和问题查找。角色筛选只减少信息噪音，真正权限仍由业务路由、接口权限和数据范围控制。

## 8. 资产策略

- `interactive-visual`：HTML 业务地图；
- `screenshot`：真实页面操作证据；
- `illustration`：概念说明图。

三类资产不能互相替代。现有 25 个 HTML 文件不等于逐步截图和真实角色验收已完成。

## 9. 发布与维护

功能 PR 必须检查运行时条目、可视化资产、路由映射、真实角色验收、截图和复核证据。专用工作流检查 Markdown 链接、目录路径、草稿元数据、资产清单、嵌入路径、ID 唯一性、角色映射、搜索、测试和构建。

## 10. 交付判断

正式商用最低标准：20 个 P0 任务达到 `reviewed`，高风险任务达到 `published`；重要业务覆盖正常、退回、失败和恢复；资产完成隐私/版本复核；自动闸门和真实角色验收均通过；多端差异明确。

当前 PR 只建立底座并提升管理 PC，不宣称已完成全部多端验收。
