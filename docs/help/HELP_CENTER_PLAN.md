# Help Center V3 建设与运营方案

更新日期：2026-08-10

## 1. 当前定位

帮助中心已经不是“待建设文档库”，而是由以下能力组成的 **核心业务自助服务层**：

- 我要办一件事；
- 我遇到问题；
- 核心业务流程；
- 本页帮助与下一步导航；
- PC / 小程序共用知识；
- 高频错误自助排查；
- 第一次使用指南；
- 搜索、阅读和反馈指标。

核心目标仍然不是文章数量，而是：

> 核心业务可自学、常见错误可自查、第一次使用可自助、错误知识不发布。

## 2. 当前权威架构

```text
业务代码 / 状态机 / 权限 / 路由
          ↓ 重新验真
frontend/src/config/help*              运行时结构化帮助真值
frontend/src/config/helpCenterRuntime  verified-only 清洗/发布门
          ↓
/admin/help                            管理端帮助中心
/help                                  公开只读帮助
miniapp pages/common/help              小程序统一入口
          ↓
help_metrics                           搜索/阅读/反馈低敏统计

frontend/public/help/*                 可视化业务图

docs/help/*                            治理、审计、覆盖和发布证据
```

`docs/help` 不复制第二套正式运行时正文。

## 4. 内容质量模型

正式任务卡应尽量具备：

1. 用途；
2. 适用角色；
3. 入口；
4. 前置条件；
5. 操作步骤；
6. 完成标志；
7. 下一步；
8. 退回/失败/异常处理；
9. 权限、数据范围和业务关系说明；
10. 何时需要找管理员。

旧条目如果不能证明这些事实，不因“看起来完整”而自动回流。

## 5. 权限解释原则

帮助中的统一解释模型：

> permissionCode + 数据范围 + 稳定业务关系/owner/assignee + 当前业务状态。

角色筛选只做推荐，不是权限边界。即使帮助显示某任务，服务端仍可以因为权限、范围、关系、状态、版本或安全审计失败而拒绝。

## 6. 搜索与角色推荐

问题式搜索支持自然语言和错误码，例如：

- 为什么成绩提交不了；
- 成绩 409；
- 为什么看不到学生；
- 为什么被退回不能改。

角色推荐保留 authRole 粗粒度自动映射，同时提供更细的人工筛选：教务处管理员、学院管理员、辅导员/班主任、学工处管理员、心理老师、资助老师、任课/录分教师、实习指导/企业导师、毕设导师/评阅/答辩等。

## 7. 指标使用边界

可用于发现知识缺口：

- 搜索命中/无结果趋势；
- 文章阅读；
- HELPFUL / NOT_HELPFUL 明确反馈。

不可伪造：

- 在真实人工升级/工单闭环尚未接通前，不能把反馈率叫“真实自助解决率”；
- 客户端遥测不能替代安全审计真值；
- 搜索原文不落库。

## 8. 资产策略

- `interactive-visual`：HTML 业务地图；
- `screenshot`：真实页面操作证据；
- `illustration`：概念说明图。

三类资产不能互相替代。流程图不是页面截图，已有 HTML 数量也不能替代真实角色和真实设备验收。

## 9. 后续不再以“继续堆文章”为主

接下来的工作转为持续运营：

1. 功能 PR 改路由、状态机、权限、字段时同步检查关联帮助；
2. 用 SEARCH 无结果与 NOT_HELPFUL 找真正缺口；
3. 多学校真实角色/范围组合做实施验收；
4. 微信真机、弱网、隐私授权持续验证；
5. 可视化资产做版本与隐私复核；
6. 将来人工客服/工单体系成熟后，再建设真实升级闭环和真实自助解决率。
