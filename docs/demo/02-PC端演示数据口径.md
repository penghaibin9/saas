## 3. 关键指标从哪来（禁止硬编码）

`frontend/src/mocks/db.js` 文件头明确写明规范：

> 驾驶舱指标一律由本文件数据经 `utils/aggregate` 计算，禁止任何地方硬编码指标值。

`frontend/src/utils/aggregate/index.js` 提供 4 组聚合函数，均以 `db.js` 的学生/实习/打卡/周报/毕设/就业/待办数据为输入，实时计算输出：

| 聚合函数 | 输入 | 输出指标（节选） |
|---|---|---|
| `aggregateInternshipMetrics` | students、internships、checkins、weeklyReports、today、currentWeek | 在岗实习人数、今日打卡率（含较昨日趋势）、连续 3 天打卡异常人数、本周周报提交率（含较上周趋势）、实习风险学生数 |
| `aggregateGraduationDesignMetrics` | gdTasks、today | 毕设学生数、开题提交率、开题通过率、开题逾期未提交人数、开题优秀人数、中期待批阅份数 |
| `aggregateEmploymentMetrics` | students、employments | 就业去向填报率、材料被退回人数、材料核验通过人数、企业拟录用人数 |
| `aggregatePracticeTeachingMetrics` | students、gdTasks、internships、weeklyReports、todos、today、currentWeek | 在管学生总数、毕设进行中人数（含节点逾期提示）、在岗实习人数（含本周周报提交进度）、风险学生数、教师待办数 |

演示口径要点：

- 这些函数只服务于**由 `db.js` 五人剧本驱动的模块**（实习/毕设/就业/实践教学总览）；`dataCenter`、`academic`、`campusService`、`orientation`、`approval`、`system`、`platform` 等模块的指标是**各自 mock 文件里预置的 `dashboardSummary`/`overviewMetrics` 常量**（如"在册学生总数 4520 人"），不是由 `aggregate` 函数现算的，但同样遵循"数字之间自洽"的设计原则（例如 `dataCenter.mock.js` 文件头注释写明"生命周期漏斗各阶段人数逐级递减""学院排行学生数合计=在册学生总数""就业去向落实=签约+升学+参军+创业"等校验过的口径）。
- 如果演示中修改任意一条 `db.js` 里的记录（比如把赵一凡的打卡状态改成 `NORMAL`），实习/毕设/就业/实践教学总览这 4 组指标会自动联动变化，这是可以现场展示的"数据驱动"能力点；但 `dataCenter` 等模块的预置指标常量**不会**跟着联动（因为它们是独立预置数字，不经过 `aggregate` 计算），演示时应避免说"改一条数据全平台指标都变"，准确说法是"实习/毕设/就业/实践教学总览这组指标是实时算出来的，其余模块概览指标是预置的演示口径"。

## 5. 演示注意事项

- 切换角色查看数据范围差异是本系统的核心卖点之一，**演示前务必确认目标模块的 `roleProfiles`/`currentRole` 支持角色切换**（多数模块支持 4～6 种角色 mock 切换，`internship.mock.js`、`graduation.mock.js` 目前是单一固定视角，不支持现场切换角色，见对应文件的 `currentRole` 常量）。
- 各模块 mock 文件顶部均写明"页面禁止直接 import 本文件，必须经 `modules/xxx/api/xxx.api.js` 获取"，这是前端门面模式的约定，演示时无需展开讲解代码结构，但如被技术评审追问，可以此说明"未来接后端时只需替换 api 层实现，页面不用改"。
- 演示驾驶舱模块时，如遇到"在册口径"与"自然口径"两套数字，统一口径解释为："在册口径只统计学籍状态为'在册'的学生；自然口径额外包含休学、保留学籍、保留入学资格的学生，用于对外报送时与教育主管部门口径对齐"（原话见 `dataCenter.mock.js` 注释）。
