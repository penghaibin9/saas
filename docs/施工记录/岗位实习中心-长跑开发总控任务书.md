# 岗位实习中心 · 长跑开发总控任务书

> 落盘：2026-07-09 ｜ 用途：岗位实习中心生产级长跑开发的**唯一权威总控**，防止长跑遗忘/跑偏/漏项。
> 配套：`岗位实习中心-长跑TODO清单.md`（机器可执行）、`岗位实习中心-生产级全栈施工卡.md`（盘点+P0记录）、`历史欠账.md`。
> 本任务书 = 长跑总提示词 + 成熟商业软件增强规则的合并落盘。两者冲突时，**以"成熟商业闭环/权限安全/真实数据/公共组件/审计/Excel/状态机"为准**。

---

## 0. 最高目标（不是"能打开几个页面"）
1. 学校管理员能管：批次、学生、企业、岗位、匹配、协议、打卡、周报、请假、指导、风险、评价、成绩、归档、统计；
2. 指导教师能看**本人负责学生**，批周报、处理异常、写指导、看风险；
3. 学生小程序能打卡、交周报、看岗位和协议，后续可申请请假/补卡；
4. 企业导师能力**预留清楚**（最小授权，只看授权学生，不做假闭环）；
5. 权限 + 数据范围**真实生效**；Excel + 审计**真实生效**；UI 达商业销售截图标准；
6. **不能正式上线的地方必须诚实标 partial，绝不把半成品混进 implemented。**

## 1. 施工顺序（不跳阶段）
```
P0  安全底座与可达性收口
P1  过程监管闭环
P2  协议、评价、成绩闭环
P3  归档统计与商业 UI 统一
P4  最终全量验收与提交报告
```
先安全/路由/数据范围/真实导入导出/小程序硬 bug；**不要先做花哨 UI、AI 推荐、统计大屏。**

## 2. 每阶段前置协议（防止凭记忆施工）
进入任一阶段**之前必须**：
1. 重新读取：`CLAUDE.md`、本任务书、`岗位实习中心-长跑TODO清单.md`、`docs/公共组件/00-高校SaaS公共组件商业化底座总控表.md`、`历史欠账.md`；
2. 先输出**「本阶段施工计划」**（要改的文件 / 新增接口 / 新增表字段 / 测试 / 公共组件 / 验收命令 / commit 建议 / 本阶段成熟商业对标项）；
3. 再开始改代码。
**不凭记忆施工、不跳阶段、不漏对标项、不把 partial 说成 implemented。**

## 3. 成熟商业岗位实习系统必备 40 项能力（对标基线）
实习计划/批次 · 企业准入/企业库 · 岗位发布/岗位库 · 岗位申请 · 岗位申请多级审核 · 岗位匹配/分配 · 换岗/退岗/调岗 · 三方协议发起 · 学生确认 · 企业确认 · 学校确认 · 协议归档 · 定位打卡 · 打卡防作弊 · 打卡异常 · 补卡申请 · 补卡审批 · 周报提交 · 周报批阅 · 请假申请 · 请假审批 · 指导记录 · 教师巡访 · 企业导师反馈 · 风险学生发现 · 风险处置 · 风险关闭 · 企业评价 · 学生自评/鉴定 · 实习成绩计算 · 实习归档 · 实习统计 · 就业去向衔接 · 企业导师最小授权 · Excel 导入导出 · 审计追踪 · 权限门禁 · 数据范围 · 附件/文件中心预留 · 小程序学生端/教师端真实闭环。
> 某项本轮不能完全实现 → 标 partial/blocked，**不得假装 implemented**。

## 4. 必须复刻的老系统 6 大精华资产（设计文档 06 已证）
1. **定位打卡防作弊字段全集**：student_id/batch_id/enterprise_id/position_id/打卡时间/类型(上班·下班·外勤·补卡)/经纬度/地址/与企业距离/是否超范围/设备ID/疑似模拟定位(is_mock)/异常设备/重复打卡/风险等级/异常原因/处理状态/补卡关联/审计。无真实地图/照片/对象存储时**字段预留 + 标 partial**。
2. **岗位申请五级状态机**：待学生提交→待指导教师审核→教师同意→待企业确认→企业已确认→学校已确认→已录用/已分配；旁支：已驳回/学生撤回/已换岗/已退岗/已归档。每态明确「谁能操作/能点什么/下一态/非法拒绝/写审计/pytest 覆盖」。
3. **三方协议双状态**：协议总状态(草稿/待学生确认/待企业确认/待学校确认/已生效/已驳回/已作废/已归档) + 签署人状态；无电子签章时做「确认流+文件归档+电子签预留」标 partial。
4. **教师巡访月报**：巡访计划/对象/企业/时间/方式/企业反馈/学生反馈/安全隐患/整改要求/整改截止/整改状态/巡访月报/审计/导出。
5. **实习成绩五项权重**：打卡分/周报分/月报总结分/企业评价分/学校评价分(+指导教师评分)/权重配置/及格线/自动核算/人工复核/发布/撤回/归档/审计/导出。pytest：权重和=100、缺项不能发布、计算正确、复核留痕、非法发布拒、数据范围隔离。
6. **企业导师最小授权门户预留**：企业导师身份/只看授权学生/可填评价/可反馈/可确认协议/不能看学校其他数据/操作审计。不做企业端页面也必须在权限与文档预留，**不得把企业评价做成学校老师代填的假闭环**。

## 5. 生产级红线（每条都是 implemented 的前置）
- **权限门禁**：管理端接口无 require_staff 不得标 implemented。测试：未登录401/学生403/教职工放行。
- **数据范围**：指导教师只看本人指导学生、辅导员看本范围、学院负责人看本院、管理员看全校、学生看本人、跨租户隔离、企业导师只看授权学生。优先复用 `resolve_teacher_scope`。
- **状态机**：每业务流程有状态枚举+操作人+允许动作+非法拒绝(后端)+前端按钮只做体验+每次流转写审计+pytest 覆盖。
- **Excel**：正式台账一律 xlsx（禁 CSV 冒充）；模板下载/行级校验/错误行反馈/导入记录/导出脱敏/水印/审计/pytest。逐步覆盖：学生/企业/岗位/匹配/打卡/周报/请假/指导/风险/协议/评价/成绩/归档台账。
- **附件**：无真实对象存储时只做 file_id 预留 + AppFileList/AppFilePreview 展示 + 附件状态 + TODO；**禁止假上传成功、禁止只存文件名就宣称附件中心完成、禁止无 file_id 却说归档包完成**。
- **审计**：复用 `audit_log.record` / `InternshipAuditTrail`（append-only），不伪造。

## 7. 商业 UI 验收（销售截图标准）
清透学院蓝 · 成熟 SaaS 质感 · 密度合理 · 不像 Demo/学生作业/AI 拼接 · 关键数据一眼懂 · 路径清晰 · 风险异常待办突出不刺眼。每个核心页必须有：顶部业务说明/关键指标/筛选区/列表区/批量操作/行内操作/空态/加载态/错误态/权限不可操作说明/审计入口/导出入口。

## 8. 提交纪律（每次 commit 前）
`git status --short` → `git diff --cached --name-only` → `git diff --cached --stat` → `npm run build` → `npm run lint` → 相关 pytest。
**禁止**：git add -A / git push / push --tags / 提交 dist、node_modules、.env、.claude、query、删除的旧设计文档、与本阶段无关的毕设/迎新/学工/教务混杂文件。
工作区有大量混杂改动时**只选择性 add 本阶段相关文件**。

## 9. 硬红线（必须停止并报告）
需删真实数据 · 大改数据库核心结构且无 migration 方案 · 需改毕业设计中心 · 需提交 backend/miniapp/frontend/docs 混杂大杂烩 · npm build 无法通过且原因不明 · pytest 大量失败无法定位 · 涉密钥/短信/对象存储真实配置 · 需 push。

## 10. 做不完的降级规则（不烂尾）
当前阶段做到 build/lint/pytest 通过 → 形成 clean commit（或本轮约定的"只改不提交"）→ 未完成写入 `历史欠账.md` 标 partial/blocked → 不假装上线 → 不把半成品混进 implemented → 再进下一阶段。
