## 二、一次性完工标准（每个模块/页面点亮的验收线）

一个页面从 `planned` 点亮为 `implemented`，必须同时满足：

1. **前端页面接真实接口**（`request('/...')`，不是纯 mock 展示）；
2. **后端齐全**：model + service + api（+ 需要时 alembic 迁移）；
3. **状态机**：状态流转有校验，非法流转被拒；
4. **权限**：用 `studentAffairs.xxx.*` 新 key（旧 key 保留兼容，不删）；
5. **数据范围**：后端按当前角色 `resolve_teacher_scope` 过滤；
6. **审计**：关键操作写审计；
7. **脱敏**：敏感字段（身份证/手机号等）默认脱敏；
8. **导入导出**：需要的页至少 CSV/XLSX 之一，真实导出；
9. **pytest 通过**（自修复 ≤ 3 轮，修不好输出剩余错误 + 续接提示词）；
10. **前端 lint + build 通过**；
11. **navPlan.js** 对应节点 `planned/partial` → 更新为真实状态；
12. **不删旧路由/表/接口，不清数据，不改生产库，不提交 git（除非明确要求）**。

只前端完成、后端未闭环 → 标 `partial`（待补强）。
只有规划 → `planned`（待施工）。
