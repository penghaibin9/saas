# 04 · 如何判断项目是否跑起来

按顺序做三步，任何一步给出结论就可以停。

## 第一步：看项目整体状态

在项目根目录执行：

```
powershell -ExecutionPolicy Bypass -File scripts\check\project-status.ps1
```

它会告诉你：哪些工程存在、依赖装没装、git 有没有未提交改动、现在哪些端口有服务在跑。

## 第二步：跑访问自检（最直接）

在项目根目录执行：

```
node scripts\check\smoke-check.mjs
```

怎么读结果：

- `[OK] PC 前端 可访问...` → PC 跑起来了。
- `[OK] 小程序 H5 可访问...` → 小程序 H5 跑起来了。
- `[--] ... 未启动` → 没在跑，按提示运行对应 start 脚本。
- `[--] 后端 API 未启动/未创建` → 目前是正常现象（后端还是底座），可忽略。
- `[?]` → 端口上有服务但对不上号，可能被别的程序占了，跑一下 check-ports 看看。

注意：服务**刚启动**时要等编译完成（启动窗口出现 ready / Local: http://... 字样），太早跑自检会误报未启动。

## 第三步：亲眼看一下页面

- PC 前端：浏览器打开 http://localhost:5173/ ，能看到页面就是活的。
- 小程序 H5：浏览器打开 http://localhost:5188/ ，能看到「我是学生 / 我是老师」入口就是活的。

## 想确认代码能不能打包（可选，较慢）

```
powershell -ExecutionPolicy Bypass -File scripts\check\build-check.ps1
```

最后有一张汇总表，全部「通过/跳过」就没问题；有「失败」就往上翻那一段的第一条红字，对照 [02-常见启动失败处理.md](02-常见启动失败处理.md)。

## 出现红字先看哪里

1. 先看**启动窗口里第一条红字**（不是最后一条）。
2. 对照 [02-常见启动失败处理.md](02-常见启动失败处理.md) 找症状。
3. 解决不了就把第一条红字截图求助。
