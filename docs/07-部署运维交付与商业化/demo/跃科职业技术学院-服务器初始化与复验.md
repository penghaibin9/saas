# 跃科职业技术学院（007）服务器初始化与复验

本说明用于把 007 演示数据随当前分支代码部署到服务器。数据库数据不依赖本地 SQL 快照交付，权威来源是版本化迁移与幂等初始化脚本。

## 边界

- 只允许租户 `1000000000000000007` / `sandbox-school`。
- 禁止使用、恢复或写入 004 `trial-school`。
- 先备份 007，再升级迁移，再执行重建；不得省略 dry-run 和最终审计。
- Alembic 迁移账号需要创建触发器权限；应用运行账号无需该权限。

## 执行顺序

```powershell
cd backend

# 1. 确认代码与数据库连接后，先备份 007
.\.venv\Scripts\python.exe scripts\backup_sandbox_tenant.py --output-dir D:\backups\sandbox-school-007

# 2. 使用迁移账号安装包含 007 不可变证据重建保护的最新迁移
.\.venv\Scripts\alembic.exe upgrade head

# 3. 只读预检
.\.venv\Scripts\python.exe scripts\reset_sandbox_school.py --dry-run --profile standard-20k

# 4. 由密钥管理/部署环境临时注入三份口令；不要写入仓库或镜像
$env:SANDBOX_ADMIN2_PASSWORD='<从密钥管理注入>'
$env:SANDBOX_TEACHER2_PASSWORD='<从密钥管理注入>'
$env:SANDBOX_STUDENT2_PASSWORD='<从密钥管理注入>'

# 仅当服务器必须保持约定的 007 固定演示口令时，显式开启并确认精确租户。
# 该确认只放宽 007 的演示账号兼容门槛，不影响其他租户账号。
$env:SANDBOX_ALLOW_FIXED_DEMO_CREDENTIALS='1'
$env:SANDBOX_FIXED_DEMO_CREDENTIALS_PRODUCTION_ACK='1000000000000000007'

# 5. 全量重建 007
.\.venv\Scripts\python.exe scripts\reset_sandbox_school.py --confirm --profile standard-20k

# 6. 独立逐表与业务验收
.\.venv\Scripts\python.exe scripts\audit_sandbox_table_coverage.py
.\.venv\Scripts\python.exe scripts\check_sandbox_20k_school.py
```

Linux 服务器使用同名环境变量，执行等价命令即可；密码应由 systemd credentials、容器 secret 或部署平台密钥注入，不能写进 `.env`、Shell 历史或日志。

## 通过标准

- `databaseTables=450`（若后续迁移新增表，以服务器实时扫描为准）。
- `coveredBusinessTables == productionBusinessTables`。
- `emptyBusinessTables=0`。
- 各业务模块覆盖率 100%。
- 关联异常、跨租户污染、非法状态、统计不一致全部为 0。
- 三个必须为空的安全/生命周期表保持为 0：`t_portal_login_otp`、`t_tenant_offboarding_job`、`t_tenant_tombstone`。
- 使用 `sandbox-school` 分别登录 `admin2`、`teacher2`、`student2`，返回租户必须为 `1000000000000000007`。

## 回滚

初始化失败时停止继续写入，保留脚本输出和审计 JSON。使用步骤 1 生成的 007 专用备份恢复；禁止对整库或其他租户执行回滚。修复脚本后重新从备份/全量 007 reset 验证，不手工补写零散生产数据。
