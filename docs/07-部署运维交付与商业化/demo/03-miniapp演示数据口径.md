## 4. mock 延时与 loading 演示

- 所有 mock 请求统一通过 `miniapp/src/services/request.js` 的 `mockRequest()` 模拟网络延时，固定 **260ms**（`ENV.mockLatency`，定义于 `miniapp/src/config/env.js`），用 `Promise + setTimeout` 实现，返回前做深拷贝避免页面修改污染 mock 源。
- 页面典型写法：进入页面时 `state` 先置为 `loading`，调用对应 `studentApi`/`teacherApi` 方法，成功后置为 `ready`，失败则置为 `error`；支持下拉刷新（`onPullDownRefresh`）重新加载。
- 全局态组件 `MobileGlobalState.vue` 支持 8 种状态：`ready`（正常渲染）、`loading`（骨架屏 + "正在加载…"）、`empty`（空状态）、`error`（"!"图标 + "加载失败" + "数据加载出现问题，请重试" + 重试按钮）、`forbidden`（"当前身份无权查看"）、`offline`（网络异常）、`readonly`（模块只读）、`noLicense`（模块未开通）。
- **重要口径**：当前所有页面的 `mockRequest()` 调用**均未传入 `fail: true`**，也就是说 mock 阶段**默认不会触发 error 态**——loading 态会正常出现（260ms 短暂骨架屏），但 error/forbidden/offline/readonly/noLicense 这些状态目前是"页面组件已具备渲染能力，但需要额外触发条件才会展示"，演示时如果想展示这些异常态（例如给客户看"断网提示长什么样"），需要提前和研发确认如何临时触发（例如改一次代码传 `fail:true`，演示后改回来），**不属于默认可直接点出来的路径**，详见 `06-演示前数据检查清单.md` 中的"断网/错误态演示开关"条目。
- 演示效果：由于延时固定 260ms，切换 tab 或进入新页面时会有一个短暂但可感知的 loading 骨架屏闪现，这是**刻意保留的真实感设计**，不是网络卡顿，讲解时可以说明"这是我们特意模拟的网络延时，方便验证界面的加载态设计"。
