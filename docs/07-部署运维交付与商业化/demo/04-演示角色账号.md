# 04 演示角色账号

- **文档性质**：演示角色账号设计表（演示用建议口径，非真实账号体系）。
- **适用端**：PC 管理端（`frontend/`）+ 小程序端（`miniapp/`）。
- **依据**：共享事实底稿第 2 节（miniapp 角色 `config/roles.config.js`）、第 3 节（RBAC 角色码 `workflow.mock.js`）；各 PC 模块 mock 文件的 `roleProfiles`/`currentRole`。
- **当前阶段声明**：**当前系统 `useMock=true`，无真实登录、无账号密码体系**。本文档中的"账号"均为**演示用建议口径**，即"演示时该用哪个身份/进入方式去看哪块数据"的操作指引，不是数据库里真实存在的用户记录。真实账号体系将在后端接入后建立（待后端确认）。
- **生成日期**：2026-07-04

---

## 0. 总口径说明

当前没有"登录输入账号密码"这件事。两端的"账号"本质是：

- **miniapp**：登录页选"我是学生"或"我是老师"→ 模拟登录成功 → 若选老师，再到身份选择页（`role-switch`）选 6 种身份之一，此后所有页面按该身份的 `dataScope` 渲染对应 mock 数据。这是**唯一登录用户+多身份切换**模式（一个人张明远，切 6 种帽子）。
- **PC 端**：无登录页拦截，各业务模块内部通过模块自带的 `roleProfiles`（如 `student.mock.js`、`dataCenter.mock.js`）或单一固定 `currentRole`（如 `internship.mock.js`、`graduation.mock.js`）来演示"切换角色查看不同数据范围与按钮权限"，具体切换入口以各模块页面内的角色选择器为准（如页面右上角"当前角色："下拉，或模块设置里的 `switchRole`/`mockRuntime.activeRoleCode` 机制）。**PC 端目前每个模块的"可切换角色数量"不完全一致**，部分模块（如实习、毕设）当前是单一固定视角，不支持现场切换，演示前请先确认目标模块是否支持切角色。

## 3. PC 端角色切换操作口径

由于 PC 端不同模块的角色切换机制尚不完全统一，演示前建议按以下口径操作：

| 模块 | 是否支持现场切角色 | 切换依据 |
|---|---|---|
| 学生主档 | 是（5 档：学籍老师/辅导员/学院管理员/教务老师/系统管理员） | `student.mock.js` 的 `roleProfiles` + `mockRuntime.activeRoleCode` |
| 数据驾驶舱 | 是（5 档：校级领导/学院管理员/教务老师/就业老师/系统管理员） | `dataCenter.mock.js` 的 `roleProfiles` + `mockRuntime.activeRoleCode` |
| 审批中心 | 是（5 档：学院管理员/辅导员/指导教师/教务老师/就业老师） | `approval.mock.js` 的 `roleProfiles` |
| 在校服务 | 是（6 档：辅导员/学院管理员/学工老师/宿管老师/资助老师/心理老师） | `campusService.mock.js` 的 `roles` |
| 学业过程 | 是（5 档：学院管理员/辅导员/任课教师/教务老师/学籍老师） | `academic.mock.js` 的 `roles` |
| 数字迎新 | 是（5 档：辅导员/学院迎新老师/财务老师/宿管老师/学院管理员） | `orientation.mock.js` 的 `roles` |
| 就业服务 | 是（4 档：就业老师/辅导员/学院管理员/教务老师） | `employment.mock.js` 的 `roles` |
| 岗位实习 | **否，单一固定视角**"刘强（实习指导教师）" | `internship.mock.js` 的 `currentRole` |

## 4. 接后端后的处理提示

**接后端后替换为真实账号（待后端确认）**。届时需要明确：

- 真实的账号/密码或统一身份认证（SSO/CAS）登录流程（miniapp 与 PC 端均待补充）；
- 真实的角色-用户绑定关系从后端 RBAC 服务下发，而非当前 mock 里"选一个身份就是那个身份"的演示态；
- `activeContextId`（当前工作上下文，例如张明远同时是辅导员/毕设导师时具体绑定哪些学生）由后端下发，前端不再本地维护；
- 平台运营等高权限角色的账号开通与安全管控机制（待后端确认，需符合共享底稿第 4 节安全基线要求，如首登强制改密、会话超时策略等）。
