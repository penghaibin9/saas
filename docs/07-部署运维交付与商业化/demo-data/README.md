# 演示数据统一口径 · 导航（docs/07-部署运维交付与商业化/demo-data/）

- **文档性质**：演示数据**统一口径**文档（设计口径 / 讲解口径），**非**产品需求、**非**接口契约、**非**数据库设计文档。
- **和 `docs/07-部署运维交付与商业化/demo/` 的分工**：
  - `docs/07-部署运维交付与商业化/demo/` = **mock 现状说明**（现在 mock 里到底有什么、数据从哪来、两套租户为什么不完全打通）。
  - `docs/07-部署运维交付与商业化/demo-data/`（本目录）= **演示统一口径**（一套"好讲、能讲通全链路"的标准叙事 + 人物 + 数据点 + 字段口径，并标注与现状的差异）。
- **一句话定位**：本目录回答"**演示时统一按什么口径讲**"；`docs/07-部署运维交付与商业化/demo/` 回答"**现在 mock 里实际是什么**"。两者配套使用，不冲突。
- **权威冻结文档只引用、不重写**：数据库以 `docs/05-数据接口权限与安全/database/00-数据库设计冻结总册.md` 为准，API 以 `docs/05-数据接口权限与安全/api/00-API契约冻结总册.md` 为准，角色以 `docs/05-数据接口权限与安全/rbac/` 为准。本目录引用其枚举与角色码，不新建表、不改字段、不改契约。
- **不改任何 mock、代码、路由、provider**：本目录纯文档。
- **学校名可配置**：演示学校名一律走可配置租户占位（`tenantBrandConfig.schoolName`），**不硬编码任何真实客户名称**。

## 三、怎么用这套口径

- **准备一次客户/领导演示** → 先读本 README 记住"世界观速览"，再照 `docs/07-部署运维交付与商业化/demo/一套完整演示脚本.md` 走一遍，用 02 确认每步用哪个角色进入。
- **被问"这个学生/这个数字怎么来的"** → 查 03～06 对应主题的数据点表；查枚举/状态含义 → 查 07。
- **被问"这是真数据吗"** → 统一回答：**当前是演示口径数据，用于验证界面与全生命周期流程；真实数据由后端接入数据库后提供（接入时间待后端确认）**。
- **改演示学校名/配色** → 只改租户品牌配置占位（见 01 §1），文档口径不受影响。

## 四、边界声明（重要）

1. 本目录是**口径层**：定义"演示应该怎么统一讲"。凡与当前 mock 现状不一致处，均标注 **【目标口径】**（后端/统一 seed 后应达到）与 **【现状差异】**（当前 mock 实际情况，指向 `docs/07-部署运维交付与商业化/demo/01`、`docs/07-部署运维交付与商业化/demo/02`）。
2. 现状 mock 存在**两套并行租户**（`tenant-demo-001` / `tenant-demo-a`）与 **两端独立人物**（PC 端剧本 vs 小程序林可欣/张明远），演示时**不要跨端/跨租户做"数据勾稽"式追问**（如在 PC 端搜林可欣、在小程序搜赵一凡）。详见 01 §4、`docs/07-部署运维交付与商业化/demo/01` §4。
3. 本目录**不修改**任何 mock 文件、组件、路由、provider、后端、数据库、API 契约。
