## 4. 无 tenant_id 不等于全局无关

473 个声明中的 24 个无 tenant_id 对象已逐项完成结构判读（报告逐表列路径、类、范围、余项）；另外两张仅在迁移中的 IAM 审计表已单列。

| 范围 | 表/结构 | 不能采取的做法 |
|---|---|---|
| 学校主体 | t_tenant.id 就是学校标识 | 只退一模块也删/停整个 Tenant |
| 父任务间接归属 | t_tenant_offboarding_step.job_id → job.tenant_id；t_provisioning_step_run.job_id → provisioning job | 父任务未建成 tenant_id 可空，不得猜成 tenant=0 |
| 跨校控制事实 | incident/update 经 IncidentTenant；change/execution 经 ChangeImpact 和 tenant_ids_json；problem/postmortem 经父关系 | 把一个多学校事件当单校独占记录整条删除 |
| 共享认证 | refresh token 的 user_id/claims_json；blocked_jti；challenge state | 模块退出撤销所有会话或清认证风险状态 |
| 公共定义 | Permission、ConfigDefinition、PlatformService、ServiceDependency、MaintenanceWindow | 随模块删除权限、配置定义或全局维护窗口 |
| 国家标准 | source/catalog/document/section；学校绑定另带 tenant_id | 删除一校绑定时一起删除公共标准 |
| 备份恢复 | BackupEvidence、RestoreDrill、RecoveryRun | 将 location_ref、摘要或机器回执当作“全部介质已销毁”证明 |

这些是结构及安全边界判读，不是记录级解析器已实现。外键可能只以 BIGINT/JSON 表达；孤儿、空父标识和多租户关系仍需阻断或单列，不归入默认可删模块。
