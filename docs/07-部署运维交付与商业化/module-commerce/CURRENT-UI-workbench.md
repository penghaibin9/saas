# PR #263｜商业办理入口、续费衔接与只读退出检查

本轮源码基线：`13476f37f2ad9d3d21369a6baf17aeb9f0847b4d`。
唯一分支：`feat/platform-module-commerce`。本文件是增量施工与验收边界，不是全阶段完成或上线批准。

## 从哪里进入

平台运营 → 产品、合同与授权 → 商业授权与计量对账。
原地址 `/admin/platform/commercial-control` 不变；平台权限仍由目录的 `platform.commercial.view` 和后端职责核验决定。学校教师、学生或学校管理员不获得平台商业办理权限。

本轮新增七个**页内办理入口**，不是七个一级菜单，也不新建独立页面路由：

| 入口 | 实际落地组件/区域 | 办理内容与边界 |
|---|---|---|
| 商品与订购 | ModuleSalesWorkspace | 商品版本、分项新购/续费、订单台账与xlsx；不自动收款 |
| 到期与续费 | ModuleRenewalWorkspace | 续费候选、现有RenewalTask跟进；本轮补通到销售草稿 |
| 应收、退款与发票 | ModuleFinanceWorkspace | 原分支已有财务请求、审批和外部凭据登记；不是自动银行退款或税务开票 |
| 售后与服务成本 | ModuleOperationsWorkspace（位于财务组件之后） | 原分支已有售后/SLA与成本办理；本轮增加可直接定位的入口 |
| 交付与模块退出 | 主页面生命周期四步工作区 | 验收、期末停续、冻结、候选交付包绑定/签收和消费者变化后的重绑 |
| 退出完整性检查 | ModuleExitReviewPanel（本轮新增） | 读取交付/保留/共享文件/资源归属阻断；没有删除、审批或执行按钮 |
| 用量与对账 | 主页面商业与存储对账 | 不把学校整体消费与模块逻辑用量混为一谈 |

销售、续费跟进、财务、售后和消费者卡片在接手基线中已存在。本轮保留这些已有实现，不把其他会话的提交计成本轮新增。

## 本轮补通的实际链路

**续费候选 → 同校同模块的销售草稿**：原按钮只滚动页面。本轮通过显式组件接口重新读取该校最新销售上下文，核对学校/模块代次/数据状态，取当前已付截止，带入RENEW业务类型与模块商品筛选。选商品后仅预填续费开始建议，商品版本/成交价必须重新选择，新的截止时间保持空白供明确填写。不创建订单、不延长授权、不复用旧价格。已提交但结果不明的原请求始终优先，不能为进入续费丢弃其幂等键。切换学校、并发编辑或身份复核期间变化会拒绝旧响应覆盖/发送。

**退出任务 → 即时只读阻断清单**：新增 GET `/api/v1/platform/commercial/tenants/{tenant_id}/module-offboarding/{job_id}/exit-review`，要求 `commercial.view`，并要求 `expectedGeneration` 与 `expectedVersion`。第一条任务查询就限定学校，之后核对任务代次与版本；跨学校404、旧版本409、依赖异常不伪装成功。基线商业路由声明由24条增加至25条，不含独立finance/operations/renewal路由。

前端绑定学校/任务/模块/代次/版本，并清除切换前的检查结果。只读响应按交付与保留、文件与共享引用、技术准入与备份、任务与消费者分组展示；候选资源分页。未知或越过只读边界的响应不显示为可执行结果。固定保留 `dryRunOnly=true` 与所有物理删除授权false、空删除语句，未完成完整闭包与备份政策仍明确阻断。

另外补上生命周期切换保护：办理中不能切学校/模块，切模块清空旧验收和政策表单；预检回执与正式冻结请求都绑定所选学校、模块和代次，旧响应不能变成另一模块的冻结依据。

退出办理表移除了未经确认的30天和SCHOOL-CONTRACT默认值，运营人员必须填写真实约定，不用程序默认值充当学校政策。
