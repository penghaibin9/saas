# 05 竞品对比话术

- **文档性质**：销售/售前对客沟通材料——通用能力对比维度与中性话术框架
- **适用对象**：销售，在客户拿本产品与其他产品/系统比较时使用
- **依据**：共享事实底稿（模块、角色、权限、审批、数据驾驶舱、多租户设计）
- **当前阶段声明**：当前为可演示版本，后端未接入真实数据，接入按 API 契约推进中
- **生成日期**：2026-07-04

---

## 使用原则（必须遵守）

1. **不点名任何具体竞品**，不评价、不猜测、不编造竞品的缺点或不足。我们没有对竞品做过详细的调研评测，任何关于"某某产品做得不好"的说法都属于无依据的编造，一旦说了、被客户追问细节或被同行听到，对公司信誉的伤害远大于短期的话术效果。
2. 讲话的立足点永远是"我们做到了什么"，不是"别人没做到什么"。中性、专业、以我为主。
3. 如果客户直接说"竞品也有这个功能"，正常回应是"很好，那说明这是行业里比较成熟的通用能力，我们在这个基础上想强调的是……"，然后讲我们的具体设计细节，而不是反驳客户或贬低对方产品。
4. 涉及到我们自己还没做到、或者还在推进中的能力（比如后端真实数据接入），如实说明现状，不要为了"赢"这场比较而夸大。

---

## 通用能力对比维度

以下十个维度，是学校客户在评估同类产品时通常会关心的通用维度。每个维度给出"我们的介绍话术"，不做与具体竞品的逐项打分对比。

### 1. 全周期覆盖

**我们的话术**："我们把学生从入学到毕业的整个周期——数字迎新、在校服务、学业过程、岗位实习、毕业设计、就业服务——放进同一个平台、同一份学生档案里管理，不是几个独立小工具拼在一起，而是围绕'一个学生'这个核心数据主体设计的完整链路。"

### 2. 角色化工作台

**我们的话术**："我们没有做成一个所有人登录进去看到同一套菜单的通用后台，而是按角色——校领导、学校管理员、二级学院管理员、指导教师、辅导员、学生、企业导师——设计了不同的工作台和权限范围，每个角色打开系统看到的都是自己职责范围内该处理的事情。"

### 3. PC+小程序闭环

**我们的话术**："管理类、汇总类的工作在 PC 端做，学生和老师的高频操作（申请、打卡、周报、审批）我们专门做了配套的小程序，两端是同一套业务逻辑和权限体系，数据是打通的，不是各自独立的两套系统简单拼接。"

### 4. 实习/毕设/就业闭环

**我们的话术**："岗位实习、毕业设计、就业服务这三个环节，我们做了完整的审批流程设计——比如实习申请从学生提交、指导教师审核、学院审核到辅导员抄送，毕业设计材料审阅要求退回必须写明原因，就业服务支持未就业学生的持续跟进——这三块是我们重点打磨的核心业务闭环。"

### 5. 风险预警

**我们的话术**："我们设计了风险学生的识别和跟进机制，辅导员和教务能在系统里看到需要重点关注的学生，并且创建关怀记录、标记跟进，把'凭经验发现问题'变成'系统辅助发现问题'。"

### 6. 审批流

**我们的话术**："审批中心把关键业务流程（实习申请、周报批阅、毕设材料审阅）统一沉淀，支持审批、退回、抄送、加签、撤回等多种动作，退回必须写明原因，全程留痕可查，这是我们在流程规范性上的设计重点。"

### 7. 数据驾驶舱

**我们的话术**："我们把分散在各模块的数据汇总成管理层能直接看的看板，减少人工汇总报表的工作量，这是数据中心模块的核心价值。"

### 8. 权限与数据范围

**我们的话术**："我们的权限设计是'角色决定能做什么、数据范围决定能看到谁的数据'两层分离的模型，数据范围细分到全平台、本校、本学院、本班级、仅本人、被指派对象六个层级，这个颗粒度是我们比较care的一个设计细节。"

### 9. 多租户与学校品牌

**我们的话术**："平台是多租户 SaaS 架构，每个学校数据独立隔离，还可以配置自己的品牌信息（校名、主色调），保证每个学校用起来感觉是'自己的系统'而不是一个通用平台的样子。"

### 10. 可扩展/集成能力

**我们的话术**："我们在架构设计上预留了跟第三方系统（比如统一身份认证）对接的方向，具体集成能力会随着后端接入和项目实施逐步完善，我们对这块的态度是稳步推进、如实汇报进展，不做过度承诺。"

## 应对"你们和 XX 有什么区别"的话术框架

当客户直接问"你们和某某产品/某某厂商有什么区别"时，使用以下三步框架回应，不评价对方产品：

**第一步：礼貌承接，不否认对方**
"XX 我们了解是这个领域里有一定知名度的产品/厂商，能进入贵校的比选名单，说明它有它的优势，这个我不方便替它评价，也没有做过详细的调研，不敢乱讲。"

**第二步：转回自己的核心差异点（挑 1–2 个跟客户当天最关心的痛点强相关的维度讲）**
"我更想跟大家分享的是我们自己的设计思路：我们围绕'一个学生一个平台全周期陪伴'这个核心理念，把迎新、在校、学业、实习、毕设、就业这条链路完整打通，角色化的工作台设计、PC+小程序的闭环、以及退回必须写明原因的审批规范，是我们在这次演示里想重点让大家感受到的。"

**第三步：邀请客户用自己的标准做判断，同时如实标注现状**
"至于哪个产品更适合贵校，还是要结合贵校的具体需求、现有系统情况、预算和实施节奏综合判断，我们也建议大家多比较、多提问。另外我也要如实说明，我们目前是可演示版本，后端真实数据接入还在按契约推进中，这一点我们不会回避，如果这个阶段不匹配贵校当前的采购节奏，我们完全理解，也欢迎大家保持关注，等我们进展到下一阶段随时再来沟通。"

## 特别提醒

- 严禁在任何场合（包括私下、非正式场合）说"某某产品的数据不安全""某某产品做得很烂""某某产品要跑路了"这类无依据的负面评价，这类话一旦传出去，无论真假都会被认为是我方素质问题，直接影响成交和公司声誉。
- 如果客户主动爆料某竞品的负面信息（比如"某某公司听说要倒闭了"），礼貌回应"这个我们不了解，不方便评论"，不要顺着话题继续讨论或转发这类信息。
- 我们的差异化话术应该始终能立得住、经得起追问——因为我们讲的都是自己产品的真实设计，不是靠贬低别人撑起来的。
