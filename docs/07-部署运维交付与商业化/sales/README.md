# docs/sales 目录导航（销售演示与客户答疑文档）

- **文档性质**：销售 / 售前对客沟通材料（话术、脚本、Q&A），非产品需求文档，非技术设计文档。
- **适用对象**：销售、售前顾问、渠道伙伴；面向的最终读者是学校客户（校领导、学工/学生处、教务、就业办、辅导员/教师、信息中心）。
- **依据**：本目录所有事实均引用自共享事实底稿（模块清单、角色、权限、当前研发阶段），不额外编造功能或接口。如需查证技术细节，请引用以下冻结文档路径，不要口头承诺底稿之外的内容：
  - `docs/05-数据接口权限与安全/database/00-数据库设计冻结总册.md`（数据库设计，冻结）
  - `docs/05-数据接口权限与安全/api/00-API契约冻结总册.md`（API 契约，冻结）
  - `docs/05-数据接口权限与安全/security/00-等保三级安全基线总册.md`（安全基线，冻结，注意：是"基线设计"不是"已测评认证"）
  - `docs/07-部署运维交付与商业化/demo/`（演示前检查清单与演示数据说明，如已生成）
- **当前阶段声明（本目录全部文档统一遵守）**：当前为**可演示版本**——PC 管理端正在做 UI 母版对接、模块齐全、使用 mock 数据；小程序端（学生端+教师端）为纯 mock，可运行/可构建/可演示；后端尚未接入真实接口，技术栈已确定（PostgreSQL + Python FastAPI + SQLAlchemy + Alembic），接入按 API 契约冻结总册推进中。**本目录任何文档都不得表述为"已对接真实后端""已联调真实数据""已通过等保三级测评"。**

## 使用说明（给销售/售前）

1. **演示前必读**：先看本目录 `06-当前阶段如实说明话术.md`，确认自己能说什么、不能说什么；再看 `02-学校客户演示脚本.md` 走一遍流程；有条件的话对照 `docs/07-部署运维交付与商业化/demo/`（演示数据与检查清单，如已生成）预演一次，确认 mock 数据剧本能覆盖当天要讲的场景。
2. **按听众选话术**：如果客户方是多角色混合听众（比如校领导+信息中心一起来听），从 `03-不同角色演示话术.md` 里挑对应章节组合使用，不要通篇照读。
3. **被问到敏感问题时**：一律先看 `04-常见问题答复.md` 有没有现成口径，没有的话参照 `06-当前阶段如实说明话术.md` 的红线清单，不确定的问题回答"我们记录下来，会同产品/技术侧确认后书面回复"，不要临场编造。
4. **被拿去和其他产品比较时**：用 `05-竞品对比话术.md` 的对比维度和框架，只讲"我们做到了什么"，不评价、不贬低点名的具体产品。
5. **口径纪律**：本目录所有文档已经统一口径为"可演示版本，后端接入按契约推进中"，销售在客户面前的措辞必须与文档一致，不能自行加码承诺（例如不能说"已经在某某学校稳定运行""已经过等保测评"等底稿未覆盖的内容）。

## 一句话产品定位

高校学生全生命周期管理平台，是面向本科院校、高职院校、职业本科院校、应用型高校的学生工作数字化平台，让学生从入学到毕业就业的每一个阶段，都有一个平台、一套流程、一份档案全程陪伴。
