# 01 · 部署总览

> 先搞清楚「这套系统由几块组成、每块现在是什么状态、部署时各自要做什么」。

---

## 1. 系统由哪几块组成

```
高校学生全生命周期管理平台
│
├── PC 管理端前端  frontend/      → 学校老师/管理员在电脑浏览器上用
│                                   Vue3 + Vite，构建成静态网站，交给 Nginx 托管
│
├── 小程序端       miniapp/       → 学生端 + 教师端
│                                   uni-app + Vue3，可编译成 H5 网页，也可编译成微信小程序
│
├── 后端服务       backend/       → 【预留】将来提供真实接口（登录、数据读写）
│                                   计划用 Python FastAPI，现在还没有真实业务接口
│
└── 数据库         （未建库）     → 【预留】将来存真实数据
                                    只有设计冻结文档 docs/05-数据接口权限与安全/database/，还没有真实库
```

## 3. 一次「现在能做的部署」到底做了什么

新手可以把当前阶段的部署理解成「上线三个静态网站 / 一个小程序包」：

1. 在 `frontend/` 里 `npm run build` → 得到 `frontend/dist/` → 让 Nginx 指向它 → PC 管理端就能在浏览器打开。
2. 在 `miniapp/` 里 `npm run build:h5` → 得到 `miniapp/dist/build/h5/` → 让 Nginx 指向它 → 小程序 H5 版就能在手机/电脑浏览器打开。
3. 在 `miniapp/` 里 `npm run build:mp-weixin` → 得到 `miniapp/dist/build/mp-weixin/` → 用微信开发者工具打开这个目录 → 上传体验版。

**没有涉及**：装数据库、连数据库、跑后端、配登录。这些都是后端接入阶段的事。

---

## 4. 部署会用到哪些目录（只读参考，别乱动）

| 目录 | 作用 | 部署时 |
|---|---|---|
| `frontend/` | PC 前端源码 | 只在这里 `npm run build`，不改 `src/` |
| `frontend/dist/` | PC 前端构建产物 | 拷到服务器，交给 Nginx |
| `miniapp/` | 小程序源码 | 只在这里 build，不改源码 |
| `miniapp/dist/build/h5/` | 小程序 H5 产物 | 拷到服务器，交给 Nginx |
| `miniapp/dist/build/mp-weixin/` | 微信小程序产物 | 用微信开发者工具打开上传 |
| `deploy/nginx/` | Nginx 配置示例 | 复制去掉 `.example` 使用 |
| `deploy/env/` | 环境变量示例 | 复制去掉 `.example` 填写使用 |
| `docs/05-数据接口权限与安全/database/` | 数据库冻结文档 | 只读引用，不动 |

---

## 5. 部署顺序（现在阶段）

```
① 准备服务器环境（装 Node、Nginx）          → 见 02
② 构建并部署 PC 前端                          → 见 03
③ 构建并部署小程序 H5 / 生成微信小程序包      → 见 04
④ 配好 Nginx（含刷新 404、缓存、安全头）      → 见 07
⑤ （后端接入后再做）部署后端、连数据库        → 见 05、06
```

先把 ①②③④ 跑通，就完成了「当前可真实部署内容」。⑤ 是后续阶段，本文档只做说明和预留。
