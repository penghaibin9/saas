# 08 · 环境变量说明

> 环境变量 = 「不写死在代码里、按环境（开发/测试/生产）不同而变的配置」，比如接口地址、密钥。
> 示例文件都在项目根目录 `deploy/env/`，以 `.example` 结尾。真实使用时复制一份去掉 `.example` 再填。

---

## 1. 现阶段最重要的一句话

**当前前端（PC + 小程序）都用 mock 假数据，不接后端，所以现阶段几乎不需要配任何环境变量就能部署演示。**
下面这些变量大多是「后端接入后才用到」的，现在了解即可，别提前乱填、别提前改代码开关。

---

## 2. 示例文件一览

```
deploy/env/
├── pc-frontend.env.example    # PC 前端（现在基本用不到，后端接入后填接口地址）
├── miniapp.env.example        # 小程序（现在恒 mock，后端接入后填接口地址）
├── backend.env.example        # 后端（预留，后端开发时用）
└── database.env.example       # 数据库（预留，建库时用）
```

> **安全红线**：真实的 `.env` 文件（含密码、密钥）**绝对不要提交到 git**。项目 `.gitignore` 已经忽略 `.env`，只保留 `.example` 模板。

---

## 3. PC 前端环境变量（Vite）

PC 前端用 Vite，环境变量必须以 `VITE_` 开头才能被前端读到。文件名一般是 `frontend/.env.production`（生产）或 `frontend/.env`。

| 变量 | 含义 | 现在 | 后端接入后 |
|---|---|---|---|
| `VITE_API_BASE_URL` | 后端接口地址 | 留空/不配（用 mock） | 填 `https://admin.example.com/api/v1` 之类 |
| `VITE_APP_TITLE` | 站点标题（可选） | 可留默认 | 可自定义 |

> 当前正在做 UI 对接、用 mock，**不需要**配 `VITE_API_BASE_URL`。等后端好了、要切真实接口时再配，并由开发同学在代码里把数据来源从 mock 切到真实接口。**本阶段不要改前端源码里的数据开关。**

### 关于「部署到子路径」（一般用不到）

如果 PC 前端不是放在域名根 `/` 而是放在 `/admin/` 这种子路径下，需要在 `frontend/vite.config.js` 配 `base: '/admin/'` 再 build。**本项目默认部署在根路径 `/`，通常不需要动这个。** 属于改前端工程配置，需谨慎，非必要不改。

## 4. 小程序环境变量

小程序当前的关键开关在源码 `miniapp/src/config/env.js`：

```js
export const ENV = {
  useMock: true,   // 是否使用 mock 假数据（当前恒为 true）
}
```

| 变量 | 含义 | 现在 | 后端接入后 |
|---|---|---|---|
| `useMock` | 是否用假数据 | `true`（恒真） | 改为 `false` 并配接口地址 |
| 接口地址（后端接入后新增） | 真实后端地址 | 无 | 填后端网关地址 |

> **本阶段红线：不要改 `useMock`，不要改 `miniapp/` 源码。** 切真实后端是后续阶段、由开发同学统一处理。
> `deploy/env/miniapp.env.example` 里给出的是「将来切后端时」需要准备的变量清单，作为提醒，不代表现在要填。

---

## 5. 后端环境变量（预留，现在不用填）

见 `deploy/env/backend.env.example`。后端开发/部署时才会用到，典型包括：

| 变量 | 含义 |
|---|---|
| `APP_ENV` | 运行环境（dev/test/prod） |
| `APP_PORT` | 后端服务端口（示例 8000） |
| `DATABASE_URL` | 数据库连接串（指向 PostgreSQL） |
| `JWT_SECRET` | 登录令牌签名密钥（务必保密） |
| `REDIS_URL` | 缓存地址（预留） |
| `FILE_STORAGE_*` | 文件存储/对象存储配置（预留） |

> 现在后端还没做，这些**都不用填**。列在这里只是让你知道后端上线时要准备哪些。

---

## 6. 数据库环境变量（预留，现在不用填）

见 `deploy/env/database.env.example`。建库时才用到：

| 变量 | 含义 |
|---|---|
| `POSTGRES_HOST` | 数据库地址 |
| `POSTGRES_PORT` | 端口（默认 5432） |
| `POSTGRES_DB` | 库名 |
| `POSTGRES_USER` | 用户名 |
| `POSTGRES_PASSWORD` | 密码（务必保密） |

> 数据库现在只有设计冻结文档、**还没建库**，这些变量现在**一律不用填**。见 `06-数据库冻结文档引用说明.md`。

---

## 7. 使用示例文件的正确姿势

```bash
# 以后端为例（后续阶段才做）
cd deploy/env
cp backend.env.example backend.env      # 复制去掉 .example
vi backend.env                          # 按注释填真实值
# backend.env 已被 .gitignore 忽略，不会提交，安全
```

现阶段你**基本不需要**做上面这步——前端 mock 部署不依赖这些变量。
