# 生产环境变量清单

> systemd 正式部署以 `deploy/env/backend.systemd.env.example` 为模板，落到 `/etc/school-lifecycle/backend.env`（权限 600）。真实密码/密钥禁止进 Git、文档、截图和日志。
> 试点前同时运行 `scripts/check/preflight-school-trial.sh` 与 `scripts/deploy/install-systemd-release.sh --check`，必须 0 FAIL。

## 一、生产启动红线

| 变量 | 生产要求 | 说明 |
|---|---|---|
| `APP_ENV` | `production` | 关闭 docs/openapi 等生产行为 |
| `DEPLOYMENT_MODE` | `production` | 禁止把开发配置误当生产 |
| `DEBUG` | `false` | 必须关闭调试 |
| `MOCK_LOGIN_ENABLED` | `false` | 禁止免密演示登录 |
| `DB_ENABLED` | `true` | 必须真实数据库 |
| `DB_DRIVER` | `mysql` | 正式只允许 MySQL |
| `JWT_SECRET` | ≥32 位随机值 | 与其它密钥分离，禁止默认值 |
| `FIELD_ENCRYPTION_KEY` | `Fernet.generate_key()` 生成的独立 key | 必须解码为 32 raw bytes；不能用任意“32 位字符串”冒充；丢失后历史敏感字段无法解密 |
| `PUBLIC_BASE_URL` | `https://正式域名` | 只填 origin，禁止 `/api`/业务路径；统一发布会注入 miniapp H5，防止生产包回退 localhost |
| `CORS_ORIGINS` | `https://正式域名` | 禁止空值/`*` |
| `INTERNAL_OPS_TOKEN` | ≥24 位随机值 | 保护 `/health/ready`、`/internal/metrics` |

## 二、MySQL 与 Redis

`DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD` 按实际填写；密码只放环境文件。EnvironmentFile 由安全 loader 按数据解析，不允许在发布脚本中 `source`/`eval`。

systemd 模板启动 2 个 Uvicorn worker，因此：

```text
WEB_CONCURRENCY=2
MULTI_INSTANCE=true
SCHEDULER_MODE=external
REDIS_URL=redis://...
```

Redis 不再是“可选缓存”：多 worker 下它承载跨进程认证安全状态，缺失必须阻止试点。

## 三、文件安全扫描

正式环境高风险附件采用 fail-closed：

```text
CLAMAV_ENABLED=true
CLAMAV_HOST=127.0.0.1
CLAMAV_PORT=3310
CLAMAV_UNIX_SOCKET=
```

必须同时运行 `school-lifecycle-file-scan.service`。如果 ClamAV disabled/down，或扫描任务进入 DEAD，`/health/ready` 会 DEGRADED/503。

## 四、文件存储

单机受控试点可先：

```text
FILE_STORAGE_BACKEND=local
UPLOAD_DIR=/opt/school-lifecycle/shared/uploads
EXPORT_DIR=/opt/school-lifecycle/shared/exports
```

此时 `UPLOAD_DIR` 必须纳入备份与恢复演练。正式 SaaS 推荐 COS：

```text
FILE_STORAGE_BACKEND=cos
COS_REGION=...
COS_BUCKET=...
COS_SECRET_ID=...
COS_SECRET_KEY=...
```

COS 永久密钥仅后端持有，禁止进入前端构建变量。发布验收会对 COS 做小对象真实 write/delete 探针；仅“参数填了”不算连接成功。

## 五、短信与微信

短信尚未开通时保持 `SMS_ENABLED=false`；若开启，必须同时填写供应商密钥、签名、相应模板（尤其 `SMS_TEMPLATE_PASSWORD_RESET`）并做真实发送验收。

微信一键登录启用时配置 `WX_APPID/WX_SECRET`；不启用时账号密码登录链不受影响。微信小程序生产包必须在同一 HEAD 上以正式 HTTPS API origin 构建并走发布闸门；服务器 systemd release 管理的是 miniapp H5，不等价于微信审核/发行包。

## 六、安全与发布红线

1. `.env` / EnvironmentFile、证书私钥、数据库备份、云密钥一律禁止提交 Git。
2. 密钥泄露立即轮换，但敏感字段加密密钥轮换必须走可回滚的数据重加密流程，不能直接替换旧 key。
3. 单机发布顺序固定为：**先完成耗时构建 → 短暂静默 Web/后台写入者 → 静默点一致备份 → Alembic `upgrade head` → 切换 release → 启动 → 真实 TLS 验收**。禁止让旧版本在 migration 期间继续写库。
4. 数据库 current 必须等于仓库动态唯一 head；migration 不自动 downgrade，因此迁移本身必须遵守 expand/contract 向后兼容原则。
5. 不允许用 `metadata.create_all`、演示 seed、手工建缺失表替代正式迁移。
6. 管理 PC、miniapp H5、学生 PC 必须同 release 发布，禁止分别手工覆盖造成版本漂移；miniapp H5 构建产物不得包含 localhost/127.0.0.1 API origin。
7. 正式发布必须串行，`install-systemd-release.sh` 使用 `flock` 拒绝并发 release。
8. `verify-systemd-release.sh` 必须通过真实 443/TLS/server_name 路径验证三端、HSTS/CSP/X-Frame/nosniff、附件静态拒绝和公网 API 鉴权，不能只看 `nginx -t`。
