# 05 · 后端预留部署说明

> 状态：**预留（当前未接入）**。本文件只做说明，不需要你现在动手部署后端。
> 目的：让你知道「后端将来长什么样、部署时大概要做什么」，以及「现在为什么不做」。

---

## 1. 现在的真实状态

- 项目里有 `backend/` 目录，但**目前只有工程壳/配置雏形，没有真实业务接口**。
- 前端（PC 和小程序）现在都用 mock 假数据运行，**不依赖后端也能演示**。
- 所以现阶段部署**不涉及后端**，你只需要按 03、04 部署好前端即可。

> 一句话：后端还没做好，现在不部署它，也不需要它。

---

## 2. 后端将来的技术栈（已在冻结文档拍板）

来自 `docs/05-数据接口权限与安全/database/00-数据库设计冻结总册.md` 与 `docs/05-数据接口权限与安全/api/00-API契约冻结总册.md`：

- 语言/框架：**Python + FastAPI**
- 数据库：**PostgreSQL**
- ORM（对象关系映射）：**SQLAlchemy**
- 数据库迁移工具：**Alembic**
- 预留：Redis（缓存）、MinIO/对象存储（文件）
- 接口前缀：统一 `/api/v1`，再按端分（`/api/v1/admin/`、`/api/v1/student-mini/`、`/api/v1/teacher-mobile/` 等）

> 这些是「将来」的设计，不是现在要装的。**现在别装 PostgreSQL、别装 Python 服务、别建库。**

---

## 3. 后端接入后，部署大概会多出哪些步骤（了解即可）

等后端真正开发完成、要上线时，会新增大致如下步骤（届时由会后端的人补真实命令）：

1. 在服务器装 Python 运行环境（建议用虚拟环境 venv）。
2. 安装后端依赖（`pip install -r requirements.txt` 之类）。
3. 配置后端环境变量（数据库地址、密钥等，见 `deploy/env/backend.env.example`）。
4. 用进程管理工具常驻运行（如 `gunicorn`/`uvicorn` + `systemd` 或 `supervisor`）。
5. 在 Nginx 里把 `/api/` 反向代理到后端服务端口（示例已在 Nginx 配置里预留并注释掉，见 `07-Nginx部署说明.md`）。
6. 把前端的「接口地址」环境变量指向后端，并把小程序 `useMock` 切成 `false`。

---

## 4. Nginx 里给后端预留的位置（现在是注释状态）

`deploy/nginx/pc-frontend.conf.example` 和 `07` 文档里，已经预留了一段 API 反向代理配置，但**默认是注释掉的**，并标注「当前后端未接入」。等后端上线时，取消注释、把端口改成后端真实端口即可。

```nginx
# ===== API 反向代理（后端接入后再启用，当前后端未接入，保持注释）=====
# location /api/ {
#     proxy_pass http://127.0.0.1:8000;      # 后端服务地址（示例端口 8000）
#     proxy_set_header Host $host;
#     proxy_set_header X-Real-IP $remote_addr;
#     proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
#     proxy_set_header X-Forwarded-Proto $scheme;
# }
```

## 5. 给新手的边界提醒

- **现在不要**：装 PostgreSQL、装 Python 后端、建数据库表、改前端的 mock 开关。
- **现在只要**：把前端（PC + 小程序 H5 / 微信包）部署好，能演示即可。
- 后端接入是独立的后续阶段，到时会有专门的部署补充文档和真实命令。
