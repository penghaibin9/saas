# 03 · PC 前端部署

> 对象：`frontend/`（PC 管理端，Vue3 + Vite）。
> 结果：把 PC 管理端做成一个静态网站，用 Nginx 托管，老师/管理员能在浏览器打开。
> 现状：正在做 UI 对接，页面用 mock 假数据；**能真实部署成演示站点**。

---

## 1. 一句话流程

```
在 frontend/ 里 npm install → npm run build → 得到 frontend/dist/ → 把 dist 里的东西交给 Nginx → 配好「刷新 404」的兜底 → 完成
```

---

## 2. 第一步：安装依赖（首次或换机器才需要）

```bash
cd frontend
npm install
```

- 在哪个目录执行：**项目里的 `frontend/` 目录**（不是根目录，不是 miniapp）。
- 这一步会下载 `node_modules`，可能要等几分钟。
- 慢的话先设镜像：`npm config set registry https://registry.npmmirror.com`

---

## 3. 第二步：构建

```bash
cd frontend
npm run build
```

- 这条命令实际执行的是 `vite build`（见 `frontend/package.json` 的 scripts）。
- 成功后会生成 **`frontend/dist/`** 目录，里面是：
  ```
  frontend/dist/
  ├── index.html          # 入口页面
  └── assets/             # 打包后的 js / css / 图片
  ```

> `dist/` 就是「可以上线的静态网站」。它是机器生成的，别手动改里面的文件。

（可选）本地先预览一下构建结果对不对：

```bash
npm run preview
```

它会起一个本地预览地址，浏览器打开看看页面正常不正常。

---

## 4. 第三步：把 dist 放到服务器网站目录

把 `frontend/dist/` **里面的内容**（不是 dist 这个文件夹本身）放到网站根目录，比如 `/var/www/pc-frontend/`。

方式 A：在服务器上 build，然后拷贝：

```bash
# 假设源码在 /opt/school-platform/frontend
cd /opt/school-platform/frontend
npm install
npm run build
sudo rm -rf /var/www/pc-frontend/*          # 清空旧内容（首次可跳过）
sudo cp -r dist/* /var/www/pc-frontend/      # 拷新内容
```

方式 B：在自己电脑上 build，再上传 `dist/` 里的文件到 `/var/www/pc-frontend/`（用 FinalShell / scp 拖上去）。

放好后 `/var/www/pc-frontend/` 里应该直接能看到 `index.html` 和 `assets/`。

---

## 5. 第四步：配 Nginx 指向它（含刷新 404 处理）

新建站点配置 `/etc/nginx/conf.d/pc-frontend.conf`（完整示例见 `deploy/nginx/pc-frontend.conf.example` 和 `docs/07-部署运维交付与商业化/deploy/07-Nginx部署说明.md`）。最小可用版本：

```nginx
server {
    listen       80;
    server_name  你的域名或IP;          # 例如 admin.example.com

    root   /var/www/pc-frontend;         # 指向刚才放 dist 内容的目录
    index  index.html;

    # 关键：前端是「前端路由」，刷新子页面要兜底回 index.html，否则 404
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

改完后：

```bash
sudo nginx -t                  # 先测配置
sudo systemctl reload nginx    # 没报错再重载
```

浏览器访问你的域名/IP，能看到 PC 管理端登录/首页就成功了。

---

## 6. 为什么会「刷新就 404」，怎么解决

**原因**：本项目 PC 前端用的是 `history` 路由模式（源码 `frontend/src/router/index.js` 里是 `createWebHistory()`）。
这种模式下，地址栏会出现像 `/student/list` 这样的路径。你在首页点进去没问题（前端自己切换），但**直接刷新或直接访问这个地址**时，浏览器会把 `/student/list` 当成一个真实文件去服务器找 —— 服务器上没有这个文件，就返回 404。

**解决**：Nginx 里加一行兜底，把「找不到的路径」都交回 `index.html`，让前端路由自己处理：

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

这就是上面配置里那一行的作用。**只要这行在，刷新 404 就解决了。**

> 记忆点：Vue/React 单页应用 + history 路由 = Nginx 必须加 `try_files ... /index.html`。

## 7. 更新版本（以后每次改了前端）

```bash
cd frontend
git pull                       # 如果用 git 管理（可选）
npm install                    # 依赖有变动才需要
npm run build                  # 重新构建
sudo cp -r dist/* /var/www/pc-frontend/    # 覆盖旧内容
sudo systemctl reload nginx    # 一般不用，静态文件换了直接生效
```

> 更稳妥的「带版本目录 + 软链 + 一键回滚」的做法见 `09-发布与回滚流程.md`。

## 8. 常见问题

| 现象 | 可能原因 | 怎么办 |
|---|---|---|
| 页面白屏 | dist 没放对 / 路径不对 | 确认 `/var/www/pc-frontend/index.html` 存在；看浏览器 F12 控制台报错 |
| 刷新子页面 404 | 少了 `try_files ... /index.html` | 按第 6 节加上 |
| 静态资源 404（js/css 加载不到） | 网站放在了子路径但没配 base | 见 `08-环境变量说明.md`「部署到子路径」一节；本项目默认部署在根路径 `/` |
| 改了代码没生效 | 没重新 build / 浏览器缓存 | 重新 `npm run build` 拷贝；强刷 Ctrl+F5 |

> 数据相关的问题（比如「新增的数据刷新就没了」）不是 bug：当前是 mock 假数据，本来就不落库。等后端接入后才会真正保存。
