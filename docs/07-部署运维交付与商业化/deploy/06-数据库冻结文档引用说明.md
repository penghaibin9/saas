---

## 2. 这份文档里已经拍板冻结了什么（摘要）

从文档开头可确认，以下已定稿冻结：

- **数据库**：PostgreSQL
- **后端**：Python FastAPI + SQLAlchemy + Alembic
- **多租户策略**：单库 / 单 schema + `tenant_id` 行级隔离（一期不做每校独立库、不做独立 schema）
- **规模**：覆盖约 20 大模块、冻结约 150 张表
- **命名规范**：表统一 `t_` 前缀、蛇形小写；主键 `id BIGINT`（应用层发号器，不用自增）；金额 `DECIMAL(12,2)`；时间用时间戳；布尔用 `BOOLEAN`；不固定结构用 `JSONB`
- **公共字段**：每张业务表都有 `tenant_id / created_at / updated_at / created_by / updated_by / is_deleted / version`

> 本阶段边界（文档自己写明）：**只创建设计文档，未连接数据库、未写迁移脚本、未写后端、未改前端。**

---

## 3. 本阶段为什么「只引用不动它」

1. 数据库设计是全系统的地基，改一处可能牵动一大片接口和页面。
2. 它已经被「冻结」，意味着已经过评审、作为唯一基线，不能随意改。
3. 现在是前端 UI 对接 + 文档补齐阶段，**根本还没到建库这一步**，没有任何理由动它。

**新手红线：不要在这份文档里加表、改字段、改类型；不要另建一份"新的数据库设计"。** 有疑问先记录，交给负责数据库的人。

---

## 4. 部署时和数据库的关系

- **当前部署**：前端用 mock 假数据，**完全不碰数据库**，所以现在不需要装 PostgreSQL、不需要建库、不需要连库。
- **后端接入阶段**（后续）：才会按这份冻结文档，用 Alembic 生成迁移、真正建库，再由后端连库。到时数据库连接信息放在 `deploy/env/database.env.example` 对应的真实环境变量里。
