# 交付文档（docs/07-部署运维交付与商业化/delivery/）

> 面向对象：拿这套系统去学校**演示、交付、验收**的人。
> 核心纪律：**如实说明当前阶段**——现在是「前端 + 演示数据（mock），后端未接入」。不夸大、不假装已接后端。
> 生成日期：2026-07-04

---

## 一句话现状（对客户口径的基准）

当前是**功能演示版本**：界面完成度高、业务流程可完整走通，但使用的是**演示数据**（mock），**尚未接入真实后端与数据库**。真实的数据存储、登录鉴权、权限、文件上传、消息推送等，将在**后端接入阶段**完成。

> 请所有对客户沟通都以这个口径为准。演示时可以说"这就是最终产品的界面和流程"，但不能说"已经接好了后端、数据已经在真实保存"。

## 三种能力，必须分清并对客户讲清

贯穿所有交付文档的一个关键区分：

1. **当前可演示能力**：界面 + 交互 + 完整流程可以现场走通（用演示数据）。
2. **当前 mock 能力**：能填、能提交、能看到状态变化，但**数据不长期保存**（刷新/换设备会回到初始演示数据）。
3. **后续接真实后端后能力**：真实登录、真实保存、真实权限、真实统计、文件上传、消息推送等。

> 验收清单（03）里，每个模块都会标出它现在属于哪一档，避免验收时理解不一致。
