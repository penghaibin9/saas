# 第一所学校试点交付清单

> 一页看清"要把系统交给一所学校试点，需要准备和确认哪些事"。面向学校信息中心/学工处对接人。

## 一、试点前（我方 + 学校共同准备）
- [ ] 学校确定试点范围（建议先 1 个学院、2–3 个班）。
- [ ] 学校提供开局数据：院系、专业、班级、学生名单、教师名单（用《XX导入模板说明》）。
- [ ] 学校确定管理员 1–2 人、辅导员若干、就业/教务老师若干。
- [ ] 我方准备演示环境 + 演示账号（见《售前演示脚本》）。
- [ ] 双方签署试点协议 + 数据处理说明（明确数据归属与保密）。

## 二、开局初始化（我方操作，学校确认）
- [ ] 建租户（学校）+ 品牌（校名/校色/校徽）。
- [ ] 导入院系 → 专业 → 班级（先 validate 看行号错误，再 confirm）。
- [ ] 导入学生名单。
- [ ] 创建教师账号 + 分配角色 + 绑定数据范围（谁管哪个班）。
- [ ] 生成初始化报告（成功/跳过/失败数量），交学校核对。

## 三、功能走查（学校老师参与，按《验收清单》）
- [ ] 学生端小程序：登录、查档案、提交一次服务申请、交一次实习周报。
- [ ] 教师端小程序：登录、看待办、批一次审批、批一次周报、看风险学生。
- [ ] 管理端：管理员登录、查看学生主档、看数据看板。
- [ ] 通知：确认待办/退回/预警的短信通道方案（试点期可先站内，短信需配密钥）。

## 四、试点期运行（1 个学期或约定周期）
- [ ] 明确支持人 + 联系方式 + 响应时效（见《SLA服务说明》）。
- [ ] 每两周收集一次问题（用《试点问题反馈表》）。
- [ ] 每月做一次数据备份恢复演练（我方，见运维手册）。

## 五、必须向学校讲清的"暂不承诺"
- 短信为**占位/需配密钥**，未配则只在系统内提醒，不发真实短信。
- 未过**等保测评/渗透**前，不作"正式商用无风险"承诺。
- 未做**恢复演练**前，不作"备份绝对可靠"承诺。
- 与学校已有教务/一卡通系统的**深度对接**不在试点范围（本期靠批量导入）。

## 六、交付物清单（随本次一并给学校）
- 本清单 + 各操作手册（管理员/辅导员/教师端/学生端）
- 导入模板说明（院系/专业/班级/学生/教师）
- 验收清单 + 部署信息采集表 + 问题反馈表 + SLA 说明
