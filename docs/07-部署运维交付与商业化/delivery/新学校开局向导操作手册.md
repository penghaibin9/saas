# 新学校开局向导操作手册

> 面向：负责给一所新学校做初始化的人（我方实施或学校管理员）。目标：把空系统变成"可试点"。

## 总体顺序（务必按此顺序）
**建租户 → 品牌 → 院系 → 专业 → 班级 → 学生 → 教师账号/角色/范围**
后面的依赖前面的（专业要挂院系、班级要挂专业、学生挂班级），顺序不能乱。

## 第 1 步：建租户（新学校）
- 平台运营账号调用 `POST /api/v1/onboarding/tenant`，填学校编码 `tenantCode`、学校全称 `tenantName`。
- 系统自动建好租户 + 默认品牌（校名水印、主色），返回学校的租户 ID。
- 记下这个**租户 ID**，后面导入都要用它。

## 第 2 步：准备导入数据
- 用《院系/专业/班级/学生/教师账号 导入模板说明》整理好数据（Excel 转 CSV/JSON）。
- 每个模板都有"字段说明 + 示例 + 常见错误"。

## 第 3 步：先校验（dry-run，不落库）
- 调 `POST /api/v1/onboarding/validate`，请求体带 `tenantId` + 各类数据。
- 系统返回：将新建/跳过/失败的数量 + **错误行号**。
- 有错就按行号改数据，反复 validate 到干净为止。**这一步不会写库，放心试。**

## 第 4 步：正式导入（confirm，落库）
- 确认无误后调 `POST /api/v1/onboarding/confirm`。
- 系统在**一个事务**里写入：院系→专业→班级→学生→教师。
- 若开了 `atomic`（默认开）且有硬错误，会**整批回滚**（一行都不写），返回错误清单——改完再来。
- 成功后返回**初始化报告**：各类"成功/跳过/失败"数量，交学校核对。

## 第 5 步：交接教师初始密码
- 教师导入成功后，响应里的 `teacherCredentials` 有每个教师的**一次性初始密码**。
- **只显示这一次，不进任何日志。** 请立即安全转交本人，并要求首次登录改密。

## 常见问题
- **重复导入怎么办？** 已存在的院系/学生/教师会自动**跳过**（不会重复建），报告里计入 skipped。
- **导错了想重来？** 先用 validate 看清；已落库的可在管理端逐条处理（本手册不含批量删除，避免误删）。
- **跨学校会串吗？** 不会。非平台运营账号只能导入本校；系统禁止跨租户写入。
- **手机号/身份证为什么不在开局表里？** 避免明文外泄；敏感信息后续单独脱敏补录。
