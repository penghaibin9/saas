# 备份恢复演练手册

> 核心原则：**未做过恢复演练的备份，不能宣称生产备份可靠。**
>
> 权威实现与首次部署清单见 `deploy/README-data-governance.md`。本手册只解释“怎么验收”，不再维护第二套 cron/恢复命令。

## 一、现在的正式备份是什么

一个有效恢复点必须是同一个 manifest 绑定的完整备份集：

- MySQL 压缩备份；
- uploads 压缩备份；
- 每个对象的 SHA-256；
- 最后提交的 JSON manifest。

只有 manifest 已提交、数据库与附件都通过校验的备份集才算成功。单独存在的 `.sql.gz` 不再视为正式生产恢复点。

正式 Linux 生产入口：

- `school-lifecycle-backup.timer`：每天 01:15 / 07:15 / 13:15 / 19:15 自动运行；
- `school-lifecycle-backup.service`：生成完整备份集并完成异地回读校验；
- `school-lifecycle-backup-watchdog.timer`：每小时检查恢复点是否过期、缺文件或缺异地 commit marker；
- `deploy/backup/restore-drill.sh`：只允许恢复到本机隔离演练库，不允许直接指向生产库。

生产基线：**RPO ≤ 6 小时，RTO ≤ 2 小时。**

## 二、首次上线只做一次人工验收

按 `deploy/README-data-governance.md` 配好真实 `backup.env`、rclone 和对象存储保护后：

1. 手动触发一次 `school-lifecycle-backup.service`；
2. 确认本地存在最新 manifest 及对应数据库、uploads、SHA-256；
3. 确认异地目标存在同一完整备份集，且 service 日志显示远端回读 SHA-256 成功；
4. 手动运行一次 backup watchdog，必须 PASS；
5. 从异地完整备份集取回到隔离恢复目录；
6. 用 `restore-drill.sh` 恢复到本地临时库；
7. 验证恢复证据中的 Alembic、表、索引、外键、租户、uploads、RPO/RTO；
8. 验证恢复后的后端 `/health/ready` 与测试账号登录；
9. 保存恢复证据和 SHA-256，删除隔离演练库。

这一步通过后，日常备份和 watchdog 都由 systemd 自动完成，不要求人工每天敲命令。

## 三、自动恢复演练

`.github/workflows/backup-restore-drill.yml` 会定时/手动执行完整恢复证明：

1. 通过真实 Alembic 链建立 MySQL 源库；
2. 生成 DB + uploads 的完整备份集；
3. 模拟异地复制并从异地对象重新取回；
4. 恢复到隔离 MySQL；
5. 启动恢复后的后端；
6. 检查 readiness 与租户账号；
7. 留存恢复证据。

CI 演练证明的是**代码与恢复链路可执行**；它不能替代真实生产 COS/rclone/版本化/WORM 的第一次人工配置验收。

## 四、恢复安全红线

- 恢复演练只允许本机、非 production 环境、特定 `_drill/_restore_test/_e2e` 库名；
- manifest 和所有 payload 必须先通过 SHA-256；
- uploads 压缩包存在绝对路径、`..` 路径穿越、符号链接、硬链接或设备文件时拒绝解包；
- 不允许拿一个时间点的数据库和另一个时间点的附件拼接恢复；
- 不允许因为“有 SQL 文件”就宣称备份成功；必须以 manifest-committed 完整恢复点为准；
- 真正生产事故恢复前，先在隔离环境验证该恢复点，再制定切换方案。

## 五、不可丢失的恢复材料

数据库内存在使用生产字段加密密钥保护的敏感字段。因此服务器完全损坏时，除了 DB/uploads 备份，还必须能找回原生产密钥历史。

在应用服务器和 Git 之外保留一份受保护恢复副本，至少包含当前 `FIELD_ENCRYPTION_KEY`、历史 `FIELD_ENCRYPTION_PREVIOUS_KEYS`（如启用轮换）以及固定 `SENSITIVE_SEARCH_HMAC_KEY`（如使用）。密码管理器或加密的密钥保险库即可，不需要另建复杂密钥平台。

## 六、故障时先看什么

- backup service 失败：先看 systemd journal / 已配置的失败 webhook；
- watchdog 失败：先确认最近 manifest 是否超过 6 小时，再检查本地 sidecar 与异地 manifest；
- 异地不可用：不要把本地成功当成正式备份成功，生产 runner 会 fail-closed；
- 恢复失败：不要修改生产库尝试“硬恢复”，先在隔离库定位是 manifest、payload、Alembic 还是密钥材料问题。
