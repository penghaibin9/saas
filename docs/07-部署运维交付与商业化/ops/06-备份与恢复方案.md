## 2. 前端版本备份 = 就是发版留目录

按 `docs/07-部署运维交付与商业化/deploy/09-发布与回滚流程.md` 的「版本目录 + 软链」做，每次发版自动就有备份：

```
/var/www/pc-frontend/releases/20260704-1000/
/var/www/pc-frontend/releases/20260704-1500/
current -> releases/20260704-1500
```

**恢复（回滚）**：把软链指回旧目录即可（见 `docs/07-部署运维交付与商业化/deploy/09` 第 3 节）。这就是前端的"备份与恢复"。

保留策略：至少留最近 3~5 个版本。

## 3. Nginx 配置与环境变量备份

```bash
# 改 Nginx 前先备份当前配置
sudo cp /etc/nginx/conf.d/pc-frontend.conf /etc/nginx/conf.d/pc-frontend.conf.bak.$(date +%Y%m%d)

# 定期把整个 conf.d 打包留存
sudo tar czf ~/nginx-conf-$(date +%Y%m%d).tar.gz /etc/nginx/conf.d/
```

真实 `.env`（含密码）**单独加密保存**（如公司密码库），不要放进 git、不要随便发。

## 4. 数据库备份与恢复（预留方案，现在不执行）

> ⚠️ 当前**没有数据库**（只有设计冻结文档 `docs/05-数据接口权限与安全/database/00-数据库设计冻结总册.md`）。以下是**方案说明**，等后端/数据库（PostgreSQL）接入后，由懂数据库的人补上真实命令并落实。

### 备份方案（思路）

- 数据库是 **PostgreSQL**（冻结文档已拍板）。
- 逻辑备份用 `pg_dump`（导出为可恢复的 SQL/自定义格式文件）。
- 建议策略：**每天全量备份 + 保留最近 N 天 + 异地/对象存储各存一份**。
- 备份文件也要纳入前面「哪些日志/文件必须保留」的长期保留范围。

示例（**占位，接入后再核对参数，勿在无库时执行**）：

```bash
# 备份（后端/数据库接入后使用，需替换真实库名/账号，并用 .pgpass 或环境变量管密码）
# pg_dump -h <host> -U <user> -d <dbname> -F c -f /backup/db_$(date +%Y%m%d).dump

# 定时：可用 crontab 每天凌晨执行上面的命令并清理过期备份
```

### 恢复方案（思路）

- 用 `pg_restore`（对应 `-F c` 自定义格式）或 `psql`（对应纯 SQL）恢复。
- 恢复前务必确认：恢复到哪个库、会不会覆盖现有数据、是否需要先建空库。
- **恢复是高危操作**，生产环境恢复必须由懂数据库的人执行，最好先在测试库演练。

示例（**占位，接入后再核对**）：

```bash
# pg_restore -h <host> -U <user> -d <dbname> --clean /backup/db_20260704.dump
```
