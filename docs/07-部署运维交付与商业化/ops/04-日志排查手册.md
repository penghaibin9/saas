# 04 · 日志排查手册

> 出问题时，日志是第一手线索。这份手册告诉新手「看哪里的日志、怎么看、看到什么代表什么」。

---

## 1. 有哪些日志、在哪里

| 日志 | 位置 | 看什么 |
|---|---|---|
| Nginx 访问日志 | `/var/log/nginx/access.log` | 谁访问了什么、返回了什么状态码 |
| Nginx 错误日志 | `/var/log/nginx/error.log` | Nginx 自己的报错（配置、找不到文件等） |
| 浏览器控制台 | F12 → Console | 前端 JS 报错、白屏原因 |
| 浏览器网络面板 | F12 → Network | 每个请求的状态码（200/404/500） |
| 前端构建日志 | 执行 `npm run build` 的终端输出 | 构建失败原因 |
| 小程序构建日志 | `miniapp/build-h5.log`、`miniapp/build-mp.log`、`miniapp/dev.log` | 小程序构建/运行报错 |
| 后端日志（预留） | 后端服务输出 / systemd journal | 接口 500 等（后端接入后才有） |

---

## 2. 看日志的常用命令

```bash
sudo tail -f  /var/log/nginx/error.log      # 实时滚动看错误日志（Ctrl+C 退出）
sudo tail -n 100 /var/log/nginx/error.log   # 看最近 100 行
sudo tail -n 100 /var/log/nginx/access.log  # 看最近 100 条访问

# 只看包含 404 的访问记录
sudo grep " 404 " /var/log/nginx/access.log | tail -n 50

# 只看包含 500 的访问记录
sudo grep " 500 " /var/log/nginx/access.log | tail -n 50
```

**access.log 怎么读**：每行末尾附近有个状态码。
- `200` 正常，`304` 用了缓存也正常。
- `404` 没找到（文件/路径不存在）。
- `500/502/503/504` 服务端错误（现阶段前端静态站点基本不会有；出现多半是 Nginx 配置或将来后端问题）。

---

## 3. 按状态码定位

| 状态码 | 含义 | 现阶段最可能的原因 |
|---|---|---|
| 200/304 | 正常 | — |
| 404 | 资源/路径不存在 | 刷新子页面没配兜底；或静态资源路径不对 |
| 403 | 没权限 | 网站目录权限不对（Nginx 读不到文件） |
| 500 | 服务器内部错误 | 现阶段少见；后端接入后是后端报错 |
| 502/504 | 网关错误/超时 | 现阶段少见；后端接入后是后端没起/超时 |

---

## 4. 前端问题主要看浏览器（不是服务器日志）

前端是静态站点，**页面白屏、按钮没反应、样式乱**这类问题，服务器日志往往看不出来，要看**浏览器 F12**：

- **Console（控制台）**：有没有红色 JS 报错？报错提到哪个文件？
- **Network（网络）**：刷新页面，哪个请求是红色的？状态码多少？
  - 某个 `.js`/`.css` 是 404 → 静态资源没部署对。
  - 页面文档本身 404 → 路由兜底没配。

> 详细的「白屏 / 404 / 500」按症状处理见 `05-故障应急处理.md`。

---

## 5. 小程序构建/运行日志

小程序目录下有现成的日志文件：

```bash
cd miniapp
tail -n 100 build-h5.log     # H5 构建日志
tail -n 100 build-mp.log     # 微信小程序构建日志
tail -n 100 dev.log          # 开发运行日志
```

构建失败时，**看这些文件的最后几十行**，一般会直接写明是哪个文件、什么错。

---

## 6. 哪些日志以后必须保留（重要）

为了将来查问题、审计、追溯，以下日志建议**长期保留并定期归档**：

1. **Nginx access.log / error.log**：保留至少 30~90 天（可配 logrotate 自动切割归档）。
2. **每次发版记录**（时间、版本号、操作人、结果）：长期保留。
3. **故障处理记录**（现象、原因、处理、回滚与否）：长期保留。
4. **小程序上传版本记录**（版本号、备注、上传时间）：长期保留。
5. **（后端接入后）后端应用日志、数据库慢查询日志、备份日志**：按等保/合规要求保留（本项目有 `docs/05-数据接口权限与安全/security/00-等保三级安全基线总册.md`，届时按其要求执行）。

### Nginx 日志自动切割（避免越来越大）

Ubuntu 一般自带 logrotate，配置在 `/etc/logrotate.d/nginx`。可确认它存在即可，默认按天切割、保留若干天。需要保留更久就调大 `rotate` 天数。

## 7. 排查口诀

1. **先复现**：自己打开页面，看是不是真有问题、哪一步出问题。
2. **分前后端**：页面/样式/白屏 → 看浏览器 F12；请求 500/502 → 看服务器/后端日志（现阶段基本是 Nginx）。
3. **看最近改了什么**：问题往往出在「刚发的版本 / 刚改的配置」，先怀疑它，必要时回滚。
4. **记录**：把现象、日志关键行、处理过程记下来。
