# 03 · 发布后检查清单

> 每次发版**之后**立刻走一遍。目的是「确认新版本真的好用，坏了能马上回滚」。

---

## A. 站点可用性（发完马上做）

- [ ] 打开 PC 管理端线上地址，**能看到登录/首页**（不是白屏、不是 Nginx 报错页）。
- [ ] 打开小程序 H5 线上地址，**能进学生端/教师端**。
- [ ] 在业务页面**刷新（F5）不 404**。
- [ ] 随机点 2~3 个页面（学生列表、某审批页、某表单），**都能正常渲染**。
- [ ] 手机上也打开一次 H5，确认移动端正常。

---

## B. 资源与缓存

- [ ] F12 → Network，刷新页面，**没有一堆红色 404**（js/css/图片都能加载）。
- [ ] 如果页面还是旧的：强刷 Ctrl+F5；确认 `index.html` 是不缓存的（见 `docs/07-部署运维交付与商业化/deploy/07` 第 2 节 ④）。

---

## C. 日志

- [ ] `sudo tail -n 50 /var/log/nginx/error.log`，发布后**没有新的异常报错**。

---

## D. 微信小程序（如本次发了小程序）

- [ ] 微信开发者工具里能打开、能操作。
- [ ] 已上传，并在小程序后台设为「体验版」，扫码能进。
- [ ] 版本号、备注填清楚了。

---

## E. 出问题就回滚

如果上面任何一条不通过、且短时间修不好：

- [ ] 按 `docs/07-部署运维交付与商业化/deploy/09-发布与回滚流程.md` **回滚到上一版**（改软链 / 后台切版本）。
- [ ] 回滚后再验证一遍站点正常。
- [ ] 记录本次问题现象，事后排查（见 `04-日志排查手册.md`）。

---

## F. 收尾

- [ ] 在运维日志记一行：**发版时间、版本号、结果（正常/回滚）**。
- [ ] 通知相关人「更新完成，可正常使用」。

> 当前 mock 阶段无需检查数据一致性。后端接入后，这里要加：关键接口是否 200、关键业务能否读写、数据库是否正常等。
