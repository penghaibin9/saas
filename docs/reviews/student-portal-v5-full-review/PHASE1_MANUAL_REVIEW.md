# Student Portal V5 第一阶段完整复审报告

## 一、总体结论

**结论：V5 的首页、公共骨架和“业务页收窄一级导航”的方向可以保留，但当前实现需要较大返工，不能认定为全门户已经按 V5 原型还原完成。**

理由：

1. 首页和公共 PortalLayout 已经形成可用的新骨架，主要路由均可真实进入，刷新与登录态基本正常；
2. PR #29 实际只逐块重写了首页和公共壳层，绝大多数三级业务页仍是旧模板套公共 CSS；
3. 教务采用动态独立路由后，V3/V5 的二级上下文侧栏没有落到 19 个独立页面，旧兼容页仍保留拥挤横向 tab；
4. 存在 1 个真实三级路由直接不可用、2 个关键交互失败、1 个学工接口 403、多个原始枚举直接显示；
5. 六套主题都能切换并持久化，但六套均存在对比度问题，橙色和粉色主按钮尤其明显，深色主题仍有白色输入框残留。

本阶段没有修改 `main`，没有修改生产后端、数据库、API、权限、路由语义、真实 tab key 或业务状态机。Draft PR #30 保持 Draft。

## P1：核心页面或主要交互明显不符合要求

### P1-01 `/academic/makeup` 真实三级路由不可用

- 页面：补考重修
- 路由：`/academic/makeup`
- 复现：学生登录 → 直接打开 `/academic/makeup`
- 实际：显示“当前教务服务入口配置异常；未找到‘补考重修申请’子工作区”
- 期望：打开考试模块中的真实“补考重修申请”工作区
- 证据：`screenshots/1920x1080--academic-makeup-补考重修.jpg`
- 初步原因：`AcademicSectionRouteView.vue` 点击主 tab 后只等待一次 `nextTick()`，随后按文本查找子 tab；子 tab 尚未稳定挂载时即判定失败
- 预计文件：
  - `student-portal/src/views/academic/AcademicSectionRouteView.vue`
  - 必要时 `student-portal/src/router/academicRoutes.js`
- 业务逻辑影响：低；只修前端路由激活和等待方式，不改 tab key、接口和状态机

### P1-02 顶栏搜索跳转后不执行真实筛选

- 页面：公共顶栏 → 办事大厅
- 路由：任意登录页 → `/service-hall?kw=请假`
- 复现：顶栏输入“请假”并回车
- 实际：URL 有 `kw=请假`，办事大厅搜索框为空，目录未过滤
- 期望：办事大厅读取 query，并立即以“请假”筛选
- 证据：`screenshots/functional-header-search.jpg`
- 初步原因：`ServiceHallView.vue` 的 `kw` 固定初始化为 `ref('')`，未读取或监听 `route.query.kw`
- 预计文件：`student-portal/src/views/hall/ServiceHallView.vue`
- 业务逻辑影响：低；只同步前端路由 query 和现有本地筛选变量

### P1-03 教务独立页面没有 V3/V5 上下文导航

- 页面：19 个教务独立三级页
- 路由：`/academic/schedule` 至 `/academic/graduation`
- 复现：从教务工作台进入“我的成绩”等独立页面
- 实际：只剩 76px 一级图标栏；页面内没有完整教务二级导航。自动交互也找不到“返回教务工作台”按钮（部分专用页面未经过 `AcademicSectionRouteView`）
- 期望：按 V3 基准保留紧凑的教务上下文导航，学生可在教务各三级页之间稳定切换
- 证据：
  - `screenshots/1920x1080--academic-grades-我的成绩.jpg`
  - `screenshots/functional-academic-back.jpg`
- 初步原因：动态教务路由中的课表、成绩、注册、选课、评教、复查使用独立组件；PR #29 的上下文 CSS 只识别顶层 `.sp-tabs`，无法覆盖这些页面
- 预计文件：
  - 新增或复用学生门户前端教务上下文组件
  - `student-portal/src/layouts/PortalLayout.vue` 或教务 shell
  - `student-portal/src/router/academicRoutes.js` 的前端 meta（不改 route path/name/tab key）
- 业务逻辑影响：低至中；仅导航壳层，但必须复验全部教务路由

### P1-04 `/academic/all` 仍为拥挤的横向 tab

- 页面：综合教务兼容页
- 路由：`/academic/all`
- 实际：1920×1080 已出现两行横向 tab；未使用 V3 208px 上下文侧栏
- 期望：作为低频安全入口，也应遵循紧凑分组导航，不占据内容首屏
- 证据：`screenshots/1920x1080--academic-all-教务全部旧功能安全入口.jpg`
- 初步原因：外层 `AcademicLegacySafeView` 包裹内层 `AcademicView`，CSS 选择器只匹配 `.sp-content > .sp-page:has(> .sp-tabs)`，未命中嵌套页面
- 预计文件：教务上下文壳层或 V5 CSS 的明确页面级规则
- 业务逻辑影响：低；不改真实 tab key

### P1-05 学工宿舍调宿接口返回 403

- 页面：我的宿舍
- 路由：`/campus-service` → “我的宿舍”
- 实际：`GET /api/v1/mobile/affairs/dorm/transfers/my` 返回 403，页面顶部显示“当前业务暂不可用”
- 期望：学生可查看本人调宿记录；若接口暂不可用，至少不应让已成功加载的床位信息整体判定不可用
- 证据：`screenshots/1920x1080--campus-service-tab-我的宿舍.jpg`
- 初步原因：学生 PC 调用了移动学工调宿接口，但当前真实权限合同拒绝学生身份
- 预计文件：需要先确认仓库已有正确学生本人端点；本轮禁止修改后端和权限，不能靠前端绕过
- 业务逻辑影响：高；涉及真实权限和调宿流程
- 当前处理原则：前端可改善分项错误展示，但不能伪造调宿记录，也不能擅自改权限/API

### P1-06 多处直接暴露内部枚举和代码值

- 页面与证据：
  - 首页成长航线：`UNEMPLOYED`；`screenshots/1920x1080--home-首页工作台.jpg`
  - 我的档案：`CLASS_REVIEW`、`PERSONAL`；`screenshots/1920x1080--profile-我的档案.jpg`
  - 消息正文：`PENDING_REVIEW`；`screenshots/1920x1080--messages-消息通知.jpg`
  - 毕业设计：`PROPOSAL`、`当前版本 v1`；`screenshots/1920x1080--graduation-毕业设计.jpg`
- 实际：学生看到后端枚举、内部节点或技术版本值
- 期望：使用现有 label，或在前端做明确中文展示映射；未知值使用“状态待确认”，不能生硬暴露代码
- 预计文件：对应页面的前端展示函数或公共状态映射
- 业务逻辑影响：低；只改展示，不改真实状态值

### P1-07 六套主题均未达到可靠可读标准

- 实际结果：6/6 主题均产生对比度候选问题
- 重点：
  - 活力橙：白字按钮对橙色主色约 `2.19:1`
  - 樱花粉：白字按钮对粉色主色约 `2.8:1`
  - 薄荷绿：主色文字对白底约 `3.32:1`
  - 科技紫：部分正文、表头和主按钮边缘不足
  - 深邃黑：办事大厅页内搜索输入框仍为纯白，破坏暗色一致性
- 证据：
  - `screenshots/theme-purple--academic-grades.jpg`
  - `screenshots/theme-green--internship.jpg`
  - `screenshots/theme-orange--campus-service.jpg`
  - `screenshots/theme-pink--graduation.jpg`
  - `screenshots/theme-dark--service-hall.jpg`
- 初步原因：同一个 `--pri` 同时承担品牌色、文字色、边框和按钮底色；浅色主题没有独立的深色文字 token 和按钮前景 token；深色覆盖只覆盖部分通用 class
- 预计文件：
  - `student-portal/src/App.vue`
  - `student-portal/src/styles/v5-overrides.css`
  - `student-portal/src/styles/v5-polish.css`
- 业务逻辑影响：低；公共 CSS 影响范围大，修复后必须全路由复验

## P2：视觉、响应式与主题细节

### P2-01 复杂模块侧栏分组标题没有真正显示

V5 CSS 声明了教务、实习、学工等分组标题，但真实截图中没有显示“日常办理 / 成长关怀”“上岗准备 / 在岗办理 / 过程成果”等标题。14 个实习入口和 8 个学工入口仍为连续长列表。

- 证据：
  - `screenshots/1920x1080--internship-岗位实习.jpg`
  - `screenshots/1920x1080--campus-service-学工事务.jpg`
- 预计文件：不能继续依赖脆弱的 `nth-child + ::before`，应由真实导航数据显式分组

### P2-02 1024 宽度学工页面拥挤

- 证据：`screenshots/1024x768--campus-service-responsive.jpg`
- 实际：上下文栏、双列表单和记录卡仍并排，状态文字被迫拆行，首屏操作区域偏挤
- 期望：在较窄桌面宽度下改为内容单列或压缩记录栏，保留清晰标签和操作按钮

### P2-03 首页把缺少聚合数据误写为“未开始”

- 实际：首页成长航线把没有 `domain` 聚合记录的“成长事务 / 毕业设计”等直接显示“未开始”
- 期望：无聚合数据应显示“状态待同步 / 暂无汇总”，不能等价为业务未开始
- 预计文件：`student-portal/src/views/home/HomeView.vue`
- 业务影响：低；只改展示判断

### P2-04 通用弱文本颜色偏浅

学院蓝、紫色、绿色和粉色截图中，说明文字、表头、单位和次要状态普遍使用 `#86909c / #98a0ae` 一类浅灰，多个样本低于常规正文对比度。需要适当加深 `--t3 / --t4`，同时避免破坏层级。

### P2-05 业务页信息密度不一致

多个教务独立页在 1920 宽屏只占顶部少量区域，V5 公共骨架已变化，但页面内容仍保留旧版空白结构。该问题不是阻断，但证明 PR #29 没有逐页还原原型。
