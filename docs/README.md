**适用范围**：二级模块首次施工、续工、生产级施工包、跨文档设计核验。明确的单文件修复、单个 Bug、测试失败和只读代码核验，按根目录 `CLAUDE.md` 的最小任务模式读取直接相关资料，不需要机械通读六步。

**禁止**：业务文档施工时跳过步骤 5 直接全仓搜索；禁止继续使用旧 `docs/modules/`、根级 `docs/project-map/` 等路径。

**重要**：文档齐全 ≠ 代码已实现。完成度以各中心 README 所列代码目录 + `frontend/src/config/navPlan.js` 为准。

### 二级模块生产级施工包特殊门禁

凡是新建、补强、复核或执行一个二级模块的生产级施工文档/施工包，在进入该中心任务文档后，还必须完整读取：

[`03-业务模块设计/系统管理中心/00-系统管理中心-权限角色模块授权与权责边界设计.md`](./03-业务模块设计/系统管理中心/00-系统管理中心-权限角色模块授权与权责边界设计.md)

施工包必须输出覆盖全部三级页面的「权限总控理解与实例化矩阵」，包括角色、模块授权、权限码、数据范围、业务关系、敏感字段、状态/审批限制、审计、拒绝码和正反向测试。只列出“已读该文档”不算完成；矩阵缺失时不得继续写代码或标记生产级。

每个二级模块首次开工还必须使用：

[`06-开发施工与质量验收/二级模块生产级施工包标准模板.md`](./06-开发施工与质量验收/二级模块生产级施工包标准模板.md)

先核验三家不同成熟系统的可打开来源资料，登记产品、资料发布方、资料标题、URL、查阅日期和具体证据位置，再把搜索结果转换为模块专属施工包。只写厂商名称、只读搜索摘要、无URL或无证据位置不算完成。施工包通过外部证据、权限理解和设计就绪门禁后，CC必须在同一次任务中继续完成全部三级模块施工、测试、部署检查和状态同步，不得只交文档后停止。
