布局与层级 页头 → 5 张带「目标线」的 KPI 卡 → 双栏（异常处理队列 1.6 : 介入面 1）。监管页的主角是队列而非图表——图表只保留能触发行动的两个：教师积压排行、巡访优先级。
导航 左栏「岗位实习」手风琴展开 9 个子页，异常/周报/风险带计数徽标——管理员不点进去也知道压力在哪。指导教师进本模块时默认落在「周报批阅」，且左栏只显示与其相关的 5 项。
核心组件 KPI 卡新增「目标线刻度 + 口径说明」（AppMetricCard 扩展 targetLine）；异常行 = 学生 + 异常类型 + SLA 停留时长 + 双动作；排行条 BarRank；巡访行带优先级色点。
角色差异 学院管理员看全院并可催办教师；实习指导教师看本人 18 名学生，无催办他人入口；教务老师只读+导出；企业导师不进此端（走企业轻门户）。
交互 「去核实」打开处理抽屉（认定正常/提醒纠正/记异常 + 意见必填）；「一键催办」有二次确认并显示将通知的教师名单；KPI 卡点击 = 带筛选跳转到对应列表。
高级感来自哪里 ① SLA 语言（停留 52h / 违反 SLA / 口径线 92%）是运营系统的可信感；② 每张 KPI 卡自带达标判断，领导不用心算；③ 异常行把「学生说明」摆在管理员眼前——系统在帮人做判断，而不是只报数。
