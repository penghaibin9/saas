布局与层级 三栏检件流：件列表（308px）→ 决策区（弹性）→ 证据区（264px）。决策区自上而下是一条「判断动线」：在哪一步 → 改了什么（diff）→ 有什么风险 → 我的意见 → 通过/驳回。所有决策要素一屏收齐，不滚动。
导航 左栏「审批中心」展开：待我审批 / 待批阅 / 我发起的 / 已处理 / 被驳回 / 流程模板。批阅类（周报/开题）与审批类（异动/变更）同一壳、不同队列，习惯只学一次。
核心组件 检件卡（类型+SLA 标签+单号+摘要）；AppStepBar（当前环节高亮+停留时长）；FieldDiff 原值/新值表（新值绿底，敏感字段带锁形）；驳回原因面板（必填≥5字+常用短语，复用小程序 T5 规则）；审计时间线 OperationLogList。
角色差异 队列只显示流转到「我」的环节；教务复核人看到的是同一单据的第 3 步视角；无权限者点单号进来是 403 状态页。转办需选择同环节可代理人，动作留痕。
交互 J/K 上下切件（处理完自动跳下一件）、Enter 通过、R 驳回（聚焦原因框）；驳回二次确认并提示「将退回学生并生成待办」；处理后件从列表淡出，计数徽标全局同步。
高级感来自哪里 ① 检件流本身——「批量处理不跳页」是效率型 SaaS 的标志性体验；② diff 表让「改了什么」一秒可读，这是审批场景最被忽视的设计；③ SLA 面板与留痕栏让合规「可见」，学校采购方在意的恰恰是这个。
