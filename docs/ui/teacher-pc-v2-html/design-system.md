# Teacher PC V2 设计系统

## 版本

`1.1.0`

## 信息架构冻结

- 顶部：一级中心。
- 左侧：真实二级模块，名称、顺序、路由和权限事实来自生产 `navPlan.js`。
- 内容顶部：三级功能页签；三级页签不得冒充新的真实二级模块。
- 面包屑严格为：一级中心 / 二级模块 / 三级功能。
- 业务聚合分组不得作为菜单、折叠层级、页面、路由、点击入口或面包屑节点。
- 教务中心当前冻结为 29 个真实二级模块直接显示；左侧菜单独立滚动，支持搜索和展开/收起。
- 普通教师、学院教务员、学校教务处等角色继续由生产权限投影过滤，原型不复制权限裁决逻辑。

## 公共组件边界

- 全局顶栏与侧栏 → `BasePortalLayout`
- 页面角色、数据范围与水印 → `ModulePageShell`
- 页面标题 → `AppPageHeader`
- 卡片、按钮、状态、风险、指标 → `AppCard`、`AppButton`、`AppBadge` / `AppStatusTag`、`AppRiskTag`、`AppMetricCard`
- 表格与高级筛选 → `DataTable`、`AdvancedFilter`
- 抽屉与确认 → `AppDrawer`、`AppConfirmDialog`
- 权限按钮 → `AppPermissionButton`
- 加载、空、错误 → `LoadingState`、`EmptyState`、`ErrorState`
- 导入导出 → 现有 Excel、文件和导出确认公共组件

完整判断见 `component-reuse-matrix.md`。有现成组件时不得在业务原型中重新发明另一套按钮、表格、筛选器、弹窗或状态标签。

## 页面母版

当前使用 17 类母版：工作台/驾驶舱、标准筛选表格、列表详情双栏、独立详情、编辑表单、多步骤表单、审批流转、配置控制台、统计分析、日历课表、排课排考复杂工作台、批量操作、导入导出、打印、复杂编辑器、归档审计和只读查询。

完整映射和独立 HTML 判断规则见 `page-archetype-matrix.md`。

普通“筛选＋表格＋分页”若布局和交互相同，应复用共享母版；复杂编辑、审批、排课、考务、打印、归档和不可逆状态流转保留独立高保真 HTML。

## 考务管理设计规则

- 真实生命周期按生产页面核对为：`DRAFT → COURSE_CONFIRMED → ARRANGED / PUBLISHED → FINISHED → ARCHIVED`。
- 自动排考必须区分仅预检与正式执行，并显示人工编排保护、漏排课程和监考缺口。
- 冲突必须分别定位教师、教室、考生时间和监考缺口。
- 考场容量与座位使用二维空间编排，不降级成普通字段表格。
- 发布前必须重新读取后端状态并核验课程、时间、考场、座位、监考和冲突。
- 考场异常只记录客观事实，不越权替代处分、申诉或成绩处理。
- 归档只读；导出用途、审计和权限边界继续保留。
- 座位表、准考证和门贴使用独立 A4 打印页面。

## 选课管理设计规则

- 批次生命周期必须在首屏清晰呈现：`DRAFT / PUBLISHED / OPEN / CLOSED / LOCKED / ARCHIVED`。
- 左侧批次、右侧详情适合教务控制台；1280 宽度下不得压坏课程表格。
- 开放态优先展示课程数、总容量、已选人数、填充率和低人数课程。
- 轮次必须区分 `FCFS / LOTTERY`，并展示选退控制与 `DRAFT / OPEN / CLOSED / DRAWN` 状态。
- 摇号属于一次性高风险动作，确认态必须写明不可重摇。
- 截止后先处理低人数课程，再锁定正式名单。
- 学生自助切面只展示真实可选课程、实时余量、选课/退课、已选状态和补选指引。
- 满额课程明确禁用选课按钮，不用假候补入口。
- 归档页只读；XLSX 导出必须填写不少于 5 字的用途。

## 统一状态与专业交互

- 所有异步原型至少覆盖：默认、加载、空、错误、403 / 只读和长数据。
- 流程页补充真实审批节点、状态变化、重复提交防护和高风险确认。
- 危险操作必须说明影响范围、填写原因并保留审计提示。
- 已发布、已归档、已封存页面必须清晰锁定，不能只隐藏按钮。
- 导入必须覆盖预检、错误行、部分成功和失败明细；导出说明范围和用途。
- 表单必须考虑未保存离开、后端状态变化和保存失败。

## 响应式与可访问性

- 固定验证 `1280×900`、`1440×1000`、`1920×1080`。
- 根页面禁止横向溢出；表格、三级页签、课表和复杂画布只在自身容器滚动。
- 左侧菜单自身滚动；收起后内容区正常扩展。
- 长模块名、长文本和长表格不得破坏根布局。
- 键盘焦点、清晰对比度、Escape 关闭和语义化状态需要显式验证。
- 原型不依赖 CDN，所有资源离线可用。
