# Teacher PC V2 公共组件复用矩阵

> 本文件是设计到生产实现的可行性约束，不是生产组件改造清单，也不是第二份菜单、路由或权限事实源。

## 1. 审计前提

### 已读取的生产事实源

- `frontend/src/layouts/BasePortalLayout.vue`
- `frontend/src/config/navPlan.js`
- `frontend/src/config/adminMenu.js`
- `frontend/src/components/ui/`
- `frontend/src/components/common/`
- `frontend/src/components/business/`
- `frontend/src/components/business/ModulePageShell.vue`
- 已覆盖工作区对应的真实页面、路由注释与 API 使用关系

### 复用原则

1. 原型只表达现有公共组件能够承载、或经过最小样式增强即可承载的界面。
2. 权限、数据范围、状态机和危险动作仍以后端与真实路由为最终裁决；原型不复制判断逻辑。
3. 已有组件优先于新组件；样式增强优先于新增组件；局部业务组合优先于扩展全局组件。
4. 标记为 `GAP` 的能力，本 PR 仅记录最小改造建议，禁止修改生产组件。
5. 原型共享 CSS/JS 的边界应尽量与 Vue 公共组件边界一致，避免每个业务页自造按钮、表格、弹窗和状态标签。

### 结论标记

- **直接复用**：现有能力足够，原型不得另造交互模型。
- **复用＋样式增强**：结构和行为已具备，仅需要密度、宽度、响应式或视觉细节增强。
- **组合复用**：由两个及以上现有公共组件组合完成，不建议新增大组件。
- **GAP**：现有组件无法完整承担特殊业务形态，需最小化扩展或新增专用公共组件。

## 3. 需要记录但不在本 PR 修改的 GAP

### GAP-01：`AppDrawer` 可访问性

现有抽屉具备语义化 `dialog`、遮罩关闭和关闭按钮，但未在组件内显式实现焦点陷阱、打开后聚焦、Escape 关闭和关闭后焦点归还。原型共享脚本已补 Escape 预览，但生产实现仍建议在 `AppDrawer` 内统一补齐，禁止每页自行实现。

### GAP-02：超大数据表

`DataTable` 已具备内部横向滚动、吸顶表头、勾选、批量操作和分页，能够承担普通业务列表。考务、成绩和学籍的超宽/超大列表可能需要可选列冻结、服务端排序和虚拟滚动，应作为同一组件的可选能力演进，不建议另建第二套表格。

### GAP-03：排课与考务空间编排

排课网格、考场编排和座位图属于二维资源分配模型。它们可以复用页面壳、筛选、按钮、抽屉、确认、状态和审计组件，但核心画布需要专用业务组件。新增组件必须保持输入输出中性，不写死具体学校或角色。

### GAP-04：统一 Excel 导入流程

现有导出和文件组件较完整，但跨模块导入仍应统一为“下载模板—上传—预检—查看错误—确认—部分成功结果—错误明细下载—审计”流程。建议后续以薄封装组合现有组件，不新增独立上传技术栈。

## 4. 原型实施约束

- 158 个 HTML 只允许引用共享 CSS/JS，不得各自复制全局顶栏、29 项菜单、按钮体系或状态逻辑。
- 普通“筛选＋表格＋分页”页面优先映射到同一页面母版；只有字段、操作、权限、状态、API 或参数存在实质差异时，才在 manifest 中登记差异。
- 复杂编辑、审批、排课、考务、打印、归档和不可逆状态流转必须保留独立高保真 HTML。
- 原型中出现 `GAP` 能力时，必须标注“生产组件待最小增强”，不能伪装为现有组件已具备。
