# 教学资源：开发还原契约

> 本目录是教师 PC V2 高保真 HTML 原型。生产权限、预约事务、冲突计算、设备状态和维修接口以后端为准。

## 9 个真实入口

| 入口 | HTML | 核心任务 |
|---|---|---|
| 教室资源 | `classroom-resources.html` | 教室位置、容量、类型、设备、无障碍和可排课状态 |
| 教室预约 | `classroom-bookings.html` | 临时教学、补课、会议等预约与审批 |
| 实训室资源 | `lab-resources.html` | 安全等级、责任人、工位、课程适配和开放状态 |
| 设备资源 | `equipment-resources.html` | 教学设备、所在实训室、数量、维修和校准状态 |
| 实训室预约 | `lab-bookings.html` | 教学任务、学生、设备、耗材、安全和时段审批 |
| 资源占用 | `resource-occupancy.html` | 统一只读展示课表、考试、预约和维修停用 |
| 资源冲突 | `resource-conflicts.html` | 定位重叠来源、处理冲突并重新校验 |
| 资源维修 | `resource-repairs.html` | 报修、分级、派工、停用、验收、复开和复发 |
| 资源统计 | `resource-stats.html` | 利用率、预约效率、冲突、维修和供需缺口 |

## 资源调度模型

```text
资源档案与能力
        ↓
课表 / 考试 / 临时预约 / 实训预约 / 维修计划
        ↓
容量、安全、设备、耗材、人员与时间预检
        ↓
生成统一占用记录
        ↓
冲突检测与来源流程处理
        ↓
使用、释放、维修或异常
        ↓
统计与审计
```

## 关键边界

1. 资源档案显示“可排课”不代表某个时段空闲。
2. 教室预约不能覆盖正式课表或考试安排。
3. 实训室预约批准前不形成正式占用。
4. 占用页是只读汇总，不能直接拖动覆盖来源业务。
5. 冲突处理必须回到课表、考试、预约或维修来源流程，再重新计算。
6. 高等级维修故障应立即冻结资源可用性和后续预约。
7. 维修完成不等于资源恢复可用，必须经过验收和复开。
8. 教学设备可用状态不替代学校固定资产财务总账。

## 教室资源最小字段

- 校区、楼栋、楼层、房间
- 教室类型
- 核定容量和座位布局
- 投影、扩声、录播、网络等教学能力
- 考试适用能力
- 无障碍入口、电梯、座位和辅助设施
- 可排课、限制使用、临时停用、永久停用
- 停用原因与时间范围
- 最近核验时间和责任人

## 实训室资源最小字段

- 实训室名称与位置
- 安全等级
- 管理责任人和应急联系人
- 核定容量与有效工位
- 适用课程、专业和项目
- 关键设备、耗材和环境要求
- 教师与学生准入条件
- 开放时间
- 安全检查、维护和停用状态

## 设备资源口径

设备至少保存：

- 资产编号或教学设备编号
- 名称、类别、型号和规格
- 所在实训室或仓储位置
- 总数量、维修数量、冻结数量和教学可用数量
- 是否需要校准、检验或资质
- 校准到期时间
- 故障和维修单关联
- 可预约条件

教学可用数量不能简单等于账面数量，应排除维修、校准过期、冻结和已占用设备。

## 预约预检

教室预约至少校验：

- 申请人权限
- 用途是否允许
- 参与人数与容量
- 教学设备和无障碍需求
- 正式课表
- 考试安排
- 其他已批准预约
- 维修停用

实训室预约还需校验：

- 教学任务或临时实训依据
- 教师准入和资质
- 学生安全培训
- 工位数量
- 关键设备数量
- 耗材储备
- 安全等级和风险要求

预检失败应给出可执行候选：换时段、换资源、拆班、减少设备需求或补齐安全条件，不能只显示“冲突”。

## 占用来源

统一占用至少区分：

- 正式课表 `TIMETABLE`
- 考试安排 `EXAM`
- 教室预约 `CLASSROOM_BOOKING`
- 实训室预约 `LAB_BOOKING`
- 维修停用 `REPAIR_BLOCK`

每条占用记录必须保留来源单、资源、日期节次、使用对象、优先级和状态。

## 冲突处理

冲突可以包括：

- 同一教室同一时段重复
- 同一实训室同一时段重复
- 设备数量不足
- 容量不足
- 教师或班级同时占用
- 维修与教学或考试重叠
- 安全条件不足

冲突页只负责解释和路由。处理完成后必须重新校验全部约束，不能靠人工把冲突标记为“已解决”而不修改来源。

## 维修闭环

```text
报修登记
→ 故障分级
→ 派工与资源停用
→ 维修过程记录
→ 完成验收
→ 恢复可用
→ 关闭或复发重开
```

高等级故障应自动进入占用和预约校验。关闭维修单必须记录验收人、验收时间、结果、附件和恢复可用时间。

## 开发 AI 读取顺序

1. 阅读每个 HTML `<head>` 的 route、permission、roles、states 和 boundary。
2. 阅读 `manifest-parts/170-resource.json` 获取机器可读字段、状态和来源模型。
3. 阅读 `shared/v2-resource-workbench.js` 获取页面结构、交互和占位数据。
4. 阅读 `shared/v2-resource-workbench.css` 获取日历、冲突、维修和响应式视觉规则。
5. 回到生产 `navPlan.js` 和真实后端 service、schema、permission、事务及冲突算法核对。

当前已确认导航中的 9 个入口和只读权限。新建、审批、停用、维修、验收等写权限，以及真实 API 和状态枚举，在生产施工前必须重新核对。
