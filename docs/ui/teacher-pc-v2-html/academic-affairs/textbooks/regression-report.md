## 重点验证

1. ISBN、版次、出版社和课程适用关系可追溯。
2. 目录建档、课程选用、审核备案和采购征订没有混成一个状态。
3. 数量依据能够表达学生、教师用书、安全库存和有效库存。
4. 沿用上期与换版均需要说明和审计。
5. 到货验收区分短缺、错版、破损和分批到货。
6. 只有验收通过数量进入可用库存。
7. 库存按 ISBN、版次、仓库和批次管理。
8. 发放、退回、损坏、盘点和调整均作为独立事务。
9. 教材费用台账明确不等同学校财务总账或毕业费用结清。
10. 统计覆盖选用、审核、到货、发放、库存和教材费用差异。

## 阻断记录

### 生产组件、API、写权限和状态枚举未定位

当前确认事实为 `navPlan.js` 中 7 个教材管理入口和 `academicAffairs.textbook.view` 权限。新增目录、提交选用、审核备案、采购、库存调整等写权限，以及真实接口和状态枚举未稳定定位。

处理：

- HTML 使用 `routeName: to verify`。
- 只读权限使用导航中已出现的权限。
- 原型中的写操作和业务状态只表达产品设计，不宣称生产后端已经具备。
- 生产施工前必须重新审计权限、库存并发、费用回传和审计接口。

### 最终 GitHub 文件无法在容器中整分支重新材料化

当前执行环境无法直接克隆最新 GitHub 分支。浏览器回归使用本地等价材料化页面；最终写入文件完成文件级、资源引用级和语法级核对。

该限制已记录，不阻断后续 HTML 原型设计。
