# 补考重修缓考免修：开发还原契约

> 本目录是教师 PC V2 高保真 HTML 原型，不是生产实现。生产权限、资格、状态与数据范围始终以后端为准。

## 1. 页面入口

| 入口 | HTML | 核心任务 |
|---|---|---|
| 补考批次 | `makeup-batches.html` | 资格快照、课程确认、名单锁定、发布、结果回写、归档 |
| 重修审批 | `retake-approval.html` | 规则预检、学院审核、教务复核、待分班衔接 |
| 免修审批 | `exemption-approval.html` | 材料核验、课程目标匹配、多级审批、结果归档 |
| 毕业清考 | `graduation-clearance.html` | 毕业批次课程缺口、资格快照、阻断处理、考务合流 |
| 缓考合流 | `deferred-merge.html` | 将已审批缓考安全并入补考批次 |
| 学生自助 | `my-makeup.html` | 查看资格、提交申请、补材料、跟踪结果 |
| 统计分析 | `makeup-stats.html` | 资格、审批、参考、通过与异常漏斗 |
| 材料归档 | `exemption-archive.html` | 原件、审批快照、版本和下载审计 |

## 2. 真实业务链

```text
成绩 / 学籍 / 培养方案 / 缓考审批
              ↓
          资格快照
              ↓
      课程确认与规则预检
              ↓
        人工审核与异常闭环
              ↓
       名单锁定 / 考务合流
              ↓
       发布执行 / 成绩回写
              ↓
          只读归档
```

资格快照必须保存输入版本。成绩更正、休复学、课程替代、重复申请等后续变化进入差异清单，不允许静默覆盖已锁定名单。

## 3. 四类业务不能混为一谈

- **补考**：通常来自未通过课程成绩，围绕考试批次、资格名单和考务执行。
- **重修**：需要重新学习或参加教学活动；审批通过后仍需进入教学班安排。
- **缓考**：先经过独立缓考审批；本模块只接收已批准记录并与补考考务合流。
- **免修**：基于证书、竞赛或既往学习成果判断课程学习义务；与免考、成绩认定分开裁决。

## 4. 不可越过的边界

1. 清考资格不是毕业资格。
2. 重修审批通过不是选课成功，也不是已分配教学班。
3. 缓考合流不能替代缓考审批。
4. 免修、免考、成绩认定不能用一个状态字段代替。
5. 学生端只展示本人数据，前端不能自行计算最终资格。
6. 发布、锁定、归档等不可逆动作必须二次确认并写审计。
7. 归档原件不能覆盖，只能形成新版本或追加说明。

## 5. 开发 AI 读取顺序

1. 先读每个 HTML `<head>` 中的 route、permission、roles、states 与 boundary 注释。
2. 再读 `manifest-parts/130-makeup.json` 获取机器可读字段和状态。
3. 读 `shared/v2-makeup-workbench.js` 获取页面结构、交互和中性占位数据。
4. 读 `shared/v2-makeup-workbench.css` 获取模块响应式规则。
5. 最后回到生产 `navPlan.js`、真实后端 service / schema / permission，确认接口与状态名；原型中的 permission 均标记为 candidate，不得直接当作既有生产事实。

## 6. 页面状态要求

每个入口都需要：

- 正常态
- 加载态
- 空态
- 错误态与重试
- 403 / 只读态
- 长数据态
- 业务状态和异常原因

批量处理必须返回成功项、失败项、失败原因与可重试入口，不能只弹“操作成功”。

## 7. 数据与隐私

原型内姓名、人数、课程、批次均为中性占位数据。统计默认聚合；学生下钻受权限和数据范围控制；小样本应隐藏或合并，避免反推出个人信息。
