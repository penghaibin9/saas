## 设计验证重点

1. 扫描绑定规则版本和数据快照，不覆盖历史结果。
2. 数据来源不可用时显示 `UNKNOWN`，不静默视为通过。
3. 红橙黄蓝等级旁边均有责任动作和时限，不只显示颜色。
4. 挂科风险区分学生个体风险与课程群体质量异常。
5. 学分风险绑定培养方案版本，并展示可修复路径。
6. 补考重修风险只负责识别断点，不越权完成审批、分班或考务处理。
7. 毕业风险预警与毕业资格审核分离。
8. 规则经过草稿、模拟、影响评估、发布和停用。
9. 跟进记录包含责任人、期限、联系、计划、证据、复评、关闭和复发。
10. 通知渠道由后端返回可用性，不假装短信已经接通。

## 阻断与诚实记录

### 生产组件、API 和状态枚举未定位

代码搜索未定位到稳定的学业预警生产组件、API 和后端状态枚举。已确认的事实只有 `navPlan.js` 中 11 个入口和其中明确声明的权限。

处理：

- HTML 中使用 `routeName: to verify`。
- 首个“预警扫描与列表”入口没有在导航中声明权限，标记为 `permission: to verify`。
- 其他入口使用导航中已出现的 `academicAffairs.warning.view`、`academicAffairs.warning.rule.manage` 和 `academicAffairs.warning.handle`。
- 原型状态为业务语义，不宣称是现有后端枚举。

该问题已记录，不阻断继续设计；生产施工前必须重新核对。

### 执行环境不能克隆最新分支

当前容器不能通过 GitHub URL 重新克隆或直接导航分支页面。浏览器回归使用本地等价材料化版本；最终 GitHub 文件完成文件级和引用级核对。

该限制不阻断后续 HTML 原型设计。
