# 学业预警：开发还原契约

> 本目录是教师 PC V2 高保真 HTML 原型。生产权限、规则、数据快照、接口与状态始终以后端为准。

## 页面入口

| 入口 | HTML | 核心任务 |
|---|---|---|
| 预警扫描与列表 | `warning-scan.html` | 绑定规则版本和数据快照，生成预警并分配责任人 |
| 预警看板 | `warning-dashboard.html` | 今天新增、逾期、解除、复发和数据源健康 |
| 学分预警 | `warning-credit.html` | 培养方案版本、学分缺口与可修复路径 |
| 挂科预警 | `warning-fail.html` | 学生连续风险与课程群体异常分开判断 |
| 绩点预警 | `warning-gpa.html` | 学期、累计、趋势、贡献课程和计算口径 |
| 补考重修预警 | `warning-retake.html` | 报名、入班、参考、连续未通过等跨模块断点 |
| 毕业风险预警 | `warning-graduation.html` | 学分、课程、实践、毕设、实习和未知来源 |
| 预警规则 | `warning-rules.html` | 草稿、模拟、影响评估、发布、生效、停用 |
| 预警跟进 | `warning-followup.html` | 责任人、期限、联系、计划、证据、复评、关闭、复发 |
| 预警统计 | `warning-stats.html` | 新增、存量、逾期、解除、复发和处置效率 |
| 预警通知 | `warning-notify.html` | 通知任务、模板版本、受众、渠道、发送和回执 |

## 闭环

```text
数据快照
  ↓
规则扫描（绑定版本）
  ↓
风险分级与合并
  ↓
分配责任人和期限
  ↓
通知、联系、帮扶计划和证据
  ↓
新数据触发复评
  ↓
解除 / 长期跟踪 / 转其他流程 / 关闭
  ↓
再次命中时重新开启或标记复发
```

## 必须坚持的边界

1. 学业预警用于帮助和干预，不是处分。
2. 预警等级不是最终毕业结论，也不能替代毕业资格审核。
3. 数据源缺失、延迟或接口未接入时结果为 `UNKNOWN`，不能静默当作 `PASS`。
4. 挂科预警要区分学生个体风险和课程群体质量异常。
5. 补考重修预警只读取相关模块的结果，问题回到审批、教学班或考务流程处理。
6. 规则发布前必须模拟，展示新增、升级、降级、解除与 UNKNOWN 的影响数量。
7. 历史预警永久绑定当时的规则版本和数据快照。
8. 关闭预警必须有责任人、处置记录、证据和复评结果。
9. 同一学生多条命中可合并为一个跟进主单，但每条规则命中仍需保留。
10. 通知渠道是否可用由后端返回，不得因为页面有短信按钮就假装短信已接通。

## 数据来源健康

建议每次扫描保存以下来源的可用状态、版本和时间：

- 已发布成绩
- 培养方案与学分达成
- 学籍状态
- 补考、重修与考务结果
- 实践环节
- 毕业设计状态
- 岗位实习状态
- 学校后续接入的外部数据

关键来源不可用时，看板必须显示“数据不完整”，不得输出强结论。

## 规则治理

每条规则至少包含：

- 指标与来源字段
- 比较符与阈值
- 红、橙、黄、蓝等级
- 学校、学院、专业、年级等适用范围
- 生效开始与结束时间
- 优先级和规则冲突处理
- 模拟结果
- 发布人、发布时间和版本号
- 停用原因

规则修改生成新版本，不覆盖历史版本。

## 跟进主单

跟进记录至少包含：

- 学生和全部命中规则
- 最高风险等级及变化历史
- 责任角色与责任人
- 分配时间、完成期限和逾期状态
- 联系方式、联系时间和客观纪要
- 帮扶计划、阶段目标和附件证据
- 复评触发条件与复评结果
- 解除、关闭、转流程或长期跟踪原因
- 关闭后再次命中的复发标记

## 开发 AI 读取顺序

1. 阅读每个 HTML `<head>` 的 route、permission、roles、states 和 boundary 注释。
2. 阅读 `manifest-parts/140-warning.json` 获取机器可读路由、字段与边界。
3. 阅读 `shared/v2-warning-workbench.js` 获取页面结构、交互和中性占位数据。
4. 阅读 `shared/v2-warning-workbench.css` 获取模块响应式设计。
5. 回到生产 `navPlan.js` 和真实后端代码核对组件、接口、权限常量与状态枚举。

当前只确认了 `navPlan.js` 的 11 个入口及其中明确声明的权限；未定位到稳定的生产组件、API 和后端枚举时，不得把原型语义名当作既有代码事实。
