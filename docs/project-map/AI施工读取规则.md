# AI 施工读取规则

> 适用：Cursor Agent、Claude Code、任何 AI 开发助手
> 更新：2026-07-09
> 与根目录 `CLAUDE.md` 配套；冲突以 `CLAUDE.md` 为准。

---

## 1. 每次开工强制顺序

```
1. docs/00-只看这个-项目入口.md
2. CLAUDE.md
3. docs/project-map/AI施工读取规则.md（本文）
4. docs/project-map/当前有效文档索引.md
5. docs/project-map/模块状态总表.md
6. docs/project-map/下一步施工总控.md
7. docs/施工记录/历史欠账.md
8. [若涉及权限] docs/modules/00-系统管理中心-权限角色模块授权与权责边界设计.md
9. 当前任务模块的 modules 成套文档（总册/页面树/API/状态机/按钮矩阵）
10. 该模块相关施工记录（docs/施工记录/日期-模块*.md）
11. frontend/src/config/navPlan.js（核对 implemented/partial/planned）
12. [若做接口] docs/api/后端当前接口清单.md + 对应 API 契约
13. [若做页面] `docs/公共组件/README.md` → 总控表 + 使用指南总册
```

**禁止跳过 1–7 直接写代码。**

## 4. 文档类型识别（勿混淆）

| 类型 | 特征 | AI 应如何使用 |
|---|---|---|
| 项目入口 | `00-只看这个` | 每次先读 |
| 总体/模块设计 | `*设计总册*`、`*页面树*` | 定义要做什么；**≠ 已完成** |
| 施工任务卡 | `*施工卡*`、`*施工总图*` | 步骤清单；**≠ 验收报告** |
| 施工记录 | `施工记录/2026-*` | **事实**：做了什么、测了什么 |
| 验收报告 | 施工记录内「完工」「收口」 | 可引用状态；仍要核对 navPlan |
| API/DB | `api/`、`database/` | 契约参考；DB 栈以 MySQL 为准 |
| 历史归档 | `archive/`、过时 project-map | 不用于施工决策 |

---

## 5. 行为铁律

1. **不允许**根据旧文档推翻 `modules/13A|13B|06` 新总册。
2. **不允许**把设计文档里的「可包含」当成已实现菜单。
3. **不允许**把施工任务卡当成「模块已交付」。
4. **不允许**把 `planned` 写成 `implemented`（必须对齐 navPlan + pytest + MySQL）。
5. **不允许** mock 写操作成功；生产环境 mock 必须禁用。
6. **不允许**只改前端：权限、数据范围、审计、租户隔离必须后端校验。
7. **不允许**越过用户当前任务范围改无关模块。
8. **不允许**未读权限总控文档就改权限相关代码。
9. **不允许**新建 CSV 正式导入导出（必须 Excel/xlsx + 公共底座）。
10. **不允许**在无用户要求时 `git commit` / `git push` / 删文档 / 改非任务目录。

## 6. 文档命名规则

| 前缀/模式 | 含义 | 示例 |
|---|---|---|
| `00-` | 全局入口/规则 | `00-只看这个-项目入口.md` |
| `01-`–`12-` | 早期中心编号（source-design） | `02-数字迎新` |
| `05-` | 毕业设计中心 | source-design 或 delivery |
| `06-` | 岗位实习中心 | `modules/06-*`（当前权威） |
| `13A-` | 学工中心 | `13A-学工中心页面树*` |
| `13B-` | 教务中心 | `13B-教务中心API*` |
| `02A-` | 数字迎新专项 | 生产级审计续接 |
| `*-施工卡.md` | 待执行施工步骤 | B包/C包施工卡 |
| `*-施工总图.md` | 多包顺序与边界 | 四大任务包总图 |
| `*-设计总册.md` | 业务流程产品规则 | 全业务流程设计总册 |
| `施工记录/YYYY-MM-DD-*` | 已完成施工事实 | 验收依据 |
| `project-map/` | 文档体系总控 | 索引/状态/冲突 |
| `archive/` | 历史废弃 | 禁止施工依据 |

**目录职责**：

- `施工记录/` — 只记**已发生**的施工与验收事实
- `modules/*施工卡*` — 只记**将要**做的步骤
- `modules/*设计总册*` — 只记**产品应有什么**（不是代码状态）

---

## 7. 与代码事实源对齐

开发前后必须核对：

| 事实源 | 核对内容 |
|---|---|
| `navPlan.js` | 菜单 status 与 path 是否真实 |
| `backend/tests/` | 接口是否回归通过 |
| MySQL dev/test | 是否真库验证（见历史欠账） |
| `历史欠账.md` | partial 是否已记账 |

## 8. 输出要求（每次任务结束）

按 `CLAUDE.md` §23 任务报告模板输出，并注明：

- 读了哪些文档（路径列表）
- 是否发现文档冲突（若有，登记冲突清单）
- navPlan 状态是否变更
- 是否新增/关闭历史欠账
