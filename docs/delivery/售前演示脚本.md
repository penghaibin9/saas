# 售前演示脚本

> 给学校做 15–20 分钟演示的标准流程。目标：让学校老师"看懂、相信、想用"。

## 演示前准备
- 打开演示环境（我方提供的演示网址 + 小程序）。
- 演示账号（演示环境 mock 登录，仅供体验，**非真实数据**）：
  - 学生：`student01`
  - 辅导员：`counselor01`
  - 毕设/实习导师：`teacher01`
  - 就业老师：`employment01`
  - 教务老师：`academic01`
  - 学院管理员：`college_admin01`
  - （演示 mock 登录口令统一为 `demo`；正式环境用真实账号密码，不用 mock）

## 演示主线（跟着学生一学期走）

### 1）开场（1 分钟）
"这套系统管学生从入学到毕业就业全过程，老师在手机上就能处理日常，学校在电脑端管理和看数据。"

### 2）学生端（5 分钟）
- 用 `student01` 登录小程序 → 首页"下一步要做什么"。
- 演示：提交一次请假申请（填事由）→ 到"我的申请"看进度。
- 演示：交一次实习周报（填内容）→ 提示提交成功。
- 强调：**学生只看得到自己**、敏感信息打码。

### 3）教师端（6 分钟）
- 用 `counselor01` 登录 → 工作台一屏看待办/风险学生。
- 演示：处理刚才学生的请假审批（通过/退回写原因）。
- 演示：风险学生列表——**只显示我带的班**，打开别班学生提示"无权限"。
- 切到 `teacher01` 批实习周报；`employment01` 看就业跟进分类。

### 4）管理端（4 分钟）
- 用 `college_admin01`/管理员登录 PC → 学生主档（脱敏）、数据看板。
- 演示：批量导入学生（先校验看行号错误，再确认）。
- 强调：多学校数据隔离、操作留痕、权限分级。

### 5）收尾（2 分钟）
- "试点很快：给我们院系/学生/教师名单，我们一天就能把贵校初始化好。"
- 讲清"暂不承诺"：短信需配密钥、正式商用需过等保、深度对接后续。

## 演示话术红线（诚实）
- 不夸大：短信是"可接入"，不是"已接通"（除非真配了密钥）。
- 演示数据要说明是**演示数据**，不是真实学生。
- 被问安全资质：如实说"技术措施已具备，等保测评/渗透需第三方，正在推进"。
