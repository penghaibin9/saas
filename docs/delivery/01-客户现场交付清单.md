# 01 · 客户现场交付清单

> 去学校现场交付/演示**之前**，对着这份把东西备齐。缺一样都可能让现场卡壳。

---

## A. 访问与环境

- [ ] PC 管理端线上地址（或本地可跑的演示环境）确认可用。
- [ ] 小程序 H5 地址确认可用；或微信小程序**体验版**已上传、可扫码。
- [ ] 演示账号/入口清楚（学生端、教师端、管理端各怎么进）。
- [ ] **本地兜底环境**已准备好（万一现场网络/服务器出问题，用本地 `npm run preview` / `npm run dev:h5` 顶上）。
- [ ] 现场网络确认能用；备好手机热点。

---

## B. 设备与投屏

- [ ] 演示用电脑（浏览器为主，建议 Chrome/Edge，最新版）。
- [ ] 演示用手机（装好微信，微信号已加入小程序体验成员）。
- [ ] 投屏线/转接头/HDMI 齐全，提前测过能投上。
- [ ] 电脑电量/电源、网线（有线更稳）。

---

## C. 材料与说明

- [ ] 演示脚本/流程顺序（先演什么后演什么，见 `04-管理员培训提纲.md` 可作参考路线）。
- [ ] **现状说明口径**：当前为功能演示版，前端 + 演示数据，后端未接（见 README）。
- [ ] 验收清单打印/带电子版（`03-验收测试清单.md`）。
- [ ] 常见问题答复（`05-常见客户问题答复.md`）随身，应对提问。
- [ ] 运维现场手册（`docs/ops/08-客户现场问题处理手册.md`）备用。

---

## D. 交付物清单（如本次是正式交付）

- [ ] 源代码（frontend / miniapp）及说明——以约定的交付方式提供。
- [ ] 文档：部署（`docs/deploy/`）、运维（`docs/ops/`）、交付（`docs/delivery/`）、目录地图（`docs/project-map/`）。
- [ ] 设计冻结文档位置说明（UI：`docs/ui/`；数据库：`docs/database/`；API：`docs/api/`）。
- [ ] 部署示例文件（`deploy/`）。
- [ ] 明确书面写清：**当前已交付能力 vs 后续阶段能力**，避免验收争议。

---

## E. 交付前最后确认

- [ ] 已按 `02-演示前检查清单.md` 跑通一遍。
- [ ] 出问题的处理/回滚路径清楚（`docs/deploy/09`、`docs/ops/05`）。
- [ ] 至少两个人知道今天演示的账号和流程（避免单点）。
