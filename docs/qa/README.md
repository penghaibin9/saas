## 一、台账用途

本台账是"高校学生全生命周期管理平台"项目的**缺陷与风险统一登记入口**，服务以下场景：

1. **测试执行回填**：`docs/testing/` 各测试清单执行中，凡用例判定为"不通过"（✗/☒），登记到 `01-当前已知问题台账.md`。
2. **工程风险公示**：项目当前处于 mock 阶段，存在大量"当前能演示、但离真实上线还很远"的结构性风险，登记到 `02-技术风险台账.md`，供项目管理者、客户方、上级汇报使用，避免"演示效果好=可以上线"的误判。
3. **上线判定依据**：哪些问题必须解决才能上线，汇总为 `03-上线前阻断项清单.md`，作为上线评审（Go/No-Go）的硬性检查表。
4. **路线图输入**：非阻断但有价值的优化项，登记到 `04-后续优化清单.md`，供产品排期参考。

## 三、更新机制

- **谁来更新**：测试执行人、开发负责人、项目管理者均可向本台账提交条目；建议由质量与风险管理角色统一维护编号与状态，避免重复编号。
- **何时更新**：
  - 测试执行（参见 `docs/testing/`）发现新问题时，即时补充到 `01-当前已知问题台账.md`。
  - 技术方案评审、架构决策变化时，同步刷新 `02-技术风险台账.md` 的"当前状态"列。
  - 后端接入（参见 `docs/backend-integration/`）里程碑达成时，对应阻断项在 `03-上线前阻断项清单.md` 中标注完成，不从表中删除（保留追溯记录）。
  - 每次上线评审前，必须整体过一遍 `03-上线前阻断项清单.md`，未完成项一票否决上线。
- **编号规则**：编号一经分配不可复用；已解决/已关闭的条目保留在表中并在"当前状态"列标注"已解决"，不删除整行，保证历史可追溯。

| 前缀 | 含义 | 使用文件 |
|---|---|---|
| `BUG-xxx` | 当前已知功能/体验问题 | `01-当前已知问题台账.md` |

## 四、表格字段统一说明

本台账所有表格（除 `04-后续优化清单.md` 另行说明外）列固定为：

**编号 / 风险或问题描述 / 影响 / 当前状态 / 建议处理时间 / 是否阻断演示 / 是否阻断上线**

| 字段 | 说明 |
|---|---|
| 编号 | 见上表前缀规则，如 `RISK-001`、`BUG-001`、`BLOCK-001`、`OPT-001` |
| 风险或问题描述 | 具体描述问题现象或风险内容；不确定的具体行为写"待测试确认"，禁止编造具体 bug 细节 |
| 影响 | 该问题/风险如果不处理，会对演示效果、用户体验、数据安全、上线合规造成什么后果 |
| 当前状态 | 当前进展，如"待处理"“待后端接入后验证”“已知未做”“待测试确认”“设计中” |
| 建议处理时间 | 建议在项目哪个阶段处理，如"后端接入阶段”“UI 对接阶段”“上线前”“上线后迭代” |
| 是否阻断演示 | 是 / 否 —— 判定标准见下 |
| 是否阻断上线 | 是 / 否 —— 判定标准见下 |

### 4.1 "是否阻断演示"判定标准

判定为"是"（阻断演示），需满足以下任一条件：

- 该问题会导致当前 mock 环境下的演示流程**无法走通**（如页面白屏、关键按钮点击无响应、核心业务流程中断）。
- 该问题会让客户/评审方在演示现场**直接看到明显的功能缺失或报错**，影响演示可信度。

不满足以上条件、仅影响真实生产可用性（如"后端未接入"本身），在当前 mock 演示场景下判定为"否"（不阻断演示），但可能同时判定为"是"（阻断上线）。

### 4.2 "是否阻断上线"判定标准

判定为"是"（阻断上线），需满足以下任一条件：

- 该问题涉及**数据真实性**：只要系统未接入真实数据库、真实后端服务，业务数据就不具备生产可用性。
- 该问题涉及**安全与合规**：无真实登录鉴权、权限仅前端判断无服务端二次校验、导入导出未走真实文件服务与审计、等保测评未完成（视客户与监管要求）。
- 该问题涉及**数据隔离与多租户安全**：数据范围（`SELF/ASSIGNED/CLASS/COLLEGE/SCHOOL/ALL`）未经服务端真实校验，存在越权访问风险。
- 该问题一旦在生产环境发生，会造成数据泄露、数据错误、越权操作等不可接受的后果。

纯体验型、非安全非数据类的优化项（如"再增加几个可视化图表”“无障碍细节”），判定为"否"（不阻断上线），归入 `04-后续优化清单.md`。

## 五、与其他文档的关系

- 缺陷发现来源：`docs/testing/`（测试策略、用例、执行记录），本台账的 `01-当前已知问题台账.md` 承接其"不通过"用例的登记，不重复定义测试用例本身。
- 技术风险的解决路径：`docs/backend-integration/`（后端接入顺序与联调任务分工），本台账的 `02-技术风险台账.md`、`03-上线前阻断项清单.md` 中涉及后端接入的条目，其具体接入计划以该目录为准，本台账只登记风险与阻断判定，不重复制定接入计划。
- 权限与数据范围的权威口径：`docs/rbac/`（RBAC 权限与数据范围矩阵，由另一 agent 生成）与共享事实底稿第 3 节；本台账中涉及权限的风险条目引用该口径。
- 安全基线的权威口径：`docs/security/00-等保三级安全基线总册.md`；本台账中涉及安全的风险条目引用该口径，不重新定义安全策略本身。
- 接口契约的权威口径：`docs/api/00-API契约冻结总册.md` 及分域文档；本台账中涉及接口的风险条目只引用，不重写契约。
