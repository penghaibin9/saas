# 上线前阻断项清单

- **文档性质**：上线阻断项清单（Go / No-Go 评审用硬性检查表）
- **适用端**：PC 管理端（`frontend/`）+ miniapp（`miniapp/`）+ 后端（`backend/`）+ 数据库 + 基础设施
- **依据**：
  - 共享事实底稿 `_shared_brief.md`
  - `docs/database/00-数据库设计冻结总册.md`（数据库设计，只引用不重写）
  - `docs/api/00-API契约冻结总册.md` 及分域文档（接口契约，只引用不重写）
  - `docs/security/00-等保三级安全基线总册.md`（安全基线，只引用不重写）
  - `docs/backend-integration/`（后端接入顺序与联调任务分工，由另一 agent 生成，本清单各阻断项的具体实施计划以其为准）
  - `docs/testing/09-上线前验收清单.md`（测试维度的上线验收项，本清单是其在质量与风险维度的补充视角）
- **当前阶段声明**：本清单只登记"**必须解决才能上线**"的硬性阻断项，均对应共享事实底稿明确的当前阶段现状：后端未接入、数据库未真实联调、无真实登录鉴权、权限仅前端判断、导入导出未接真实文件服务、等保三级未测评。本清单不是可选优化项列表，而是上线评审的一票否决检查表。
- **生成日期**：2026-07-04

---

## 一、使用方式

本清单用于项目上线前的 **Go / No-Go 评审**：清单中每一项在评审时必须逐条确认"是否完成"，任一项未完成，原则上不具备上线条件（除非客户方与项目管理者共同书面确认可接受的例外与补偿措施）。清单同时标注该阻断项是否也阻断当前的 mock 演示，帮助区分"现在能不能演示"与"能不能上线"两个独立判断维度。

## 二、上线前阻断项清单（BLOCK-xxx）

| 编号 | 阻断原因 | 负责方向 | 完成判据 | 是否同时阻断演示 |
|---|---|---|---|---|
| BLOCK-001 | 后端接入并实现服务端鉴权：当前 `backend/` 仅有 config/middlewares/utils，无真实业务接口；无真实登录鉴权意味着任何人都能扮演任意角色，系统不具备最基本的身份安全前提 | 后端开发（技术栈 PostgreSQL + Python FastAPI + SQLAlchemy + Alembic），对应 `/api/v1/authz/*` 权限与身份底座 | 1）实现真实的登录鉴权流程（含首登强制改密）；2）实现会话管理（PC 30 分钟无操作超时、移动端 7 天、并发 3、超时前 5 分钟预警）；3）`tenant_id` 由后端从登录上下文解析，前端不传；4）对照已冻结的 `docs/api/01-认证租户与当前上下文API.md` 完成接口实现并联调通过 | 否（当前演示环境刻意用 mock 登录简化流程） |
| BLOCK-002 | 数据库真实联调：数据库设计已冻结（`docs/database/00-数据库设计冻结总册.md`），但从未与真实数据库实例产生过读写交互，模型的真实可用性未经验证 | 后端开发 + 数据库工程 | 1）完成 Alembic 迁移脚本并在真实 PostgreSQL 实例上执行通过；2）核心业务域（学生主档、迎新、在校服务、学业过程、岗位实习、毕业设计、就业服务）完成 ORM 模型（SQLAlchemy）与真实接口的读写联调；3）关键约束（唯一性、外键、索引）在真实库上验证生效 | 否 |
| BLOCK-003 | 真实登录：与 BLOCK-001 强相关但聚焦"登录"本身——当前 PC 端与 miniapp 均为预置账号 mock 登录（如 miniapp 固定账号"学生 林可欣 2024010612”“教师 张明远 T20190087”），无法支持真实用户注册/账号分配/找回密码等场景 | 后端开发 + PC/miniapp 前端联调 | 1）支持真实账号体系（学校/学院分配账号或统一身份认证对接，具体方式待后端确认）；2）密码策略、找回密码/重置密码流程落地；3）PC 端与 miniapp 均切换为真实登录接口，移除 mock 登录路径 | 否 |
| BLOCK-004 | 数据范围服务端过滤：当前数据范围判断（`SELF/ASSIGNED/CLASS/COLLEGE/SCHOOL/ALL`）仅在前端 `permission.context.js` 中实现（`getDataScope`），前端判断不可信，服务端若不做二次过滤，会导致跨班级/跨学院/跨学校的越权数据访问 | 后端开发，覆盖所有列表/详情类接口 | 1）所有数据查询接口在服务端根据当前角色的 `dataScope` 强制过滤，不依赖前端传参；2）越权访问返回统一错误码 `NO_DATA_SCOPE`（403）；3）按 `docs/testing/05-数据范围测试清单.md` 逐项执行验证并通过；4）多租户 `tenant_id` 隔离同步验证（不同租户账号互相尝试访问返回拒绝） | 否 |
| BLOCK-005 | 文件服务：`/api/v1/files/*` 文件中心尚未真实实现，当前导入导出、材料上传等功能均为前端 mock 交互，无真实文件存储、解析、下载能力 | 后端开发，独立的文件中心域 | 1）实现统一文件上传/下载接口，遵循"上传只返回 `file_id`，业务只提交 `file_id`"的契约原则；2）落地上传白名单（pdf/doc/docx/jpg/jpeg/png/zip/rar/xlsx/pptx）、单文件 ≤50MB 限制、黑名单（exe/js/bat/sh/php/jsp/html/svg）过滤；3）与依赖文件服务的各业务模块（学生材料上传、迎新材料、毕业设计材料、实习周报附件等）完成真实联调 | 否 |
| BLOCK-006 | 导入导出真实化：学生批量导入（`student.import`）、导出（`student.export`）、导出档案（`exportArchive`）当前仅有 mock 响应，无真实的模板生成、文件解析、逐行校验、错误行返回能力 | 后端开发（依赖 BLOCK-005 文件服务先行） | 1）实现真实的导入模板下载；2）实现文件解析与逐行校验，校验失败返回错误码 `VALIDATION_ERROR` 及具体错误行清单；3）导出功能实现三档策略（LIST / ENCRYPTED_ARCHIVE / DESENSITIZED）并对应权限点（`security.export.list` / `security.export.archive` / `security.export.desensitized`）真实校验；4）默认导出行数上限（≤5000 行）在服务端强制生效；5）按 `docs/testing/06-导入导出测试清单.md` 验证通过 | 否 |
| BLOCK-007 | 审计落地：共享事实底稿定义的审计事件类型（`LOGIN`/`LOGOUT`/`PERMISSION_DENIED`/`PERMISSION_CHANGE`/`EXPORT`/`DOWNLOAD`/`UPLOAD`/`APPROVAL`/`SENSITIVE_VIEW`/`SESSION_EXPIRED`）当前仅有前端安全基线设计（`frontend/src/security/`），服务端未真实记录任何审计日志 | 后端开发，审计需贯穿所有涉及敏感操作的接口 | 1）服务端对上述全部审计事件类型完成真实日志记录（含操作人、时间、`tenant_id`、`traceId` 等关键字段）；2）导出、敏感信息查看（`SENSITIVE_VIEW`）、权限变更等高风险操作的审计记录可被查询（对应权限点 `student.audit.view`/`security.export.list` 等相关模块的审计查看能力）；3）审计日志具备不可篡改性的基本保障（具体存储与保护方案待后端确认） | 否 |
| BLOCK-008 | 安全测评/等保定级（视客户要求）：`docs/security/00-等保三级安全基线总册.md` 是安全基线**设计**文档，当前系统未做过任何正式的安全测评或等保定级测评 | 项目管理者 + 客户方共同决策是否需要、以及测评范围 | 1）与客户方确认是否有等保三级（或其他等级）合规硬性要求；2）若需要，选择有资质的测评机构，在 BLOCK-001~BLOCK-007 完成、系统具备真实鉴权与安全能力后启动正式测评；3）测评通过并取得对应等级证明文件 | 否（该项本身不影响演示，但若客户方明确要求测评作为合同交付条件，则视为上线阻断） |
