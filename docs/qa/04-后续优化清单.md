# 后续优化清单

- **文档性质**：非阻断优化项清单（产品路线图输入）
- **适用端**：PC 管理端（`frontend/`）+ miniapp（`miniapp/`）
- **依据**：
  - 共享事实底稿 `_shared_brief.md`
  - `docs/rbac/`（RBAC 权限与数据范围矩阵，涉及角色/入口类优化引用其口径）
  - `docs/backend-integration/`（部分优化项依赖后端能力，具体实施顺序以其为准）
- **当前阶段声明**：本清单登记的是**非阻断**的功能/体验优化项，即使不处理也不影响系统上线（上线阻断项参见 `03-上线前阻断项清单.md`）。这些优化项建立在项目当前 mock 阶段（PC 端 UI 母版对接中、miniapp 纯 mock 可演示、后端未接入）的现状基础上，是对未来产品迭代方向的建议，不代表当前已排期或已承诺交付时间。
- **生成日期**：2026-07-04

---

## 一、说明

本表所列条目均为"有价值但不紧急"的优化方向，字段设计区别于其他三张台账，采用**编号 / 优化项 / 价值 / 建议优先级 / 建议时间**五列结构，便于产品侧直接用于路线图排期讨论。

建议优先级分档：**高**（对客户签单/续约有明显帮助，建议纳入近期迭代）、**中**（提升体验但非核心卖点，视资源排期）、**低**（长期方向性优化，暂不紧急）。

---

## 二、后续优化清单（OPT-xxx）

| 编号 | 优化项 | 价值 | 建议优先级 | 建议时间 |
|---|---|---|---|---|
| OPT-001 | 补齐更多完整独立表单页：将当前以弹窗/简化交互呈现的复杂业务场景（如学生主档信息变更、迎新材料补充、毕业设计材料提交等，具体范围以 `docs/testing/02-PC管理端测试清单.md` 逐页核对结果为准）改造为完整的独立表单页，支持分步骤填写、草稿保存、多文件上传等复杂交互 | 提升长表单/多步骤业务场景的录入体验与专业度，减少弹窗承载复杂逻辑带来的体验局限 | 中 | UI 母版对接阶段之后 / 后端接入同步推进 |
| OPT-002 | 家长授权与知情入口：当前学生模块已有 `student.guardian.view`/`student.guardian.update` 权限点定义，但尚未见对应的家长端查看/授权独立入口或流程；补齐家长在关键节点（如实习安全告知、请假审批知情、就业去向确认等）的授权/知情能力 | 覆盖"学生-学校-家长"三方协同场景，是本科/高职院校在学生安全管理、家校共育方面的常见诉求，有助于差异化竞争 | 中 | 需求确认后排期，建议先明确家长端承载形式（独立小程序端 / 短信通知 / H5 轻量页面） |
| OPT-003 | 企业导师入口深化：共享事实底稿已定义企业导师角色（PC 端 `ENTERPRISE_MENTOR`，范围 ASSIGNED，仅授权实习学生评价确认；miniapp 暂未见独立企业导师身份）当前权限口径已就绪，但企业端实际的独立登录入口、工作台页面（`/api/v1/enterprise-portal/*` 已在 API 前缀规划中标注"后期"）尚需完整实现 | 打通企业导师参与实习评价、实习过程协同的完整闭环，是产教融合类院校客户的重要关注点 | 中 | 待 `/api/v1/enterprise-portal/*` 域排期，建议在核心后端接入完成后跟进 |
| OPT-004 | miniapp 订阅消息推送：当前 miniapp 学生端/教师端均为纯 mock，尚未接入微信小程序订阅消息能力（如审批结果通知、实习周报待提交提醒、风险预警推送等） | 提升关键流程（审批、待办、预警）的触达效率，减少学生/教师需主动打开小程序才能看到消息的体验断点 | 高 | 建议在后端消息中心接口就绪后、小程序真机联调阶段一并接入 |
| OPT-005 | 可视化流程设计器：当前审批流模板（岗位实习申请审批流、实习周报批阅流、毕业设计材料审阅流等）以预置模板形式存在（`workflow.mock.js` processTemplates），尚无面向学校管理员的可视化流程配置/设计界面 | 支持不同院校按自身管理规范自定义审批流程，提升平台的可配置性与多校适配能力，是 SaaS 产品规模化复制的关键能力 | 中 | 建议作为后端工作流引擎接入之后的中期规划项 |
| OPT-006 | 数据驾驶舱指标扩展：当前数据驾驶舱（`dataCenter` 模块）指标为 mock 演示数据，覆盖维度有限；可结合各院校实际管理关注点（如就业率趋势、实习覆盖率、风险学生分布、毕业设计进度等）扩展更多维度的可视化指标 | 数据驾驶舱是管理层最直观感知平台价值的入口，指标丰富度直接影响续约与口碑 | 高 | 建议在后端数据接口就绪、具备真实统计数据后逐步扩展 |
| OPT-007 | 性能优化（大数据量场景）：当前系统性能表现基于 mock 小规模数据，尚未针对真实生产规模（如数千至数万学生的院校）做列表分页、检索、批量操作等场景的性能优化 | 保障中大型院校客户在真实数据规模下的流畅使用体验，避免因性能问题影响客户满意度 | 高（一旦后端接入且客户规模较大，应尽快跟进） | 后端接入并具备真实数据规模后 |
| OPT-008 | 无障碍与响应式细节完善：当前 PC 端处于 UI 母版对接阶段，无障碍访问（如键盘导航、屏幕阅读器兼容、色彩对比度）与不同分辨率/窗口尺寸下的响应式细节尚未系统性验证与优化 | 提升产品的合规性（如政府/教育行业采购中可能涉及的无障碍要求）与在不同办公环境设备上的适配体验 | 低 | UI 母版对接完成后的体验打磨阶段 |
| OPT-009 | 国际化与多校品牌深化：当前品牌配置（`config/brand.config.js` tenantBrandConfig）已支持平台名称、学校名称、主色等基础租户品牌化能力（示例：platformName「高校学生全生命周期管理平台」，schoolName「示范高校」占位，主色 `#2563EB`），但尚未支持多语言国际化，品牌深度定制（如 Logo、多套配色方案、自定义域名等）能力也较基础 | 提升多校规模化交付时的品牌一致性与院校自身识别度需求，国际化则面向未来可能的中外合作办学类院校场景 | 低 | 长期方向性优化，视客户群体拓展需要排期 |
| OPT-010 | 小程序真机体验与交互细节打磨：在完成 BLOCK-005（文件服务）、后端真实接口接入后，针对微信小程序真机环境（不同机型、不同微信版本）做交互细节（如加载态、下拉刷新、分享卡片样式等）的专项体验优化 | 提升小程序渠道的用户体验一致性，降低真机环境下的体验风险 | 中 | 后端接口接入、真机联调启动之后 |

## 三、与其他文档的关系

- 本清单中标注"待需求确认"“待排期"的条目，最终优先级与时间表需结合产品路线图与客户实际反馈确定，本文档仅提供质量与风险视角的建议，不代表产品最终决策。
- 涉及角色/权限相关的优化项（如 OPT-002 家长授权、OPT-003 企业导师），其权限点与数据范围定义以共享事实底稿第 3 节与 `docs/rbac/` 为准。
- 涉及后端能力的优化项（如 OPT-004 订阅消息、OPT-006 驾驶舱指标扩展、OPT-007 性能优化），其具体后端实现顺序以 `docs/backend-integration/` 为准。
