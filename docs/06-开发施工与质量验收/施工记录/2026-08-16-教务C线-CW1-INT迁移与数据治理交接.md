# 教务 C-W1 → INT：Attendance 正式课次 / 特殊补录迁移与数据治理交接

> C 分支：`agent/academic-c-teaching-execution`  
> 原则：C 不抢 `backend/alembic/versions/**`、公共注册/权限；本文只冻结 INT 后续迁移与数据治理输入，不在 C 线制造第二 Authority。

## 1. 当前代码事实

`AaAttendanceSession` 当前只有行政班、课程展示名、学期代码、教师、日期、节次、`session_type`、名单 JSON/统计/状态等字段；没有：

- `teaching_task_id`
- 正式 `occurrence_identity`
- `source_type`
- `source_reason`
- `source_evidence`
- 同一正式课次唯一约束

C-W1 已在应用层把新写入口 fail-closed：

- 普通教师只能 TeachingTask-first；
- 普通教师永远不能创建 `ADMIN_SPECIAL`；
- 管理员无 TeachingTask 必须显式 `ADMIN_SPECIAL`；
- `ADMIN_SPECIAL` 必须 reason ≥ 5 字 + evidence；
- 关联 TeachingTask 时仍冻结正式 RosterConsumerSnapshot；
- 默认课堂统计与标准旷课预警排除 `ADMIN_SPECIAL`；
- PC / 教师小程序只显示来源，不给普通教师增加特殊补录入口。

## 2. Published Occurrence 依赖

C 不自行定义正式课次 Authority。B-C1 Published Schedule Contract 已冻结并被 C-W1 正式消费。

当前普通课堂 occurrence 解析固定为：

`term + ScopeHead active batch + TeachingTask + EFFECTIVE ScheduleItem + APPLIED ScheduleChange + calendar/week/parity`

C-W1 已落实以下 fail-closed 语义：

- 只认当前 `ScopeHead.active_batch_id` 指向的 `PUBLISHED` 批次，不回退历史 EFFECTIVE 行；
- SCHOOL / COLLEGE ScopeHead 指向同一 active batch 时按同一 Authority 去重；同一 TeachingTask 同时落入不同 current active batch 时视为冲突；
- 只认 `EFFECTIVE ScheduleItem`；调课旧 `CHANGED` occurrence 拒绝；
- 带 `change_id` 的新课次必须回链同租户 `AaScheduleChange(status=APPLIED)`，且 `new_item_id / task_id / batch_id` 一致；
- `HOLIDAY` 拒绝普通点名；`SWAP` 原停课日拒绝，补课日映射到原教学日计算 week/weekday；
- `ODD / EVEN / ALL` 周次规则在服务端实时判定；
- 客户端可携带 `scheduleItemId` 作为 optimistic occurrence identity；实时 resolver 命中不同 item 时返回 409，不静默漂移。

任何历史治理/迁移都不得用课程名、行政班、教师名或裸 `日期+节次` 自由拼接替代上述正式课次 Authority。

## 3. INT migration 候选约束

仅在 B-C1 正式合同冻结后，INT 评估以下最小字段/约束；字段名以最终 exact-head 模型命名为准：

1. `teaching_task_id`：普通课堂必须有；ADMIN_SPECIAL 可空。
2. `occurrence_identity`：普通课堂必须有，来自 B-C1 canonical provider；ADMIN_SPECIAL 可空。
3. `source_type`：至少区分 `FORMAL_TEACHING / ADMIN_SPECIAL`。
4. `source_reason`：ADMIN_SPECIAL 必填；普通课堂默认空。
5. `source_evidence`：ADMIN_SPECIAL 必须有可审计证据引用/快照；避免把任意自由文本当文件 Authority。
6. 普通课堂唯一性：同租户 + canonical occurrence identity 只能有一个有效考勤场次；并发重复创建只能单赢家或幂等命中同一事实。当前 C-W1 应用层已在持有正式课次 Authority 锁后，对 `tenant + class + teacher + actual sessionDate + slot` 做 current locking read，MySQL 并发合同已证明单赢家；这只是 DB UNIQUE 落地前的应用层保护，**不得替代最终数据库约束**。
7. occurrence 冻结建议同时保存/可追溯以下证据：`scheduleItemId`、`teachingTaskId`、`activeBatchId`、`scopeType/scopeId/scopeHeadVersion`、actual `sessionDate`、calendar logical date、`calendarSource/calendarEventId`、`weekNo/weekday/slotNo/weekParity`、`changeId/changeType/changeAppliedAt`。
8. 归档/软删语义必须与现有 archive guard 一致，禁止通过删除旧行再重建来绕唯一性历史。

## 4. Legacy ADMIN_MANUAL inventory

历史 public attendance create 曾在 `AffairsAuditTrail` 的 `AA_ATTENDANCE / CREATE / detail` 中记录 `source=ADMIN_MANUAL`。

因此 backfill 顺序必须是：

1. inventory：按 `biz_type=AA_ATTENDANCE + action=CREATE + detail contains source=ADMIN_MANUAL` 找历史候选；
2. 将 audit `biz_id` 回连 `AaAttendanceSession.id`；
3. 分租户/学期输出数量与无法回连清单；
4. 能证明来源的候选回填 `source_type=ADMIN_SPECIAL`；
5. reason/evidence 不足的历史行标治理债务，**不得凭猜测补内容**；
6. backfill 前后做总数、状态、统计/预警差异对账；
7. 只有 dirty-data 清零或明确隔离后，才收紧 DB NOT NULL / CHECK / UNIQUE。

## 5. 并发与 MySQL Gate

C-W1 已完成的应用层/MySQL 证据：

- 同一正式 occurrence 双事务并发创建 → current locking read 单赢家，另一请求 409；
- 调停课新 occurrence 必须 `APPLIED` 且 change→item 回链一致；旧 `CHANGED` occurrence 不可继续创建；
- stale `scheduleItemId` 与实时 resolver 命中不一致 → 409，并返回 expected/resolved item evidence；
- ADMIN_SPECIAL 仍是独立审计来源，不占用正式 occurrence duplicate guard；
- Roster 继续消费 versioned TeachingRoster 并冻结 `RosterConsumerSnapshot`。

INT 落数据库约束时仍必须补齐/重放：

- canonical `occurrence_identity` 的 tenant-scoped UNIQUE / active-fact 约束；
- duplicate retry 明确选择幂等命中还是稳定 409，不能泄漏随机 500/IntegrityError；
- 与 Roster 换版、Schedule publish/change finalizer 的锁序/死锁回归；
- dirty-data/backfill 后再收紧 NOT NULL/CHECK/UNIQUE，禁止迁移脚本静默删重。

## 6. 禁止项

- C 分支自己新 Alembic revision；
- 课程名/教师名/行政班名充当 occurrence identity；
- 把 `AffairsAuditTrail.detail` 永久当 source Authority；
- 为 ADMIN_SPECIAL 新建第二套 Attendance 模型；
- 用 SQLite 代替 MySQL 并发验收；
- 因历史数据难治理而恢复管理员无 Task 普通课堂旁路。

## 7. INT 接收条件

INT 真正施工前必须同时具备：

- B-C1 Published Schedule Contract = FROZEN（当前已满足）；
- C-C1 Attendance Consumer Contract = FROZEN 后再由 INT 接手 schema 落地；
- exact-head collision audit 已确认 PR #96/#132/#133 与迁移头；
- legacy inventory 可重复执行；
- upgrade/downgrade/backfill/rollback 策略齐全。
