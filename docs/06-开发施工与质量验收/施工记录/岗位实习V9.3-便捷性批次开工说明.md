## 1. 批次一：前端便捷性四项（主体工作）

### 1.1 U15 冲突提示保留输入 —— 先做这个

**为什么排第一**：上一批给巡访计划、投诉、企业考察加了并发保护，两人撞车时后端现在返回 409。**但前端如果只弹个错误框，老师刚敲的整段处理意见就没了**——后端更严谨了，体感反而更糟。这是上一批留下的直接欠账。

**要做成什么样**（总册 U15 原话：保留输入、刷新真值、重新确认）：
1. 收到 409（`code: 'DATA_CONFLICT'`）时，**不清空表单**，老师填的内容原样留着
2. 提示明确：「这条记录刚被其他人处理过，下面是最新状态，请确认后重新提交」
3. 拉一次最新数据展示，让老师**自己决定**是覆盖还是放弃
4. **禁止自动重放**老师的决定——不能偷偷替他再提交一次

**涉及页面**（后端已确认会返回 409）：
- `frontend/src/modules/internship/views/GuidanceVisitView.vue`（巡访计划状态迁移）

**已有参考**：`frontend/src/modules/internship/api/enterprise-eval.api.js:37` 有 `DATA_CONFLICT` 的抛出写法可参考。

## 3. 纪律（这几条是踩出来的，别省）

1. **测试先证明会红，再证明变绿**。顺序反了就是给自己发合格证。上一批一夜栽了三次假绿：撤销脚本静默没匹配、只撤一半修复、并发测试只同步线程起跑。
2. **反证要撤到真正原始实现**：`git show HEAD:<path> > <file>`，别手工挑着撤。撤销脚本必须带 `assert old in s, "PATTERN NOT FOUND"`。
3. **加 DB 约束必须 ORM 与迁移双写**：测试夹具用 `create_all` 建库不跑 alembic，只写迁移的约束在测试库不存在。
4. **约束生效 ≠ 错误码正确**：`db.add(); db.flush()` 这步 INSERT 就发出了，唯一约束在 flush 时就拒绝——只包 `commit` 的话输家照样拿 500。
5. **前端改完要真机验**（Browser 面板跑起来点一遍），不能只看代码对。便捷性这批尤其如此：它的全部价值就在体感上。
