## 1. 业务 outbox 清干净

### 结论
业务服务侧已不再直接 `UnifiedMessage(...)` 入库（除投递/Outbox 消费、沙箱种子）。

### 证据
- 仓库检索 `UnifiedMessage(` 仅命中：
  - `message_event_outbox_service.py`（消费写个人消息）
  - `message_delivery_service.py`（campaign 投递）
  - `sandbox_service.py`（演示种子）
  - 模型定义与注释
- `_msg` 在资助/困难认定/处分/风险/学籍变更/调停课等改为 `emit_receiver_notice` / `emit_message_event`
- 业务 commit 后调用 `try_process_pending_outbox` 尽力同步消费；失败由 `run_scheduled_jobs` 重试
- [Outbox-ify remaining _msg writes](baa703d6-0eac-4f8f-8fbe-546140b4eb6a) 已完成 12 个业务服务迁移；父任务又为教务学籍/调停课/成绩/课表发布、实习周报提醒补了 commit 后 inline drain

## 2. 深链 / 频控 / 静默

| 能力 | 落点 | 行为 |
|---|---|---|
| 深链白名单 | `message_action_registry.py` | 未登记 key → `MESSAGE_ACTION_NOT_ALLOWED`；缺参 → 422 |
| 注册表 API | `GET /admin/message-campaigns/action-keys` | 发布页下拉、收件「去办理」取 PC 路由 |
| 发布频控 | `assert_publish_rate` @ `publish_campaign` | 同发布人 60 分钟 ≤ 20 次，超限 429 |
| 静默时段 | `apply_quiet_hours_policy` | 普通 22:00–07:00(UTC+8) 顺延；紧急可绕过并写备注 |
| 设置页展示 | `message_meta_service.channel_settings` | 展示 quietHours + rateLimit |
| 小程序详情 | `GET /mobile/me/messages/{id}` | 按 messageId 重拉，杀进程可重开 |
