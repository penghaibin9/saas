## 0. 两处自我纠正（用户当面追问后发现，如实记录）

**A. 三家成熟系统对标：未达标，非"已完成"。** 本轮 12 个模块开发前，并未按 CLAUDE.md §0.0
输出真正的"三家成熟系统对标表"。实际做法是复用仓库内已有的**同一个**老系统（`99-老毕业设计系统`，
基于湖南石化职院真实采购项目）的反向建模文档（`source-design/05-...V1.0.md` +
`docs/02-商业化交付/16-...md`），环境无法联网，未能再独立引入第 2、第 3 个系统的对标数据。
这满足"无法联网时改用仓库已有资料"的兜底条款，但**不满足"三家"的字面要求**，此前的报告版本
未清楚说明这一点，属于表述不准确，现予更正。

**B. 一次真实的验证失误：`test_graduation_taskbook.py::test_confirm_advances_student_stage_to_guiding`
曾被误报为通过。** 该测试与导师管理测试联合运行时，命令用了 `| tail -60` 管道，导致工具返回的
"completed / exit code 0" 实际是 `tail` 的退出码，掩盖了 pytest 自身的失败退出码（真实结果是
"1 failed, 8 passed"）。本报告曾据此错误宣称"导师+任务书测试全部通过"。全量回归跑完后原样暴露
了这个失败，现已定位根因并修复：
- **根因**：测试的 `_gd_student_with_mentor` 辅助函数只分配了导师，没有分配选题；而
  `t_gd_student.stage` 从 `TOPIC_SELECTING` 推进到 `TASKBOOK_CONFIRM` 的唯一触发点是**选题确认**
  （`graduation_student_service.assign_topic`），不是导师分配——这是既有代码的正确行为，是测试
  的前置条件搭建错了，不是服务逻辑的 bug。
- **修复**：新增 `_gd_student_with_topic_and_mentor` 辅助函数（先建题目→审核通过→分配选题→
  再分配导师），让该测试真正满足"已到达 TASKBOOK_CONFIRM 阶段"的前置条件后再验证确认任务书能
  推进到 GUIDING。修复后单独重跑 `test_graduation_taskbook.py`：**4 passed**（真实检查 exit code，
  非管道掩盖）。
- **教训**：本轮之后所有"是否通过"的判断，一律用 `echo $?` 或 `run_in_background` 的原生退出码
  确认，不再通过管道（`| tail`）间接推断，避免同类误报。

## 1. 毕业设计中心完整业务流程

主状态机（学生维度，贯穿全模块）：

```
未启动 → 选题中(TOPIC_SELECTING) → 任务书确认(TASKBOOK_CONFIRM) → 指导中(GUIDING)
→ 中期检查(MIDTERM) → 成果检查(FINAL_CHECK) → 答辩中(DEFENSE) → 已完成 → 已归档(ARCHIVED)
```

各阶段承接的业务闭环（本次报告新增部分用 ★ 标出）：

1. 批次启动 → 2. 题目申报/审核 → 3. 学生志愿/匹配/教师确认 → 4. ★导师分配（或选题即绑定导师）
→ 5. ★任务书下达/确认/变更 → 6. 开题材料提交/审核 → 7. ★指导过程记录（频次统计预警）
→ 8. ★中期检查（三档结论+整改闭环）→ 9. 成果提交（论文定稿）→ 10. ★查重记录（复查申请）
→ 11. ★教师评阅（SoD 独立评阅人）→ 12. 答辩安排（分组/排期）→ 13. ★答辩评分（多评委+二次答辩）
→ 14. ★成绩评定（三段加权核算→复核→发布→撤回）→ 15. ★毕设归档（材料自动核验清单）
→ 16. ★问题预警（全流程风险扫描处置）→ 17. ★毕设统计（跨模块聚合看板）

## 2. 三家成熟系统对标结论（沿用既有 source-design 文档的对标资产）

本轮 12 个新模块未重新做外部联网调研（环境不可联网），而是复用 `docs/source-design/05-毕业设计中心

11 张业务表、8 个 API 域、16 个页面，并提炼了"三家成熟系统共同具备的核心能力"结论：

- **导师确认制**：课题 0/1/2 确认流（老系统字段级证据），本轮"导师分配"在此基础上补齐了

- **成果四类型独立版本计数、已通过不可修改、驳回必带原因**：已在既有"开题材料/成果提交"落地，
  本轮"教师评阅"补齐了独立评阅角色的 SoD（老系统由指导教师兼任评阅，源文档 §16A 标注"新系统升级为
  独立评阅"）。
- **三段成绩构成（导师/评阅/答辩）**：老系统 `gdGradeModel` 字段级证据，本轮"成绩评定"按批次

  必备材料清单"（比老系统的人工清单更进一步）。
- **毕业资格联动、批次总控、问题预警**：source-design §16C 明确标注"老系统未发现明确实现，新系统
  必须补齐"——本轮"问题预警"（GD-R01~R13 部分落地）与"毕设归档"→"毕业资格"标记位即补齐此空白。
