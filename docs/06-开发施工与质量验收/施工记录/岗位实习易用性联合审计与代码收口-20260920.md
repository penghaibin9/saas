## 2. 复核结论

旧 V8 诊断中下列问题已经在当前 main 被修复，本轮不重复施工：

1. 学生小程序“十几个入口同权重”已改为“当前必须做 / 今天 / 当前阶段服务 / 更多服务”。
2. 教师小程序静态快捷入口已放到“待我处理 / 需要关注”之后，常用服务最多 6 个且可编辑。
3. PC 周报已具备重交前后对比、409 冲突保留评语、操作回执与连续批阅。
4. W17 已有 20K、MySQL、浏览器 Golden Journey 与能力保留证据，本轮不做性能重构。

当前仍成立且适合低风险直接修改的问题：

- PC 宽权限岗位实习日常侧栏仍有 35 个可见叶子，其中多项只是同一工作台的筛选、辅助入口或低频审计入口。
- 教师小程序首页能显示当前实习批次，但已有 `internshipContext.selectBatch()` 未接到首页，切批次只能进入下级业务页。
- 学生小程序批次选择卡暴露内部 `recordId`，且底部固定“写周报 + 去打卡”与上方合规下一步重复竞争主动作。

仍成立、但不在本轮直接改后端的问题：

- Staff Today Work 当前权威对象主要来自 RiskRecord / AttendanceException / WeeklyReport；资格、协议、保险、上岗等仍靠阶段入口办理。
- PC 连续办理使用 `sessionStorage`，教师小程序使用自己的移动队列；跨设备没有统一 resume cursor。

这两项需要后端权威投影与跨端持久化设计，不应混入本轮纯前端降噪提交。

### 3.2 教师微信首页批次切换

文件：`miniapp/src/pages/teacher/workbench/index.vue`

复用既有 `useInternshipContextStore()`：

- 当前角色为 `intern_mentor` 且有多个可用批次时，首页当前批次卡显示“切换批次”。
- 选择后只调用既有 `context.selectBatch(batch.id)`，不新增本地批次事实。
- 清理当前工作台缓存签名并重新读取工作台，后续实习服务页面继续消费同一 store 的 `selectedBatchId`。
- 无第二批次时不出现切换控件。

### 3.3 学生微信唯一主动作

文件：`miniapp/src/pages/student-internship/index.vue`

- 删除候选批次卡上的内部 `recordId` 展示。
- 移除上方重复的独立 `compliance.nextAction` 按钮。
- 底部 SafeArea 只保留一个 `primaryAction`，优先级固定为：
  1. 服务端返回的 `compliance.nextAction`
  2. 未打卡 → 立即打卡
  3. 已打卡但周报未交 → 填写本周周报
  4. 当天均完成 → 只读“今天的实习任务已完成”
- 历史批次不产生可写主动作。
