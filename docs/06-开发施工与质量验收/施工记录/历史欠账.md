## B 类欠账关闭：alembic 迁移实库执行



- **根因定位**：Alembic 默认 `alembic_version.version_num` 为 `VARCHAR(32)`，而本项目存在 33 字符的 revision id（`0010_13b_p2_status_change_program`），导致 `UPDATE version_num` 触发 MySQL 1406 Data too long，**全链在 0010 处中断**——这是全项目级迁移阻断，不止岗位实习。

- **修复**：`backend/alembic/env.py` 的 `run_migrations_online` 增加 `_ensure_wide_version_table`：在【独立且显式 commit 的连接】上 `CREATE TABLE IF NOT EXISTS` + `ALTER MODIFY version_num VARCHAR(255)`，兼顾全新库与既有库，仅 MySQL 生效。（注意：必须独立连接显式提交，否则遗留未提交事务会让 SA 2.0 关闭连接时回滚 alembic 的 version 戳。）

- **证据**：清空测试库后 `alembic upgrade head` 从零 **29→30 条迁移全部应用，最终 stamp=0030_internship_leave**；dev 库 `student_lifecycle_dev` 已补齐 makeup/guidance/visit/leave 表并 `alembic upgrade head` 到 0030，version_num 加宽为 255。**结论：迁移已可在真实 MySQL 从零部署，B 类关闭。**

- 说明：dev 库历史由 create_all 建表并 stamp 至 0009，本轮已 reconcile；旧库全量迁移路径（0010→0026 各历史迁移对 create_all 既有表的幂等性）仍建议在正式上线前用一次「全新库 alembic 建库」作为标准部署路径（本轮已在测试库验证通过）。
