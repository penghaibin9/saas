# 岗位实习阶段 3：人岗确定审计

日期：2026-09-06。工作区：`职校学生全生命周期系统-internship-ui-20260905`；分支：`codex/internship-ui-refactor-20260905`；叠加阶段 1、2 的本地改动，阶段 2 的实际页面复验缺口已在对应记录中纠正。当前状态：学校正式志愿查询、教师 PC 队列、详情深链及确认/退回动作已接通；通知、移动办理和四端整链仍未完成，阶段 3 尚未闭环。阶段 4～9 不同时施工。

模块目标是形成真实的人岗关系：学生通过公开岗位志愿或自主实习分支发起，企业在授权范围内处理报名，学校完成退回修订或最终确认，并把学生、批次、企业、岗位、校内指导教师和企业导师关系落在同一实习记录与不可变快照中。结果只表示人岗已确定，不等于协议、保险和上岗条件已通过。

## 设计与施工顺序

阶段 3 内部按真实依赖连续推进：

1. **公开选岗确认闭环：** 先审计当前学生 PC/H5 志愿、企业候选页和教师旧申请页的实际画面；补学校 canonical 队列、详情、退回/解锁、最终确认和结果通知；跑同一学生/岗位/企业的完整链路。
2. **自主实习闭环：** 保留 campaign-null 记录和历史兼容，把学生入口明确成自主实习；核验材料真实绑定、退回补正、重提、审核与结果；不得由学校按钮冒充企业本人确认。
3. **补充匹配与导师分配：** 将旧意向/推荐/手动/批量匹配限定为学校补充安排，统一确认到 assign + snapshot；把校内指导教师和企业导师关系作为人岗完成检查，补改派与冲突恢复。
4. **四端与企业协同收口：** 学生 PC/H5、教师 PC/H5、企业端使用同一安全测试记录；验证通知深链、返回上下文、历史版本、跨租户/跨范围、重复与并发、窗口关闭和名额竞争。阶段 3 完成后才进入协议、保险与上岗核验。

## 学校正式志愿查询落地（2026-09-06）

新增 `internship_school_volunteer_service.py`，只投影 canonical group/application/snapshot/decision，不复制志愿真值、不调用旧申请审核服务。教师 PC 可通过 `/internship/recruitment-campaigns/{campaignId}/volunteer-groups` 及其 `/{groupId}` 读取；教师移动端通过 `/mobile/teacher/internship/context/volunteer-groups` 及其详情复用同一服务，必须携带匹配的 campaignId、batchId，接入现有 `internship.application.view` 权限及移动权限表。

列表先在 SQL 层限制教师指导范围，再统计及分页。默认只看 SUBMITTED/LOCKED，学生解锁申请、锁定截止优先；支持状态与学生姓名/学号搜索，搜索中的 `%`/`_` 按文字处理。详情同时核验租户、招聘季、批次、学生和实习记录，返回本次公共材料快照、每个志愿申请版本、当前企业决定和分开的决定历史。旧 `campaign_id IS NULL` 的校内岗位申请不会混入三志愿；上一版材料的拟接收不覆盖本次面试决定。读取超时锁只标记 `lockExpired`，不在 GET 中隐式改变业务状态。

验证：独立 MySQL checks 库执行 `test_internship_school_volunteers.py` 3 项及既有 `test_internship_volunteer_service.py` 14 项，共 **17 passed，118.50 秒**。覆盖实际 HTTP 读接口、SQL 范围与分页、当前/历史材料隔离、PC/移动同一组、移动批次必填和不匹配拒绝、学生/匿名拒绝、跨租户不可见、旧接口隔离契约。日志：`.codex-artifacts/internship-stage3-school-queue-tests.log`。第一轮仅因分页校验测试误写 FastAPI 默认 422 而失败，项目统一返回 400；断言修正后以上复跑通过。

本轮应用内浏览器实际查看学生 PC 选岗空状态：测试学生资格未通过且没有已发布岗位，不能将其作为有效投递链路证据。教师正式入口仍跳转登录，本轮未取得教师旧审核页有效业务截图。尚未做页面样式改动或把隔离组件当作真实办理验收；原管理员密码未写入代码或文档。

下一步仍属于阶段 3：

1. 完成教师正式登录/授权上下文定位并采集原审核页、企业候选页及教师/学生移动页面；据此施工任务队列与详情深链。

## 教师 PC 正式队列与详情深链（2026-09-06 续）

新增 `InternshipVolunteerReviewView.vue` 及 `school-volunteer.api.js`，导航位于申请与落岗 → 岗位确认。三级页为学生任务队列，四级页 `/admin/internship/volunteer-review/:groupId` 使用完整页面展示身份、志愿与企业处理、本次冻结材料和企业决定历史。批次、招聘季、状态、搜索与页码保留在 URL；材料/历史分区由 `section` 恢复，返回队列移除详情分区并保留筛选。切换批次清除旧招聘季、对象及分区，立即清空旧详情，迟到响应不能覆盖新对象。
