## 9. 规划状态判断标准（navPlan / 施工图统一口径）

| 状态 | 判断标准 | 菜单/搜索 | 文档写法 |
|---|---|---|---|
| `implemented` | 真实前端 + 真实后端 + MySQL 表 + 权限数据范围 + 审计 + 测试 + build 通过 + 验收用例通过 | 可挂正式菜单 | 可标 implemented |
| `partial` | 上述任一项缺失，或仍依赖 mock/旧页/外链主链路 | 可展示但须标待补或 partial | 必须写缺口与归属包 |
| `planned` | 仅有设计文档，无真实闭环代码 | hidden / backlog | 不得进入正式可点菜单 |
| `external-link` | 主能力在其它模块，学工只做入口/摘要/跳转 | 可展示外链或摘要卡 | 必须写承接系统路径 |
| `merged` | 多个三级入口合并为同一页面/路由的不同 Tab 或面板 | 菜单可合并展示 | 施工卡须写清面板/Tab 边界 |

硬规则：

1. 数字迎新 21 个三级入口不得全量标 `implemented`；当前只能 `external-link` + `partial`（D 包底座补强专项关闭欠账前）。
2. 在校服务只能 `external-link` / `partial`，不能标学工已完成。
3. 学生主档在画像中只能 `merged` 承接，学工不重复造主档页面。
4. 日期 / Excel / 导出确认 / 审计 / 水印等数字迎新公共底座欠账，只在 D 包「数字迎新公共底座补强专项」处理，B/C 包禁止顺手修 orientation。
