## 二、后端（academic_affairs_textbook_service.py，全链路）
- **目录**：CRUD，ISBN 唯一（重复 400）。
- **选用**：按教学任务申报（同 task 无未终结选用，重复 409），DRAFT→SUBMITTED，撤回（仅草稿）。
- **审核**：批次纳入 SUBMITTED 选用 → 逐级推进 DRAFT→COLLEGE_REVIEWING→COLLEGE_APPROVED→ACADEMIC_APPROVED→PUBLISHED（备案公示），PUBLISHED 时选用置 APPROVED；RETURN 退回（原因≥5字，选用回 RETURNED）。
- **征订**：从 APPROVED 选用**汇总合并**（同教材合并数量）生成征订明细，提交，**登记到货**（部分/全部到货状态联动 PARTIALLY_ARRIVED/ARRIVED），归档。
- **发放**：按班级+征订批次生成发放名单（自动排除非在籍学生 EXCLUDED），**签收 RECEIVED 自动生成费用台账应收**（幂等按 distribution_record 唯一）。
- **费用**：台账列表，标记已收 PAID / 减免 WAIVED（原因≥5字）。
- **统计**：选用/征订/到货率/欠费金额聚合。
- 复用：AaTeachingTask（选用挂载）/StudentProfile（发放名单）/AffairsAuditTrail（biz_type=AA_TEXTBOOK_*）/build_affairs_context（学院范围）。
- router：23 个 `/textbooks/*` 端点。权限 `academicAffairs.textbook.{catalog|selection|review|order|distribution|fee}.manage`/`.view`，由 ACADEMIC_TEACHER/COLLEGE_ADMIN/SCHOOL_ADMIN 的 `academicAffairs.*`/`*` 通配覆盖，**未新增 TEXTBOOK_ADMIN/OFFICER 角色**（施工卡确认通配覆盖，免 RBAC 改动）。

### 七个菜单的办理关系

| 菜单 | 负责事项 | 下一步与前提 |
| --- | --- | --- |
| 教材目录 | 学校维护名称、书号、版次、出版社、定价 | 教师从正式教学任务选择教材；未定价不能在编辑时自动变成免费 |
| 教材选用 | 关联教学任务，保存草稿、提交；退回后修改原申报再提交 | 学校按来源学院组建审核批次 |
| 审核备案 | 查看申报明细；学院初审，学校审核并备案 | 只有已备案选用才能生成征订；已备案或已征订不能再退回 |
| 征订到货 | 汇总已备案选用，提交征订，按教材登记累计到货 | 部分或全部到货后生成班级发放名单；已有名单从“发放签收记录”进入 |
| 教材库存 | 核对到货、待签收占用、已签收和可用库存 | 可用库存＝到货－待签收占用－已签收；不能把待签收占用当作仍可分配库存 |
| 费用台账 | 签收按征订价格快照生成应收，登记全额/部分收款或未实收减免 | 显示学生姓名、学号，并可返回发放来源；签收不等于已收款 |
| 教材统计 | 汇总选用、有效征订、到货、未结费用 | 取消征订不再计入有效征订量与到货率分母；明细链接进入对应业务页 |

发放签收继续作为征订流程的子工作区，不增加第八个主菜单。征订、库存和费用页面提供可见入口；支持当前学期/全部学期查询，保留历史发放记录的访问路径。

### 本轮确定并修复的问题

1. 审核“查看证据”只改变页面选中行，没有申报明细。新增按批次分页读取与抽屉展示，包含课程、书号、版本、出版社、需求人数、选用原因；后端验证本租户和来源学院范围。明细说明其为关联申报当前内容，不把退回后修订的内容当作原审核快照。
2. 审核同一责任层级重复点击。按用户决定变为两次审核；旧学院审核中、教务已通过节点仍可继续办理，已备案终态保持不可重复推进。
3. 征订单“打开”没有展示明细。接入正式征订明细，草稿/已到货/归档/取消状态只读，已征订/部分到货状态可登记；校验累计到货整数和上下限，成功后回读。
4. 已有发放批次入口缺失。补充“发放签收记录”和返回路径；费用台账可打开原发放批次并返回费用页。
5. 同一本教材关联多个选用时，行定位优先使用教材编号，可能选错申报。改为优先使用当前业务对象编号。
6. 费用接口缺姓名、学号和发放来源。增加同租户关联投影，学生资料缺失时仍保留费用历史；整校征订、库存、费用、统计读接口增加学校范围检查，不让学院身份读取全校台账。
7. 取消征订仍计入统计。有效批次数及征订/到货数量统一排除取消批次，并验证父批次租户和删除状态。
8. 选用下拉只取前200本。改为按接口总数继续分页读取；清除旧目录、忽略迟到响应，读取失败不沿用上次目录。
9. 未定价目录被编辑页面转换为0元。保留空价格；公开目录接口拒绝负数、非有限金额和超过两位小数的金额。
10. 到货登记与发放的加锁顺序相反。到货登记调整为先锁征订单、再重读并锁明细，汇总前刷新本次修改；实际数据库并发仍待验证。
11. 组审核批次、审核推进、生成征订、生成发放名单采用60秒请求时限，减少大批次尚未返回就被前端4秒默认超时误判的问题；不把延长时限当作性能验收。
12. 非目录页面只做本页筛选时，不再把原第三页数据标成第一页。目录查询继续使用服务端筛选。

## 十一、历史征订来源与费用权限静态复核

- 同一选用来源若同时关联其他未取消、未删除的有效征订批次，取消征订和生成发放名单均拒绝办理；已取消批次的历史来源保留，不阻止后续正常重新征订。单个征订批次中来源记录重复也拒绝生成发放名单。
- 教材发放工作台按实际费用管理权限裁剪金额：无费用管理权限的发放人员只看必要的费用办理状态及归属冲突提示，接口不返回应收、已收或退款金额，也不查询退款金额；有权限时继续返回明细。
- 整校教材统计根据费用权限决定是否查询和返回未结金额、累计退款和退款待退领条数；没有权限的页面显示“无费用查看权限”，不将缺失数据展示为零。发放详情的费用台账入口同样按权限显示。费用权限仍须结合学校数据范围，未扩大岗位权限。
- 静态验证：教材后端隔离检查28项、管理端教材行为检查36项通过，受影响页面代码规范检查通过；包含跨有效征订单重复来源、取消来源保留、无费用权限时不查询/不返回金额的正反向检查。
- 本轮未启动服务、执行迁移或修改沙箱；未进行隔离 MySQL 并发、迁移和真实角色页面回读。缺失或已损坏的历史来源无法仅凭静态检查确定，仍须先核对原始事实，不能自动补造。

## 十二、退款与历史发放链静态续审

- 学生本人签收在锁定发放记录后重新核对学生归属；锁定前的预览不能作为最终授权。缺少征订价格快照、价格/数量无效或金额超出费用表范围时阻断签收，不把未知价格当作免费。
- 已签收历史记录缺费用台账时，不自动补造费用；待签收记录已有费用、既有费用学生或金额与发放记录不一致时阻断。正常首次签收及一致的重复签收保留原行为。
- 费用登记仅允许合理的费用状态、金额及已签收记录；退款和退领遇到空金额时不再当作零。目录定价接口的最大位数与现有数据库列一致，避免提交后才发生数据库金额溢出。
- 已退领记录的重复请求须重新核对费用及退款流水；历史退领与费用不一致时明确报冲突，不伪装成功或自动修改历史。
- 教材后端隔离检查38项及管理端教材行为检查36项通过，覆盖正常签收、重复签收、本人归属变化、缺价格、缺费用、异常费用状态、退款/退领重试等；未连接数据库。重复签收同样检查已有费用状态与退款流水，异常时不伪装成功。
- 本轮未启动服务、执行迁移或修改沙箱数据；未验证 MySQL 实际加锁/并发、迁移及真实角色页面回读。
