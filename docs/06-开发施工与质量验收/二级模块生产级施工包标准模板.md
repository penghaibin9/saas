### 2.1 外部证据门禁

- [ ] A/B/C 为三个不同成熟系统；
- [ ] 每个系统都有实际打开核验的 URL、资料标题和发布方；
- [ ] 每个系统都有当前模块能力证据和高校真实采用证据；
- [ ] 关键结论能定位到具体页面、章节或页码；
- [ ] 厂商宣传与学校真实使用资料已区分；
- [ ] 搜索摘要、博客或 AI 经验没有被冒充为产品事实；
- [ ] 无法核验的内容已经标记“未验证”，没有进入正式施工范围。

任一项不满足，施工包状态只能为 `draft / blocked`，不得进入代码施工。

## 17. 设计就绪门禁

- [ ] 三家外部对标证据真实可核验；
- [ ] 全部三级模块已逐项设计；
- [ ] 每个三级模块均有独立施工卡且通过三级卡设计就绪门禁；
- [ ] 主流程、异常流程和状态机完整；
- [ ] 数据、API、权限、业务关系、敏感字段和审计完整；
- [ ] 测试、部署、升级和回滚完整；
- [ ] 每项正式设计都有来源；
- [ ] 未验证内容未冒充事实；
- [ ] 可从仓库查明的技术事实没有写成“需人工确认”；
- [ ] 关键冲突和需甲方确认事项已处理。

全部通过后将状态改为 `design_ready`，并在同一次任务中继续施工；不得只交施工包后停止。

## 19. 施工完成证据与最终闸门

施工后回填：修改文件、迁移、API、权限实现、测试结果、build/lint、smoke、部署证据、遗留问题、回滚方式、`git status --short`。

只有全部三级模块真实可用且前后端、MySQL、权限、审计、测试和部署检查闭环，才能标记 `verified / implemented`。否则必须标记 `partial` 并逐项记账。
