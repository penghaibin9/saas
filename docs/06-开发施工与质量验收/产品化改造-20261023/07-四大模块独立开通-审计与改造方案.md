## 一句话版本（给新手看）

**做法是对的，而且底子比想象中好。** 四个模块之间几乎没有直接互相调用，"一套底座 + 四个可开关模块"的骨架代码里已经有了：后端有统一的模块门禁，PC 菜单和学生手机端会按授权隐藏，运营端也已经能按模块建商品、下分项订单。

**但现在还不能放心地"只卖实习"给一所学校。** 差在三类事：

1. 有几处"底座"功能其实藏在学工或教务里（比如给班级设辅导员），只买实习的学校会卡住；
2. 首页、数据看板、待办、教师手机工作台这些"汇总页"不看授权，只买实习的学校会看到课表、毕设通过率这些空卡片；
3. 运营端新旧两套授权并存：老套餐是"按规模分档、全模块都开"，新的"按模块售卖"做到 9 月上旬的 M3 就停了，单买一个模块的完整流程从没在真实数据库和浏览器里走通过。

**建议先用"岗位实习"试点**，第二个做毕业设计；学工、教务放后面。

## 一、结论

| 问题 | 结论 |
|---|---|
| 平台化这条路对不对 | 对。职校客户往往分批采购、分部门决策，"统一底座 + 模块单独开通单独收费"是这一行的通行做法；代码已按这个方向设计（模块四态、分项订单、单模块退出） |
| 四个模块耦合紧不紧 | **代码层很松**：实习、毕设对其他三个业务模块零引用；教务只读学工的两张表。耦合集中在**共用底座**（学生档案、学院专业班级、审批、消息、文件），这是应该的 |
| 现在能否只开一个模块 | **技术上能开，体验和运营上没准备好**。后端拦截基本齐全；但缺底座入口、汇总页不过滤、运营端单模块流程未验收 |
| 要改多少 | 不需要拆系统、不需要拆库。约 3 个施工包：底座补口、汇总页按授权过滤、运营端收口单模块开通。详见第四、五节 |
| 先试点哪个 | **岗位实习**。理由见第六节 |

按 `backend/app/modules/` 逐模块统计 import 与表名引用：

| 方向 | 依赖 | 性质 | 影响单独开通吗 |

## 三、只开一个模块会卡在哪里（以"只开实习"为例）

### 3.1 底座入口藏在业务模块里

| # | 严重度 | 问题 | 证据 |

| B1 | 高 | **班级辅导员只能在学工或教务里设**。实习的预警、请假等通知按"学生 → 班级 → 辅导员"找人；系统管理的组织维护（`/system/org-nodes`）只能建学院专业班级，不能设辅导员；系统管理的"任职"表是另一张表，实习不读。只买实习的学校没有地方配辅导员，通知会落空 | `internship_service.py:71-87`；写 `counselor_id` 的只有 `affairs_counselor_service.py`、`affairs_class_service.py`、`academic_affairs_org_service.py`；`org_master_service.py` 无此字段 |

### 3.2 汇总页不看授权

后端门禁只拦"进入模块"的接口；下面这些跨模块汇总页本身属于底座，**没有按已购模块过滤**，只买实习的学校会看到其他模块的空卡片、点进去才被 403：

| # | 页面 | 会露出什么 | 证据 |
|---|---|---|---|
| S1 | 数据中心 / 领导看板 | 毕设通过率、学业预警等 KPI（值为 0） | `services/stats_service.py:89-99` |
| S2 | 学生手机首页快捷入口 | 我的课表、缓考申请、毕业设计 | `services/mobile_student_home_projection.py:38-60` |
| S3 | 教师手机工作台、学生 360 | 实习、毕设、学业卡片 | `teacher_mobile_student360_projection_service.py`、`teacher_mobile_workbench_v3_service.py` |
| S4 | 待办路由表 | 按模块注册的待办类型全量下发 | `services/todo_route_registry.py` |
| S5 | 学校岗位/角色模板 | 未核实是否按已购模块隐藏教务、学工岗位（文档 02、06 的岗位方案需补这一条） | 待核实 |

### 3.3 就业服务卖不出去

就业在模块清单里要求授权，但新版商品只认四个核心模块，四个模块的赠送能力里也都没有就业。结果：**按新方式开通的学校永远看不到"就业服务"菜单**。实习归档推送就业去向走的是服务直调，不受影响，但学校看不到结果。需要决定：就业并入实习一起卖，还是作为独立附加模块。

证据：`commercial_catalog_contract.py:19` `MODULE_FEATURES` 只有四项；`commercial_catalog_service.py:18` 实习的赠送范围无 `employment`。

## 五、要做到"按学校单独开通"需要改什么

不拆系统、不拆数据库。按优先级分三包：

### 包 A：底座补口（让只买一个模块的学校能用）

1. 系统管理的组织维护加上"班级辅导员 / 班主任"设置，与学工、教务写同一字段（或统一改为读任职表）。修 B1。
2. 系统管理组织维护补齐学工、教务之外都需要的部分（停用、转班至少要能做），教务"组织管理"保留为增强入口。修 B2。
3. 教务注册预检在迎新未开通时给明确提示，不按"未报到"处理。修 B3。
4. 决定就业的售卖方式（建议并入实习：实习商品赠送 `employment`）。修 3.3。

### 包 B：汇总页按授权过滤（体验）

1. 首页、看板、学生手机首页、教师工作台、学生 360、待办类型，统一调用一个"当前学校已开通模块"函数（后端已有 `module_access_state`），未开通的卡片不下发。修 S1–S4。
2. 学校岗位模板按已购模块隐藏无关岗位。修 S5，同时写进文档 02、06 的岗位方案。
3. 加一条自动测试：用"只开实习"的学校跑全部首页和汇总接口，响应里不得出现其他三个模块的入口。

### 包 C：运营端收口单模块开通

1. 删除或改造 O1 的假开关：要么下线，要么改成写新方式的"受控例外"授权，并改掉"即刻生效"字样。
2. 学校详情页加"已开通模块"一栏：四个模块各自的来源（订单/试用/例外）、到期日、学校是否停用，一屏看清。修 O4。
3. 套餐页面改为"选模块 + 选规模"，技术开关收进高级设置。修 O3。
4. 存量学校切换：先做一所的影子对账 → 切换 → 回切演练。修 O2。
5. 补齐 M3 缺口：真实 MySQL + 浏览器，单买实习从"建学校 → 下单 → 标记已付 → 学校只看到实习 → 跑完实习主流程"走通一遍。
6. 商务、实施岗位能操作开通和订单（按文档 06 第六节的岗位方案）。修 O5。

M4–M8（单模块退出、销毁、分项退款）不是试点前置条件，试点期按"整校合同"处理退出即可。

## 六、建议先试点哪个模块：岗位实习

| 维度 | 实习 | 毕设 | 学工 | 教务 |
|---|---|---|---|---|
| 与其他模块的代码耦合 | 最低（只连就业） | 最低 | 中（教务读它的迎新） | 高（最大、读学工） |

## 九、补充：集成版与独立版并存（2026-10-25 用户选定"能单独部署"）

用户目标：**同一套代码出两种形态**。集成版是四个模块都在的平台；独立版是"底座 + 岗位实习"或"底座 + 毕业设计"，可以单独卖、单独部署。不另起一套代码（`products/internship-platform/` 那份旧副本就是反例，见 O6）。

### 9.1 两种形态长什么样

| | 集成版 | 实习版 / 毕设版 |
|---|---|---|
| 包含 | 底座 + 学工 + 教务 + 实习 + 毕设（+ 就业、迎新等） | 底座 + 实习（含就业、企业端）/ 底座 + 毕设 |
| 云上（SaaS） | 现状 | 同一套云服务，学校只开通该模块，配独立品牌、域名、登录页 |
| 私有化 | 现状 | 同一个安装包，用"版本档位"配置只启用该模块 |
| 升级 | — | 实习版学校加购毕设或学工，**不迁移数据**，加授权就变成集成版 |

最后一行是这条路最大的好处：独立版只是集成版的一个子集，客户升级时不换系统。

### 9.2 代码现状：哪些地方好拆，哪些不好拆

| 部分 | 现状 | 好不好拆 | 证据 |
|---|---|---|---|
| 后端路由注册 | 已按模块分函数（`register_internship_routes`、`register_graduation_routes`…） | 好拆 | `api/v1/route_registration.py:167-242` |
| 后端路由补充挂载 | 总路由额外挂了一批学工补充路由，启动时还有 57 处 `install` 包装 | 中：需按模块分组 | `api/v1/router.py` |
| 底座反向引用业务模块 | 底座代码（core/services/api）有 31 个文件在顶部直接 import 业务模块，另有 42 个文件在函数内 import。例如文件权限解析、学生手机服务、教师手机服务都直接调实习、毕设、教务的代码 | **不好拆**：物理删掉某模块代码会导致启动失败 | `services/file_access_resolvers.py:14`、`services/_mobile_teacher_service_impl.py:22-24`、`core/permissions.py:583` |
| 学工代码位置 | 学工 83 个服务文件放在公共 `app/services/affairs_*`，没有自己的模块目录 | 不好拆 | `ls services/affairs_*` |
| 全平台审计流水消费者 | 放在**实习模块**里（`internship_audit_service.process_pending`），由启动程序调用。底座依赖实习，方向反了 | 必须先挪回底座 | `main.py:164` |
| 后台定时任务 | 实习、学工、审批等定时任务都写在 `main.py` 里，无模块判断 | 好拆：加判断即可 | `main.py:130-300` |
| 数据库 | 一条共用迁移链，约 351 个版本，各模块交织 | **不拆**：独立版也建全量表，没开的模块表为空 | `alembic/versions/` |
| PC 前端路由 | `router/index.js` 统一汇总 13 组模块路由；实习、毕设前端代码不引用其他业务模块 | 好拆：按配置决定汇总哪几组 | `frontend/src/router/index.js:27-63` |
| 小程序 | 实习已有独立分包（学生 20 页、教师 18 页）；毕设页面混在学生、教师大包里 | 实习好拆，毕设中等 | `miniapp/src/pages.json` |
| 企业端 | 已是独立前端 `enterprise-portal/` | 直接归入实习版 | — |
| 授权 | 授权来自平台订单（同一数据库）。私有化客户能改库给自己开全部模块，缺离线授权文件 | 需新增 | `commercial_authority_read.py` |
| 配置 | 只有 `DEPLOYMENT_MODE`、`SCHEDULER_MODE`，没有"版本档位"概念 | 需新增 | `core/config.py` |

结论：**按"开关"拆容易，按"删代码"拆很难**。所以独立版的做法是"整套代码都在，按版本档位只启用一部分"，而不是物理裁剪代码。

### 9.3 实现方案：一个"版本档位"配置

新增一个配置项 `EDITION`（取值 `full` / `internship` / `graduation`），只在一处定义每个档位包含哪些模块（复用 `module-manifest.json`，不另立清单）。它控制以下几处：

| # | 位置 | 做什么 |
|---|---|---|
| E1 | 授权上限 | `module_access_service` 计算"已购"时再与档位求交集：实习版即使数据库里有教务订单，教务也不可用。这是独立版的安全底线 |
| E2 | 私有化授权文件 | 私有化独立版用厂商签名的授权文件（学校、档位、到期日、学生数上限），系统用公钥校验，不再依赖同库平台订单。云上版本不需要 |
| E3 | 后端路由 | `register_all_routes` 和 `router.py` 的补充挂载按档位只注册底座 + 本档位模块；其他模块接口直接 404（比 403 更干净，也缩小攻击面） |
| E4 | 定时任务 | `main.py` 的定时任务按档位启停；先把审计流水消费者从实习模块挪到底座 |
| E5 | PC 前端 | 构建时读 `VITE_EDITION`，`router/index.js` 只汇总底座 + 本档位的路由组；菜单、首页、汇总卡片同步（与包 B 合并） |
| E6 | 品牌 | 系统名称、Logo、登录页、浏览器标题按档位给默认值（如"岗位实习管理平台"），学校品牌配置可覆盖。复用现有租户品牌配置 |
| E7 | 小程序 | 实习版：同一小程序按授权显示，或另注册一个微信小程序只打包实习分包。毕设版需先把毕设页面拆成独立分包 |
| E8 | 部署 | 同一个后端镜像、同一个前端源码，`docker-compose` 增加按档位的配置文件，实习版附带 `enterprise-portal` |
| E9 | 运营端 | 私有化独立版不带运营端；云上由运营端把"实习版、毕设版、集成版"作为三种商品管理（与包 C 合并） |
| E10 | 测试 | CI 增加档位矩阵：每个档位至少验证能启动、路由清单不含其他模块、主流程冒烟通过 |

`main` 上的 `router/index.js`、`platform.routes.js`、`platformManagementCatalog.js` 目前有官网拆分的未提交改动，E5、E9 施工前要先合入或协调。

### 9.4 分期

| 期 | 内容 | 交付结果 |
|---|---|---|
| 一期 | 文档 07 包 A、B、C + E1、E6、E8 | **云上实习版可以卖**：学校只开实习、独立品牌和域名；私有化可以装，但靠授权上限兜底 |
| 二期 | E2、E3、E4、E5、E10 | **私有化实习版可以交付**：离线授权、只注册实习接口、前端只打包实习；毕设版同步 |
| 三期（按需） | E7 独立小程序；毕设页面拆分包 | 有学校要求独立小程序时再做 |
| 不做 | 物理裁剪代码、拆数据库、拆迁移链 | 底座有 70 多处反向引用，代价远大于收益。只有客户要求交付源码时才单独评估 |

独立版和集成版共享同一条主线，任何修复两边同时生效。这是防止重演 `products/internship-platform/` 分叉的关键，CI 档位矩阵（E10）负责守住。
