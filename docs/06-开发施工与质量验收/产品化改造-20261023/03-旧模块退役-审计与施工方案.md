# 文档 3：旧模块与兼容层退役 · 审计与施工方案（2026-10-23）

> 三份并行文档之一：文档 1 文案清洗 ｜ 文档 2 教务角色与菜单 ｜ **文档 3 旧模块退役**。文件归属与合并顺序见文档 1 第七节。
> 你的要求：**不再兼容以前的旧模块。** 本文档列出全仓旧入口、旧页面、兼容层、演示/mock 体系和运行时补丁，给出删除或收口方案。
> 依据：当前工作区代码检索（含未提交改动），前端 1,757 个源文件、后端 1,571 个 Python 文件。

## 结论

系统里同时存在“新旧两套”的地方很多：**70 处旧路由跳转**、一整套已经没人用的“学业过程中心”（前端 9 个页面 + 内存 mock 数据库，后端 27 个接口还挂着）、**前端 436KB / 小程序 92KB 的 mock 数据**、后端 9 个 `mock_*` 服务、19 个 `*_legacy` / `*_compat` / `*_v2` 文件、**134 个运行时补丁函数 `install()`**（教务独占 58 个），以及管理员能看到的“待施工”占位菜单。

这些东西的代价：学校看到“待施工”“旧产品体验页（存档）”；同一件事有两个接口、两份数据；改一处要猜哪套在生效。退役后：**每件事一个入口、一个接口、一份数据。**

## 一、退役原则（已替你定）

1. **不留跳转、不留别名、不留“已停用”占位接口**：旧地址直接 404（后端）/ 进入 404 页（前端）。现在后端有“保留旧 URL、返回业务冲突”的做法（如 `academic_affairs_legacy_grade_write_guard.py`），一并删除。
2. **只删代码，不删数据**：业务数据、审计记录、上传文件保留。**本轮不删数据库表**；只读、无人写的旧表列入第五节，下一轮单独确认。
3. **“名字带 legacy”不等于没在用。** 先确认是不是现行实现：
   - 是现行实现 → 改成正式名字、并入正式模块，然后删除旧外壳；
   - 不是 → 迁移调用方，然后删除。
4. **删除前列清单给你确认**（AGENTS.md 要求）。本文档第二节就是清单；你在本文档上确认后，Codex 按包执行，每包再给一次实际删除文件列表。
5. **沙箱库的演示数据保留**：删除的是“没有数据库时用假数据顶上”的代码，不是沙箱里的演示学校。

### L6 运行时补丁（`install()`）

- 后端 **134 个** `def install(...)` 函数，教务模块 **58 个**。和毕设模块审计（2026-09-28）发现的问题一样：导入时替换函数、往路由表插路由，实际执行哪段代码取决于导入顺序。
- 前端 8 个 `install*`，其中 `installSystemAuthorityCompatibility`、`installGraduationW76…`（`workbench/config/graduationW76Workbench.js`）属于补丁性质；`installDirtyFormGuard`、官网 SEO / 微信运行时属于正常初始化，可保留但改名为 `setup*`。

做法（照搬毕设 P1）：先生成**路由与行为快照测试**（每个接口的路径、方法、权限、响应结构）→ 按模块把 `install()` 内联回原函数 / 原路由 → 删补丁文件 → 快照不变。教务 58 个分 3–4 批做。
