## 结论

现在教务菜单是“**一个 263 项的大目录，按权限码过滤**”，再用两个前端补丁给任课教师和学院“投影”出简化菜单。结果是：

- **学院管理员和教务处看到的一模一样**（263 项全可见），连“学年学期设置、校历、课表发布、成绩发布”都在学院菜单里。
- **辅导员能看到 17 个排课 / 课表管理菜单**（排课规则、自动排课、课表发布……），因为它们只要求“查看课表”权限。
- **校领导看到 206 个办理页面**，而不是一个看板。
- **只有一个“教务处管理员”角色**，没有考务、学籍、运行、教材、质量等科室分工；学院层面也分不出“教学院长（审核）”“教学秘书（办理）”“专业负责人（编方案）”。
- **学院管理员同时拥有学工、教务、毕设全部权限**（`COLLEGE_ADMIN` = `studentAffairs.*` + `academicAffairs.*` + `graduationDesign.*`）。学院教务员能处理处分、资助；学工干事能改成绩任务。

学校采购会问“我们教务处 5 个科、二级学院 8 个，权限能不能分开”，现在答不上来。改造目标：**按真实岗位给每个人一套固定的小菜单（5–10 项）和明确的数据范围，菜单由岗位决定，权限码只用于后端校验。**

## 一、现状审计

### 1.1 菜单是怎么出来的

1. `navPlan.js` 定义教务中心 30 个二级模块、263 个菜单项，每项挂一个权限码（共 91 个不同权限码，`schedule.view` 一个码挂了 18 项）。
2. `getVisibleNavPlan` 按当前角色权限过滤。没有权限码的菜单项“默认可见”。
3. 对任课教师和学院，再分别用 `academicTeacherNavigation.js`、`academicCollegeNavigation.js` 在前端重排、改名、隐藏。
4. 规划中的菜单（`planned`）对管理员可见，显示“待施工”（文档 3 处理）。

问题：菜单可见性由“粗粒度权限码 + 前端补丁”共同决定，后端看不到“这个岗位应该有哪些菜单”，任何权限码调整都可能让一批页面意外出现在别的角色菜单里。

## 二、目标岗位模型

按职业院校常见编制设计：**校级教务处按科室分岗，二级学院分审核、办理、专业三类，教师分任课、班主任、督导，领导只读。** 一个人可以同时挂多个岗位（例如“专业负责人 + 任课教师”），菜单按岗位分组显示，不需要整页切换。

小学校可以把多个校级岗位挂给同一个人，或直接用“教务处综合管理员”。**系统不新增可配置开关**，只提供固定岗位，学校决定把岗位给谁。

| # | 岗位（中文名） | 建议角色码 | 数据范围 | 一句话职责 |
|---|---|---|---|---|

| 3 | 考务成绩岗 | `AA_EXAM` | 全校 | 排考、监考分配、补考重修缓考免修、成绩录入期、成绩发布与更正终审、成绩单 |

### 2.2 职责分离规则（已替你定）

| 事项 | 发起 / 录入 | 审核 | 最终生效 |
|---|---|---|---|
| 教学任务 | 学院教学秘书（专业负责人建议教师） | 教学院长 | 教学运行岗下达；任课教师确认 |
| 课表 | 教学运行岗排课 | — | 教学运行岗发布（二次确认、留痕） |
| 调停课 | 任课教师 | 教学院长 | 教学运行岗（跨学院或影响考试时终审） |
| 成绩 | 任课教师 | 教学院长 | 考务成绩岗发布 |
| 成绩更正 | 任课教师 | 教学院长 | 考务成绩岗；**已发布成绩更正需教务处长确认** |
| 缓考 / 免修 | 学生 | 任课教师 → 班主任意见 → 教学院长 | 考务成绩岗 |
| 学籍异动 | 学生或学院教学秘书 | 班主任意见 → 教学院长 | 学籍岗 |
| 毕业资格 | 系统核算 | 教学院长初审 | 学籍岗提交，**教务处长确认**（写入毕业 / 结业 / 延毕，不可逆） |
| 培养方案 | 专业负责人 | 教学院长 | 教务处长发布 |
| 教材选用 | 任课教师 | 专业负责人 | 教材岗汇总征订 |

硬规则：**同一个人对同一条业务不能既录入又审核又生效**，后端校验，不靠菜单隐藏。

## 三、各岗位菜单（目标）

每个岗位一个首页 + 5–10 个菜单项。括号里是复用的现有页面或能力，Codex 实现时按“岗位专用视图 + 共用组件”的方式做，不复用带身份分支的大控制台。

### 3.1 校级

**① 教务处长**（首页：教务运行总览）
1. 总览：各学院本学期进度（任务确认率、成绩提交率、调停课数、预警数），异常列表
2. 待我确认：已发布成绩更正、毕业资格确认、培养方案发布、教学事故认定
3. 课表与教学任务查询（只读）
4. 成绩与考试查询（只读）
5. 学籍与毕业查询（只读）
6. 教学质量（评教结果、督导、教学检查）
7. 统计报表
8. 教务大屏

**② 教学运行岗**（首页：本学期运行阶段清单——开学前 / 开学 / 期中 / 期末 / 学期末各要做的事）
1. 学年学期与校历（含节次、教学周、节假日调休、教学进程：军训 / 实训周 / 顶岗周）
2. 教学任务（下达、汇总、退回）
3. 排课（排课规则、自动排课、冲突处理、人工调整）
4. 课表发布与查询
5. 调停课审批
6. 教室与实训室（资源、借用审核、占用查询）
7. 运行统计

**③ 考务成绩岗**（首页：考试与成绩进度）
1. 考试安排（排考、监考分配、座位、打印）
2. 补考 / 重修 / 缓考 / 免修
3. 成绩录入期（开放、截止、延期、催交）
4. 成绩审核发布
5. 成绩更正与复查
6. 成绩单与在读证明打印
7. 考试成绩统计

**④ 学籍岗**（首页：学籍待办）
1. 学籍名册
2. 学期注册
3. 学籍异动审批
4. 专业分流
5. 毕业资格审核
6. 证书与学籍归档
7. 学籍统计

**⑤ 教材岗**：教材目录 / 选用汇总 / 征订 / 发放 / 结算 / 统计（6 项）

**⑥ 质量督导岗**：评教批次与结果 / 督导听课安排 / 教学检查 / 教学事故 / 质量报告（5 项）

**⑦ 教务处综合管理员**：②–⑥ 的菜单按科室分组合并显示，不另做一套。

4. 教材汇总
5. 学籍材料（本院异动、注册情况）

**⑩ 专业负责人**（首页：本专业事项）

### 3.3 教师级

**⑪ 任课教师**：今日 / 我的课表 / 我的课程 / 我的申请 / 查询（详见教师端方案）。

**⑫ 班主任 / 辅导员 · 本班学业**（挂在辅导员现有菜单下一个分组）
1. 本班课表
2. 本班成绩（已发布）
3. 本班考勤
4. 学业预警处理
5. 待我意见（缓考、学籍异动）

## 四、技术方案

1. **岗位菜单契约**：新建 `shared/contracts/role-menus/academic.json`（或同等位置），按岗位列菜单项（名称、路由、所需权限、分组），用现有契约生成命令生成到前端；`BasePortalLayout` 按“当前账号的所有岗位”合并渲染。**删除** `academicTeacherNavigation.js`、`academicCollegeNavigation.js` 两个投影补丁和 `getVisibleNavPlan` 中“无权限码默认可见”的逻辑。`navPlan.js` 的 263 项目录收缩为“全部页面登记表”，不再直接当菜单用。
2. **权限码分层**：每个业务域拆成 `view`（查询）/ `operate`（办理）/ `review`（审核）/ `publish`（生效）。管理页面要求 `operate` 及以上；“查看课表”只放行查询页。现有 91 个码按此重排，`shared/contracts/permission-catalog*.json` 同步重新生成。
3. **数据范围**：岗位自带范围类型：全校 / 本学院 / 本专业 / 本人课程 / 本班 / 听课对象。复用现有 `dataScope` 与 `build_affairs_context`，新增“本专业”“听课对象”两种。
4. **职责分离**：第 2.2 节的规则在后端服务层校验：审核人 ≠ 录入人；生效人 ≠ 审核人。现有“端点内角色 = 教务处 / 学校管理员”的特判改为岗位判断。
5. **一人多岗**：登录后取所有岗位，菜单按岗位分组显示；待办汇总所有岗位。切换数据范围不再需要整页刷新（取代教师端方案 A7）。
6. **角色迁移（不兼容）**：Alembic 数据迁移把沙箱里的 `COLLEGE_ADMIN` 账号按名单拆到新岗位；删除别名“教务老师 → 任课教师”，改为“教务老师 → 教务处综合管理员”；`LEADER` 收窄为大屏 + 统计权限；`SCHOOL_ADMIN` 去掉教务业务菜单。
7. **人员导入**：`identity_import` 模板增加岗位列，可选值为上表中文名。
