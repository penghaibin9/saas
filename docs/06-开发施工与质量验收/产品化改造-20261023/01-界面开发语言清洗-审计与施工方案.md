## 本轮定位

**目标：所有页面上，老师、学生和管理人员看到的每一句话都看得懂、不重复、不乱解释；保留现有办理规则和操作能力。**

范围扩展到**全部端的全部页面**，以“每页截图审计”为主、代码扫描为辅：

- 代码扫描只能找到写死在代码里的字；像工作台待办下面露出的 `RISK_HANDLE`、`AA_SCHEDULE_CHANGE_APPROVAL`，是页面运行时把后端的类型代码直接显示出来，只有打开页面才看得到。
- 所以每个页面都要**用对应角色真实登录、打开、截图、读一遍屏幕上的字**，再改代码，改完再截图对比。

本轮只改用户看得见的文字和显示方式，不改交互流程、接口、状态值、权限、菜单结构和业务规则。下文第一、二节是原审计数据，保持原样；第三节起是本轮施工要求。

## 结论

## 二、为什么会这样（根因）

1. **施工说明直接写进了界面。** 开发时为了让 AI、测试“看懂”，把“由服务端校验、不使用浏览器估算、以正式记录为准”这类工程约束写成了页面提示。
2. **“提交结果不确定”被做成了用户要处理的事。** 网络超时后，系统让用户自己点“只读核对原命令”。这一个交互模式贡献了“回读 / 原命令 / 只读核对 / 待核实 / 不会重发 / 不能证明”几百处文字。
3. **帮助中心一层叠一层。** `frontend/src/config/help/` 有 41 个文件、560KB：HelpCards → CleanHelpCards → CoreFlowHelpCards → VerifiedOverrides → V305B / V305C，正文写满权限码和状态码。
4. **后端错误原样上屏。** 435 处 `error.message` 直接展示；后端提示里有字段名（“taskId 必填”）、内部概念（“幂等重放”“投影”“名单版本”）。
5. **状态值没有中文时显示原值。** 模板里有 38 处 `|| row.status }}` 这类兜底，字典缺项时页面就露出 `PENDING_REVIEW`。

## 三、要清理的四类问题

### 3.1 英文代码和内部编号外露

| 情况 | 例子 | 改法 |
|---|---|---|
| 类型、状态、角色等代码直接显示 | 工作台待办下面的 `RISK_HANDLE`、`AA_SCHEDULE_CHANGE_APPROVAL`；表格里的 `PENDING_REVIEW` | 显示中文名称。优先复用已有的中文对照（如 `frontend/src/modules/workbench/config/workbenchRecipes.js` 里已有 `RISK_HANDLE → 风险待处置`、`AA_SCHEDULE_CHANGE_APPROVAL → 调停课待审`）。对照表缺项时显示“其他事项 / 其他状态”，**绝不显示原始代码** |
| 字段名、接口名、英文报错 | `taskId 必填`、`expectedVersion`、`HTTP 409`、`traceId` | 改成中文说明（“请选择教学任务”“内容已被他人修改，请刷新后重试”） |
| 数据库编号 | `#1000000000000000007`、`记录 18`、`课程ID 3021` | 从正文移除，用名称描述对象（“软件测试技术 · 22 软件 1 班”）。**保留**：学号、工号、业务单号（申请编号、准考证号等）、现有的“复制问题编号” |
| 英文装饰标题 | `ACCOUNT SECURITY`、`VOCATIONAL EDUCATION` | 改成中文或删除 |

已定位的典型根因：`frontend/src/modules/workbench/views/WorkbenchView.vue` 的 `todoMeta()` 在没有模块名时退回 `t.todoType`，所以露出代码；同一函数还会显示“记录 {编号}”和“待核对”。同类写法（显示时最后退回原始代码字段）扫描脚本已能粗筛，CSV 中类别为“运行时代码外露”，共 121 处候选，需逐个判断。

### 3.2 重复文字

同一屏上同一个意思只说一遍。常见重复：

- **标题层层重复**：菜单、标签页、页面大标题、卡片标题都写同一个词（如“我的工作台”出现在二级菜单、标签页和页面标题三处时，页面内不再加同名卡片）。
- **说明复述标题**：标题“请假审批”，下面一行写“在这里审批学生的请假申请”——删掉说明。
- **同一提示出现多处**：顶部横幅、卡片内、空状态各写一遍“当前学期未开放”——只留最靠近操作的一处。
- **按钮旁复述按钮**：按钮“导出”，旁边写“点击导出按钮可导出数据”——删掉。
- **两个区块展示同一组数字**（如“今日工作摘要”和“待我办理”各显示一次待办数）——保留一处，另一处改为补充信息或删除。由施工者判断，拿不准的记入施工记录，不擅自删区块。

### 3.3 乱解释文字

每一段说明文字都必须回答下面之一，否则删掉：

1. 用户现在要做什么；
2. 做了之后会发生什么、交给谁；
3. 有什么真实限制（截止时间、不能撤回、需要先完成某事）。

要删或改的典型写法：

| 类型 | 例子 | 处理 |
|---|---|---|
| 解释系统内部原理 | “此限制由服务端强制执行”“浏览器只展示服务端预检”“来源：当前正式范围头下的行政班课表投影” | 删除；有真实限制就只说限制 |
| 自证、免责、否定式说明 | “不代表已取得使用资格”“当前状态不能证明本次命令是否成功”“以正式记录为准” | 改成一句正向提示（“提交后由管理员审核”），或删除 |
| 写给开发或测试看的话 | “防止浏览器估算被误认为正式事实”“不会自动重发” | 删除 |
| 冗长段落 | 灰色说明超过两行 | 压到一句（40 字以内）；确需详细说明的放进帮助中心 |

**语义不能改错**：“待核验 / 待核对”表示还没核验，不能改成“未填写”；“结果尚未确认 / 待核实”表示不知道成功没有，不能改成“提交失败”或“已提交”，可改成“正在确认提交结果，请稍后刷新查看”；“暂无数据”只用于确实没有数据，加载失败、无权限不能写成“暂无数据”。

### 3.4 开发词

原审计的开发词照常清理，按语境改写，不做机械替换：

| 常见开发词 | 改写方向 |
|---|---|
| 回读、已回读正式记录 | 已保存、已更新、已刷新 |
| 原命令、命令引用、只读核对、只读刷新 | 上次提交、刷新查看结果（**保留原按钮和恢复操作**，只改名字和说明） |
| 正式事实、事实、真值 | 记录、信息、已确认的结果 |
| 服务端、后端、前端、接口、数据库、字段、枚举、权限码、令牌、缓存 | 系统；或删掉这句 |
| 门禁、原子、事务、持久化、链路、闭环、兜底、降级、投影、契约、快照版本、指纹、口径 | 删掉技术说明，保留其中的业务限制 |
| 责任队列、当前责任、下一责任 | 待办、下一步由 ×× 办理 |
| 对象、业务对象 | 具体名词：课程、学生、申请、批次 |
| 预检、证据、阻断 | 检查、材料 / 记录、必须先处理的问题 |
| 预留、兼容、旧版、演示数据、mock、占位、待施工、P0 / V2 等内部编号 | 删除 |

**可以保留**：Excel、PDF、Word、二维码、学号、工号，以及管理端的“台账”“回执”。

### 3.5 不做的事

- 不新建统一提交工具，不加轮询判定，不删除各页面的恢复文件；现有提交恢复、操作记录和防重复机制全部保留，只改其中的文字。
- 不新建全局状态系统；复用各端已有的中文状态与错误展示工具，只在显示层把代码换成中文。不改接口字段、状态值、权限码、错误码。
- 帮助中心只改正文：不合并、不删除、不改名文件，不改匹配和跳转。
- 不改审批、考勤默认值、成绩计算、角色权限、菜单结构、登录策略；不改代码注释、变量名、日志。
- 不为了“零命中”删掉真实业务限制。

### 4.2 审计工具（先做）

在 `e2e/tools/` 下新建只读巡检脚本（Playwright），要求：

1. **只读**：拦截浏览器发出的所有写请求（POST / PUT / PATCH / DELETE），只放行登录和切换身份所需的接口；不点击提交、审批、删除、导出类按钮。
2. **按角色登录**：学校管理员、教务处、学院、任课教师、辅导员、学工处、毕设管理、实习管理、校领导、学生、企业联系人，用沙箱学校 `sandbox-school` 已有账号。账号从沙箱种子和现有 E2E 引导脚本里找；**账号密码不写进文档和代码**，用环境变量传入。
3. **逐页**：打开页面，等加载完成，整页截图，保存 `document.body.innerText`。
4. **自动标记**：英文代码（`[A-Z]{2,}_[A-Z0-9_]+`、驼峰词）、长数字编号、第 3.4 节开发词、同一句话在一页出现两次以上、超过两行的灰色说明。
5. **输出**：截图和报告放在 `e2e/runtime/ui-audit/`（已被 Git 忽略，不提交）；报告按页列出“页面 / 角色 / 截图 / 自动标记 / 人工结论”。

### 4.3 审计与修改流程

每个页面：截图 → 看自动标记，并**人工通读整屏**，找出第三节的四类问题 → 定位代码改掉 → 重新截图 → 前后对比。自动标记只是辅助，重复文字和乱解释主要靠人工读。

页面上的文字来自后端返回的，同步改后端提示（只改文字，错误码和返回结构不变）。

### 4.4 运行环境

- 截图审计要能启动系统：本地 MySQL 容器 `student-lifecycle-v8-mysql`（端口 3307）、后端、各端前端。**需要在本机跑**，云端环境没有数据库时只能做代码扫描部分，截图审计写“未执行”。
- 浏览的是日常沙箱库（2 万学生数据，最接近学校真实页面）。巡检脚本是只读的，不提交任何表单；不对沙箱库运行任何种子、清理或迁移脚本。
- 演示后端重启后浏览器登录会失效，需要重新登录。

## 六、验收

1. **每个已处理页面有前后对比截图**，报告里写明改了什么。
2. 已处理页面上：没有英文代码、数据库编号、开发词；同一意思不重复；每段说明都能回答“做什么 / 会怎样 / 有什么限制”。保留项写明理由。
3. **意思一致**：真实限制没有丢，状态没有说错（见 3.3 末段）。
4. 断言旧文案的测试同步改成新文案，**不允许删断言**；受影响端 `node --test`、`eslint`、构建通过；改了后端提示的跑相关 pytest（顺序执行）。
5. 手机宽度（390）下，学生 PC 和移动端页面文字不重叠、不截断。
6. 只改文案和显示方式，不要求重跑全系统业务验收；微信真机未测就写“未验证”。

## 七、注意事项

- 扫描是静态规则，有误报（例如学生填写示例里的“CAD, PLC”）；误报在 CSV“建议”列注明“保留”。
- 同一句话改写时保留原有业务含义；拿不准的写进施工记录，不擅自删。
- 导航文案若由源头生成（如导航契约），改源头后用命令重新生成，不手改生成结果。
- 截图里可能有学生姓名等信息，只放在被忽略的 `e2e/runtime/` 目录，不提交、不外传。
