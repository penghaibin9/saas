## 4. 审批受理人和兼岗校验

| 业务 | 具体承接规则 | 缺配置/历史状态处理 | 同人限制 |
|---|---|---|---|
| 请假审批 | 根据单据当前节点找对应辅导员、学院、校级职责及具体 `WorkflowTask` | 缺流程或有效受理人：保留台账、提示待配置，不在可办队列伪装可审 | 普通请假允许真实双任职分节点确认，不自动跳过 |
| 续假/销假 | 查各自 `UnifiedTodo`，不能误要求主请假当前状态一定有同名流程任务 | 缺待办受理人拒绝；不改变已确认的续假业务标准 | 使用该业务已确认规则；真实用户不可伪装 |
| 困难评审 | `AID_APPROVAL` 主流程当前任务；学校终审排除前序实际评审人 | 缺任务或无法核验当前账号拒绝 | 学校终审与前序实际评审分开 |
| 困难动态调整 | `AID_ADJUST` 独立统一待办；不机械复用主流程当前节点任务 | 保留现有调整流程，缺对应受理人拒绝 | 不新增未经确认的业务层级 |
| 奖助评审 | 保留最终资金扫描保护的严格三级节点/范围/受理人，改造任职时同步候选池 | 不放宽现有缺流程/缺任务拒绝 | 学校终审与前序评审分开；金额调整申请复核分开 |
| 处分/解除 | 主流程与解除子流程各自的当前任务和节点；历史投影不可当审批真值 | 缺任务不推进，保留历史单据及审计 | 正式复核人不同于登记人；申诉避开原决定审核人 |
| 调宿 | 本班辅导员初审、目标楼栋宿管审核，分别匹配当前待办 | 缺另一名合格人员等待配置，不给校级兜底 | 两次审核必须不同真实人员 |
| 风险/心理/工单 | 当前责任人或明确授权上级；原文另鉴权 | 非审批业务不强造工作流；保留真实版本和责任人 | 日常跟进可由同人连续办理 |

真实人员取账号主键并核对租户/账号状态，旧显示姓名、无法解析的编号不能作为授权依据。按04发现的全校范围跳过、缺任务跳过、编号为零跳过分别补反向用例，不直接把资助三级范围判断复制到所有域。
