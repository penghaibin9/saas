## 2. 统一页面结构：按任务选型，不统一堆卡片

| 类型 | 从上到下的固定信息顺序 | 主要操作 | 不应出现 |
|---|---|---|---|
| 列表/台账 | 业务标题和必要范围 → 常用筛选 → 对象列表 → 分页 | 新建只在有权限时展示；逐行操作紧邻对象 | 默认首行冒充当前对象；重复标题、无依据统计卡 |
| 对象详情 | 返回入口 → 对象业务名与实际状态 → 核心字段/明细 → 必要历史/材料 | 当前状态真正允许的下一步；危险动作分离 | 内部编号代替名称；与对象无关的固定进度 |
| 编制/申请表 | 对象与适用范围 → 核心字段 → 依据材料 → 校验/确认 → 保存或提交 | 每一操作区一个明确主操作；长表可在顶部与底部各保留同一动作 | 同一区域两个等价保存按钮；失败清空输入 |
| 审批/处理队列 | 筛选与队列 → 当前选中对象 → 依据/差异 → 意见 → 按原规则处理 | 通过/退回等原有动作；结果未知时先查询 | 空队列要求选择不存在对象；未选对象显示虚假责任 |
| 配置页 | 当前有效配置与作用范围 → 可编辑字段 → 变更影响 → 保存入口 | 现有的保存、检查、启用按状态呈现 | 未配置装作默认值；配置解释占满首屏 |
| 统计页 | 统计范围与更新时间 → 筛选 → 指标与明细 → 授权下钻/快照 | 更新统计，已有权限下查看明细 | “暂无”显示0；不同分母比较；筛选未更新无提示 |
| 归档/结果页 | 范围与当前状态 → 完整性/处理结果 → 缺项定位 → 历史查看 | 只展示状态允许的原有动作 | 批量部分成功写成全部完成；省略封存限制 |

说明取舍：帮助判断对象、状态、下一步、影响范围或恢复的文字保留；重复来源声明、技术实现过程、固定“流程视角”等移除或合并。普通规则使用已有帮助/折叠能力，不把关键阻断和不可逆影响折叠隐藏。

## 4. 统一状态和恢复设计

| 状态 | 用户应看到 | 动作与数据保护 |
|---|---|---|
| 加载 | 原对象名和读取进度；不抢先显示空数据 | 禁止基于未取得数据提交；切对象后旧响应不覆盖 |
| 正常空结果 | 当前筛选下没有对象 | 提供调整筛选；不诱导无意义造数据 |
| 读取失败 | 失败原因和重试入口 | 保留筛选；不能继续显示“共0条”冒充成功 |
| 无权限/状态不允许 | 清楚的岗位或条件说明 | 不扩大权限；危险操作隐藏/禁用沿现有规则 |
| 字段校验失败 | 定位字段及可纠正信息 | 输入保留，焦点回错误处 |
| 提交中 | 对象、正在处理的动作 | 防止重复提交和切错对象 |
| 版本冲突 | 对象已变化、需重新核对 | 保留草稿，先刷新正式状态，不覆盖别人结果 |
| 结果未知 | 结果待确认与查询入口 | 保留原请求恢复引用，不允许随意重发 |
| 部分完成 | 已完成、失败、未处理的数量和原因 | 只处理允许重试部分，不把批量总数当成功数 |
| 已完成 | 本次真实结果、后续责任/入口 | 下一步指向同一对象；已有历史完成不冒充本轮办理 |

桌面优先让筛选、对象和主要动作进入首屏；窄屏按标题/范围/操作/内容顺序排列。长原因可横向查看或展开，不逐字压窄、不截断必需判断。键盘操作、可见焦点、按钮名称、禁用原因均列入后续检查；当前截图不能证明全面无障碍合规。

## 5. 跨模块衔接的固定核对表

| 衔接 | 必须保持的对象与条件 | 设计收口证据 |
|---|---|---|
| 课程/方案→开课 | 当前学期、适用专业年级、已发布版本、课程身份 | 从方案进入任务时携带正确范围；校验失败能回原方案 |
| 任务→课表 | 真实任务批次、教师关系和确认事实 | 课表使用相同任务；调整后的重新确认按原规则呈现 |
| 注册/分流/选课→名单 | 学生、批次/学期、教学班、有效状态 | 名单来源明确；资格通过、注册完成、选课成功不互相代替 |
| 课表→调停课/考勤/预约 | 课程、教师、周次节次、教室 | 原安排可见；审批结果与查询视图一致；不丢冲突信息 |
| 考试→成绩→预警→毕业 | 学生课程版本、考试类型、正式成绩、有效更正 | 不把草稿分数用于正式结果；预警跟进与毕业不通过原因有来源 |
| 课程任务→教材/评价 | 课程/教学班/教师、有效学期、适用范围 | 选用、发放、评价对象不串；保留未接入能力的真实边界 |
| 业务结果→统计/归档 | 相同范围、分母、更新时间、版本与完整性 | 聚合口径可解释，缺项返回原业务；个人字段范围按原权限 |

本轮只做设计与只读衔接核对。申请、审批、正式发布、注册生效、生成和归档等写入链未执行时，均保留“真实办理未验证”。设计不得增加数据库字段、后端权限或业务节点来掩盖现有证据缺口。
