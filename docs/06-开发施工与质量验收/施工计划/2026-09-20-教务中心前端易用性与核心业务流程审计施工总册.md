# 教务中心前端易用性与核心业务流程审计施工总册

> 审计日期：2026-09-20  
> 仓库：`penghaibin9/saas`  
> 审计基线：`main`，HEAD=`b7cfdb74987e19f8dad407ff830622ef5fcd2834`（PR #270 已合并后）  
> 本文定位：**前端信息架构、任务导航、核心业务连续性、老师零基础可用性施工总册**。  
> 施工原则：不推倒既有教务底层，不另造第二套课程/方案/教学任务/课表/成绩事实；优先复用现有路由、权限、状态机、API、UnifiedTodo、readiness、工作台配方与已完成的真实业务工作台。

---

## 0. 一句话结论

**当前教务中心不是“功能少”，而是“功能太全但日常入口仍按系统能力目录组织”，导致老师必须先理解系统结构，才能完成业务。**

现有底层已经具备大量生产级能力：学期、校历、学籍、培养方案、课程、教学任务、排课、选课、考务、成绩、预警、毕业、教材、资源、质量、统计、归档，以及权限、数据范围、审计、XLSX、状态机与若干 E2E。当前最优先的施工方向不是继续增加页面，而是把这些能力重组为**任务式、阶段式、角色式前端**。

最终目标不是“老师知道 127 个路由在哪里”，而是：

> 老师登录后只需要回答五个问题：  
> **现在做到哪一步？我今天要做什么？为什么做不了？做完会发生什么？下一步去哪里？**

# 2. P0 根因一：任课教师仍能看到约 15/17 个教务工作区

`backend/app/core/permissions.py` 中的 `ACADEMIC_TEACHER` 已经从历史通配符收窄为 31 个显式教务权限点，这是安全方向上的进步。

但是按当前 `getVisibleNavPlan()` + `buildAcademicNavigation()` 投影逻辑，只要某个工作区里存在一个当前角色可见叶子，该工作区就会保留。

按当前代码静态核对，任课教师仍会出现约 **15 个教务工作区**，包括：

- 教务大屏
- 教务总览
- 教务基础
- 学籍管理
- 培养与课程
- 开课管理
- 排课与课表
- 选课管理
- 日常教学
- 考务管理
- 成绩管理
- 教材管理
- 教学资源
- 教学质量
- 教务统计

这与 `workbenchRecipes.js` 已经定义好的 **T1 任课教师工作台**明显冲突。

T1 当前真正的高频入口只有：

- 成绩录入
- 我的课表
- 教学任务
- 发起调停课

**这说明仓库已经有正确的“角色任务模型”，但教务中心左侧导航还没有消费它。**

### P0 施工裁决

权限不删，页面不删，路由不删。

只重做“默认呈现层”：

- **角色拥有权限 ≠ 必须进入默认菜单**
- 低频查看能力进入“全部业务 / 查询工具”
- 高频责任能力进入“我的教务”
- 管理岗再进入完整 8 阶段教务流程

这是一项纯前端信息架构升级，不应借机修改后端权限边界。

# 3. P0 根因二：教务窄菜单当前存在重复名称，老师无法辨认

`TeacherWorkspaceFrame.vue` 的二级工作区在 compact 模式使用：

`workspaceShort(item)`

而 `teacherWorkspace.js` 的 `SHORT_NAMES` 当前只定义了学工模块，没有定义任何 `aa-*` 教务工作区。

因此教务工作区会退化成：

`String(item.label).slice(0, 2)`

实际会形成明显冲突：

| 完整名称 | 当前窄栏显示 |
|---|---|
| 教务大屏 | 教务 |
| 教务总览 | 教务 |
| 教务基础 | 教务 |
| 教务统计 | 教务 |
| 教务归档 | 教务 |
| 教学资源 | 教学 |
| 教学质量 | 教学 |

这不是视觉偏好问题，而是**导航辨识度缺陷**。

### P0 立即修复

在 `teacherWorkspace.js` 增加教务专用短名称：

| key | 建议短名 |
|---|---|
| aa-big-screen | 大屏 |
| aa-dashboard | 总览 |
| aa-terms | 基础 |
| aa-student-status | 学籍 |
| aa-training | 培养 |
| aa-teaching-tasks | 开课 |
| aa-schedule | 课表 |
| aa-course-selection | 选课 |
| aa-daily | 日常 |
| aa-exam | 考务 |
| aa-grades | 成绩 |
| aa-graduation-qual | 毕业 |
| aa-textbooks | 教材 |
| aa-resources | 资源 |
| aa-quality | 质量 |
| aa-stats | 统计 |
| aa-archive | 归档 |

验收规则：**同一可见菜单中不得出现重复 compact label。**

# 4. P0 根因三：教务首页存在“看起来能点、实际暂未接入”的入口

`AaOverviewWorkspace.vue` 当前把责任队列定义成四类：

- 待我办理
- 待我启动
- 我发起的
- 我的已办

但是代码同时明确：

`unsupported() { return ['toStart', 'initiated'].includes(this.tab) }`

后端 `academic_affairs_role_queue_service.py` 也返回：

- `capabilities.pending = true`
- `capabilities.done = true`
- `capabilities.toStart = false`
- `capabilities.initiated = false`

且 `summary.toStart = None`、`summary.initiated = None`。

这会造成典型的小白体验：

> 首页显示“待我启动 / 我发起的” → 用户以为是正式功能 → 点击 → “暂未接入”。

### P0 施工裁决

只有两种合格处理方式：

**方案 A（优先）：** 正式补齐 `toStart` / `initiated` 的统一事实投影。

**方案 B（本轮更稳）：** 在正式事实没有补齐之前，从一级责任导航中移除这两项，只保留：

- 待我办理
- 我的已办
- 24 小时到期
- 当前阶段阻断

禁止继续把未接入能力作为主任务 Tab。

# 5. P0 根因四：“我的常用”默认内容与任课教师真实任务不一致

`teacherWorkspace.js` 的 `defaultShortcutIds()` 默认优先尝试：

- 学生列表
- 请假审批
- 宿舍

- 风险

这些明显是通用/学工倾向入口。

在纯教务角色找不到这些路径时，会退化为：

> “当前可见页面的前 4 个”

对于任课教师，这极有可能优先变成：

- 教务大屏
- 教务总览
- 学期管理
- 其它基础查询

而不是 `workbenchRecipes.js` 已经明确的：

- 成绩录入

- 教学任务

`TeacherWorkspaceFrame` 的默认快捷栏必须支持 **role recipe 注入**。

- ACADEMIC_ADMIN 使用 T2 默认入口
- COLLEGE_ADMIN 使用 T3 默认入口
- 用户自行修改后继续以用户保存结果优先

# 6. P0 根因五：单个页面已经有“下一步”，但跨业务工作区仍缺连续接力

当前多个页面内部已经明显进步：

- `AaProgramEditorView.vue`：有 4 步编制流程与结构化校验
- `AaTaskDetailView.vue`：有 5 步教学任务阶段
- `AaSchedulingConsoleView.vue`：有 5 步排课阶段
- `AaSelectionConsoleView.vue`：有选课生命周期
- `AaExamConsoleView.vue`：有考务阶段
- `AaGradeEntryView.vue`：有成绩业务阶段
- `AaArchiveConsoleView.vue`：有归档阶段

问题是：**这些“局部流程”没有被一条“全学期主流程”串起来。**

例如当前代码可见：

- 教学任务终审成功后，文案写“正式就绪任务可进入排课”，但 `AaTaskDetailView.vue` 自身主要跳转仍停留在 `/teaching-tasks/*`
- 排课正式发布后，回执主要告诉用户“四端读取正式课表 / 后续调停课”，但缺统一的“进入下一教务阶段”按钮
- 选课锁定后显示“正式名单已锁定”，但下一阶段仍需要用户重新理解菜单
- 考务结束与成绩录入不是统一接力
- 成绩发布后的预警/补考/毕业风险仍是分散入口
- 学期收口没有从“成绩/毕业完成度”直接接“归档 readiness”

### P0 施工裁决

所有主链页面统一增加 **“下一责任动作”**，只消费真实状态与已有路由，不猜业务。

统一结构：

```text
当前对象
当前状态
当前责任人/岗位
当前阻断
[主按钮：完成本步骤]
完成后会发生什么
[下一步：进入 xxx]
```

所有跨页跳转必须保留：

- termId
- batchId / taskId（有正式对象时）
- returnToken / returnTo
- 当前角色上下文
- 当前正式对象，不允许重新靠用户手选猜对象

# 10. 统一页面骨架

所有核心办理页逐步统一为以下结构。

## 10.1 顶部对象条

必须显示：

- 当前学期
- 当前业务对象
- 当前正式状态
- 数据范围
- 当前责任
- 下一责任

---

## 10.2 阶段条

示例：

`方案 → 开课 → 排课 → 课表 → 选课 → 考试 → 成绩 → 归档`

要求：

- 当前步骤高亮
- 已完成显示 ✓
- 未解锁写清前置条件
- 点击已完成步骤允许回查
- 禁止用“灰掉按钮”代替原因

---

## 10.3 主任务区

一个页面必须只有 **一个视觉主按钮**。

其它动作分为：

- 次按钮
- 更多操作
- 只读查询

不要在首屏同时出现 5—10 个同权重按钮。

---

## 10.4 阻断区

必须说人话：

错误示例：

`STATUS_INVALID`

正确示例：

`当前还有 2 门课程未分配任课教师，完成分配后才能提交学院确认。`

每个阻断必须提供：

- 发生在哪个对象
- 为什么阻断
- 谁负责
- 去哪里处理

---

## 10.5 操作回执

所有关键写操作后统一使用现有 `AaOperationReceipt` 思路：

- 本次操作对象
- 操作是否确认成功
- 正式状态
- 产生了什么结果
- 下一责任
- **下一步按钮**

禁止只 toast “成功”。

# 11. P1：大控制台拆“主任务”，不是简单拆文件

本轮不要求为了代码漂亮而全面重构 100 KB 文件。

拆分标准只按用户任务：

## 应优先拆清的页面

### `AaProgramConsoleView.vue`
保留总览/版本/只读统计；方案编制、审核、发布、影响分析分别进入独立任务视图。

### `AaSchedulingConsoleView.vue`
排课规则、排课操作、冲突处理、结果发布必须在视觉上形成四个任务阶段；不要依赖用户理解 Tab 名。

### `AaSelectionConsoleView.vue`
批次生命周期可以保留同页，但：
- 规则
- 名单
- 轮次
- 异常
- 归档

必须以阶段卡/对象上下文进入，禁止横向堆功能。

### `AaExamConsoleView.vue`
考试批次主线与缓考审批是两类责任队列，应清楚分区；不能让普通用户同时理解所有考务子域。

### `AaGradeEntryView.vue`
任课教师默认只看到：
- 当前课程
- 正式名单
- 成绩项
- 保存状态
- 质量检查
- 提交审核

管理员特殊补录、动态方案、Excel 导入等能力降级到“高级操作”。

### `AaOrgConsole.vue`
普通业务阶段只需要组织核对；组织同步、批量调整、专业方向等进入设置/高级目录。

# 12. P1：未保存内容保护目前不统一

`TeacherWorkspaceFrame.vue` 当前通用离开检查只兜底检测：

它并不能可靠判断：

- input
- select
- checkbox
- picker
- 表格内编辑
- 动态成绩方案
- 批量配置

当前静态搜索仅发现少量教务页面自己实现 `beforeRouteLeave`，而教务 views 总量有 134 个。

- AaProgramEditorView
- AaCourseFormView
- AaScheduleMaintainView

- AaSelectionConsoleView 中新建/规则配置
- AaExamConsoleView 中编排/配置
- AaGradeEntryView

统一行为：

- 未修改：直接离开
- 已修改未保存：确认
- 正在提交：禁止重复离开

# 17. 验收门禁

- 旧深链不失效

## 17.2 首屏门禁

每个核心页首屏必须能回答：

1. 我现在在哪个学期/对象？

3. 当前是否被阻断？
4. 我现在应该做什么？
5. 做完后去哪？

任何核心页面答不全，UX 验收不通过。
