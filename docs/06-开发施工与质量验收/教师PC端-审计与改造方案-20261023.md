# 教师 PC 端 · 审计与改造方案（2026-10-23）

> 范围：**任课教师（`ACADEMIC_TEACHER`）在电脑上的全部体验**，包括登录后首页、侧栏菜单、课表、教学任务确认、成绩、考勤、调停课、教材、教室/实训室预约、资料查询。班主任、毕设导师、实习指导教师的 PC 页面只在“多身份”一节提到，不展开。
> 方法：代码静态审计（`frontend/src/modules/academicAffairs`、`frontend/src/modules/workbench`、`frontend/src/layouts`、`backend/app/core/permissions.py`）。**没有启动系统、没有登录点页面**。
> 用法：第六节是给 Codex 的施工包，一次做一包；第七节是可直接粘贴的提示词。

---

## 结论

老师觉得“臃肿”是对的，根因有三个：

1. **老师用的是“管理员页面 + 隐藏按钮”。** 老师的 17 个菜单项基本都指向教务处的管理页面，靠 `isAcademicTeacher / isAdminRole` 分支把管理功能藏起来。成绩录入页 90KB、28 处身份分支；教材页 64KB、15 处；预约页 49KB、17 处。老师看到的标题、提示、空状态，很多还是给管理员写的（例如“请先输入教师工号”“课表批次”“正式方案 #id”）。
2. **按“业务模块”组织，不按“老师的一节课、一门课”组织。** 同一门课的确认、名单、考勤、成绩、教材、调停课分散在 6 个菜单组的不同页面，老师得自己记“这件事在哪个菜单”。
3. **界面写的是开发者语言。** “回读”“原命令”“正式事实”“冻结名单版本”“生效策略 LATEST_FORMAL_SOURCE_V1”“来源新鲜度”“数据库原子门禁”“不再存在第二套点名事实”等直接展示给老师。

改造方向：**给教师单独一套薄页面（教师端），菜单从 17 项收成 5 项，所有操作围绕“今天的课”和“我的课程”展开；管理页面里的教师分支全部删掉。**

## 一、现状地图

### 1.1 老师登录后有两个“首页”

| 入口 | 位置 | 内容 |
|---|---|---|
| 统一工作台 | `/workbench`（登录后默认进这里，`router/index.js:181`），配方 `workbenchRecipes.js` 的 `ACADEMIC_TEACHER`“任课教师工作台” | 待办数字 + 待录成绩磁贴 + 课表积木 + 4 个快捷入口 |
| 今日教学 | `/admin/academic-affairs/teacher/today`（教务中心默认页，`academicTeacherNavigation.js`） | 学期责任进度 + 5 个指标 + 今天的课 + 我的待办 |

两处都有课表和待办，数字口径不同（一个读 `/todos/summary`，一个读教务工作台接口），老师不知道该看哪个。

### 1.2 侧栏菜单（`academicTeacherNavigation.js`）：6 组 17 项

| 组 | 菜单项 |
|---|---|
| 我的教学 | 今日教学、教学任务确认 |
| 我的课表 | 个人课表、我的调停课记录 |
| 课表查询 | 班级课表、教室课表、教学班课表、周课表、学期课表（**5 个独立页面**） |
| 成绩与考勤 | 成绩录入与提交、成绩更正申请、课堂考勤 |
| 教材与资源 | 教材选用、教室预约、实训室预约 |
| 教学资料 | 培养方案、课程库 |

外壳标题是“××学校 · 管理端”（`AdminAcademicAffairsLayout.vue` 的 `brandTitle`），网址都在 `/admin/...` 下。

### 1.3 后端给了权限、PC 却没有入口

`backend/app/core/permissions.py` 给 `ACADEMIC_TEACHER` 授了下面这些权限，但教师 PC 菜单里**没有对应入口**（部分只在移动端有）：

| 能力 | 权限码 | PC | 移动端 |
|---|---|---|---|
| 缓考审批（教师节点） | `academicAffairs.deferredExam.review` | 无 | 有（`teacher/exam-defer`） |
| 免修审批（教师节点） | `academicAffairs.exemption.review` | 无 | 无 |
| 本人课程选课名单 | `academicAffairs.selection.rosterView` | 无 | 无 |
| 监考安排 + 考场异常登记 | `academicAffairs.exam.view` / `exam.recordAbnormal` | 无 | 有（教务中心“我的监考”） |
| 本人评教结果/申诉 | `academicAffairs.evaluation.view` | 无 | 有（`teacher/evaluation`） |
| 工作量申报 | （PC 只有管理员的“工作量申报审核”页） | 无 | 有（`teacher/academic-affairs/workload`） |

## 二、问题清单

严重度：**高**＝老师办不顺或会出错；**中**＝明显费劲或看不懂；**低**＝体验细节。

## 三、目标设计

### 3.1 原则

1. **教师端独立。** 新建 `frontend/src/modules/teacherDesk/`（名称可调），网址 `/teacher/...`，外壳标题“××学校 · 教师工作台”。只放教师页面，复用现有接口和公共组件，**不复用管理页面**。
2. **围绕“课”。** 一切操作从“今天的某节课”或“我的某门课”进入。
3. **一屏一件事。** 列表页只有列表，办理在抽屉里完成，办完回到原位置。
4. **默认值替老师做决定。** 点名默认全到；成绩构成、截止时间由教务定好，老师只填分。
5. **只说老师听得懂的话。** 不出现 ID、版本、正式/回读/命令/事实等词。

### 3.2 新菜单：5 项

```
教师工作台
├─ 今日            ← 唯一首页（登录后直接进）
├─ 我的课表        ← 周视图 / 学期视图 / 查其他课表（班级、教室）
├─ 我的课程        ← 本学期我教的每门课；点进去是“课程页”
├─ 我的申请        ← 调停课、成绩更正、教室/实训室预约、工作量申报，统一列表
└─ 查询            ← 培养方案、课程库、校历（低频）
```

审批类（缓考、免修）不单设菜单，进“今日 → 待我处理”；监考进“今日 → 本周安排”和“我的课表”。

### 3.3 页面设计

**① 今日（替代 `/workbench` 的任课教师配方 + `teacher/today`）**

- 顶部一行：日期 · 第 N 教学周 · 校历状态（节假日/调休时说明“今天不上课”）。
- **今天的课**（按节次排列）。每节课一张卡：时间、课程、班级、教室、人数；按钮：`点名`（已点显示“已点名 43/45”）、`学生名单`、`调课/停课`。
- **待我处理**：按截止时间排序，跨类型（确认教学任务、录成绩、缓考审批、免修审批、教材申报、退回的申请）。每条一个动作按钮，直接打开办理抽屉。
- **本周安排**：监考、成绩提交截止、教材申报截止、已批准的调课/补课。
- **我的申请进度**：最近 5 条，显示“学院审核中 / 已通过 / 被退回（原因）”。
- 删除：学期责任接力面板（B1）、开发说明（B2）、指标磁贴（和待办重复）。

**② 我的课表**

- 默认本周周视图，可切学期总表；周次切换在表头。
- 点课位 → 右侧抽屉：这节课的信息 + `点名` `学生名单` `调课` `停课` `补课`。**周次由点击的那一格自动带入**（解决 C2）。
- 第二个 tab“查其他课表”：类型下拉（班级/教室/教学班）+ 搜索框，一个页面替代原 5 个查询页。
- 右上角“打印 / 导出本学期课表”。

**③ 我的课程 → 课程页**（新增，核心）

“我的课程”列表：每门课（教学任务）一张卡，显示班级、人数、周学时、周次，以及状态标签：`待确认` `教材待申报` `成绩待录 · 截止 1 月 10 日` `已提交学院`。

课程页 tab：

| tab | 内容 | 取代 |
|---|---|---|
| 概况 | 教学任务信息；待确认时顶部显示“确认接受 / 有异议”两个按钮 | 教学任务确认页 |
| 学生名单 | 选课/教学班名单，可导出/打印点名册 | （新增入口，接口已有权限 `selection.rosterView`） |
| 考勤 | 本课程所有课次点名情况 + 学生缺勤次数排行 | 考勤统计页的教师部分 |
| 成绩 | 录入表（见下）；已发布后显示成绩与分析；某学生行“申请更正” | 成绩录入页 + 成绩更正入口 |
| 教材 | 本课程已申报教材、状态，`申报/更换教材` | 教材控制台的 selection tab |
| 调停课记录 | 本课程的调课/停课/补课历史 | 调停课台账（教师部分） |

**④ 成绩 tab 的录入表（重做）**

- **成绩任务自动生成**：教务开放成绩录入期时，系统为所有已就绪的教学任务生成成绩任务，比例和及格线来自教务设定。老师端**删除“新建录入任务”和比例输入**。
- 一张表：学号、姓名、各成绩项（列名就是“平时 40%”“期末 60%”）、总评（自动算）、特殊情况（缺考/缓考/免修/作弊下拉）。动态多项方案由教务配置时，老师看到的只是列多了几列，不出现“模式”概念。
- 键盘：回车到下一行，Tab 到下一列；支持从 Excel 复制一列直接粘贴；保留“导入 Excel”。
- **自动保存**：单元格失焦 1 秒后静默保存为草稿（服务端草稿），表头显示“已自动保存 · 14:32”。不再有逐行保存按钮和“先保存再翻页”。全班一页显示（职校班级通常 ≤60 人）。
- **提交前预览**：分数段分布、平均分、及格率、未录人数、特殊情况人数；有未录时提交按钮写“还有 3 人未录”。
- 提交后：“已提交学院审核”+ 下一步是谁；可下载《成绩登记表》PDF（签字用）。
- 截止时间只显示，不可设置（E5）。

**⑤ 点名（PC 与移动端同规则）**

- 从“今日”或课表课位点 `点名` → 直接打开本节课名单（若场次不存在，后台自动按正式课次创建，不让老师选任务/节次/日期）。
- **默认全部“出勤”**，老师只点缺勤/迟到/请假的人；学工已批准的请假**自动标为请假**并注明“学工请假”。
- 全班一页；标记先在本地累计，点“提交”一次发出。
- 提交后 48 小时内可修改，之后走更正申请（见第四节决定）。

**⑥ 我的申请**

- 一个列表，筛选：类型（调停课/成绩更正/教室预约/实训室预约/工作量）、状态。
- 新建按钮按类型打开抽屉。调停课抽屉：选好目标时间和教室后**自动检测冲突**（H2），显示“周三”而不是“周3”。
- 教室/实训室预约：日期 + 节次 → 直接列出空闲教室（每页 20 项，可按容量/楼栋筛）→ 点“预约”填用途提交。

### 3.4 文案与交互统一

- **禁用词表**（教师端模板中出现即测试失败）：回读、原命令、命令、只读核对、正式事实、事实来源、责任队列、冻结名单、名单版本、生效策略、来源新鲜度、待治理、待解析、持久化、原子、门禁、写链、投影、Manifest、ImportJob、服务端、接口、#{数字}、ID。
- **提交结果不确定时**：前端带幂等键提交；超时后自动按幂等键/业务键轮询最多 3 次；界面只显示“正在确认是否提交成功…”→“已提交”或“没有提交成功，请重试”。删掉所有“核对原命令”按钮。

### 3.5 多身份（第二阶段）

### 9.3 当前明确断点与优先级

**1. 高：缓考退回后只有重提，没有实际补正。**

- 场景：老师要求学生修改缓考说明或补证明，学生打开退回记录，只能点“确认补充完成并重提”。
- 证据：`StudentExamView.vue:31–32` 只读展示说明及处理意见；`:209` 起的重提方法未编辑原单。`portalApi.js:57` 不传补正内容。`academic_affairs_exam_service.py:1195` 的 `defer_resubmit` 只检查归属、状态、可选版本，再修改审核状态并写审计，没有更新说明或附件。
- 影响：原内容不变便重新进入审批，形成重复退回；“补材料重提”的审计名称不能证明材料已补交。
- 最小修复方向：原单补正界面接上后端补正命令，保留课程/学生/考试归属，携带版本；涉及证明文件时复用文件中心并记录变更。具体必交材料政策不能由助手新增。

**2. 高：学生免修原单补正未接入。**

- 场景：审核人退回免修申请后，学生在本人办理记录中只看到状态，无法修改原理由和材料再提交。
- 证据：`StudentMakeupView.vue:22` 的记录区只有展示；学生请求文件无免修重提方法，学生源码检索未找到免修重提消费者。后端 `student_portal/router.py:204` 已有原单重提路由，`academic_affairs_makeup_service.py:1286` 已支持本人原单理由与材料集更新。
- 最小修复方向：复用现有接口与文件能力补原单编辑，不重新创建申请，不重写审批状态机。

**3. 高：任课教师免修审核权限与电脑入口不匹配。**

- 证据：`permissions.py:289` 默认授予任课教师免修审核权限，但该角色权限块没有 `academicAffairs.makeup.view`；`academic-affairs.routes.js:162` 的免修所在控制台却要求此查看权限。教师 17 项导航也没有免修审核入口。
- 影响：仅使用默认任课教师权限时，既无常用入口，直接进入现有控制台也不满足路由权限。实际学校角色模板和账号是否有额外授权尚未核验。
- 最小修复方向：提供只覆盖本人审核节点的入口与相应读取权限设计，复用后端关系校验；不靠授予全校补重修管理权限解决。
- 缓考、监考、评教结果、选课名单同样不在当前教师导航中；它们是否存在其他可达待办需继续核验，不能一概认定后端未实现。

**4. 中：任务确认责任交接展示的现有检查失败。**

- `frontend/tests/academic-teacher-flow-closure-v2.test.mjs:339` 要求页面绑定当前责任人及下一责任人；当前模板未匹配，相关方法仍在页面中。
- 当前证据只能证明模板与合同不一致，尚不能判定实际业务状态机错误。后续结合页面设计检查是展示回退还是断言过期，不能直接删断言使测试通过。

### 9.4 交互规划：先补办理闭环，再收拢导航

1. **教师工作按实际身份组织。** 任课教师围绕今日课程和本人课程；班主任围绕所带学生与待审申请；毕设导师围绕指导学生及阶段；实习教师围绕指导关系及过程报告。切换身份保留目标对象，但重新校验权限，不将多个身份权限拼成一套全能页面。
2. **学生工作按当前事项组织。** 首页优先显示今天上课、待提交、退回待补、即将截止和最新结果。办理入口直达原课程、原申请、原材料，避免每次重新选择。
3. **一条申请形成一条可追踪记录。** 详情展示申请内容、当前进度、当前责任人、处理意见、下一步。退回提供“修改并重新提交”，已提交提供“查看进度”，终态提供结果或下一业务入口；不能只改状态文案。
4. **提交后必须确认对方接收。** 成功提示需要对应业务记录；审核完成还要核对下一节点队列，发布完成还要核对学生结果。超时不能盲目再次提交，失败保留输入。
5. **共用业务对象，复用现有能力。** 课程使用教学任务及具体课次；申请使用原单；毕设使用学生、批次和版本；实习使用原实习关系。优先修现有入口和契约，暂不新建大而全“我的课程”模块或通用流程引擎。
6. **菜单收拢放到链路验证后。** 可向教师“今日、课程与课表、待办、申请进度”靠拢，学生保持业务中心但加强待办直达。最终栏目数和旧入口退役清单在实测后确定；本轮不删页面。

每条流程至少记录以下结果，任一缺失不能标“全通”：

- 退回链：原因可见→原单可编辑→重新提交→审核端看到修改后的版本。
- 边界链：另一学生/无关系教师不能查看或操作；过期、重复、版本变化有明确结果。
- 持久化：提交后刷新、退出重进仍是同一结果；附件与审计关联正确。
- 业务结果：发布成绩进入学生成绩单，调课进入双方课表，教材签收对应实际发放，申请审批不冒充最终办理完成。
- 页面交互：电脑实际显示、错误与空状态、返回位置、未保存输入保护；窄屏按项目规则单独检查。
