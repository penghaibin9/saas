- [ ] **真实权限拦截（RBAC 后端）** —— 现在后端权限拦截"近空",等于门没锁死。所有业务端点接入统一鉴权 + 数据范围 + 越权 403 + 审计。分支 `system-admin-role-bootstrap`（已发提示词③）。

    - 2026-07-12 进度②（SEC-5 收口）：**新学工面 `/api/v1/student-affairs/*` 全部端点已接入** `studentAffairs.<域>.<动作>` 细粒度权限（`backend/app/api/v1/student_affairs.py`：dashboard/班级/辅导员考评/请假/困难/资助/违纪/画像/谈话/家校/归档 共 79 端点 `require_staff`→`require_permission`；仅 `/aid/.../reveal` 保留 `require_staff` 因授权+越权审计由服务层 `reveal_family_economy` 负责，网关不得短路吞审计）。`COUNSELOR` 角色已按「本班范围广读 + 班级/请假/风险/谈话/家校可操作、困难/资助/违纪只读、无 sensitiveView」实例化（`app/core/permissions.py`）。证据：8 套 affairs 测试真 MySQL **61 passed**（含各域 `counselor01` 跨范围 → `NO_DATA_SCOPE`、`aid/reveal` 越权 → 403 且落 `SENSITIVE_VIEW` DENY 审计）。
    - ⚠️ **仍缺（阻断）· SEC-6 旧「在校服务」面越权**：`backend/app/api/v1/campus_service.py`（`/api/v1/campus-service/*`，前端仍用于 班级/请假/学生主档/资助grants/违纪disciplines/宿舍/工单）约 30 端点仍用 `Depends(get_current_user)`——**只认证、不鉴别身份**（`app/core/security.py:get_current_user` 不校验 `userType`，弱于 `require_staff`，学生令牌不被网关拦截）。这是与 SEC-5 同域、更严重的越权面。上线前必须逐端点接 `campusService.*`（或收敛/重定向到已加固的 `/student-affairs/*`）。运行期学生实际可达深度待实测；代码事实已确证。
