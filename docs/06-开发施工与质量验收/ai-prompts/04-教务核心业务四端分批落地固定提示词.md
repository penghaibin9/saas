| 第四批：完成选课及上课变更 | 选课管理 → 调停课 | 选课/退课/补选、容量和冲突控制、名单与个人课表同步；调课/停课/补课申请审批、生效、资源释放/占用及受影响师生通知 |
| 第五批：支撑日常教学 | 课堂考勤 → 教材管理 → 教学评价 → 教学质量 | 实际课次点名及异常核验、教材选用审核和领用、评教与评价结果、督导听课/巡课/检查、问题整改与复核 |
| 第六批：完成考试与成绩闭环 | 考务管理 → 成绩管理 → 成绩审核发布更正 → 补考重修缓考免修 | 考试资格与名单、考场座位、监考巡考及通知；成绩暂存/提交/审核/发布/复查/更正；补考、重修、缓考、免修分别衔接资格、安排、成绩及学分 |
| 第七批：处理学业变化和风险 | 专业分流 → 学籍异动 → 学业预警 | 分流与学籍异动申请/审核/生效/留痕；衔接方案、班级、注册、选课与考试范围；依据有效学业结果识别风险、通知、跟进并复核 |
| 第八批：毕业与学期收口 | 毕业资格审核 → 教务归档 → 教务统计 → 教务看板 | 毕业预审、缺项补正、关联结果复核、终审及证书；学期完整性检查、归档封存、统计下钻、工作量及报表；统一收口教务待办与今日教学运行 |

“教务看板”和公共工作台的相关待办、课程、考试及结果提醒随各模块逐步接通，最后统一收口，不等到第八批才展示已接通事项。学期、组织、学生主档、任课关系、教学班名单等前置依赖在每个模块开工前核验并复用；后续模块尚未完成页面适配，不代表可以用模拟基础数据代替真实依赖。

批次表示页面完整适配的默认安排，不是业务发生时间：专业分流、休复学等可能是本学期开课/选课的前置，教材须满足实际开课使用时间，缓考须在相关考试前受理。遇到这类依赖应提前核验并接通所需能力；若必须完整建设另一二级模块才能继续，记录断点后调整顺序。排课和选课采用先排后选、先选后排或分阶段安排，依据学校现行规则和系统契约处理，不由本表强制选择。

选择本次模块时按以下顺序判断：用户明确指定 → 当前未完成模块 → 阻断当前主线的前置模块 → 默认顺序中的下一项。没有续接记录时，先用当前路由、已有施工记录和关键接口形成简短的主线现状图；优先解决无法开课、无法查课表、无法选课、无法录入/发布成绩等真实断点。若没有优先断点，再按表从最早未完成模块推进。无需为普通施工排序反复请求用户拍板，但应说明采用顺序及其依据。

排期名称是产品分组，不能据此臆造数据库域或接口。以实际 `navPlan`、路由和施工包映射真实二级边界；共享页面、查询参数页签和别名入口也要纳入全部三级页面核验。新出现的二级模块登记后按依赖安排，不静默遗漏。编写时尤其要保留以下边界，执行时核对是否已有有效变更：

- **教学计划**按既有收编决定复用培养方案、教学任务和教务归档，不另建一套教学计划业务真值。
- **排课管理、课表管理、选课管理、调停课**共享开课、名单、时间和资源事实；分别完成各自页面及动作，不各建一套课表或选课结果。
- **成绩管理、成绩审核发布更正、补考重修缓考免修**先统一契约和结果消费关系，再按二级模块逐个适配；录入成功不等于发布，免修审批通过不自动等于已获学分。
- **课堂考勤**先核验现有点名来源与教务统计消费关系；教务统计页不另造签到系统，学工请假也不在教务重复建立。
- **学籍、实习、毕设、处分、财务结清**按既有主责中心和授权接口衔接。无法取得真实结果时明确“未接入/待核验”，不得默认为已满足毕业条件。

### 2.1 核心流程与岗位交接

教务不只有申请审批。按当前模块使用配置、编排、查询、批量录入、审核发布、现场记录或结果核验等合适的交互方式，不把所有业务套成相同表单。以下是产品流程规划，具体节点和审批人以有效规则为准：

| 核心流程 | 主要岗位与交接 | 必须能确认的结果 |
|---|---|---|
| 从培养要求到正式上课 | 教务/学院维护有效方案与开课安排 → 分配教师和教学班 → 排课、核验冲突并发布 → 师生查询 | 学生知道何时、何地上什么课；教师看到正确课次和授权名单；课程、名单与资源事实对应 |
| 从选择课程到名单生效 | 教务开放批次和规则 → 学生选退补选 → 服务端核验资格、容量和冲突 → 结果进入个人课表及教师名单 | 学生能确认最终选课结果，教师使用有效名单，重复或并发提交不造成重复记录和容量超限 |
| 从教学变更到实际执行 | 教师提出调停补课 → 授权岗位审核 → 按契约使安排生效 → 师生接收变化 → 现场教学与考勤消费新安排 | 审批结果、课表、资源占用、通知和实际课次一致；保留原安排与变更记录 |
| 从考试安排到学生成绩 | 教务组织考试 → 师生查询各自任务 → 授权教师录入和提交 → 学院/教务按规则审核发布 → 学生查分或申请复查 | 正确学生、课程和考试结果对应；学生只看到可公开结果；更正能追溯并衔接学分与后续判断 |
| 从学业问题到毕业结论 | 学生/教务办理适用异动、补缓重免和学分认定 → 预警与跟进 → 毕业条件核验、补正和终审 → 证书及归档 | 不达标和缺数据原因可解释，有可执行的下一步；最终结论引用真实、有效且可追溯的依据 |

首次只做足以确定施工顺序的主线核验，详细关联审计仍聚焦当前二级模块。验收分两层记录：**当前模块的完整办理过程**与**跨模块主线的实际接通程度**。单模块通过不等于整条教务主线通过；主线存在断点时明确责任模块和下一步，不能把每个页面分别打开当作流程完成。

### 3.1 每个模块的关联代码审计与施工前置门

**执行顺序固定为：模块及关联代码审计 → 真实流程与问题清单 → 依赖顺序和设计就绪 → 四端内容页面设计制作及后端修复 → 联调验证 → 记录收口。** 在审计和必要设计门禁完成前，不按原型的假定状态直接改正式业务。

沿每个适用三级页面和动作追踪实际调用链，至少覆盖：

- 四端入口、路由、菜单、工作区组件、课表/名单/成绩表、表单/附件、接口适配及状态展示。
- 后端 router、schema、service、状态转移、数据模型/迁移、事务、幂等和版本冲突处理。
- 身份与租户、角色与审批节点、数据范围、学院/专业/年级/行政班/教学班、任课与选课关系、学籍及注册状态、敏感字段。
- 学年学期、校历、周次节次、培养方案版本、课程及学分学时、批次/名单/发布状态等当前模块适用的基础事实。
- 上游触发条件、下游结果使用方、待办、通知、文件绑定、审计、统计、归档、定时或异步任务。
- 同一接口的其他调用方、旧路由兼容、适用测试和安全测试环境；不只审计前端当前打开的页面。

审计结论写入当前模块施工包或施工记录，至少包括三张可复核清单：

1. **代码关联清单：** 页面/动作 → 接口 → 服务与模型 → 上下游调用方 → 测试，带当前基线、真实路径和 symbol/行号。
2. **实际流转清单：** 发起条件 → 当前责任人与节点 → 可执行动作 → 下一状态 → 生效或发布条件 → 四端可见结果；分别记录正常、退回、撤销、终止、超时、锁定和冲突等实际存在的分支。课表查询等只读动作按数据来源、可见范围和刷新规则记录，不硬套审批流。
3. **问题及施工顺序：** 问题证据、受影响端/动作、类型（代码错误、流程断点、页面缺失或设计改进）、优先级、前置依赖、修复落点和验证方式。阻断注册、开课、发布、选课、考试资格、成绩落库和结果消费的缺陷优先处理。

明确区分“代码阅读确认”“已复现”“待运行核验”，未执行的链路不能写已经走通。检查空实现、假成功、字段与状态不匹配、错误审批节点、学期串用、名单错位、重复提交、容量超卖、成绩提前可见、丢失反馈、敏感信息越界和成功后下游未接续等问题，但不得预设它们一定存在。

按审计结果安排当前模块内部的依赖顺序：通常先校正契约/状态与必要后端缺陷，再实现四端页面，最后验证课表、名单、成绩、通知、台账和跨模块结果；已有完整实现直接复用。四端设计清单应在施工前同时列清，不能先交完 PC 就把两套小程序留作未登记的后续事项。

### 4. 当前模块必须形成的设计与实现

先将各三级页面和动作逐一映射到真实流程：发起人、前置条件、学期/批次/名单、材料、处理人及范围、当前节点、允许动作、下一节点、时限、生效与发布条件、结果去向、异常分支、通知与审计。明确“已有可复用”“需要修改”“缺失待补”，标明代码或外部依据；学校政策参数不凭经验硬编码。

四端按职责覆盖：

- **学生 PC：** 本人学籍与注册、培养与学业信息、选课退课、个人课表、考试安排、已发布成绩、补考/重修/缓考/免修及复查申请、评教、预警与毕业审核结果；适合 PC 的长表单、附件、完整记录和打印下载。
- **学生小程序：** 今日/本周课程、选课和进度、考试及调停课通知、成绩查询、便捷申办与补交、评教、适合手机的确认操作。
- **教师 PC：** 授课任务和课表、教学班名单、成绩录入、本人申请与工作量；按岗位授权提供教务工作队列、审核发布、学期与批次配置、排课考务、台账、统计和适用的 Excel 操作。
- **教师小程序：** 今日课程及考试任务、授权名单和点名入口、调停课申请、授权节点审批、材料与意见、巡课/监考/教学检查等现场记录；成绩等敏感写操作按现有授权、锁定和复核规则判断适用性。

不是每个教务管理功能都要放到学生端或手机端；不适用的端和动作明确说明理由。基础配置模块的学生端通常消费已生效信息，不给学生配置权限；移动端可以提供与任务相符的查看或简化操作，但不能以跳转 PC、手机框原型代替适用页面。复杂排课、批量录入等是否移动化依据实际任务和施工包决定。

四端共用同一业务记录、服务端状态和权限裁决，不在各端另存一套流程真值；一端处理后，其他端按现有刷新/消息机制更新，过期页面提交必须得到明确冲突反馈。区分管理端草稿、教师可见版本和学生已发布结果，不为追求“四端同步”泄露尚未发布的课表或成绩。

使用“三级业务/动作 × 四端页面”的覆盖表统一设计和跟踪。各适用格必须列出真实路由、内容布局、字段与操作、异常状态、接口和验证结果；不适用格写业务理由。不能用换壳、跳转未适配旧页面、单张通用空模板或仅一端截图代替四端正文设计。页面可以复用合适的成熟组件，但需按本次流程完成交互适配和实际检查。

页面实现至少覆盖：

1. **列表/工作队列：** 紧凑筛选、清楚的学年学期与批次、中文状态、当前责任人、待处理事项和必要的主操作；回到列表时按业务需求保留筛选、分页和滚动，不用全局缓存冒充完整状态恢复。
2. **申请/编辑/录入：** 字段分组、条件校验、真实文件上传及补正反馈。保存/提交失败保留内容，阻止重复提交；需要草稿时核验或实现真实草稿能力，明确未保存状态，不把页签恢复称为表单恢复。成绩、课程和名单表格明确可编辑单元格、锁定原因、校验位置及保存范围。
3. **详情/审批/发布：** 业务信息、材料、名单、处理记录与状态时间线清楚；按角色及当前节点提供动作。服务端成功之后才更新结果，退回补正与终止性驳回分开；审核冲突不能显示成功。发布或变更前显示实际影响范围、适用版本与必要检查结果，不只给一个无上下文的“确认”。
4. **课表与安排：** 展示适用日期、周次、节次/时间、课程、地点、授课或监考任务及调停变化；支持当前任务需要的班级/教师/学生/教室视图。未发布、当天无课、学期未配置、请求失败分别处理。手机优先可读的日/周课程列表，保留切换与详情。
5. **全状态：** 加载、空数据、失败与重试、无权限、只读/到期、未开放/未发布/已锁定、正常和处理中；不能将请求失败显示为数量 0 或空列表。界面全中文，状态/异常经统一展示适配，不透传内部枚举、权限码或技术异常。
6. **相关公共链路：** 附件、通知、待办、敏感字段、审计、Excel、打印、统计及归档分别说明真实落点或不适用原因。成绩通过审核不冒充已发布，教材费用台账不冒充支付到账，毕业预审通过不冒充已发证；消息投递失败不抹掉已成功提交的业务。

优先现有公共组件、框架原生能力和最小封装。两套 PC 复用一致的视觉规则，不共享角色特权业务逻辑。教师小程序的改造要在当前模块中形成真实 uni-app 页面；HTML 手机框、H5 截图不能证明微信运行正常。

### 4.1 便捷性与实际办事体验

以下是逐模块适用性检查项，不代表当前代码都存在缺陷。根据实际流程选择实现或复用；不适用项写理由。每次至少核验首次办理、熟练重复办理、出错后继续办理三类情境，不能只检查页面能否打开。

| 容易遗漏的场景 | 设计与实现要求 |
|---|---|
| 不知道从哪里办 | 常用业务可从工作台/待办、菜单或搜索到达；支持“查课表、查成绩、选课、申请缓考、提交成绩”等中文业务名及合理别称。同一事项的不同入口指向同一记录，不要求用户记住两字菜单含义。 |
| 不知道能否办理 | 填写前说明资格、开放/截止时间、必需材料、剩余容量等适用条件。未注册、无开课任务、名单未锁定、批次未开放、没有审批人等情况与“没有记录”分开，给出符合权限的处理入口或明确联系岗位；不编造学校制度。 |
| 学期、班级或课程选错 | 明确当前学期与查看学期，筛选和编辑对象携带正确上下文。行政班、教学班、合班和个人选课名单按真实含义展示；切换身份/学期/课程后重新核验权限和待保存内容，不把上一门课的数据提交到下一门课。 |
| 重复填已知信息 | 当前身份、有效学期、本人基础信息、授课课程、已选教学班等从授权数据合理带入或供选择。主档字段按权限只读或走原变更流程；不在申请里偷偷改主档，不把敏感信息写入浏览器持久存储以追求方便。 |
| 不清楚该改哪一项 | 必填、格式、分值范围和材料限制在输入处说明；表格错误定位到具体行列，保留其他输入。退回原因与待补内容对应；选课冲突能看到允许展示的冲突课程和时间，不只给“操作失败”。 |
| 提交后不知道结果 | 区分已暂存、已提交、待补正、审批中、已发布、已生效、已锁定等真实状态；说明当前处理岗位、可见记录、下一步和适用时限。“审批通过”与课表生效、成绩发布、学分认定分别展示。 |
| 连续处理很多事项 | 按合理范围保留筛选、分页、滚动及返回位置；支持处理下一件。真实业务和接口支持时提供批量录入/操作与常用意见，明确范围、条数、影响和逐项失败结果；不能把当前页操作静默扩展到整校数据。 |
| 中途被打断 | 切页、返回、登录过期、断网和上传失败时给出准确状态与恢复路径。长表单和成绩录入需要草稿时使用真实受控保存，未支持跨端草稿就明确说明。写请求超时先核对结果或使用幂等机制，避免重复选课、重复提交成绩或重复生成批次。 |
| 通知收到却办不了 | 待办与普通消息分清，已读不等于办结。通知进入对应端真实详情；登录后在授权范围内恢复目标。旧通知遇到改课、考试变更、已办结或权限变化时说明原因，不跳空页；未经真实授权不能许诺微信通知必达。 |
| 手机办理不顺手 | 检查课表阅读、拍照/文件选择、预览返回、长表单和成绩输入、键盘遮挡、底部安全区及网络中断。四端相同动作名称与状态含义一致；确保字号、焦点、点击范围和放大显示可用，状态不能仅靠颜色区分。 |
| 导入导出、排课和统计时间长 | 复用现有 Excel/异步任务能力展示真实进度或明确处理中状态；可找到完成结果、失败原因和重试入口。成绩导入区分预检与正式写入，排课任务区分求解结果与课表发布。按规模分页查询，典型操作在独立测试环境测量，不凭主观写“很快”。 |
| 新学期或换老师后卡住 | 核验学校时区、学年学期、开学日期、教学周、节次、节假日调课、批次开放、任课关系和审批岗位。规则来源不明不擅自设值；人员交接复用授权转派能力，不自动跳过审批或给新老师开放全校数据。 |
| 新版接入后旧记录变了 | 除新建记录外，验证历史课表、旧成绩、在途申请、已锁定名单和旧链接。培养方案版本、换班、分流、休复学、教师调整后的在途业务依现有契约处理，保留必要快照，不按新默认值重写历史事实。 |

这些要求是本项目的设计与验证检查项，不构成学校制度、外部厂商能力或既有实现的证明。正式对标和通用可用性参考按当前模块的有效证据包核验；不得把原稿中的查阅日期或结论直接写成此次重新核验的结果。

### 4.2 必要配套随当前模块完成

关联审计中把配套项分为两类并明确记录：

- **当前办理必需：** 缺失会导致用户找不到入口、填不完、无法提交/审批/发布、课表或名单不同步、看不到结果、无法继续办理或历史记录断流。包括直接关联接口和中文适配、必要角色/范围配置入口、学期/批次前置提示、文件与材料、待办通知落点、结果台账、失败恢复、历史兼容及相关公共组件缺陷；在当前模块内一起完成或明确阻碍，不能因为“原计划只改页面”而遗漏。
- **独立扩展：** 与当前办理无直接关系的新业务、整套基础平台重建、第三方商业服务或额外插件，登记为后续建议，不自动扩大施工。已有公共能力优先复用；确需修改公共组件时，说明调用方影响并检查其他已接入模块。

“配置入口”是交付学校人员按授权维护本业务配置的能力，不等于代替学校更改真实审批政策、选课资格、成绩权重、毕业规则、角色授权或生产数据。前置配置缺失时，先查真实原因和已有入口，必要时补充可操作提示；重大业务决定仍交用户明确。

### 4.3 教务专项业务一致性

以下规则逐模块判断适用性，按有效学校依据、既有契约和真实代码核验；不得为了凑齐表格新建业务。每项适用规则都要能追溯到页面、服务端校验和验证证据。

| 业务边界 | 必须核验的事实与结果 |
|---|---|
| 学期、校历与时间 | 当前学期与查询学期区分；周次、单双周、节次、跨日期及节假日调整口径一致。变更校历不得静默重写已发布安排和历史考勤。 |
| 学籍、注册与异动 | 学生主档、学籍记录和注册结果按既有主责分工处理；异动审批与生效日期区分。休复学、转专业/班级、退学等适用动作对在途选课、课表、考试及毕业范围的影响有真实规则和记录，不能按新身份抹掉旧记录。 |
| 培养方案、课程与名单 | 方案版本绑定适用年级/专业/学生范围；课程性质、学分学时和考核方式有依据。行政班不能直接冒充教学班，名单来源、选退课变化和锁定规则必须明确；考试及成绩名单消费有效版本。 |
| 排课、发布与调停课 | 核验教师、教学班/学生、教室、容量、周次节次及资源限制等适用冲突。预检不能替代保存或生效时的服务端复核；排课草稿不自动向学生发布。调停课审批后按契约更新有效安排和资源占用，保留原课次及变更记录，并验证受影响师生通知。 |
| 选课与容量 | 核验开放时间、资格、先修条件、学分限制、冲突、容量、退补选窗口等已定义规则。并发选课不能超容量，重试不能重复占位；退课释放名额与名单/个人课表同步按真实契约执行，锁定后变更不能绕过授权。 |
| 考勤与请假 | 以有效授课场次和对应名单为依据，核验迟到、早退、缺勤、请假及更正口径。消费原有点名/请假结果，不重复建来源；补录、更正及其对学业预警的影响有授权与留痕。 |
| 考试与补缓重免 | 核验报名/考试资格、名单版本、时间场地、座位容量、监考冲突和考试变更。补考、重修、缓考、免修分别按现有规则衔接考务、成绩及学分；不把批准申请直接当作考试通过或学分达成。菜单含“毕业清考”等名称不代表学校已启用该政策。 |
| 成绩、复查与更正 | 区分暂存、提交、学院审核、教务发布、复查、更正和归档；任课教师只能处理授权课程及名单。分值、权重、精度、四舍五入、缺考/作弊/缓考等特殊标记、补考重修计分、课程替代与学分认定按有效依据处理。未录入不等于 0 分，未发布成绩不能向学生暴露。更正保留原值、原因、审批及版本，核验成绩单、学分、预警和毕业判断的受影响结果。 |
| 教材、评教与质量 | 教材需求基于真实课程和名单，费用与支付、库存与采购边界按现有范围处理。评教资格与实际授课关系一致，匿名性及结果可见范围按有效规则实现，不泄露可识别评价者的信息；质量问题应有责任人、整改、复核及留痕。 |
| 学业预警与毕业资格 | 预警和毕业判断使用适用方案版本、有效成绩及真实关联结果；缺少数据、数据异常和确实不达标分别说明。毕业预审与终审分开，显示可理解的未达条件及下一步。上游成绩或实践结果变更后依契约复核，已封存结果不得悄悄覆盖。 |
| 统计、工作量与归档 | 列表、导出、看板和归档明确同一学期/批次、权限范围、统计时间和版本口径；工作量核验合班、拆班、多人授课、调停课等适用规则，不能简单按课表行数冒充正式工作量。归档检查完整性、保留快照和受控更正，不把实时查询冒充封存。 |

### 5. 真实权限与验证

只有资料环境时，下列内容用于设计验收场景及标明待验证项；只有实际执行后才能记录验证结果。不能把设计中“应允许/应拒绝”的场景直接标成测试通过。

沿用后端租户、模块授权、角色权限、数据范围、业务关系、敏感字段、状态机和版本/并发检查。学生仅处理本人允许的事务；教师只能处理被授权的课程、教学班、考试任务、范围与节点，不能把“能看教务菜单”当成能修改成绩、发布课表或审核毕业。未发布成绩、其他学生信息、评教身份及内部审核材料不能随学生同壳暴露。权限矩阵及正反向测试必须与当前三级页面和动作对应。

在独立测试环境验证当前模块的实际正常及适用异常链路：创建/申请/录入、暂存、提交、受理、退回补正、重提、驳回、撤回、审核、发布或生效、锁定、更正、超时、重复或并发处理、最终结果、通知及台账。不存在的动作标不适用，不为凑流程增加接口；只读模块验证真实来源、授权范围、上下文和异常展示。

至少验证本人/他人、任课/非任课、角色/节点、学院/班级/教学班范围、跨租户、敏感信息的允许与拒绝场景；涉及相应业务时验证：

- 一个端完成操作，其他适用端读取同一记录的正确状态；过期页面提交得到冲突反馈。
- 切换学期、身份和课程后的名单及权限隔离；历史和在途记录仍可正确解释。
- 已发布与未发布课表/成绩的可见性；调停课实际生效后的课程、资源及通知。
- 选课重复提交、并发容量竞争、退课释放与名单同步。
- 成绩暂存和提交失败后的数据保留、审核锁定、发布、更正及下游重算/复核。
- 考试安排冲突、补缓重免结果衔接、毕业审核遇到缺失或变更数据时的真实行为。

先跑最小相关检查，再按改动风险扩大；命令以各工程 `package.json`、后端说明和 `e2e/README.md` 为准。改动四端时运行相应前端测试、lint（存在时）、构建；小程序检查 H5 与 mp-weixin 构建，并区分构建、浏览器检查、微信开发者工具/真机验证。后端和迁移在独立 MySQL 测试库验证，真实 E2E 必须满足项目安全门。每项记录实际命令、退出码、数量、环境和本次工作区/候选基线，不引用旧通过记录替代当前验证。

原型、mock 和隔离组件样例只用于设计或组件检查，不能当真实业务验收。登录态或安全测试环境缺失时，完成可以独立进行的代码与检查，记录未验证项；需要用户配合时请其在测试页面登录，不索取聊天明文密码，不绕过认证，不试用生产账号或数据库。

每个模块额外提交一份简短的“实际办事检查”：分别以学生、任课教师、教务经办/业务管理员等适用身份说明从哪里进入、需要填写什么、哪里容易出错、办完去哪里；不适用身份写清理由。四端使用同一组安全测试记录检查交接；记录多余重复输入、无必要跳转、返回后状态丢失和没有下一步的页面，并修复已确认问题。附经过实际执行的简短步骤和结果，区分智能体走查与真实用户试用；未做真人测试不能声称普通师生已验证。

最终给用户可直接打开的测试入口、适用身份和少量具体操作步骤，让用户评价“是否看懂、是否顺手、是否符合学校实际”。路径、字段、权限、数据库和技术回归由智能体核验，不要求用户自己找技术遗漏。

- 网页版项目资料及本地资料的实际读取范围、版本与引用定位；尚不可访问的依据、文档冲突、跨环境转交内容及待代码核验项。

遵守根规则的 `planned/partial/implemented/verified/deliverable/deployed` 含义。未提交工作区检查要注明，不标成候选 commit 已验证。模块未完成时下次继续该模块；没有安全测试环境不抹掉剩余验证，也不反复执行已经通过且未受后续改动影响的检查。

最终先说明“本次完成什么、还缺什么”，提供实际入口、关键改动、实际测试和四端验证结果、数据库/迁移/权限/旧路由影响、当前 Git 状态、下一模块。截图明确是真实测试业务、隔离样例还是原型。用户应能按完整办理过程验收，而不是代替智能体核对技术文件。

本提示词不授权自动提交、推送、部署、生产操作、删除真实数据、不可逆迁移、认证/权限核心重构或大批删除旧文件；遵守根规则中对应的明确决定要求。不得因当前任务量大静默缩减当前二级模块的三级页面。默认顺序执行，不自动创建其他用户任务或并行智能体；模块切换的任务边界按适用根规则执行，记录交接入口，不擅自批量开任务。

现在先定位当前环境能读取的网页版项目资料、本地资料和代码，再根据教务续接记录与核心流程选择当前模块。优先续完已在推进的模块；没有记录时先检查“开学准备—培养与开课—排课选课—教学运行—考试成绩—学业预警与毕业审核”的关键交接，复用真实可用的前置能力，选择最先阻断实际办事的二级模块。没有优先断点时按默认批次从最早未完成模块开始。有代码环境则完成该模块适用页面的设计制作、关联缺口修复、验证与收口；只有资料环境则完成当前模块有依据的设计与交接，明确待代码核验和未实现项。最后写清主线还缺什么及下一模块。
