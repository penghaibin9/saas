# 二级模块外部对标证据包标准模板

> 作用：由具备联网能力的执行者查证原文并落盘，供不能联网的 Claude Code / 子智能体可靠复用。
>
> 一个证据包只服务一个二级模块及其全部三级模块；禁止跨二级模块用一份宽泛证据包凑数。

---

## 0. 包身份

| 字段 | 必填内容 |
|---|---|
| 证据包状态 | `verified_external_evidence_v1 / partial / invalid` |
| 中心/二级模块 | `<中心> / <二级模块>` |
| moduleKey | `<稳定英文key>` |
| 覆盖三级模块 | `<逐项列出>` |
| 核验执行者 | `<Codex/其他具备联网能力的执行者>` |
| 核验方式 | `<实际打开HTML/PDF/采购附件/官方文件>` |
| 首次查阅日期 | `YYYY-MM-DD` |
| 最近复核日期 | `YYYY-MM-DD` |
| 适用代码基线 | `<commit；纯产品证据可写不绑定>` |

标准路径：

`docs/03-业务模块设计/<中心>/施工包/外部对标证据/<NN>-<二级模块>-外部对标证据包.md`

---

## 1. 证据等级

| 等级 | 来源 | 用法 |
|---|---|---|
| A | 国家机关/教育主管部门原文、高校官网使用/培训/验收、正式采购结果或采购文件 | 正式事实依据 |
| B | 高校项目人员署名行业案例、上市公司正式披露、公开产品手册 | 可作为正式能力证据，但企业效果数据须标自报 |
| C | 厂商官网宣传、媒体转述 | 只能作为候选或辅助，不能独立证明高校采用和实际效果 |

---

## 2. 证据注册表（强制）

证据 ID 使用稳定 ASCII：

- `<MODULE>-UNI-01`：高校真实使用/案例；
- `<MODULE>-VEN-01-CAP`：厂商能力；
- `<MODULE>-VEN-01-ADOPT`：该产品高校采用；
- `<MODULE>-POL-01`：国家/学校制度；
- `<MODULE>-STD-01`：标准规范。

| evidenceId | 等级 | 系统/产品 | 厂商 | 发布方 | 标题 | sourceUrl | 查阅日期 | locator | 直接证明 | 不能证明 | 适用三级模块 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| `<MODULE>-UNI-01` | A |  |  |  |  |  |  |  |  |  |  |

没有 `sourceUrl + locator + 直接证明 + 不能证明` 的记录无效。

---

## 3. 至少三套成熟系统逐家核验

每套分别写：

1. 产品/系统及厂商；
2. 模块能力证据ID；
3. 高校采用证据ID；
4. 已核验事实；
5. 不可推断边界；
6. 可转化的设计输入。

不得把采购需求写成中标产品已经实现；不得把厂商官网客户数量写成当前模块采用证据。

## 7. 禁止推断清单

---

## 8. CC本地复用规则

CC回填施工包/施工卡时，每个正式设计项必须保留：

```text
designSource=external_evidence
evidenceId=<稳定ID>
sourceUrl=<原始URL>
locator=<页码/章节/正文位置>
localEvidencePath=<本证据包路径>
```

CC自身不能联网时：

1. 先核验本文件结构和门禁表；
2. 只使用状态为 PASS 的证据；
3. 不重写或扩张“直接证明”；
4. 不把 `design_inference` 写成厂商事实；
5. 缺证据项继续标 `PARTIAL / FAIL`，不得整包宣布通过。

## 9. 门禁结果

| 门禁项 | PASS/PARTIAL/FAIL | 证据 |
|---|---|---|
| 三套成熟系统 |  |  |
| 每套当前模块能力证据 |  |  |
| 每套高校真实采用证据 |  |  |
| 至少一份制度/标准 |  |  |
| 全部来源可定位 |  |  |
| 三级模块映射完整 |  |  |
| 不可推断边界完整 |  |  |

只有全部强制门禁 PASS，外部证据项才允许通过；施工包能否升 `design_ready` 仍需同时通过代码事实、权限、安全、测试设计和跨模块复核。
