# 07-平台运营与学校租户隔离

- **文档性质**：SaaS 多租户隔离、平台运营权限边界、企业导师硬隔离红线
- **适用端**：平台运营端 + 后端租户中间件 + 全端数据访问
- **依据（只引用、不重写）**：`docs/security/00-等保三级安全基线总册.md` §1.5 SaaS 多租户边界、§7.4 归属校验；`docs/database/00-数据库设计冻结总册.md` §10 多租户与数据范围设计（`tenant_id` 行级隔离已冻结）；`docs/rbac/01/04/07`（`PLATFORM_OPERATOR`、`ALL` 范围、平台运营边界）
- **当前阶段声明**：租户隔离与平台运营边界**必须后端强制**；当前为设计红线。平台运营权限最高，一旦越权即为最严重安全事故，须重点管控 + 审计。
- **生成日期**：2026-07-04

## 一、多租户隔离模型（已冻结）

- **唯一方案：单库 / 单 schema + `tenant_id` 行级隔离**（一期不做每校独立库 / 独立 schema）。
- 所有业务表都有 `tenant_id`（`NOT NULL`）。
- **所有查询默认带 `tenant_id`**：中间件层（FastAPI 依赖注入 + SQLAlchemy 会话级过滤）**强制注入** `WHERE tenant_id = :currentTenant`，**禁止业务代码手写、禁止前端传**。
- `tenant_id` 由后端从登录上下文解析（引用底稿 §5），前端无法指定 / 篡改。
- **例外表（不带 `tenant_id`）**：控制面 `t_tenant` / `t_saas_package` / `t_tenant_subscription`；系统级元数据 `t_dict` / `t_module_def` / `t_permission`（跨租户共享定义）。

> 租户隔离是本平台第一安全边界：任何接口若能被诱导跨 `tenant_id` 取数，即为越权数据泄露。

## 二、红线 5：平台运营不能越权看学校敏感数据

`PLATFORM_OPERATOR`（数据范围 `ALL`）权限最高，但**业务上"不看学生业务明细"**，边界如下：

| 平台运营**可以**看 / 做 | 平台运营**不可以**看 / 做（硬隔离） |
|---|---|
| 租户（学校）列表、套餐、授权 / 到期状态 | 学生主档、身份证 / 手机 / 家庭 / 心理 / 处分等任何敏感明细 |
| 模块授权变更、开通 / 停用（`licenseContext`） | 学生审批业务明细、成绩 / 就业 / 实习明细 |
| 跨租户 / 系统级审计（租户 / 授权 / 登录 / 系统事件） | 学生业务审计明细（`SENSITIVE_VIEW`/业务审批等属学校侧） |
| 跨校**聚合指标**（脱敏后、不可反推到个人） | 可识别到具体学生个人的任何数据 |
| 平台巡检、健康度 | 代替学校做业务操作 |

要点：

- 平台运营接触到的任何学生相关数字必须是**脱敏聚合口径**，不得暴露可识别个人的信息。
- 平台运营与学校业务角色**强隔离、不可混用同一账号身份**（见 `docs/rbac/05-角色切换规则.md`）。
- 平台运营**所有操作（尤其模块授权变更）必写审计**，且审计对被服务学校租户建议可见（增强透明度，是否开放待后端确认）。
- 平台运营为 `SECRET` 级最高敏感操作范畴，强制 MFA（见 `01`）。

## 三、红线 8：租户 / 归属后端二次校验

- 每个接口在租户过滤之外，还要校验**具体数据行归属**（`tenant_id` + `college_id/class_id/student_id` + 文件归属），详情接口二次校验，不在范围返回 `DATA_SCOPE_DENIED`。
- 前端不参与租户判定；即便前端传了 `tenant_id` 也以后端登录上下文为准（忽略前端值）。
- 跨租户接口（仅平台运营）单独审计、单独限制，不与普通业务接口共用鉴权分支。

## 四、企业导师硬隔离红线

`ENTERPRISE_MENTOR`（企业侧账号）是最需要防越权的外部角色：

- 数据范围 `ENTERPRISE_AUTH_STUDENTS` = **仅授权在岗实习学生**，且仅限实习相关字段。
- 对**毕设成果、家庭信息、心理信息、处分信息硬隔离**（DB 冻结册 §10 红线），后端强制不返回。
- **禁批量导出 / 批量下载**（见 `04`/`06`）。
- 企业端走独立分域前缀 `/api/v1/enterprise-portal`，与学校管理端接口隔离。

## 五、模块授权与只读降级

- 学校按套餐授权模块；未授权模块 `MODULE_NOT_AUTHORIZED`，到期 `MODULE_EXPIRED_READONLY`（只读降级）。
- `licenseContext`（模块是否授权）优先级高于 `permissionContext`（角色权限）：**先判模块授权，再判角色权限，再判数据范围**（引用基线 §1.7）。

## 六、开发验收清单

- [ ] 中间件强制注入 `WHERE tenant_id`，业务代码无手写 tenant 过滤
- [ ] 控制面 / 系统级元数据表按冻结册豁免 `tenant_id`
- [ ] 平台运营接口不返回任何学生业务明细（仅租户 / 授权 / 聚合 / 系统审计）
- [ ] 平台运营操作全审计 + 强制 MFA
- [ ] 企业导师硬隔离毕设 / 家庭 / 心理 / 处分 + 禁批量导出下载
- [ ] 详情 / 导出接口二次校验数据行归属（tenant + 组织 + 文件）
