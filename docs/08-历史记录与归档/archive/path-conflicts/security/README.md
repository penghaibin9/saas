## 一、本分册解决什么

高校（职校）学生全生命周期系统承载大量学生**敏感个人信息**（身份证、手机号、家庭与经济困难、心理、处分、实习定位、成绩等），且是**多学校 SaaS 多租户**平台。本分册把散落在等保基线、数据库冻结册、RBAC 矩阵里的安全要求，收敛成**可执行、可验收的红线清单**，覆盖账号、权限、脱敏、导入导出、审计、文件上传、租户隔离七大面，并配套一份合规说明。

## 二、八条不可退让红线（本轮重点）

| # | 红线 | 主责分册 |
|---|---|---|
| 1 | **明确哪些字段必须脱敏**：身份证号、手机号、家庭地址、家长电话、家庭经济困难信息、心理信息、处分信息、实习定位明细、企业联系人电话、成绩明细等一律默认脱敏 | `03-学生敏感信息脱敏规则.md` |
| 2 | **谁能看完整手机号 / 身份证 / 家庭信息**：默认所有人只看脱敏值；查看完整值需 `field:view_full` 字段级权限 + 数据范围命中 + 写审计，最小授权到学校管理员 / 学籍专职角色 | `03`、`02` |
| 3 | **导出必须水印 + 审计**：L3/L4 导出强制水印（学校 / 用户 / 时间 / 用途 / requestId），每次导出写 `EXPORT` 审计与 `t_export_task` | `04-导入导出安全规则.md` |
| 4 | **批量操作必须二次确认**：批量分班 / 改学籍 / 催办 / 导出等，前端二次确认 + 后端整批数据范围校验，超范围对象整批拒绝 | `04`、`02` |
| 5 | **平台运营不能越权看学校敏感数据**：`PLATFORM_OPERATOR` 只看租户 / 授权 / 跨校审计与聚合指标，**硬隔离**学生业务明细 | `07-平台运营与学校租户隔离.md` |
| 6 | **普通老师只能看自己数据范围**：辅导员=本班级、指导教师=被指派学生、学院角色=本学院，越范围返回 `DATA_SCOPE_DENIED` | `02-权限与数据范围安全.md` |
| 7 | **逻辑删除，禁止物理删除**：业务表 `is_deleted` 软删除 + 回收站；审计 / 流水表 append-only 不可删不可改 | `02`、`05-审计日志规则.md` |
| 8 | **后端必须再次校验权限，不能只靠前端**：`tenant_id`、数据范围、字段权限、功能权限一律服务端强制，DTO 脱敏裁剪，绝不直接回表行 | `02`、全册贯穿 |

## 四、贯穿全册的三条基本原则

1. **服务端强制**：任何"隐藏按钮 / 前端脱敏 / 前端过滤"都只是体验优化，真正的安全边界一律在后端，前端不可绕过（红线 8）。
2. **最小授权**：默认拒绝、按需授予；敏感字段完整值、导出、跨范围访问一律走"权限点 + 数据范围 + 审计"三重门。
3. **可追溯**：所有敏感查看 / 导出 / 删除 / 权限变更 / 越权尝试全部留痕，审计不可篡改（红线 7）。

## 五、统一错误码（引用底稿，供各分册复用）

| 错误码 | 含义 | HTTP |
|---|---|---|
| `NO_PERMISSION` | 无功能权限点 | 403 |
| `DATA_SCOPE_DENIED` | 数据范围越权（有权限点但数据不在范围内） | 403 |
| `PERMISSION_DENIED` | 通用鉴权拒绝（含越权尝试审计事件名） | 403 |
| `SOD_VIOLATION` | 职责分离冲突（如导出申请人=审批人） | 409 |
| `MODULE_NOT_AUTHORIZED` / `MODULE_EXPIRED_READONLY` | 模块未授权 / 已到期只读 | 403 |
| `IDEMPOTENCY_CONFLICT` | 写接口幂等冲突 | 409 |
| `REJECT_REASON_TOO_SHORT` | 驳回理由少于 5 字 | 400 |

> 前端遇到上述错误统一走拦截提示或 `/security/403`，**不得暴露"数据是否存在"**等可被枚举利用的信息。
