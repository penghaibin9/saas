# 09 · 后端验收标准

> 文档性质：后端总验收 gate 勾选清单（贯穿全部模块的收口验收标准）
> 适用端：后端开发自查 + 前后端联调双方验收 + 项目管理里程碑验收
> 依据：共享事实底稿全篇；`docs/api/08-后端联调检查清单.md`（已有的可勾选清单，本文档与其互补，不重复列出其全部条目）；本目录 01–08 各文档验收标准小节
> 当前阶段声明：以下全部条目均**未勾选**，代表后端真实接口尚未实现、尚未通过验收；本清单是"完成态"的定义，不是"当前进度"的记录
> 生成日期：2026-07-04

---

## 使用说明

- 本文档是**总验收 gate**，即"后端接入到什么程度才能认为完成"，与 `docs/api/08-后端联调检查清单.md` 是互补关系：`08` 文档偏"逐接口/逐环境的操作清单"，本文档偏"分类别的验收标准总纲"，两者建议对照使用。
- 每个大类下的条目是**验收标准**，不是任务列表；具体任务分解见本目录 `02-按模块后端任务清单.md` 与 `03-接口联调顺序.md`。
- 验收责任人建议由后端负责人 + 前端负责人共同签字确认，不由单方面自证完成。

## 一、契约一致性

- [ ] 后端已实现的每个接口的**路径、方法、请求参数、返回字段**与对应 `docs/api` 契约文档逐条核对一致（历史冻结 01–05 优先，本轮新增 01–08 补充覆盖域）。
- [ ] 与契约文档存在偏差的接口，已记录偏差原因并走评审确认（不存在"后端擅自改了契约但文档未同步"的情况）。
- [ ] 分端前缀（`/api/v1/admin`、`/api/v1/student-pc`、`/api/v1/student-mini`、`/api/v1/teacher-mobile`、`/api/v1/platform`、`/api/v1/authz`、`/api/v1/files`）已全部落地，路由分组清晰。
- [ ] `/api/v1/enterprise-portal/*`（企业导师 PC 端）本期不实现的决定已明确记录（非遗漏）。

## 二、鉴权与数据范围服务端校验

- [ ] 服务端权限校验链 `authMiddleware → tenantMiddleware → moduleEntitlementMiddleware → featureFlagMiddleware → permissionMiddleware → dataScopeMiddleware → sodMiddleware → auditMiddleware` 已完整实现，且用真实账号（非纸面约定）测试验证。
- [ ] 七类角色（PLATFORM_OPERATOR/SCHOOL_ADMIN/COLLEGE_ADMIN/TEACHER/COUNSELOR/STUDENT/ENTERPRISE_MENTOR）与数据范围的映射已在服务端配置，非硬编码在前端。
- [ ] `04-数据库对接注意事项.md` §5.2 提出的"前端 6 值 DATA_SCOPE ↔ 数据库 12 值 data_scope"收敛方案已确认并实现，不存在两套口径互相打架的情况。
- [ ] `tenant_id` 隔离已验证：用 A 校账号尝试访问 B 校数据应返回 `TENANT_NOT_FOUND`/`NO_PERMISSION`（非仅设计层面声明，需实测）。
- [ ] 企业导师对毕设成果/家庭情况/心理记录/处分记录的字段级硬隔离已在服务端验证（字段完全不下发，非前端隐藏）。
- [ ] 越权访问返回 `NO_DATA_SCOPE`/`NO_PERMISSION` 已用真实账号测试验证。
- [ ] `permissionContext` 聚合方案（新增聚合接口 或 前端自行拼接 1.7+1.9+1.10+1.11）已与前端确认一致，不存在两边各自假设不同实现方式的情况（见 `05-鉴权与权限接入.md` §四）。

## 三、错误码与响应结构

- [ ] 所有接口返回 `{code, message, data, traceId, timestamp}` 五字段结构，无裸 500、空白响应体、非标准 JSON 结构。
- [ ] `code` 为字符串枚举，成功恒为 `SUCCESS`；workflow 模块历史数字 code（0/41001 等）已在真实接口中转换为字符串 code。
- [ ] 完整错误码表（`docs/api/04-统一响应结构与错误码.md` §四）已实现，且与历史冻结总册已使用的错误码字符串的收敛方案已确认（见 `01-后端接入总览.md` §三.2）。
- [ ] 列表类接口 `data` 内层为 `{list,total,page,pageSize}` 分页结构（统一用 `list`，非历史冻结总册的 `items`）。
- [ ] 空列表返回 `{list:[],total:0}`，非 `null` 或字段缺失。

## 四、脱敏

- [ ] 敏感字段（手机号/身份证号/家庭住址等 SENSITIVE 级）默认返回脱敏值。
- [ ] `SECRET` 级字段（密码、完整身份证号原文）任何角色均不下发明文，已用抓包工具验证。
- [ ] 查看完整值的字段级权限校验已在服务端实现，非前端按钮显隐。
- [ ] 敏感字段查看已写 `SENSITIVE_VIEW` 审计，可在审计查询中检索到对应记录。

## 五、审计完整

- [ ] 审计事件类型覆盖：`LOGIN/LOGOUT/PERMISSION_DENIED/PERMISSION_CHANGE/EXPORT/DOWNLOAD/UPLOAD/APPROVAL/SENSITIVE_VIEW/SESSION_EXPIRED`。
- [ ] 五张审计表（`t_student_field_audit`/`t_security_audit`（及 `t_security_audit_log`）/`t_permission_audit`/`t_operation_audit_log`/`t_file_access_log`）均为 append-only，无 `is_deleted`/`update` 能力。
- [ ] 审批/导出/敏感访问类操作的审计写入已确认"必须成功落审计"（非"尽力而为"），审计写入失败时是否阻断主流程已明确策略（待后端确认后记录，不留模糊状态）。
- [ ] 审计日志查询接口（各模块 `getAuditLogs`）已实现分页与筛选，`system.log.view`/`workflow.audit.view`/`student.audit.view` 权限点已生效。

## 六、幂等与乐观锁

- [ ] 写操作携带的 `requestId` 幂等键已在服务端生效（同 `requestId` 不同 payload 返回 `IDEMPOTENCY_CONFLICT`）。
- [ ] 审批类写操作携带的 `version` 乐观锁已在服务端生效（版本不一致返回 `APPROVAL_VERSION_CONFLICT`）。
- [ ] 退回/驳回类操作的 `reason`/`rejectReason` 服务端二次校验 ≥5 字（不仅依赖前端表单校验），不足返回 `REJECT_REASON_REQUIRED`。
- [ ] 任务已终态重复处理返回 `TASK_ALREADY_FINISHED`；不可撤回节点撤回返回 `TASK_NOT_WITHDRAWABLE`。

## 七、文件与导入导出

- [ ] 文件中心：上传只返回 `file_id`，业务表未直接存储文件二进制或路径明文；白名单/黑名单/50MB 已服务端强制；签名 URL 含有效期。
- [ ] 导入：模板下载、真实文件解析校验（非模拟回执）、错误行清单、异步任务队列（大数据量场景）均已实现。
- [ ] 导出：三档权限（`security.export.list/archive/desensitized`）已服务端校验；默认 ≤5000 行已服务端强制；异步任务 + 签名 URL 下载（非同步返回二进制）；`EXPORT` 审计已写入。
- [ ] 详细验收标准见 `06-文件上传接入.md` §七、`07-导入导出接入.md` §四。

## 八、性能与分页

- [ ] 所有列表接口已支持 `page`/`pageSize`（页码分页）或 `cursor`/`pageSize`（游标分页）。
- [ ] 单次 `pageSize` 上限 100 已在服务端强制校验。
- [ ] 高频查询字段（`tenant_id`、`student_id`、`class_id`/`college_id`/`mentor_id`）已建立索引（见 `04-数据库对接注意事项.md` §六），大数据量场景下列表查询响应时间已做基准测试（具体基准值待后端确认）。
- [ ] 数据驾驶舱等聚合统计类接口的响应时间在可接受范围内（具体阈值待后端确认，建议不超过前端加载态可接受时长）。

## 十、与前端 mock 行为一致性回归

- [ ] 前端切换真实数据源后（PC 各模块 `api/*.api.js` 从 mock 切 real、miniapp `ENV.useMock` 从 `true` 切 `false`），页面与 store 层**未发生任何改动**（契约要求：只改 api 实现，页面与 store 一行不动）。
- [ ] 演示租户"演示职业技术学院/软件学院"在真实接口下的行为与 mock 阶段演示剧本（基准日 `TODAY=2026-07-02`、当前实习周 `CURRENT_WEEK=4`）在数据结构层面保持一致（不要求数值完全相同，但字段结构、状态枚举、分页行为应一致）。
- [ ] 全部错误态（`DATA_NOT_FOUND`/`NO_PERMISSION`/`NO_DATA_SCOPE`/`VALIDATION_ERROR` 等）在真实接口下的前端展现（空状态/安全错误页跳转/表单标红）与 mock 阶段的既定行为一致，未出现真实接口报错但前端白屏/无提示的情况。
- [ ] 回归测试已覆盖至少一轮"mock 阶段可演示的核心业务流程"，在真实接口下重新走一遍且结果一致（如：学生登录 → 查看首页 → 提交服务申请 → 教师审批通过 → 学生查看审批结果，全链路不依赖 mock 数据）。
