# 03 · 接口联调顺序

> 文档性质：后端接口联调顺序与依赖关系（12 步，含并行项）
> 适用端：后端开发 + 前后端联调双方
> 依据：共享事实底稿建议顺序；`docs/api/00-API契约冻结总册.md` §十四一期优先级（P0–P4）；`docs/api/08-后端联调检查清单.md` §十二联调冒烟用例顺序
> 当前阶段声明：以下顺序为**建议实施顺序**，尚未开始任何一步；每步"联调完成判据"均未达成
> 生成日期：2026-07-04

---

## 一、总顺序（按共享底稿建议）

```text
① 登录鉴权 → ② 租户与学校品牌 → ③ 用户角色权限 → ④ 学生主档 → ⑤ 审批中心
→ ⑥ 岗位实习 → ⑦ 毕业设计 → ⑧ 就业服务 → ⑨ 数据中心 → ⑩ 导入导出
→ ⑪ 文件上传 → ⑫ 审计日志
```

> 说明：文件上传（⑪）虽排在后面，但其**基础上传/签名 URL 能力**必须在 ④ 学生主档、⑥ 岗位实习等模块涉及附件字段前提前完成（如学生信息更正证明材料、请假证明、打卡照片）。此处的"⑪ 文件上传"位置指的是"作为独立联调项完整验收"的顺序，不代表其基础能力可以推迟到最后才开发，详见下方逐步说明与依赖关系表的区分。

---

## 二、逐步说明

### 步骤 1 · 登录鉴权

| 项 | 内容 |
|---|---|
| 为什么先做 | 所有其余步骤都需要登录态（Token）与用户上下文，是最底层依赖 |
| 前置依赖 | 无（最先做），但需要统一响应结构中间件、错误码中间件先落地（见 `01-后端接入总览.md` §三） |
| 联调完成判据 | 1）PC 管理员、miniapp 学生、miniapp 教师三类账号均能登录成功并返回符合 `docs/api/01-认证租户与当前上下文API.md` 1.1 的响应结构；2）Token 刷新、登出正常；3）并发会话数超 3 个触发踢出验证通过；4）首次登录强制改密拦截业务接口验证通过 |
| 可并行项 | 文件中心基础上传接口（不依赖具体业务权限，可与登录鉴权并行开发） |

### 步骤 2 · 租户与学校品牌

| 项 | 内容 |
|---|---|
| 为什么先做 | 登录页与全端顶栏品牌位依赖此接口，且该接口可公开访问（不依赖登录态），可与步骤 1 并行验收 |
| 前置依赖 | `t_tenant`、`t_tenant_brand_config` 表数据已就绪（演示租户"演示职业技术学院/软件学院"，待后端确认初始化脚本） |
| 联调完成判据 | 品牌配置接口返回字段完整（`platformName/logoLightUrl/primaryColor/watermarkText` 等），PC 登录页与顶栏、miniapp 首页均正确渲染品牌位，无硬编码学校名 |
| 可并行项 | 可与步骤 1 完全并行（本身不依赖登录态） |

### 步骤 3 · 用户角色权限

| 项 | 内容 |
|---|---|
| 为什么先做 | 后续所有业务模块的接口访问都需要"当前身份的菜单/按钮/数据范围"作为权限校验依据，是 RBAC 底座 |
| 前置依赖 | 步骤 1（登录鉴权，需要 Token 与 `activeContextId`） |
| 联调完成判据 | 1）我的菜单、我的按钮权限、我的数据范围、我的模块授权四个接口均返回正确结构；2）七类角色与六类数据范围映射已在服务端配置校验通过（用不同角色账号验证返回的菜单/按钮/数据范围符合共享底稿 §3 角色定义）；3）身份切换后四个接口重新加载正确 |
| 可并行项 | 角色权限管理的写操作接口（`workflow.role.edit`、`workflow.permission.toggle`）可与步骤 4 学生主档并行开发（不互相阻塞，但建议角色权限读接口先行） |

### 步骤 4 · 学生主档

| 项 | 内容 |
|---|---|
| 为什么先做 | 学生主档是全平台数据的核心枢纽（`student_id` 串联所有业务表，见数据库冻结总册 §3.2），后续实习/毕设/就业/审批等模块都依赖学生主档数据存在 |
| 前置依赖 | 步骤 1（登录鉴权）、步骤 3（用户角色权限，需要数据范围过滤生效） |
| 联调完成判据 | 1）学生列表/详情/360 接口按数据范围正确过滤（辅导员仅见本班级）；2）敏感字段默认脱敏，查看完整值需字段权限+审计；3）身份核验、学籍状态变更、信息更正接口走审批流验证通过 |
| 可并行项 | 学生主档的导入导出接口可与步骤 10（导入导出通用规则）共同开发，因为学生主档是导入导出规则的第一个落地模块 |

### 步骤 5 · 审批中心

| 项 | 内容 |
|---|---|
| 为什么先做 | 审批中心（待办/审批横切能力）是岗位实习、毕业设计、就业服务、学生主档信息更正等多个模块共用的能力，提前打通可避免后续模块各自重复实现审批逻辑 |
| 前置依赖 | 步骤 3（用户角色权限，审批任务的处理人需要按角色/数据范围过滤）、步骤 4（学生主档，审批业务对象多数关联学生） |
| 联调完成判据 | 1）待办列表、审批列表/详情、通过/退回/驳回接口全部走通；2）乐观锁 `version` 冲突验证通过（`APPROVAL_VERSION_CONFLICT`）；3）退回原因 <5 字拦截验证通过（`REJECT_REASON_REQUIRED`）；4）任务已终态重复处理、不可撤回节点撤回两类异常场景验证通过 |
| 可并行项 | 消息中心（见 `08-消息待办接入.md`）可与审批中心并行开发，两者共享部分底层表（`t_unified_todo`/`t_unified_message`）但业务逻辑相对独立 |

### 步骤 6 · 岗位实习

| 项 | 内容 |
|---|---|
| 为什么先做 | 共享底稿建议顺序中排在毕业设计、就业服务之前；岗位实习历史冻结总册已有完整 18 接口契约（P3 一期范围），且是当前 mock 演示剧本"当前实习周 CURRENT_WEEK=4"覆盖最完整的业务模块 |
| 前置依赖 | 步骤 4（学生主档）、步骤 5（审批中心，实习申请审核走审批流） |
| 联调完成判据 | 1）实习申请提交→指导教师审核→学院审核→辅导员抄送→结束 全流程走通；2）打卡（含定位校验，禁止代打卡）、周报提交与批阅（退回原因≥5字）验证通过；3）企业导师对毕设成果/家庭/心理/处分信息字段级硬隔离验证通过 |
| 可并行项 | 岗位实习的文件上传相关能力（打卡照片、协议文件）应与步骤 11 文件上传基础能力同步开发，不必等文件上传作为独立项完全验收后才开始 |

### 步骤 7 · 毕业设计

| 项 | 内容 |
|---|---|
| 为什么先做 | 排在岗位实习之后，因两者同属"教学实践"分组且共用归档能力（`t_filing_record`），先做完岗位实习可复用归档、审批流经验 |
| 前置依赖 | 步骤 4（学生主档）、步骤 5（审批中心，选题审批/开题批阅/答辩排期走审批流） |
| 联调完成判据 | 1）选题→开题→中期→成果→答辩 主流程走通；2）SoD 校验"毕设导师≠自己学生答辩评分人"验证通过（违反返回 `SOD_VIOLATION`，待后端确认最终错误码归属）；3）成绩发布、归档流程状态机验证通过 |
| 可并行项 | 查重环节（`t_gd_plagiarism`）对接第三方查重服务可独立并行（待后端确认查重服务选型） |

### 步骤 8 · 就业服务

| 项 | 内容 |
|---|---|
| 为什么先做 | 就业服务部分依赖学生的毕业资格预检（`t_graduation_precheck_*`，属学业过程模块）与实习经历（`t_intern_to_employment`），排在实习、毕设之后可减少跨模块数据未就绪的联调风险 |
| 前置依赖 | 步骤 4（学生主档）、步骤 6（岗位实习，`t_intern_to_employment` 衔接关系） |
| 联调完成判据 | 1）就业去向登记、材料审核走审批流验证通过；2）未就业跟进任务与响应记录、催办功能验证通过；3）就业老师（数据范围 COLLEGE）仅能查看本学院数据验证通过 |
| 可并行项 | 校友库（`t_alumni_profile`）相关接口可独立并行，非核心就业流程阻塞项 |

### 步骤 9 · 数据中心

| 项 | 内容 |
|---|---|
| 为什么先做 | 数据驾驶舱是跨模块统计聚合视图，必须等学生主档、审批中心、岗位实习、毕业设计、就业服务等业务模块数据产生后才能验证统计口径的正确性，因此排在业务模块之后 |
| 前置依赖 | 步骤 4、5、6、7、8（需要各业务模块已有真实/测试数据用于统计验证） |
| 联调完成判据 | 1）全局概览多口径统计数字与业务模块明细数据核对一致；2）生命周期漏斗、风险统计下钻到具体学生遵循数据范围过滤；3）报表/排行榜分页正常，导出走 `EXPORT` 审计 |
| 可并行项 | 数据中心的静态报表模板配置可提前开发，只是数据验证环节需等待业务模块数据 |

### 步骤 10 · 导入导出

| 项 | 内容 |
|---|---|
| 为什么先做 | 导入导出是横切通用能力，虽然学生主档等模块在步骤 4 已涉及导入导出接口，但"三档导出权限+审计+异步任务"的完整通用规则建议在核心业务模块联调稳定后统一收口验证，避免过早固化影响业务模块字段调整 |
| 前置依赖 | 步骤 4、6、7、8（各业务模块的导入导出字段清单需业务模块基本稳定后才能最终确定） |
| 联调完成判据 | 详见 `07-导入导出接入.md` 验收标准 |
| 可并行项 | 各模块的导入模板下载接口（静态文件）可提前开发，不依赖业务模块联调完成 |

### 步骤 11 · 文件上传（作为独立项完整验收）

| 项 | 内容 |
|---|---|
| 为什么先做 | 文件上传**基础能力**（上传返回 `file_id`、签名 URL）必须在步骤 4/6/7 等涉及附件的模块之前就绪（见本文档开头说明），但"文件中心完整能力"（病毒扫描、对象存储生产级配置、多业务类型差异化限制）建议作为独立项在业务模块基本走通后统一收口验证 |
| 前置依赖 | 步骤 1（登录鉴权，上传需要登录态） |
| 联调完成判据 | 详见 `06-文件上传接入.md` 验收标准 |
| 可并行项 | 与步骤 1 登录鉴权可并行启动基础开发 |

### 步骤 12 · 审计日志

| 项 | 内容 |
|---|---|
| 为什么先做 | 审计日志贯穿全部前序步骤（登录、身份切换、审批、导出、敏感查看等均需写审计），放在最后是因为"审计查询与展示接口"的完整验收需要前序步骤都已产生真实审计数据，但**审计写入本身必须与各步骤同步实现，不能延后** |
| 前置依赖 | 步骤 1–11 全部（审计数据来源覆盖登录、权限、学生主档、审批、业务模块、导入导出、文件访问） |
| 联调完成判据 | 详见 `09-后端验收标准.md` 审计完整性一节 |
| 可并行项 | 审计查询接口的分页/筛选能力可提前开发，真实数据验证需等待前序步骤产生数据 |

## 三、依赖关系表

| 步骤 | 模块 | 直接前置步骤 | 可并行的其他步骤/子项 |
|---|---|---|---|
| ① | 登录鉴权 | 无 | 文件上传基础能力（⑪ 的子集） |
| ② | 租户与学校品牌 | 无（可公开访问） | ①（完全并行） |
| ③ | 用户角色权限 | ① | 角色权限管理写操作可与 ④ 并行 |
| ④ | 学生主档 | ①③ | 导入导出通用规则（⑩ 的子集，学生主档先落地） |
| ⑤ | 审批中心 | ③④ | 消息待办（见 `08-消息待办接入.md`） |
| ⑥ | 岗位实习 | ④⑤ | 文件上传业务对接（打卡照片/协议文件） |
| ⑦ | 毕业设计 | ④⑤ | 查重服务对接 |
| ⑧ | 就业服务 | ④⑥ | 校友库相关接口 |
| ⑨ | 数据中心 | ④⑤⑥⑦⑧ | 静态报表模板配置可提前 |
| ⑩ | 导入导出 | ④⑥⑦⑧ | 各模块导入模板下载可提前 |
| ⑪ | 文件上传（完整验收） | ①（基础能力） | 与 ①③④⑥⑦ 并行开发，独立作为收尾验收项 |
| ⑫ | 审计日志 | ①–⑪ 全部 | 查询接口开发可提前，数据验证需等待 |

> 提醒：此依赖关系表描述的是"完整验收顺序"，不代表开发工作只能串行推进。建议后端团队按 `01-后端接入总览.md` 的 M0/M1/M2/M3 里程碑分批并行排期，本表用于识别"哪些环节必须等前一环节数据/权限就绪才能验证"，避免过早联调导致返工。
