# 01 · 日常运维检查清单

> 现阶段只有前端静态站点在跑，日常运维很轻。照着勾即可。

---

## 每天检查（2 分钟）

- [ ] **站点能打开**：浏览器打开 PC 管理端地址，能看到登录/首页。
- [ ] **小程序 H5 能打开**：打开 H5 地址，能进学生端/教师端。
- [ ] **随手点一个业务页**：比如学生列表，页面正常渲染、不白屏。
- [ ] **刷新不 404**：在某个子页面按 F5 刷新，页面仍在（不出现 Nginx 404）。
- [ ] **服务器还活着**：能 SSH 登上服务器；`sudo systemctl status nginx` 显示 `active (running)`。
- [ ] **磁盘没满**：`df -h`，根分区使用率别接近 100%。

> 现在是 mock 数据，不用检查「数据对不对」——数据是演示用的假数据。

---

## 每周检查（10 分钟）

- [ ] **看错误日志有没有异常**：`sudo tail -n 100 /var/log/nginx/error.log`，有没有反复报错。
- [ ] **磁盘趋势**：`df -h` 和 `du -sh /var/www/*`，历史发版目录是不是堆太多（清理见 `docs/deploy/09`）。
- [ ] **系统更新（可选）**：`sudo apt update`（Ubuntu）看有没有安全更新，重要更新择机打。
- [ ] **备份确认**：前端当前版本目录还在、能回滚（见 `06-备份与恢复方案.md`）。
- [ ] **证书有效期（如配了 HTTPS）**：确认证书没快过期（certbot 一般自动续期）。

---

## 每月检查（可选）

- [ ] 清理过老的发版目录，只留最近 3~5 个。
- [ ] 回顾这一个月有没有反复出现的问题，记录到问题台账。
- [ ] 确认服务器登录密码/密钥安全，没有泄露。

---

## 记录习惯

建议维护一个简单的「运维日志」（一个 txt 或表格即可），每次检查/发版/故障都记一行：**日期、做了什么、有没有异常、怎么处理的**。出问题时这份记录非常值钱。

---

## 后端/数据库接入后要新增的日常检查（现在不用做）

- [ ] 后端服务进程是否存活（`systemctl status` 后端服务）
- [ ] 数据库是否可连接、连接数是否正常
- [ ] 接口健康检查地址是否返回正常
- [ ] 数据库备份任务是否成功执行

> 这些等后端/数据库上线后再补真实命令。
