# 08 · 客户现场问题处理手册

> 场景：你在学校现场（演示/交付），突然出问题，需要**当场冷静处理**。这份是给现场的人用的速查。

---

## 0. 现场心态（重要）

- **先稳住**：大多数现场问题是「网络 / 缓存 / 刷新 404」这类小问题，不是系统坏了。
- **别当场改源码**：现场不是改 `frontend/src`、`miniapp` 的地方。能绕过就绕过，能回滚就回滚，事后再修。
- **如实沟通**：当前系统是**演示版（前端 + 假数据，后端未接）**，遇到「数据不保存」是正常的，不是故障（见第 4 节）。

---

## 1. 现场必备（去之前准备好）

- [ ] 记好线上地址（PC 管理端、H5）、演示账号入口。
- [ ] 记好**上一版可回滚的目录名/版本号**。
- [ ] 手机能开热点（现场网络不稳时备用）。
- [ ] 带上这份手册和 `docs/delivery/02-演示前检查清单.md`。
- [ ] 提前在现场网络里**自己先跑一遍**（见演示前检查清单）。

---

## 2. 现场高频问题速查

| 现象 | 大概率原因 | 现场怎么办 |
|---|---|---|
| 页面打不开 | 现场网络/WiFi 问题 | 换网络/开热点；确认能上外网；换设备试 |
| 打开是旧版本 | 浏览器缓存 | Ctrl+F5 强刷；换隐私窗口打开 |
| 刷新变 404 | 路由兜底（一般部署时已配好） | 别在演示中途刷新；从首页正常点进去；事后确认 Nginx `try_files` |
| 页面白屏 | 缓存/资源没加载 | 强刷；换设备；不行就用你本地已跑通的环境演示 |
| 某图片/图标不显示 | 资源缓存或网络 | 强刷；不影响主流程可先跳过 |
| 小程序打不开 | 网络/体验版权限 | 确认扫的是体验版码；确认微信号在体验成员里 |
| 投屏字太小 | 显示问题 | 浏览器 Ctrl+「+」放大；调分辨率 |

---

## 3. 现场万能三招

1. **强刷**：Ctrl+F5（清缓存刷新），解决一大半"看起来坏了"的问题。
2. **换环境**：现场服务器/网络不行，就用你**本地已经跑通的** H5/PC 演示（`npm run preview` / `npm run dev:h5`）顶上，保证演示不中断。
3. **回滚**：如果是刚更新导致的，按 `docs/deploy/09` 退回上一版。

---

## 4. 客户当场问「数据怎么没保存 / 是不是真系统」怎么答

据实、专业地说明（也见 `docs/delivery/05-常见客户问题答复.md`）：

> "当前是**功能演示版本**，用于展示完整的界面和业务流程。它现在使用的是**演示数据**，所以新增/修改在刷新后不会长期保存。**真实的数据存储、登录、权限，会在后端接入阶段完成**。今天演示的界面和流程，就是最终产品的样子。"

**不要**说"系统已经全部做好了、已经接了后端"——那不属实，交付验收时会出问题。

---

## 5. 现场记录

现场遇到的每个问题都记一行：**时间、现象、当场怎么处理、是否解决、待办**。回去后：

- 属于**部署/配置**问题 → 自己按运维文档修。
- 属于**代码/功能**问题 → 整理清楚反馈给开发，不要自己在现场改源码。
- 属于**后端未接导致的"限制"** → 归入"后端接入后解决"，如实向客户说明。

---

## 6. 升级路径（搞不定时找谁）

- 部署/Nginx/服务器问题 → 运维负责人。
- 前端页面/功能 Bug → 前端开发。
- 小程序问题 → 小程序开发。
- 数据库/后端（后续阶段） → 后端负责人。

现场**先保证演示能继续**（用本地环境顶上也行），复杂问题事后处理，别在客户面前长时间卡壳。
