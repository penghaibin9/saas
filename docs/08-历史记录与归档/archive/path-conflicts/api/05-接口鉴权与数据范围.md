# 05 · 接口鉴权与数据范围

> 文档性质：全端接口鉴权、租户隔离、角色身份、数据范围规则权威说明（本轮新增）
> 适用端：全端（PC 管理端 / 学生小程序 / 教师移动端 / 平台运营端）
> 依据：共享事实底稿 §3、§4、§5；`frontend/src/security/constants/security.constants.js`；`frontend/src/modules/workflow/context/permission.context.js`；`frontend/src/modules/workflow/mock/workflow.mock.js`；引用历史冻结 `docs/api/00-API契约冻结总册.md` §五–§九、`docs/security/00-等保三级安全基线总册.md`

## 一、登录态与会话

| 项 | 策略 |
|---|---|
| PC 会话超时 | 30 分钟无操作自动失效，超时前 5 分钟弹窗预警 |
| 移动端（miniapp）会话有效期 | 7 天 |
| 并发会话数 | 最多 3 个（第 4 个登录会导致最早会话被踢下线，下次请求返回 `UNAUTHORIZED`） |
| 首次登录 | 强制改密后才可继续使用业务功能（`mustChangePassword=true` 期间仅放行改密接口） |
| 会话失效响应 | 401（`UNAUTHORIZED`，未登录/Token 失效）；419（`SESSION_EXPIRED`，会话超时/CSRF 失效） |
| 前端安全错误页 | `/security/401`、`/security/403`、`/security/419`、`/security/500` |

> 会话与身份相关接口以历史冻结 `01-认证租户与当前上下文API.md` 为权威（登录 1.1、登出 1.2、刷新 Token 1.3、当前用户 1.4）。

## 二、租户隔离（tenant_id）

- `tenant_id` **前端永不传递**，后端从登录会话/Token 解析当前租户，在数据访问层（SQLAlchemy 会话级）统一注入 `WHERE tenant_id = :currentTenant` 过滤。
- 跨租户访问一律拒绝，返回 `TENANT_NOT_FOUND` 或 `NO_PERMISSION`。
- 唯一例外：平台运营端（`/api/v1/platform/*`）可查看多租户数据，但必须：
  1. 当前角色为 PLATFORM_OPERATOR；
  2. 拥有对应平台权限点；
  3. 每次跨租户查询/操作写入 `t_security_audit`。
- 演示租户当前为"演示职业技术学院 / 软件学院"（frontend mock 剧本），真实多租户场景下每个学校对应独立 `tenant_id`，数据完全隔离，不共享任何业务数据。

## 三、currentRoleCode + activeContextId（角色/身份）

- 一个用户可能拥有多个身份（例如同一教师同时是辅导员+教务老师），登录后返回全部可用身份列表（历史冻结 1.6 我的身份列表）。
- 每个客户端（PC/学生小程序/教师移动端）激活**一个** `activeContextId`，对应一个 `currentRoleCode` 与一个 `dataScope`，**权限不跨身份合并**——即同时具备两个身份时，当前只按激活的那个身份计算权限与数据范围，不会取两者权限的并集。
- 切换身份：`POST /api/v1/authz/contexts/{contextId}/activate`（教师移动端专属路径 `/api/v1/teacher-mobile/contexts/{id}/activate`）。切换后菜单、待办、数据范围、按钮、首页全部按新身份重新加载，并写身份切换审计。
- 前端通过请求头或会话（具体载体待后端确认：请求头 `X-Active-Context-Id` 或会话内绑定，二选一）携带 `activeContextId`，后端据此确定 `currentRoleCode` 与 `dataScope`，**服务端为最终裁定方，前端不参与计算**。

## 四、六类数据范围（DATA_SCOPE）如何影响接口返回

| 数据范围 | 含义 | 典型持有角色 | 对接口返回的影响 |
|---|---|---|---|
| ALL | 全平台 | PLATFORM_OPERATOR | 可跨租户查询（仅平台专属接口），业务学生明细类接口**不返回**（该角色权限点仅 workflow.audit.view，不含学生数据查看权限） |
| SCHOOL | 本校 | SCHOOL_ADMIN | 列表/统计类接口聚合本校（`tenant_id` 范围内）全部数据，不再按学院/班级过滤 |
| COLLEGE | 本学院 | COLLEGE_ADMIN、miniapp EMPLOYMENT/ACADEMIC/COLLEGE_ADMIN 身份 | 服务端在 `WHERE` 条件追加 `college_id = :currentCollegeId`，跨学院资源访问返回 `NO_DATA_SCOPE` |
| CLASS | 本班级 | COUNSELOR | 服务端追加 `class_id IN (:counselorClassIds)`，只能查看/操作所带班级学生，其余班级返回空列表或 `NO_DATA_SCOPE`（具体判定原则见 `04-统一响应结构与错误码.md` §三） |
| SELF | 仅本人 | STUDENT | 服务端追加 `student_id = :currentUserStudentId`，任何试图传入他人 ID 的请求一律 `NO_DATA_SCOPE` |
| ASSIGNED | 被指派对象 | TEACHER（指导教师）、ENTERPRISE_MENTOR（企业导师）；miniapp MENTOR=MENTEES、INTERN_MENTOR=INTERNS 为 ASSIGNED 的细分命名 | 服务端追加 `mentor_id = :currentTeacherId` 或等价的师生指派关系表过滤，仅能查看/操作被指派给自己的学生；企业导师额外对毕设成果/家庭情况/心理记录/处分记录**字段级硬隔离**（不返回，非脱敏而是完全不下发） |

### 4.1 数据范围判定优先级

1. 服务端权限校验链（见历史冻结总册 §五）：`authMiddleware(登录) → tenantMiddleware(租户) → moduleEntitlementMiddleware(模块授权) → featureFlagMiddleware(功能开关) → permissionMiddleware(权限码) → dataScopeMiddleware(数据范围) → sodMiddleware(职责互斥) → auditMiddleware(留痕)`。
2. 前端隐藏菜单/按钮/字段仅用于体验优化，**服务端必须重新校验权限码与数据范围**，不可信任前端传参。
3. 每个业务接口在 02/03 文档中均标注"权限要求"（权限码）与"数据范围要求"（scope 枚举），后端实现须与文档一致。

## 五、敏感字段脱敏与字段级权限 + 审计

- 敏感分级（`SENSITIVE_LEVEL`）：`PUBLIC`（公开）、`INTERNAL`（校内可见）、`SENSITIVE`（默认脱敏，如手机号/身份证号/家庭住址）、`SECRET`（禁止前端明文，如密码、完整身份证号原文）。
- 默认返回脱敏值（如手机号 `138****1234`、身份证号 `1101**********1234`）；查看完整值需要：
  1. 用户具备对应字段级权限（如 `student.identity.view`）；
  2. 该操作写入审计（`SENSITIVE_VIEW` 事件类型）。
- `SECRET` 级别字段（密码、完整身份证号原文）**任何角色的前端都不下发明文**，仅服务端内部使用；重置密码类接口（如 PC system 模块 `resetUserPassword`）也不回传明文。
- 敏感字段审计事件类型（`AUDIT_EVENT_TYPE`）：`LOGIN`、`LOGOUT`、`PERMISSION_DENIED`、`PERMISSION_CHANGE`、`EXPORT`、`DOWNLOAD`、`UPLOAD`、`APPROVAL`、`SENSITIVE_VIEW`、`SESSION_EXPIRED`。

## 六、CSRF 与请求追踪

| 项 | 约定 |
|---|---|
| CSRF 保护方法 | `POST`、`PUT`、`PATCH`、`DELETE`（`GET` 不受保护） |
| CSRF 请求头 | `X-CSRF-Token`，客户端从登录响应或专用接口获取后，每次写请求携带；校验失败返回 `SESSION_EXPIRED`（419） |
| 请求追踪头 | `X-Request-Id`，客户端可自行生成（建议 UUID）随请求发送；后端生成/透传 `traceId` 并在响应体回传（见 `04-统一响应结构与错误码.md` §一） |
| 幂等 | 写操作携带 `requestId`（业务层幂等键，区别于 `X-Request-Id` 链路追踪头），同一 `requestId` 重复提交但 payload 不同返回 `IDEMPOTENCY_CONFLICT` |
| 乐观锁 | 审批类写操作携带 `version` 字段，与服务端当前版本不一致返回 `APPROVAL_VERSION_CONFLICT`（409） |

## 七、越权返回约定

| 场景 | 返回码 | 前端表现 |
|---|---|---|
| 无对应权限码（菜单/页面/按钮/接口层面均无权限） | `NO_PERMISSION`（403） | 页面级：跳转 `/security/403`；按钮级：前端隐藏（体验层）+ 服务端仍需二次校验 |
| 有权限码但访问的具体资源不在自己数据范围内 | `NO_DATA_SCOPE`（403） | 拦截提示"当前身份无权查看该数据" |
| 有权限码、数据范围内确实没有数据 | `SUCCESS` + 空列表 | 正常空状态渲染，不视为越权 |
| 模块未授权（licenseContext 预留，租户未购买该模块） | `MODULE_NOT_AUTHORIZED`（403） | 未授权占位页 |
| 模块到期只读 | `MODULE_EXPIRED_READONLY`（403） | 只读态横幅提示，隐藏写操作按钮 |

- 前端安全底座目录：`frontend/src/security/`（`security.constants.js` 定义会话策略、敏感分级、上传/导出策略、审计事件类型、CSRF 常量）。
