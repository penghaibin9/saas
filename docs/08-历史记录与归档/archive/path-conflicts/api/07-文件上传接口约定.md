# 07 · 文件上传接口约定

> 文档性质：全端文件上传/下载通用接口约定（本轮新增）
> 适用端：全端共用（`/api/v1/files/*`）
> 依据：共享事实底稿 §4、§5；`frontend/src/security/constants/security.constants.js`（UPLOAD_POLICY）；引用历史冻结 `docs/api/00-API契约冻结总册.md` §一原则 9、§十
> 当前阶段声明：以下为契约设计，文件中心真实接口尚未接入；当前 PC/miniapp mock 均未真正上传文件（如 miniapp service-apply 页面 `pickFile()` 仅调用 `uni.chooseImage` 演示态选择，未真正上传）
> 生成日期：2026-07-04

---

## 一、核心原则：上传只返回 file_id

**业务写操作只提交 `file_id`（或 `file_id` 数组），不把文件本体写进业务表。** 这是文件中心与业务模块解耦的核心约定，后端实现任何涉及附件的写接口时必须遵守。

```text
① 前端选择文件 → ② 调用文件中心上传接口（与业务接口分离） → ③ 上传成功返回 file_id
→ ④ 业务表单提交时携带 file_id（如学生信息更正申请的证明材料、服务申请的附件、审批的证据材料）
→ ⑤ 后端把 file_id（或 file_id 数组）存入业务表对应字段，不存文件二进制或文件路径明文
→ ⑥ 需要查看/下载时，前端用 file_id 请求签名 URL，再从签名 URL 拉取文件内容
```

## 二、上传限制

| 项 | 规则 |
|---|---|
| 白名单类型 | pdf、doc、docx、jpg、jpeg、png、zip、rar、xlsx、pptx |
| 黑名单类型 | exe、js、bat、sh、php、jsp、html、svg（即使白名单未覆盖到的可疑类型，命中黑名单一律拒绝） |
| 单文件大小限制 | ≤50MB（可按业务类型细分配置，如身份证照片可能有更小的限制，具体细分规则待后端确认） |
| 超限/类型不符 | 返回 `UPLOAD_FAILED`（本轮统一码），历史冻结总册细分为 `FILE_TOO_LARGE`（413）/`FILE_TYPE_NOT_ALLOWED`（400）两种更细的码，后端实现时**优先采用历史冻结总册的细分码**以便前端区分提示文案，`UPLOAD_FAILED` 作为兜底/未分类上传失败使用 |

## 三、上传接口

| 项 | 内容 |
|---|---|
| 接口名称 | 文件上传 |
| 适用端 | 全端共用 |
| 请求方法 | POST（multipart/form-data） |
| 建议路径 | `/api/v1/files` |
| 请求参数 | multipart 表单：文件二进制 + `bizType?`（业务类型标识，用于分类存储与差异化限制，如 `STUDENT_CORRECTION_PROOF`/`SERVICE_APPLY_ATTACHMENT`/`CHECKIN_PHOTO`，待后端确认枚举清单） |
| 返回字段 | `{ fileId, fileName, size, mimeType, hash }` |
| 权限要求 | 登录态即可（具体业务附件是否需要额外权限点由调用方业务接口自行控制，文件中心本身只做类型/大小/病毒扫描等通用校验） |
| 数据范围要求 | 不涉及（上传行为归属操作者本人，写 `t_file_object` 关联 `uploader_id`） |
| 空状态 | 不适用 |
| 异常状态 | 文件类型不在白名单/命中黑名单；文件超过 50MB；网络中断上传失败 |
| 错误码 | UPLOAD_FAILED（本轮统一）；建议同时支持历史冻结总册细分码 FILE_TOO_LARGE（413）、FILE_TYPE_NOT_ALLOWED（400） |
| 审计 | 写 `UPLOAD` 审计事件 |

## 四、下载/预览接口（签名 URL）

| 项 | 内容 |
|---|---|
| 接口名称 | 获取文件签名下载/预览 URL |
| 适用端 | 全端共用 |
| 请求方法 | GET |
| 建议路径 | `/api/v1/files/{fileId}/url` |
| 请求参数 | 路径参数 `fileId` |
| 返回字段 | `{ url, expiresIn }`（短期签名 URL，含有效期，过期后需重新请求） |
| 权限要求 | 需具备该文件所归属业务对象的查看权限（由业务层校验后再放行文件中心签名，文件中心本身不重复判断业务权限，仅校验"该 file_id 是否存在于调用者有权访问的业务记录中"——具体实现方式待后端确认，建议业务接口返回详情时已带出 file_id，前端凭此 file_id 请求签名 URL，后端在生成签名前二次核对该 file_id 与请求者数据范围的关联关系） |
| 数据范围要求 | 与该文件关联的业务对象数据范围一致（如学生本人上传的材料，仅本人与有权限的教师/管理员可获取签名 URL） |
| 空状态 | 不适用 |
| 异常状态 | file_id 不存在；无权限访问该文件 |
| 错误码 | DATA_NOT_FOUND、NO_PERMISSION |
| 审计 | 敏感材料下载写 `t_file_access_log`（对应 `DOWNLOAD` 审计事件类型） |

## 五、上传 → file_id → 业务提交 → 下载 完整流程图（文字版）

```text
学生提交请假申请（含证明材料）示例：
1. 学生在 miniapp 选择"请假证明.jpg"
2. 前端调用 POST /api/v1/files（携带文件二进制）
3. 文件中心返回 { fileId: "f-xxx", fileName: "请假证明.jpg", size, mimeType, hash }
4. 前端调用业务接口 POST /api/v1/student-mini/internship/leaves
   body: { leaveType, startAt, endAt, reason, proofFileId: "f-xxx", clientDraftId }
5. 后端把 proofFileId 存入 t_leave.proof_file_id 字段，不存文件内容
6. 教师端审批详情页展示该材料时，前端凭 proofFileId 调用 GET /api/v1/files/f-xxx/url
7. 文件中心校验教师对该请假记录有查看权限后，返回短期签名 URL
8. 教师端浏览器/小程序直接用签名 URL 加载图片预览
```

## 六、miniapp 与 PC 端差异说明

| 维度 | miniapp | PC 管理端 |
|---|---|---|
| 选择文件方式 | `uni.chooseImage`（图片）/ `uni.chooseFile`（其他类型，视基础库支持情况） | 标准 `<input type="file">` 或组件库上传控件 |
| 当前 mock 实现 | 未真正上传，仅演示态占位（如 service-apply 页面 `pickFile()` 失败兜底文案"示例附件.jpg（演示）"） | 各模块导入导出功能同样为模拟回执，未真正处理文件二进制 |
| 上传时机 | 建议选择即上传（获得 file_id 后再随表单提交），避免表单提交时才处理大文件导致弱网环境超时 | 同样建议选择即上传，与 miniapp 一致 |
| 弱网处理 | miniapp 处于移动网络环境，建议上传失败可重试，且业务表单支持 `clientDraftId` 草稿机制（见 03 miniapp 接口契约 weekly-report 周报草稿说明），避免用户重复填写 | PC 端网络环境相对稳定，弱网重试优先级较低（待后端确认是否仍需实现） |
| 打卡照片 | 岗位实习打卡（`internship.checkin`）涉及的 `photoFileId` 走同一套文件中心上传流程，且**只在主动点击时采集定位**，禁止代打卡（见 05 接口鉴权与数据范围文档及历史冻结 05 岗位实习 API 5.6 红线说明） | 不涉及 |
| 文件预览 | 小程序内嵌预览组件（图片/PDF），走签名 URL | 浏览器新标签页预览或下载，走签名 URL |

## 七、错误码汇总

| code | 触发场景 | HTTP |
|---|---|---|
| UPLOAD_FAILED | 上传过程失败（类型不符/超限/网络中断等未细分场景） | 400/500 |
| DATA_NOT_FOUND | file_id 不存在或已被清理 | 404 |
| NO_PERMISSION | 无权限访问该文件对应的业务数据范围 | 403 |
