# 01 · 接口契约总览

> 文档性质：全端接口总览地图（不含逐接口细节，细节见 02/03 及历史冻结 01–05）
> 适用端：PC 管理端 / 学生小程序 / 教师移动端 / 平台运营端
> 依据：共享事实底稿 §1–§3、§5；`frontend/src/config/adminMenu.js`；`frontend/src/modules/*/api/*.api.js`；`miniapp/src/services/studentApi.js`、`teacherApi.js`；`docs/api/00-API契约冻结总册.md`
> 当前阶段声明：本表所列"当前 mock 门面方法"均为前端内存 mock 实现，真实网络接口尚未接入；"建议后端路径"为本轮契约设计，供后端按此实现
> 生成日期：2026-07-04

## 一、分端前缀表

统一版本前缀 `/api/v1`，以下前缀口径与历史冻结总册 `00-API契约冻结总册.md` §一致，本轮不新增前缀：

| 前缀 | 适用端 | 说明 |
|---|---|---|
| `/api/v1/admin/*` | PC 管理端 | 学校管理员、二级学院管理员、指导教师、辅导员、平台运营等 PC 端全部业务模块 |
| `/api/v1/student-pc/*` | 学生 PC 门户 | 学生用 PC 浏览器访问（长文本提交场景，如周报） |
| `/api/v1/enterprise-portal/*` | 企业导师 PC 端 | 后期建设，本轮不展开 |
| `/api/v1/student-mini/*` | 学生小程序 | miniapp 学生端（uni-app），对应 `services/studentApi.js` |
| `/api/v1/teacher-mobile/*` | 教师移动工作台 | miniapp 教师端（uni-app，多身份切换），对应 `services/teacherApi.js` |
| `/api/v1/platform/*` | 平台运营端 | 仅 PLATFORM_OPERATOR 角色，PC 内 `/admin/platform` 路由下但走独立业务前缀 |
| `/api/v1/authz/*` | 权限与身份底座 | 全端共用：登录/身份切换/菜单/按钮权限/模块授权，见历史冻结 `01-认证租户与当前上下文API.md` |
| `/api/v1/files/*` | 文件中心 | 全端共用：上传只返回 file_id，详见 `07-文件上传接口约定.md` |

> `tenant_id` 由后端从登录上下文解析，前端不传；当前角色用 `currentRoleCode` + `activeContextId` 表达；数据范围用 `dataScope` 表达（详见 `05-接口鉴权与数据范围.md`）。

## 二、契约来源说明

本表汇总的"当前 mock 门面方法"逐一来自以下前端源码文件（页面禁止直接 import mocks，必须经门面获取数据）：

| 端 | 门面文件模式 | 统一返回结构 |
|---|---|---|
| PC 管理端 · workflow 模块 | `frontend/src/modules/workflow/api/workflow.contract.js`（18 接口契约冻结，`workflow.api.mock.js` 为 mock 实现，`workflow.api.real.example.js` 为真实实现示例） | `{ code(number,0=成功), message, data, timestamp, requestId }` |
| PC 管理端 · student 模块 | `frontend/src/modules/student/api/student.api.js`（门面）+ `student.contract.js`（15 接口冻结契约，字段命名与本表略有差异，以 02 学生主档API.md 冻结口径为准） | `Promise<{code(0=成功), data, message}>` |
| PC 管理端 · 其余 9 个业务模块 | `frontend/src/modules/{orientation,campusService,academic,internship,graduation,employment,dataCenter,approval,system,platform}/api/*.api.js` | `Promise<{code(0=成功), data, message}>` |
| miniapp 学生端 | `miniapp/src/services/studentApi.js`（10 方法） + `services/request.js`（`mockRequest`） | mock 直接 resolve payload 对象（无 code 包裹），失败态 reject `{code:'MOCK_ERROR', message}` |
| miniapp 教师端 | `miniapp/src/services/teacherApi.js`（10 方法） + `services/request.js` | 同上 |

## 五、与历史冻结文档的边界

- 历史冻结 `01-认证租户与当前上下文API.md`、`02-学生主档与学生360API.md`、`03-数字迎新API.md`、`04-待办审批消息API.md`、`05-岗位实习API.md` 已对"认证/学生主档/数字迎新/待办审批消息/岗位实习"5 个域给出逐接口冻结契约（含 DB 表映射、一期 P0–P4 优先级），**本轮 02/03 文档对这些域不重复展开细节**，仅在总览表中标注引用关系，避免出现两份互相矛盾的接口定义。
- 本轮新增覆盖的域：workflow 权限与流程、campusService 在校服务、academic 学业过程、graduation 毕业设计、employment 就业服务、dataCenter 数据驾驶舱、approval 审批中心、system 系统管理、platform 平台运营，以及 miniapp 全部 20 个服务层方法 + 2 个表单提交接口。
