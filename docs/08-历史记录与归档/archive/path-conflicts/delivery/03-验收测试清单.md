# 03 · 验收测试清单

> 按模块逐项验收。**每项都标注它当前属于哪一档能力**，避免"以为是真实系统"的误会。
> 生成日期：2026-07-04

---

## 能力档位说明（贯穿全表）

| 标记 | 含义 |
|---|---|
| 🟢 可演示 | 界面 + 交互 + 流程可现场走通（用演示数据） |
| 🟡 mock | 能填/能提交/能看状态变化，但**数据不长期保存**（演示数据，刷新会回初始） |
| 🔵 待后端 | 需接入真实后端/数据库后才具备（真实保存、真实登录、真实统计、上传、推送等） |

> 验收原则：本阶段验收的是 **🟢 + 🟡**（界面与流程）。**🔵 属于后续阶段**，本次不作为"已完成"验收，只确认"设计已冻结、界面已预留"。

## 验收结论建议写法（避免争议）

建议验收结论按这样表述：

> "本阶段验收范围为**全端界面与业务流程演示（🟢/🟡）**，覆盖上述 13 个模块，界面完成度与流程走通情况符合演示要求；**真实后端与数据库相关能力（🔵）为约定的后续阶段交付**，其设计已在 `docs/database/`、`docs/api/` 冻结，界面已预留对接点。"

这样既承认已完成的工作，又不把"待后端"的部分算成已完成，双方口径一致。
