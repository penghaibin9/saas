## 一、总体原则

### 1.1 端侧定位（冻结，不得违反）

- **学生无 PC 门户**：PC 管理端 `require_staff`，学生令牌一律 403。教务面向学生的全部功能只在小程序（uni-app），新建教务 API 走 `/api/v1/mobile/academic-affairs/*`（复用既有 `/api/v1/mobile/academic/my/*` 成绩/预警端点不变）（读沿用既有 `{domain}/my` 风格）。
- **PC 仅教职工**：教师在移动端只做高频轻操作（查看/审批/处置/发起），重操作（成绩正式录入、培养方案编制、排课、毕业审核等）一律回 PC，见 §3.0 回 PC 项清单表。
- **不新建独立 App**：学生页面挂在既有小程序 `pages/student/*` 之下，教师页面挂在既有 `pages/teacher/*` 工作台之下，以卡片/宫格/待办接入，不另起端、不另建壳。
- **契约先行**：本文档给出的页面路径与端点是与 PC 页面树文档、后端契约文档三方对齐的唯一移动端基准。

### 1.3 复用既有小程序基建（全部页面强制遵守）

| 基建 | 用法约定 |
|---|---|
| realFirst 请求层 | 真实接口优先；**业务错误（code≠0）一律透出给页面处理，不做 mock 兜底**；仅纯网络失败进入可重试错误态 |
| createSubmitLock | 所有写操作按钮（提交/撤回/审批/处置）必须包防连点锁，请求返回前二次点击无效 |
| safeToast | 全部轻提示统一走 safeToast，禁止裸调 uni.showToast |
| 401 单飞刷新 | 401001 触发单飞（并发只发一次）refreshToken 刷新，成功后重放原请求；刷新失败清凭据跳登录页 |
| MobileGlobalState | 每页必须实现 loading（骨架/转圈）/ error（错误文案+【重试】按钮）/ empty（空态插画+引导文案）三态 |
| MobileSensitiveText | 身份证、手机号等敏感字段展示一律经脱敏组件（`*_encrypted` 出口已脱敏，前端不二次拼接明文） |
| 消息与待办 | 一律读 t_unified_message / t_unified_todo 的既有移动端消息中心，本设计只新增消息类型→路由映射（§4.3） |

### 1.4 统一错误码处理表

> 各页「错误码处理」小节均引用本表，只写本页增量特殊项。错误码与事实速查 §1 冻结清单一致。

| 错误码 | bizCode | 移动端统一表现 |
|---|---|---|
| 401001 | UNAUTHORIZED | 静默单飞刷新 token → 成功后重放原请求，用户无感知；刷新失败 → 清凭据跳登录页（不弹业务报错） |
| 403001 | NO_PERMISSION | 跳无权限提示页/页面内无权限态：「暂无权限查看此内容」；demo-school 只读锁写操作命中时统一文案「演示环境只读，请使用沙箱账号 sandbox-school 体验提交」 |
| 403002 | NO_DATA_SCOPE | 同 403001 展示形式，文案「该数据不在你的可见范围」；后端已记审计，前端不自动重试 |
| 404001 | DATA_NOT_FOUND | 页面内「数据不存在或已被删除」态 + 【返回】按钮；从列表点入命中 404 时返回并刷新列表 |
| 409001 | DATA_CONFLICT / IDEMPOTENCY_CONFLICT / APPROVAL_VERSION_CONFLICT | 提交类：safeToast「已有在途申请，请勿重复提交」并跳转/刷新到在途单详情；审批/处置类：「该任务已被处理」并刷新待办列表 |
| 422001 | VALIDATION_ERROR | **逐字段表单标红**：按返回的字段错误明细定位到具体控件下方红字，首个错误字段自动滚动到可视区；不弹整页错误、不清空已填内容 |
| 429001 | RATE_LIMITED | safeToast「操作过于频繁，请稍后再试」，按钮解锁允许稍后重试 |
| 网络失败 | —（无响应/超时） | 进入 MobileGlobalState.error 可重试错误态（错误插画+文案+【重试】按钮）；**不用 mock 数据兜底**；写操作失败不自动重发，由用户手动重试 |

### 1.5 通用交互约定

- 只读列表页统一支持下拉刷新；长列表触底加载更多；筛选项变化即时重拉。
- 写操作成功：safeToast 成功提示 → 返回上一页（列表）→ 列表自动刷新（onShow 携带刷新标记）。
- 审批结果到达：t_unified_message 收 WORKFLOW_RESULT → 消息中心点击 → 跳对应详情页（映射见 §4.3）。
- 状态标签颜色语义全端统一：**蓝**=进行中/审批中；**绿**=通过/正常；**橙**=退回/待办/需关注；**红**=拒绝/异常/风险；**灰**=已撤回/已归档/已结束。
- 学生 my 端点后端自动从 token 取 studentNo/tenant，前端**不传学生标识**；越权访问由后端 403/404 拦截并审计。

## 二、学生小程序 9 页逐页设计

> 学生总入口：小程序首页新增「教务服务」宫格分组，V1 仅渲染 7 个 V1 入口（P2 宫格由 feature flag 控制不渲染，避免空壳页）；另有消息中心卡片直达（§4.3）。

### 2.1 我的课表（周视图）★V1 只读

**页面路径与入口**
- 路径：新增 `pages/student/academic-affairs/schedule`（周视图为主页面；课程格详情用页内弹层，不单独建详情页）。
- 入口 1：学生首页「教务服务」宫格「我的课表」（一级高频位，建议置于分组首位）。
- 入口 2：消息中心 PUBLISHED_NOTICE（课表发布）/ STATUS_CHANGED（调停课变更）点击直达并定位变更周。
- 入口 3：「我的课程」详情【查看课表】回跳并定位该课程所在周。

**接口**
- `GET /api/v1/mobile/academic-affairs/my/schedule?termId=&week=`：读已发布课表按本人过滤；响应携带 currentWeek/totalWeeks/weekDates（教学周来自已发布校历）。

**展示字段**
| 区块 | 字段 |
|---|---|
| 顶部栏 | 学期名、第 N 教学周、本周日期范围、「今天」列高亮 |
| 周网格（7 天 × 节次） | 课程名、教师姓名、教室、节次跨度；调停课变更格子加「调/停/补」角标 |
| 课程格弹层 | 课程名、课程编号、教师、教室、周次范围（如 1-16 周）、节次、课程性质、调停课变更说明 |

**按钮与动作**
| 按钮 | 出现条件 | 动作 | 成功变化 |
|---|---|---|---|
| 周次左/右切换 | 常显（首末周单侧禁用） | 重拉目标周 | 网格切换渲染 |
| 周次选择器 | 常显 | 跳任意教学周 | 同上 |
| 【回到本周】 | 非当前周时 | 跳 currentWeek | 定位本周并高亮今天 |
| 学期切换 | 存在多学期时 | 重拉该学期课表 | 周次重置为该学期当前周 |
| 下拉刷新 | 常显 | 重拉当前周 | 网格刷新 |

**防重复**：只读页无写操作；周次/学期快速连续切换做请求防抖，以最后一次为准渲染，忽略过期响应。

**网络失败/错误码处理**：引用 §1.4 统一表。本页特殊项：课表未发布 → empty 态「本学期课表尚未发布」（不报错）；校历未发布导致无教学周 → 同 empty 态并提示以学校通知为准。

**成功后刷新策略**：下拉刷新重拉当前周；从调停课/发布类消息点入本页时强制刷新目标周数据，保证变更即时可见。

**状态展示**：课程格本身无业务状态机；变更角标——「调」橙色、「停」灰色（原格划线样式）、「补」蓝色；今天列底色高亮。

**V1/P2 标记**：★V1 只读。V1 数据源为 PC 课表导入+发布（页面树链路 2）；P2 自动排课上线不改变本页契约。

### 2.2 我的课程 ★V1 只读

**页面路径与入口**
- 路径：新增 `pages/student/academic-affairs/courses`（列表）+ `pages/student/academic-affairs/course-detail`（详情）。
- 入口 1：学生首页宫格「我的课程」。
- 入口 2：「我的课表」课程格弹层【查看课程】跳入详情。

**接口**
- 列表 `GET /api/v1/mobile/academic-affairs/my/courses?termId=`：本学期修读课程（按培养方案+已审教学任务生成，本人过滤）。
- 详情 `GET /api/v1/mobile/academic-affairs/my/courses/{courseId}`。

**展示字段**
| 区块 | 字段 |
|---|---|
| 列表项 | 课程名、课程性质（必修/选修/实践）、学分、周学时、任课教师、上课班级/合班标识、修读状态标签 |
| 详情 | 课程编号、课程类别、理论/实践学时、开课学期、先修课程、任课教师、上课时间地点汇总（读课表）、所属培养方案模块 |

**按钮与动作**
| 按钮 | 出现条件 | 动作 | 成功变化 |
|---|---|---|---|
| 学期切换 | 常显 | 重拉该学期课程 | 列表刷新 |
| 课程性质筛选 | 常显 | 本地/服务端过滤 | 列表过滤 |
| 下拉刷新 | 常显 | 重拉列表 | 列表刷新 |
| 【查看课表】 | 详情页常显 | 跳 2.1 并定位该课程所在周 | 页面跳转 |
| 【查看成绩】 | 修读状态=未通过时 | 跳 2.4 我的成绩 | 页面跳转 |

**防重复**：只读页无写操作；筛选/切换防抖。

**网络失败/错误码处理**：引用 §1.4。本页特殊项：新学期教学任务未审定 → empty「本学期课程尚未生成，请留意学校通知」。

**成功后刷新策略**：下拉刷新；学期切换即时重拉；无写操作触发的刷新。

**状态展示**：修读状态——在修（蓝）/已通过（绿）/未通过（红，仅成绩已发布后出现）。已通过/未通过判定读已发布成绩（t_acad_grade.pass_status），未发布不显示中间态。

**V1/P2 标记**：★V1 只读。选课（P2）上线后本页增加「选修待确认」状态与选课入口，V1 不渲染任何选课元素。

### 2.3 我的考试 ☆P2

**页面路径与入口**
- 路径：新增 `pages/student/academic-affairs/exams`（列表+详情弹层；缓考申请表单二级页 `exam-deferral-form`）。**P2 才注册页面**。
- 入口 1：学生首页宫格「我的考试」（**V1 不显示该宫格**）。
- 入口 2：消息中心考试发布 PUBLISHED_NOTICE / 考前 DEADLINE_REMINDER 点入。

**接口**
- 列表 `GET /api/v1/mobile/academic-affairs/my/exams?termId=`。
- 缓考提交 `POST /api/v1/mobile/academic-affairs/exam-deferrals`；撤回 `POST /api/v1/mobile/academic-affairs/exam-deferrals/{id}/cancel`（辅导员初审前）。

**展示字段**
| 区块 | 字段 |
|---|---|
| 列表（未考/已考分组，按时间排序） | 课程名、考试类型（期末/补考/缓考）、日期时间、考场、座位号、状态标签 |
| 详情 | 准考信息、考场地点楼层、注意事项、考后标记（缺考/违纪/缓考）、缓考申请状态与缓考安排 |
| 缓考表单 | 缓考原因（必填 10-500 字）、证明材料（按类型必填，PDF/JPG/PNG，单件 ≤10MB）、关联已批请假单（可选一键带入，联动请假模块） |

**按钮与动作**
| 按钮 | 出现条件 | 动作 | 成功变化 |
|---|---|---|---|
| 学期切换/下拉刷新 | 常显 | 重拉 | 列表刷新 |
| 【申请缓考】 | 该场未考且在申请窗口内、无在途缓考单 | 进缓考表单 | 提交后生成缓考申请 |
| 表单【提交】 | 表单页 | POST exam-deferrals | 返回列表刷新，考试行显示「缓考申请中」 |
| 【撤回】 | 缓考单 SUBMITTED 且辅导员未审 | POST cancel | 状态变 CANCELLED |

**防重复**：【申请缓考】提交与【撤回】走 createSubmitLock；服务端同一考试在途缓考申请唯一，重复提交 409001。

**网络失败/错误码处理**：引用 §1.4。本页特殊项：409001 → toast「该考试已有在途缓考申请」并跳该申请详情；422001 对原因/材料逐字段标红。

**成功后刷新策略**：缓考提交成功 → toast「已提交，等待辅导员初审」→ 返回考试列表并刷新；审批结果经 WORKFLOW_RESULT 消息点入本页详情；缓考安排发布经 PUBLISHED_NOTICE 点入。

**状态展示**：考试——未开始（蓝）/已结束（灰）/缺考（红）/缓考（橙）；缓考申请——SUBMITTED 审批中（蓝）/APPROVED 通过（绿）/RETURNED 退回可编辑重提（橙）/REJECTED 拒绝（红）/CANCELLED 已撤回（灰）。

**V1/P2 标记与降级说明**：☆P2（随考务 P2 上线，审批链：辅导员→任课教师→学院→教务，页面树链路 7）。**V1 降级**：入口宫格与页面均不渲染（feature flag），考试信息 V1 无移动端出口，不出现空壳页或悬空跳转。

### 2.4 我的成绩 ★V1 只读

**页面路径与入口**
- 路径：**复用既有** `pages/student/academic/grades` 成绩页骨架（事实速查 §9：pages/student 学业页面已有成绩骨架），扩展字段**不重建页面**，详见 §4.1。
- 入口 1：学生首页宫格「我的成绩」（既有入口保留位次）。
- 入口 2：成绩发布 PUBLISHED_NOTICE 消息点入并定位新发布学期。
- 入口 3：「我的课程」未通过课程行、「我的学业预警」涉及课程链入。

**接口**
- **复用既有** `GET /api/v1/mobile/academic/my/grades?termId=`（直读既有 t_acad_grade：course/term/score/pass_status）；13B 扩展响应字段（成绩构成、学分、绩点、补考重修标记），**不新增平行端点**。
- 单科详情 `GET /api/v1/mobile/academic/my/grades/{gradeId}`（新增下钻端点，仍挂 my 前缀）。

**展示字段**
| 区块 | 字段 |
|---|---|
| 顶部汇总卡 | 本学期已获学分、平均绩点、不及格门数（>0 红色提醒并链到我的学业预警） |
| 列表（按学期分组） | 课程名、课程性质、学分、总评成绩、通过状态标签；补考/重修后成绩带「补/重」角标与计分规则说明 |
| 单科详情 | 平时/期末/总评构成与占比、任课教师、考试类型、成绩更正记录（仅显示更正时间与原因摘要，不显示原始分值明细） |

**按钮与动作**
| 按钮 | 出现条件 | 动作 | 成功变化 |
|---|---|---|---|
| 学期切换 | 常显 | 重拉该学期成绩 | 列表与汇总卡刷新 |
| 仅看不及格 | 常显（开关） | 过滤 pass_status=未通过 | 列表过滤 |
| 下拉刷新 | 常显 | 重拉 | 刷新 |

> **无任何写操作**：成绩录入/审核/发布/更正一律回 PC（教师/教务），学生端纯只读（需求 §11 明确约定）。

**防重复**：无写操作。

**网络失败/错误码处理**：引用 §1.4。本页特殊项：成绩未发布的课程不出现在列表（不显示「录入中」中间态，避免学生误读）；本学期全部未发布 → empty「本学期成绩尚未发布」。

### 4.4 演示环境与安全

- **demo-school 只读锁**：本设计全部移动端写操作（异动提交/撤回、审批、预警处置、缓考/重修/调停课提交）在 demo-school 命中中间件 403 → 前端统一文案「演示环境只读，请使用沙箱账号（sandbox-school：student2/teacher2 · 123456，每晚 0 点重置）体验提交」。

### 5.2 移动端验收用例

**用例 1：异动重复提交 → 仅一条 + 409（必含）**
学生（sandbox-school student2）在「异动申请」提交一条休学申请成功 → 列表出现一条 SUBMITTED 单；不刷新页面再次进入表单提交同类型申请（或提交瞬间连点【提交】）→ createSubmitLock 保证连点仅发出一次请求；第二次提交服务端返回 409001 → toast「已有在途申请，请勿重复提交」并跳转在途申请详情；后台核查该学生休学在途申请**仅一条**；辅导员待办（t_unified_todo）仅生成一条。

**用例 2：跨学生越权 → 403/404（必含）**
学生 A 令牌构造请求学生 B 的异动详情（篡改 changeId）→ 返回 403002 或 404001（不泄露存在性），页面呈现「该数据不在你的可见范围/数据不存在」态，无任何 B 的字段泄露，后端留审计；非 B 授课/带班范围的教师经 URL 直入 B 的学生 360 → 403 + 审计。学生端所有 my 端点不接受显式 student_id 参数。

**用例 3：断网重试（必含）**
学生在「我的课表」加载中断网 → realFirst 不做 mock 兜底，页面进入 MobileGlobalState.error 可重试态（错误文案+【重试】按钮）→ 恢复网络点【重试】→ 正常渲染本周课表；异动表单提交时断网 → 提示网络失败、表单内容完整保留、按钮解锁，用户手动重试成功后仅生成一条申请（服务端在途唯一兜底幂等）。

**用例 4：422 逐字段标红（必含）**
学生提交休学异动：原因仅填 3 个字、未传证明材料、结束日期早于开始日期 → 服务端 422001 返回字段错误明细 → 表单在「原因」「证明材料」「休学期限」三个控件下方分别红字提示（原因需 10-500 字/材料必传/结束须晚于开始），页面自动滚动到首个错误字段，不弹整页错误、不清空已填内容；逐项修正后重新提交成功 → toast → 返回列表刷新，新单置顶且状态 SUBMITTED 审批中（蓝）。

**用例 5（补充）：审批版本冲突 409**
两名有权教师同时打开同一异动审批待办，教师甲移动端【通过】成功（POST /api/v1/mobile/teacher/approvals/{id}/approve）；教师乙随后点【通过】→ 409 APPROVAL_VERSION_CONFLICT → toast「该任务已被处理」并刷新待办列表，该项消失；学生端收到一条（且仅一条）WORKFLOW_RESULT，点击跳转异动详情，状态 APPROVED（绿），「我的学籍」刷新后体现变更。
