## 四、界面细节检查

- [ ] 无横向滚动条（PC 端各页面在常见分辨率下检查，尤其是表格类页面）
- [ ] 品牌占位正确：PC 端显示"演示职业技术学院"（各模块 mock 的 `schoolName`），miniapp 显示"示范高校"（`brand.config.js` 的 `schoolName`），两者不要在演示中混用说辞
- [ ] 品牌主色正确渲染（`#2563EB` 系，教师端强调色 `#0D9488`）
- [ ] 演示角色切换正常：按 `04-演示角色账号.md` 逐个角色切换一遍，确认切换后数据范围与工作台内容确有变化，无卡死或空白
- [ ] miniapp 页面切换/tab 切换时能看到短暂 loading 骨架屏（260ms 延迟），不是长时间卡顿

## 五、断网 / 错误态演示开关（可选，视听众需求决定是否演示）

- [ ] 确认是否需要演示 error / empty / forbidden / offline 等异常态
- [ ] 如需要演示：**当前所有 `mockRequest()` 调用默认不传 `fail:true`**，即默认不会触发 error 态；如确需展示，需与研发确认临时触发方式（如本地改一行代码传 `fail:true` 后演示，演示结束后务必改回，不要带着调试态提交代码或遗留在演示环境中）
- [ ] 如不需要演示异常态，此项可跳过，直接说明"异常态设计已具备，本次演示聚焦正常业务流程"

## 六、投屏与现场环境

- [ ] 投屏分辨率与浏览器窗口尺寸适配（建议使用 1920×1080 或以上，避免 PC 端表格类页面在低分辨率下出现意外换行/裁切）
- [ ] miniapp H5 演示建议使用浏览器"移动设备模拟"视图（开发者工具设备工具栏）或实际手机浏览器访问局域网地址，避免直接用桌面宽屏窗口展示手机端页面导致比例失真
- [ ] 演示设备电量/网络连接确认（本地 mock 演示不依赖外网，但局域网访问 `localhost` 时需确保投屏设备与开发服务器在同一网络，或直接在开发机上投屏）
- [ ] 演示前清一次浏览器缓存（含 localStorage/sessionStorage，避免 miniapp 会话状态残留导致身份切换结果与预期不符）
- [ ] 准备好 `05-演示场景脚本.md` 打印稿或第二屏幕，方便照稿讲解

## 七、演示中话术底线（不涉及可勾选项，供讲解人提醒自己）

- 被问"这是真实数据吗" → 统一回答"当前为 mock 演示数据，来自前端 mock 脚本，用于验证界面与业务流程设计，不接后端、不连数据库"
- 被问"能不能登录我的账号看看" → 统一回答"当前演示环境没有真实登录能力，是通过'选择身份'的方式演示不同角色看到的数据范围，真实账号体系将在后端接入后建立"
- 不主动展开讲解 mock 数据内部的已知不一致点（如学生档案摘要文案滞后、毕设时间线日期顺序问题），如被细心的听众发现，可如实说明"这是 mock 演示数据的已知小瑕疵，不影响功能设计的完整性，会在正式数据接入前修正"
