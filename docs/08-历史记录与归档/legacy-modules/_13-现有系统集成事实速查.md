# 13A/13B 设计必读：现有系统集成事实速查（以代码为准，2026-07 核对）

> 所有 13A/13B 设计文档必须与本文件对齐，禁止与下列既有实现冲突或重复造轮子。

## 1. 统一响应与错误码（冻结，不得另造）
响应体：`{ code(数字), bizCode(字符串), message, data, traceId, timestamp }`；成功 code=0/bizCode=SUCCESS。
错误：401001 UNAUTHORIZED / 403001 NO_PERMISSION / 403002 NO_DATA_SCOPE / 404001 DATA_NOT_FOUND / 409001 DATA_CONFLICT·APPROVAL_VERSION_CONFLICT·IDEMPOTENCY_CONFLICT / 422001 VALIDATION_ERROR / 429001 RATE_LIMITED / 400001 BAD_REQUEST。业务错误绝不 500。

## 2. 认证与租户（已实现）
- 真实登录 `POST /api/v1/auth/login`（pbkdf2，失败 5 次锁 15 分钟，审计）。mock-login 生产 403。
- Token claims：`userId=db-<id>`、realName、userType(STUDENT/TEACHER/ADMIN)、tid(租户码)、tenantId、tenantName、activeContextId=`ctx_<login_name>`、currentRoleCode、学生附 studentNo。refreshToken/jti 黑名单已落库（t_auth_refresh_token / t_auth_blocked_jti），多 worker 可用。
- 租户：单库行级 `tenant_id BIGINT`。既有租户：主 demo=…001；demo-school=…003（**中间件只读锁**：写操作 403）；trial=…004；expired=…005；disabled=…006；sandbox-school=…007（**每晚 0 点自动重置**）。到期租户只读中间件已存在。
- PC 仅教职工（`require_staff`，学生令牌 403）；学生一律走 `/api/v1/mobile/*`。

## 3. 数据库与模型约定（冻结）
- 表名 `t_` 前缀 snake_case；BIGINT 主键；公共字段 tenant_id/created_at/updated_at/created_by/updated_by/is_deleted/version（乐观锁）；审计/流水表 append-only。
- 敏感字段 `*_encrypted` 存储，出口一律脱敏（`_mask_phone`/`_mask_id_card`）。
- 组织：`t_college(code,college_name)`、`t_major(college_id,code,major_name)`、`t_class(major_id,class_name,grade,counselor_id,head_teacher_id)`。
- 学生主档：`t_student_profile`（student_no/real_name/college_id/major_id/class_id/grade/current_stage/student_status/id_card_encrypted…）+ `t_student_contact`（联系方式，读时脱敏）+ `t_student_stage_event`（阶段事件→360 时间线数据源）。
- 统一待办/消息：`t_unified_todo`（assignee_id/student_id/todo_type/source_module/due_at/status）、`t_unified_message`（receiver_id 精确接收人，已有"标已读"端点）。13A/13B 的通知与待办**必须写这两张表**，不得自建消息表。
- 审计：`app.services.audit_log.record(action, resource, detail, result)`（DB 模式落 t_security_audit_log，含 ip/ua/traceId）。域级留痕另有 t_*_audit_trail（append-only）。
- 导出登记：`t_export_task`（用途/行数/sha256/水印）。

## 4. Workflow（已实现，13A/13B 审批必须复用）
- `t_workflow_instance` + `t_workflow_task`（node_code、status=PENDING/APPROVED/REJECTED/TRANSFERRED、acted_at、action_reason、version 乐观锁；已处理再审 → 409 APPROVAL_VERSION_CONFLICT）。
- PC API：`/api/v1/approvals/tasks`、`/{id}/approve|reject|transfer`、`/processed`、`/cc`（require_staff，审计）。
- 移动包装（含教师范围校验+审计+409）：`POST /api/v1/mobile/teacher/approvals/{id}/approve|reject`。
- 13A/13B 新审批 = 新 workflow_code + node_code 序列，节点流转逻辑在各自 service，但任务/实例落这两张表，待办进 t_unified_todo。

## 5. 教师数据范围（已实现，必须复用扩展）
- `t_teacher_student_scope`（teacher_key=登录名或姓名、role_code 空=全角色、scope_type=CLASS/COLLEGE/STUDENT/ADVISOR、ref_value、status）。
- 统一函数（mobile_teacher_service）：`resolve_teacher_scope(user)` → mode=SCOPED/ADMIN_TENANT/TENANT_FALLBACK + classNames/studentNos/collegeNames/advisorNames；`scope_match_row(scope,…)`；`can_teacher_view_student(user,stu,scope,db)`（学号/班级/学院/导师四路判定，越权 403+审计）。
- 需求书中的 getCounselorScope/getStudentAffairsScope/getAcademicScope 应设计为**该机制的封装/扩展**（如新增 scope_type=DORM_BUILDING、PSY_STUDENT），不另起炉灶。
- 原则：**看得见=能处理**（列表过滤与写操作校验共用同一 scope 函数），教师列表已按此实现（实习/毕设/就业/风险/待办/消息/审批）。

## 6. 已有六域与 13A/13B 的表级衔接（防重复建设，设计必须显式处理）
- **请假已存在**：campus-service `t_cs_leave`（PENDING_REVIEW/APPROVED/RETURNED，approve/return API + 批量），及移动端学生提交（防重复 409）。13A 请假 = 在其上**扩展**（状态机扩展/审批流升级/销假续假新表关联），设计文档必须给出「扩展 vs 平迁」决策与数据迁移说明，不得平行再建一套请假。
- **处分已存在骨架**：`t_cs_discipline`（record_status ACTIVE，学生端只回数量不回明细）。13A 处分流程在其上升级或新表引用之，需说明归属关系。
- **心理已存在骨架**：`t_cs_mental_record`（强权限）。
- **宿舍已存在骨架**：`t_cs_dorm_record` / `t_cs_dorm_exception`（迎新分宿在 orientation：building/room/dorm_status）。
- **学业预警已存在**：academic `t_acad_warning`（PENDING_HANDLE/PROCESSING/ESCALATED/CLOSED + close/escalate/assign/remind API + 移动端处理端点）。13B 学业预警 = 扩展其规则引擎与来源，不新建预警表。
- **补考/重修已存在骨架**：`t_acad_makeup` / `t_acad_retake`；成绩表 `t_acad_grade`（course/term/score/pass_status）。
- **学籍**：现为 StudentProfile.current_stage(ORIENTATION/ON_CAMPUS/INTERNSHIP/GRADUATION_DESIGN/EMPLOYMENT) + student_status(NORMAL 等) + StageEvent。13B 学籍状态机（在籍/休学/复学/退学…）应设计为 student_status 的受控扩展 + 异动表新增，禁止再建学生主表。
- 实习：t_internship_record/weekly_report/checkin/attendance_exception/risk_record（周报批阅、打卡、异常处理、转风险已实现）。
- 毕设：t_gd_student/topic/proposal/final/defense_group（开题/终稿批阅已实现）。
- 就业：t_emp_student/company/job/material/followup（跟进、材料核验已实现）。
- 迎新：t_orientation_student/material/green_channel/exception(+followup)。
- **学生360现状**：mobile teacher `student/{id}` 聚合六域 + StageEvent 时间线。13A/13B 的"进入学生360"= 写 StudentStageEvent/域记录被该聚合读取，设计需列明每业务落哪张表、聚合端点如何扩展。

## 7. 统计（已实现模式）
`/api/v1/stats/overview|lifecycle|risk|workbench`（require_staff，租户内 count 聚合，实时）。13A/13B 统计指标接入方式=扩展 stats_service 聚合 + dashboard 按角色 preset；辅导员维度走 scope 过滤。

## 8. 导入导出（已实现能力）
导入：模板→dry-run 行级错误（行号/字段/原因）→批次确认整批事务→5000 行/20MB/类型白名单→跨租户批次拒绝。域通用导入 `/api/v1/import/domain/{domain}/validate|confirm`。
导出：`/api/v1/export/domain/{domain}`（用途必填≥5字、脱敏列、首行水印、t_export_task 留痕、5 次/分限流、5000 行上限、下载审计）。13A/13B 新增导入导出=注册新的 domain 配置，复用该管线。

## 9. 前端事实
- PC：Vue3 + vite，路由 `/admin/<module>/…`，全站强制登录（无 token 跳 /login），token 存 sessionStorage，右上角 AppUserChip（退出）。模块目录 `frontend/src/modules/<name>/`（api/ routes/ views/），mock 兜底 withFallback（仅网络失败）。
- 小程序：uni-app Vue3 options API；页面 `pages/student/*`、`pages/teacher/*`；请求层 realFirst（业务错误透出不兜底）、createSubmitLock 防连点、safeToast、401 单飞刷新失败跳登录；MobileGlobalState(loading/error/empty)；MobileSensitiveText 脱敏展示；教师端移动写操作全部走 `/api/v1/mobile/teacher/*` 包装（范围+审计+409）。
- 演示账号（登录页明示）：demo-school admin/teacher/student·123456（只读）；sandbox-school admin2/teacher2/student2·123456（0 点重置）。
