## 一、总体原则（对齐 12 号中心十条铁律 + 现有基建）

1. **两种模式**（12 号 §1.2）：轻量模式=Excel 导入（见文件一，V1 唯一通道）；集成模式=API/中间库/文件交换（本文件，V1 仅预留框架）。
2. **先注册后调用**：任何外部系统对接先登记 t_external_system（系统名/厂商/对接模式/凭证），无注册不放行。
3. **暂存区铁律**：外部数据进业务表前必经 t_integration_staging → 校验 → 身份匹配（映射到 student_id）→ 业务表写入，禁止直写业务表（12 号 §3.2 数据流总链路）。
4. **复用现有安全底座**：统一响应与错误码（速查 §1，业务错误绝不 500）；审计 `audit_log.record()` 落 t_security_audit_log；敏感出口 `_mask_phone`/`_mask_id_card`（backend/app/services/db_service.py）；导出水印+t_export_task（domain_export_service.py）。
5. **鉴权双轨制**：内部三端（PC/学生小程序/教师移动）继续走现有 JWT token 体系（`POST /api/v1/auth/login`，claims 含 tid/tenantId/userType，refresh/jti 黑名单已落库，速查 §2）；**对外开放接口走独立的 app_key/secret 验签轨**（§4），两轨互不混用——开放接口永不签发用户级 JWT，外部系统拿不到内部 token。
6. **只读优先**：对外开放 V1 一律只读；任何回写场景必须走审批式设计评审（P2+），且回写只允许进暂存区再走校验链路。
7. **租户隔离**：外部系统注册、开放应用、调用日志全部挂 tenant_id；一个 app_key 只属于一个租户，跨租户查询按"不存在"处理（对齐导入批次隔离口径）。

## 三、14 类对接对象逐个设计

> 每对象统一八要素：对接模式 / 同步方向与频率 / 失败重试 / 冲突处理 / 字段映射要点 / 鉴权 / 日志审计 / 失败提示策略；末行给 V1 档位。
> 通用约定（逐对象不重复）：①同步任务全部登记 t_sync_task/t_sync_batch，失败行进 t_sync_error（错误原因+处理建议，12 号铁律 8）；②重试默认指数退避 1min/5min/30min 三次，仍失败转人工工单并推 t_unified_todo 给系统管理员；③全部调用记 t_api_call_log 或 t_integration_audit_log；④页面失败提示遵守统一错误码，网络类提示"外部系统暂不可用，已加入重试队列（批次号 xxx）"，数据类提示具体行级原因并给下载差异清单入口——**外部系统故障绝不阻塞本系统内闭环功能**（降级只读缓存展示+staleness 时间戳）。

### 3.5 CAS / OAuth2 统一身份认证（含 OIDC/LDAP 预留）

| 要素 | 设计 |
|---|---|
| 对接模式 | **API（标准协议）**：CAS 3.0 ticket 校验 / OAuth2 授权码 / OIDC；LDAP 仅账号校验兜底。登录方式配置表位对齐 12 号 §6.7.2（登录方式/启用状态/适用端/回调地址/Token有效期/是否自动创建账号/是否强制绑定） |
| 方向与频率 | 认证时实时（外→本）；无批量同步 |
| 失败重试 | 认证不重试（用户重登）；健康检查 5min 探活，故障自动降级**本地账号登录**（本地账号永远保留，12 号 §6.7.1） |
| 冲突处理 | 账号映射：学号→student_id、工号→user_id（12 号 §6.7.3）；映射不上→按配置"自动创建（默认关）/人工审核绑定"；一外部账号绑多本地身份→登录后走现有 role-switch 页 |
| 字段映射要点 | CAS attributes 中取 employeeNumber/studentNumber；缺属性学校走"首登补绑"页 |
| 鉴权 | 协议本身；**认证成功后一律换发本系统自有 JWT**（claims 结构不变，速查 §2），后续链路零改动 |
| 日志审计 | 每次 SSO 登录 audit_log.record("SSO_LOGIN")；绑定/解绑强审计 |
| 失败提示 | "学校统一认证暂不可用，请使用本地账号登录"（登录页降级开关） |
| V1 档位 | **V1 预留**：登录方式配置的数据结构与登录页协议分支占位冻结，不实施联调（见 §5） |

## 四、开放接口设计（/api/open/v1/*，V1 框架预留）

### 4.1 命名空间与隔离

- **对外命名空间 `/api/open/v1/*`**，与内部 `/api/v1/*` 物理隔离：独立 APIRouter、独立鉴权中间件（不挂内部 JWT 校验、不挂 require_staff），部署层可独立限流与灰度。融合证据报告已确认该前缀零占用。
- 管理端（配置开放应用/查日志）沿用 12 号 §10.5 规划路径 `/api/v1/integration/open-apps|api-catalog|api-call-logs`，页面进 `/admin/platform` 既有平台模块（速查 §11：不新建管理端），租户侧配置页进系统设置。
- 响应体沿用统一结构 `{code,bizCode,message,data,traceId,timestamp}`（速查 §1），新增开放域错误：401002 OPEN_AUTH_FAILED（验签失败）、403003 OPEN_SCOPE_DENIED（越权范围）、403004 OPEN_IP_REJECTED、429001 RATE_LIMITED（复用）。

### 4.2 租户级 app_key/secret 与验签

- 落表沿用 12 号 §9.11/9.12：`t_open_app`（tenant_id/app_name/app_key 唯一/secret_hash/status/有效期）+ `t_open_app_permission`（授权 API 清单+数据范围+限流策略）。secret 仅创建/重置时一次性明文展示，库中只存 hash（对齐现有 pbkdf2 口径）。
- 验签：请求头 `X-App-Key` + `X-Timestamp` + `X-Nonce` + `X-Signature`，签名 = HMAC-SHA256(secret, method+path+sorted(query)+timestamp+nonce)；时间窗 ±5 分钟，nonce 10 分钟内去重防重放。
- 数据范围（12 号 §6.5.4）：全校/本学院/指定专业/指定班级/指定数据对象 × 只读/读写——**V1 只发只读**；范围过滤实现复用 t_teacher_student_scope 同型的范围判定思想，落在开放层独立实现（不与教师 scope 混表）。

### 4.3 限流 / IP 白名单 / 熔断

| 控制 | 默认值（平台规则中心键，租户可覆盖） | 说明 |
|---|---|---|
| 每分钟请求数 | openApi.rate.perMinute = 60 | 超限 429001 RATE_LIMITED，Retry-After 头 |
| 每日请求数 | openApi.rate.perDay = 10000 | 12 号 §6.5.4 限流策略四件套 |
| 并发数 | openApi.rate.concurrency = 5 | |
| 失败熔断 | 连续 5xx≥20 次/5min 自动停用应用并告警 | 12 号"停用异常应用"；恢复需管理员手动启用 |
| IP 白名单 | 逐应用配置，空=拒绝一切（默认关） | 403004 |

全部阈值接现有平台规则中心（platform_service.safe_rule，速查 §11），不新建配置端。

### 5.3 红线

1. V1 不写任何外部系统适配代码；不建 12 号中心的表以外的任何集成表。
2. 外部数据永不直写业务表（暂存区铁律）；开放接口 V1 永不放写权限。
3. 心理记录、家庭经济明细、完整证件号**永不进开放接口**（任何档位）；成绩开放需租户二次确认。
4. 内部 JWT 与开放 app_key 两轨永不互通；开放层拿不到、也不代理内部端点。
5. 对接失败不得阻塞校内闭环：所有外部依赖项均有"人工登记/UNKNOWN 三态/末次快照"降级路径（§3 逐对象已注明）。
