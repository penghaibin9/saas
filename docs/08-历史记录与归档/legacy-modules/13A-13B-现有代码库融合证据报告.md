### 2.3 裁定（最终，覆盖既有文档）

- **13A = `student-affairs`（学工中心）**——维持既有 13A 文档集命名不变（13A 十份文档已统一使用 student-affairs / studentAffairs / t_affairs_\*，实测 grep 计数见 2.5）。
- **13B = `academic-affairs`（教务中心）**——**推翻**既有 13B 文档集与 _13-现有系统集成事实速查.md §10 采用的 `academic-affairs`。理由：
  1. **零前缀碰撞**：/api/v1/academic-affairs、/admin/academic-affairs、academicAffairs.\*、t_aa_\* 与现有 /api/v1/academic（backend/app/api/v1/router.py 第 33 行）、/admin/academic（frontend/src/modules/academic/academic.routes.js）、academic.\* 权限键、t_acad_\*（backend/app/models/academic.py）作为完整标识符均不相等；尤其 **t_aa_\* 与 t_acad_\* 不存在肉眼/补全混淆**，而 academic-affairs 方案的 t_aa_\* 与 t_acad_\* 高度相似（这正是 _13-事实速查 §10 自己都要求"文档中需给出两者映射说明"的原因——说明该方案先天带混淆税）。
  2. **语义准确**：Academic Affairs 即"教务"，直接对应甲方需求域（学年学期/校历/学籍/异动/培养方案/课程/课表/考试/成绩/学业预警/毕业审核，发现于 docs/modules/_13-需求输入-V1.1.md §1）；academic-affairs 不携带该语义。
  3. **与 student-affairs 严格对仗**：学工处/教务处（Student Affairs / Academic Affairs）成对出现，PC 菜单、权限前缀、表前缀、移动端前缀全线对称，降低 20 份文档与后续代码的记忆成本。
