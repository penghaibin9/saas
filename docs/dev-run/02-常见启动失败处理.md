# 02 · 常见启动失败处理

出红字不要慌：**只看窗口里第一条红字**（后面的红字大多是被第一条带崩的），然后在下面找对应症状。

## 1. 提示 "npm 不是内部或外部命令" 或 "无法将 npm 项识别为..."

原因：没装 Node.js。
处理：去 https://nodejs.org 下载 LTS 版安装 → 关掉所有 PowerShell 窗口重新打开 → 再启动一次。

## 2. 提示 "在此系统上禁止运行脚本"（ExecutionPolicy / 执行策略）

原因：Windows 默认不让直接跑 .ps1 脚本。
处理：不要双击运行脚本，改用带 `-ExecutionPolicy Bypass` 的完整命令，例如在项目根目录执行：

```
powershell -ExecutionPolicy Bypass -File scripts\dev\start-all.ps1
```

## 3. npm install 报错（一堆红字，带 network / timeout / 404）

第一步：检查网络能不能上网。
第二步：删掉出问题工程里的 `node_modules` 文件夹（比如 `frontend\node_modules`）。
第三步：重新运行对应的 start 脚本，让它重新安装。
还不行：在出问题的工程目录（如 `frontend`）执行 `npm install --registry=https://registry.npmmirror.com` 换国内镜像。

## 4. 小程序启动/构建报 manifest.json 相关错误（JSON 解析失败）

可能原因：`miniapp\src\manifest.json` 被意外截断（文件结尾缺了半截，曾出现过这种现象）。start-miniapp 和 project-status 脚本会自动检测并提醒。
处理：在**项目根目录**执行下面一条命令，把它恢复成 git 里的完好版本：

```
git checkout -- miniapp/src/manifest.json
```

然后重新运行 `scripts\dev\start-miniapp.ps1`。

## 5. 提示端口被占用（port 5173 is in use / EADDRINUSE）

看 [03-端口占用处理.md](03-端口占用处理.md)。vite 一般会自动换端口，以窗口里显示的地址为准。

## 6. 窗口一闪就没了

原因：直接双击了 .ps1 文件。
处理：按 01 文档的方式，在项目根目录的 PowerShell 里用完整命令运行，报错信息就能留在窗口里看到。

## 7. 浏览器打开是空白页或"无法访问"

第一步：回到启动窗口看编译完成没有（要出现 ready / Local: http://... 字样才算好）。
第二步：确认地址和窗口里显示的一致（端口可能自动换了）。
第三步：跑一次自检：`node scripts\check\smoke-check.mjs`。

## 8. 后端窗口提示"还在搭建中/缺少入口，跳过"

这不是错误。后端正在搭建（Python/FastAPI），入口文件还没写好时本来就启动不了；PC 和小程序用的是 mock 数据，不受影响。等后端搭建完成后，同一个脚本 `scripts\dev\start-backend.ps1` 就能直接启动它（会自动创建 .venv 并安装依赖）。

## 还是解决不了？

把窗口里**第一条红字**截图，发给 AI 或有经验的同学，并说明你运行的是哪条命令。
