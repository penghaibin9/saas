## 一、本目录是什么 / 不是什么

**是**：
- 一份写给后端开发团队的**任务清单 + 联调顺序 + 验收标准**，告诉后端"接下来要做什么、按什么顺序做、做到什么程度算完成"。
- 一份写给前后端联调双方的**对齐文档**，明确"前端已经按契约把 mock 门面搭好了，后端只要照着契约实现，前端只切数据源，不改业务代码"。

**不是**：
- 不是 API 契约本身（契约见 `docs/api/`，本目录只引用、不重写、不新增接口定义）。
- 不是数据库表结构文档（表结构见 `docs/database/00-数据库设计冻结总册.md`，本目录只引用、不新增字段、不新增表）。
- 不包含任何后端代码、任何数据库迁移脚本、任何前端代码改动方案。

## 三、接入总原则（贯穿全部 10 篇文档）

1. **契约先行、后端对齐前端已搭好的门面**：前端每个业务模块已有 `api/xxx.api.js`（页面唯一数据入口）、部分模块已有 `xxx.contract.js`（契约）与 `xxx.api.real.example.js`（真实实现示例）。后端按 `docs/api` 契约实现接口后，前端**只切换 api 实现（mock → real），页面与 store 层不应改动一行**。
2. **数据库只引用、不重写**：本目录所有表结构表述一律采用"依赖表：见冻结总册中的 X 表"的方式；不确定的表名一律标注"（待与冻结总册核对）"，禁止杜撰字段或新表。
3. **服务端二次鉴权是安全底线**：前端隐藏菜单/按钮/字段只是体验优化，服务端必须对权限码、数据范围、模块授权重新校验，不可信任前端传参（详见 `05-鉴权与权限接入.md`）。
4. **统一响应结构与错误码是硬约束**：所有接口返回 `{code, message, data, traceId, timestamp}` 五字段结构，`code` 为字符串枚举（详见 `01-后端接入总览.md` 与 `docs/api/04-统一响应结构与错误码.md`）。
5. **不写后端代码、不写数据库迁移、不重写数据库**：本目录是任务清单/顺序/注意事项/验收标准，具体实现由后端开发团队按清单执行。
