- **文档性质**：敏感操作专项权限清单
- **适用端**：PC 管理端 + miniapp（敏感数据/导出类操作以 PC 端为主，miniapp 侧主要涉及 `student360.view` 等查看类敏感操作）
- **依据**：
  - `frontend/src/security/constants/security.constants.js`（`SENSITIVE_LEVEL`、导出策略、审计事件类型）
  - `docs/05-数据接口权限与安全/security/00-等保三级安全基线总册.md`（引用，不重写）
  - `frontend/src/modules/workflow/`（`workflow.mock.js` permissions[] 中的 `student.identity.*`/`student.guardian.*`/`security.export.*` 等）
  - `frontend/src/mocks/student/student.mock.js`（`viewSensitive`/`exportArchive` 等细粒度按钮）
  - 共享底稿第 4 节安全基线、第 6 节统一错误码
- **当前阶段声明**：本清单所列"是否脱敏""是否写审计"均为前端 mock 设计意图的如实记录，**当前系统尚未通过等保三级测评**，真实的脱敏规则、审计落库、敏感字段加密存储等均需后端在数据库与接口层正式实现后方可视为生效；前端隐藏/脱敏展示不能替代服务端强制校验。

## 一、敏感分级定义（`SENSITIVE_LEVEL`）

| 分级 | 说明 |
|---|---|
| `PUBLIC` | 公开信息，无查看限制 |
| `INTERNAL` | 校内可见，登录用户在权限范围内均可查看 |
| `SENSITIVE` | 敏感信息，**默认脱敏**展示，需特定权限点才能查看完整值 |
| `SECRET` | 机密信息，**禁止前端明文展示**，如密码、完整身份证号 |

## 二、敏感操作专项清单

### 2.1 查看敏感数据（身份证/手机号/监护人信息）

| 项目 | 内容 |
|---|---|
| 所需权限点 | `student.identity.view`（身份信息）、`student.contact.view`（联系方式/手机号）、`student.guardian.view`（监护人信息）；细粒度按钮对应 `viewSensitive` |
| 允许角色 | `SCHOOL_ADMIN`（明确具备）；`COLLEGE_ADMIN`/`TEACHER`/`COUNSELOR` 是否具备完整查看权限，底稿未逐一明确，**待后端确认**，当前建议按最小权限原则仅授予 `SCHOOL_ADMIN` 及必要的学籍管理角色（如 `REGISTRAR` 学籍老师画像，见 `06-权限按钮清单.md` 说明） |
| 数据范围要求 | 需叠加数据范围过滤：即使拥有 `student.identity.view` 权限点，也只能查看本角色数据范围内的学生身份信息（如辅导员即使有权限点也只能看本班级学生，不能看全校） |
| 是否脱敏 | **是**。身份证号、手机号默认按 `SENSITIVE` 分级脱敏展示（如身份证号中间位掩码），完整身份证号属 `SECRET` 级，**禁止前端明文展示**，如确需查看完整值需字段级权限 + 审计（见共享底稿第 5 节"敏感字段默认脱敏，查看完整值需字段权限 + 审计"） |
| 是否写审计 | **是**，审计事件类型 `SENSITIVE_VIEW` |
| 敏感分级 | 身份证号：`SECRET`（完整值）/ `SENSITIVE`（脱敏摘要）；手机号：`SENSITIVE`；监护人信息（姓名+联系方式）：`SENSITIVE` |

### 2.2 导出（三档）

| 档位 | 所需权限点 | 说明 |
|---|---|---|
| LIST（清单档） | `security.export.list` | 导出摘要级清单，字段范围小、默认脱敏程度较高 |
| ENCRYPTED_ARCHIVE（加密归档档） | `security.export.archive` | 导出较完整的档案数据，导出文件需加密处理（具体加密方式待后端确认） |
| DESENSITIZED（脱敏导出档） | `security.export.desensitized` | **默认 `DISABLED`**，专业版功能开启后才可用；即使开启，导出内容仍按脱敏规则处理 |

| 项目 | 内容 |
|---|---|
| 允许角色 | `SCHOOL_ADMIN`（明确具备三档权限点绑定）；其他角色是否具备导出权限，底稿未逐一列出，**待后端确认**，建议默认收紧为仅 `SCHOOL_ADMIN` 及系统管理员角色可用 |
| 数据范围要求 | 导出内容需先按当前角色数据范围过滤，再叠加导出行数上限（默认 ≤5000 行，见共享底稿第 4 节导出策略） |
| 是否脱敏 | LIST/ENCRYPTED_ARCHIVE 档默认按字段敏感分级脱敏（`SECRET` 级字段一律不导出明文）；DESENSITIZED 档顾名思义强制脱敏 |
| 是否写审计 | **是**，审计事件类型 `EXPORT`（对应共享底稿第 4 节"导出写审计"） |
| 敏感分级 | 视导出字段范围而定：含身份证/监护人等字段的导出为 `SECRET`/`SENSITIVE`级操作；仅含姓名学号等基础字段的清单导出为 `INTERNAL` 级 |
| 学生模块对应按钮 | `exportStudents`（学生列表导出）、`exportArchive`（学生档案导出，敏感级更高）、`exportStatusRecords`（学籍变更记录导出）、`exportIdentityRecords`（身份核验记录导出）、`exportCorrections`（信息纠错记录导出）、`exportRiskList`（风险学生清单导出） |

### 2.3 批量操作

| 项目 | 内容 |
|---|---|
| 所需权限点 | 无统一的 `batch.*` 权限点，各批量按钮独立控权：`batchAssignClass`（批量分班）、`batchAssignCounselor`（批量分辅导员）、`batchRemind`（批量催办）、`batchChangeStatus`（批量学籍变更）、`batchRemindRisk`（批量催办风险学生） |
| 允许角色 | `SCHOOL_ADMIN`（明确具备大部分批量操作）；`COUNSELOR` 具备 `batchRemind`/`batchRemindRisk` 类催办操作（依据其班级管理职责推断，**待后端确认**具体绑定） |
| 数据范围要求 | 批量操作的对象集合必须完全落在当前角色数据范围内；若批量操作请求中混入超出数据范围的对象 ID，应整体拒绝或过滤剔除并提示（具体策略待后端确认），不能"部分执行"而不告知调用方 |
| 是否脱敏 | 不涉及数据展示脱敏问题，但操作日志中涉及的学生身份信息应遵循同等脱敏规则 |
| 是否写审计 | **是**，批量操作因影响面大，建议记录审计事件（类型对应具体操作，如 `batchChangeStatus` 对应学籍异动类审计，见 2.5 节） |
| 敏感分级 | `batchChangeStatus`（批量学籍变更）敏感级较高，归入 `SENSITIVE`；`batchRemind` 类催办操作敏感级较低，归入 `INTERNAL` |

### 2.4 审批

| 项目 | 内容 |
|---|---|
| 所需权限点 | `workflow.task.approve`（通过）、`workflow.task.reject`（驳回）、`workflow.task.withdraw`（撤回）；业务专项审批：`internship.apply.review`、`internship.report.review`/`reject`、`graduation.topic.approve`、`graduation.material.review`（DISABLED）、`onboarding.material.review`（DISABLED） |
| 允许角色 | `SCHOOL_ADMIN`（全部）、`COLLEGE_ADMIN`（`workflow.task.*`、`internship.apply.review`、`graduation.topic.approve`、`onboarding.material.review`）、`TEACHER`（`workflow.task.*`、`internship.report.review`/`reject`、`graduation.material.review`）、`STUDENT`（仅 `workflow.task.withdraw` 本人任务） |
| 数据范围要求 | 审批人只能审批数据范围内的任务（如 `TEACHER` 只能批阅 `ASSIGNED` 范围内学生的实习周报/毕设材料） |
| 是否脱敏 | 审批过程中若涉及学生敏感信息展示，遵循 2.1 节脱敏规则 |
| 是否写审计 | **是**，审计事件类型 `APPROVAL` |
| 敏感分级 | `INTERNAL`（一般审批流转，非涉及身份/学籍类敏感字段变更时） |
| 特殊规则 | 驳回（REJECT）操作必须填写退回原因，且**最少 5 字**，服务端需校验（错误码 `REJECT_REASON_REQUIRED`，见共享底稿第 6 节） |

### 2.5 学籍异动

| 项目 | 内容 |
|---|---|
| 所需权限点 | `student.status.update`（单个学籍状态变更）；细粒度按钮 `changeStatus`（单个）、`batchChangeStatus`（批量）、`exportStatusRecords`（导出变更记录） |
| 允许角色 | `SCHOOL_ADMIN`（明确具备）；其余角色是否具备学籍异动权限，底稿未列出，**待后端确认**，学籍异动通常属于高敏感操作，建议严格收紧到学校管理员/学籍专职角色（如 `REGISTRAR` 画像） |
| 数据范围要求 | 仅可对当前角色数据范围内的学生执行学籍异动 |
| 是否脱敏 | 学籍异动记录本身（如"休学""退学""转专业"等状态标签）通常为 `INTERNAL` 级，但异动原因说明如涉及隐私信息（如病历、家庭变故）应按 `SENSITIVE` 处理 |
| 是否写审计 | **是**，且应作为重点审计对象（学籍异动直接影响学生身份状态，建议审计记录需包含变更前后状态、操作人、操作理由、时间戳） |
| 敏感分级 | `SENSITIVE`（学籍状态本身）/ 视异动原因内容可能上升至更高敏感级别 |

### 2.6 权限变更

| 项目 | 内容 |
|---|---|
| 所需权限点 | `workflow.role.view`/`workflow.role.edit`（角色查看/编辑）、`workflow.permission.view`/`workflow.permission.toggle`（权限点查看/启停） |
| 允许角色 | `SCHOOL_ADMIN`（唯一明确具备）；系统管理员角色（当前暂映射 `SCHOOL_ADMIN` 子集，见 `01-角色体系说明.md`）理论上也应具备，但因无独立角色码，当前无法区分 |
| 数据范围要求 | 权限变更操作本身通常作用于"本校"范围内的角色/权限配置（`SCHOOL` 范围），不涉及跨校操作（跨校/平台级授权归 `PLATFORM_OPERATOR` 的模块授权范畴，非本节"角色权限变更"） |
| 是否脱敏 | 不涉及个人隐私数据脱敏问题，但权限变更本身是高影响操作 |
| 是否写审计 | **是**，审计事件类型 `PERMISSION_CHANGE`（角色切换、权限点启停、角色权限绑定调整均应计入此类型，见共享底稿第 4 节及 `05-角色切换规则.md`） |
| 敏感分级 | `SENSITIVE`（权限变更直接影响系统安全边界，建议列为重点监控审计对象） |

### 2.7 审计日志查看

| 项目 | 内容 |
|---|---|
| 所需权限点 | `workflow.audit.view`（审计日志查看）、`student.audit.view`（学生模块操作审计查看） |
| 允许角色 | `SCHOOL_ADMIN`（`workflow.audit.view`、`student.audit.view`）、`PLATFORM_OPERATOR`（`workflow.audit.view`，仅跨租户审计视角，不含学生业务审计明细） |
| 数据范围要求 | `SCHOOL_ADMIN` 查看本校审计记录（`SCHOOL` 范围）；`PLATFORM_OPERATOR` 查看跨租户审计记录（`ALL` 范围，但内容限定为租户/授权/系统级事件，不含学生业务明细） |
| 是否脱敏 | 审计日志中若引用了学生敏感字段（如某次 `SENSITIVE_VIEW` 事件的目标对象信息），展示时仍应遵循脱敏规则，不能因为是"审计日志"就豁免脱敏 |
| 是否写审计 | 查看审计日志本身是否需要"审计的审计"，**待后端确认**（多数等保三级实践中，审计日志的访问本身也应留痕，建议规划） |
| 敏感分级 | `SENSITIVE`（审计日志属于安全监控核心数据，访问权限应严格收紧） |

### 2.8 平台运营

| 项目 | 内容 |
|---|---|
| 所需权限点 | `workflow.audit.view`（跨租户审计）；模块授权/租户管理相关权限点（`licenseContext` 预留，尚未在 `permissions[]` 清单中给出具体权限点 key，**待后端确认**） |
| 允许角色 | `PLATFORM_OPERATOR`（唯一角色，且与学校业务角色强隔离，见 `05-角色切换规则.md`） |
| 数据范围要求 | `ALL`（全平台），但业务上明确"不看学生业务明细"，仅涉及租户、模块授权、跨校巡检类数据 |
| 是否脱敏 | 若巡检过程中偶发接触到学生相关统计数字（非明细），应确保为脱敏后的聚合口径，不暴露可识别到具体个人的信息 |
| 是否写审计 | **是**，平台运营的所有操作（尤其模块授权变更）均应留痕，且审计记录应对被服务的学校租户可见（增强透明度，具体是否开放给学校查看待后端确认） |
| 敏感分级 | `SECRET`（跨租户操作权限极高，属系统最高敏感操作范畴之一） |

## 三、敏感操作汇总速查表

| 敏感操作 | 核心权限点 | 数据范围叠加 | 脱敏 | 写审计 | 敏感分级 |
|---|---|---|---|---|---|
| 查看敏感数据（身份证/手机号/监护人） | `student.identity.view`/`student.contact.view`/`student.guardian.view` | 是 | 是 | 是（`SENSITIVE_VIEW`） | `SECRET`/`SENSITIVE` |
| 导出-LIST | `security.export.list` | 是 | 是 | 是（`EXPORT`） | `INTERNAL`/`SENSITIVE` |
| 导出-ENCRYPTED_ARCHIVE | `security.export.archive` | 是 | 是 | 是（`EXPORT`） | `SENSITIVE` |
| 导出-DESENSITIZED（默认关闭） | `security.export.desensitized` | 是 | 是（强制） | 是（`EXPORT`） | `SENSITIVE` |
| 批量操作 | 各业务专属 `batch*` 按钮 | 是 | 视内容而定 | 建议是 | `INTERNAL`/`SENSITIVE` |
| 审批（通过/驳回/撤回） | `workflow.task.approve`/`reject`/`withdraw` 等 | 是 | 视内容而定 | 是（`APPROVAL`） | `INTERNAL` |
| 学籍异动 | `student.status.update` | 是 | 视内容而定 | 是（建议重点审计） | `SENSITIVE` |
| 权限变更 | `workflow.role.edit`/`workflow.permission.toggle` | 是（本校范围） | 否（无个人数据） | 是（`PERMISSION_CHANGE`） | `SENSITIVE` |
| 审计日志查看 | `workflow.audit.view`/`student.audit.view` | 是 | 是（引用敏感字段时） | 待后端确认 | `SENSITIVE` |
| 平台运营（跨租户） | `workflow.audit.view` + 模块授权权限点（待后端确认） | 是（`ALL`，但不含学生明细） | 是（聚合口径） | 是 | `SECRET` |

## 四、与安全基线的衔接说明

- 本清单中的脱敏规则、导出策略、审计事件类型均直接对应 `frontend/src/security/constants/security.constants.js` 与 `docs/05-数据接口权限与安全/security/00-等保三级安全基线总册.md` 所定义的基线（本文档只引用，不重写基线细则）。
- 敏感错误场景对应的统一错误码：`NO_PERMISSION`（无权限，403）、`NO_DATA_SCOPE`（数据范围越权，403）均适用于本清单所有敏感操作的失败场景，前端应跳转 `/security/403` 或做拦截提示，不应泄露"数据是否存在"等可被枚举利用的信息。
- 上传相关的敏感操作（如上传身份证扫描件、监护人证明材料）遵循共享底稿第 4 节上传策略（白名单 `[pdf,doc,docx,jpg,jpeg,png,zip,rar,xlsx,pptx]`，单文件 ≤50MB，黑名单 `[exe,js,bat,sh,php,jsp,html,svg]`），本清单不重复展开，仅提示上传后应同步写入 `UPLOAD` 审计事件。
