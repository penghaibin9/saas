# 04 · 导入导出与批量操作安全（SECURITY-P0）

> 既有基线见《04-导入导出安全规则.md》（三档导出 / 行数上限 / 审计）。本文是 P0 落地口径补充。

## 一、导出确认（必须四点提醒）

所有导出入口确认框必须包含：
1. 导出数据包含学生个人信息，仅限工作用途；
2. 文件将附带操作人与时间水印；
3. 本次导出会记录审计日志（操作人/时间/数据范围/用途，用途必填 ≥5 字）;
4. 不得通过微信/QQ 等随意转发。

落地方式（现有导出按钮多达百余处，不大改页面）：
- 新入口：直接用 `components/common/AppExportConfirm.vue`（已内置文案与用途必填）。
- 存量入口：保留现有 AppConfirmDialog，仅把 message 换成 `buildExportConfirmMessage()`（utils/security/confirm-text.js），逐步接入。
- 校验与审计沿用 `security/guards/export.guard.js`（权限 → 行数上限 → 审计事件）。

## 二、导入安全

沿用 upload.guard：扩展名白名单 + 黑名单双保险、50MB 上限；导入结果需可追溯（成功/失败行数写审计）。

## 三、危险操作二次确认（统一口径）

作废 / 停用 / 删除 / 批量分班 / 批量提醒 / 批量审批 / 批量导出：
- 必须二次确认；文案统一走 `buildDangerConfirmMessage()`（写明审计留痕、逻辑删除可追溯）。
- 作废/退回类必填原因 ≥5 字（AppConfirmDialog `require-reason` 已支持）。
- 批量操作确认框必须显示影响条数；超出数据范围的记录自动跳过并提示。

## 四、后端必须兜底

前端确认与 guard 均可被绕过：后端必须重复校验权限 / 行数 / 数据范围，服务端生成水印与审计日志，导出文件落盘加密或限时签名下载。
