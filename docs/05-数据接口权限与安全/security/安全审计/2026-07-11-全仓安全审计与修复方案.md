### P0 · 认证绕过

#### P0-1 · 下线 / 门禁 `/authz/login` 免密登录
- **级别 P0** · 位置 `backend/app/api/v1/authz.py:65`、`router.py:53` · CWE-287/306
- **根因**：`authz.router` 无门禁挂载，`authz.login` 不检查 `mock_login_enabled`，任意非空密码即为 `admin01` 等 mock 账号签发合法管理员 JWT；与受门禁的 `/auth/mock-login` 双标。
- **修复方案**
  - 首选：整套下线 authz 的 login/logout/token-refresh（与真实 `/auth/*` 重复），前端统一改调 `/api/v1/auth/login`。
  - 过渡：给 `authz.login` 与 `/token/refresh` 加 `mock_login_enabled` 门禁 + 登录限流；`authz.logout` 复用 `auth.py` 的 `block_jti` + `revoke_refresh`。
- **关键代码**
  ```python
  # authz.py — login() 首行加门禁（与 auth.mock_login 一致）
  def login(body: LoginBody):
      from app.core.config import settings
      if not settings.mock_login_enabled:            # 生产默认关闭
          audit_log.record("MOCK_LOGIN_DENIED", f"user:{body.loginName}", result="DENIED")
          raise AppException("NO_PERMISSION", "演示登录已关闭，请使用账号密码登录")
      _login_rate_guard()
      ...  # 原逻辑
  # 更彻底：router.py 不再无条件挂载 authz 登录路由，或直接删除，统一走 /auth/*
  ```
- **验收**：生产配置下 `POST /api/v1/authz/login` 任意口令 403；新增回归：`mock_login_enabled=false` 时该端点 403。

### P1 · 高危（13 项）

#### P1-1 · 统一生产判定，禁止默认弱 JWT 密钥启动
- **级别 P1** · 位置 `core/security.py:26`、`main.py:40` · CWE-798/321 · 跨租户
- **根因**：`assert_secret_safe()` 与 `main.py` 的 `_is_prod` 只看 `APP_ENV`，而 `is_prod` 同时认 `ENV/ENVIRONMENT`。运维用 `ENV=production` 时弱密钥守卫与 `/docs` 关闭均不触发 → 用公开默认密钥启动，可伪造任意租户/平台超管令牌。
- **关键代码**
  ```python
  # security.py
  def assert_secret_safe() -> None:
      if settings.is_prod:                           # ← 原：settings.APP_ENV in (prod, production)
          weak = {"change-me-in-production",
                  "school-lifecycle-dev-secret-change-me-please-32", ""}
          if settings.jwt_secret in weak or len(settings.jwt_secret) < 32:
              raise RuntimeError("生产必须用环境变量设置 ≥32 位随机 JWT_SECRET_KEY")
  # main.py
  _is_prod = settings.is_prod                        # ← 原：settings.APP_ENV.strip().lower() in (...)
  ```
- **验收**：`ENV=production` 且 JWT_SECRET 为默认值时 `create_app()` 抛 RuntimeError；`/docs` 在该配置下 404。

#### P1-12 · 敏感 PII 字段级加密落地
- **级别 P1** · 位置 `db_service.py:165` 等写路径 + models 基类 · CWE-312
- **根因**：全仓无任何 encrypt/decrypt 实现，写路径把明文塞进 `*_encrypted` 列（身份证/手机/家庭经济/监护人电话），生产库一次导出即大规模 PII 泄露。
- **关键代码**
  ```python
  # 新增 backend/app/core/crypto.py
  from cryptography.fernet import Fernet
  import hmac, hashlib
  _f = Fernet(settings.FIELD_ENCRYPTION_KEY.encode())   # 32B urlsafe-base64，环境注入
  def enc(p):  return _f.encrypt((p or "").encode()).decode()
  def dec(c):
      try:    return _f.decrypt((c or "").encode()).decode()
      except Exception: return c or ""     # 兼容历史明文过渡期
  def fhash(p): return hmac.new(settings.FIELD_HMAC_KEY.encode(), (p or '').encode(), hashlib.sha256).hexdigest()
  # 写：StudentContact(..., contact_value_encrypted=enc(body.phone), contact_value_hash=fhash(body.phone))
  # 读脱敏：_mask_phone(dec(c.contact_value_encrypted))；迁移：存量明文 enc() 一次性回填
  ```
- **验收**：写入后直查库为密文；解密脱敏正确；导出无明文。

#### P1-13 · Nginx 去除 `/uploads//exports/` 直读
- **级别 P1** · 位置 `deploy/nginx/nginx.mysql.conf:90` · CWE-284/200 · 跨租户
- **根因**：nginx `location /uploads/`、`/exports/` 用 alias 直读磁盘、无鉴权，含 PII 的导出 xlsx 可匿名 URL 直下，绕过后端 `require_staff`+租户校验+审计。
- **关键代码**
  ```nginx
  # 删除以下两段：
  #   location /uploads/ { alias /srv/uploads/; ... }
  #   location /exports/ { alias /srv/exports/; ... }
  # 如需 nginx 直发大文件——内部重定向，后端鉴权后回 X-Accel-Redirect：
  location /internal-files/ { internal; alias /srv/uploads/; }
  # 后端校验通过后：Response.headers['X-Accel-Redirect'] = '/internal-files/<相对路径>'
  ```
- **验收**：匿名 `curl http://host/uploads/exports/...` 返回 403/404；仅经后端鉴权端点可下载并写审计。
