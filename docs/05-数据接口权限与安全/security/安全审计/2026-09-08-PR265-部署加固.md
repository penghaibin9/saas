## 运行镜像攻击面收缩

生产安全镜像当前只复制七类允许文件中的生产必需脚本/探针（安全探针、Redis/ClamAV 预检、Scheduler、共享导入清理、加密兼容及对应运行入口按提交实际内容为准），不复制整个 `backend/scripts`。既有 `USER 10001:10001`、read-only、`cap_drop: ALL`、`no-new-privileges`、SUID/SGID 清理继续保留。

已移除的在线运行 CLI 包括：

- apt/dpkg 包管理入口；
- curl/wget/git/ssh/scp/sftp/nc/telnet/ftp 等常用联网或横向工具；
- su/passwd/useradd/usermod/groupadd 等账户管理工具；
- mount/umount/nsenter；
- 全部 `perl*` 运行入口；
- gzip/gunzip/zcat、infocmp、sqlite3、systemd-homed、getfacl/setfacl、pcre2grep/grep/egrep/fgrep。

`security_profile_probe.runtime_surface()` 在镜像/文件系统启动检查时拒绝这些命令重新出现，并拒绝 SUID/SGID 回归。该控制只是在无发行版修复时降低真实触发面和被入侵后的可利用工具，**不是漏洞豁免**；Trivy 仍然扫描这些已安装系统包并保持发布阻断。

GitHub 代码检索未发现在线应用使用 `shell=True` 或 `os.system`。仓库内仍存在独立验收/迁移顺序工具调用 `git`，但这些脚本不属于安全生产镜像允许运行脚本集合。历史 Dockerfile/旧部署脚本可能使用 curl/grep/shell，它们不是本安全候选配置，不能因此被视为可直接公网发布。

新增 `test_security_runtime_cve_surface.py` 将 Dockerfile 删除集合、启动探针与 Trivy 不放宽策略绑定，并已经接入 `Security image vulnerability audit` 的 build 前合同测试。当前 HEAD 的真实镜像 build、部署专项和 Main/CI 必须以该 HEAD 自己的 Actions 为准，父提交绿色不复用。
