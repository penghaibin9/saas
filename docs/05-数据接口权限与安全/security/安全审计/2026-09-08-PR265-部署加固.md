## 当前运行镜像收口（2026-09-08 晚）

最新安全镜像继续使用 `python:3.12-slim-trixie`。Bookworm 对照扫描已实际执行，阻断项和 Critical 均未优于 trixie，因此没有为了“换旧基线”硬切。漏洞扫描策略仍保持 UNKNOWN/HIGH/CRITICAL 阻断、`ignore-unfixed=false`、无 ignorefile/VEX/suppression；保留 `/var/lib/dpkg` 软件包库存，禁止通过删除扫描证据伪造绿灯。

上一份完整有效 Trivy 回执在 cryptography 升级后仍有 59 条 Debian OS 包级阻断、23 个不同漏洞标识；它们大量集中于少数源包的重复二进制映射，且该报告未列 FixedVersion。包级数量不是“59 个已证实公网 RCE”，但未修复也不能被当成安全或静默豁免。

为减少应用进程一旦失守后的可利用工具面，本分支在最终镜像完成系统升级、依赖安装和非 root 账号准备后执行以下收口：

- 只复制生产真实需要的安全探针、Redis/ClamAV 预检、Scheduler、共享导入清理和加密兼容脚本，不复制整个 `backend/scripts`。
- 移除所有 SUID/SGID 位，保留 `USER 10001:10001`、read-only、`cap_drop: ALL`、`no-new-privileges` 等既有边界。
- 移除 package/network/account/mount 管理 CLI：apt/dpkg 系列、curl/wget/git/ssh/scp/sftp/nc 等、su/passwd/useradd/groupadd、mount/umount。
- 进一步移除与当前无修复系统包风险触发面直接相关、且在线服务不需要的 CLI：所有 `perl*` 运行入口、`gzip/gunzip/zcat`、`infocmp`、`nsenter`、`sqlite3`、`systemd-homed`、`getfacl/setfacl`、`pcre2grep/grep/egrep/fgrep`。
- `security_profile_probe.runtime_surface()` 每次镜像/文件系统启动检查时都拒绝这些命令重新出现，也拒绝 SUID/SGID 回归。该探针是补偿控制，不是 CVE waiver；Trivy 仍会扫描对应已安装包并保持阻断。

GitHub 代码检索未发现在线应用使用 `shell=True` 或 `os.system`。仓库内存在独立验收/迁移顺序工具对 `git` 的调用，但这些运维脚本不在生产安全镜像允许的运行脚本集合中。历史 Dockerfile 和旧部署脚本可能仍使用 shell/grep/curl，它们不是本安全候选配置，不能因本轮收口而被视为可直接公网发布。
