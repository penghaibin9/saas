## SEC-03：只缓存拒绝，不缓存未撤销

`token_store.jti_blocked()` 不再使用进程内 `_allowed_jti` 或旧 Redis `0` 作为授权结论；Redis 未给出撤销时查询 MySQL，严格环境存储不可用返回 503。过期的本地拒绝也必须重新查询。禁止把一次查询的“没有撤销记录”写成缓存 0 覆盖并发撤销。

浏览器会话墓碑复用该路径。已经在撤销提交前通过授权的在途请求不可追回；本补丁不做不真实的全请求原子中断承诺。移除负缓存增加 MySQL 读压力，必须通过原有负载/连接池回归后才能生产发布，不能为了性能恢复允许缓存。

### 实现与原包差异

采用原可核验代码包的独立批准策略、实际认证入口和小程序补丁；把原包 Redis 单次消费实现改为现有 `t_auth_challenge_state` 的命名空间记录，不新增表、不修改 Alembic。原因是批准消费、微信绑定和高危审计必须能够在同一 MySQL 事务回滚，不能先耗掉 Redis 凭据再留下失败的绑定。该记录与图形验证码的 ID 哈希命名空间、purpose 和 payload 都分离。

- `wx_binding_approval_service`：批准码有效期 300 秒，随机生成，只存码的哈希、微信摘要和学校/用户/版本绑定。签发与消费函数都不自行 commit。消费用行锁及当前读取，错对象、旧版本、过期、重复消费和存储故障均拒绝。
- `control_plane_auth_service.wx_bind`：真实密码风控仍使用原实现；先锁定并复核账号状态、学校、岗位与平台身份边界，再在同一事务完成批准消费、正式绑定和 `WX_BINDING_ACTIVATED` 审计。已归档关联不会复活；禁用关联即使旧 openid 相同也需要独立批准。
- 现有有效同账号绑定与精确的历史 openid 关联可继续登录，不批量删除既有学校身份。此兼容不代表既有绑定经过了新策略核验；疑似被盗仍须执行之前的受控隔离流程。
- 实际 `control_plane_auth` 路由、共享 `WxBindRequest` 与旧兼容 handler 一起接收/传递 `bindingApprovalToken`；保留原安装器及唯一 URL。学校微信登录签发点拒绝平台与未知账号类型。
- 小程序按服务端返回显示批准码输入、复制临时绑定申请凭证和办理说明；不复制校园密码，不把批准码写进持久存储。成功、取消清理本地敏感状态；取消后的迟到响应不得自动登录。长表单可滚动。

正式与预发布环境缺批准码必须拒绝；只有原有显式 mock-login 开启的非正式测试夹具可以不提供批准码，且只要提交了批准码就必须验证。没有新增生产放宽开关。正常密码登录、现有微信免密登录、迎新录取身份核验的独立激活流程不被替换。本批只收口密码通道新绑定，不声称所有 SSO/恢复通道都已验完。

### 受控签发操作（本次未对真实账号执行）

`security_wx_approval.py` 仅在 Linux 受控运维环境使用，无 HTTP 签发接口。学校必须通过原有可信联系方式或现场流程独立核验本人；知道密码、提供 wxToken 或声称自己是本人都不能代替核验。核验凭证只记工单引用，不在审计备注中填写密码、原始令牌或证件照片。

先通过已提交的只读 `security_account_control.py` 确认目标学校/账号/版本，再由获授权运维人员执行：

```bash
cd backend
python scripts/security_wx_approval.py \
  --tenant-code "$TENANT_CODE" --user-id "$USER_ID" \
  --expected-version "$EXPECTED_VERSION" --incident-ref "$VERIFICATION_TICKET" \
  --ticket-file "$NEW_PRIVATE_TICKET_PATH" --identity-verified --apply
```

程序在终端隐藏读取申请人的短时 wxToken，不从命令行参数或日志接收校园密码。签发与 `WX_BIND_APPROVAL_AUTHORIZED` 审计提交成功后，才把批准码写入新建的 0600 文件；拒绝覆盖已有文件、符号链接和无终端回显降级。终端只显示引用、有效期和文件位置，不显示批准码。通过已独立验证的私密通道把码交给本人，在五分钟内完成绑定；申请 wxToken 过期则重新申请并核验，不放宽 TTL。

提交确认丢失返回 UNCONFIRMED，交付失败区分 COMMITTED；禁止盲目重放签发，应检查审计引用或等待码过期。预检失败可能留下一个空的预留私密文件，人工核对后清理或换一个新文件名，不自动覆盖。已用或过期私密文件按本校安全制度清除。本批没有接通自动短信通知/MFA、自助批准页面或账号自动恢复；人工独立核验与安全交付是运行前提，不能把勾选 `--identity-verified` 当成系统自动核验本人。
