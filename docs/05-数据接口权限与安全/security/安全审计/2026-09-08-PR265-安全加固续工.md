## SEC-03：只缓存拒绝，不缓存未撤销

`token_store.jti_blocked()` 不再使用进程内 `_allowed_jti` 或旧 Redis `0` 作为授权结论；Redis 未给出撤销时查询 MySQL，严格环境存储不可用返回 503。过期的本地拒绝也必须重新查询。禁止把一次查询的“没有撤销记录”写成缓存 0 覆盖并发撤销。

浏览器会话墓碑复用该路径。已经在撤销提交前通过授权的在途请求不可追回；本补丁不做不真实的全请求原子中断承诺。移除负缓存增加 MySQL 读压力，必须通过原有负载/连接池回归后才能生产发布，不能为了性能恢复允许缓存。

## SEC-02 的应急隔离部分（不是微信新绑定审批全链完成）

新增 `account_compromise_service.contain_in_session()`：按 tenant_id + user_id 锁定唯一账号，核对 expected_version。先设置强制主体回库标记，再在同一 MySQL 事务中禁用账号、递增版本、要求重设密码、清空 User.wx_openid、禁用该账号 WxAccountBinding、删除刷新凭据并写 `ACCOUNT_COMPROMISE_CONTAINED` 高危审计。服务不自行 commit；审计失败必须由调用者回滚。

`security_account_control.py` 仅供持有服务器运维权限的操作者使用，没有 HTTP 入口。默认 inspect 仅读取；contain 必须同时给出 `--apply`、学校编码、用户数字 ID、预期版本和事件编号。拒绝平台身份，不提供自动恢复账号或设置新密码的动作。成功隔离不等于完成身份核验和账号恢复。

只读检查入口（变量须由获授权运维人员提供；本轮未执行）：


实际隔离须另获明确操作授权并复核 inspect 的版本。提交成功但缓存清理失败，回执仍显示 committed=true、cacheRecoveryRequired=true；只恢复缓存，不重放禁用。提交确认丢失时标记 UNCONFIRMED，应先重新 inspect，不能假定事务未提交。

尚未接入包内新增微信绑定的独立批准码、消费端和小程序 UI，因此命令不暴露 approve-wx 选项；不能把本次隔离能力说成已阻止所有密码泄露后的新增绑定。可信身份恢复与所有 SSO 通道仍需专项验收。
