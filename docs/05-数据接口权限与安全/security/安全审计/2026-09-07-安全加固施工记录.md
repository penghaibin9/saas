## 实际修改

### SEC-01：正式角色来源与旧缓存

`auth_service_db._role_contexts` 在生产/预发布环境无有效 UserRole 时拒绝按登录名补角色。开发/测试兼容仍受原 mock-login 策略约束；现有有效角色优先，平台控制面身份不被转换成学校角色。

`_subject_cache_matches` 对生产/预发布旧 `legacy:` 学校身份不再接受已缓存的允许结果，必须重新核对有效岗位。保留其他账号状态、租户、权限版本及发布版权限模板。

新增 `backend/scripts/check_legacy_role_dependencies.py`：只读识别依赖旧回退的账号，包括可能受影响的学校首管；发现记录则以非零状态阻断发布。脚本不自动授予角色、不输出密码。

### SEC-04：来源 IP 可信边界

在非冻结的 `middleware/context.py` 入口先调用 `forwarded_ip_security`，再进入原上下文中间件。只接受配置中的直接代理；代理链从右向左选择最近的不可信节点，拒绝重复、非法、过长链。同步维护 Starlette 已缓存请求头与下游 ASGI scope。

MySQL Nginx 边缘将 X-Forwarded-For 替换为 socket 来源，不再追加客户端自行填写的链。生产仍须按实际拓扑收窄 TRUSTED_PROXY_IPS，并统一 Uvicorn 的代理处理；本批未部署服务器，也没有把旧 HTTP 模板变成 HTTPS。
