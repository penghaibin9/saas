# 06-文件上传安全规则

- **文档性质**：文件上传 / 下载 / 预览安全规则（白名单、大小、病毒扫描、签名 URL、访问审计）
- **适用端**：PC 管理端 + miniapp（材料上传 / 打卡照片）+ 后端对象存储
- **依据（只引用、不重写）**：`docs/05-数据接口权限与安全/security/00-等保三级安全基线总册.md` §9.1/§9.2；`docs/05-数据接口权限与安全/database/00-数据库设计冻结总册.md` §14 文件与材料设计（`t_file_object`、`t_file_access_log`）；`docs/05-数据接口权限与安全/rbac/07-敏感操作权限清单.md`（`UPLOAD` 审计）
- **当前阶段声明**：上传校验、病毒扫描、签名 URL、访问审计**必须后端实现**；前端扩展名 / 大小校验只是第一道拦截，可被绕过，**不能作为安全边界**。
- **生成日期**：2026-07-04

---

## 一、上传白名单与限制

| 项 | 规则 |
|---|---|
| 扩展名白名单 | `pdf, doc, docx, xlsx, pptx, jpg, jpeg, png, zip, rar`（以 `security.constants.js` 常量为准；**服务端按真实 MIME + 魔数校验，不只信扩展名**） |
| 扩展名黑名单 | `exe, js, bat, sh, php, jsp, html, svg`（可执行 / 可脚本一律拒绝） |
| 单文件大小 | **≤ 50MB** |
| 图片 | 打卡照片等按需二次压缩，剥离多余 EXIF（尤其定位），定位仅打卡场景采集、最小化 |
| 校验位置 | 前端预校验 + **后端强制校验**（扩展名 + MIME + 大小 + 魔数） |

## 二、存储红线

- 业务表**只存 `xxx_file_id BIGINT`**，**禁止存路径 / 大二进制**；唯一登记走 `t_file_object`（`file_key` + `hash_sha256` + `size_bytes` + `mime_type` + `sensitive_level` + `(biz_module, biz_id, student_id)` 归属）。
- 对象存储用**私有桶**，不暴露真实路径 / 公开直链。
- `hash_sha256` 用于去重与完整性校验。

## 三、病毒 / 恶意文件扫描

- 上传后**异步病毒扫描**；扫描未过 / 疑似的文件**禁止被访问**，并告警 + 审计。
- SVG 等可内嵌脚本的类型直接列黑名单，杜绝存储型 XSS。

## 四、下载 / 预览安全

| 项 | 规则 |
|---|---|
| 访问方式 | **短期签名 URL**（一次性或短 TTL，**≤ 15 分钟**），禁止公开直链 |
| 鉴权 | 每次生成 URL 前校验 **user + tenant + 数据范围 + 文件归属**（四要素） |
| 敏感材料 | 证件、家庭、心理、处分、就业证明、劳动合同等下载 / 预览写 `t_file_access_log`（**append-only**） |
| 企业导师 | **默认禁批量下载**；且对毕设 / 家庭 / 心理 / 处分材料硬隔离（见 `07`） |
| 水印 | 敏感档案类下载 / 导出叠加水印（见 `04`） |

## 五、上传 / 下载审计

- 上传写 `UPLOAD`、下载写 `DOWNLOAD` 审计（字段见 `05`）。
- 敏感材料访问单独落 `t_file_access_log`，可追溯"谁在何时下载了哪份材料"。

## 六、miniapp 特别注意

- 打卡照片 / 定位：**仅打卡场景**申请定位权限，定位明细最小化采集，**不在本地缓存敏感信息**，全程 HTTPS。
- 上传走同一套白名单 + 大小 + 后端校验，不因移动端而放宽。

## 七、开发验收清单

- [ ] `uploadSecurity.helper`：扩展名 + 大小前端预校验
- [ ] 后端强制校验（扩展名 + MIME + 魔数 + 大小 + 黑名单）
- [ ] 业务表只存 `file_id`；`t_file_object` 唯一登记
- [ ] 私有桶 + STS 短期签名 URL（≤15 分钟）
- [ ] 上传后异步病毒扫描，疑似禁止访问
- [ ] 敏感材料下载写 `t_file_access_log`（append-only）
