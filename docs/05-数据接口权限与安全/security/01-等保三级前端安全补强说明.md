# 01 · 等保三级前端安全补强说明（SECURITY-P0）

> 项目：高校学生全生命周期管理平台 · 前端（frontend/src）
> 结论先行：**本次补强只覆盖"前端展示层"安全，不代表、也不可能代表系统已满足等保三级。**
> 等保三级是"网络 + 主机 + 应用 + 数据 + 管理制度"的整体测评，前端只是应用层的一小部分。

| # | 能力 | 位置 |

## 二、前端明确做不到、必须由其它层完成

| 层 | 必须完成的事 |
| --- | --- |
| HTTPS / Nginx / 网关 | TLS1.2+ 全站加密、HSTS、安全响应头（CSP/X-Frame-Options 等）、WAF、限流防爆破 |
| 后端应用 | 登录口令安全传输与验证、密码哈希（bcrypt/argon2/SM3+盐）、服务端权限与数据范围校验、字段级授权、服务端审计日志、导出服务端拦截与水印落盘、防越权（前端隐藏按钮≠权限） |
| 数据库 / KMS | 存储加密（TDE / 字段级加密 / SM4）、密钥管理与轮换、备份加密 |
| 运维制度 | 账号生命周期、最小权限、日志留存 ≥6 个月、应急响应、渗透测试与等保测评整改 |

## 三、红线声明

1. 前端不保存密钥、不硬编码密钥（含 SM2/SM4/RSA、盐值）。
2. 前端"加密后存储"= 明文存储，禁止以此宣称安全。
3. 前端脱敏/隐藏只是展示层防护：后端必须按角色返回脱敏数据，不能依赖前端遮挡。
4. 平台运营角色不得越权查看学校（租户）学生敏感明文；系统管理员不默认绕过业务脱敏。
5. 所有导出必须：权限校验 + 用途登记 + 水印 + 审计日志（前端确认只是第一道闸）。
