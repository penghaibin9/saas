- **文档性质**：必审计操作、冻结审计字段、审计表 append-only、留存与分级
- **适用端**：全端行为最终落后端审计；PC / miniapp 统一 `auditEvent` 结构上报
- **依据（只引用、不重写）**：`docs/05-数据接口权限与安全/security/00-等保三级安全基线总册.md` §8；`docs/05-数据接口权限与安全/database/00-数据库设计冻结总册.md` §16 审计日志设计（五张 append-only 审计表）
- **当前阶段声明**：审计当前为 mock `appendAudit` 模式；后端须替换为异步落库、只追加。审计是安全事后追溯的唯一依据，**不可缺、不可改、不可删**。
- **生成日期**：2026-07-04

## 一、必须审计的操作（引用基线 §8.1）

登录、登出、登录失败、身份切换、权限分配 / 变更、角色变更、数据范围变更、**敏感数据查看**、**导出**、下载、删除 / 归档、审批通过 / 退回 / 驳回 / 撤回 / 转交、流程模板变更、**模块授权变更**（platform）、系统配置变更、**越权访问尝试**、异常登录、异常操作、用户创建 / 删除 / 禁用、密码重置、**批量导出学生 / 就业 / 成绩数据**。

## 二、审计事件类型（`AUDIT_EVENT_TYPE`）

| 事件类型 | 触发 |
|---|---|
| `LOGIN` / `LOGOUT` / `LOGIN_FAIL` | 登录相关 |
| `SENSITIVE_VIEW` | 查看完整身份证 / 手机 / 家庭 / 心理 / 处分等敏感值 |
| `EXPORT` / `UPLOAD` / `DOWNLOAD` | 导出 / 上传 / 下载 |
| `APPROVAL` | 审批通过 / 退回 / 驳回 / 撤回 / 转交 |
| `PERMISSION_CHANGE` | 角色 / 权限点 / 数据范围变更、身份切换 |
| `PERMISSION_DENIED` | 越权访问尝试（含数据范围越权） |
| 学籍异动 / 删除归档 / 系统配置 / 模块授权变更 | 对应业务审计 |

## 三、审计字段（冻结，引用基线 §8.2）

```
auditId, timestamp(UTC), userId, username, tenantId, schoolId,
operatorRole, action, resourceType, resourceId, operation,
ip, userAgent, result, detail(JSON,脱敏), moduleCode,
errorCode, duration, requestId, riskLevel
```

- `detail` 中 **`L4`/`SECRET` 字段脱敏**；**禁止写入 `password` / `token`**。
- 敏感字段在审计里**只存摘要 + hash，不存明文**（DB §16）。
- `requestId` 贯穿请求链，便于把导出 / 越权 / 审批串起来追溯。

## 四、红线 7：审计 / 流水 append-only，禁止物理删除

| 表（DB 冻结册 §16，五张） | 用途 |
|---|---|
| `t_student_field_audit` | 学生主档字段级审计（字段 / 阶段 / 组织 / 联系方式 / 证照 / 授权变化） |
| `t_security_audit` / `t_security_audit_log` | 安全审计（登录 / 越权 / 敏感查看 / 下载 / 导入导出 / 删除 / 合并 / 放行） |
| `t_permission_audit` | 权限审计（`before_json` / `after_json`） |
| `t_operation_audit_log` | 业务操作审计（审批 / 批阅 / 退回 / 发布 / 归档） |

规则：

- 五张审计表**全部 append-only：无 `is_deleted`、无 `update`**，**只允许 INSERT**。
- **禁止用软删除替代冲正**；需要更正时**追加反向记录**，原记录保留。
- 实现优先应用层 AOP 强制写入，关键表加 **DB 触发器兜底**，防止漏写。
- 与业务表的逻辑删除区分：业务数据可软删进回收站（可恢复），**审计 / 流水不可删不可改**（见 `02` 第五节）。

## 五、存储与留存

| 项 | 要求 |
|---|---|
| 存储 | 集中存储，**DB + 日志文件双写** |
| 留存 | 审计数据**留存 ≥ 3 年**（依 DB 冻结册 §16；不低于等保基线 §8.3 的 ≥6 个月） |
| 访问 | 审计查询页只读；查看审计本身建议也留痕（"审计的审计"，待后端确认） |
| 脱敏 | 审计展示引用敏感字段时仍按 `03` 脱敏，不因"是审计日志"而豁免 |

## 六、安全事件分级与响应（引用基线 §8.5）

| 级别 | 示例 | 响应 |
|---|---|---|
| P1 | 疑似大规模数据泄露 | 1 小时内隔离 + 通报 |
| P2 | 越权批量导出 | 4 小时锁定账号 + 追溯 |
| P3 | 暴力破解 | 自动锁定 + 告警 |
| P4 | 单次失败登录 | 计数 |

## 七、谁能看审计

- `SCHOOL_ADMIN`：本校审计（`workflow.audit.view` / `student.audit.view`，`SCHOOL` 范围）。
- `PLATFORM_OPERATOR`：**仅跨租户 / 授权 / 系统级审计**，**不含学生业务审计明细**（见 `07`）。
