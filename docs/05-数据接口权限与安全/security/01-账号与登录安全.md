# 01-账号与登录安全

- **文档性质**：账号、登录、会话、认证安全规则
- **适用端**：PC 管理端 + miniapp（学生端 / 教师端）+ 后端 Auth 服务（规划中）
- **依据（只引用、不重写）**：`docs/05-数据接口权限与安全/security/00-等保三级安全基线总册.md` §4；`docs/05-数据接口权限与安全/database/00-数据库设计冻结总册.md`（`t_user`、`t_user_login_log`、`phone_encrypted/phone_hash`）；`docs/05-数据接口权限与安全/rbac/05-角色切换规则.md`
- **当前阶段声明**：后端 Auth 服务尚未落地，以下为设计要求；密码校验、失败锁定、MFA、会话撤销**必须在后端实现**，前端只做体验层配合，不得作为安全边界。

## 一、账号模型与存储红线

| 项 | 规则 |
|---|---|
| 登录名 | `t_user.login_name`（工号 / 学号 / 手机号），租户内唯一（`uk_tenant_login`） |
| 密码存储 | **bcrypt cost≥12** 或 scrypt；**禁止明文 / MD5 / SHA1**；代码审查强制 |
| 手机号 | 库内 `phone_encrypted`（密文）+ `phone_hash`（不可逆，供登录匹配 / 查重），**不存明文** |
| 账号-学生绑定 | 通过 `t_student_user_link` 关联，禁止用手机号 / 学号当业务主键 |
| 账号禁用 | 逻辑禁用（状态位），禁用即撤销全部会话；不物理删除账号（见 `02` 逻辑删除红线） |

## 二、密码策略（后端强制）

| 规则 | 要求 | 实现位置 |
|---|---|---|
| 最小长度 | ≥ 12 位 | 后端校验 + 前端表单提示 |
| 复杂度 | 大写 / 小写 / 数字 / 特殊字符至少三类 | 后端 |
| 有效期 | 90 天强制修改 | 后端 + 登录后拦截 |
| 历史密码 | 最近 5 次不可重复 | 后端 hash 历史表 |
| 失败锁定 | 连续 5 次失败锁定 15 分钟 | 后端 + Redis 计数 |
| 传输 | 全程 HTTPS/TLS；登录接口不回显密码策略明细以免被枚举 | 后端 |

> 前端可做密码强度实时提示，但**判定与拒绝一律以后端为准**，前端提示不得替代后端校验。

## 三、初始密码与重置

- 初始 / 临时密码 **24 小时有效**，首次登录**强制改密**。
- 管理员重置密码需**短信 / 邮件二次确认**；重置操作写审计（`password_reset`）。
- 批量开户（如迎新导入建账号）生成的初始密码不得回显明文清单，须走安全下发（一次性链接 / 单独短信），并写审计。
- 学生自助找回：短信 / 邮箱验证码 + 频率限制，防撞库。

## 四、多因子认证（MFA）

| 角色 | MFA 要求 |
|---|---|
| 系统管理员、学校管理员、二级学院管理员、平台运营 | **强制 MFA** |
| 普通教师（辅导员 / 指导教师 / 就业 / 教务） | 建议 MFA；标准版起可配置强制 |
| 学生 | 可选；高敏感操作（如修改绑定手机、查看完整证件）可 step-up 二次验证 |

- 优先 TOTP，其次短信验证码；MFA 密钥**加密存储**（KMS / 应用密钥）。
- MFA 丢失：人工核验身份 + 审计留痕，禁止自助无验证解绑。

## 五、会话安全

| 端 | 空闲超时 | 同账号最大并发 |
|---|---|---|
| PC Web | 30 分钟无操作退出 | ≤ 3 会话 |
| 移动 / H5 / 小程序 | 7 天无操作退出 | ≤ 3 会话 |

- Token：JWT access 短有效期 + RefreshToken 存 Redis（**可撤销**）。
- **登出 / 改密 / 锁定 / 禁用 / 角色权限变更**：撤销该账号全部 RefreshToken，强制重新登录。
- Cookie：`HttpOnly` + `Secure` + `SameSite=Lax|Strict`；前端**禁止**在 localStorage 存 token / 身份证 / 手机号等敏感值。
- 身份切换（一人多教师身份）：每次切换重新解析权限与数据范围，写 `PERMISSION_CHANGE` 审计（见 `docs/05-数据接口权限与安全/rbac/05-角色切换规则.md`）。

## 六、登录留痕与异常检测

- 每次登录（成功 / 失败 / 锁定）写 `t_user_login_log`（`result: SUCCESS/FAIL/LOCKED`、`ip`、`client_type`、`occurred_at`），该表 **append-only**。
- 必审计事件：`login` / `logout` / `login_fail` / `password_reset` / `mfa_bind` / 身份切换 / 异常登录（见 `05-审计日志规则.md`）。
- 安全事件分级（引用基线 §8.5）：暴力破解 → P3 自动锁定 + 告警；异地 / 异常设备登录 → 告警并可要求 step-up。

## 七、后端强制校验红线（对应总红线 8）

1. 认证结果、账号状态、会话有效性一律**后端判定**，前端登录态仅供渲染，不可作为访问控制依据。
2. 每个受保护接口都必须校验：会话有效 → `tenant_id` 归属 → 功能权限点 → 数据范围（见 `02`）。
3. 前端"未登录跳转 / 隐藏入口"只是体验，**接口自身必须独立鉴权**，直接调用 API 同样被拒。

## 八、验收清单

- [ ] 后端 Auth：login / logout / refresh / mfa / enroll / reset 全链路
- [ ] 登录失败计数与锁定（Redis）
- [ ] 密码历史表 + 90 天过期拦截
- [ ] 改密 / 登出 / 禁用撤销全部 RefreshToken
- [ ] 管理员 MFA 强制开启
- [ ] 前端：30 分钟倒计时续期、401→登录、419→会话过期页、不落敏感值到本地存储
