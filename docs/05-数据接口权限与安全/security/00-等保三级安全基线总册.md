## 1. 安全建设总览

### 1.1 安全建设结论

职校学生全生命周期 SaaS 平台处理**学生个人信息、学籍、实习、毕设、就业**等教育数据，按行业惯例与学校采购要求，**建议按网络安全等级保护 2.0 第三级思路**进行安全设计、开发加固、部署运维与测评材料准备。

当前工程状态（commit `4013204` 及以后）：

| 能力 | 状态 |
| --- | --- |
| 11 权限与流程中心（RBAC、数据范围、审批、permissionContext mock） | **前端已实现** |
| licenseContext / 动态菜单 / 路由守卫 / 审计落库 | **已设计，P6-2～P8 实装** |
| 身份认证、MFA、会话、加密存储、WAF、备份 | **待后端与部署** |
| 等保测评、定级备案 | **待学校与第三方机构** |

### 1.2 当前不能承诺「已通过等保三级」的原因

1. **定级与备案**需学校作为责任单位完成（GB/T 22240-2020 定级流程）。
2. **第三方测评**需具备资质的测评机构现场/远程测评、出具报告。
3. **整改与复测**：初测不符合项需整改后复测，最终结论以测评报告为准。
4. **管理类控制**（制度、机构、人员、建设、运维）需学校组织落实，非纯软件交付可替代。
5. **物理与环境**（机房、边界设备）取决于部署方式（SaaS 托管 vs 私有化），厂商与学校责任需合同界定。

本文档体系仅定义**建设目标、控制措施、开发任务与材料清单**，**不保证、不承诺**测评结论。

### 1.3 为什么建议按三级思路设计

- 系统含**大量未成年人/学生个人信息**（身份证、手机号、家庭信息、成绩、实习、就业去向）。
- **SaaS 多租户**：一所平台服务多校，租户隔离失败影响面大。
- **多角色多端**：学生、教师、管理员、企业导师、厂商运营，权限边界复杂。
- 高职/中职采购与验收 increasingly 要求等保或同等安全能力。
- 按三级思路前置设计，可避免业务模块堆叠后再补安全的返工成本。

```text
┌───────────────────────────▼─────────────────────────────────┐

├─────────────────────────────────────────────────────────────┤
│ 数据层 — PostgreSQL/MySQL（tenant_id）、Redis、对象存储         │
└─────────────────────────────────────────────────────────────┘
         │                              │
         ▼                              ▼
   审计日志库（append-only）        备份（加密）
```

### 1.5 SaaS 多租户安全边界

| 层级 | 控制 |
| --- | --- |
| 数据 | 所有业务表含 `tenant_id`；ORM/Repository 强制过滤 |
| 缓存 | Redis key 前缀 `{tenantId}:` |
| 文件 | 对象存储路径含 tenant；签名 URL 校验 tenant + 权限 |
| 配置 | licenseContext 按 tenant 隔离；平台后台 #4 授权中心写开关 |
| 跨租户 | 禁止默认查询；跨租户需审批 + 审计（厂商运维场景） |

### 1.6 路由域安全边界

| 路由域 | 用户 | 数据可见性 | 安全红线 |
| --- | --- | --- | --- |
| `/platform/*` | 厂商运营 | 租户/套餐/授权/配额/审计元数据 | **禁止学生业务明细** |
| `/admin/*` | 学校教师/管理员 | 本校 + 数据范围 | 不得见其他 tenant |
| `/student/*` | 学生 | 仅本人（SELF） | 不得见他人敏感字段 |
| `/enterprise/*` | 企业导师 | ENTERPRISE_AUTH_STUDENTS | 禁批量导出、禁家庭/心理/处分 |
| `/` | 学校管理端 Dashboard | 聚合指标（按 license 过滤） | 指标不含 L4 明文 |

与 `docs/02-总体架构与公共底座/frontend/route-freeze.md`、`07-P5.5` 拍板一致。

### 1.7 licenseContext 与 permissionContext 优先级

生效顺序（高→低，与 `03-模块开关` 一致）：

```text
租户停用 > 到期只读 > 模块未授权(菜单隐藏) > 试用限制 > 功能开关
  > 角色权限(permissionContext) > 按钮权限 > 数据范围
```

- **licenseContext**（P6-2）：模块买没买、到没到期、配额、端开关。
- **permissionContext**（已实现 mock，`workflow/context/permission.context.js`）：角色、权限点、数据范围。
- 页面**禁止**自行 `if (module === 'xxx')`；统一 `useModule` + `canAccessPage` / `canClickButton` / `checkDataScope`。

### 1.8 数据分级概要

| 级别 | 典型数据 | 要求 |
| --- | --- | --- |
| L4 极高 | 身份证、手机号、住址、监护人 | 加密存储 + 脱敏展示 + 严格审计 |
| L3 高 | 成绩、就业、薪资、实习单位/地址、毕设材料、周报 | 权限 + 审计 + 导出水印 |
| L2 中 | 班级、专业、课题、流程状态 | 访问控制 |
| L1 低 | 学校名、公开配置 | 普通控制 |

## 4. 身份认证与会话安全

开发可执行规范。后端 Auth 服务为主实现；前端配合会话超时与 MFA 引导。

### 4.1 密码策略

| 规则 | 要求 | 实现位置 |
| --- | --- | --- |
| 最小长度 | ≥ 12 位 | 后端校验 + 前端表单 |
| 复杂度 | 大写/小写/数字/特殊字符至少三类 | 后端 |
| 有效期 | 90 天强制修改 | 后端 + 登录后拦截 |
| 历史密码 | 最近 5 次不可重复 | 后端 hash 历史表 |
| 失败锁定 | 连续 5 次失败锁 15 分钟 | 后端 + Redis |
| 存储 | bcrypt cost≥12 或 scrypt | 后端 |
| 禁止 | 明文、MD5、SHA1 | 代码审查 |

### 4.2 初始与重置密码

- 临时密码 **24 小时**有效。
- 首次登录**强制改密**。
- 重置密码：管理员重置 + 短信/邮件二次确认；操作入审计。

### 4.3 MFA

| 角色 | 要求 |
| --- | --- |
| 系统管理员、学校管理员、二级学院管理员 | **强制 MFA** |
| 普通教师 | 建议 MFA；标准版起可配置强制 |
| 学生 | 可选（高敏感操作可 step-up） |

- 支持 TOTP（优先）或短信验证码。
- MFA 密钥**加密存储**（KMS/应用密钥加密）。
- 丢失 MFA：人工核验 + 审计。

### 4.4 会话

| 端 | 空闲超时 | 最大并发 |
| --- | --- | --- |
| PC Web | 30 分钟无操作退出 | 同账号 ≤3 会话 |
| 移动/H5/小程序 | 7 天无操作 | 同账号 ≤3 |

- Token：JWT access 短有效期 + RefreshToken 存 Redis（可撤销）。
- 登出/改密/锁定：**撤销全部 RefreshToken**。
- Cookie：`HttpOnly`、`Secure`、`SameSite=Lax|Strict`。

### 4.5 前端任务（待开发）

- [ ] 401 统一跳转登录；419 会话过期页
- [ ] 不在 localStorage 存 token/身份证/手机号
- [ ] 登录页：密码强度实时提示（不调后端泄露策略）

### 4.6 后端任务（待后端）

- [ ] Auth API：login/logout/refresh/mfa/enroll
- [ ] 登录失败计数 Redis
- [ ] 密码历史表
- [ ] 审计：login/logout/login_fail/password_reset/mfa_bind

### 4.7 验收

- [ ] 弱密码注册被拒绝
- [ ] 第 6 次失败锁定 15 分钟
- [ ] 管理员无 MFA 无法登录生产

## 5. RBAC 权限与数据范围安全

与 `modules/workflow`、`docs/01-产品需求与范围/commercialization/03-模块开关` 对齐。

### 5.1 权限模型

```text
Tenant → Role → Permission(module.resource.action)
              → Menu(page permissionKey)
              → Button(action permissionKey)
              → DataScope(ALL|SCHOOL|COLLEGE|CLASS|SELF|ASSIGNED + 业务域)
```

### 5.2 命名规范

- 权限点：`module.resource.action`，例 `internship.report.review`、`workflow.role.edit`
- 路由 meta：`permissionKey` 与上表一致（已实现 `/admin/workflow/*`）
- 禁止页面内硬编码角色名判断

### 5.3 统一判断入口（已实现 / 待扩展）

| 函数 | 文件 | 用途 |
| --- | --- | --- |
| `canAccessPage(key)` | `workflow/context/permission.context.js` | 路由/页面 |
| `canClickButton(key)` | 同上 | 按钮 |
| `canViewMenu(key)` | 同上 | 菜单 |
| `getDataScope()` | 同上 | provider 查询参数 |
| `checkRoutePermission` | `workflow/guards/workflow.guards.js` | P8 路由守卫 |
| `checkDataScope` | 同上 | 行级 |
| `useModule(code)` | P6-2 licenseContext | 模块开关 |

**优先级**：license（停用/只读/未购）> permission（角色/按钮/范围）

### 5.4 数据范围

| 范围 | 含义 | 查询注入 |
| --- | --- | --- |
| ALL | 平台/校级超管（慎用） | tenant_id 仍必填 |
| SCHOOL | 本校 | tenant_id + school_id |
| COLLEGE | 本院系 | + college_id |
| CLASS | 本班级 | + class_id |
| SELF | 本人（学生） | student_id = 当前用户 |
| ASSIGNED | 分配学生集 | assignedStudentIds |
| INTERN_STUDENTS | 实习指导范围 | 06 专用 |
| GD_STUDENTS | 毕设指导范围 | 05 专用 |
| ENTERPRISE_AUTH_STUDENTS | 企业授权学生 | 06 企业端 |

provider **必须**注入 scope；禁止前端传 `studentId` 越权查询。

### 5.5 SoD（职责分离）

| 规则 | 说明 |
| --- | --- |
| 评阅 ≠ 指导 | 同一学生毕设评阅人与指导教师不可同人（可配置例外+审计） |
| 评委 ≠ 导师 | 答辩评委不可为指导教师 |
| 发布 ≠ 录入 | 成绩发布与录入分权 |
| 核验 ≠ 提交 | 就业核验与填报分权 |
| 管理员不参与业务审批 | 系统管理员仅配置与审计 |

### 5.6 权限变更审计

角色/权限/数据范围变更 → `action=permission.change`，detail 含 before/after（脱敏）。

### 5.7 开发检查

- [ ] 新页面路由带 `meta.permissionKey`
- [ ] 新按钮用 `canClickButton` 或 `filterActionsByPermission`
- [ ] 新列表 API provider 带 scope 参数
- [ ] 未使用 `if (role === 'teacher')` 散写

## 7. 后端接口与数据库安全

后端尚未建设；本清单供 P7+ 使用。

### 7.1 接口通用

| 项 | 要求 |
| --- | --- |
| 认证 | 所有业务接口 JWT 或 Session；白名单仅 login/captcha/health |
| 授权 | 每接口校验 permissionKey；列表按 dataScope 过滤 |
| 租户 | 每请求校验 tenantId（Header/JWT claim）；与资源 tenant 一致 |
| 注入 | ORM/参数化；禁止拼接 SQL；禁止 eval/exec |
| 校验 | Joi/Zod/class-validator：类型、长度、格式、枚举 |
| 错误 | 统一错误码；不返回堆栈、SQL、路径 |
| CSRF | 写操作 CSRF Token |
| 限流 | 见下表 |
| 幂等 | 写操作 Idempotency-Key（审批、支付类） |
| 防重放 | 关键写操作 timestamp + nonce（可选） |

### 7.2 限流建议

| 接口 | 限制 |
| --- | --- |
| 登录 | 10 次/分钟/IP |
| 验证码 | 1 次/分钟/手机号 |
| 导出 | 5 次/小时/用户 |
| 审批写 | 20 次/分钟/用户 |
| 普通查询 | 100 次/分钟/用户 |

### 7.3 数据库与 Redis

- 所有业务表：`tenant_id` NOT NULL + 索引
- 敏感列加密：id_card、phone、address（应用层 AES + KMS）
- 账号最小权限：app 只读写业务库；无 DDL 生产权限
- 审计表：**仅 INSERT**；触发器或权限禁 UPDATE/DELETE
- 备份：加密；异地；季度恢复演练
- Redis Key 前缀 `{tenantId}:`；RefreshToken、登录失败计数、限流计数；禁止存 L4 明文

### 7.4 归属校验

`studentId`、`schoolId`、`collegeId`、`classId` 写入/查询前校验属于当前 tenant + scope。

## 11. 移动端与小程序安全

08A 学生小程序、08B 教师移动工作台 — **当前暂缓开发**（P5.5）；结构先冻结。

### 11.1 传输

- 全链路 **HTTPS**；禁 HTTP 降级
- 可选证书绑定（pinning）防中间人

### 11.2 本地存储

- **敏感数据不落本地**（身份证、手机号、成绩、周报全文）
- 仅缓存非敏感配置（主题、菜单结构 hash）
- 若必须缓存 token：加密存储 + 短有效期

### 11.3 权限

- 地理位置：**仅打卡时**申请；说明用途
- 相机/相册：上传材料时申请
- 禁止跳转未验证第三方 URL（白名单）

### 11.4 会话

- 7 天无操作退出
- 同账号并发 ≤3
- 小程序 session 与 PC 独立

### 11.5 业务

- 菜单受 licenseContext + 学生阶段过滤
- 企业/家长端若启用：最小权限 + 审计
- 移动批阅：退回原因 ≥5 字（workflow 已冻结）

### 11.6 开发任务（后期）

- [ ] 小程序 request 封装 + 401 处理
- [ ] 禁 WebView 加载外部 HTML
- [ ] 截图水印（敏感页可选）

## 12. 密钥密码与环境变量管理

### 12.1 禁止

- 硬编码 JWT Secret、DB 密码、OSS Key、短信 Key
- 提交 `.env`、`.env.production` 到 Git
- 在日志、前端 bundle、错误页暴露密钥

### 12.2 必须走环境变量或 KMS 的项

| 密钥 | 用途 |
| --- | --- |
| JWT_SECRET / JWT_PRIVATE_KEY | 签发 Token |
| DB_PASSWORD | 数据库 |
| REDIS_PASSWORD | 缓存 |
| OSS_ACCESS_KEY | 文件 |
| SMS_API_KEY | 短信/MFA |
| ENCRYPTION_KEY / KMS_KEY_ID | 字段加密 |
| MFA_ENCRYPTION_KEY | MFA 密钥加密 |

### 12.3 仓库规范

- `.env.example` 仅 placeholder，无真实值
- `.gitignore` 含 `.env*`
- CI 用 Secret 注入

### 12.4 轮换

- 关键密钥 **至少每季度**轮换
- 轮换计划：双密钥并行 → 切换 → 废弃旧密钥
- 轮换操作审计

### 12.5 开发/运维

- [ ] 密钥清单登记表（不在 Git）
- [ ] 离职人员密钥轮换
- [ ] 生产密钥仅运维角色可读

### 12.6 前端

- 前端 bundle **不得**含后端 Secret
- Vite 仅 `VITE_*` 公共配置（API 基址等非密钥）

## 13. 应急响应与安全事件处置

### 13.1 触发场景

异常登录、越权访问、批量导出敏感数据、账号异常锁定、密码泄露 suspected、模块授权异常变更、高频失败请求、可疑文件上传、租户数据交叉 suspected、DDoS、勒索软件。

### 13.2 处置能力（须具备）

| 能力 | 说明 |
| --- | --- |
| 强制下线 | 撤销 RefreshToken、踢会话 |
| 紧急锁账号 | 禁用 user + 审计 |
| 数据快照 | DB/文件只读快照备查 |
| 审计追溯 | 按 userId/requestId/时间窗查 audit |
| 模块授权回滚 | platform 恢复 license 快照 |
| 安全通知 | 学校联系人 + 内部值班 |

### 13.3 流程

1. **发现** — 监控/用户/report
2. **分级** — P1～P4（§8.5）
3. **遏制** — 锁账号、关入口、WAF 规则
4. **根除** — 补丁、改密、轮换密钥
5. **恢复** — 验证后开服
6. **总结** — 报告 + 整改项入库

### 13.4 记录

每次事件：**事件单号、时间线、影响范围、处置人、根因、整改** — 保留 ≥2 年。

### 13.5 联系人（模板）

| 角色 | 职责 |
| --- | --- |
| 安全负责人 | 决策 |
| 运维值班 | 遏制 |
| 开发负责人 | 修复 |
| 学校对接人 | 通报 |
