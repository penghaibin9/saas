# 04 · 统一响应结构与错误码

> 文档性质：全端统一响应结构与错误码权威规范（本轮新增，与历史冻结总册对齐，见 §四/§五）

> 依据：`docs/05-数据接口权限与安全/api/00-API契约冻结总册.md` §二/§三/§四（**错误码以冻结总册 §三为准，本文档逐条对齐**）；`docs/05-数据接口权限与安全/database/00-数据库设计冻结总册.md`；前端 `frontend/src/security/constants/security.constants.js`

## 一、权威统一响应结构

**本轮所有文档统一使用以下结构，必须含 `code`/`message`/`data`/`traceId`/`timestamp` 五个顶层字段。**

### 1.1 成功响应

```json
{
  "code": "SUCCESS",
  "message": "success",
  "data": {},
  "traceId": "req-8f3a1c2e-...",
  "timestamp": "2026-07-04T14:05:00+08:00"
}
```

### 1.2 失败响应

```json
{
  "code": "NO_PERMISSION",
  "message": "无权限访问",
  "data": null,
  "details": {
    "required": "student.profile.view"
  },
  "traceId": "req-8f3a1c2e-...",
  "timestamp": "2026-07-04T14:05:00+08:00"
}
```

### 1.3 字段说明

| 字段 | 类型 | 必含 | 说明 |
|---|---|---|---|
| code | string | 是 | 业务码，字符串枚举（见 §四错误码表），`SUCCESS` 表示成功，其余均为失败 |
| message | string | 是 | 人类可读提示，前端可直接展示给用户 |
| data | object\|array\|null | 是 | 成功恒为对象（或分页对象，见 §二）；失败恒为 `null` |
| details | object | 否 | 失败时的补充信息（如缺失的权限码、字段级/行级校验错误），成功响应不含此字段 |
| traceId | string | 是 | 请求链路 ID，格式建议 `req-{uuid}`，对应请求头 `X-Request-Id` 回传值，同时对应 DB 审计表的 `request_id`；前端报错时展示给用户便于报障 |
| timestamp | string | 是 | ISO8601 带时区时间戳，如 `2026-07-04T14:05:00+08:00` |

- `code` 为业务码；HTTP 状态码另用于传输层语义（200/400/401/403/404/409/413/429/500，映射见 §四）。
- `traceId` 由后端生成并回传，对应请求头 `X-Request-Id`（见 `05-接口鉴权与数据范围.md`）。
- ID 一律字符串化返回（避免 BIGINT 雪花值超出 JS 安全整数）；时间统一 ISO8601 带时区；金额返回字符串或两位小数数字，前端不做浮点运算；枚举返回英文码 + 可选 `xxxLabel` 中文标签。

## 二、分页结构

**请求参数（页码分页，PC 列表默认）：**
```
GET /api/v1/admin/students?page=1&pageSize=20&sort=createdAt,desc
```

**请求参数（游标分页，小程序滚动加载可选）：**
```
GET /api/v1/student-mini/messages?cursor=xxx&pageSize=20
```

**响应结构（放在 `data` 内）：**
```json
{
  "code": "SUCCESS",
  "message": "success",
  "data": { "list": [], "total": 100, "page": 1, "pageSize": 20 },
  "traceId": "req-...",
  "timestamp": "2026-07-04T14:05:00+08:00"
}
```

| 字段 | 说明 |
|---|---|
| list | 当前页数据数组，空态为 `[]` |
| total | 总条数；游标模式可为 `null`（不强制计算总数） |
| page | 当前页码（游标模式可省略，改用 `nextCursor`） |
| pageSize | 每页条数，默认 20（PC 部分模块默认 10 或 50，见各模块文档），单次上限 100 |

> **字段名历史差异**：历史冻结总册 §四使用 `items` 作为列表字段名，本轮共享底稿统一为 `list`。两者语义相同，后端 DTO 层归一为 `list`，不让前端同时处理两种字段名；此点待后端在冻结总册下一版本同步收敛，本轮不修改历史冻结文档。

## 三、空态与异常态约定

| 场景 | 约定 |
|---|---|
| 列表查询无数据 | `code=SUCCESS`，`data={list:[],total:0,page,pageSize}`，不返回错误码，前端渲染"暂无数据"空状态组件 |
| 详情查询目标不存在 | `code=DATA_NOT_FOUND`，`data=null`，前端渲染空状态页或返回上一页 |
| 有菜单权限但当前数据范围内无数据 | 优先 `code=SUCCESS` + 空列表（体验更友好）；**越权尝试访问不属于自己范围的具体资源 → `NO_DATA_SCOPE`**。判定标准：能正常访问但范围内确无数据→空列表；越权访问具体资源 ID→NO_DATA_SCOPE |
| 网络异常/服务端异常 | `code=SERVER_ERROR`，`data=null`，前端跳转 `/security/500` 并展示 `traceId` |
| 未登录 / Token 失效 | `code=UNAUTHORIZED`，`data=null`，前端跳转登录页或 `/security/401` |
| 会话超时 / CSRF 失效 | 契约层统一为 `code=UNAUTHORIZED`（HTTP 401）；前端安全层（`security.constants.js`）另用自定义状态 **419** 区分"会话超时"体验，跳转 `/security/419` 要求重新登录（见 §4.2） |
| 表单/参数校验失败 | `code=VALIDATION_ERROR`，`details` 给字段级原因，前端表单标红提示，不跳转 |
| 禁止裸返回 | 任何情况下不允许返回裸 `500`、空白响应体或非本结构的 JSON；所有响应必须走本结构包裹 |

## 四、完整错误码表（= 冻结总册 00 §三，逐条对齐）

**权威来源为 `docs/05-数据接口权限与安全/api/00-API契约冻结总册.md` §三。本表与其逐条一致；本轮全部文档统一使用下列字符串码。** 各模块专用码需挂靠下表大类，不得新造与下表语义重复的码。

| code | HTTP | 含义 | 前端表现 |
|---|---|---|---|
| SUCCESS | 200 | 成功 | 正常渲染 |
| VALIDATION_ERROR | 400 | 参数校验失败（**含导入校验失败**，`details` 给字段级/行级原因） | 表单标红 / 导入错误行清单 |
| UNAUTHORIZED | 401 | 未登录 / Token 失效 / 会话超时 / 并发被踢 | 跳登录（`/security/401`） |
| NO_PERMISSION | 403 | 无角色权限（缺权限码） | 无权限页 `/security/403` 或按钮隐藏 |
| NO_DATA_SCOPE | 403 | 有菜单权限但**数据范围越权**/范围内无数据 | 空列表 + "当前身份范围暂无数据" |
| TENANT_NOT_FOUND | 404 | 租户不存在 / 停用 | 提示联系管理员 |
| ROLE_NOT_FOUND | 404 | 角色 / 身份不存在 | 引导切换身份 |
| DATA_NOT_FOUND | 404 | 资源不存在 | 空态 / 详情 `data=null` |
| DATA_CONFLICT | 409 | 数据冲突（重复 / 状态不允许） | 提示原因 |
| APPROVAL_VERSION_CONFLICT | 409 | 乐观锁冲突（他人先改） | 提示刷新后重试 |
| REJECT_REASON_REQUIRED | 400 | 驳回未填原因或 < 5 字 | 强制填写 |
| MODULE_NOT_AUTHORIZED | 403 | 模块未授权 | 菜单隐藏 / 未开通页 |
| MODULE_EXPIRED_READONLY | 403 | 模块到期只读 | 只读横幅 + 续费提示 |
| FILE_TOO_LARGE | 413 | 文件超限（> 50MB） | 提示压缩 |
| FILE_TYPE_NOT_ALLOWED | 400 | 文件类型不允许（白名单外） | 提示允许类型 |
| UPLOAD_FAILED | 500 | 上传失败 | 允许重试 |
| WECHAT_AUTH_REQUIRED | 401 | 需微信授权 | 拉起微信授权 |
| LOCATION_PERMISSION_REQUIRED | 400 | 需定位权限（打卡） | 引导开定位 |
| IDEMPOTENCY_CONFLICT | 409 | 相同 `request_id` 不同 payload | 提示重复提交 |
| RATE_LIMITED | 429 | 触发限流 | 稍后重试 |
| SERVER_ERROR | 500 | 服务异常 | `/security/500` + traceId |

> 任务书要求覆盖的 9 类错误 → 本表映射：未登录=`UNAUTHORIZED`；无权限=`NO_PERMISSION`；数据不存在=`DATA_NOT_FOUND`；参数错误=`VALIDATION_ERROR`；租户不存在=`TENANT_NOT_FOUND`；数据范围越权=`NO_DATA_SCOPE`；文件上传失败=`UPLOAD_FAILED`（+`FILE_TOO_LARGE`/`FILE_TYPE_NOT_ALLOWED`）；导入校验失败=`VALIDATION_ERROR`（域码 `IMPORT_VALIDATION_FAILED`，见 §4.1）；系统异常=`SERVER_ERROR`。

### 4.1 各域可扩展专用码（挂靠上表大类，语义不重复）

冻结总册 §三允许"各域扩展专用码，但必须挂靠上表大类"。本轮涉及的域码：

| 域码 | 挂靠大类 | HTTP | 使用域 | 说明 |
|---|---|---|---|---|
| `IMPORT_VALIDATION_FAILED` | VALIDATION_ERROR | 400 | 导入域 | 导入模板校验失败，`details.rows` 返回错误行清单（见 `06-导入导出接口约定.md`） |
| `TASK_ALREADY_FINISHED` | DATA_CONFLICT | 409 | workflow | 审批任务已终态，不可重复处理（前端 mock `workflow.contract.js` 中为数字 42001） |
| `TASK_NOT_WITHDRAWABLE` | DATA_CONFLICT | 409 | workflow | 当前节点不允许撤回（mock 42002） |
| `TEMPLATE_HAS_RUNNING_INSTANCE` | DATA_CONFLICT | 409 | workflow | 停用流程模板时该模板存在在途实例，需二次确认（mock 42003） |
| `TEACHER_MOBILE_SCOPE_DENIED` / `SOD_VIOLATION` / `LOCATION_OUT_OF_RANGE` | NO_DATA_SCOPE / NO_PERMISSION / LOCATION_PERMISSION_REQUIRED | — | 教师移动/审批/打卡 | 冻结总册 §三示例保留 |

### 4.2 前端安全层特有状态（非契约码）

| 前端状态 | 契约层归一 | 说明 |
|---|---|---|
| 419（`security.constants.js` `SESSION_EXPIRED`） | `UNAUTHORIZED`(401) | 前端用 419 区分"曾登录、现超时/CSRF 失效"，展示"会话已超时，请重新登录"并跳 `/security/419`；后端契约层不新增 419，仍返回 `UNAUTHORIZED`。 |

## 五、前端 mock 历史差异说明（后端对接前务必读懂）

本文档 §四错误码表已与历史冻结总册 §三**完全一致**，二者无差异。真正需要注意的差异在**前端 mock 各自的历史实现**——后端实现真实接口时一律以本文档（=冻结总册）为准，不得照抄任何 mock 现状：

| 口径来源 | 响应包裹 | code 类型 | 追踪字段 | 现状 |
|---|---|---|---|---|
| **本文档（= 冻结总册 §二/§三，权威）** | `{code,message,data,traceId,timestamp}` | 字符串（`SUCCESS`/`NO_PERMISSION`…） | `traceId`（回传自 `X-Request-Id`） | 后端应实现的目标口径 |
| workflow 前端 mock（`workflow.contract.js`） | `{code,message,data,timestamp,requestId}` | **数字**（`0`=成功、`41001`=NO_PERMISSION、`404xx`…） | `requestId`（非 `traceId`） | 前端历史 mock，字段名与类型均不同 |
| student 等 9 个 PC 模块 mock（`*.api.js`） | `Promise<{code,data,message}>` | **数字**（仅 `0`=成功 / `1`=失败，无细分码） | 无 | 极简 mock，未体现细分错误码 |
| miniapp mock（`request.js` `mockRequest`） | 直接返回业务数据（无包裹），失败态 `{code:'MOCK_ERROR',message}` | 仅 `MOCK_ERROR` | 无 | 演示态实现 |

**后端实现原则**：

1. 一律按本文档 §一/§三/§四实现真实接口：字符串 `code` + `traceId` + `timestamp`，不采用任何 mock 的字段名/类型差异版本。
2. workflow 模块的**数字 code 与 `requestId` 字段名**，后端真实接口必须转换为**字符串 code 与 `traceId`**；前端切真实 API 时同步把 `code===0` 的判断改为 `code==='SUCCESS'`。
3. student 等模块 mock 的 `0/1` 二值码，后端按本表细分为具体字符串码（如原来笼统 `code:1` 的失败，区分为 `VALIDATION_ERROR`/`NO_PERMISSION`/`DATA_NOT_FOUND` 等）。
4. miniapp `{code:'MOCK_ERROR'}` 仅演示态标记，后端不使用；前端 `request()` 真实实现层需把后端标准错误响应转换为页面可用提示，不让页面直接判断 `MOCK_ERROR`。
