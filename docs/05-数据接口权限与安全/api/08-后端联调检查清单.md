## 二、统一响应结构落地

- [ ] 后端所有接口返回 `{code,message,data,traceId,timestamp}` 五字段结构（见 `04-统一响应结构与错误码.md` §一）
- [ ] `code` 为字符串枚举，成功恒为 `SUCCESS`
- [ ] `traceId` 由后端生成，格式统一（建议 `req-{uuid}`），并与请求头 `X-Request-Id` 关联
- [ ] `timestamp` 为 ISO8601 带时区字符串
- [ ] 列表类接口 `data` 内层为 `{list,total,page,pageSize}` 分页结构（见 `04` §二）
- [ ] 无裸 500、空白响应体、非标准 JSON 结构的接口（逐一自查所有已实现接口）

## 四、分页

- [ ] 所有列表接口已支持 `page`/`pageSize`（页码分页）或 `cursor`/`pageSize`（游标分页）
- [ ] `pageSize` 默认值与各模块文档一致（多数模块默认 10，部分默认 20/50，见 02 文档各模块说明）
- [ ] 单次 `pageSize` 上限 100 已在服务端强制校验（防止前端传超大值拖垮数据库）
- [ ] 空列表返回 `{list:[],total:0}`，非 `null` 或缺失字段

## 五、幂等与乐观锁

- [ ] 写操作携带的 `requestId` 幂等键已在服务端生效（同 `requestId` 不同 payload 返回 `IDEMPOTENCY_CONFLICT`）
- [ ] 审批类写操作携带的 `version` 乐观锁已在服务端生效（版本不一致返回 `APPROVAL_VERSION_CONFLICT`）
- [ ] 退回/驳回类操作的 `reason`/`rejectReason` 服务端二次校验 ≥5 字（不仅依赖前端表单校验）
