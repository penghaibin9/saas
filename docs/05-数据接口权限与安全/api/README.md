## 一、为什么本目录有"两套"文档

`docs/05-数据接口权限与安全/api/` 下存在两个批次的文档，**关系是互补，不是替代或冲突**：

| 批次 | 文件 | 产出时间 | 定位 | 本轮是否可改 |
|---|---|---|---|---|
| 第一批（历史冻结） | `00-API契约冻结总册.md`、`01-认证租户与当前上下文API.md`、`02-学生主档与学生360API.md`、`03-数字迎新API.md`、`04-待办审批消息API.md`、`05-岗位实习API.md` | 2026-07-03 | **权威冻结总册 + 按业务域的详细契约**（认证/学生主档/迎新/待办审批消息/岗位实习 5 个域已逐接口冻结，含 DB 表映射、一期 P0–P4 优先级） | **禁止修改、禁止覆盖** |
| 第二批（本轮新增） | `01-接口契约总览.md` ~ `08-后端联调检查清单.md`（9 个文件，与第一批编号并存但内容独立） | 2026-07-04 | **跨端组织视图 + 尚未覆盖域的补齐规范**：把 PC 11 个业务模块、miniapp 学生端/教师端全部接口按"总览表 + 逐接口契约"方式补齐，并新增响应结构、鉴权、导入导出、文件上传、联调清单等**横切规范** | 本轮产出，后续如需变更请走评审流程，不在本次任务范围内 |

**阅读顺序建议**：
1. 先看历史冻结总册 `00-API契约冻结总册.md`，理解统一响应结构、错误码、分页、tenant_id/角色/数据范围、审计、文件上传等全局规则的**原始权威定义**。
2. 再看本轮 `04-统一响应结构与错误码.md` 和 `05-接口鉴权与数据范围.md`，这两篇是本轮对同一套全局规则的**再确认版本**（口径与共享事实底稿一致，个别错误码字符串与历史冻结总册 §三 存在历史差异，详见 04 文档"前端 mock 历史差异"一节的说明，以共享底稿口径为准）。
3. 已被历史冻结总册覆盖的域（认证/学生主档/迎新/待办审批消息/岗位实习）→ 优先看 `01`–`05`（历史冻结）里的对应文档；本轮 `02-PC管理端接口契约.md`、`03-miniapp接口契约.md` 对这些域只做**概览级引用**，不重复制定接口细节，避免双重权威。
4. 历史冻结总册**未覆盖**的域（workflow 权限与流程、在校服务、学业过程、毕业设计、就业服务、数据驾驶舱、审批中心、系统管理、平台运营，以及 miniapp 全部页面服务层方法）→ 看本轮 `01-接口契约总览.md`（全景表）+ `02-PC管理端接口契约.md` / `03-miniapp接口契约.md`（逐接口契约）。
5. 需要落地联调时 → 看 `06-导入导出接口约定.md`、`07-文件上传接口约定.md`、`08-后端联调检查清单.md`。

## 三、当前阶段声明（务必先读）

- **当前为 mock 口径**：PC 管理端（`frontend/`）与 miniapp（uni-app）当前均通过前端门面（`api/*.api.js`、`services/*Api.js`）读取内存 mock 数据，**没有真实网络请求**、没有连接数据库、没有真实后端鉴权。
- **后端接入时按此契约实现**：本目录所有接口的路径、方法、参数、返回字段、权限点、数据范围、错误码，均为后端实现的**目标契约**。后端联调时应对照本目录文档实现真实接口，前端只需将对应 `api/*.api.js`（PC）或 `ENV.useMock`（miniapp）从 mock 实现切换为真实请求，页面与 store 不应改动（切换细节见 `08-后端联调检查清单.md`）。
- 本目录不涉及任何代码修改，纯文档产出；数据库字段/表结构以 `docs/05-数据接口权限与安全/database/00-数据库设计冻结总册.md` 为唯一权威，本目录只引用不重写。
