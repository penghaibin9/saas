## 3. workflow node_code 序列冻结（补 C4 §12 的节点明细，审批流实现依据）

> 通用规则：实例落 `t_workflow_instance(workflow_code, source_module, source_biz_type, source_biz_id, status, current_node)`；任务落 `t_workflow_task(node_code, assignee_id, status, action_reason, acted_at, version)`。退回=回 `SUBMIT` 节点重提（新任务，旧任务留痕）；驳回=终态。审批层级由**规则中心阈值**动态决定（见 §5），节点序列本身固定。

### 3.1 13A 关键流程 node_code

| workflow_code | node_code 序列 | 分流规则 |
|---|---|---|
| AFFAIRS_LEAVE | `SUBMIT → COUNSELOR_REVIEW → DONE` | days ≤ `college_threshold_days`(默3) 走此单节点 |
| AFFAIRS_LEAVE_LONG | `SUBMIT → COUNSELOR_REVIEW → COLLEGE_REVIEW → DONE` | college_threshold < days ≤ `sa_office_threshold_days`(默7) |
| AFFAIRS_LEAVE_MAJOR | `SUBMIT → COUNSELOR_REVIEW → COLLEGE_REVIEW → SA_OFFICE_REVIEW → DONE` | days > sa_office_threshold |
| AFFAIRS_LEAVE_EXTENSION | `SUBMIT → (按累计天数重算走上面三档之一) → DONE` | 续假累计天数重定档 |
| AFFAIRS_LEAVE_CANCEL | `SUBMIT → COUNSELOR_CONFIRM → DONE` | 单节点销假确认 |
| AFFAIRS_AID_IDENTIFY | `SUBMIT → [CLASS_REVIEW] → COUNSELOR_REVIEW → COLLEGE_REVIEW → SCHOOL_REVIEW → PUBLICITY → DONE` | `[CLASS_REVIEW]` 受 `affairs.aid.class_review_enabled`(默 true) 控制；关则跳过（见 §4-裁定2） |
| AFFAIRS_SCHOLARSHIP / AFFAIRS_GRANT | `SUBMIT → COUNSELOR_REVIEW → COLLEGE_REVIEW → SCHOOL_REVIEW → PUBLICITY → DONE` | 按 **workflow_code** 路由，非按 projectType（见 §4-裁定3） |
| AFFAIRS_DISCIPLINE | `SUBMIT → COLLEGE_REVIEW → SA_OFFICE_REVIEW → [SCHOOL_REVIEW] → EFFECTIVE` | `[SCHOOL_REVIEW]` 当 disc_type ≥ `discipline.school_review_levels`(默"记过及以上") 才加 |
| AFFAIRS_DISCIPLINE_REMOVE | `SUBMIT → COUNSELOR_REVIEW → COLLEGE_REVIEW → SA_OFFICE_FINAL → REMOVED` | 解除门槛 `remove_min_months`(默6) |
| AFFAIRS_DORM_TRANSFER | `SUBMIT → COUNSELOR_REVIEW → DORM_MANAGER_REVIEW → EXECUTED` | 目标床位校验在业务层（占用 409） |
| AFFAIRS_ARCHIVE | `SUBMIT → COLLEGE_REVIEW → SA_CONFIRM → ARCHIVED` | — |

### 4.2 五大集成点工程约定（最高风险处，逐点定死）

**集成① t_cs_leave 双状态列并行**（依据 C3 §5.2/§5.3，本总纲确认）
- 写侧单点：13A 上线起新请假单只经 13A 服务写，同事务维护 `affairs_status`(真相) + 旧 `status`(投影)。投影映射：过程审批态→`PENDING_REVIEW`；APPROVED/CLOSED/ARCHIVED→`APPROVED`；REJECTED/RETURNED→`RETURNED`。
- 旧 campus-service 请假**读端点零改动全绿**；旧**写端点**保留路径、内部转发 13A 流程，禁双入口各写。
- backfill 一次性回填 affairs_status/student_id/days（脚本 `backend/scripts/_backfill_cs_leave_affairs_status.py`，先 `--dry-run` 对账 0 差异）。
- 对账门禁：每日任务比对投影一致性；13A-P8 验收含「对账 0 差异」硬门禁。并行期至 P8 后一迭代下线旧写端点，**旧 status 列永久保留不删**。

**集成② t_cs_discipline 处分投影**（依据 C3 §3.5/§5.3）
- t_affairs_discipline_case 进 EFFECTIVE 时**同事务**写/更新一行 t_cs_discipline（投影，`source_case_id` 回链），REMOVED 时更新该投影行 record_status。既有学生端「只回数量」接口零改动。
- 一致性对账口径：`EFFECTIVE 的 case 数 == source_case_id 非空且 record_status=ACTIVE 的投影行数`。投影写入用 version 乐观锁，冲突重试。
- 13B 毕业预审**只读**该投影行最新状态，不改写；13A-P4 晚于 13B-P6 时，13B 先按投影 ACTIVE 口径 + 规则开关实现，13A 上线后零代码切换。

**集成③ `change_student_status()` 学籍状态单一写入口**（13B-P1 落地，全平台红线，NEW 规格）
- **职责**：全平台**唯一**允许写 `t_student_profile.student_status` 的函数。签名建议 `change_student_status(db, student_id, to_status, change_type, reason, operator, source_biz_id=None) -> None`。
- **五件事（同一事务）**：① 校验 `(from_status → to_status)` 在**合法转移白名单**内（非法→422 `VALIDATION_ERROR`）；② 乐观锁更新主档 student_status（version+1）；③ 写 t_aa_status_change 异动流水一行；④ 写 t_student_stage_event（source_module='academic-affairs'）；⑤ 调 audit_log.record。
- **枚举白名单扩展**（t_student_profile 零加列，仅扩 student_status 取值）：新增 `PENDING_REGISTER/REGISTERED/UNREGISTERED/SUSPENDED/RETAINED/WITHDRAWN/TRANSFER_SCHOOL/GRADUATED/COMPLETED/INCOMPLETE`；保留 `NORMAL/MERGED/RECYCLED`；存量 NORMAL 语义即「在籍」不回填。
- **合法转移矩阵**（V1 冻结，P1 产出用例库）：`NORMAL/REGISTERED →(休学)→ SUSPENDED →(复学)→ REGISTERED`；`→(退学)→ WITHDRAWN`(终)；`→(留级)→ RETAINED →REGISTERED`；`→(毕业审核)→ GRADUATED/COMPLETED/INCOMPLETE`(终)；`PENDING_REGISTER →(注册)→ REGISTERED`/`→(逾期)→ UNREGISTERED`。`MERGED/RECYCLED/WITHDRAWN/GRADUATED` 为终态，禁再发起业务（各域入口读「在籍判定」函数拦截）。
- **在籍判定工具函数** `is_enrolled(student_status) -> bool`（`REGISTERED/NORMAL/RETAINED` 为 True；`SUSPENDED/WITHDRAWN/GRADUATED/…` 为 False），供 13A/13B 全域入口校验（休学生禁发起请假/选课等）。
- **红线落地**：P1 全库 `grep -rn "student_status\s*=" backend/app` 产出硬编码写清单并清零（除本函数外）；CI 加一条「禁止其他 student_status 直写」的 grep 门禁用例。

**集成④ 成绩发布回写 t_acad_grade**（V1 只读，契约冻结留 P2 实施）
- V1：成绩查看**纯读** t_acad_grade（`/academic/grade-views` 聚合），**零成绩写端点**（C4 红线3）；既有 `/academic/grades` 端点**零改动 + 快照回归**。

**集成⑤ 毕业预审七项供数契约**（13B-P6，只读六域，不得要求各域改表）
- 七项判定，每项三态 `PASS / FAIL / UNKNOWN`（+证据引用），**UNKNOWN ≠ FAIL**（缺数据默认按规则开关处理，不直接判不通过）：
  1. 学籍正常 ← t_student_profile.student_status（is_enrolled 且非异常）
  2. 学分/必修达标 ← t_acad_grade 聚合 vs t_aa_program.requirement_json
  3. 实习完成 ← 实习域 t_internship_record 归档态
  4. 毕设通过 ← t_gd_student/final/defense 结论
  5. 无未解除严重处分 ← t_cs_discipline(record_status=ACTIVE) 投影（集成②）
  6. 就业去向填报 ← t_emp_student（默认「提醒不卡审」，受 `academicAffairs.graduation.conditions` 开关）
  7. 材料/费用 ← t_orientation_student + 归档
- 规则开关 `academicAffairs.graduation.conditions.treatMissingDataAs`（默 `UNKNOWN`，可配 `FAIL`）控制缺数据学生的整体判定。
- 异常推待办按 §4-裁定6 责任方路由；终审经 change_student_status 写结论（集成③）；结果表 `(tenant_id,batch_id,student_id)` 唯一，重跑覆盖更新。
