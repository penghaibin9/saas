## 第 0 章 统一设计要素清单（28 要素）

需求输入 §0 要求每个业务不做普通 CRUD，必须回答「谁发起……是否需要导出归档」并覆盖「业务流程/状态机/权限/审批/消息/360/统计/导入导出/移动端/审计」。本册将两组要求合并、去重、编号为下列 **28 要素**，第 3 章每个 V1 业务逐项作答：

| 编号 | 要素 | 编号 | 要素 |
|---|---|---|---|
| E01 | 谁发起 | E15 | 是否进入学生360（落哪张表、聚合如何读） |
| E02 | 谁审核 | E16 | 是否影响数据中心/统计指标（口径） |
| E03 | 谁处理/执行 | E17 | 是否涉及敏感字段与脱敏 |
| E04 | 谁查看 | E18 | 审计记录（audit_log.record 动作点） |
| E05 | 业务主流程 | E19 | 导入导出（domain 注册） |
| E06 | 状态机 | E20 | 移动端高频入口（学生小程序/教师端） |
| E07 | 状态-操作矩阵（什么状态能/不能操作） | E21 | 核心表（新建 t_aa_* / 复用既有表） |
| E08 | 退回后回到哪里 | E22 | 关键 API（契约级路径） |
| E09 | 通过后影响什么 | E23 | 页面与路由（/admin/academic-affairs/*） |
| E10 | 失败/驳回后提示什么 | E24 | 与既有系统衔接决策（扩展 vs 新建） |
| E11 | 审批流（workflow_code 与节点序列） | E25 | 异常与边界场景 |
| E12 | 权限点与数据范围 | E26 | 幂等与并发控制 |
| E13 | 消息通知（统一消息类型与接收人） | E27 | 归档要求 |
| E14 | 是否通知学生/老师/家长 | E28 | 需学校确认的问题 |

**全局默认值（各业务不再重复，只写差异）**：

1. 响应体/错误码：一律沿用既有实现 `{code(数字), bizCode, message, data, traceId, timestamp}`；401001/403001/403002/404001/409001/422001/429001/400001；业务错误绝不 500。
2. 审批：一律新增 workflow_code + node_code 序列，实例/任务落 `t_workflow_instance`/`t_workflow_task`，待办进 `t_unified_todo`，消息进 `t_unified_message`；已处理再审 409 APPROVAL_VERSION_CONFLICT。禁止自建审批表和消息表。
3. 消息类型：仅允许 WORKFLOW_TODO / WORKFLOW_RESULT / RISK_ALERT / DEADLINE_REMINDER / STATUS_CHANGED / RETURNED_NOTICE / PUBLISHED_NOTICE / ARCHIVE_NOTICE 八类。
4. 数据范围：教务处=全校；学院教务员=本学院；专业负责人=本专业；任课教师=本人课程/授课学生；督导=授权课程学院；学生=本人。统一封装 `getAcademicScope(user)` / `canAccessAcademicStudent(user, studentId)` / `filterAcademicRecordsByScope(query, user)`，实现为既有 `t_teacher_student_scope` + `resolve_teacher_scope` 机制的扩展（新增 scope_type=MAJOR、COURSE、SUPERVISED_COLLEGE），**不另起炉灶**；看得见=能处理，列表过滤与写校验共用同一 scope 函数。
5. 权限点命名：`academicAffairs.<biz>.<action>`。
6. API：PC 教职工 **13B 新建** `/api/v1/academic-affairs/*`（require_staff）；**复用既有学业过程** `/api/v1/academic/grades|warnings|students`；学生新建 `/api/v1/mobile/academic-affairs/*`，复用 `/api/v1/mobile/academic/my`；教师移动写操作 `/api/v1/mobile/teacher/*` 包装（范围+审计+409）。
7. 新表：`t_aa_*` 前缀（避开既有 `t_acad_*`），BIGINT 主键（雪花）、公共字段（tenant_id/created_at/updated_at/created_by/updated_by/is_deleted/version）、审计/流水表 append-only。
8. 导入导出：注册新 domain 走既有 `/api/v1/import/domain/{domain}/validate|confirm` 与 `/api/v1/export/domain/{domain}` 管线（dry-run 行级错误、整批事务、水印、t_export_task 留痕、用途必填≥5字、5000 行上限）。
9. 幂等：写操作带 request_id；重复提交 409001 IDEMPOTENCY_CONFLICT；审批带 version 乐观锁。
10. 演示环境：demo-school 只读锁对教务中心同样生效（写操作 403 引导沙箱）；可配置规则（预警阈值、异动时间窗、成绩构成比例等）接入既有平台规则中心（safe_rule），不新建管理端。

## 第 1 章 总体定位、边界与全局约定

### 1.1 业务域边界（必须遵守）

教务中心负责：学年学期、校历、学籍、学籍异动、专业、培养方案、课程库、教学任务、课表、调停课、选课、考试、缓考、补考、重修、成绩、成绩更正、学业预警、毕业资格审核、教务归档。

**不负责（明确让渡）**：

| 事项 | 归属 | 教务中心的关系 |
|---|---|---|
| 请假/销假/续假 | 学工中心（13A，基于 t_cs_leave 扩展） | 只读消费：考试期间生效请假单可触发缓考申请（§5.3） |
| 过程性学业数据（平时表现、课堂过程） | 既有学业过程中心（academic 域） | 成绩总评、预警记录与其共库衔接（第 2 章） |
| 实习/毕设/就业过程管理 | 既有 06/05/07 模块 | 毕业资格预审取数（§5.4 取数矩阵） |
| 学生主档与 360 聚合 | 学生中心 | 只写 StageEvent 与域记录，不建学生主表 |
| 审批引擎/消息/审计/导入导出/统计管线 | Workflow / Security / Dashboard 底座 | 全部复用，只注册新 code/domain |

### 1.2 角色与数据范围

| 角色 | 范围 | scope 实现 |
|---|---|---|
| 教务处管理员 | 全校 | resolve_teacher_scope → ADMIN_TENANT |
| 学院教务员 | 本学院 | scope_type=COLLEGE |
| 专业负责人 | 本专业 | scope_type=MAJOR（新增枚举） |
| 任课教师 | 本人课程/授课学生 | scope_type=COURSE（新增枚举，ref_value=teaching_task_id） |
| 教学督导 | 授权课程/学院 | scope_type=SUPERVISED_COLLEGE（新增枚举） |
| 辅导员 | 负责班级学生（预警联动只读） | 既有 CLASS/ADVISOR |
| 学生 | 本人课表/成绩/考试/进度 | token studentNo，新建教务走 /api/v1/mobile/academic-affairs/*；学业过程聚合复用 /api/v1/mobile/academic/my |

### 1.3 PC 菜单与路由关系（与既有 /admin/academic 学业过程模块的关系）

- 既有 `/admin/academic/*` = 学业过程中心（过程性学业数据、既有预警处理页），**保留不动**。
- 教务中心新路由 `/admin/academic-affairs/*`，一级菜单「教务中心」，与「学业过程」并列展示。
- 菜单归并原则：**学业预警的处理入口收敛到既有学业过程页面**（因预警记录仍在 t_acad_warning），教务中心内的「学业预警」菜单为规则配置 + 全景统计 + 跳转既有处理页；成绩查看在教务中心（读 t_acad_grade），避免双入口双真相。

### 1.4 开发分期（承接需求输入 §11）

13B-P1 契约冻结 → P2 学年学期/校历/学籍 → P3 专业/方案/课程库 → P4 教学任务/课表查看 → P5 成绩查看/学业预警 → P6 毕业资格预审 → P7 小程序教务入口 → P8 测试验收。P2/P3 业务（第 4 章）在 V1 之后另立阶段。

## 第 2 章 核心业务对象模型

### 2.1 对象总览（Academic* 对象 → t_aa_* 表）

命名规则：业务对象 `AcademicXxx` → 新表 `t_aa_xxx`。下表逐一标注与既有表的关系（**硬约束，违反即设计不通过**）：

| # | 业务对象 | 新表 / 承载 | 与既有表关系（红线） |
|---|---|---|---|
| 1 | AcademicYear 学年 | `t_aa_year` | 纯新建；全校唯一时间基准 |
| 2 | AcademicTerm 学期 | `t_aa_term` | 纯新建；term_code 冗余到各业务表，衔接 t_acad_grade.term 字段（见 2.3） |
| 3 | AcademicCalendarEvent 校历事件（教学周/考试周/实习周/节假日/调休） | `t_aa_calendar_event` | 纯新建；实习周与 t_internship_record 时间仅作展示比对，不建外键 |
| 4 | AcademicPeriodConfig 作息节次 | `t_aa_period_config` | 纯新建 |
| 5 | AcademicRegistrationBatch / AcademicRegistration 注册批次/注册记录 | `t_aa_registration_batch`、`t_aa_registration` | 注册结果**回写 t_student_profile.student_status**（受控扩展，见 2.4）；迎新完成状态从 t_orientation_student 只读取数 |
| 6 | AcademicStatusChange 学籍异动 | `t_aa_status_change`（异动主表，append 型留痕 + 主状态） | **禁止再建学生主表**；异动生效=更新 t_student_profile.student_status/major_id/class_id + 写 t_student_stage_event |
| 7 | AcademicProgram 培养方案（+版本） | `t_aa_program`、`t_aa_program_course`、`t_aa_program_requirement` | 纯新建；major_id 引用既有 `t_major`，禁止新建专业表 |
| 8 | AcademicCourse 课程库 | `t_aa_course`、`t_aa_course_prerequisite` | 纯新建；college_id 引用既有 `t_college` |
| 9 | AcademicTeachingTask 教学任务（+批次） | `t_aa_teaching_task_batch`、`t_aa_teaching_task` | teacher_id 引用 `t_teacher_profile`；class_id 引用既有 `t_class`，禁止新建班级表 |
| 10 | AcademicSchedule* 排课（批次/节次/规则/条目/冲突/发布） | `t_aa_schedule_batch`、`t_aa_time_slot`、`t_aa_schedule_rule`、`t_aa_schedule_item`、`t_aa_schedule_conflict`、`t_aa_schedule_publish` | 纯新建（需求 §3.7 的 academic_schedule_* 统一加 t_ 前缀落名） |
| 11 | AcademicScheduleChange 调停课 | `t_aa_schedule_change` | 纯新建；生效后修改 t_aa_schedule_item |
| 12 | AcademicEnrollment 选课（P2） | `t_aa_enrollment_batch`、`t_aa_enrollment` | 纯新建 |
| 13 | AcademicExam* 考务（P2） | `t_aa_exam_batch`、`t_aa_exam`、`t_aa_exam_room`、`t_aa_invigilation`、`t_aa_exam_incident` | 纯新建；考场引用 t_aa_classroom |
| 14 | AcademicDeferredExam 缓考 | `t_aa_deferred_exam` | 关联学工请假单（leave_ref_id → t_cs_leave 体系）；缓考安排并入补考批次后**结果落 t_acad_makeup**（见 2.3） |
| 15 | AcademicMakeup 补考 | **不新建记录表**：记录=既有 `t_acad_makeup` 受控扩展；仅新建批次安排表 `t_aa_makeup_batch` | 红线：补考基于 t_acad_makeup，本册只允许对其加列（batch_id/exam_time/room_id/final_score_rule），不得平行建补考记录表 |
| 16 | AcademicRetake 重修 | **不新建记录表**：记录=既有 `t_acad_retake` 受控扩展；报名审批状态列扩展其上 | 红线：重修基于 t_acad_retake，同上只加列（apply_status/enrollment_id/new_grade_id） |
| 17 | AcademicExemption 免修 | `t_aa_exemption` | 纯新建；通过后在学业进度视图中等价「已通过」，不伪造 t_acad_grade 分数行（写入 pass_status=EXEMPTED 的成绩行，分数为空） |
| 18 | AcademicGradeInputTask / AcademicGradeDetail 成绩录入任务/成绩构成明细（P2） | `t_aa_grade_input_task`、`t_aa_grade_detail` | 红线：**总评成绩唯一真相=既有 t_acad_grade**；明细表存平时/期末构成，发布动作把总评+pass_status 回写 t_acad_grade，禁止建第二张总评表 |
| 19 | AcademicGradeCorrection 成绩更正（P2） | `t_aa_grade_correction`（append-only，保留原值/新值/原因/材料） | 生效=更新 t_acad_grade 当前值，历史留在更正表 |
| 20 | AcademicWarningRule 学业预警规则 | `t_aa_warning_rule`（规则新表） | 红线：**预警记录不新建表**，命中后写既有 `t_acad_warning`（扩展 source_type/rule_id/term_code 列），处置沿用其 close/escalate/assign/remind API |
| 21 | AcademicGraduationAudit 毕业资格（批次/学生审核单/逐项结果） | `t_aa_graduation_batch`、`t_aa_graduation_audit`、`t_aa_graduation_audit_item` | 取数只读六域（§5.4）；毕业结论回写 t_student_profile.student_status（GRADUATED/COMPLETED/INCOMPLETE）+ StageEvent |
| 22 | AcademicClassroom 教室资源（P2） | `t_aa_campus`、`t_aa_building`、`t_aa_classroom` | 纯新建；与宿舍楼栋（t_cs_dorm_*）无关，禁止混用 |
| 23 | AcademicTextbook 教材（P3） | `t_aa_textbook`、`t_aa_textbook_order`、`t_aa_textbook_issue` | 纯新建 |
| 24 | AcademicEvaluation 教学评价（P3） | `t_aa_evaluation_plan`、`t_aa_evaluation_record` | 纯新建 |
| 25 | AcademicArchive 教务归档 | `t_aa_archive_batch`、`t_aa_archive_package` | 复用 t_file_object / t_export_task / 水印管线，不自建文件表 |

组织维度（学院/专业/班级）**一律复用既有 `t_college` / `t_major` / `t_class`**，教务中心只增加维护入口与校验，不建平行组织表。

### 2.2 对象关系图（文字版）

```
AcademicYear ─1:n─ AcademicTerm ─1:n─ CalendarEvent / PeriodConfig
t_major ─1:n─ AcademicProgram(版本) ─1:n─ ProgramCourse ──→ AcademicCourse(课程库)
AcademicTerm + Program ─→ TeachingTaskBatch ─1:n─ TeachingTask(课程×班级×教师)
TeachingTask ─→ ScheduleItem(课表条目) ─→ ScheduleChange(调停课)
TeachingTask ─→ GradeInputTask ─→ GradeDetail ─发布→ t_acad_grade(总评唯一真相)
t_acad_grade(FAILED) ─→ t_acad_makeup(补考) / t_acad_retake(重修) / WarningRule→t_acad_warning
StudentProfile.student_status ←─ Registration / StatusChange / GraduationAudit 回写
GraduationAudit ←取数← t_acad_grade + 实习 + 毕设 + 就业 + 处分 + 归档
```

### 2.3 专节：t_aa_* 与 t_acad_* 的映射关系（硬约束）

既有 `t_acad_*` 是「学业过程中心」已上线的表（以代码为准），`t_aa_*` 是教务中心新表。二者**分工不重叠、单点真相**：

| 数据 | 唯一真相表（既有 t_acad_*） | 教务中心新表的角色 | 衔接方式 |
|---|---|---|---|
| 学业预警记录 | `t_acad_warning`（PENDING_HANDLE/PROCESSING/ESCALATED/CLOSED，close/escalate/assign/remind API 已实现） | `t_aa_warning_rule` 只存规则与阈值 | 扫描任务按规则命中→**INSERT INTO t_acad_warning**（新增列：source_type、rule_id、term_code、course_ref）；处理端点复用既有，不新建预警处理 API |
| 课程总评成绩 | `t_acad_grade`（course/term/score/pass_status） | `t_aa_grade_input_task`（任务）+ `t_aa_grade_detail`（平时/期末构成） | 成绩「发布」动作事务内回写 t_acad_grade（新增列：grade_source=NORMAL/MAKEUP/RETAKE/EXEMPTED/CORRECTED、input_task_id、gpa_point）；学生端查成绩仍读 t_acad_grade |
| 补考记录 | `t_acad_makeup` | `t_aa_makeup_batch` 只存批次与场次安排 | t_acad_makeup 加列 batch_id/exam_time/room_id/makeup_score/result_status；补考成绩按计分规则回写 t_acad_grade（grade_source=MAKEUP） |
| 重修记录 | `t_acad_retake` | 重修报名/审批状态扩展在 t_acad_retake 上（apply_status 列）；P2 选课后关联 enrollment_id | 重修成绩产生新 t_acad_grade 行或按学校规则覆盖（§4.3 确认项） |
| 学籍状态 | `t_student_profile.student_status` + `t_student_stage_event` | `t_aa_status_change` 只存异动过程单据 | student_status 枚举受控扩展（2.4）；每次生效写 StageEvent（360 时间线数据源） |
| 学生过程性学业数据 | 既有 academic 域其余表 | 不触碰 | 教务中心统计可只读聚合 |

**迁移与兼容承诺**：对 t_acad_* 只做「加列 + 加索引」级别的受控扩展（Alembic 可回滚），不改既有列语义、不改既有 API 响应结构；既有 `/api/v1/academic/students|grades|warnings`（复用既有 academic 学业过程模块） 端点行为不变。

### 2.4 专节：学籍状态 = StudentProfile.student_status 受控扩展

现状：`current_stage`（ORIENTATION/ON_CAMPUS/INTERNSHIP/GRADUATION_DESIGN/EMPLOYMENT）+ `student_status`（NORMAL 等）+ StageEvent。设计：

- **current_stage 不动**（生命周期主线，归学生中心）。
- **student_status 受控扩展**为需求 §3.3 的学籍状态机取值：PENDING_REGISTER / ACTIVE(=NORMAL 兼容映射) / REGISTERED / UNREGISTERED / SUSPENDED / RESUMED / TRANSFER_MAJOR / TRANSFER_SCHOOL / WITHDRAWN / RETAINED / GRADUATED / COMPLETED / INCOMPLETE / ARCHIVED。兼容规则：存量 NORMAL 读作 ACTIVE，写入统一新枚举；映射表落在字典 t_dict（academic_student_status）。
- 所有状态变更**只允许**经由三个入口：入学/学年注册（§3.3）、学籍异动审批生效（§3.4）、毕业资格终审生效（§3.11）。禁止任何模块直接 UPDATE student_status。
- 每次变更同事务写 `t_student_stage_event`（event_type=STATUS_CHANGED，携带 from/to/单据号），被学生 360 聚合端点读取。

## 第 4 章 P2/P3 业务精简设计

> 精简版结构：目标 / 角色 / 主流程 / 状态要点 / 联动 / 确认问题。其中**缓考、补考、重修、成绩四个状态机为完整冻结版**（后续开发直接引用，V1 建表预留状态列取值域）。

### 4.1 自动排课 + 调停课（P2）

- **目标**：在 V1 人工排课基础上引入自动排课引擎（约束求解：硬约束=六类冲突为零，软约束=教师偏好/课程分布均匀/教室就近），产出方案供人工微调；补齐调停课全流程。
- **角色**：教务处（引擎配置/裁决）、学院教务员（微调）、任课教师（调停课发起）、师生（接收变更）。
- **主流程（自动排课）**：V1 批次基础上选「自动排」→载入规则权重→引擎求解→未解任务清单+冲突报告→人工兜底排→其余同 V1 发布链。
- **主流程（调停课）**：教师发起调/停/补→选原课次→原因→目标时间/教室→系统冲突检查→学院审→教务审→APPLIED 更新 t_aa_schedule_item（原条目 CHANGED，新条目挂 change_id）→STATUS_CHANGED 通知该课次全体师生。
- **状态要点**：调停课 SUBMITTED → COLLEGE_REVIEW → ACADEMIC_REVIEW → APPROVED → APPLIED / REJECTED / CANCELLED（需求 §3.8 原样）；APPLIED 前可撤销，APPLIED 后反向=再发起一次调课。
- **联动**：调停课 APPLIED→学生课表即时刷新+消息；停课未补→周学时缺口出现在排课完成率报表；考试周禁止调入。
- **确认问题**：是否上自动排课（校方明确不要可长期停留 V1 人工模式）；教师偏好采集口径；调课次数上限。

### 4.2 完整选课（P2）

- **目标**：选修课/重修选课的全流程线上化（建批次→规则→学生选→校验→锁定）。
- **角色**：教务处（批次/规则）、学院（课程容量核定）、学生（小程序选课）、任课教师（名单查看）。
- **主流程**：建批次（时间窗/适用年级专业班级/课程池/容量）→规则配置（先修/时间冲突/学分上限/专业限制/人数上下限）→发布→学生小程序选课（校验链：时间窗内/范围内/未修过/满足先修/课表不冲突/不超学分/不超容量/重修规则）→即时成功或候补→退选（窗内）→低于开班人数课程取消（选课学生改选提醒）→锁定→名单进教学任务/课表/成绩链。
- **状态要点**：批次 DRAFT→PUBLISHED→OPEN→CLOSED→LOCKED；选课记录 SELECTED→CANCELLED（学生退选）/COURSE_CANCELLED（开课取消）→LOCKED。容量并发=数据库原子扣减，超员即 409。
- **联动**：选课结果生成成绩录入名单；重修报名（§4.3）注入选课批次；课表按选课名单渲染个人课表（走班）。
- **确认问题**：职校是否开放学生自主选课（部分学校全部行政班配课）；候补机制要不要；选课学分上限。

### 4.3 完整考务：缓考/补考/重修/免修全流程（P2，状态机完整冻结）

- **目标**：考试批次→考场座位→监考→异常记录闭环，以及缓考/补考/重修/免修四条特殊线。
- **角色**：教务处（批次/裁决）、学院（确认与安排）、任课教师（确认/监考/录入）、辅导员（缓考初审）、学生（申请/应考）。
- **主流程（考务）**：建考试批次（期末/补考/等级）→按教学任务和选课生成考试课程→学院确认→排时间（避让课表与校历考试周）→分考场座位（读教室资源）→排监考（冲突检测）→发布准考名单→学生看考试安排/教师看监考任务→考后登记缺考/违纪/缓考→进成绩链。
- **主流程（缓考）**：学生申请（关联生效请假单或伤病材料）→辅导员初审→任课教师确认→学院审→教务终审→APPROVED 标记原考试 DEFERRED→并入下一补考批次场次→应考→成绩按「缓考按正常计分」规则回写。
- **主流程（补考）**：成绩发布后系统识别 FAILED→生成补考名单（t_acad_makeup 行）→建补考批次（t_aa_makeup_batch）→排场次→学生查看→应考→教师录入补考成绩→按计分规则更新 t_acad_grade（grade_source=MAKEUP，最终成绩标记规则见确认项）→仍不及格→进入可重修池。
- **主流程（重修）**：系统展示可重修课程（补考后仍 FAILED / 缺考违纪失去补考资格）→学生报名（t_acad_retake.apply_status）→教务审→注入重修选课/跟班重修→随课教学与考试→成绩回写（grade_source=RETAKE）→更新学业进度与预警。
- **主流程（免修）**：学生申请（等级证书/已修等效课程材料）→任课教师审→学院审→教务审→APPROVED→写 t_aa_exemption+t_acad_grade 行（pass_status=EXEMPTED 无分数）→学业进度标记。

**状态机（完整冻结版）**：

```
缓考 t_aa_deferred_exam.status：
DRAFT → SUBMITTED → COUNSELOR_REVIEW → TEACHER_CONFIRM → COLLEGE_REVIEW
      → ACADEMIC_REVIEW → APPROVED → SCHEDULED(并入补考场次) → TAKEN → GRADED
   分支：任一审核节点 → RETURNED(回 DRAFT 可改重提) / REJECTED(终态)
   APPROVED 后学生缺考 → ABSENT(按缺考处理，失去本次缓考资格)
   SUBMITTED~ACADEMIC_REVIEW 间学生可 CANCELLED

补考 t_acad_makeup.result_status（受控扩展列）：
ELIGIBLE(识别进名单) → PUBLISHED(批次场次发布) → TAKEN → GRADED
      → PASSED / FAILED_AGAIN(→进入重修池)
   分支：ABSENT(缺考→FAILED_AGAIN 且标记缺考) / EXEMPT_BY_DEFER(缓考并入者标记来源)
   名单勘误：ELIGIBLE → REMOVED(成绩更正后不再需要补考，留痕)

重修 t_acad_retake.apply_status（受控扩展列）：
OPEN(可报名) → APPLIED → ACADEMIC_REVIEW → APPROVED → ENROLLED(入选课/跟班)
      → LEARNING → EXAMED → GRADED → PASSED / FAILED(可再次报名，次数受规则限制)
   分支：ACADEMIC_REVIEW → REJECTED / RETURNED(回 APPLIED 前)；ENROLLED 前可 CANCELLED

免修 t_aa_exemption.status：
DRAFT → SUBMITTED → TEACHER_REVIEW → COLLEGE_REVIEW → ACADEMIC_REVIEW
      → APPROVED(生效写成绩 EXEMPTED) / REJECTED / RETURNED(回 DRAFT)
```

- **联动**：请假→缓考闭环见 §5.3；补考/重修人数进数据中心与学业预警规则（重修过多）；缓考批准后考务名单自动摘除该生并通知监考教师。
- **确认问题**：补考/重修计分规则（按实际分/封顶 60/标注「补」）；重修次数上限与收费；缓考适用情形清单；等级考试是否纳入平台。

### 4.4 成绩录入/审核/发布/更正（P2，状态机完整冻结）

- **目标**：把 V1 的「查看」升级为全流程：任务生成→教师录入→学院审→发布→更正，总评唯一真相仍是 t_acad_grade。
- **角色**：教务处（任务批次/发布）、学院教务员（完整性审核）、任课教师（录入/更正发起）、学生（查询/异议）。
- **主流程**：课程结束（按校历+任务）生成录入任务（t_aa_grade_input_task，绑定教学任务与学生名单）→教师 PC 录入（平时/期末分项+构成比例校验，比例配置在规则中心；支持 Excel 导入 dry-run）→提交→学院审（完整性：全员有分/构成合规/异常分布提示）→教务发布→事务回写 t_acad_grade→PUBLISHED_NOTICE 学生→触发预警扫描→毕业审核可取数。更正：教师发起（原/新成绩+原因≥5字+材料）→学院审→教务审→更新 t_acad_grade（原值留 t_aa_grade_correction，append-only）→通知学生。
- **状态机（完整冻结版）**：

```
成绩录入任务 t_aa_grade_input_task.status：
NOT_STARTED → INPUTTING → SUBMITTED → COLLEGE_REVIEW → ACADEMIC_REVIEW
      → PUBLISHED → ARCHIVED
   分支：COLLEGE_REVIEW/ACADEMIC_REVIEW → RETURNED(回 INPUTTING，已录分数保留)
   PUBLISHED 后唯一修改通道=更正流程：
成绩更正 t_aa_grade_correction.status：
SUBMITTED → COLLEGE_REVIEW → ACADEMIC_REVIEW → APPROVED(生效更新 t_acad_grade)
      / REJECTED / RETURNED(回 SUBMITTED)
   生效后原值/新值/审批链全程 append-only 可追溯；同一成绩行在途更正唯一
```

- **状态-操作要点**：INPUTTING 仅任课教师可录；SUBMITTED 后教师不可改（撤回需学院同意）；PUBLISHED 学生可见；RETURNED 必附行级原因；发布前学生一律不可见任何分数。
- **联动**：发布→预警扫描（§5.2）→挂科→补考名单生成（§4.3）；更正生效→重跑该生相关预警与毕业审核项（增量）。
- **确认问题**：成绩构成模板（平时/期末比例是否全校统一）；发布后更正时限；学生成绩异议入口是否开放。

### 4.5 教学评价（P3）

- **目标**：学生评教/同行互评/督导评价/教师自评/课程问卷与结果统计。
- **角色**：教务处（方案/问卷）、督导（评价）、师生（参评）。
- **主流程**：建评价方案（学期/对象/问卷/权重）→发布→学生小程序匿名评教（选课/授课关系校验）→同行与督导按授权评→截止汇总→结果分级发布（教师本人见明细、学院见汇总）→进教学质量档案。
- **状态要点**：方案 DRAFT→PUBLISHED→OPEN→CLOSED→RESULT_PUBLISHED；评价记录匿名化存储（学生身份单向散列，防反查）。
- **联动**：结果供教师考评（13A 思政队伍/辅导员考评边界外，教学口自用）；低分课程触发督导听课建议。
- **确认问题**：是否强制评教后才能查成绩；结果对教师的公开粒度。

### 4.6 教材管理（P3）

- **目标**：教材目录→课程选用→征订→到货→班级/学生发放→费用与退换台账。
- **角色**：教务处（目录/征订）、学院（选用审核）、任课教师（选用申报）、学生（领用确认）。
- **主流程**：维护教材目录→教师按教学任务申报选用→学院审→教务汇总生成征订单→到货登记→按班级分发→学生领用确认（小程序扫码/签收）→费用记录→退换处理。
- **状态要点**：征订单 DRAFT→CONFIRMED→ORDERED→ARRIVED→ISSUING→SETTLED；发放记录学生级留痕。
- **联动**：教学任务确定后才可申报；费用台账供学校财务对账导出。
- **确认问题**：教材费收缴方式（平台只记台账不做支付）；是否循环教材。

### 4.7 教室资源（P2）

- **目标**：校区/楼宇/教室（含实训室/机房）主数据与可用时间、借用、维修管理，支撑排课与考务。
- **角色**：教务处（主数据）、学院（借用申请）、后勤（维修状态）。
- **主流程**：维护校区→楼宇→教室（容量/类型/设备/可用时间模板）→排课与考务占用自动登记→空闲时段可借用（申请→教务审→占用）→维修停用（占用冲突自动告警联动调课）。
- **状态要点**：教室 ENABLED→MAINTENANCE→DISABLED；借用单 SUBMITTED→APPROVED→USED/CANCELLED。
- **联动**：V1 排课已用教室基础清单即本模块首批数据（§3.8 E24）；维修停用触发受影响课表变更提醒。
- **确认问题**：借用是否开放给学工活动（跨模块占用日历）；实训室设备台账深度。

### 4.8 国家/省平台上报（P3）

- **目标**：按国家学籍/教学状态数据口径生成上报数据集（导出文件为主，接口对接视省平台而定）。
- **角色**：教务处（生成/核对/上报登记）。
- **主流程**：选择上报口径版本→字段映射（平台字段→上报字段字典化配置）→生成数据集→校验（必填/字典值/格式）→差异比对（与上次上报）→导出（水印+t_export_task 登记）→上报结果回填登记。
- **状态要点**：上报批次 DRAFT→VALIDATED→EXPORTED→REPORTED→CONFIRMED；数据集只读快照。
- **联动**：学籍/异动/毕业数据为主要来源；口径差异（如学籍状态枚举映射）字典表维护。
- **确认问题**：对接哪个省平台、是否有接口规范文档；上报频率；是否需要对接已有教务系统做历史数据迁移。

### 5.1 联动总览

### 5.2 闭环一：成绩 → 学业预警 → 学工处置

1. 成绩发布（§4.4；V1 期为存量 t_acad_grade 变更）事务提交后发领域事件 `GRADE_PUBLISHED(term, course, studentIds)`。
2. 预警扫描服务消费事件（V1 无事件总线则同步调用扫描函数+每日兜底定时）：按 ENABLED 规则命中（挂科门数/绩点/学分缺口）。
3. 写 t_acad_warning（幂等键防重复），t_unified_todo 分派辅导员、抄送学院教务员，RISK_ALERT 消息。
4. 辅导员工作台（13A-02）风险学生列表出现该生；处置动作复用既有 warnings API；需要时创建谈心谈话（13A-10）、家校联系（13A-13），关联 warning_id。
5. 关闭→StageEvent→360 时间线完整呈现「挂科→预警→谈话→关闭」链；数据中心「预警处置及时率」更新。
- **验收锚点**：同一学生同学期同规则重复扫描仅 1 条记录；预警关闭后成绩更正翻案→生成 DATA_CORRECTED 关闭的对冲记录，不静默删除。

### 5.3 闭环二：请假 → 缓考

1. 学生存在覆盖考试时间的 APPROVED 请假单（13A t_cs_leave 扩展体系）。
2. 学生小程序「我的考试」中该场次出现「申请缓考」入口（前置校验：请假时段覆盖考试时间，或另传伤病材料）。
3. 缓考单（§4.3 状态机）携带 leave_ref_id 只读引用请假单快照（请假被撤销→缓考单自动挂起提醒人工复核）。
4. APPROVED→原考试名单标 DEFERRED、监考教师收到名单变更 STATUS_CHANGED→并入下一补考批次场次→成绩按正常计分回写。
- **验收锚点**：无有效请假且无材料→422001 拒绝发起；缓考批准后学生仍参加原考试→成绩以原考试为准并关闭缓考单（人工裁定留痕）。

### 5.4 闭环三：毕业资格审核取数矩阵（各模块供数字段）

| 审核项 | 供数模块 | 取数表/字段（只读） | 判定规则 | 异常时责任方 |
|---|---|---|---|---|
| 学籍正常 | 学生中心/教务 | t_student_profile.student_status | ∈{REGISTERED,ACTIVE}（应届口径） | 教务处（异动核查） |
| 方案学分达标 | 教务 | t_acad_grade（PASSED/EXEMPTED 行）× t_aa_program_requirement | Σ学分 ≥ 各模块最低+总学分 | 学院教务员 |
| 必修全通过 | 教务 | t_acad_grade × t_aa_program_course(性质=必修) | 无 FAILED 且无缺行 | 学院教务员 |
| 选修学分达标 | 教务 | 同上（性质=选修） | Σ选修学分 ≥ 要求 | 学院教务员 |
| 实习完成 | 岗位实习 | t_internship_record.status、周报完成度、评价结论 | 实习记录终态=完成且评价通过 | 实习指导教师 |
| 毕设通过 | 毕业设计 | t_gd_student（终稿/答辩结果）、t_gd_defense_group 结论 | 答辩结论=通过 | 毕设指导教师 |
| 无未解除严重处分 | 学工(13A) | t_cs_discipline（13A 扩展后含 severity/remove_status） | 不存在 severity≥严重 且未 REMOVED 的生效处分 | 学院学工 |
| 费用材料满足 | 迎新/财务台账 | t_orientation_payment_status + 学校财务确认标记 | 无欠费标记（或校方关闭该项） | 财务/迎新 |

矩阵约定：毕业审核**只读不写**上游表；每项取数结果连同证据快照（关键字段 JSONB）写入 t_aa_graduation_audit_item，上游后续变更不影响已锁定结论（重跑刷新）；每项可配置「硬条件/软条件/停用」，默认值按上表，开关权归学校（§3.11 E28）。

### 5.5 闭环四：处分 → 毕业资格（含解除时序）

处分生效（13A）即写 360；毕业预审跑批时点读取「最新状态」：审批中的解除申请不算已解除（PENDING 不放行，提示「解除审批中」，学院可等待终审后单人重跑）。处分在毕业终审后才解除的→走结业换毕业补办规则（E28 确认项），平台支持 DELAYED/COMPLETED 单据基础上的补审单。

### 5.6 学籍异动 → 全域资格拦截（L5 实施细则）

## 第 6 章 风险与冲突说明

### R-1 API 路径冲突：/api/v1/academic/* 已被学业过程域占用（**已解决**）

既有 academic 域已占 `/api/v1/academic/` 下 students/grades/warnings 等路径。**本册最终决策（已冻结）**：13B 教务中心全部新建端点挂 `/api/v1/academic-affairs/*`，与既有学业过程 API **物理隔离**；`grades`/`warnings`/`students` **读与处置复用**既有 `/api/v1/academic/*` 端点（加范围参数，不改响应结构）。冲突项 R-1 在 P1 契约冻结时关闭。

### R-2 文档基线与代码基线的响应格式冲突（中，已裁定）

API 契约总册（docs/api/00）定义 `code` 为字符串业务码，而集成速查（以代码为准）明示现实现为 `{code(数字), bizCode(字符串)}`。本册**以代码事实为准**（数字 code + bizCode），13B 全部接口按现实现格式设计；建议后续修订 API 总册与代码对齐，避免下游文档继续引用旧格式。

### R-3 学籍状态双字段的语义重叠（中）

current_stage（生命周期）与 student_status（学籍）并存，SUSPENDED（休学）期间 current_stage 停留原值可能产生「实习阶段+休学」组合。裁定：**student_status 优先级高于 current_stage**，各模块资格拦截一律看 student_status；组合合法但 UI 需明示；恢复（RESUMED→REGISTERED）不回改 stage 历史。需在 P2 阶段与学生中心模块联测。

### R-4 t_acad_grade 的 course/term 为字符串弱键（中）

存量成绩以字符串课程名/学期存储，毕业审核按方案课程逐项比对需要 course_id 强关联。裁定：新写入双落 course_id+course_code；存量行在毕业审核首批跑批前做一次「课程映射盘点」（人工确认映射表，未映射行审核项记 PENDING 而非 FAIL），不强制回刷存量数据。

### R-5 补考/重修表为「骨架」，字段容量未知（中）

t_acad_makeup/t_acad_retake 现为骨架表，本册按受控加列设计，但若现表存在与新状态机冲突的存量状态值，需在 P1 盘点后给出兼容映射（老值→新枚举），迁移脚本必须可回滚。

### R-6 学业预警单表双模块的写冲突（低）

教务扫描写入与学工/既有移动端处置并发操作同一 t_acad_warning 行：以既有 version 乐观锁为准，扫描只 INSERT 不 UPDATE 既有行，规避写冲突；关闭动作唯一归处置方。

### R-7 毕业审核对上游数据质量的强依赖（高，非技术）

实习/毕设/就业/处分数据不全或口径不一将导致大面积 SYSTEM_ABNORMAL 误报。对策：每项独立 PASS/FAIL/PENDING 三值结论（数据缺失≠不合格）、证据快照留证、单人重跑、人工改判强审计；上线首批建议先跑「影子批次」只出报告不出结论。

### R-8 与既有教务系统的共存问题（高，商务+技术）

需求 §9 明示需现场确认「是否对接已有教务系统」。若学校已有排课/成绩系统，本册排课与成绩录入链路可能降级为「只读同步+查看」，此时 V1 的课表/成绩查看设计天然兼容（读视图不依赖录入链路），但学籍与毕业审核仍建议以本平台为准系统。该决策直接影响 P2 范围，必须在 P1 前拍板。

### R-9 演示/沙箱租户的教务数据种子（低）

demo-school 只读锁与 sandbox-school 每晚重置对 13B 同样生效；教务中心上线需补充演示种子（学期/校历/方案/课表/成绩），纳入 reset 脚本，否则演示首页全空态。

### R-10 需求文档中表名前缀不一致（低，已裁定）

需求 §3.7 写作 `academic_schedule_batch` 等无 t_ 前缀；本册统一按 DB 冻结总册规范落为 `t_aa_schedule_*`，以本册为准。
