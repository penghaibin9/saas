## 4. 21 个二级目录按 A/B/C/D 开发顺序拆包

> 这是 13A 学工中心的主口径：21 个二级目录模块不是散着做，也不是拆成 A-J 小包做，而是先分入 A/B/C/D 四个大任务包，再严格按 A -> B -> C -> D 顺序开发和验收。

| 顺序 | 任务包 | 二级目录模块 | 本包开发结论 |
|---|---|---|---|
| 1 | A 施工地图 + 底座欠账冻结 | 覆盖全部 21 个二级目录的目录规划、边界、现有系统串联、欠账冻结 | A 包不做业务代码，先把“哪些模块归哪个包、哪些现有系统只串联、哪些底座欠账后补”说清楚 |
| 2 | B 学工 PC 高频主线 | 学工看板、学生画像、班级管理、宿舍管理、请假销假、风险预警 | B 包先做高频主链路，是 PC 试运行的第一批业务页面 |
| 3 | C 审批业务闭环 | 困难认定、奖助勤贷补、违纪处分、谈心谈话、家校联系 | C 包在 B 的画像、权限、待办、风险基础上补审批/沟通/台账闭环 |
| 4 | D 上线补强与商业增强 | 数字迎新、心理健康、学生活动、第二课堂、社团与学生组织、党团建设、辅导员考评、学工归档、学工统计、在校服务 | D 包做正式上线补强和商业化增强；数字迎新只补公共日期/Excel/导出底座与学工入口串联，不在学工内重做迎新 |

### 4.4 开发顺序红线

1. 任何后续开发都必须先说明自己属于 A/B/C/D 哪个任务包。
2. B 包未验收前，不启动 C 包业务开发。
3. C 包未验收前，不启动 D 包商业增强开发；D 包中的心理健康、归档、统计可作为正式上线专项提前设计，但不混入 B 包提交。
4. 数字迎新属于 D 包专项，只做现有系统串联和公共底座补强，不进入 B 包开发。
5. 在校服务属于 D 包承接口径，未完整实现前只能写“入口/摘要/跳转/待补”，不得写成学工中心已完成。

## 6. 角色权限矩阵

| 角色 | 可见范围 | 可做动作 | 禁止事项 |
|---|---|---|---|
| 学生 | 本人数据、本人申请、本人公开通知 | 申请请假/资助/活动，查看本人进度，提交销假/回执 | 不得访问管理端、他人画像、审批台账 |
| 辅导员 | 所绑定班级/学生 | 查看画像、处理请假/风险/谈话/家校、维护班级干部 | 不得看非绑定学生敏感详情 |
| 班主任 | 所带班级 | 查看班级学生、协同请假/风险/谈话 | 不得越过班级访问全院数据 |
| 宿管员 | 被授权楼栋/房间/床位 | 入住、调宿、检查、夜不归宿登记 | 不得查看资助/心理/处分敏感详情 |
| 心理老师 | 被授权学生或心理业务范围 | 预约、危机、转介、随访、结案 | 不得导出敏感明细；不得给出诊断结论 |
| 资助老师 | 被授权学院/项目/资助范围 | 困难认定、奖助勤贷补评审、台账 | 不得查看无关心理/处分详情 |
| 学院负责人 | 本学院 | 审批、查看学院汇总、督办 | 不得跨学院明细 |
| 学工处 | 全校学工范围 | 规则配置、终审、全校统计、督办 | 不得绕过敏感授权查看心理详情 |
| 校领导 | 全校汇总与经授权明细 | 查看驾驶舱、趋势、重点风险摘要 | 默认不看个人敏感原文 |
| 系统管理员 | 租户内系统配置 | 角色权限、租户内配置 | 不因管理员身份自动获得业务敏感明细 |
| 租户管理员 | 本租户 | 租户配置、账号授权 | 严禁跨租户访问 |

硬规则：前端隐藏不等于后端授权；所有详情接口必须二次校验数据范围；超范围返回 403；导出按当前数据范围裁剪；任何跨租户数据访问均返回 403/404 且写安全审计。

## 8. API 契约总原则

统一前缀：`/api/v1/student-affairs`。统一错误：`{ code, bizCode, message, data, traceId, timestamp }`。每个核心模块必须具备：列表、详情、新建、编辑、状态流转/审批、导入模板、导入校验、错误行导出、正式导入、导出、统计、审计查询。

| 能力 | 方法与路径模板 | 入参 | 出参 | 权限/数据范围 | 审计与测试 |
|---|---|---|---|---|---|
| 列表 | `GET /{module}` | page, pageSize, keyword, status, orgId, dateStart, dateEnd | items, total, summary | 后端按角色裁剪 | 测无登录 401、越权 403、空列表 |
| 详情 | `GET /{module}/{id}` | id | detail, permissions, auditSummary | 详情二次范围校验 | 查看敏感字段另写审计 |
| 新建 | `POST /{module}` | body + idempotencyKey | id, status | 校验可创建范围 | 写创建审计，测重复提交 |
| 编辑 | `PUT /{module}/{id}` | body, version | detail | 乐观锁/状态限制 | 写变更差异 |
| 审批/状态 | `POST /{module}/{id}/actions/{action}` | action, comment, files, version | newStatus, workflowTask | 审批人必须来自流程任务 | 写流程审计，测非法流转 |
| 导入模板 | `GET /{module}/import-template` | scene | xlsx file | 按权限生成字段 | 写下载审计 |
| 导入校验 | `POST /{module}/imports/validate` | xlsx | jobId, validRows, invalidRows | 行级范围裁剪 | 只校验不落库 |
| 错误行导出 | `GET /imports/{jobId}/error-rows` | jobId | xlsx | 只能下载本人 job | 写导出审计 |
| 正式导入 | `POST /imports/{jobId}/confirm` | confirmToken | affectedRows | 再校验权限 | 写导入审计 |
| 导出 | `POST /{module}/exports` | filters, columns, reason | exportJobId | 数据范围裁剪、敏感脱敏 | 确认弹窗、台账、水印 |
| 统计 | `GET /{module}/stats` | orgId, date range | metrics | 汇总级授权 | 测时间范围和空态 |
| 审计 | `GET /{module}/{id}/audits` | id | audit list | 仅有权人员 | 审计查询也审计 |
