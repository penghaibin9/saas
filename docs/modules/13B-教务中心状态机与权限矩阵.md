## 0. 通用约定（适用于本文件全部状态机）

### 0.1 矩阵列定义

| 列 | 含义 |
|---|---|
| 当前状态 | 业务单据/对象当前所处状态（枚举严格采用需求输入 §3） |
| 可执行操作 | 该状态下允许发生的动作（按钮/接口/定时任务） |
| 执行角色 | 谁可以做（教务处=教务处管理员；学院=学院教务员；负责人=专业负责人；教师=任课教师；督导=教学督导；学生=本人；系统=定时任务/联动触发） |
| 目标状态 | 操作成功后的状态 |
| Workflow | 是否落 `t_workflow_instance/t_workflow_task`（✓=新增 workflow_code 复用现有审批底座；✗=业务状态直迁+审计） |
| 通知 | 是否写 `t_unified_todo`/`t_unified_message`（统一消息类型：WORKFLOW_TODO/WORKFLOW_RESULT/RISK_ALERT/DEADLINE_REMINDER/STATUS_CHANGED/RETURNED_NOTICE/PUBLISHED_NOTICE/ARCHIVE_NOTICE，禁止自建消息表） |
| 审计 | 是否调 `audit_log.record()` 落 `t_security_audit_log`（域级另落 `t_aa_audit_trail`，append-only） |
| 360 | 是否写 `t_student_stage_event` / 域记录被学生360聚合读取 |

### 0.2 通用非法转移防护（每个状态机默认生效，不再逐条重复）

| 场景 | HTTP / bizCode | 说明 |
|---|---|---|
| 目标状态不在当前状态出边集合 | 409 / DATA_CONFLICT | 服务端以状态机表为唯一裁定，前端按钮隐藏不作为防线 |
| 审批任务已被处理再次提交审批 | 409 / APPROVAL_VERSION_CONFLICT | version 乐观锁，复用 Workflow 既有行为 |
| 重复提交（同 request_id / 同业务幂等键） | 409 / IDEMPOTENCY_CONFLICT | 写操作一律带 request_id |
| 角色无该权限点 | 403 / NO_PERMISSION | details.required 返回权限点码 |
| 有权限点但对象不在数据范围内 | 403 / NO_DATA_SCOPE | 越权访问同时写审计（result=DENIED） |
| 对象不存在或跨租户 | 404 / DATA_NOT_FOUND | 跨租户按不存在处理，不暴露存在性 |
| 字段校验失败（枚举/长度/日期序） | 422 / VALIDATION_ERROR | 行级错误结构 |
| 驳回/退回未填原因（≥5 字） | 422 / VALIDATION_ERROR | 全局规则 |
| demo-school 租户写操作 | 403 / NO_PERMISSION | 只读锁中间件，引导 sandbox |

## 1. SM-01 学年学期与校历（DRAFT / PUBLISHED / FROZEN / ARCHIVED）

校历对象含：学年、学期、教学周、考试周、实习周、节假日、调休、作息节次。学期与其校历共用一个状态机（校历随学期状态走）。

| 当前状态 | 可执行操作 | 执行角色 | 目标状态 | Workflow | 通知 | 审计 | 360 |
|---|---|---|---|---|---|---|---|
| DRAFT | 编辑学期起止/教学周/考试周/节假日/调休/作息节次 | 教务处 | DRAFT | ✗ | ✗ | ✓ | ✗ |
| DRAFT | 删除（未被任何业务引用） | 教务处 | —（物理软删） | ✗ | ✗ | ✓ | ✗ |
| DRAFT | 发布（完整性校验：起止连续、教学周无空洞、节次已配） | 教务处 | PUBLISHED | ✗ | ✓ PUBLISHED_NOTICE（全体教职工待办面板 + 学生端校历同步） | ✓ | ✗ |
| PUBLISHED | 有限修正（仅节假日/调休/作息微调，记录变更差异） | 教务处 | PUBLISHED | ✗ | ✓ STATUS_CHANGED（受影响课表的教师/学生） | ✓ | ✗ |
| PUBLISHED | 冻结（排课/选课/考试任一批次进入进行中后建议冻结） | 教务处 | FROZEN | ✗ | ✗ | ✓ | ✗ |
| FROZEN | 解冻（原因≥5 字） | 教务处 | PUBLISHED | ✗ | ✗ | ✓ | ✗ |
| FROZEN | 归档（学期结束且成绩/考试批次均 ARCHIVED） | 教务处 | ARCHIVED | ✗ | ✓ ARCHIVE_NOTICE（教务处/学院） | ✓ | ✗ |
| ARCHIVED | 只读查看/导出（水印） | 教务处/学院/督导 | ARCHIVED | ✗ | ✗ | ✓（导出留痕 t_export_task） | ✗ |

**专属非法转移防护**
- DRAFT→FROZEN、DRAFT→ARCHIVED、ARCHIVED→任意：409 DATA_CONFLICT。
- PUBLISHED 修改教学周结构（非微调字段）：409，提示“已发布学期结构性调整须走冻结-解冻或新学期”。
- 存在 PUBLISHED 排课批次时修改作息节次：409（先处理批次）。
- 同学年同名学期重复创建：409 IDEMPOTENCY_CONFLICT。

**定时任务触发点**
- 新学期开学前 30/7 天仍无 PUBLISHED 学期：给教务处发 DEADLINE_REMINDER。
- 学期结束日 +7 天自动提示冻结；成绩域全部 ARCHIVED 后提示归档。

## 2. SM-02 学籍状态（14 态，t_student_profile.student_status 受控扩展）

| 当前状态 | 可执行操作 | 执行角色 | 目标状态 | Workflow | 通知 | 审计 | 360 |
|---|---|---|---|---|---|---|---|
| PENDING_REGISTER | 入学注册确认（学院核身份/专业/班级 + 系统校验报到/缴费/材料 → 名单 → 教务处审核通过） | 学院发起 / 教务处终审 | REGISTERED（并置 ACTIVE 在籍标志） | ✓（注册批次审核 workflow_code=AC_ENROLL_REVIEW） | ✓ STATUS_CHANGED（学生）+ 同步学工/教务/实习/毕设/就业 | ✓ | ✓ |
| PENDING_REGISTER | 注册截止仍未完成（定时扫描） | 系统 | UNREGISTERED | ✗ | ✓ RISK_ALERT（辅导员+学院教务员）+ 生成学业预警（来源 UNREGISTERED） | ✓ | ✓ |
| UNREGISTERED | 补注册（材料补齐后重走确认） | 学院/教务处 | REGISTERED | ✓（同上） | ✓ STATUS_CHANGED | ✓ | ✓ |
| ACTIVE | 学年注册（每学年批次，校验缴费/上学年状态） | 学院发起 / 教务处审核 | REGISTERED | ✓ | ✓ STATUS_CHANGED | ✓ | ✓ |

| SUSPENDED | 休学期间禁选课/考试/实习/毕设（拦截，非迁移） | 系统 | SUSPENDED | ✗ | 按需 403 提示 | ✓（越权尝试） | ✗ |

**专属非法转移防护**
- 任何 PC 端直接 PUT student_status：403 NO_PERMISSION（只允许四类受控入口）。
- SUSPENDED 学生发起选课/缓考外的考试报名/实习/毕设：403 + 明确文案“休学期间不可办理”。
- GRADUATED/COMPLETED/INCOMPLETE/WITHDRAWN → 除 ARCHIVED 外任何迁移：409。
- 注册确认对非 PENDING_REGISTER/ACTIVE/RESUMED/RETAINED/TRANSFER_MAJOR 学生：409。

**定时任务触发点**
- 注册截止日 24:00 扫描未注册 → UNREGISTERED + 学业预警（SM-13 来源 UNREGISTERED）。
- 休学到期前 30/7 天：DEADLINE_REMINDER 提醒学生/辅导员发起复学。
- 休学到期 +30 天未复学：RISK_ALERT 升级学院教务员，建议启动退学流程（人工确认，不自动退学）。

## 3. SM-03 学籍异动单（转专业 / 休学 / 复学 / 退学）

一张异动单表 `t_aa_status_change`，`change_type` = TRANSFER_MAJOR / SUSPEND / RESUME / WITHDRAW（TRANSFER_SCHOOL 预留 P2）。状态全集 11 个，各类型走各自节点序列；审批全部复用 Workflow（每类型一个 workflow_code：AC_SC_TRANSFER / AC_SC_SUSPEND / AC_SC_RESUME / AC_SC_WITHDRAW）。

状态全集：DRAFT / SUBMITTED / COUNSELOR_REVIEW / OUT_COLLEGE_REVIEW / IN_COLLEGE_REVIEW / COLLEGE_REVIEW / ACADEMIC_REVIEW / APPROVED / REJECTED / RETURNED / CANCELLED

各类型节点序列：
- 转专业：SUBMITTED → COUNSELOR_REVIEW → OUT_COLLEGE_REVIEW（原学院转出）→ IN_COLLEGE_REVIEW（目标学院接收）→ ACADEMIC_REVIEW → APPROVED
- 休学：SUBMITTED → COUNSELOR_REVIEW → COLLEGE_REVIEW → ACADEMIC_REVIEW → APPROVED
- 复学：SUBMITTED → COUNSELOR_REVIEW → COLLEGE_REVIEW（学院定班）→ ACADEMIC_REVIEW → APPROVED
- 退学：SUBMITTED → COUNSELOR_REVIEW → COLLEGE_REVIEW → ACADEMIC_REVIEW → APPROVED

| 当前状态 | 可执行操作 | 执行角色 | 目标状态 | Workflow | 通知 | 审计 | 360 |
|---|---|---|---|---|---|---|---|
| DRAFT | 编辑/删除草稿（原因/材料 file_id/目标专业等） | 学生（移动端）；退学可由学院代发起 | DRAFT | ✗ | ✗ | ✓ | ✗ |
| DRAFT | 提交（校验：本人+在籍态合法+窗口期内+成绩条件（转专业）+材料齐+无在途同类异动） | 学生 | SUBMITTED→自动进首节点 | ✓ 建实例 | ✓ WORKFLOW_TODO（首节点审批人） | ✓ | ✗ |
| COUNSELOR_REVIEW | 初审通过 / 驳回 / 退回补材料 | 辅导员（学工角色作为教务流程节点审批人） | 下一节点 / REJECTED / RETURNED | ✓ | ✓ WORKFLOW_TODO（下节点）或 RETURNED_NOTICE（学生） | ✓ | ✗ |
| OUT_COLLEGE_REVIEW | 转出审核（学籍/学分/欠费核查） | 原学院教务员 | IN_COLLEGE_REVIEW / REJECTED / RETURNED | ✓ | ✓ | ✓ | ✗ |
| IN_COLLEGE_REVIEW | 接收审核（容量/面试/成绩门槛） | 目标学院教务员 | ACADEMIC_REVIEW / REJECTED / RETURNED | ✓ | ✓ | ✓ | ✗ |
| COLLEGE_REVIEW | 学院审核（休学/复学/退学；复学时指定编入班级） | 学院教务员 | ACADEMIC_REVIEW / REJECTED / RETURNED | ✓ | ✓ | ✓ | ✗ |
| ACADEMIC_REVIEW | 终审通过（触发学籍状态联动 SM-02：更新 student_status/专业/班级/培养方案绑定） | 教务处 | APPROVED | ✓ | ✓ WORKFLOW_RESULT + STATUS_CHANGED（学生/辅导员/原目标学院） | ✓ | ✓（StageEvent + 异动记录） |
| ACADEMIC_REVIEW | 终审驳回 | 教务处 | REJECTED | ✓ | ✓ WORKFLOW_RESULT（学生） | ✓ | ✗ |
| RETURNED | 补充材料后重新提交（回到被退回节点的上一提交点：重走 SUBMITTED 全链） | 学生 | SUBMITTED | ✓ 新审批轮次 | ✓ | ✓ | ✗ |
| SUBMITTED～ACADEMIC_REVIEW（任一在途） | 撤销申请（终审前） | 学生 | CANCELLED | ✓ 终止实例 | ✓ WORKFLOW_RESULT（已收待办的审批人） | ✓ | ✗ |
| APPROVED / REJECTED / CANCELLED | 只读查看/导出（异动原因脱敏，见 §16） | 按数据范围 | 不变 | ✗ | ✗ | ✓（看完整原因须审计） | APPROVED 已进 |

**专属非法转移防护**
- 非 SUSPENDED 学生提交复学：409 DATA_CONFLICT（文案“当前学籍状态不可申请复学”）。
- 在途异动未结再提同类/互斥异动（休学 vs 转专业并行）：409 IDEMPOTENCY_CONFLICT。
- 转专业窗口期外提交：422 VALIDATION_ERROR（窗口期由平台规则中心配置）。
- 审批人操作不属于自己学院的单据：403 NO_DATA_SCOPE + 审计。
- APPROVED 后尝试撤销：409（已生效，如需纠正走新异动或数据订正流程）。

**定时任务触发点**
- 休学 APPROVED 且到达休学起始日：执行 SM-02 置 SUSPENDED（生效日驱动，非审批即时生效）。
- 休学到期提醒复学（见 SM-02）。
- 转专业批次窗口开/关：自动开放与截止入口。

## 4. SM-04 培养方案（8 态，版本化）

DRAFT / COLLEGE_REVIEW / ACADEMIC_REVIEW / RETURNED / PUBLISHED / ENABLED / FROZEN / DISABLED；workflow_code=AC_PROGRAM_REVIEW。

| 当前状态 | 可执行操作 | 执行角色 | 目标状态 | Workflow | 通知 | 审计 | 360 |
|---|---|---|---|---|---|---|---|
| DRAFT | 编制/编辑（课程模块/学分学时/开课学期/性质/毕业要求；课程必须来自课程库 ENABLED） | 专业负责人 | DRAFT | ✗ | ✗ | ✓ | ✗ |
| DRAFT | 提交学院审（校验：课程不重复/总学分达标/开课学期合法/毕业要求完整） | 专业负责人 | COLLEGE_REVIEW | ✓ | ✓ WORKFLOW_TODO（学院教务员） | ✓ | ✗ |
| COLLEGE_REVIEW | 通过 / 退回（原因≥5 字） | 学院教务员 | ACADEMIC_REVIEW / RETURNED | ✓ | ✓ | ✓ | ✗ |
| ACADEMIC_REVIEW | 通过发布 / 退回 | 教务处 | PUBLISHED / RETURNED | ✓ | ✓ PUBLISHED_NOTICE（学院/专业）或 RETURNED_NOTICE | ✓ | ✗ |
| RETURNED | 修改后重新提交 | 专业负责人 | COLLEGE_REVIEW | ✓ 新轮次 | ✓ | ✓ | ✗ |
| PUBLISHED | 启用并绑定专业+年级（生成学生-方案绑定关系） | 教务处 | ENABLED | ✗ | ✓ STATUS_CHANGED（学院/负责人）；学生绑定进 360 | ✓ | ✓（绑定关系） |
| ENABLED | **修改 → 强制新版本**（复制为 version+1 的新 DRAFT；旧版本保持 ENABLED 服务历史学生） | 专业负责人 | 新记录 DRAFT | ✗ | ✗ | ✓ | ✗ |
| ENABLED | 冻结（暂停被教学任务/选课引用） | 教务处 | FROZEN | ✗ | ✓ STATUS_CHANGED | ✓ | ✗ |
| ENABLED | 停用（不再招收绑定；历史学生仍按其版本审核毕业） | 教务处 | DISABLED | ✗ | ✓ | ✓ | ✗ |
| FROZEN | 解冻 | 教务处 | ENABLED | ✗ | ✗ | ✓ | ✗ |
| DISABLED | 只读/导出（终态） | 按范围 | DISABLED | ✗ | ✗ | ✓ | ✗ |

**版本规则（冻结）**
1. 版本键 =（专业, 入学年级, version）；同键 ENABLED 唯一。
2. ENABLED 后一切内容修改必须新版本；新版本 ENABLED 时旧版本对**新绑定**停用，**已绑定学生不迁移**（历史学生用旧版本，毕业审核按学生绑定版本取数）。

## 17. 与 t_teacher_student_scope 机制的映射（速查 §5，封装不另起炉灶）

### 17.1 新增 scope_type 建议

| scope_type | ref_value | 赋予对象 | 语义 |
|---|---|---|---|
| CLASS / COLLEGE / STUDENT / ADVISOR | （既有，不动） | 既有教师角色 | 既有四路判定保持 |
| **COURSE**（新增） | `term_code:course_code:class_no`（教学班键） | 任课教师 | 教学任务 READY 时由系统自动写入/回收，教师对该教学班学生可见可办（名单/成绩/调停课/缓考确认） |
| **MAJOR**（新增） | `major_code` | 专业负责人 | 本专业方案/课程/任务确认与专业维度只读 |
| **SUPERVISE**（新增） | `college_code` 或 `term_code:course_code` | 教学督导 | 授权学院/课程的只读听课与质量视图 |

### 17.2 统一函数封装

- `getAcademicScope(user)` = `resolve_teacher_scope(user)` 的教务封装：教务处管理员 → mode=ADMIN_TENANT（全校）；学院教务员 → COLLEGE；专业负责人 → MAJOR；任课教师 → COURSE(+既有 CLASS/ADVISOR 叠加)；督导 → SUPERVISE；学生 → SELF（token.studentNo）。
- `canAccessAcademicStudent(user, studentId)` = `can_teacher_view_student` 增补 COURSE/MAJOR/SUPERVISE 三路判定（学号→教学班名单→专业→授权范围），越权 403 + 审计。
- `filterAcademicRecordsByScope(query, user)`：列表过滤与写操作校验共用同一 scope（“看得见=能处理”原则，速查 §5）。
- `assertCanApproveWorkflow(user, task)`：审批节点执行前校验节点角色 + 数据范围双条件，失败 403 NO_DATA_SCOPE。
- 写入时机：COURSE 行随教学任务 READY 自动生成、随学期 ARCHIVED 自动置 status=INACTIVE；MAJOR/SUPERVISE 行由教务处在 PC 端维护（每次变更审计）。
