# 13B 教务中心表单字段与校验规则

> 版本：V1.1 字段级设计 · 依据《_13-需求输入-V1.1.md》§3/§11、《_13-现有系统集成事实速查.md》、《13B-教务中心页面树与路由设计.md》
> 范围：教务中心 16 个核心表单的逐字段设计与校验规则；PC 路由前缀统一省略 `/admin/academic-affairs`。
> 约定：本文档不写代码；错误码/响应结构与事实速查 §1 冻结口径完全一致（422001 VALIDATION_ERROR、409001 DATA_CONFLICT 系列、403/404 等业务错误绝不 500）。

## 一、统一校验约定（后文各表单直接引用，不再重复展开）

> 引用方式：表单章节中以「约定 G1」「约定 G5」等编号引用本章条目。

### G0 通用提交行为约定（全部表单默认生效）

| 项 | 规则 |
|---|---|
| 身份来源 | 学生端 student_id 一律从 token 取（claims 附 studentNo），教师端 userId=db-<id>；前端传入的身份字段一律忽略 |
| 租户来源 | tenant_id 从登录上下文取，不接受前端传入；跨租户数据引用 → 404001 |
| 端侧隔离 | PC 表单仅教职工（require_staff，学生令牌 403001）；学生新建教务表单走 `/api/v1/mobile/academic-affairs/*`；复用既有 `/api/v1/mobile/academic/my/grades|warnings`（学业过程） |
| 演示环境 | demo-school 租户全局只读锁：全部写提交 → 403，提示引导使用 sandbox-school 沙箱（每晚 0 点重置） |
| 必填判定 | 去首尾空格后为空、空数组、全空格 均视为未填 → 422001 rule=`required` |
| 提交审计 | 创建/修改/审批类提交统一走 audit_log.record（含 ip/ua/traceId）；敏感字段查看另行审计 |
| 敏感字段 | 身份证/联系方式等 `*_encrypted` 存储，表单回显一律脱敏（`_mask_phone`/`_mask_id_card`）；表单不提供明文回显入口 |
| 附件上传 | 先传后提交：附件单独上传拿 fileId，表单提交携带 fileId 列表；提交时后端复核格式/大小/数量（G6） |

### G1 学分范围约定

| 项 | 规则 | 说明 |
|---|---|---|
| 单课程学分 | 0.5 ~ 12，步长 0.5 | 超范围或非 0.5 倍数 → 422001 |
| 方案总学分下限 | 默认 ≥120，可配置 | 配置项 `program.minTotalCredits` 接平台规则中心（safe_rule），学校现场可调 |
| 方案模块学分 | 各模块学分之和 = 方案总学分 | 保存/提交审核时校验，偏差即 422001 |
| 学时换算 | 1 学分对应学时数可配置（默认 16） | 配置项 `course.hoursPerCredit`，仅提示不强卡（现场确认后可改为强校验） |

### G2 时间合法性约定

| 项 | 规则 |
|---|---|
| 起止顺序 | 一切「开始/结束」成对字段：开始 < 结束（日期相等时按时间比较；纯日期字段允许开始 = 结束的单日场景须逐表单显式声明） |
| 学期嵌套校历 | 教学周、考试周、节假日、调休、实习周的日期必须全部落在所属学期起止日期之内 |
| 教学周/考试周 | 二者周次区间不得重叠；考试周默认位于教学周之后（可配置 `term.examAfterTeaching`） |
| 节次递增 | 同一作息方案内节次号严格递增；第 N 节结束时间 ≤ 第 N+1 节开始时间，任何两节时间段不重叠 |
| 异动生效日期 | 学籍异动（转专业/休学/复学等）生效日期不得早于申请日期 |
| 学期不重叠 | 同校区/同租户下任意两个学期的起止日期区间不得重叠（跨学年顺延允许首尾相接） |

### G3 成绩约定

| 项 | 规则 |
|---|---|
| 分数格式 | 0 ~ 100，整数或一位小数（如 85、85.5）；两位小数、负数、>100 → 422001 |
| 总评构成 | 总评 = Σ(单项成绩 × 权重)；构成各项权重（平时 % + 期末 % 等）合计必须 = 100%，否则 422001 |
| 单项权重 | 0 ~ 100，步长 5；默认构成「平时 40% + 期末 60%」可配置（`grade.compositionPreset`，接平台规则中心） |
| 等级制映射 | 优 ≥90 / 良 80-89 / 中 70-79 / 及格 60-69 / 不及格 <60；等级制课程录等级、系统按映射存折算分（映射表可配置 `grade.levelMapping`） |
| 特殊标记互斥 | 缺考/违纪/缓考标记与分数互斥：打标记后各项分数必须置空；已有分数时打标记须先清分（前端自动清空+二次确认） |
| 缓考/补考计分 | 缓考按实考成绩计；补考及格按 60 记（可配置 `grade.makeupCapScore`）。计分口径属需求 §9 现场确认项，本约定为默认值 |
| 绩点换算 | 绩点 =（总评-50）/10，<60 记 0（可配置 `grade.gpaFormula`）；转专业快照、学业预警、毕业预审统一引用同一口径 |

### G4 版本规则（乐观锁与业务版本双轨）

| 项 | 规则 |
|---|---|
| 业务版本 vX.Y | 培养方案/课程 `ENABLED 已启用`（课程）或 `PUBLISHED 已发布/ENABLED 已启用`（方案）后禁止原地修改，任何变更必须另存新版本（主版本 X 结构性变更 +1，微调 Y+1），旧版本转 `FROZEN 冻结` |
| 历史学生绑定 | 已按旧版本方案培养的学生继续绑定旧版本；新版本仅对发布后新绑定的专业年级生效 |
| 记录版本 version | 全部业务表带 `version` 乐观锁公共字段；提交时携带读取时的 version，不一致 → 409001 APPROVAL_VERSION_CONFLICT（审批场景）或 DATA_CONFLICT（编辑场景），提示「数据已被他人修改，请刷新后重试」 |

### G5 防重复约定

| 项 | 规则 |
|---|---|
| 在途申请唯一 | 同一学生（或教师）同一业务类型存在「在途」（非终态：APPROVED/REJECTED/CANCELLED/CLOSED/ARCHIVED 之外）申请时，再次提交 → 409001 DATA_CONFLICT，message 指明在途单号 |
| 幂等键 | 创建类提交携带幂等键（前端生成 UUID，请求头 `Idempotency-Key`）；同键重放 → 409001 IDEMPOTENCY_CONFLICT，返回首次结果单号 |
| 提交防连点 | PC 提交按钮 loading 锁定；小程序统一走 createSubmitLock（既有实现），失败解锁可重试 |
| 唯一编码 | 编码类字段（学期编码/课程编号/方案编号/批次编号）租户内唯一，冲突 → 409001，message 指明与哪条记录冲突 |

### G6 文本与附件约定

| 项 | 规则 |
|---|---|
| 原因/说明类文本 | 10 ~ 500 字（中文字符计），去首尾空格后计数；不足或超长 → 422001 |
| 短文本（名称类） | 2 ~ 50 字，特殊声明的除外 |
| 附件格式 | PDF / JPG / PNG；其他格式 → 422001「仅支持 PDF/JPG/PNG」 |
| 附件大小与数量 | 单文件 ≤10MB；单表单附件数 ≤5 |
| 附件必填 | 按业务类型判定（矩阵见下）；必填缺失 → 422001 |

附件业务必填矩阵：

| 业务（表单） | 附件必填 | 备注 |
|---|---|---|
| 转专业申请（5） | 否 | 成绩单/获奖证明选传 |
| 休学申请（6） | 是（≥1） | 疾病类须含医院证明 |
| 复学申请（7） | 条件 | 疾病休学的复学必传健康证明 |
| 调停课申请（12） | 否 | 病假类建议传，审批节点可要求补传 |
| 缓考申请（13） | 是（≥1） | 医院证明/讣告相关/单位公函 |
| 成绩更正申请（15） | 是（≥1） | 原始试卷/成绩册照片 |
| 毕业异常说明（16） | 条件 | 处理方式=申请豁免时必传 |

### G7 422 响应结构约定

422001 VALIDATION_ERROR 统一在响应体 `data` 中返回行级错误数组，前端逐字段红框+汇总提示：

| 字段 | 说明 |
|---|---|
| field | 出错字段名（表格类表单为 `行标识.字段名`，如 `items[3].finalScore`） |
| rule | 违反的规则编号或规则名（如 `G3.score-range`、`required`） |
| message | 中文提示，可直接展示给用户 |
| rowNo | 导入/批量场景附带模板行号（从数据首行=第 2 行起计），单表单场景省略 |

导入类表单沿用既有导入管线 dry-run 行级错误格式（行号/字段/原因），见第三章简表。

### G8 编码规则

| 编码 | 规则 | 示例 | 唯一性 |
|---|---|---|---|
| 学年学期编码 | `起始年-结束年-学期序号`，系统按字段自动拼装，不允许手改 | `2025-2026-1` | 租户内唯一 → 409001 |
| 课程编号 | 4~20 位大写字母+数字，建议前缀=学院/类别码（如 `GB` 公共基础），格式 `^[A-Z]{1,4}[0-9]{3,8}$` | `GB1001`、`JSJ20501` | 租户内唯一 → 409001 |
| 方案编号 | `专业代码-入学年级-P序号` | `610201-2025-P01` | 租户内唯一 → 409001 |
| 批次编号 | `业务缩写-学期编码-序号`（注册 REG / 教学任务 TT / 毕业 GRD / 成绩 GRD-T 等），系统生成 | `REG-2025-2026-1-01` | 系统生成保证唯一，冲突重试 |
| 申请单号 | `业务缩写+年份-流水号`（异动 RC / 调停课 CA / 缓考 ED / 成绩更正 GC），系统生成，409 冲突提示中引用 | `RC2026-0012`、`GC2026-0007` | 系统生成保证唯一 |

### G9 审批类表单通用约定（复用 Workflow，不另建审批）

| 项 | 规则 |
|---|---|
| 审批落表 | 全部审批走 t_workflow_instance + t_workflow_task（新增 workflow_code + node_code 序列）；待办写 t_unified_todo，通知写 t_unified_message，不自建消息表 |
| 审批意见 | 「通过」意见选填 ≤200 字；「退回/驳回」意见必填，G6：10~500 字，缺失 → 422001「退回必须填写意见」 |
| 重复审批 | 任务已被处理再提交审批 → 409001 APPROVAL_VERSION_CONFLICT「该任务已由 XX 处理」 |
| 退回去向 | 退回一律回到发起人对应编辑表单（状态 RETURNED），发起人修改后重新提交，重走完整审批链（节点直退上一节点的例外须逐业务声明） |
| 撤销规则 | 发起人在首个节点未处理前可撤销（→CANCELLED）；任一节点已通过后不可撤销，只能等终态或走反向业务 |
| 消息类型 | 仅用统一消息类型：WORKFLOW_TODO / WORKFLOW_RESULT / RETURNED_NOTICE / STATUS_CHANGED / DEADLINE_REMINDER / PUBLISHED_NOTICE 等，禁止模块自造类型 |

## 二、核心表单逐字段设计（16 个）

> 每表单固定：一句话说明（所属页面+路由+提交 API+触发状态流转）→ 字段表 → 表单级校验。
> 字段表列：字段 | 类型 | 必填 | 枚举/取值 | 校验规则 | 422 场景示例。

字段类型图例（控件规范，PC 与小程序同名控件同语义）：

| 类型标记 | 控件 | 说明 |
|---|---|---|
| text / textarea | 单行/多行文本 | 长度按 G6；textarea 显示剩余字数 |
| number | 数字输入 | 声明范围与步长，超步长直接吸附提示 |
| date / time / date-range | 日期/时间/区间选择器 | 按 G2 联动限制可选区间（灰选不可选日期） |
| select / select(多选) / select(检索) | 下拉/多选/远程检索 | 枚举写「代码值 中文名」；检索型防全量拉取 |
| switch / checkbox | 开关/勾选 | 布尔；必勾类未勾 → 422001 |
| file(多) | 附件上传 | 先传后提交（G0）；格式/大小/数量按 G6 |
| 只读区块 / text(只读) | 系统带出 | 不可编辑，提交时随单固化或由后端重新取值 |

### 表单 1：学年学期创建

学年学期新增页（`/terms/create`），提交 `POST /api/v1/academic-affairs/terms`，成功创建学期记录，初始状态 `DRAFT 草稿`（状态机 DRAFT→PUBLISHED→FROZEN→ARCHIVED）。

| 字段 | 类型 | 必填 | 枚举/取值 | 校验规则 | 422 场景示例 |
|---|---|---|---|---|---|
| 学年名称 | text | 是 | 如「2025-2026 学年」 | 2~30 字；起始年 ≥2000 且 结束年=起始年+1 | 填「2025-2027 学年」→「学年跨度必须为 1 年」 |
| 学期序号 | select | 是 | 1 第一学期 / 2 第二学期 / 3 第三学期(小学期，可配置开关) | 枚举内取值 | 传 4 →「学期序号仅支持 1/2/3」 |
| 学期编码 | text(只读) | 系统 | 按 G8 自动拼装 | 唯一性校验 | 同码已存在 → 409001「学期 2025-2026-1 已存在」 |
| 开始日期 | date | 是 | — | G2：开始 < 结束；与既有学期不重叠 | 开始 2026-03-01 结束 2026-01-10 →「开始日期必须早于结束日期」 |
| 结束日期 | date | 是 | — | 同上；学期总跨度 ≤300 天 | 与「2025-2026-1」区间重叠 →「与学期 2025-2026-1 日期重叠」 |
| 教学周数 | number | 是 | 1~30 整数 | 教学周数 × 7 ≤ 学期总天数 | 填 40 →「教学周数超出学期日期容量」 |
| 考试周设置 | number+range | 是 | 考试周数 0~4 整数 + 起始周次 | G2：考试周与教学周不重叠且不超学期末 | 考试起始周 ≤ 教学周末周 →「考试周与教学周重叠」 |
| 是否当前学期 | switch | 否 | 是/否，默认否 | 同租户同一时间仅一个「当前学期」；切换即取消原当前学期标记（二次确认） | 直接置两个当前学期 → 409001「当前学期已是 2025-2026-1」 |
| 备注 | textarea | 否 | — | ≤200 字 | 超长 →「备注不超过 200 字」 |
| 状态 | select(只读) | 系统 | DRAFT 草稿 / PUBLISHED 已发布 / FROZEN 冻结 / ARCHIVED 已归档 | 创建固定 DRAFT，发布走发布页 | 创建时传 PUBLISHED →「新建学期状态只能为草稿」 |

表单级校验：
1. G2 学期不重叠：保存时按租户扫描既有学期区间，重叠 → 422001（若编码也撞则 409001 优先）。
2. G5 幂等键防重复创建；同学年同序号仅一条 → 409001。
3. 教学周数 + 考试周数所占日历天数 ≤ 学期起止跨度，否则 422001 汇总提示。
4. 仅 `DRAFT 草稿` 状态可再编辑（编辑页 `/terms/:termId/edit` 复用本表单，携带 version，冲突 → 409001，见 G4）。
5. 发布前置（发布页校验，此处声明）：校历（表单 2）与节次（表单 3）均已配置完整，缺一 → 422001「请先完成校历与节次配置再发布」。

### 表单 2：校历节假日与调休

校历编辑页（`/terms/:termId/calendar`），提交 `PUT /api/v1/academic-affairs/terms/{termId}/calendar`，保存后校历仍处学期 `DRAFT 草稿`，经 `/terms/:termId/publish` 发布转 `PUBLISHED 已发布` 并同步排课/课表/学生端。

| 字段 | 类型 | 必填 | 枚举/取值 | 校验规则 | 422 场景示例 |
|---|---|---|---|---|---|
| 日期 | date / date-range | 是 | — | G2：必须落在学期起止内；同日不允许两条同类型记录 | 学期外日期 →「2026-08-01 不在本学期范围内」 |
| 类型 | select | 是 | HOLIDAY 节假日 / SWAP_WORKDAY 调休上课 / INTERNSHIP_WEEK 实习周 / EXAM_WEEK 考试周 | 枚举内取值 | 传 REST →「不支持的校历日类型」 |
| 名称 | text | 是 | 如「国庆节」「教学实习周」 | 2~20 字 | 填 1 字 →「名称长度须为 2-20 字」 |
| 所在教学周 | number(只读) | 系统 | 按学期开始日期自动折算周次 | 系统计算展示，不可改；类型=INTERNSHIP_WEEK/EXAM_WEEK 时按整周落点 | — |
| 补课映射日期 | date | 条件 | — | 类型=SWAP_WORKDAY 时必填；映射的被调休原日必须是本学期内的 HOLIDAY 或停课日；一个原日仅映射一次 | 调休未选映射 →「调休上课必须指定补课对应的原上课日」 |
| 按课表补课 | select | 条件 | BY_ORIGIN_DAY 按原日课表 / BY_TARGET_DAY 按当日课表 | 类型=SWAP_WORKDAY 时必填，默认 BY_ORIGIN_DAY（发布后驱动课表引擎替换当日课程） | 空 →「请选择补课执行的课表口径」 |
| 备注 | textarea | 否 | — | ≤200 字 | 超长 →「备注不超过 200 字」 |

表单级校验：
1. EXAM_WEEK 记录须与表单 1 的考试周设置一致（周次落点吻合），不一致 → 422001 汇总提示「校历考试周与学期考试周设置不一致」。
2. 同一日期不可同时为 HOLIDAY 与 SWAP_WORKDAY → 422001（行级 field=`items[n].type`）。
3. 学期 `PUBLISHED 已发布` 后修改校历须先转回可编辑流程（教务处操作+审计），直接保存 → 409001 携带 version 冲突语义。
4. 保存为整表提交，任一行失败整批不落库（与导入事务一致）。

### 表单 3：节次配置

节次配置页（`/terms/:termId/time-slots`），提交 `PUT /api/v1/academic-affairs/terms/{termId}/time-slots`，保存作息方案；学期发布后作息随校历同步给排课与课表。

| 字段 | 类型 | 必填 | 枚举/取值 | 校验规则 | 422 场景示例 |
|---|---|---|---|---|---|
| 节次号 | number | 是 | 1~14 整数 | 同方案内唯一且连续递增 | 出现两个「第 3 节」→「节次号 3 重复」 |
| 节次名称 | text | 是 | 如「第一节」「晚自习一」 | 2~10 字 | 空 →「节次名称必填」 |
| 开始时间 | time | 是 | HH:mm | G2：本节开始 < 本节结束 | 08:50~08:30 →「开始时间必须早于结束时间」 |

| 字段 | 类型 | 必填 | 枚举/取值 | 校验规则 | 422 场景示例 |

| 行备注 | text | 否 | 如「二次补交作业」 | ≤100 字 | — |

表单级校验：
1. 提交（INPUTTING→SUBMITTED）前置：每行「有完整分数」或「有特殊标记」二者必居其一；存在空行 → 422001「尚有 5 名学生未录入」（行级数组带 `items[n]`）。

5. 异常分布提示（不阻断）：不及格率 >40% 或全班同分等异常分布在提交时弹确认框并记录，供学院审核页重点复核。

表单级校验：
1. 处理方式=REMEDIED 已补救 时提交即触发该条件项系统复检；复检仍不通过 → 422001「复检未通过：学分缺口仍为 4 学分」。
2. 处理方式=EXEMPTION_REQUESTED 申请豁免 的记录必须经教务终审节点显式批准，学院初审不能终定。
3. 每条异常处理记录带 version（G4），学院教务与辅导员并发处理 → 409001。
4. 学院初审提交前置：该生全部异常条件项均已有处理记录；存在未处理项 → 422001「尚有 2 项异常未处理」。
5. 数据范围：学院教务限本院学生，辅导员限本班且仅可填补充说明（403002 越权）。

### 3.8 表单通用验收用例模板（每表单落地时按此出 ≥4 条）

1. 正常提交：合法数据提交 → 单据生成/状态流转正确 → 审批人 t_unified_todo 出现待办 → 发起人可见当前节点。
2. 重复提交：同数据连点/重放幂等键/在途再提 → 仅一条记录 + 409001，message 含在途单号。
3. 校验失败：逐条触发本表单 422 场景列 → 返回 G7 行级数组，field/message 与本文档一致，无 500。
4. 越权访问：学生 A 提交/查看学生 B 的单据、教师操作非本人课程、学院教务跨院操作 → 403002/404001 + 审计记录。
5. 并发冲突（编辑/审批类）：两端同时基于同 version 提交 → 后者 409001，刷新后可重做。
