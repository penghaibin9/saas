# 13A 学工中心表单字段与校验规则

> 依据：《_13-需求输入-V1.1.md》（§2 各业务流程与状态机、§11 字段级设计格式示例）、《_13-现有系统集成事实速查.md》（统一错误码 422001/409001、`*_encrypted` 存储与出口脱敏 `_mask_phone`/`_mask_id_card`、导入导出管线、平台规则中心）、《13A-学工中心页面树与路由设计.md》（页面编号与路由唯一基准）。
> 本文档是 13A 全部表单的字段级设计唯一基准：字段名、控件、必填、枚举常量、前后端校验、脱敏标注均以本文为准；页面编号（05-3、06-5、08-2 等）与路由不得另造，一律引用页面树文档。
> 表名沿用 `t_affairs_*` 约定（请假/处分/宿舍在既有 `t_cs_*` 表上扩展，扩展决策见页面树文档 §1.5）；状态机与枚举全部沿用需求输入 §2；本文不写代码。

## 一、统一校验约定（全部表单默认继承，各表单只写增量规则）

### 1.1 时间类校验

| 规则编号 | 规则 | 说明 |
|---|---|---|
| T1 | 开始时间不早于当前（允许当日） | 比较粒度到日：`start_date >= today`；补录场景（教工代录、处分登记等）按各表单单独放开并标注 |
| T2 | 结束时间必须晚于开始时间 | `end_time > start_time`，等于也视为不合法（时长为 0 无业务意义） |
| T3 | 跨学期提示 | 起止时间跨越校历学期边界时，前端黄色提示「本次申请跨学期，审批与统计将按开始日期所在学期归属」，不阻断提交 |
| T4 | 时长自动计算 | 请假/续假天数 = 按自然日计算（含首尾），前端实时展示、只读不可改；后端以同一算法复算，不一致以后端为准并返回 422 |
| T5 | 服务器时间为准 | 所有「不早于当前 / 不晚于当前」判定以服务器时间为准；前端仅做体验级预校验，客户端改时区不能绕过 |

### 1.2 字数类校验

| 规则编号 | 适用字段 | 长度 | 说明 |
|---|---|---|---|
| L1 | 原因/说明/理由/陈述类 | 10–500 字 | 如请假原因、调宿说明、风险处置说明、申请理由 |
| L2 | 意见类（审批意见/评议意见/核对意见） | 5–200 字 | 驳回/退回时必填，同意时选填 |
| L3 | 标题/主题类 | 2–50 字 | 如活动标题、谈话主题、归档批次名称 |
| L4 | 长文本纪要/事实类 | 各表单单独定义 | 如违纪事实经过 20–1000 字、谈话内容纪要 20–2000 字、解除表现说明 50–1000 字 |
| — | 统一实现 | — | 前端实时字数计数（当前/上限），超限禁止继续输入并标红；后端按同一区间复验，超限返回 422001 |

字数按去除首尾空白后的字符数计，中英文均按 1 字计。

### 1.3 附件类校验

| 规则编号 | 规则 | 说明 |
|---|---|---|
| F1 | 类型白名单 | 业务材料统一 PDF/JPG/PNG；批量导入类另允许 xlsx（走既有导入管线，5000 行/20MB 限制，不在本文表单范围重复设计） |
| F2 | 单文件大小 | ≤10MB，前端选择文件时即校验并提示，后端复验 |
| F3 | 单表单附件数量 | 默认 ≤5 个/附件字段（各表单可单独标注上限），超出禁止再选 |
| F4 | 按业务类型定必传 | 材料是否必传由业务类型决定（如病假必传病历/诊断证明），必传规则接平台规则中心可配置开关 |
| F5 | 病毒扫描 | 上传落盘前经统一文件扫描服务，扫描不通过整个文件拒收，返回 422001（field=附件字段，message=「文件安全扫描未通过」） |
| F6 | 文件名清洗 | 服务端重命名为系统生成文件名（业务单号+序号+扩展名），原始文件名仅作展示字段保存并过滤特殊字符/路径穿越字符；下载走鉴权+审计 |

### 1.4 防重复提交

| 层 | 机制 |
|---|---|
| 前端·小程序 | 统一使用既有 `createSubmitLock` 防连点：提交中锁定按钮，返回（成功/失败）后释放；网络失败走 realFirst 层提示，不静默重试写操作 |
| 前端·PC | 提交按钮 loading + 禁用，直至响应返回；审批类页面额外携带 workflow task version（乐观锁，冲突 409 APPROVAL_VERSION_CONFLICT） |
| 后端·幂等 | 业务幂等键校验：同学生同业务类型时间区间重叠（请假/续假/调宿）、同学生同批次唯一（困难认定/奖助申请/勤工/贷款年度）、同风险单进行中处置唯一等 → 命中返回 **409001 IDEMPOTENCY_CONFLICT**，前端 safeToast「已存在相同申请，请勿重复提交」并刷新列表 |

409（业务冲突）与 422（字段不合法）严格区分：能在字段级定位的错误一律 422001；与已有单据冲突的一律 409001。

### 1.5 草稿规则

| 项 | 约定 |
|---|---|
| 支持 DRAFT 的表单 | 请假申请、续假申请、困难认定申请、奖学金/助学金/勤工助学申请、处分解除申请（学生/长表单侧）；销假、风险处置、谈话记录、宿舍检查、调宿、活动发布、归档批次创建不设草稿（短表单或管理动作，一次填完） |
| 草稿保存校验 | 放宽为仅校验「必填主键字段」：学生身份（token 取）、业务类型/所属批次；其余字段允许为空或暂不合法，字数/时间/附件规则不在草稿阶段拦截 |
| 草稿数量上限 | 同一学生同一业务类型同时最多 **3** 条 DRAFT（可配置），超限保存返回 422001（field=global，message=「草稿数量已达上限，请先提交或删除」） |
| 提交时校验 | DRAFT → SUBMITTED 触发**全量校验**（与直接提交完全同一规则集），任一字段不合格停留在 DRAFT 并逐字段标红 |
| 草稿可见性 | 仅本人可见可编辑可删除；草稿不产生待办、不进统计、不进学生360 |

### 1.6 后端校验统一返回格式

- 校验失败统一返回 `code=422001, bizCode=VALIDATION_ERROR`，`data.errors` 为字段级错误数组：每项含 `field`（字段名，跨字段错误挂在语义主字段上，全局错误用 `global`）与 `message`（中文提示，可直接展示）。
- 前端处理约定：PC 表单逐字段标红 + 滚动定位到第一个错误字段；小程序逐字段标红 + safeToast 展示第一条 message。
- 业务错误绝不 500；越权 403002 + 审计；重复冲突 409001；审批版本冲突 409 APPROVAL_VERSION_CONFLICT。

### 1.7 可配置项（接平台规则中心，不新建管理端）

表单渲染时通过规则读取接口拉取当前租户生效配置，以下项在对应表单中以「⚙可配置」标注：

| 配置项 | 默认值 | 影响表单 |
|---|---|---|
| 长假天数阈值（升学院审批） | 3 天 | 请假、续假 |
| 重大请假天数阈值（升学工处审批） | 7 天 | 请假、续假 |
| 病假材料必传开关 | 开 | 请假、续假 |
| 住院假材料必传开关 | 开 | 请假 |
| 草稿数量上限 | 3 条 | 全部支持草稿表单 |
| 单字段附件数量上限 | 5 个 | 全部含附件表单 |
| 处分解除最短考察期 | 6 个月（按等级可分档） | 处分解除申请 |
| 奖学金绩点门槛/挂科门槛 | 按批次配置 | 奖学金申请 |
| 勤工助学困难等级门槛 | 需在困难库 | 勤工助学申请 |
| 贷款金额上限 | 按年度政策配置 | 贷款登记 |
| 活动人数上限最大值 | 2000 人 | 活动发布 |

### 1.8 审批/审核意见通用子表单（所有审批页共用，不在各表单重复定义）

05-4、05-6、06-5、07-5、08-4、08-6、11-4、15-4 等审批/审核页的操作区统一使用以下字段组，任务与实例落 `t_workflow_instance` / `t_workflow_task`：

| 字段 | 类型（控件） | 必填 | 枚举/取值 | 校验规则 | 后端 422/409 场景 |
|---|---|---|---|---|---|
| 审批动作 action | 按钮组 | 是 | APPROVE 同意 / REJECT 驳回 / RETURN 退回修改 / TRANSFER 转办 | 单选动作，按钮出现条件 = 角色 + 当前节点 + 单据状态 | 状态不允许该动作 → 422001 action |
| 审批意见 opinion | textarea | REJECT/RETURN 必填，APPROVE 选填 | — | L2 5–200 字 | 驳回未填意见 → 422001 opinion |
| 转办对象 transfer_to | 人员选择 | TRANSFER 时必填 | 同节点可办角色 | 范围函数过滤候选人 | 对象无权限 → 422001 transfer_to |
| 任务版本 task_version | 隐藏 | 是 | 乐观锁 version | 页面加载时取，提交时携带 | 已被他人处理 → 409 APPROVAL_VERSION_CONFLICT，统一弹「该任务已被处理」并刷新 |

审批操作全部落审计；退回（RETURN）的单据回到发起人可编辑态（各状态机的 RETURNED），修改重交后回到退回节点而非从头重走。

## 三、核心表单逐个设计

### 3.1 请假申请（05-3 / 小程序 pages/student/affairs/leave/create）

学生小程序发起为主流程；05-3 为教工代录（学生字段变为可搜索选择，范围函数校验可代录学生；T1 对代录放开为「允许回溯 ≤3 天 ⚙可配置」）。

| 字段 | 类型（控件） | 必填 | 枚举/取值 | 前端校验规则 | 脱敏 | 后端 422 校验场景 |
|---|---|---|---|---|---|---|
| 学生 | 隐藏（token 取）/ 代录时学生搜索选择 | 是 | 本人 / 范围内学生 | 代录时必选；小程序端不可改 | — | 非在籍学生（student_status 异常）拒绝；代录越权走 403002 |
| 请假类型 leave_type | select | 是 | SICK 病假 / PERSONAL 事假 / HOME 探亲假 / HOSPITAL 住院假 / OTHER 其他 | 必选枚举 | — | 枚举外值 → 422001 leave_type |
| 开始时间 start_time | 日期时间选择 | 是 | — | T1 不早于当前（允许当日） | — | 早于当日（服务器时间）→ 422001 start_time |
| 结束时间 end_time | 日期时间选择 | 是 | — | T2 晚于开始时间；T3 跨学期提示 | — | 不晚于开始时间 → 422001 end_time |
| 请假天数 leave_days | 只读自动计算 | 自动 | ≥1 自然日 | T4 实时计算展示；达长假阈值 ⚙时提示「将升级至学院审批」 | — | 前后端天数不一致 → 422001 leave_days |
| 请假原因 reason | textarea | 是 | — | L1 10–500 字实时计数 | — | <10 或 >500 字 → 422001 reason |
| 证明材料 attachments | 文件上传 | 按类型 ⚙ | PDF/JPG/PNG，单个 ≤10MB，≤5 个 | SICK/HOSPITAL 必传（⚙可配置）；F1–F3 | — | 病假未传材料 → 422001 attachments；类型/大小超限 → 422001 attachments |
| 目的地 destination | input | 探亲/离校类必填 | 2–50 字 | HOME 及勾选「离校」时必填 | — | 离校未填目的地 → 422001 destination |
| 联系电话 contact_phone | input | 是 | 11 位手机号格式 | 格式正则校验；默认带出本人主档号码可改 | 存 phone_encrypted，出口 _mask_phone | 格式不合法 → 422001 contact_phone |
| 是否通知家长 notify_parent | switch | 否 | true/false，默认 false | — | 家长号码取主档联系人，展示脱敏 | — |
| 是否离校 leave_campus | switch | 是 | true/false | 勾选后目的地必填 | — | — |

- 草稿：支持（DRAFT ≤3 条 ⚙；保存仅校验请假类型）；提交时全量校验。
- 防重复：`createSubmitLock`（小程序）/ 按钮 loading（PC 代录）；后端幂等键 = 学生 + 时间区间重叠（非 REJECTED/CANCELLED/CLOSED 单）→ **409001**「该时间段已有请假单」。
- 提交后状态：DRAFT/直接提交 → SUBMITTED → COUNSELOR_REVIEW，生成辅导员待办（t_unified_todo）；按天数阈值 ⚙ 决定是否续入 COLLEGE_REVIEW / STUDENT_AFFAIRS_REVIEW。
- 典型 422/409：① 结束时间早于开始时间 → 422001 end_time；② 原因 8 字 → 422001 reason；③ 病假未传诊断证明 → 422001 attachments；④ 同时间段已有 APPROVED 请假单 → 409001。

### 3.2 销假（学生小程序发起 / 05-5 辅导员销假确认）

前提状态：请假单为 APPROVED 或 OVERDUE。学生提交后进入 WAIT_CANCEL_LEAVE，辅导员在 05-5 确认后 CLOSED。

| 字段 | 类型（控件） | 必填 | 枚举/取值 | 前端校验规则 | 脱敏 | 后端 422 校验场景 |
|---|---|---|---|---|---|---|
| 请假单号 leave_id | 隐藏（详情页带入） | 是 | 本人有效请假单 | 不可改 | — | 单据状态非 APPROVED/OVERDUE → 422001 leave_id「当前状态不可销假」 |
| 实际返校时间 actual_return_time | 日期时间选择 | 是 | — | 不晚于当前（T5 服务器时间）；不早于请假开始时间 | — | 晚于当前时间 → 422001 actual_return_time；早于开始时间 → 422001 actual_return_time |
| 返校证明 return_proof | 文件上传 | OVERDUE 时必传，其余选传 ⚙ | PDF/JPG/PNG ≤10MB ≤3 个 | F1–F3 | — | 逾期单未传证明 → 422001 return_proof |
| 销假说明 remark | textarea | 逾期时必填 | L1 10–500 字 | OVERDUE 单必填并需说明逾期原因 | — | 逾期未填说明 → 422001 remark |

- 草稿：不支持（单次动作）。
- 防重复：`createSubmitLock`；后端同一请假单仅允许一条进行中销假记录 → 重复提交 **409001**。
- 提交后状态：APPROVED/OVERDUE → WAIT_CANCEL_LEAVE，辅导员待办生成；05-5 确认后 → CLOSED，写学生360（t_student_stage_event）；OVERDUE 单关闭时同步关闭关联风险记录跟进项。
- 典型 422/409：① 实际返校时间填了明天 → 422001 actual_return_time；② 逾期单说明为空 → 422001 remark；③ 已在 WAIT_CANCEL_LEAVE 再次提交 → 409001；④ 单据已 CLOSED → 422001 leave_id。

### 3.3 续假（学生小程序发起 / 05-6 续假审批）

前提状态：APPROVED 且未到期（到期后只能走销假/逾期流程）。

| 字段 | 类型（控件） | 必填 | 枚举/取值 | 前端校验规则 | 脱敏 | 后端 422 校验场景 |
|---|---|---|---|---|---|---|
| 原请假单号 leave_id | 隐藏（详情页带入） | 是 | 本人 APPROVED 单 | 不可改，页面展示原起止/天数 | — | 状态非 APPROVED → 422001 leave_id |
| 新结束时间 new_end_time | 日期时间选择 | 是 | — | 必须晚于原结束时间；T3 跨学期提示 | — | 不晚于原结束时间 → 422001 new_end_time |
| 续假后总天数 total_days | 只读自动计算 | 自动 | 原开始 → 新结束 | T4 自动算；达阈值 ⚙ 提示「续假后总天数 X 天，将升级至学院/学工处审批」 | — | 前后端计算不一致 → 422001 total_days |
| 续假原因 extension_reason | textarea | 是 | — | L1 10–500 字 | — | 字数不符 → 422001 extension_reason |
| 补充材料 attachments | 文件上传 | 病假/住院续假必传 ⚙ | PDF/JPG/PNG ≤10MB ≤5 个 | F1–F4 | — | 病假续假未传材料 → 422001 attachments |

- 草稿：支持（保存仅校验原单号）。
- 防重复：同一请假单同时只允许一条进行中续假（EXTENSION_REVIEW）→ **409001**。

## 六、附录B：移动端表单错误处理统一约定（小程序提交链路）

| HTTP/业务码 | 场景 | 小程序处理 |
|---|---|---|
| 401001 | token 失效 | 走既有 401 单飞刷新，失败跳登录；表单内容暂存本地待恢复 |
| 403001 / 403002 | 无权限 / 越权（含 demo-school 只读锁） | safeToast 后返回上一页；只读锁提示「演示环境只读，请前往沙箱环境」；越权后端已落审计 |
| 404001 | 单据不存在（已被删除/撤销） | 提示「单据不存在或已撤销」，刷新列表 |
| 409001 IDEMPOTENCY_CONFLICT | 重复提交/业务冲突 | safeToast 展示 message（如「该时间段已有请假单」），释放提交锁，刷新我的列表 |
| 409 APPROVAL_VERSION_CONFLICT | 审批任务已被处理（教师端） | 弹「该任务已被处理」，刷新待办列表 |
| 422001 VALIDATION_ERROR | 字段校验失败 | 解析 data.errors，逐字段标红并滚动至第一个错误字段，safeToast 第一条 message；不清空已填内容 |
| 429001 | 触发限流 | 提示「操作过于频繁，请稍后再试」，提交锁延时释放 |
| 网络失败 | 断网/超时 | realFirst 层提示网络异常；写操作**不自动重试**，由用户手动重发（配合后端幂等键保证安全） |

> 校验实现原则复述：前端校验只做体验（实时计数、联动、禁用），**后端 422001 全量复验是唯一防线**；所有写操作过 demo-school 只读锁与租户过滤；审批提交带乐观锁 version；导入导出一律走既有管线注册新 domain，不在表单侧另造上传下载通道。
