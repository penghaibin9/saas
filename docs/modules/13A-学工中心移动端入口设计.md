## 一、总则

### 1.1 端定位

| 端 | 定位 | 说明 |
|---|---|---|
| 学生小程序 | 学生唯一入口 | 本轮不开学生 PC 门户（需求 §12 禁止事项、事实速查 §11）。学生令牌访问 PC 接口一律 403（`require_staff`），学生业务全部走 `/api/v1/mobile/*` |
| 教师移动端 | 高频轻操作 | 工作台/待办/审批/快速记录/学生详情查看；材料多、节点重、配置类操作必须回 PC（见 §3.9 总表） |
| PC 学工中心 | 全量管理端 | 页面与路由见《13A-学工中心页面树与路由设计.md》，本文以「05-4」等编号引用 |

### 1.2 页面路径约定

- 学生学工新页统一放 `pages/student/affairs/*`，教师学工新页统一放 `pages/teacher/affairs/*`；与既有 `pages/student/*`、`pages/teacher/*` 并存，命名沿用现有 uni-app Vue3 options API 风格（list / detail / create 后缀语义）。
- 复用优先：教师工作台复用既有 `pages/teacher/workbench`（扩展学工待办角标），审批复用既有 `pages/teacher/approvals/*`（新增学工审批类型），学生360复用既有教师端学生详情页（扩展聚合），不重建同类页面。
- 既有学生请假提交页（campus-service）升级为本文 S-01 请假页，路由沿用或重定向，详见第四章 4.2。

### 1.3 API 约定

| 类别 | 约定 | 示例 |
|---|---|---|
| 学生读 | `GET /api/v1/mobile/affairs/{biz}/my` 风格（沿用既有 `{domain}/my`） | `GET /api/v1/mobile/affairs/leave/my`、`GET /api/v1/mobile/affairs/dorm/my` |
| 学生写 | `POST /api/v1/mobile/affairs/{biz}`，子动作 `POST /api/v1/mobile/affairs/{biz}/{id}/{action}` | `POST /api/v1/mobile/affairs/leave`、`POST /api/v1/mobile/affairs/leave/{id}/cancel-leave` |
| 教师读写 | 全部走 `/api/v1/mobile/teacher/*` 包装（范围校验 + 审计 + 409） | `POST /api/v1/mobile/teacher/approvals/{taskId}/approve` |
| 身份注入 | `student_id` 一律从 token 取（claims 附 studentNo），`tenant_id` 从上下文取；请求体不接受、不信任前端传入的学生身份与租户参数 | — |
| 响应体 | 冻结格式 `{ code, bizCode, message, data, traceId, timestamp }`，业务错误绝不 500 | — |

### 1.4 统一错误处理约定表（全部移动端页面共用，逐页小节仅写本页差异）

| 场景 / bizCode | 统一处理 |
|---|---|
| 401001 UNAUTHORIZED | 请求层单飞刷新 token（并发请求只触发一次刷新，其余排队等待）；刷新成功自动重放原请求；刷新失败清空登录态并跳登录页 |
| 403001 NO_PERMISSION | safeToast 提示「无权限操作」并返回上一页；后端已落审计（t_security_audit_log），前端不吞码、不兜底 |
| 403002 NO_DATA_SCOPE | safeToast 提示「该学生/单据不在你的管理范围」并返回上一页；后端审计越权访问 |
| 404001 DATA_NOT_FOUND | 提示「单据不存在或已被撤销」，返回列表并触发列表刷新（防止点击已失效的角标/消息残留项） |
| 409001 DATA_CONFLICT（IDEMPOTENCY_CONFLICT / APPROVAL_VERSION_CONFLICT） | 提交类：safeToast「请勿重复提交」；审批/确认类：safeToast「该单已被处理」；两者均随后刷新当前列表或详情，展示服务端最新状态 |
| 422001 VALIDATION_ERROR | 逐字段表单标红（后端返回字段级错误明细逐项映射到表单项），首个错误字段滚动到可视区；不弹全局错误页 |
| 网络失败（超时/断网） | realFirst 请求层不兜底假数据：读接口渲染 MobileGlobalState error 态 + 「重试」按钮；写接口 safeToast「网络异常，请重试」，提交锁释放、表单内容保留 |
| 429001 RATE_LIMITED | safeToast「操作过于频繁，请稍后再试」 |
| demo-school 只读锁 | 写操作后端 403，前端统一提示「演示环境只读，请前往沙箱环境操作」 |

### 1.5 通用组件与规则

1. **五态复用 MobileGlobalState**：所有列表/详情页统一 loading / error / empty 三态由 MobileGlobalState 承载，另加业务只读态（审批中/已归档单据隐藏写按钮）与 noPermission 态（403 返回场景）。空态文案必须给出下一步指引（如「暂无请假记录，点击右下角发起请假」）。
2. **敏感字段一律 MobileSensitiveText**：手机号、身份证号、家庭经济信息、联系人号码等出口已脱敏（`*_encrypted` 存储 + `_mask_phone` / `_mask_id_card`），前端用 MobileSensitiveText 统一渲染，不自行拼接明文；移动端不提供「查看完整」入口（查看完整明文仅 PC，且填原因 + 审计）。
3. **写操作防重复双保险**：前端 createSubmitLock 防连点（提交期间按钮禁用 + 锁未释放前丢弃重复触发）+ 后端 409001 幂等/版本冲突拦截。所有写操作逐页小节标注此项。
4. **待办与消息**：角标与消息一律来源 t_unified_todo / t_unified_message，页面不自建消息轮询；消息点击跳转按 source_module + 业务 id 路由到对应移动端详情页。
5. **进 360**：学生侧成功提交/状态变化由后端写 t_student_stage_event 等域记录，移动端不直接操作 360 数据。

## 四、与既有 miniapp 的复用说明

### 4.1 请求层与通用组件复用（逐项）

| 既有能力 | 在学工新页中的复用方式 |
|---|---|
| realFirst（业务错误透出不兜底） | 学工所有新页请求走同一请求层实例：业务错误码（403/404/409/422）原样透出给页面按 §1.4 表处理，**绝不兜底假数据**；仅网络级失败进入 MobileGlobalState error 态。新增学工 API 只登记 baseURL 路径，不复制请求层 |
| createSubmitLock 防连点 | 第二、三章所有标注写操作的按钮统一挂锁：请假提交/销假/续假/困难提交/奖助申请/勤工申请/解除申请/调宿申请/审批/处置/谈话保存/上报/催办。锁与后端 409001 构成双保险，缺一不可（锁防连点、409 防跨端重复与并发处理） |
| safeToast | 所有非表单级提示（无权限/已处理/网络异常/催办频繁/演示只读）统一 safeToast，禁止各页自造弹窗；表单级错误走字段标红不走 toast |
| 401 单飞刷新 | 学工页不感知 token 逻辑，401 由请求层单飞刷新并重放，失败统一跳登录；学工新页禁止自行捕获 401 做跳转 |
| MobileGlobalState | 学工全部列表/详情页复用 loading/error/empty 三态组件；复合页（T-01 工作台、T-08 学生360简版）按区块粒度使用，单区块失败不拖垮整页 |
| MobileSensitiveText | 覆盖字段清单：学生/联系人手机号、身份证号、家庭经济信息（S-03/T-05）、困难等级标签（对非授权角色）、家长号码（S-11/T-08）。移动端一律脱敏渲染，不提供明文开关；完整明文仅 PC 且填原因 + 审计 |

### 4.2 既有页面与端点复用

**学生请假：既有 campus-service 提交页升级为 S-01（扩展而非重建）**

1. 数据与状态机：沿用既有 `t_cs_leave`（已实现学生移动端提交 + 防重复 409），13A 在其上扩展状态机（新增 COLLEGE_REVIEW/STUDENT_AFFAIRS_REVIEW/WAIT_CANCEL_LEAVE/CLOSED/OVERDUE/EXTENSION_REVIEW 等）、审批流升级为 Workflow 实例、销假/续假走关联新表（t_affairs_leave_cancel_record / t_affairs_leave_extension），不平行再建请假单（「扩展 vs 平迁」决策详见交互矩阵文档）。
2. 页面路由：既有学生请假提交页路由保留并**重定向**至 `pages/student/affairs/leave/create`（老入口、老消息深链不断链）；列表/详情为新页。既有提交接口升级期兼容：老端点继续可用并内部落新状态机，服务大厅新入口直连 `/api/v1/mobile/affairs/leave`。
3. 既有防重复 409 逻辑原样保留，仅扩展冲突判定覆盖销假/续假在途单。

**教师审批：复用既有移动审批包装，不新增端点模式**

- 13A 全部新审批类型（请假多级/续假/销假确认/困难初审/调宿/处分解除）= **新增 workflow_code + node_code 序列**，任务与实例落 t_workflow_instance / t_workflow_task，移动端审批统一走既有 `POST /api/v1/mobile/teacher/approvals/{id}/approve|reject` 包装（范围校验 + 审计 + 409 APPROVAL_VERSION_CONFLICT 已实现），**不为任何学工业务新增审批端点模式**；审批详情页按 workflow_code 渲染业务字段模板即可。
- 非审批类教师写操作（风险处置、谈话保存、宿舍上报等）遵循同一包装原则：`/api/v1/mobile/teacher/affairs/*` 内统一做 scope 校验 + 审计 + 409。

**教师范围：复用 resolve_teacher_scope / can_teacher_view_student**

- 学工教师端全部列表过滤与写操作校验复用 `resolve_teacher_scope(user)`（SCOPED/ADMIN_TENANT/TENANT_FALLBACK）与 `can_teacher_view_student(user, stu, scope, db)`（学号/班级/学院/导师四路判定，越权 403 + 审计）；需求书的 getCounselorScope 设计为该机制封装。
- 新增 scope_type 扩展而不另起炉灶：`DORM_BUILDING`（宿管楼栋，T-07）、`PSY_STUDENT`（心理授权学生，T-03/T-08 心理区块）、`AID_STUDENT`（资助业务学生，T-05）。t_teacher_student_scope 表结构不变，仅扩枚举。

**角标规则**（统一数据源，不自建计数）：

1. 宫格/底部导航角标 = `t_unified_todo`（assignee_id=本人、status=未处理，按 source_module 分组计数）+ `t_unified_message`（receiver_id=本人未读数）。学生端角标主要由消息驱动（审批结果/退回/公示/提醒），教师端由待办驱动（todo_type 分组）。
