### 1.2 13A/13B 扩展方式裁定（新增 domain 注册，不建自有导入表）

1. **注册而非重造**：13A/13B 全部历史导入 = 在 `domain_import_service.DOMAINS` 注册新 domain（本章 §1.4 清单共 21 个），行为完全继承 §1.1 管线。禁止任何模块自写 openpyxl 入库（融合证据报告 R14 红线）。
2. **配置元数据扩展建议**：现有 DOMAINS 四元组不足以表达 13A/13B 的模板列/唯一键/重复策略/脱敏规则，建议将注册项扩展为配置对象（key_field、create_svc、list_svc、label、template_columns、unique_key、dup_policy、precheck_hooks、mask_rules），置于新增配置模块（如 `affairs_import_config` / `aa_import_config`）后注册进同一 DOMAINS——**管线代码不动，只加配置**。
3. **批次表复用**：批次继续落 `t_student_import_batch`，domain 编码记入 remark（零 DDL）；如 P2 需要按域检索再提"加 domain 列（nullable）"的草案勘误，本轮不加列。
4. **重复数据三策略（全局定义，逐类指定默认值）**：
   - `ERROR`（默认）：命中唯一键即报 DUP_IN_DB，整批 dry-run 失败，与现有行为一致；
   - `SKIP`：命中唯一键的行跳过并计入 skippedRows（用于修错后重传同一文件，幂等重跑）；
   - `OVERWRITE`：命中唯一键的行按白名单字段覆盖更新（乐观锁 version+1，写域 trail）；**仅字典/资源类域开放**（宿舍房源、课程库、作息、校历），单据/流水类域一律禁用（历史单据不可覆盖）。策略由 validate 请求参数 `dupPolicy` 传入，OVERWRITE 强制 `audit_log.record("IMPORT_OVERWRITE", …)`。
5. **导入日志（双留痕）**：①批次表一条（§1.1 第 7 条）；②`audit_log.record("IMPORT_CONFIRM", resource=domain, detail={batchNo, rows}, result)` 落 t_security_audit_log（含 ip/ua/traceId）；③涉业务表写入的按草案总纲 6 条同步写 t_affairs_audit_trail / t_aa_audit_trail。
6. **失败重试口径**：dry-run 失败 → 下载错误清单（rowNo+message）→ 修正源文件 → 重新 validate（新 batchNo，旧批次作废）；confirm 阶段异常 → 整批回滚 → 批次状态置 CONFIRM_FAILED → 重新 confirm 同一 batchNo 幂等可重试。**禁止行级补写**。
7. **通用规约 G1–G5**（逐类不再重复，仅标注偏差）：
   - G1 确认流程：dry-run 全绿（errorRows=0）才允许 confirm；有错必须改文件重来；
   - G2 事务回滚：confirm 整批一个事务，任一行落库失败全部回滚；
   - G3 导入日志：批次表 + 安全审计 + 域 trail 三处；
   - G4 失败重试：见上第 6 条；
   - G5 跨租户隔离：批次绑定 tenant，confirm 校验；目标表全部 TenantMixin，中间件注入过滤。

## 二、学工 10 类导入逐类设计

> 每类给出：模板列（Excel 列→表字段映射+必填+示例）、唯一键、重复策略、预检规则、行号错误示例、敏感脱敏、导入后对账清单。G1–G5 通用规约全部适用，仅标注偏差。

### A1 宿舍房源（affairs-dorm-building）

- 目标表：t_affairs_dorm_building / t_affairs_dorm_room / t_affairs_dorm_bed（一张模板三级展开，服务层按楼→房→床顺序建）。前置依赖：无。
- 模板列：

| Excel 列 | 映射字段 | 必填 | 示例 |
|---|---|---|---|
| 楼栋编码 | building_code | 是 | B01 |
| 楼栋名称 | building_name | 是 | 梅苑1栋 |
| 性别限制 | gender_limit（M/F/MIXED） | 是 | F |
| 宿管工号/登录名 | manager_teacher_key | 否 | dorm001 |
| 楼层 | floor_no | 是 | 3 |
| 房号 | room_no | 是 | 302 |
| 床位数 | capacity（按数生成 bed 行，bed_no 1..N） | 是 | 4 |
| 房间类型 | room_type | 否 | 四人间 |

- 唯一键：`(tenant, building_code, room_no, bed_no)`；重复策略默认 **OVERWRITE**（房源为资源字典，允许整表刷新，覆盖仅更新 capacity/room_type/manager，**不清占用**）。
- 预检：性别限制枚举；capacity 1–12；同楼栋 gender_limit 前后一致；床位缩减时若被占用床 > 新 capacity → 行错误 BED_OCCUPIED_SHRINK。
- 行号错误示例：`{"rowNo":18,"field":"capacity","errorCode":"BED_OCCUPIED_SHRINK","rawValue":"2","message":"B01-302 现有 3 个已占用床位，容量不能缩为 2"}`
- 脱敏：无敏感列。
- 对账清单：①楼/房/床三级行数与 Excel 汇总一致（`count(*) group by building_code` 对 Excel 数据透视）；②`sum(capacity)` = bed 行数；③占用床数导入前后不变（房源导入不得影响占用）。

### A2 住宿分配（affairs-dorm-assign）

- 目标表：t_affairs_dorm_bed（VACANT→OCCUPIED）＋事务内回写 t_cs_dorm_record（草案 §3.8 硬约束，既有"我的宿舍"读链路零改动）。前置依赖：学生主档、A1 房源。
- 模板列：学号→student_id（经 t_student_profile 反查）| 是 | 2023010001；楼栋编码/房号/床号→bed 定位 | 是 | B01/302/2；入住日期→occupied_at | 否 | 2025-09-01。
- 唯一键：`(tenant, student_id)`（一生一床）；床位维度校验 `(tenant, bed_id)` 只允许一个 OCCUPIED。重复策略 **ERROR**（学生已有床位即报错，调宿走业务流程不走导入）。
- 预检：学号存在且非 WITHDRAWN/GRADUATED；床位存在且 VACANT；学生性别与楼栋 gender_limit 匹配；与 t_cs_dorm_record 既有记录冲突检测（三方对账口径见草案 §5.2 宿舍初始化行）。
- 行号错误示例：`{"rowNo":41,"field":"bedNo","errorCode":"BED_OCCUPIED","rawValue":"B01-302-2","message":"床位已被 2023010007 占用"}`
- 脱敏：无。
- 对账：①OCCUPIED 床数 = 导入成功行数 + 存量占用；②t_affairs_dorm_bed 占用行与 t_cs_dorm_record 逐生一致（差异行清单=0 方可验收）；③空床数 = 总床数 − 占用数。

### A3 请假历史（affairs-leave-history）

- 目标表：t_cs_leave（加列后，affairs_status 直写终态）。前置依赖：学生主档。
- 模板列：

| Excel 列 | 映射字段 | 必填 | 示例 |
|---|---|---|---|
| 学号 | student_no→student_id | 是 | 2023010001 |
| 请假类型 | leave_type（SICK/PERSONAL/OTHER） | 是 | SICK |
| 开始时间 / 结束时间 | start_time / end_time | 是 | 2025-03-02 08:00 |
| 天数 | days（缺省按起止计算） | 否 | 3 |
| 原因 | reason | 是 | 流感发热就医 |
| 最终状态 | affairs_status（仅收 APPROVED/REJECTED/CLOSED/OVERDUE） | 是 | CLOSED |
| 实际返校时间 | actual_return_at（CLOSED 必填） | 条件 | 2025-03-05 09:00 |

- 唯一键：`(tenant, student_id, start_time, leave_type)`；重复策略 **ERROR**。
- 预检：状态白名单（过程态一律拒收——历史数据只进终态，避免生成假待办）；end_time>start_time；CLOSED 必带 actual_return_at；旧 status 投影列按草案 §5.3 映射同步写。
- 行号错误示例：`{"rowNo":7,"field":"studentNo","errorCode":"REF_NOT_FOUND","rawValue":"2023010099","message":"学号 2023010099 不在学生主档"}`
- 脱敏：reason 原样入库，出口按角色权限展示。
- 对账：①按状态 count 与老系统报表一致；②OVERDUE 行满足 end_time<导入日 且无销假记录；③导入行不产生任何 t_unified_todo（历史单零待办，SQL：source_module='student-affairs' 且 source_biz_id∈本批次 的待办数=0）。

### A4 困难认定历史（affairs-aid-history）

- 目标表：t_affairs_aid_apply（终态 APPROVED/ARCHIVED）＋逐行追加 t_affairs_aid_level_history（change_type=认定）。前置依赖：学生主档；批次外键指向预建"历史迁移批次"（t_affairs_aid_batch 一条 ARCHIVED 占位）。
- 模板列：学号 | 是；学年 year_code | 是 | 2024-2025；认定等级 final_level（特别困难/困难/一般困难编码）| 是；认定日期 | 是；备注 reason | 否。**不含家庭经济明细列**——t_affairs_aid_family_economy 强敏感表不开放批量导入（草案 §3.3），历史家庭经济信息不迁移，只迁等级结论。
- 唯一键：`(tenant, student_id, year_code)`；重复策略 **ERROR**。
- 预检：等级枚举白名单；year_code 格式 `YYYY-YYYY`；同生同学年多行冲突（DUP_IN_FILE）。
- 行号错误示例：`{"rowNo":12,"field":"finalLevel","errorCode":"ENUM_INVALID","rawValue":"特困","message":"认定等级须为：特别困难/困难/一般困难"}`
- 脱敏：等级属敏感（草案 §3.3），列表出口仅授权角色可见明级，其余显示"已认定"；导入预览页同样脱敏。
- 对账：①level_history 追加行数 = 成功行数；②困难库视图（level_history 最新行）人数 = 老系统当期困难生数；③apply 终态行 workflow_instance_id 全 NULL（历史单不补流程，详情页标"历史迁移"）。

### A5 奖助获得记录（affairs-funding-history）

- 目标表：t_affairs_funding_application（GRANTED/ARCHIVED）；project/batch 不存在时先按模板"项目编码+项目类型"预建（ENABLED/ARCHIVED）。前置依赖：学生主档。
- 模板列：学号 | 是；项目编码/名称 | 是 | GJJXJ 国家奖学金；项目类型 project_type 七枚举 | 是 | SCHOLARSHIP；学年 | 是；金额 amount | 是 | 8000；获得日期 result_at | 是。
- 唯一键：`(tenant, student_id, 项目编码, year_code)`（对齐草案 funding 唯一键）；重复策略 **ERROR**。
- 预检：project_type 白名单；金额 0<amount≤99999999.99（DECIMAL 12,2）；日期不晚于导入日。
- 行号错误示例：`{"rowNo":23,"field":"amount","errorCode":"RANGE_INVALID","rawValue":"-500","message":"金额必须大于 0"}`
- 脱敏：金额与困难关联属敏感（草案 §3.4），出口按权限；导出走水印管线。
- 对账：①`sum(amount) group by 项目` 与财务台账一致；②GRANTED 行均写一条 StageEvent（source_module='student-affairs'）——历史迁移**可选**写 360（默认写，开关参数控制）；③check_snapshot_json 统一置 `{"legacy":true}` 标记免校验来源。

### A6 处分历史（affairs-discipline-history）

- 目标表：t_affairs_discipline_case（EFFECTIVE 或 REMOVED）＋事务内投影 t_cs_discipline 一行（source_case_id 回链，草案 §3.5 硬约束）。前置依赖：学生主档。
- 模板列：学号 | 是；处分类型 disc_type（WARNING/SERIOUS_WARNING/DEMERIT/PROBATION/EXPEL）| 是；文号 doc_no | 是 | 校学字〔2024〕12号；处分日期 decide_date | 是；事由 reason | 是；是否已解除（是/否）| 是；解除日期 removed_at | 条件。

### B11 历届毕业结论（aa-graduation-history）

- 目标表：t_aa_graduation_audit_result（conclusion=GRADUATED/COMPLETED/DELAYED，状态 ARCHIVED）＋批次预建 ARCHIVED；结论写 StageEvent。前置依赖：B4（学籍状态先行）。
- 模板列：学号 | 是；毕业年份/批次名 | 是；结论（毕业/结业/延毕）| 是；结论日期 | 是；备注 | 否。
- 唯一键：`(tenant, batch_id, student_id)`（草案库级唯一）；重复策略 **ERROR**。
- 预检：结论枚举；结论=毕业 而主档 status≠GRADUATED 出 WARN（提示先跑 B4 或本批联动修正声明）；item_results_json 置 `{"legacy":true}`。
- 行号错误示例：`{"rowNo":19,"field":"conclusion","errorCode":"CROSS_CHECK_FAILED","rawValue":"毕业","message":"该生主档学籍状态为 WITHDRAWN（退学），不能导入毕业结论"}`
- 对账：历届毕业人数按年份与上报数一致；GRADUATED 结论行主档状态同为 GRADUATED（交叉 SQL 差异=0）。

## 四、老系统通用适配策略（正方/青果/金智/强智/Excel）

### 4.1 统一落地顺序（三步法，V1 唯一迁移通道）

```
老系统（正方/青果/金智/强智/自建/纸质台账）
   └─(1) 老系统自带"导出 Excel"功能逐模块导出原始文件（不改动、留存归档）
        └─(2) 按《映射对照表》把原始列改写为本文件 §2/§3 官方模板列（逐校一份对照表，实施交付物）
             └─(3) 按 §5 依赖顺序分批导入：validate（dry-run）→ 错误清零 → confirm
```

- 对齐 12-集成开放中心 §1.2"轻量模式"：V1 不做任何老系统 API/中间库直连（该能力属 12 号中心 P2–P3 档，见《13A-13B-第三方系统对接与开放接口设计》）。
- 原始导出文件、映射对照表、每批错误清单、confirm 回执四件套按校归档（实施 SOP），满足 12 号中心铁律"旧系统数据导入后可追溯"。

### 4.2 四厂商导出能力速记（实施侧口径）

| 厂商 | 常见可导出物 | 特别注意 |
|---|---|---|
| 正方（zfsoft） | 学籍名册/成绩/课表/教学计划 xls | 老版导出为 xls（Excel 97-2003），需另存为 xlsx；课表为矩阵式（星期×节次交叉表），要先转行式 |
| 青果（qingguo/kingosoft） | 学籍/成绩/异动 xls·csv | csv 常为 GBK 编码；学期编码风格 `2024-2025-1` 与本模板一致可直用 |
| 金智（wisedu） | 学籍/组织/成绩（多经数据中台） | 字段名多为拼音缩写（XH/XM/BJMC），映射对照表工作量最大 |
| 强智（qzdatasoft） | 学籍/成绩/教学任务 xls | 成绩含"总评/平时/期末"多列，V1 只取总评列（构成明细属 P2 成绩域） |

### 4.3 常见坑与处置（预检规则的来源清单）

| # | 坑 | 现象 | 处置（管线内） |
|---|---|---|---|
| 1 | 编码 | 青果/强智 csv 为 GBK，直接上传中文全乱码 | 管线 csv 按 utf-8-sig 解码（parse_upload_rows 现状），乱码行必然 REF_NOT_FOUND——实施规范：**csv 一律先转 xlsx 再传**；模板发放只发 xlsx |
| 2 | 日期格式 | `2026/7/5`、`45678`（Excel 序列值）、`2026.07.05` 混杂 | 预检统一解析三种格式，解析失败报 FORMAT_INVALID 并回显原值；时间缺时分默认 00:00 出 WARN |
| 3 | 重名学生 | 老系统台账只有姓名无学号（谈话/处分纸质台账常见） | **一律以学号为身份键，姓名仅作复核列**；只有姓名的行报 REF_AMBIGUOUS，实施侧先经"姓名+班级"人工补学号再导 |
| 4 | 班级名不一致 | 「软件26-1班」「软件2601」「2026级软件1班」指同一班 | 班级反查失败时 message 携带最相近候选（编辑距离提示，见 A10 示例）；实施交付物含《班级名对照表》，导前批量替换 |
| 5 | 学号前导零丢失 | Excel 把 `0230101` 存成数字 230101 | 模板学号列强制文本格式；预检对纯数字且位数少于校方学号规则的行出 WARN |
| 6 | 身份证 X 大小写/科学计数 | `340...x`、`3.40E+17` | 预检统一大写 X、拒收科学计数法（FORMAT_INVALID）；身份证列仅 A8/学生主档模板存在且入库即加密 |
| 7 | 合并单元格/多级表头 | openpyxl 读出大量空值行 | 预检：首列为空且整行 <2 个非空值的行自动跳过并计入 ignoredRows；多级表头文件报 TEMPLATE_MISMATCH 提示用官方模板 |
| 8 | 状态字面翻译 | 老系统"在读/休学中/已退学"与枚举不一致 | 每类模板附《状态映射表》（如 B4），映射表外字面报 ENUM_INVALID 并在 message 给候选 |
| 9 | 同一学生多学籍 | 转专业后老系统留两条学籍 | B4 唯一键每生一行强约束；实施侧取"最新有效"行，历史轨迹走 B5 |
| 10 | 幽灵数据 | 已退学学生仍有在住宿/成绩增量 | 依赖顺序（§5）保证学籍先行；A2/B10 预检对 WITHDRAWN 学生出 WARN 或拒收 |

### 4.4 分批策略

- 单文件 ≤5000 行、≤20MB（管线硬限）；建议按 **学院×年级** 切文件（命名 `域_学院_年级_序号.xlsx`），错误定位与返工范围最小化。
- 大校成绩类（B10）通常 >5000 行/学期：按 学期×学院 切分，逐批 confirm，批间无事务依赖（唯一键防重）。
- 同一 domain 多批并行禁止（批次内存态 + 唯一键竞争），实施 SOP 规定同域串行导入。
