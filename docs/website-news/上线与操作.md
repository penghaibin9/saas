# 官网新闻资源包发布｜交付边界与运维

## 用户操作
平台运营 → 官网内容运营 → 新闻资源包发布。上传GPT给出的ZIP，核对整包分类、标题、摘要及来源，点击“确认并自动发布”及整包审核确认按钮。默认全部合格稿选中，可以排除个别稿。没有每日发布额度，也不需要每天选分类、配图、复制正文或逐篇设置时间。

默认第一篇在确认后30秒进入可执行时段，此后每3分钟一篇；可以在确认时调整。按全局队列顺序持续排期，超过当天的部分自动延续，不截断。工作进程每次50条只是数据库事务批量，不是每天上限。服务器运行时关闭浏览器也会继续。列表明确区分“排期”和“实际发布”。

## 安全与业务界限
上传和校验不等于审核。JSON不能自行把文章变成已批准。学校管理员的*权限不能访问平台新闻功能；本轮仅平台根职责（PLATFORM_OWNER/PLATFORM_SUPER_ADMIN）可操作，未擅自把控制面能力扩给学校或平台普通人员。
ZIP按25MB/80MB解压量/5000文件/2000篇单包进行安全限制，可拆多包；无每日篇数限制。只在内存中读取白名单路径，禁止链接、加密、活动内容和异常压缩比，图片重编码后存MySQL。不会按包中网址抓取内网或下载图片。来源链接格式检查不能替代事实核验；请核对内容真实性及转载/图片权限。
重复整包、重复正文跳过，不重复建稿。网络超时后重复确认不会重新排期。未通过格式检查、重复及主动排除的文章不发布；全部问题明确显示，不静默漏稿。问题稿需上游修正后以新包上传。本轮不支持已审核正文被静默覆盖，也不做第三方平台群发。

## 部署（技术人员执行一次）
在原PR269验收及合并授权完成后，备份数据库，检查当前Alembic head。新增迁移20260909_website_news_packages接20260906_fee_reduction_four_end；如其他分支带来新的head，先人工代码复核后合并迁移，不能盲目覆盖。
执行现有backend环境的 `alembic upgrade head`。新表只含平台公开内容/队列/审计，不使用学校业务表。
Nginx必须把 /news 和 /news/ 子路径代理给后端，不能落入SPA；主Docker Nginx已给出对应配置，其他环境使用locations示例合入已有server。上传端点26m，后端实际25MB，超出明确拒绝。
网站和backend部署后，选择其中一种持久工作进程：
- Systemd：部署deploy/systemd/school-lifecycle-website-news.service，校对schoolapp目录与env；技术人员显式enable --now。
- Docker：在现有compose.mysql.yml之外合并docker-compose.website-news.yml，显式加 --profile website-news 启动website-news-worker。先通过docker compose config；无新的数据库。
WEBSITE_NEWS_ORIGIN设置为真实官网HTTPS源站（默认https://hnyueke.com）。进程WEBSITE_NEWS_WORKER_ENABLED=true。未启用工作进程时，UI应明确显示“发布服务未就绪”，不能说已全量发布。

## 验收
真实MySQL8专用test_库执行 NEWS_TEST_REQUIRED=true python -m unittest discover -s tests/website_news -v。不得回落SQLite。覆盖75篇不限30、105篇跨页整包确认、并发双worker、并发重复上传、事务回滚、权限与未发布图片隔离、XLSX与SSR。
前端执行专属Node合同测试、真实npm ci和npm run build，并检查实际Vue上传/确认页面、/news无JS阅读、暂停恢复和最终页面。微信真机与生产短信不是本模块的自动化验收结论。
上传一包1—3篇经过人工核实的新闻，确认后检查表中发布回执及公开URL、RSS、sitemap。停止浏览器再确认工作进程继续。停进程后查看UI故障提示，恢复后检查无重复发布。

## 搜索与配乐
文章页提供服务器HTML正文、独立URL、canonical、来源、真实首次发布日期/更新时间、BlogPosting、RSS和分片sitemap。robots加入/news/sitemap.xml。AI搜索引用和收录由搜索服务决定，不保证收录，更不能用重复低价值内容刷量。
配乐更换为Scott Buckley《Discovery》的32秒片段，保留来源/CC BY4.0/修改说明，默认静音，主动开启才加载，关闭/暂停导览立即停。网站静态目录提供本地文件，不热链原作者。

## 回滚
先暂停所有队列并停worker，再回滚官网代码。保留新表、公开内容和审计；迁移downgrade在存在新闻数据时主动拒绝删表。取消队列不下架既有文章，下架动作逐篇留痕。
