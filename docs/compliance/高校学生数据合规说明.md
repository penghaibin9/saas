## 一、为什么高校学生数据要专门做合规

本平台承载学生**全生命周期**数据：身份证、手机号、家庭与经济困难、心理、处分、实习定位、成绩、就业去向等，多为**敏感个人信息**；且为**多学校 SaaS 多租户**平台，跨校数据隔离要求高。职校学生中**可能存在未成年人（14–18 岁，甚至不满 14 周岁）**，触发对未成年人个人信息的**特别保护**要求。因此合规不是可选项，而是产品能否进校的前提。

## 三、PIPL 关键原则 → 系统落地映射

| PIPL 原则 | 系统如何落地（对应设计） |
|---|---|
| 合法、正当、必要、诚信 | 按业务场景最小化采集；定位仅打卡时采集（`03`/`06`） |
| 告知—同意 | 采集页告知用途；敏感信息单独同意；监护人授权 `t_student_guardian_auth`、家长知情 `t_guardian_consent` |
| 目的限定 / 最小必要 | 数据范围三层门（`02`）；DTO 脱敏裁剪，不裸返回表行 |
| 敏感个人信息特别保护 | 默认脱敏 + 字段级完整权限 + 查看审计（`03`/`05`）；库内加密存储（`xxx_encrypted`） |
| 个人权利（查阅 / 更正 / 删除） | 学生自助查本人数据；信息纠错 `t_student_data_correction`；删除走逻辑删除 + 回收站（`02`） |
| 委托 / 共享 / 对外提供 | 企业导师硬隔离（`07`）；脱敏外发导出须填外发对象 / 目的 / 保留期限（`04`） |
| 处理者责任 / 可追溯 | 全量审计 append-only、留存 ≥3 年（`05`）；安全事件分级响应 |

## 四、敏感个人信息识别（PIPL 口径）

本平台以下数据属 PIPL "敏感个人信息"或需从严处理，映射见 `03` 脱敏清单：

- **特定身份 / 证件**：身份证号、学籍号
- **金融账户**：银行卡、资助 / 薪资
- **医疗健康 / 心理**：心理信息、帮扶记录
- **行踪轨迹**：实习打卡定位明细
- **不满十四周岁未成年人的个人信息**：整体按敏感个人信息从严处理（见第五节）

处理敏感个人信息须满足：**单独同意、特定目的与充分必要性、更严格保护措施（加密 / 脱敏 / 最小授权 / 审计）**。

## 五、未成年人特别保护（职校重点）

职校学生可能为未成年人，须落实：

1. **监护人参与**：处理不满十四周岁未成年人个人信息，须取得**父母或其他监护人同意**，并制定专门处理规则；系统以 `t_student_guardian_auth`（监护人授权边界）、`t_guardian_consent`（上岗前家长知情）承接。
2. **家长访问边界**：监护人可访问范围受 `auth_status`（`PENDING/ACTIVE/REVOKED/EXPIRED`）控制，授权可撤销、可过期。
3. **最小化 + 从严**：未成年人心理 / 家庭 / 处分等信息从严脱敏与隔离，企业导师一律不可见（`07`）。
4. **实习特别注意**：未成年学生实习须符合劳动与教育主管部门规定，家长知情为上岗前置（`t_guardian_consent`）。

## 六、数据全生命周期合规要点速览

| 阶段 | 合规要点 | 主责文档 |
|---|---|---|
| 收集 | 最小必要、告知同意、监护人同意、模板校验 | `03`/`04`、本文 §3/§5 |
| 存储 | 敏感字段加密（`xxx_encrypted`+`xxx_hash`），私有桶存文件 | `03`/`06` |
| 使用 | 三层权限门、默认脱敏、完整值需授权+审计 | `02`/`03` |
| 传输 | 全程 TLS；签名 URL；不落敏感值到本地 | `01`/`06` |
| 共享 / 对外 | 企业导师硬隔离；脱敏外发 + SoD 审批 | `04`/`07` |
| 删除 | 业务逻辑删除+回收站；审计不可删 | `02`/`05` |
| 追溯 | 全量审计 append-only、留存 ≥3 年、事件分级 | `05` |
| 跨租户 | `tenant_id` 行级隔离；平台运营不看学生明细 | `07` |

## 七、当前差距与整改方向（诚实记录）

- **未过等保三级测评**：当前为按三级思路设计，尚未定级备案 / 测评；整改路线见基线 §1.9。
- **后端鉴权 / 加密 / 审计落库待实现**：现为前端 mock；`tenant_id` 中间件、字段加密、审计 append-only、导出水印均待后端落地。
- **同意与告知文案待完善**：正式隐私政策 / 告知同意书 / 未成年人处理规则须由法务出具。
- **PIPIA 待开展**：敏感个人信息与未成年人处理场景应做个人信息保护影响评估并留档。
- **部分角色 / 数据范围待后端补充**（学工老师、系统管理员、校领导只读、`MAJOR` 专业级范围等，见 `docs/rbac`）。

## 八、合规责任提示

本平台为 SaaS 服务方与学校（个人信息处理者）之间通常构成**委托处理 / 共同处理**关系，双方权责、数据处理协议（DPA）、安全事件通报义务须在合同中明确。本文档不替代法律文书，落地前须经法务与学校信息 / 保密主管部门共同确认。
