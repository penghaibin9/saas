# 等保三级 · 上线前自查清单（对照现状）

说明：等保（网络安全等级保护）三级是涉及公民个人信息的教育类系统常见要求。本清单把三级核心控制点逐条对照当前系统现状。
状态图例：✅ 已具备（代码/配置层） · 🔶 部分具备/需配置 · ⬜ 需运维或第三方补齐（非代码可完成）。

> 重要：等保达标 = 技术措施 + 管理制度 + 物理/网络环境 + 第三方测评四位一体。代码只覆盖"技术措施"的一部分，最终定级测评必须由**有资质的等保测评机构**出具报告。本清单仅供上线前自查，不等于测评通过。

## 三、安全区域边界 🔶
| 控制点 | 状态 | 说明 |
|---|---|---|
| 访问控制（防火墙/安全组） | ⬜ | 仅放行 80/443；8000/3306 不对公网开放，由运维在云安全组配置。 |

## 四、安全计算环境（核心，代码覆盖最多）
| 控制点 | 状态 | 说明 |
|---|---|---|
| 身份鉴别 | ✅ | JWT + pbkdf2_sha256(20万次) 口令哈希；登录失败 5 次锁 15 分钟；生产禁用默认密钥（弱密钥拒启）。 |
| 访问控制（RBAC） | ✅ | 多角色 + 数据范围（本班/本院/全校）；平台总控强制超管校验，越权 403 + 审计。 |
| 多租户数据隔离 | ✅ | 行级 tenant_id 隔离 + 令牌绑定租户；实测 demo 账号只见本校数据。 |
| 安全审计 | ✅ | 登录/审批/导入导出/敏感访问/权限拒绝全留痕；各业务域独立审计链 append-only（不可改删）。 |
| 数据完整性 | ✅ | 乐观锁 version；逻辑删除（is_deleted/VOIDED），禁物理删除。 |
| 数据保密性（敏感字段） | 🔶 | 响应恒脱敏（手机/身份证/薪资）；导出脱敏+水印+审计+用途必填。**落库加密**当前为演示占位明文，正式生产需开 AES 加密（字段已预留 *_encrypted）。 |
| 数据备份恢复 | 🔶 | 自动备份脚本已备（每日+保留14天+附件）；需你部署 crontab 并**每月做恢复演练**。 |
| 剩余信息保护 | ✅ | 登出即 jti 黑名单 + 吊销 refresh；密码重置仅一次性返回、不落日志。 |
| 个人信息保护 | 🔶 | 数据最小化、脱敏已做；隐私政策/告知同意需法务补（管理制度层）。 |

4. ⬜ 云安全组：仅开 80/443，数据库不对公网。

**结论**：技术措施层面，本系统已覆盖等保三级"安全计算环境"的大部分核心控制点（鉴别/访问控制/隔离/审计/完整性/剩余信息保护）；剩余为配置项（HTTPS/加密/备份/安全组）和管理/测评项（制度/渗透/测评备案）。达"可对真实学校上线"，技术侧已就位，合规侧需走测评流程。
