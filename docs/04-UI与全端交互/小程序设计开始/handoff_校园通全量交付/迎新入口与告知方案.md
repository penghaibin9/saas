# 数字迎新 · 入口布局与新生告知方案

> 适用范围：校园通小程序（学生端）。目标：新生"不会漏、找得到、走得完"。
> 归档建议路径：`docs/04-UI与全端交互/迎新入口与告知方案.md`

## 1. 背景与难点

数字迎新是本平台的核心卖点，但新生场景有其特殊性：

- 新生在报到前**尚未拥有正式在校账号**，甚至学籍未激活；
- 报到是**强时效**任务（集中在开学前后 1–2 周），过期入口不应干扰在校生；
- 新生对小程序完全陌生，**默认不知道去哪里报到**。

因此迎新入口不能只依赖"登录后在服务大厅里找"，必须做成**多渠道触达 + 前置引导**。

## 2. 总体方案（三层）

### 2.1 第一层 · 告知触达（进入小程序之前）

| 渠道 | 内容 | 说明 |
| --- | --- | --- |
| 录取通知书二维码 | 专属二维码直达小程序迎新页 | 随通知书寄出，扫码即进 |
| 短信 | 下发**报到码** + 小程序链接 | 号码来自招生录取数据 |
| 微信订阅消息 | 报到开放、临近截止、材料待补提醒 | 首次进入时引导授权订阅 |

### 2.2 第二层 · 入口（登录页 · 限时）

- 登录页在**迎新批次开放期内**显示醒目的「新生报到通道」卡片（含倒计时）；
- 新生用**录取通知书编号 / 身份证号 + 微信**首次登录，无需预先拥有完整账号；
- 迎新批次结束后该入口**自动隐藏**，不干扰老生登录。

**显示条件**：`orientationBatch.status == 'OPEN'`（由后端下发批次开关与起止时间）。

### 2.3 第三层 · 登录后状态驱动（最关键）

登录后按**报到状态**决定首页形态：

```
if 用户身份 == 新生 且 报到状态 ∈ {未报到, 预报到中}:
    首页顶部 = 迎新引导卡（报到进度环 + 倒计时 + 「去报到」主按钮）
    其余功能弱化/置灰，报到为唯一主任务
else if 报到状态 == 已完成:
    迎新引导卡自动收起，首页恢复为普通学生首页
    数字迎新降级为「我的 / 服务大厅」中的普通入口（可回看报到记录）
```

**报到状态机**（与 mock `studentOrientation.overallStatus` 对齐）：

`未报到 → 预报到中（信息采集/身份核验/缴费/绿色通道）→ 已现场报到 → 学籍已注册（完成）`

## 3. 移动端布局要点

- **登录页迎新卡**：置于品牌区下方、常规登录按钮上方；用区别于蓝色主题的强调色 + 倒计时，突出时效性。
- **未报到首页态**：迎新引导卡整块占据首屏，包含
  1. 进度环（如"已完成 3/8 环节"）；
  2. 距报到截止倒计时；
  3. 「继续报到」主按钮，直达当前待办环节；
  4. 下方折叠展示后续环节清单。
- 报到完成后，首页顶部改为普通问候 + 常用服务网格，迎新入口沉入「服务大厅 · 学工中心」。

## 4. 文案建议

- 登录页卡片：`2024 级新生报到通道 · 距报到截止 12 天`，副文案 `凭录取通知书编号一键报到`。
- 首页引导卡标题：`欢迎加入！先完成入学报到`，按钮 `继续报到 ›`。
- 完成态提示：`全部报到环节已完成，欢迎加入！`
