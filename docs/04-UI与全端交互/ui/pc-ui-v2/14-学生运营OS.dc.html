14 学生运营 OS ·「航道」
总体概念：把导航杀掉，让业务本身成为界面。系统没有菜单树——顶部一条「成长航道」横贯所有页面：六个阶段是六座车站，实时挂着人数与异常，点进去就是那个阶段的作战室。老师不再「找功能」，而是「看见哪里堵了就点哪里」。首屏不是仪表盘，是今日指挥：系统替你排好今天该处理的事，每件事带着当事学生和一键动作。学生不是表格里的一行，是航道上的一个点——360 档案页里，TA 的头像就钉在航道上属于 TA 的位置。这就是「学生运营 OS」和后台的分界线。

③ 其余核心页 · 一条公式生成整个系统
每一页 = 航道（你在哪一站）＋ 堵点（这一站哪里堵）＋ 名单（涉及谁）＋ 一键动作（怎么疏通）。学会一页 = 学会全部。
学生主档（角色化首页同源）
屏 2 的名单形态：航道点某一站 → 下方即该站学生名单。每行 = 头像 + 全周期进度条 + 「当前卡在哪」业务语句 + 一键动作。辅导员进来自动锁本班（航道数字变成本班口径），教务看全院——同一页面，角色只换数据范围与动作权限。
岗位实习（站点作战室）
点航道「岗位实习」进入：顶部本站四指标（到岗率/异常/周报/巡访，带口径线），主体是异常处理队列（学生说明前置 + 认定正常/提醒纠正/记异常三选一），右侧教师积压与巡访优先级。全部处理动作走抽屉，不跳页。
毕业设计（节点看板）
横轴 = 选题→开题→中期→定稿查重→答辩五个节点，纵向是各节点的滞留名单（王浩逾期 2 天置顶）。导师视角只看本人指导 12 人，SoD 回避自动生效。批阅沿用审批中心的检件流。
就业服务（冲刺面板）
第一屏是就业率大数字 + 目标线与未落实 34 人的分层名单（未联系 8 置顶），材料核验队列在右。三方协议驳回/重传与学生小程序闭环打通，核验动作留痕。
审批中心（检件流）
三栏：件列表 → 决策区（步骤条 + 原值/新值 diff + 风险提示 + 意见）→ 证据区（SLA + 审计时间线）。J/K 切件、Enter 通过、R 驳回（必填 ≥5 字）。全站唯一的高密度页，皮肤与 OS 一致。
数据驾驶舱（对上的一页）
航道终点站。领导只读：全校航道大图 + 学院对比 + 风险 30 天趋势 + 就业率，宋体大数字，一键「生成院情简报」导出进 PPT。没有任何操作按钮——领导的界面不需要按钮。
系统管理（发布心智）＋ 角色化首页规则
权限矩阵（模块 × 查看/操作/审批/导出/高敏），任何变更 = 「影响 86 人 · 次日生效 · 可回滚」的发布卡；审计流水号贯穿。角色化首页：同一工作台由「综述句 + 堵点卡 + 右栏」三个槽位按角色装配——辅导员的堵点是「今天要联系谁」，导师是「待批 8 份」，就业老师是「未落实 34 人」，领导直接落驾驶舱。切身份，全屏随之重排。
视觉语言
纸白 #F9FBFE / 墨 #0B1526 / 唯一蓝 #2B5CE6；红橙只给真风险（全屏 ≤6 处）。字：系统栈，综述 25/800，数字 tabular；卡片 16 圆角 + 双层柔影；表格无竖线、56px 行高；图标 2px 线性；动效只有三处——航道流动虚线、当前站呼吸、卡片入场 200ms；版心 1180 居中，留白是刻意的。
为什么比普通后台高级
普通后台是「功能的仓库」——一棵所有人相同的菜单树，进去是空表格。这套是「业务的地图」：航道即导航，界面长得像它要管的东西本身。层次靠光与留白而非线框，色彩预算制（唯一蓝 + 只在真风险出现的红），大数字用 tabular 撑起数据的庄重。它不像"做出来的网页"，像"买来的成熟系统"。
为什么老师愿意用
老师从不"逛菜单"——他们只想知道"今天轮到我处理谁"。首屏直接把当天堵点排好、附上学生和一键动作；航道让"哪里堵了"一眼可见；学生 360 把一个人的全过程串成一条时间线，不用在六个模块间来回跳。少找、少跳、少等——累的三个根源被逐个拆掉。
为什么销售有冲击力
打开第一屏，客户在 3 秒内看懂整个产品：一条会流动的成长航道 + 一句"今天有 3 处堵点"。它自带演示脚本——点航道任意一站进作战室、点学生上时间线、切角色全屏重排。竞品还在展示"我们有多少功能"，你展示的是"学生的一生怎么被管好"。这是把功能清单卖成了理念。
落地：仍是 BasePortalLayout + tokens 改值路线；航道是一个可复用的 <LifecycleRail> 组件，贯穿所有页顶；工作台三槽位按 ctx.currentRole 装配。确认此方向后，我把 01/02/审批/登录全部铺成此语言，并出配套 tokens 与组件规范。
