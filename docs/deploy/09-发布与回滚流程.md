# 09 · 发布与回滚流程

> 目标：给新手一套「稳的发版方式」和「出事能一键退回上一版」的方法。
> 适用于当前阶段：PC 前端静态站点 + 小程序 H5。

---

## 1. 最简单的发布（够用版）

```bash
# PC 前端
cd frontend
npm install            # 依赖有变才需要
npm run build
sudo cp -r dist/* /var/www/pc-frontend/

# 小程序 H5
cd miniapp
npm install
npm run build:h5
sudo cp -r dist/build/h5/* /var/www/miniapp-h5/
```

缺点：直接覆盖，出问题不好退。适合个人测试、演示环境。

---

## 2. 推荐发布（带版本目录 + 软链，可秒回滚）

思路：每次发版放进一个带时间戳的新目录，用一个软链 `current` 指向「当前生效版本」。回滚就是把软链指回旧目录。

### 目录规划

```
/var/www/pc-frontend/
├── releases/
│   ├── 20260704-1000/     # 某次发版
│   └── 20260704-1500/     # 新一次发版
└── current -> releases/20260704-1500     # 软链指向当前版本
```

Nginx 的 `root` 指向 **`/var/www/pc-frontend/current`**。

### 发布脚本（PC 前端示例，手动照着敲也行）

```bash
# 1. 构建
cd /opt/school-platform/frontend
npm install
npm run build

# 2. 放进带时间戳的新目录
TS=$(date +%Y%m%d-%H%M)
sudo mkdir -p /var/www/pc-frontend/releases/$TS
sudo cp -r dist/* /var/www/pc-frontend/releases/$TS/

# 3. 切换软链到新版本（原子操作，瞬间生效）
sudo ln -sfn /var/www/pc-frontend/releases/$TS /var/www/pc-frontend/current

# 4. 重载 Nginx（静态站点一般不用，稳妥起见可执行）
sudo nginx -t && sudo systemctl reload nginx

echo "已发布版本：$TS"
```

> 对应 Nginx：`root /var/www/pc-frontend/current;`

---

## 3. 回滚（退回上一版）

```bash
# 看有哪些历史版本
ls -1 /var/www/pc-frontend/releases/

# 把软链指回你要的旧版本目录
sudo ln -sfn /var/www/pc-frontend/releases/20260704-1000 /var/www/pc-frontend/current
sudo systemctl reload nginx
echo "已回滚"
```

因为旧版本目录还在，回滚就是「改一下软链指向」，**几秒钟就能退回**，不用重新 build。

> 小程序 H5 同理，把路径换成 `/var/www/miniapp-h5/` 即可。

---

## 4. 微信小程序的「回滚」

微信小程序不走 Nginx，回滚方式不同：

- 在**微信小程序管理后台**，可以把「体验版/线上版本」切回之前上传过的某个版本，或撤回当前版本。
- 所以每次上传都**填清楚版本号和备注**，方便识别要回退到哪个版本。

---

## 5. 发版前后必须做的检查

- 发版**前**：见 `docs/ops/02-发布前检查清单.md`
- 发版**后**：见 `docs/ops/03-发布后检查清单.md`

最少要确认：
- [ ] build 成功、无报错
- [ ] 关键页面能打开（登录、首页、一个业务页）
- [ ] 刷新子页面不 404
- [ ] 出问题知道怎么回滚（记住上一版目录名）

---

## 6. 清理旧版本（避免磁盘占满）

保留最近几个版本即可，太老的可以删：

```bash
# 进入 releases，保留最新 5 个，删掉更老的（谨慎执行，先 ls 确认）
cd /var/www/pc-frontend/releases
ls -1t | tail -n +6 | xargs -r sudo rm -rf
```

> 建议至少保留 3~5 个历史版本，保证还能回滚。
