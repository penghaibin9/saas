# 职校学生全生命周期系统：当前唯一入口

> 更新：2026-08-31。本文只负责导航，不再手写模块完成度。代码、分支和门禁状态以机器生成文件为准。

## 先看结论

当前整理分支是“集成候选”，不是“可上线版本”。是否允许上线，只看 [`project-status.json`](./project-status.json) 的 `deliverable`：只有它为 `true`，并且候选版本检查返回 0，才允许进入生产发布。

两个仍在开发的功能工作区结束前，不删除工作区、不合并最终基线、不修改共享数据库容器。整理工作只在独立分支进行。

## 四个事实入口

| 要确认什么 | 唯一入口 |
|---|---|
| 当前 commit、分支收敛、导航和交付门禁 | [`project-status.json`](./project-status.json) |
| 当前有效文档及历史替代关系 | [`document-catalog.json`](./document-catalog.json) |
| 仓库文件、类别、哈希和处理建议 | [`repo-inventory.json`](./repo-inventory.json) |
| 人工阅读的当前文档索引 | [`project-map/当前有效文档索引.md`](./project-map/当前有效文档索引.md) |

`implemented` 只表示代码能力存在，不代表迁移、测试、安全、备份恢复和容量门禁已经通过。

## 按任务进入

- 开发或修复：先读根目录 [`CLAUDE.md`](../../CLAUDE.md)，再读对应业务中心 README 和代码测试。
- 部署上线：只从 [`../07-部署运维交付与商业化/deploy/README.md`](../07-部署运维交付与商业化/deploy/README.md) 进入。
- 测试验收：从 [`../06-开发施工与质量验收/testing/README.md`](../06-开发施工与质量验收/testing/README.md) 进入。
- 文档寻路：从 [`../README.md`](../README.md) 进入。
- 历史追溯：只在明确需要时读取 `docs/08-历史记录与归档/`，其中内容不得作为当前施工或上线依据。

## 文档冲突规则

1. 当前代码、数据库迁移和自动化测试结果高于手写进度描述。
2. `document-catalog.json` 中只有 `status=active` 是当前权威入口；`reference` 只作参考，`archived` 或 `superseded` 不能作为操作手册。
3. 同一主题有冲突时，使用目录 README 指定的权威文档；仍无法判断时停止操作，不猜测。
4. 真实密码、密钥、证书和生产备份永远不进入 Git、文档、截图或聊天记录。

## 上线前最后一步

在候选 commit 的干净工作区运行：

```powershell
python scripts\check\check-release-readiness.py
```

该命令默认只读。任何 `BLOCK` 都表示不能上线；它不会部署、删文件、改数据库或连接生产服务器。
