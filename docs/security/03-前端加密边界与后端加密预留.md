# 03 · 前端加密边界与后端加密预留（SECURITY-P0）

## 一、前端最多做什么

- 传输前字段格式化（去空格、统一格式）
- 公钥加密占位：`utils/security/crypto-boundary.js`（公钥由后端运行时下发、仅存内存、当前 mock 阶段直接抛错防"假加密"）
- 脱敏显示、风险提示、操作确认、审计参数传递（X-Request-Id / X-Trace-Id 等）

## 二、前端绝对不做什么（红线）

1. 不在前端硬编码 SM2/SM4/RSA 密钥、盐值 —— 打包产物人人可读，写进 JS 的密钥等于公开。
2. 不把密钥写入 localStorage / sessionStorage / IndexedDB / Cookie(非HttpOnly)。
3. 不把"前端加密后的数据"当作安全存储——密钥和密文同侧即等于明文。
4. 不用前端加密替代 HTTPS：传输加密由 TLS 完成，前端字段加密只是纵深防御的可选补充。

## 三、必须由后端 / 网关 / 数据库完成

| 项 | 责任层 | 预留说明 |
| --- | --- | --- |
| HTTPS/TLS、HSTS、安全响应头 | Nginx/网关 | 前端无动作 |
| 登录口令安全传输 | 网关 TLS + 后端（可选：后端下发一次性公钥，前端 crypto-boundary 加密口令字段） | 占位已留 |
| 密码哈希存储 | 后端（bcrypt/argon2/SM3+盐） | 前端永不接触哈希 |
| 数据库存储加密 | DB TDE / 字段级 SM4 + KMS | 前端无感知 |
| 文件加密与防直链 | 对象存储 + 签名 URL + 后端鉴权 | 前端 maskUrl 只管展示 |
| 密钥管理 | KMS/HSM，轮换与吊销 | 前端仅消费运行时公钥 |
| 服务端权限校验 / 审计日志 | 后端 | 前端 guards 与审计事件仅是第一道闸与参数来源 |
| 国密算法适配（SM2/SM3/SM4） | 后端/网关统一决策 | 前端待算法定型后接库，不自选算法 |
