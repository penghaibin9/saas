# 02-PC端权限矩阵

- **文档性质**：PC 管理端角色 × 模块权限矩阵
- **适用端**：PC 管理端（`frontend/`，Vue3，`/admin/*`）
- **依据**：
  - `frontend/src/config/adminMenu.js`（模块清单 + `ROLE_MODULE_ALLOW` 角色-模块允许关系）
  - `frontend/src/modules/workflow/`（`workflow.mock.js` roles[] 角色权限绑定）
  - `frontend/src/mocks/student/student.mock.js`（学生模块细粒度按钮 roleProfiles）
  - `frontend/src/modules/workflow/context/permission.context.js`（判断入口）
- **当前阶段声明**：矩阵中"可见并操作/只读可见/不可见"判定依据前端 mock 的角色-模块-权限点绑定关系推导，尚未经真实后端权限服务验证；生产环境须以后端 RBAC 服务返回结果为准。
- **生成日期**：2026-07-04

## 一、矩阵读法说明

- **列**：PC 端 13 个模块入口（对应共享底稿第 1 节模块表）：工作台（权限与流程）、学生主档、数字迎新、在校服务、学业过程、岗位实习、毕业设计、就业服务、数据驾驶舱、审批中心、系统管理、安全与审计（敏感）、平台运营。
- **行**：PC 端 7 个 ROLE_CODE 角色，另加 3 个"待后端补充角色码"的业务角色（学工老师/系统管理员/校领导，按其当前实际映射角色码估算权限，标注待确认）。
- **单元格取值**：
  - **可见并操作**：模块入口可见，且拥有该模块内至少一个 `BUTTON`/`DATA` 级操作权限点。
  - **只读可见**：模块入口可见，但仅有 `MENU`/`PAGE`/`view` 级权限，无编辑/审批/导出等操作权限。
  - **不可见**：模块入口不出现在该角色菜单中（`ROLE_MODULE_ALLOW` 未包含该模块，或该角色在 `workflow.mock.js` 中无任何相关权限点）。
- **模块-角色总闸**（来自 `adminMenu.js ROLE_MODULE_ALLOW`，作为第一道过滤，先判断模块是否在允许清单内，再判断该角色在该模块下的具体权限点决定"可见并操作"还是"只读可见"）：

| 角色码 | ROLE_MODULE_ALLOW 允许的模块 |
|---|---|
| `PLATFORM_OPERATOR` | 仅 `PLATFORM`（平台运营） |
| `SCHOOL_ADMIN` | 全部业务模块（`WORKFLOW`/`STUDENT`/`ORIENTATION`/`CAMPUS_SERVICE`/`ACADEMIC`/`INTERNSHIP`/`GRADUATION`/`EMPLOYMENT`/`DATA_CENTER`/`APPROVAL`/`SYSTEM`），不含 `PLATFORM` |
| `COLLEGE_ADMIN`（业务管理员，对应底稿 `ACADEMIC_STAFF` 口径） | `STUDENT`/`ACADEMIC`/`DATA_CENTER`/`APPROVAL`/`INTERNSHIP`/`GRADUATION`/`EMPLOYMENT` |
| `TEACHER`（业务教辅口径同 `ACADEMIC_STAFF`） | `STUDENT`/`ACADEMIC`/`DATA_CENTER`/`APPROVAL`/`INTERNSHIP`/`GRADUATION`/`EMPLOYMENT` |
| `COUNSELOR` | `STUDENT`/`ORIENTATION`/`CAMPUS_SERVICE`/`ACADEMIC`/`INTERNSHIP` |
| `STUDENT` | （待后端确认：`adminMenu.js` 面向的是 PC 管理端角色，学生角色通常走学生 PC 门户 `/api/v1/student-pc/*` 而非 `/admin/*`，本矩阵仍列出学生行以对照，但学生原则上不应出现在 `/admin/*` 管理端菜单中） |
| `ENTERPRISE_MENTOR` | （待后端确认，`ROLE_MODULE_ALLOW` 未在底稿中列出企业导师条目，暂按 `workflow.task.view` 权限点推断仅可见"审批中心"只读） |
| `AUDITOR`（审计角色，底稿明确给出，PC 端当前无独立 ROLE_CODE 与之对应，待后端确认是否等同"系统管理员") | `SYSTEM`/`DATA_CENTER`/`APPROVAL` |

> 注：底稿给出的 `ROLE_MODULE_ALLOW` 分组用了 `ACADEMIC_STAFF`、`AUDITOR` 两个业务口径名，系统当前 `ROLE_CODE` 中没有与之完全一一对应的角色码；本矩阵将 `ACADEMIC_STAFF` 口径同时应用于 `COLLEGE_ADMIN` 与 `TEACHER` 两个角色码（因两者在 `workflow.mock.js` 中的权限点均落在学生/学业/实习/毕设/就业/数据中心/审批范围内，与 `ACADEMIC_STAFF` 允许清单吻合）；`AUDITOR` 口径对应"系统管理员/校领导只读审计"场景，PC 端暂无独立角色码，待后端补充角色码（待后端确认）。

### 3.10 审批中心 —— moduleCode `APPROVAL`
