## 一、核心原则：上传只返回 file_id

**业务写操作只提交 `file_id`（或 `file_id` 数组），不把文件本体写进业务表。** 这是文件中心与业务模块解耦的核心约定，后端实现任何涉及附件的写接口时必须遵守。

```text
① 前端选择文件 → ② 调用文件中心上传接口（与业务接口分离） → ③ 上传成功返回 file_id
→ ④ 业务表单提交时携带 file_id（如学生信息更正申请的证明材料、服务申请的附件、审批的证据材料）
→ ⑤ 后端把 file_id（或 file_id 数组）存入业务表对应字段，不存文件二进制或文件路径明文
→ ⑥ 需要查看/下载时，前端用 file_id 请求签名 URL，再从签名 URL 拉取文件内容
```

依赖表：见冻结总册中的 `t_file_object`（唯一文件登记表，`file_key`（对象存储 key）+ `hash_sha256`（去重/校验）+ `size_bytes` + `mime_type` + `sensitive_level` + `(biz_module,biz_id,student_id)` 归属）、`t_file_access_log`（append-only，敏感材料下载/预览留痕）表。

## 二、接口清单

| 接口名称 | 方法/路径 | 权限要求 | 审计 |
|---|---|---|---|
| 文件上传 | `POST /api/v1/files`（multipart/form-data） | 登录态即可（具体业务附件是否需要额外权限点由调用方业务接口自行控制） | 写 `UPLOAD` 审计事件 |
| 获取文件签名下载/预览 URL | `GET /api/v1/files/{fileId}/url` | 需具备该文件所归属业务对象的查看权限（业务层校验后放行文件中心签名） | 敏感材料下载写 `t_file_access_log`（对应 `DOWNLOAD` 审计事件类型） |

### 2.1 上传接口请求/返回

| 项 | 内容 |
|---|---|
| 请求参数 | multipart 表单：文件二进制 + `bizType?`（业务类型标识，用于分类存储与差异化限制，如 `STUDENT_CORRECTION_PROOF`/`SERVICE_APPLY_ATTACHMENT`/`CHECKIN_PHOTO`，具体枚举清单待后端确认） |
| 返回字段 | `{ fileId, fileName, size, mimeType, hash }` |
| 数据范围要求 | 不涉及（上传行为归属操作者本人，写 `t_file_object` 关联 `uploader_id`） |
| 异常状态 | 文件类型不在白名单/命中黑名单；文件超过 50MB；网络中断上传失败 |
| 错误码 | `UPLOAD_FAILED`（本轮统一）；建议同时支持历史冻结总册细分码 `FILE_TOO_LARGE`（413）、`FILE_TYPE_NOT_ALLOWED`（400） |

### 2.2 签名下载/预览 URL 请求/返回

| 项 | 内容 |
|---|---|
| 请求参数 | 路径参数 `fileId` |
| 返回字段 | `{ url, expiresIn }`（短期签名 URL，含有效期，过期后需重新请求） |
| 数据范围要求 | 与该文件关联的业务对象数据范围一致（如学生本人上传的材料，仅本人与有权限的教师/管理员可获取签名 URL） |
| 异常状态 | `file_id` 不存在；无权限访问该文件 |
| 错误码 | `DATA_NOT_FOUND`、`NO_PERMISSION` |

## 三、白名单 / 黑名单 / 50MB 限制

| 项 | 规则 |
|---|---|
| 白名单类型 | pdf、doc、docx、jpg、jpeg、png、zip、rar、xlsx、pptx |
| 黑名单类型 | exe、js、bat、sh、php、jsp、html、svg（即使白名单未覆盖到的可疑类型，命中黑名单一律拒绝） |
| 单文件大小限制 | ≤50MB（可按业务类型细分配置，如身份证照片可能有更小的限制，具体细分规则待后端确认） |
| 校验层级 | 白名单/黑名单/大小限制**必须在服务端强制校验**，不能仅依赖前端表单的 `accept` 属性或前端 JS 校验 |

## 四、病毒扫描 / 存储（对象存储）

| 项 | 任务清单 |
|---|---|
| 病毒扫描 | 【待办】接入病毒扫描能力（具体扫描引擎/服务选型待后端确认，如 ClamAV 或云厂商托管扫描服务），上传文件应在写入 `t_file_object` 前完成扫描，扫描不通过文件应拒绝入库并返回 `UPLOAD_FAILED` |
| 对象存储 | 【待办】确定对象存储选型（MinIO 自建 或 云对象存储，待后端确认，共享事实底稿与数据库冻结总册均标注"预留"），`t_file_object.file_key` 对应该存储的 key |
| 存储去重 | 依据 `hash_sha256` 做文件去重校验（相同文件内容不重复存储，具体去重策略——是否物理去重还是仅记录去重——待后端确认） |
| 敏感文件加密存储 | 涉及身份证、家庭情况、心理记录、处分记录等敏感材料的文件，存储层是否需要额外加密（待后端确认，冻结总册 §17.2 敏感字段存储方式主要针对结构化字段，文件类敏感材料的加密策略需单独确认） |

## 五、下载签名 URL 与短期有效

- 预览/下载**一律走短期签名 URL**，不直接暴露对象存储原始地址或服务器文件路径。
- 签名 URL 有效期（`expiresIn`）具体时长待后端确认（建议参考行业常见做法，如 5–15 分钟，具体数值由后端结合业务场景——如打卡照片查看 vs 大文件归档下载——确定）。
- 敏感材料（证件、家庭、心理、处分、就业证明、劳动合同）下载/预览**必须**写 `t_file_access_log`（append-only）。

## 六、与 PC / miniapp 的对接点

| 维度 | miniapp | PC 管理端 |
|---|---|---|
| 选择文件方式 | `uni.chooseImage`（图片）/ `uni.chooseFile`（其他类型，视基础库支持情况） | 标准 `<input type="file">` 或组件库上传控件 |
| 当前 mock 实现 | 未真正上传，仅演示态占位（如 service-apply 页面 `pickFile()` 失败兜底文案"示例附件.jpg（演示）"） | 各模块导入导出功能同样为模拟回执，未真正处理文件二进制 |
| 上传时机 | 建议选择即上传（获得 `file_id` 后再随表单提交），避免表单提交时才处理大文件导致弱网环境超时 | 同样建议选择即上传，与 miniapp 一致 |
| 弱网处理 | miniapp 处于移动网络环境，建议上传失败可重试，且业务表单支持 `clientDraftId` 草稿机制，避免用户重复填写 | PC 端网络环境相对稳定，弱网重试优先级较低（待后端确认是否仍需实现） |
| 打卡照片 | 岗位实习打卡（`internship.checkin`）涉及的 `photoFileId` 走同一套文件中心上传流程，且**只在主动点击时采集定位，禁止代打卡**（红线，见历史冻结 05 岗位实习 API 说明） | 不涉及 |
| 文件预览 | 小程序内嵌预览组件（图片/PDF），走签名 URL | 浏览器新标签页预览或下载，走签名 URL |

**完整流程示例（学生请假申请附证明材料）**：

```text
1. 学生在 miniapp 选择"请假证明.jpg"
2. 前端调用 POST /api/v1/files（携带文件二进制）
3. 文件中心返回 { fileId: "f-xxx", fileName: "请假证明.jpg", size, mimeType, hash }
4. 前端调用业务接口 POST /api/v1/student-mini/internship/leaves
   body: { leaveType, startAt, endAt, reason, proofFileId: "f-xxx", clientDraftId }
5. 后端把 proofFileId 存入 t_leave.proof_file_id 字段（依赖表：见冻结总册中的 t_leave 表），不存文件内容
6. 教师端审批详情页展示该材料时，前端凭 proofFileId 调用 GET /api/v1/files/f-xxx/url
7. 文件中心校验教师对该请假记录有查看权限后，返回短期签名 URL
8. 教师端浏览器/小程序直接用签名 URL 加载图片预览
```

## 七、验收标准

- [ ] 上传接口返回 `{fileId, fileName, size, mimeType, hash}`，字段完整。
- [ ] 白名单/黑名单类型校验、50MB 限制已在服务端强制（非仅前端校验），用非法类型文件（如 `.exe`）实测应被拒绝并返回明确错误码。
- [ ] 业务写接口只接收 `file_id`，已确认无任何接口把文件二进制直接写入业务表字段。
- [ ] 下载/预览签名 URL 接口已实现，URL 含有效期，过期后重新请求可获得新 URL。
- [ ] 敏感材料下载已写 `t_file_access_log`（对应 `DOWNLOAD` 审计事件类型），可在审计查询中检索到对应记录。
- [ ] 病毒扫描能力已接入（或明确本期暂不接入并记录风险，待后端确认）。
- [ ] 对象存储选型已确定并可用（MinIO 或云对象存储）。
- [ ] 跨用户越权获取他人文件签名 URL 的场景已实测拦截（返回 `NO_PERMISSION`）。
- [ ] 冒烟用例：文件上传 → 获得 `file_id` → 提交服务申请表单携带该 `file_id` → 教师端凭 `file_id` 获取签名 URL 预览（对齐 `docs/05-数据接口权限与安全/api/08-后端联调检查清单.md` 冒烟 7）。
