## 三、统一响应结构与错误码落地

### 3.1 响应结构（强制，五字段）

```json
// 成功
{ "code": "SUCCESS", "message": "success", "data": {}, "traceId": "req-...", "timestamp": "2026-07-04T14:05:00+08:00" }

// 失败
{ "code": "NO_PERMISSION", "message": "无权限访问", "data": null, "details": {}, "traceId": "req-...", "timestamp": "..." }
```

| 字段 | 要求 |
|---|---|
| code | 字符串枚举，成功恒为 `SUCCESS` |
| message | 人类可读，前端可直接展示 |
| data | 成功恒为对象/数组包装对象；失败恒为 `null` |
| details | 失败时可选补充信息 |
| traceId | 后端生成，对应请求头 `X-Request-Id` 回传值，同时对应审计表 `request_id` |
| timestamp | ISO8601 带时区 |

- **ID 一律字符串化返回**（避免雪花 ID 超出 JS 安全整数）；**时间 ISO8601 带时区**；**金额字符串或两位小数**，前端不做浮点运算；**枚举返回英文码 + 可选 xxxLabel 中文标签**。
- 列表类接口 `data` 内层必须是 `{list, total, page, pageSize}` 分页结构（详见 `docs/05-数据接口权限与安全/api/04-统一响应结构与错误码.md` §二；注意与历史冻结总册 `items` 字段名的差异——**统一使用 `list`**，由后端 DTO 层做字段名归一）。

### 3.2 错误码落地要求

- 完整错误码表以 `docs/05-数据接口权限与安全/api/04-统一响应结构与错误码.md` §四 为准（该表**已与冻结总册 `00` §三逐条对齐**），至少覆盖：`SUCCESS / VALIDATION_ERROR / UNAUTHORIZED / NO_PERMISSION / NO_DATA_SCOPE / TENANT_NOT_FOUND / ROLE_NOT_FOUND / DATA_NOT_FOUND / DATA_CONFLICT / APPROVAL_VERSION_CONFLICT / REJECT_REASON_REQUIRED / MODULE_NOT_AUTHORIZED / MODULE_EXPIRED_READONLY / FILE_TOO_LARGE / FILE_TYPE_NOT_ALLOWED / UPLOAD_FAILED / WECHAT_AUTH_REQUIRED / LOCATION_PERMISSION_REQUIRED / IDEMPOTENCY_CONFLICT / RATE_LIMITED / SERVER_ERROR`（导入校验失败用 `VALIDATION_ERROR`，域码 `IMPORT_VALIDATION_FAILED`）。
- **错误码已统一**：`docs/05-数据接口权限与安全/api/04` §四 与历史冻结总册 `00` §三是同一套字符串码，二者无差异，后端一套实现即可，无需并集处理。前端 419（`SESSION_EXPIRED`）为安全层体验状态，契约层归一为 `UNAUTHORIZED`（见 `docs/05-数据接口权限与安全/api/04` §4.2）。
- workflow 模块前端 mock 当前用**数字** code（0=成功、41001=NO_PERMISSION 等）+ `requestId` 字段名，后端真实接口**必须转换为字符串 code + `traceId`**，不得沿用数字 code。

## 四、鉴权 / 租户 / 角色 / 数据范围落地要点

> 详细方案见 `05-鉴权与权限接入.md`，本节仅列总览要点。

| 要点 | 落地要求 |
|---|---|
| 服务端权限校验链 | 每个业务接口必须走：`authMiddleware(登录) → tenantMiddleware(租户) → moduleEntitlementMiddleware(模块授权) → featureFlagMiddleware(功能开关) → permissionMiddleware(权限码) → dataScopeMiddleware(数据范围) → sodMiddleware(职责互斥) → auditMiddleware(留痕)` |
| tenant_id | 前端永不传递；后端从登录会话/Token 解析，SQLAlchemy 会话级统一注入 `WHERE tenant_id = :currentTenant`；跨租户访问返回 `TENANT_NOT_FOUND`/`NO_PERMISSION` |
| currentRoleCode + activeContextId | 用户可有多身份，每客户端激活一个；权限不跨身份合并；切换后菜单/待办/数据范围/按钮/首页全部重载 |
| 数据范围（dataScope） | 服务端在 `WHERE` 条件按角色对应规则追加过滤（学院/班级/本人/被指派关系等），前端不参与计算 |
| 前端不可信 | 前端隐藏菜单/按钮/字段只是体验优化，**服务端必须重新校验权限码与数据范围** |

## 五、幂等与乐观锁

| 机制 | 规则 |
|---|---|
| 幂等（写操作） | 携带 `requestId`（业务层幂等键，区别于链路追踪头 `X-Request-Id`），同一 `requestId` 重复提交但 payload 不同返回 `IDEMPOTENCY_CONFLICT` |
| 乐观锁（审批类写操作） | 携带 `version` 字段，与服务端当前版本不一致返回 `APPROVAL_VERSION_CONFLICT`（409），对应数据库冻结总册每张业务表的公共字段 `version INT NOT NULL DEFAULT 0` |
| 退回/驳回二次校验 | `rejectReason`/`reason` 服务端二次校验 **≥5 字**（不仅依赖前端表单校验），不足返回 `REJECT_REASON_REQUIRED` |

## 六、脱敏与审计落地要点

> 详细规则见 `04-数据库对接注意事项.md` 与 `docs/05-数据接口权限与安全/api/05-接口鉴权与数据范围.md` §五。

- 敏感分级 `SENSITIVE_LEVEL`：`PUBLIC`/`INTERNAL`/`SENSITIVE`（默认脱敏，如手机号/身份证号/家庭住址）/`SECRET`（禁止前端明文，如密码、完整身份证号原文）。
- 默认返回脱敏值；查看完整值需字段级权限（如 `student.identity.view`）+ 写 `SENSITIVE_VIEW` 审计。
- `SECRET` 级字段任何角色前端都不下发明文，仅服务端内部使用。
- 审计事件类型（`AUDIT_EVENT_TYPE`）：`LOGIN/LOGOUT/PERMISSION_DENIED/PERMISSION_CHANGE/EXPORT/DOWNLOAD/UPLOAD/APPROVAL/SENSITIVE_VIEW/SESSION_EXPIRED`，落地对应数据库冻结总册 §十六 五张审计表（`t_student_field_audit`/`t_security_audit`（及 `t_security_audit_log`）/`t_permission_audit`/`t_operation_audit_log`，均为 append-only，留存 ≥3 年）。

## 七、文件中心落地要点

> 详细方案见 `06-文件上传接入.md`。

- 核心原则：**上传只返回 `file_id`，业务写操作只提交 `file_id`**，不把文件本体写进业务表。
- 白名单 `[pdf,doc,docx,jpg,jpeg,png,zip,rar,xlsx,pptx]`；黑名单 `[exe,js,bat,sh,php,jsp,html,svg]`；单文件 ≤50MB。
- 依赖表：见冻结总册中的 `t_file_object`、`t_file_access_log` 表。

## 八、里程碑（M0 底座 → M1 核心 → M2 业务 → M3 数据与治理）

| 里程碑 | 范围 | 对应接口联调顺序（详见 `03-接口联调顺序.md`） | 交付判据 |
|---|---|---|---|
| **M0 底座** | 统一响应结构与错误码中间件、tenant_id 隔离中间件、服务端权限校验链骨架、登录鉴权、租户与学校品牌、用户角色权限、文件中心基础上传/签名 URL | 步骤 1（登录鉴权）、步骤 2（租户与学校品牌）、步骤 3（用户角色权限）局部 | 能登录、能拿到 `currentUser`/`tenantBrand`/`menus`/`buttons`，文件上传能返回 `file_id` |
| **M1 核心** | 学生主档、审批中心（待办/审批横切能力）、权限点与角色管理落地 | 步骤 3（收尾）、步骤 4（学生主档）、步骤 5（审批中心） | 学生列表/详情/360 可查（脱敏正确），审批任务通过/退回流程闭环 |
| **M2 业务** | 岗位实习、毕业设计、就业服务三大教学实践模块 | 步骤 6、7、8 | 三个模块的看板/列表/详情/关键写操作按契约联调通过 |
| **M3 数据与治理** | 数据中心（数据驾驶舱）、导入导出、审计日志，以及数字迎新/在校服务/学业过程/平台运营等剩余模块 | 步骤 9（数据中心）、步骤 10（导入导出）、步骤 11（文件上传收尾）、步骤 12（审计日志） | 导出三档权限校验通过、审计日志完整可查、数据驾驶舱多口径统计接口联调通过 |
