# 01 产品一句话定位

- **文档性质**：销售/售前对客沟通材料——产品定位与电梯陈述
- **适用对象**：销售、售前顾问；面向学校客户（校领导、各职能部门）口头/书面介绍产品时使用
- **依据**：共享事实底稿（产品名称、适用范围、模块清单）
- **当前阶段声明**：当前为可演示版本（PC 管理端 UI 母版对接中 + 小程序 mock 演示闭环），后端真实数据接入按 API 契约推进中；本产品尚未经过等保三级测评
- **生成日期**：2026-07-04

## 一句话定位

**高校学生全生命周期管理平台——让每一个学生，从入学第一天到毕业离校，都有一个平台、一套流程、一份档案全程陪伴。**

## 适用院校类型

本科院校、高职院校、职业本科院校、应用型高校，均可使用。产品面向的是"学生工作数字化管理"这件事本身，不限定某一类院校的独有场景，无论是普通本科的学工体系，还是高职、职业本科强调的实习就业闭环，平台的模块设计都覆盖到了。

## 电梯陈述（3–5 句，30 秒版本）

1. 我们做的是**高校学生全生命周期管理平台**，把学生从入学、在校、实习、毕业设计到就业的每一个阶段，串成一条完整的数字化流程。
2. 平台不是单一功能工具，而是**按角色分工的工作台体系**——校领导看数据驾驶舱，学工看学生主档，教务看学业过程，就业办看就业闭环，辅导员和老师用手机就能处理审批和风险预警。
3. 所有流程走审批中心统一沉淀，谁审批了、什么时候审批的、退回了什么原因，全部留痕，管理更规范。
4. PC 端管理、学生和教师小程序端服务，两端数据打通，学生和老师在手机上就能完成申请、周报、审批这些高频操作，不用非得坐在电脑前。
5. 目前这套系统处于**可演示版本**阶段——核心模块和操作流程都可以现场演示，后端与学校真实数据的对接，我们是按标准接口契约在推进的。

## 稍长版本（面向正式介绍场景，1-2 分钟）

高校学生全生命周期管理平台，是一个面向本科院校、高职院校、职业本科院校、应用型高校的学生工作数字化平台。它解决的核心问题是：学生在校期间要经历数字迎新、在校服务、学业过程、岗位实习、毕业设计、就业服务这一整条链路，但传统做法往往是各个环节用各自的表格、系统、群聊分散管理，信息割裂、进度看不清、风险发现晚。

我们把这条链路完整搬到一个平台上：PC 管理端按"学生中心""教学实践""数据中心"等分组织组织了从学生主档、数字迎新、在校服务、学业过程，到岗位实习、毕业设计、就业服务的全部模块；每个角色——校领导、学校管理员、二级学院管理员、指导教师、辅导员、学生——登录后看到的都是符合自己职责范围的工作台，而不是一个大而全、谁都要自己找功能的后台。审批中心把岗位实习申请、周报批阅、毕业设计材料审阅这些流程标准化，谁在哪个节点、退回原因是什么，全部有记录可查。数据驾驶舱把分散在各模块的数据汇总成管理层能一眼看懂的看板，风险预警帮辅导员和教务及时发现需要关注的学生。

同时,我们不是只做PC端——学生和教师的高频操作场景，我们做了配套的小程序：学生可以在小程序里完成服务申请、实习打卡、周报提交、请假申请、就业上报；教师可以在小程序里处理待办审批、批阅周报、查看风险学生、查看学生 360 度画像，角色之间还支持身份切换（比如一位老师同时是辅导员又是毕设指导老师）。PC 和小程序是同一套业务逻辑、同一套权限体系，形成一个完整闭环，而不是两套互不相干的系统贴在一起。

需要如实说明的是：目前平台处于**可演示版本**阶段。PC 管理端的模块和界面已经齐全，正在做统一 UI 母版的对接；学生和教师小程序是可以直接运行、构建、演示的 mock 版本；后端数据库设计和 API 接口契约已经完成冻结，技术栈也已确定（PostgreSQL + Python FastAPI），但真实的后端接口尚未接入，目前展示的数据都是演示用的模拟数据。这意味着我们可以完整地把产品的业务逻辑、操作流程、角色分工、权限体系演示给学校看，但如果学校要的是"现在就能连上我校教务系统跑真实数据"，这部分工作是按项目实施计划、按已经确定的接口契约在推进的，需要按实际项目周期来安排。

## 核心价值：一个学生一个平台，全周期陪伴

| 传统方式的痛点 | 平台提供的价值 |
|---|---|
| 迎新、学籍、实习、毕设、就业分别用不同工具或表格记录，信息不互通 | 一个学生从入学到离校的所有关键节点，沉淀在同一份"学生主档"里，全周期可追溯 |
| 各岗位角色用同一套后台，谁都能看全部功能，权限边界模糊 | 按角色（校领导/学校管理员/学院管理员/指导教师/辅导员/学生/企业导师）分配工作台和数据范围，各司其职 |
| 审批走线下或零散的即时通讯工具，无留痕、无法追责 | 审批中心统一沉淀实习申请、周报批阅、毕设材料审阅等流程，退回必须写明原因，全程可查 |
| 风险学生（学业、实习异常等）依赖人工经验发现，容易滞后 | 风险预警机制辅助辅导员和教务及时关注需要跟进的学生 |
| 管理层想看整体数据，要靠各部门人工汇总报表 | 数据驾驶舱把关键数据集中呈现，减少人工汇总 |
| 老师和学生的高频操作（周报、审批、打卡）离不开电脑 | 小程序覆盖学生和教师的移动化高频场景，PC+小程序数据打通 |
| 多个学校用同一套系统，品牌和数据边界容易混淆 | 多租户设计，每个学校有独立的品牌配置和数据边界 |
